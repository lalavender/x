# 产品评审：yh 系统架构与长期演进设计（2026-10-24）

评审人：gstack-product-reviewer　对象：`docs/03-design/yh-系统架构与长期演进设计-2026-10-24.md`
方法：全文精读 + 对仓库实测核对（非语法校对）

## 结论：🟡 有条件通过

分层方向与依赖无环判断成立，K4 是该做的；但三处欠账的定价有误——S3 被高估（`.s.i` 已版本化）、
S2 的目标不可达也不该达、M1 五件事内部自相矛盾（K4 纯搬迁必然让 `build` 超 8k 预算，
M1 自己的退出条件无法达成）。修掉下面 3 条 🔴 后可放行。

## 阻塞项

### 🔴 B1　S3 被高估，事实陈述错误

§1.3 R3 与 §4.2 称 `.s.i`/`.s.ct`/缓存键"没有显式 schema 版本与不兼容拒绝"。实测：

- `compiler/parse/iface.yh:195-198` 发射 `// yh-iface v3 arch=arm64 suffix=`（v1/v2/v3 三档）；
- `iface.yh:429-431` 三个 magic 常量；`:446` 已有边界拒绝文案
  `yh: 接口不兼容（头行不是 yh-iface v1/v2/v3 arch=arm64）`；
- `compiler/ir/ssa_module_40_function_cache.yh:28` 已有 `IR_FUNCTION_CACHE_MAGIC`。

即"magic + version + 读取端边界拒绝"这三件事在 `.s.i` 上**已经做完了**，正是 K1 要做的东西。
真实缺口只剩：`.s.ct`、manifest、缓存键纳入 `schema_version`、`yh version` 输出契约版本集。

**建议改法**：R3 改写为"`.s.i` 已版本化但版本未进缓存键；`.s.ct`/manifest 缺失"；§4.2 删掉
"契约版本缺失=全部"；K1 范围缩到原 1/3。**副作用是好的**：K1 变便宜，可以先做。

### 🔴 B2　M1 退出条件与 §4.2 预算互斥

§2.2 要求 `cmd` ≤1.5k，§4.2 要求单模块 ≤8,000，M1 退出条件写 `cmd` ≤8k。三者不能同时成立：

- K4 是"纯搬迁"，把 argv 之外全部移入 `build` → `build` ≈ 12,235 − 1.5k ≈ **10.7k 行 > 8,000**；
- "单文件 ≤1,200"要求拆 `module_build.yh`(2,170) 与 `link_cache.yh`(1,448)，而**拆文件不是纯搬迁**；
  纯搬迁原样保留文件，最大文件仍是 2,170，A6 预算门禁必然红。

**建议改法**：K4 拆成 K4a（纯搬迁，字节对照）+ K4b（按职责拆文件），M1 退出条件改为
"越界边=0 且 `cmd` ≤8k 且预算项走报告模式"；`build` 的 ≤8,000 目标明确排到 M1b。
否则 arch-check 阻断模式在 M1 永远开不起来——这正好会印证 B4 的担忧。

### 🟠 B3　"模块级可变 let 189→0"不可达也不该达

实测分布：`cmd` 66、`comptime` 49、`ast` 42、`parse` 18、`gen` 14。

- `cmd` 的 66 是驱动层 scratch（`link_inputs.yh` 20+、`toml.yh` 10+、`build_scheduler.yh` 3）。
  驱动是单线程的，消除这些是纯 churn，零收益。
- yh 语言规则"`let` 不导出"（AGENTS.md）决定模块级 `let` 是静态存储的唯一形态。归零等于给每块
  缓冲找宿主，在自举固定点下做 189 次这样的搬迁，收益只在 M2 并行才兑现。
- 真正阻塞 M2 的是**前端路径**的 109 处（comptime/ast/parse）+ 51 个 `gen.G()` 读点。

**建议改法**：目标改为"前端路径模块级 `let` = 0，`gen.G()` 读点 51 → ≤16（仅 cmd）"；
`cmd` 的 `let` 走白名单 + 局部性规则（只允许出现在单线程 driver 边界），新增需 ADR。

### 🟠 B4　"先报告后阻断"会变成永久报告

文档已有"只减不增"的措辞，却把阻断推到"M1 末"，等于给 M1 期间的增量开了口子——而 M1 恰恰是
改动最密集的时期。**建议改法**：棘轮从第一天就阻断，只对**新增**违规（新文件超限、新 `let`、
新越界边、新 `gen.G()` 读点）失败；存量走白名单只减不增。另：预算统计不必新写，
`tools/yh-code-stats.py` 已是词法精确行统计、`make test-code-stats` 已在 Makefile，arch-check 应复用它
（文档未提这个已有资产）。

### 🟠 B5　K1 的"拒绝"会掐断种子链

若新编译器只认 vN 而拒绝 rc.N−1 种子发出的 v1/v2，自举闭包当场断。K1 验收只写了"版本不匹配负例"，
不够。**建议改法**：显式规定"接受 v1..vN，拒绝 >vN 与未知"，并把"rc.N−1 编 rc.N 时 v1/v2 仍可读"
写成 K1 的独立验收项。

### 🟠 B6　"不新增语言特性"与 IF1–IF5 并行自相矛盾

§0 主张 1~2 个版本不新增语言特性，§5 却让 IF1–IF5 在 M1 期间并行；而 IF3 就是 **`.s.i` v4**——
正撞在 K1 要版本化的同一个产物上。**建议改法**：M1 期间 IF 冻结，或 K1 落地并把 v4 纳入版本协商后再开 IF。
二选一，不要两件都写。

### 🟡 B7　诊断质量被整篇漏掉（最该补的一项）

全文只有 3 个错误函数：`gen/buffer.yh:183 err_lc`、`:355 err_tok`、`gen/symbols.yh:97 sem_err`。
纯文案、无错误码、无 severity、无 sink。§2.3 把 Diagnostic 列为六张契约之一，但 M1–M5 **没有任何
一条交付它**。而 M4 的 LSP、`fail-contains:` 语料、`yh-explorer` 全都依赖结构化诊断。

这是全文最便宜的欠账，也是 M1 唯一能给出的用户可见产出。**建议加入 M1：K6 诊断错误码**
（最常用 30 条，`E####` + 文案模板 + `// fail-code:` 语料），成本低于 K2 一个数量级。

### 🟡 B8　M1 零用户可见产出，且种子滚动操作未定义

五项交付全是内部重构。同时 todo 里 R1–R5（发版流程未闭）、YT4、memory/math/fmt 空白都还开着。
0.0.x 确实是打破的最佳时机，但"整版无产出"需要比"先还地基"更强的理由——K6 就是那个理由。

另：M1 退出条件里没有"0.0.10 由哪个种子编出"。重构期间 `make seed` 何时滚、rc 怎么发、
`bin/` 与 `link-closure` 是否受影响，§6 只说"两阶段落地"，不够。**建议补 K0 门禁基线计时（半天）**：
五项重构并行前必须知道 `make selfhost-native` 多久，否则无法判断每次切片的验证成本。

## M1 范围调整建议

| 条目 | 建议 | 理由 |
| --- | --- | --- |
| K1 契约版本化 | **保留，缩范围** | `.s.i` 已完成，只补 `.s.ct`/manifest/缓存键/`yh version` |
| K2 Session | **移出 M1**，仅留 A4 白名单冻结（1 天） | 189 let + 51 文件，风险最高、M2 前无收益、M2 并行会再改一遍 |
| K3 `api` 门面 | 保留（包装态） | 低风险，是 K4 的前置 |
| K4 `cmd`→`build` | **保留，拆 K4a/K4b** | 纯搬迁不降单文件行数，无法满足预算 |
| K5 arch-check | **保留，提前到第一周，棘轮即时阻断** | 唯一能防回涨的机制 |
| K6 诊断错误码 | **新增** | 唯一用户可见产出，成本最低 |
| K0 门禁基线计时 | **新增（半天）** | 并行重构前必须知道门禁成本 |

**K4 与 K2 的真实风险差异**：K4 是机械的、编译器可判定的（产物逐字节 + 两代固定点），失败立刻可见、
完全可回退；K2 是语义的、静默的（状态别名 bug 在 804 个语料里可能只出现在千分之一路径），
且要穿过"`let` 不可导出"这条语言规则做 189 次指针传递，做完 M2 换线程模型还要再动一次。
结论：K4 进 M1，K2 不进。

## 替代方案（文档缺失）

§2.2 只给了"新增 4 模块"一条路，没有对照"**不新增模块，只在 `cmd` 内部按职责拆目录**
（`cmd/project/`、`cmd/link/`、`cmd/build/`）+ 收缩导出面"的轻量路径。

- 重路径代价：4 个新模块 × `.s.i` 重排 × 13×13 依赖矩阵全量登记 × 6 个新 ADR。
- 轻路径代价：驱动仍不可复用，M4 的 LSP 到来时要再拆一次。

判断：若 LSP/包管理不在 12 个月内，轻路径 ROI 更高；若在，重路径正确。**建议在 §8 加 D7 显式记录
这个取舍及判定依据**（触发条件写成"LSP 立项即启动 K4"），而不是把重路径当唯一选项。

## 最高优先级行动项

1. 修 §1.3 R3 / §4.2 的事实错误（`.s.i` 已有 v1/v2/v3 + 边界拒绝），K1 缩到 1/3。
2. 解 M1 退出条件与预算的互斥：K4 拆 K4a/K4b，`build` ≤8k 排到 M1b。
3. 把"let→0"改成"前端路径 let→0 + `gen.G()` 51→16"，`cmd` 走白名单 + 局部性规则。
4. K2 移出 M1；K5 提前到第一周并即时阻断新增违规，复用 `tools/yh-code-stats.py`。
5. M1 加 K6 诊断错误码 + K0 门禁计时，给这一版一个用户可见产出。

## 1. 结论摘要

- **适合迁移的是「纯逻辑断言」**：断言目标在同模块或同项目内、结果确定、
  不依赖编译失败诊断、不依赖进程 argv/stdin/stdout/退出码、不需要特定后端/目标
  或源码改写重建。典型是标准库行为夹具、CLI 的 `--selftest` 主体、编译器内部
  fixture（`irverify`/`astcheck`/`irfront`）。
- **不适合迁移的是「编译器契约」**：语法/反例语料、编译期诊断、交叉与目标矩阵、
  一致性语料、失败注入、安装树、自举固定点、IR/对象/符号检查、性能测量。
  这些继续由外部 runner 承担。
- **迁移的收益不是门禁变快**，而是：断言失败有位置与消息、单例失败不掩盖后续
  用例（按组）、`--filter`/`--timeout`/skip、测试与被测代码同模块、以及删除
  fixture 里的 `ok()/fail()/return N/main` 脚手架与 runner 里的登记项。
  实测见 §8：`tests/string/run.py --group model`（217 行、43 处断言）约 2.0s，
  `yh test string` 冷跑 1.5s、热跑 0.3s，量级相同。
- **必须先补 YT2d 的测试运行目录/缓存隔离**：测试模式的构建目录固定为
  `<项目>/tmp/yh-test/check`，测试二进制固定为 `tmp/yh-test/bin/<模块>`，
  不区分目标、优化级、并发运行；本机分析期间两次出现
  `tmp/yh-test/gen/yh_test_module/entry.yh: … 模块没有导出该名字`，都只能用
  `rm -rf <项目>/tmp/yh-test` 恢复（§7.1）。
- **必须保留至少一个「外部消费者」smoke**：语言内测试直接编译被测模块，
  绕过了 `.s.i` 导出面与链接边界；每个库保留一个薄夹具走 `yh run`，
  防止「测试全绿但 pub 面坏了」。
- 迁移粒度按**行为组**（每块 5–20 条断言）而不是一条断言一个 `test`：
  逐例 fork + 重复 setup 的成本才会被摊薄。

## 2. 判定标准

一条现有用例可以改写为 `test` 块，需要同时满足：

1. 断言对象在同一模块/项目内可命名（不要求跨项目）；
2. 期望结果是"值相等/状态正确"，不是"编译器必须报某条诊断"；
3. 不把 argv、stdin、stdout 文本、stderr 文本、进程退出码当作被测契约；
4. 不要求特定后端/目标/优化级；平台差异只用文件名筛选
   （`*.linux.yh`、`*.darwin.yh`）表达；
5. 不需要改写源码后重建（失败注入）、下载语料、安装树或仓库外运行；
6. 不检查编译产物（IR、对象、接口、符号、缓存键、耗时）；
7. 能接受"一个模块一个测试二进制 + 逐例 fork/exec"的执行模型，
   不依赖用例之间的进程内状态。

补充的粒度约定：同一段 setup（解析同一份输入、构造同一组对象）产生的断言
放在同一个 `test` 里；用 `$assert` 消息区分断言。理由见 §7.5。

## 4. 可迁移清单

### 4.1 P1：低风险、纯逻辑、已有一等公民身份

P1 的共同特征：断言体可以原样保留（值、消息不变），删掉的是
`main`/`ok`/`failed`/编号返回/`FAIL 打印`/fixture 清单与 runner 登记；
新增的是失败位置、`--filter`、按组继续执行。

| `llvmlower`(605)/`llvmchecked`(248) | 断言可迁入 lowering/snapshot 模块测试 | 依赖 `input/*.yh` 文件与真实前端组合，先保留；`build-check.py` 的复制逻辑较重，迁移收益与风险需单独评估 |

### 4.3 P3：不建议迁移

- `tests/yh/`、`tests/modules/{accept,reject}`：断言对象是"能否解析/接受"，
  不是值。
- `tests/yh-run/fail`、`test-check.py` 的 `ytestbad`/`ytestsem`：断言的是诊断
  文本与位置，`test` 块无法表达"编译必须失败"。
- `tests/yh-run/run` 整体：每例是一个独立单文件语义探针，覆盖 stdout 格式、
  argv、stdin、退出码与平台差异；改写会同时丢掉这些契约，且需要把单文件
  重组为项目（YT1.1 未实现，项目外单文件仍被拒绝）。
- `tests/selfhost/` 全部探针、`tests/tools/`、`tests/perf/`：测的是编译器产物、
  链接、安装、统计与耗时。

## 5. 迁移形态示例

### 5.1 string 夹具（`if … return N` → 分组 `$assert`）

```yh
// 迁移前：tests/modules/projects/stringview 里的一个片段
if (first.value.count != 1) { return 11 }
if (second.value.count != 1) { return 12 }
if (empty.value.count != 0) { return 13 }

// 迁移后：libs/string/tests.test.yh
test "切分：空片段与迭代器" {
    let text View = test_view("a,,b")
    let iter SplitIter
    $assert(split(text, test_view(","), &iter) == Status.status_ok)
    $assert(split_next(&iter).value.count == 1, "首片段")
    $assert(split_next(&iter).value.count == 0, "空片段")
    $assert(split_next(&iter).value.count == 1, "末片段")
}
```

### 5.2 toml 夹具（`ok()` → `$assert`）

```yh
// 迁移前
ok((max == 9223372036854775807).to_type(int), "i64 max")
ok((min == -9223372036854775808).to_type(int), "i64 min")

// 迁移后（同一 test 内，保留原有小节分组）
$assert(max == 9223372036854775807, "i64 max")
$assert(min == -9223372036854775808, "i64 min")
```

### 5.3 cli selftest（编号返回 → `test`）

```yh
// 迁移前：clibasics 的 selftest 片段
if (r1.status != cli.ok) { cli.release(&r1); cli.destroy(&parser); return 10 }
if (string.equals(path, "bundle.bin") != 1) { … return 11 }

// 迁移后：libs/cli/tests.test.yh
test "默认值与位置参数" {
    let parser cli.Parser
    $assert(build_pack_parser(&parser) == 0, "parser 装配")
    let args [1]*char
    args[0] = "in.txt"
    let r cli.Result = cli.parse(&parser, args[0..1])
    $assert(r.status == cli.ok, "解析应成功")
    let path *char
    $assert(cli.get_text(&r.values, "output", &path) == 0)
    $assert(string.equals(path, "bundle.bin") == 1, "默认值")
    cli.release(&r)
    cli.destroy(&parser)
}
```

注意：`cli.parse_main_or_exit` 这类会写 stderr 并 `exit` 的路径、以及真正的
`argv` 入口，仍留在外部 runner。

## 6. 不可迁移清单与理由

| 用例族 | 关键理由 |
| --- | --- |
| 词法/语法/项目发现语料 | 期望是"接受/拒绝"，不是值断言；`yh test` 不提供"编译失败"用例 |
| 运行语料 `run/` | 契约是 stdout 逐行 + 退出码（含 argv/stdin）；改写会降低覆盖 |
| 反例 `fail/` | 契约是诊断文本/位置 |
| 交叉与目标矩阵 | `yh test` 首版只跑宿主兼容目标；目标/后端差异属于门禁维度 |
| conformance/参考差分 | 期望来自外部语料或 Python 语义，需要文件注入与逐项比对 |
| 失败注入/预算门 | 需要改写标准库源码后重建，`test` 块无法表达 |
| 安装/仓库外导入 | 需要 `make install` 与独立工作目录 |
| 自举固定点、缓存、IR/对象/符号 | 断言对象是编译器产物与两次构建的字节一致性 |
| 性能/复杂度 | 断言是耗时口径，不是值 |

## 7. 前置条件与风险

### 7.1 测试运行目录与缓存隔离（YT2d，实施前置）

代码事实：`compiler/cmd/module_build.yh` 的 `mb_build_dir()` 在测试模式下
返回固定的 `<项目>/tmp/yh-test/check`，不拼接目标/优化级；测试二进制路径
（`compiler/cmd/test_cmd.yh`）固定为 `tmp/yh-test/bin/<模块>`，逐例日志也尚未
独立（YT2d 未完成）。

分析期间的观测（Darwin/arm64，仓库内）：

- `libs/` 下第一次 `yh test string` 命中旧 `libs/tmp/yh-test` 时，入口模块
  报 `entry.yh:… 模块没有导出该名字`；`rm -rf libs/tmp/yh-test` 后通过。
- `compiler/` 下同一现象：`../yh test gen` 失败，清除 `compiler/tmp/yh-test`
  后通过；`make test-compiler-tests` 在污染缓存上曾只通过 1/3。
- 清理后，`O2 → O0`、`O0 → O2` 交替运行均正常重编译（manifest 键含优化级），
  说明目录级共享是真实风险，但具体触发条件尚未定位到单一原因。

结论：在把大批断言搬进 `test` 块之前，先完成测试缓存/运行目录隔离
（编译器身份 + 目标 + 优化级 + 运行实例），否则门禁红灯会被误判为迁移引入
的回归。此项与 YT2d 合并处理。

### 7.2 门禁入口

当前 `make test`、`make selfhost-native`、`make test-lib-tests` 都写死
`cd libs && yh test string`（`Makefile` 第 334、390–391、418 行）。迁移后：

- 改成无选择器 `yh test`（发现 libs 全部模块；分析时 `--list` 已验证只列出
  有测试的模块），或显式列出模块；
- 增加 O2 入口（`yh -O2 test …`，全局优化级参数对 `test` 有效，已实测）；
- 保留 `tools/compiler-tests.py` 的闭包环境准备（compiler 测试需要 LLVM 桥）。

### 7.3 依赖方向

- `libs/string` 不 import `toml`，`libs/toml` 也不 import `string`；interop
  测试放 `libs/toml` 并写测试专用 `import string` 即可，不形成生产依赖环。
- `libs/cli` 的测试主体会用到 `string`/`io`，按"仅测试体内使用的导入"规则
  不进入生产构建。

### 7.4 外部消费者边界

语言内测试编译的是被测模块本身，因此：

- 无法发现 `.s.i` 导出缺失、跨模块可见性/私有类型错误、链接顺序问题；
- `tests/modules/build-check.py` 的 `iface`/`rebind`/`run` 类用例不可省。

建议每个库保留一个薄 `stdlib-run` 夹具（现有的 `stringmodel`/`libsbase`
可缩减成 smoke），迁移后它的职责从"行为清单"变成"公开面 + 链接 smoke"。

### 7.5 粒度与成本

- 一个 `test` 块内的 `$assert` 失败会中止该例，但父进程继续后续用例；
  把一大段 `ok()` 断言塞进一个 `test` 会丢掉"继续检查"的能力，因此按小节
  分组（5–20 条断言）。
- 逐例 fork：同一模块多例共用一次编译，多一次 `exec`；相对每条断言一次
  重建的旧模式是净收益，相对"一个程序跑到底"是少量额外开销。
- 实测（Darwin/arm64，仓库内）：`tests/string/run.py --group model`
  （1 个 fixture、43 处断言）2.05s；`yh test string`（5 例、构建 memory+string）
  冷跑 1.47s，`--filter` 热跑约 0.3s。迁移不承诺减少门禁时间。

### 7.6 平台

- 平台差异继续用文件名筛选（`libs/sys/raw.linux.yh`、
  `libs/os/directory.darwin.yh` 已是现成约定），不要给 `test` 块发明
  `// platform:` 注释语义（设计文档已明确）。
- Linux 专属断言放在 `*_tests.linux.yh`；Darwin 端由 CI 的 darwin 任务覆盖。

### 7.7 自举与种子

- 入库种子已支持 `test` 语法（0.0.9-rc.2 起），因此迁移不再受"种子不认识
  test 块"限制；但 `make` 冷编会解析新增测试文件（语法检查、不发射），
  文件数量与体积要保持在合理范围。
- compiler 模块的测试必须经 `tools/compiler-tests.py` 运行（需要固定 LLVM
  闭包与 SDKROOT），不要直接 `yh test <compiler 模块>`。

## 8. 分阶段实施建议

每个阶段独立可回滚；先加新测试，双跑通过后再删旧断言体与 runner 登记。

| 阶段 | 内容 | 验证 |
| --- | --- | --- |
| **YT4a 前置** | 完成 YT2d 的测试运行目录/缓存隔离；`test-lib-tests` 改成无选择器；补 `-O2` 入口 | `make test-lib-tests` 连跑两次、`-O2` 与 O0 交替；`make test`、`make selfhost-native` |
| **YT4b** | string 5 组夹具 → `libs/string` 测试；`stringinterop` → `libs/toml` | `cd libs && yh test string`；`make test-string`（外部门仍绿）；`make` |
| **YT4c** | toml 5 组 API 夹具 → `libs/toml` 测试 | `cd libs && yh test toml`；`make test-toml`、`make test-toml-conformance` |
| **YT4d** | cli 5 个 `--selftest` 主体 → `libs/cli` 测试 | `cd libs && yh test cli`；`python3 libs/cli/test/run.py`（保留 5 个进程级用例） |
| **YT4e** | `irverify`/`astcheck`/`irfront` → `compiler/{ir,ast,check}` 测试；删除 fixture 与 `copy_proj` 特判 | `make test-compiler-tests`；`tests/modules/build-check.py`；`make selfhost-native` |
| **YT4f** | os/sys/time 纯模型断言迁入 `*.linux.yh`/`*.darwin.yh` 测试；FS/进程/环境保留 | `cd libs && yh test`；`make test-os`/`tests/modules` Linux 容器门 |

每个阶段完成后：

1. `make`（冷编编译器，确认新测试不破坏自举）；
2. `make test` 与 `make selfhost-native`；
3. 被迁移库的专项门（`make test-string`/`test-toml`/`libs/cli/test/run.py` 等）
   仍绿，直到对应外部断言体删除；
4. `git diff --check`。

## 9. 未决问题（需要决策）

1. **范围**：只迁标准库与 CLI，还是同时做编译器 fixture 合并（YT4e）？
2. **双跑时长**：迁移后旧 runner 保留一个版本周期（双跑）还是同版本删除？
3. **OS/FS/进程**：是否接受"测试用例自建/自清临时目录"的约定并迁入
   `libs/os` 测试，还是永久留在外部 E2E？
4. **粒度**：按小节分组（建议）还是逐断言一例（失败定位最细，fork 最多）？
5. **私有访问**：迁移后是否允许测试直接调用私有 `fn`（覆盖更强、但会降低对
   pub 面的约束）？建议保持"断言只调 pub 名字"，私有旁路另开测试。
6. **消费者 smoke 规模**：每个库保留 1 个薄夹具，还是保留现有全部
   `stdlib-run` 行为清单作为额外保障？

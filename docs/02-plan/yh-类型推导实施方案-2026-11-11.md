# yh 类型推导实施方案（参考 V）

- 日期：2026-11-11
- 状态：规划；用户已确认 `let x = expr`、首版支持模块级私有声明、
  `pub` API 强制显式类型；模块级**类型**按依赖解析，模块级**值**依赖由
  [符号依赖解析方案](yh-编译期符号依赖解析实施方案-2026-11-11.md) 的 S1 调度；
  含 `$` 的初值首版要求显式类型；编译器内部迁移等发种子后再做。
- 范围：函数内与模块级私有 `let` / `const` 的初值类型推导；不改运行期类型系统、
  不加隐式转换、不做全局 Hindley–Milner 推断。
- 一句话：V 的 `x := expr` 对应 yh 的 `let x = expr`；显式
  `let x int = expr` 完全保留，`pub` 声明仍必须写类型。

---

## 1. 目标与非目标

### 1.1 可观测目标

1. 函数内：
   `let x = 1` → `int`，`let s = "hi"` → `*char`，`let ok = true` → `bool`，
   `let c = 'a'` → `char`，`let f = 1.5` → `f64`。
2. 模块级私有：
   `let g = 1`、`const N = 3`、`let s = "hi"`、`let xs = [1,2,3]` 同样由初值
   推断；模块级 `let` 仍受现有“初值必须是编译期常量”约束。
3. 表达式保持现有类型规则：
   `let n = 1 + 2` → `int`，`let f = 1 + 2.5` → `f64`，`let p = &x` → `*T`，
   `let v = p[0]` → 元素类型，`let q = x.to_type(u8)` → `u8`。
4. `let xs = [1, 2, 3]` → `[]int`（切片，与 V 的 `a := [1,2,3]` 一致）；
   嵌套 `[[1,2],[3,4]]` → `[][]int`。
5. `let p = Point{ x: 1 }`、`let e = Color.red`、`let g = add`、
   `let r = f()` 分别使用结构体、枚举、函数签名、返回值类型。
6. `pub` API 不参与推导：`pub const X = 1` 必须报错并要求写类型；
   `pub fn` 的参数/返回、`pub` 结构体字段本来就要求显式。
7. 无法推断或字面量越界时给出确定诊断，绝不静默截断。
8. 显式写法零改动；新语法不会出现在编译器源码中，旧种子仍可自举。
9. 前向**常量值**依赖不再是类型推导的限制：由依赖解析方案 S1 在编译期
   按依赖求值（`const B = A + 1; const A = 1` 可编译）。

### 1.2 非目标（本方案不做）

- 不做全局约束求解 / HM 推断；不做函数返回类型推导（V 也要求写返回类型）。
- 不做 `$any` 泛型实参推断（已有
  [泛型 any 方案](yh-泛型any单态化实施方案-2026-11-10.md)，本方案与其正交）。
- 不做结构体字段、函数参数、类型别名、数组长度的类型推导。
- 不改变隐式转换规则：仍只有整数加宽和字面量可表示窄化，其余必须 `.to_type`。
- 不引入 `if` 表达式、闭包、多返回值。
- 不把裸 `[1,2,3]` 推成定长数组 `[3]int`；要定长数组请显式写类型。
- 不推导 `pub` 声明；不推导运行时初始化（`let g = runtime_fn()` 仍按现有规则
  拒绝：模块级初始化必须是编译期常量）。
- **首版模块级推断初值不允许出现 `$` 编译期调用/表达式**（如 `$f()`、`$mod.f()`、
  `$if`）；先用显式类型，后续再扩。
- 不实现模块级值依赖调度本身；由
  [符号依赖解析方案](yh-编译期符号依赖解析实施方案-2026-11-11.md) 的 S1 承担。
  类型推导只负责给出类型，不负责值顺序。

### 1.3 关键假设

- 语法形态采用 `let x = expr`（不新增 `:=` token），理由见 §2.3。
- 推导结果就是右值表达式现有类型，不额外“统一成 int”或跨类型提升。
- 模块级推断只针对**私有**声明；`pub const` / `pub fn` / `pub` 字段一律显式。
- 编译器源码在拿到“支持推导的种子”之前继续显式写类型；新语法先只进测试语料，
  避免旧种子无法编译新编译器。

### 1.4 决策摘要（已确认）

| 编号 | 决策 | 说明 |
| --- | --- | --- |
| D1 | 用 `let x = expr`，不新增 `:=` | 复用现有 `let`，语法增量最小 |
| D2 | 函数内 + 模块级私有 `let`/`const` 推导 | 用户确认首版包含模块级 |
| D3 | 类型 = 右值现有类型，不额外提升 | 保持 `u8` 等精确类型 |
| D4 | 裸数组字面量推成切片 `[]T` | 与 V 一致；定长数组显式 `[N]T` |
| D5 | 不新增隐式转换；只保留现有字面量/加宽规则 | 不破坏 yh 显式转换契约 |
| D6 | `pub` API 强制显式类型 | 公开契约不依赖推断 |
| D7 | 编译器源码暂不迁移到新语法 | 旧种子兼容；种子支持后再议 |

## 2. V 的实测基线（本机 V 0.5.1）

### 2.1 实测结果

```v
a := 1          // int
b := 1.5        // f64
c := 'x'        // V 的 string；yh 对应 char
d := "hi"       // string；yh 对应 *char
e := true       // bool
f := [1, 2, 3]  // []int（切片，不是 [3]int）
g := [1, 2.5]   // 错误：invalid array element: expected int, not float literal
h := 2147483648 // 错误：overflow in implicit type int
i := 1 + 2.5    // f64（二元表达式做数值提升）
j := &f         // &[]int
```

结论：V 的局部推导是「取右值表达式的类型 + 整数字面量默认 `int`（32 位）」，
不是全局约束求解；数组字面量默认推成切片。

### 2.2 与 yh 的映射

| V | yh 目标 | 说明 |
| --- | --- | --- |
| `x := 1` | `let x = 1` | yh 复用现有 `let`，不增加 `:=` |
| `a := [1,2,3]` | `let a = [1,2,3]` | 都推成 `[]int` 切片 |
| `x := f()` | `let x = f()` | 取函数返回类型 |
| `x := if c { 1 } else { 2 }` | `let x = c ? 1 : 2` | yh 没有 `if` 表达式，用三元 |
| `const x = 1`（模块级） | `const x = 1`（私有）；`pub const` 必须显式 | 模块级支持；含 `$` 的初值首版仍要求显式 |
| `2147483648` 推断失败 | 同样失败，并提示显式 `i64` | 修字面量范围检查 |
| `[1,2.5]` 推断失败 | 同样失败 | 元素必须可赋给首元素类型 |

### 2.3 为什么用 `let x = expr` 而不是 `:=`

- yh 已有 `let`、语句终结符和绑定列表；只把 `typeRef` 改为可选，语法增量最小。
- `:=` 要新增 token，并与标签 `L:`、三元 `:`、现有赋值扫描共享前瞻，风险更高。
- `let x = 1` 与显式 `let x int = 1` 只差类型，迁移和代码审查更直观。
- 若坚持 V 形态，可另立提案把 `:=` 作为语法糖；本方案不混用两套声明语法。

## 3. 现状与约束

### 3.1 语法与规范目前强制显式类型

```text
docs/yh.g4
  binding   : IDENT typeRef ('=' expr)? ;
  constDecl : 'const' IDENT typeRef '=' expr stmtEnd ;
```

`docs/03-design/yh-编码规范.md` §3 明确：

> 所有声明显式写类型。`let` / `const` / 参数 / 返回都必须有类型（语法强制）；
> `let a int` 合法，`let a = 1` 非法。

实测当前行为：

```text
$ ./yh tmp/infer_now.yh
tmp/infer_now.yh:4:11: 错误: 此处需要一个类型

$ ./yh tmp/const_infer.yh
tmp/const_infer.yh:3:9: 错误: 此处需要一个类型
```

### 3.2 字面量与表达式类型已经有默认值

| 字面量 | 当前 `Res.type_id` | 代码 |
| --- | --- | --- |
| 整数字面量 | `int`（`TY_I32`） | `check.sem_number` |
| 浮点字面量 | `f64` | `check.sem_number` |
| 字符串 | `*char` | `check.sem_string` |
| 字符 | `char` | `check.sem_char` |
| `true/false` | `bool` | `check.sem_bool` |

因此 `let x = <字面量>` 不需要新造默认类型，只要把 `Res.type_id` 取出来。
二元/一元/调用/成员/下标等表达式也已经写好 `Res.type_id`，并且已有
`sem_promote` 处理数值提升（`1 + 2.5` 当前就是 `f64`）。

### 3.3 现有绑定流程

`compiler/parse/parse_global_init.yh` 的 `parse_binding` 当前顺序：

```text
名字 → parse_type_ref → 登记符号/类型 → 解析初值 → sem_can_assign → 存局部槽
```

难点：

1. 类型在初值之前就要登记，无法“先看初值再决定类型”。
2. 局部变量只在 pass 2 解析（pass 1 跳过函数体），所以局部推导没有
   pass 1 的前向引用问题；模块级变量在 pass 1 就要登记类型。
3. `AstBinding.sym_type_id` 在 `ast_binding_add` 时记录声明类型；必须在登记
   符号之后、绑定行捕获之前确定 `tid`，否则 checked 快照/降低读到错类型。
4. `sem_declare_local` 会按 `tid` 分配局部槽并清零；必须用推导后的 `tid` 调用。
5. 模块级初始化目前要求编译期常量（见 `parse_global_init`），推导不能绕过它。

### 3.4 模块级编译流程与插入点

`compiler/build/module_worker.yh` 的顺序：

```text
pass1（登记全部顶层符号与声明索引）
→ mb_check_binding_clash / main 检查 / 未使用函数
→ pass2 CT 函数正文（MB_PASS2_CT_FNS）
→ 布局注册/求值（LAYOUT_*）
→ 全局初始化（MB_PASS2_GLOBALS）
→ 接口发射
→ 普通函数体（MB_PASS2_FN_BODY）
```

关键点：**函数体在全局初始化之后解析**，但 CT 函数正文在全局初始化之前。
因此模块级推断类型必须在 CT 函数之前就绪，不能等到 `MB_PASS2_GLOBALS` 才回填；
否则 CT 函数引用推断全局时会看到占位类型。方案是在 pass1 之后、CT 函数之前插入
一个“全局类型解析”子遍（见 §5.3）。

### 3.5 数组字面量目前强依赖上下文

`parse_array_literal` 取 `c_expect_tid`，没有目标类型就直接拒绝：

```text
数组/切片字面量需要目标类型上下文（let 初始化或同型赋值）
```

所以 `let xs = [1,2,3]` 必须同时实现“无上下文数组”的推导，不能只改 `let`。

### 3.6 两个必须先修的前置问题

**P0-a：同型字面量越界被短路。**

`compiler/table/api.yh` 的 `vk_can_assign` 第一行：

```yh
if (dst == src) { return 0 }
```

导致下面的代码当前**静默截断并通过**：

```yh
let x int = 2147483648
printf("%d\n", x)   // 实测输出 -2147483648
```

V 会报 `overflow in implicit type int`。推导 `let x = 2147483648` 会得到
`int`，若不先修这里，推导会继承同一 bug。

**P0-b：三元表达式没有合流两支类型。**

`sem_ternary_end` 只恢复标签，不比较中支/右支类型；当前
`let x int = c ? 1 : "s"` 能通过（分支不执行时更隐蔽）。推导
`let x = c ? 1 : "s"` 会直接拿到中支类型，必须先把三元类型合流补上
（可复用 `$if` 的 `ct_if_merge_type` 规则：同型，或字面量可赋给另一支）。

## 4. 目标语义

### 4.1 语法

```text
binding   : IDENT (typeRef)? ('=' expr)? ;
constDecl : 'const' IDENT (typeRef)? '=' expr stmtEnd ;
```

合法/非法：

```yh
let a int = 1          // 显式，保持
let b = 1              // 推断，新增
let c int              // 显式零值，保持
let d =                // 错误：缺少初值
let e                  // 错误：既无类型也无初值
let f = 1, g = "x"     // 每条绑定各自推断
let h, i = 1, 2        // 不合法：推断绑定必须自己带初值
const K = 3            // 私有常量推断
pub const P = 3        // 错误：pub API 必须显式类型
```

模块级：

```yh
let g = 1              // 私有全局变量；初值必须是编译期常量
const G = 2            // 私有全局常量
pub const P int = 2    // 显式，保持
```

### 4.2 默认类型

| 初值形状 | 推导类型 |
| --- | --- |
| 整数字面量 | `int`（32 位，越界报错，不自动升级 `i64`） |
| 浮点字面量 | `f64` |
| 字符串 | `*char` |
| 字符 | `char` |
| `true` / `false` | `bool` |
| 变量/参数/常量 | 其声明类型 |
| 二元/一元 | 现有表达式类型（含 `sem_promote`） |
| 函数调用 | 函数返回类型 |
| 下标/成员/解引用/转换 | 现有元素/字段/指向/目标类型 |
| 结构体/联合体字面量 | 字面量名对应的类型 |
| 枚举成员 | 枚举类型 |
| 数组/切片字面量 | `[]首元素类型`（见 §4.4） |
| 三元 | 合流后的类型（见 §3.6） |
| `$if` 表达式 | 现有 `ct_if_merge_type` 结果 |

明确不做：

- 整数字面量推不出 `int` 时**不自动**改推 `i64`/`u64`；报错并提示显式写。
- 不把 `u8` 变量推成 `int`；`let x = y` 的 `x` 就是 `u8`。
- 不新增 `int + f64` 之外的隐式转换；现有提升规则保持不变。

### 4.3 标量/表达式推导规则

记 `T(expr)` 为现有解析器写入 `Res.type_id` 的类型：

```text
let x = expr    ⇒   x : T(expr)
```

随后做三项校验：

1. `T(expr)` 不能是 `void`；
2. 不能是可 opaque 的 C 类型值（沿用现有 `ty_has_opaque_value` 规则）；
3. 若 `expr` 是字面量，必须能放进 `T(expr)`；例如 `2147483648` 默认 `int`
   放不下 → 报错，而不是截断。

### 4.4 数组/切片字面量规则

`let xs = [e1, e2, ...]`：

1. 没有元素（`[]`）→ 错误：无法推断元素类型。
2. 解析 `e1` 得到 `E = T(e1)`，作为元素候选类型。
3. 其余元素以 `E` 为目标上下文解析，并逐个检查
   `sem_can_assign(E, T(ei), ...)`；允许现有规则（字面量可表示窄化、整数加宽），
   不允许隐式整数↔浮点、窄化、同宽换符号。
4. 最终类型为切片 `[]E`（不是 `[N]E`）。
5. 嵌套数组递归使用同一规则：`[[1,2],[3,4]]` → `[][]int`。
6. 空切片仍可显式写：`let xs []int = []`。

示例：

```yh
let a = [1, 2, 3]          // []int
let b = [1.to_type(u8), 2] // []u8（首元素 u8，字面量 2 可表示）
let c = [1, 2.5]           // 错误：首元素 int，2.5 不能赋给 int
let d = [[1,2],[3,4]]      // [][]int
let e = []                 // 错误：空字面量无法推断
```

首元素定类型是 V 的行为（V 实测 `[1, x]` 为 `[]int`、`[x, 1]` 为 `[]u8`），
也让实现只需一次顺序解析。

### 4.5 名字查找与作用域

- 局部：先解析初值，再登记新符号：
  - `let x = x + 1` 中的右侧 `x` 只能解析到外层/已声明名字；没有外层则报
    “引用了未声明的名字”，而不是引用未初始化的新 `x`。
  - 同名重复仍由 `sem_check_duplicate` 拒绝（yh 的函数级作用域规则不变）。
- 模块级：**类型解析按依赖走，不按源码声明顺序**。
  - `const B = A + 1; const A = 1` 中 B 可推出 `int`；
  - 类型依赖成环报“类型推断存在循环依赖”；
  - **值**的初始化顺序由 S1 依赖调度解决：A 先 commit，B 下一轮 commit；
    不再要求“A 必须先声明”。循环值依赖由 S1 报完整路径。
- `let a = 1, b = a + 1` 中 `a` 在解析 `b` 前已登记，`b` 能看到 `a`。
- 不做“声明提升”；模块级声明顺序不再参与类型/值语义（除诊断位置），
  但 `pub` API 仍强制显式类型。

### 4.6 公开 API 规则

- `pub const X = 1`：错误，必须写 `pub const X int = 1`。
- `pub fn` 参数/返回、`pub struct/union/enum` 字段：本来就显式，不变。
- `pub let` 现行语法不允许导出变量，不变。
- `pub fn` 的函数体内部仍可使用局部推断；公开的是签名，不是函数体内的每个局部。
- 私有 `let`/`const` 可以推断；它们不进入 `.s.i`，不会让消费者依赖推断结果。

### 4.7 诊断文案（首版）

- `let x =` → `此处需要一个表达式`
- `let x` → `let 绑定需要类型或初值`
- `pub const X = 1` → `公开 API 必须显式写类型（pub const 不能依赖类型推导）`
- 模块级 `let x = runtime_fn()` → 沿用 `全局初始化必须是编译期常量`
- 模块级 `let x` → `模块级 let 推断需要初值`
- 模块级推断初值含 `$` → `模块级推断暂不支持 $ 编译期调用/表达式；请显式写类型`
- 类型依赖成环 → `类型推断存在循环依赖（A -> B -> A）`
- 值前向引用 → 沿用 `编译期常量尚未就绪`（不是类型推导错误）
- `let x = void_fn()` → `不能从 void 表达式推断变量类型`
- `let x = 2147483648` → `字面量超出目标类型可表示范围`（附说明：
  `默认类型是 int（32 位）；请显式写 let x i64 = ...`）
- `let x = []` → `空数组/切片字面量无法推断元素类型；请显式写 let x []T = []`
- `let x = [1, 2.5]` → `数组/切片字面量元素类型不一致（首元素 int，当前 f64）`
- 局部 `const` 聚合字面量 → `局部 const 聚合暂不支持（现有显式写法也不支持聚合 const）`

诊断位置优先用名字 token / 初值起始 token；与 V 风格源码片段方案
（[诊断方案](yh-V风格编译诊断实施方案-2026-11-11.md)）兼容。

## 5. 实现设计

### 5.1 语法与解析入口

`docs/yh.g4`：

```text
binding
    : IDENT (typeRef)? ('=' expr)?
    ;
```

`parse_binding` 在读到名字后先看下一个 token：

```text
if p_cur() == TK_ASSIGN:
    → parse_inferred_binding(global, kind, start, n, name_token)
else:
    → 现有显式路径（parse_type_ref ...）
```

局部 `parse_inferred_binding` 的最小流程：

```text
1. 编译模式才做语义；语法模式解析初值后返回。
2. 局部（global == 0）：
   - 解析初值（const 置 c_fold）；
   - 取 tid = r.type_id；校验非 void/opaque；局部 const 聚合拒绝；
   - sem_can_assign(tid, r.type_id, ...)；重复检查；
   - sem_declare_local / sym_push(SYM_CONST)；
   - ast_binding_add；变量 sem_store_local_value；常量写 cval/const_ready。
3. 模块级（global != 0）：见 §5.3；本地不在这里直接解析初值。
```

要点：

- 初值先于符号登记，保证 `let x = x` 不会引用自身。
- `ast_binding_add` 必须在 `sem_declare_local` 之后、`ast_stmt_end` 之前。
- 变量仍走 `SYM_VAR`，不因为初值是常量而变成 `const`；`let` 的可变性不变。

### 5.2 数组字面量推导

`parse_array_literal` 增加“推断模式”：

```text
tid = c_expect_tid
if tid < 0 && parse.ctx().infer_lit != 0:
    解析 e1（无上下文）→ E = e1.type_id
    其余元素 c_expect_tid = E，并 sem_can_assign(E, ...)
    tid = check.ty_slice(E)
    空元素 → 诊断
else if tid < 0:
    现有错误“需要目标类型上下文”
else:
    现有显式路径（数组/切片都支持）
```

`parse.ctx().infer_lit` 只在推断绑定解析初值期间置 1，解析后恢复；
这样 `f([1,2])` 之类仍然依赖函数形参提供上下文，不会把任意位置的裸数组都推成切片。
嵌套数组因为标志仍在，会递归推导。

### 5.3 模块级推断：pass1 占位 + 类型解析子遍

模块级不能像局部一样“先解析初值再登记”，因为函数体可以在声明之前引用它
（实测 `fn f() { return g } let g int = 1` 合法）；而 CT 函数正文又在全局初始化
之前解析。采用两段式：

**第一段：pass1 登记占位**

`parse_binding(global=1)` 看到无类型：

1. `pub` → 立即报错（公开 API 必须显式）。
2. 用 `sym_push` 登记符号，`type_id = TY_VOID` 作为内部“待推断”占位；
   不解析初值，沿用 `skip_init()`。
3. 记录或依赖 PDecl 索引，供第二段重新定位声明。

**第二段：全局类型解析子遍（CT 函数之前）**

在 `module_worker` 的 pass1 之后、`MB_PASS2_CT_FNS` 之前插入一次。
**按依赖多轮解析，不按源码顺序**：

```text
pending = 所有无类型的私有 let/const 声明
while pending 非空:
    progress = 0
    for 每个 pending 声明:
        global_infer_only = 1
        重新解析该声明 → 初值 type_probe
        若初值引用了仍是 TY_VOID 的 pending 全局:
            标记 defer，本轮跳过（不报错）
        若初值含 `$`:
            报“模块级推断暂不支持 $；请显式写类型”
        否则:
            tid = r.type_id；校验并更新 syms[idx].type_id
            从 pending 移除；progress = 1
    if progress == 0:
        报“类型推断存在循环依赖”并停止
```

依赖解析只看**类型**：`const B = A + 1; const A = 1` 第一轮解析 A、第二轮解析 B，
与声明顺序无关。值初始化仍由后面的 `MB_PASS2_GLOBALS` 按现有顺序执行，B 在 A 前
仍会报“编译期常量尚未就绪”（值限制，见 §4.5）。

可以复用现有 `parse_indexed_decls`，新增 mode 6 选择“无类型 let/const”；
`parse_binding` 在 `global_infer_only` 下只做类型探测，不发射数据、不写 AST、
不执行 CT。第二段结束后所有模块级推断符号都已有 `type_id`，CT 函数正文、布局、
全局初始化、接口发射都能看到最终类型。

**第三段：pass2 全局初始化**

`MB_PASS2_GLOBALS` 重新解析推断声明时：

```text
tid = syms[idx].type_id（已由第二段填好）
解析完整初值 → parse_global_init（与显式声明同一条路径）
断言 r.type_id == tid；不一致报内部错误
```

类型探测与真实解析必须一致；不一致时宁可报内部错误，也不能让快照/降低
读到两种类型。

### 5.4 类型探测模式（type probe）

新增 `support.fc().c_type_probe`（名字可调），只在 §5.3 第二段置 1。
它只负责“得到类型”，必须关闭所有值/发射副作用：

| 位置 | 正常行为 | probe 行为 |
| --- | --- | --- |
| `sem_string` / `sem_raw_string` | 分配数据标签、登记字符串 | 不分配；只写 `*char` |
| `sem_ident_val` 常量 | 要求 `const_ready`，写 `cval` | 只取 `type_id`，跳过就绪/值；若仍是待推断占位则标记 defer，交回多轮解析 |
| `sem_sizeof` | 检查布局、写大小 | 只写 `int`，跳过布局等待 |
| `sem_len` | 读长度/折叠 | 只写 `int` |
| `sem_call` | 检查实参、ABI、常量性 | 参数按 probe 解析；用函数签名返回类型，跳过 ABI/常量检查 |
| 初值含 `$` 调用/`$if` | 执行 CT/生成模型 | 直接报错“请显式写类型”，不进入探测 |
| 数组字面量 | 写元素/后备存储/CT 模型 | 只做 §5.2 类型推导 |
| 结构体字面量 | 可能建 CT 聚合模型 | 只取结构体类型，跳过模型/数据 |
| 枚举/字段元信息 name | 分配数据标签 | 只取 `*char` |
| `sem_ternary_end` | 生成标签/折叠 | 只做类型合流 |
| `sem_binop` / 一元 | 常量折叠 | 可保留只读折叠；禁止发射/分配 |

实施要求：

- probe 分支必须集中在少数 `sem_*` 入口，不在每个调用点散落。
- 用 `YH_INFER_PROBE_CHECK=1`（临时调试）或 pass2 的 `r.type_id == tid` 断言，
  对全量语料比对探测类型与真实类型；发现漂移立即失败。
- probe 只服务模块级推断；局部推断走完整解析，不受该标志影响。

### 5.5 前置修复

**P0-a：`vk_can_assign` 字面量范围。**

在 `dst == src` 早退之前，对整数目标检查 `is_lit`/`big`/`sem_lit_fits(dst, ival)`；
行为与现有 `VK_LIT_OUT_OF_RANGE` 一致。这样：

- `let x int = 2147483648` → 报错（不再截断）；
- `let x i64 = 2147483648` → 通过；
- `let x u8 = 300` → 仍走原错误路径。

风险：可能拒绝现有依赖截断的代码；用全量语料与 `just test` 确认（当前语料未发现
同类写法）。

**P0-b：三元合流。**

把 `ct_if_merge_type` 的规则抽成 check 侧公共 helper（例如
`sem_merge_branch_type(then, els, merged)`）；`sem_ternary_end` 需要拿到中支类型
（改签名传入 `mid`，或新增 `sem_ternary_merge(mid, else)`），在种子编译器兼容的
前提下只改内部调用，不改 AST。同型或字面量可赋给另一支才通过，否则报
“三元表达式两个分支的类型不一致”。`$if` 表达式继续使用同一 helper，避免两套
规则漂移。

### 5.6 AST / 快照 / 降低 / 接口

- `AstBinding.sym_type_id` 已是现有字段，不需要新增或改格式；推导只需在
  `ast_binding_add` 前把 `tid` 定下来。
- `AstExpr` 的数组节点 `type_id` 设为 `[]E`；元素节点的类型保持自然类型，
  降低阶段已有 `checked_lower_literal_retype` / `checked_lower_adjust` 处理
  字面量窄化和整数加宽（`checked_lower_array_elements`）。
- `.fchk`/`.fir` 无结构变更；推导只改变写入的类型值。
- 跨模块：局部变量与私有全局都不进 `.s.i`；`pub` 声明强制显式，接口无需
  处理“待推断”类型。
- 若 `pub const` 推断被拒绝，接口发射永远看不到 `TY_VOID` 占位；在接口发射
  前加一道断言：任何导出的 `let/const` 必须有非 void 类型。

### 5.7 与现有 `for` / CT / 泛型的边界

- `for-in` 已有隐式元素类型，不改。
- `@[comptime]`/`$for` 内的 `let x = ...` 走同一局部解析路径；CT 执行器读取
  `AstBinding.sym_type_id`，推导后应可直接工作，需补 CT 用例。
- `$any` 泛型实例化后，`let t = *a` 的右值类型是具体类型，本方案天然支持；
  `$any` 自身的调用点推断仍归泛型方案。

## 8. 风险与回退

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 类型探测与真实解析漂移 | 快照/降低读错类型 | 集中 probe 入口；pass2 断言 `r.type_id == tid`；全量语料比对 |
| probe 模式漏掉某个发射副作用 | 重复数据标签/静态数据 | 审计数据/CT/静态入口；probe 期间禁止 `data_label_advance`/CT 执行；全量测试 |
| 模块级类型依赖 | 推断链/循环 | 多轮依赖解析；pending 引用 defer；无进展时报循环依赖 |
| 前向常量值 | 值顺序限制 | 由依赖解析方案 S1 的 probe→commit 调度；类型推导只负责类型 |
| CT 函数需要推断全局值 | 值尚未就绪 | S1 调度直接依赖；S3 再纳入 CT 函数体依赖；首版 `$` 初值仍要求显式类型 |
| `pub` 推断漏检 | 公开 API 不稳定 | pass1 和类型解析子遍双重检查；接口发射前断言无 `TY_VOID` 导出 |
| 初值先解析改变局部名字查找 | 自引用/遮蔽诊断变化 | `let x = x`、重复声明、外层同名用例锁定 |
| 数组首元素定类型不符合预期 | 与 V 差异 | 与 V 实测一致；文档给显式类型写法 |
| 字面量范围修复拒绝旧代码 | 兼容性 | 全量 `just test`；当前语料未发现依赖截断 |
| 三元合流修复拒绝旧代码 | 兼容性 | 现有三元用例同型；分 P0 单独提交便于回退 |
| 旧种子不认识新语法 | 自举死锁 | `compiler/` 不使用新语法；新语法先只进测试；滚种子后再迁移 |
| probe 增加编译时间 | 性能 | 只处理无类型私有全局；模块级声明通常很少；记录前后时间 |

回退开关：

- 语法层是增量：删除 `binding` 的可选类型和 `parse_inferred_binding` 分支即可
  回到全显式；模块级类型解析子遍单独可禁用。
- P0-a/P0-b 是独立 bug 修复，可单独 revert，不影响语法。

## 9. 已确认决策

1. 语法：`let x = expr`。
2. 首版范围：函数内 + 模块级私有 `let`/`const`。
3. 公开 API：`pub const`、`pub fn` 参数/返回、`pub` 类型字段必须显式。
4. 不引入 `:=`；不改变隐式转换规则。
5. 模块级**类型**按依赖多轮解析，不按声明顺序；模块级**值**依赖由
   [符号依赖解析方案](yh-编译期符号依赖解析实施方案-2026-11-11.md) 的 S1
   按依赖调度（probe→commit），因此 `const B = A + 1; const A = 1` 可以编译；
   循环依赖报完整路径。
6. 模块级推断初值含 `$` 编译期调用/表达式：首版直接要求显式类型，不做 CT 类型探测。
7. 编译器内部非 `pub` 代码：等新种子发布并完成 `just selfhost-native` 后再迁移，
   首版 `compiler/` 不使用新语法。

以上 1–7 为实施约束；后续若要放开 5/6，单独立项。

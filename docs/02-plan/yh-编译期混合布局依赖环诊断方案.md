# yh 编译期混合布局依赖环诊断方案

日期：2026-10-06。状态：**已完成**。

## 目标

当布局阶段的整数编译期常量与数组、结构体类型布局互相依赖时，诊断完整的值/布局闭环，
不再只报告“编译期布局依赖环或未完成依赖”。

## 范围

- 将值常量和类型布局作为不同种类的依赖节点；以 CT 函数中的 `sizeof(T)` 建立值到布局的
  依赖，以结构体字段、数组元素和数组长度建立布局到布局/值的依赖。
- 沿 typed CT 函数的直接和嵌套 `$` 调用收集布局及常量读取依赖。
- 仅在布局调度停滞时搜索未就绪节点；纯常量环仍保留现有常量闭链诊断。
- 不改变普通全局 const 的声明顺序、数组长度可接受语法、执行预算或 CT 函数可见范围。

## 步骤与验收

1. 收紧 `fail/119-comptime-sizeof-pending-layout.yh`，要求闭环文本包含
   `ITEM_COUNT -> PendingLayoutPacket -> 数组长度(ITEM_COUNT) -> ITEM_COUNT`；先确认旧
   编译器因缺少路径而失败。
2. 在 `compiler/comptime/` 记录混合节点及边，布局请求注册时保存结构关系，解析器在活动
   源文件上下文中保存长度表达式依赖，常量请求沿 typed CT 调用图收集 `sizeof` 布局依赖。
3. 在无纯常量环时对混合图做 DFS，输出闭合节点路径与对应源码位置；保留无法证明为环时的
   现有未完成依赖诊断。
4. 验证混合环路径、纯常量环诊断、长度表达式直接 `sizeof` 与嵌套 CT 调用，以及全部语法/运行/模块/自举门。
5. 更新过程设计、CT5A 待办、测试说明与完成流水。全门通过后滚动种子并冷编。

## 成功标准

- fail/119 明确指出从 `ITEM_COUNT` 到 `PendingLayoutPacket` 的尺寸查询、再经字段数组长度
  回到 `ITEM_COUNT` 的闭环；fail/126–127 覆盖表达式长度中的嵌套 CT 调用与直接 `sizeof`。
- `fail/123` 的纯常量环仍输出其常量名称闭链；正向 `run/124–125` 和模块布局项目继续通过。
- `make test`、`make selfhost-native`、`git diff --check` 通过；新种子经冷编验证。

## 实施结果

  长度 token 表达式及 typed CT 函数闭包中的 `sizeof`/常量引用进入图。停滞时先保留旧的
  纯常量闭链，再搜索并打印混合闭环；不能确认环时沿用原未完成依赖诊断。
- fail/119 验证常量经嵌套 typed CT 调用读取结构体布局，再经字段数组长度回到自身；
  fail/126 验证数组长度直接调用嵌套 CT 函数读取自身结构体 `sizeof`；fail/127 验证长度表达式
  直接使用 `sizeof`。三个用例都比对闭环路径。

  `make selfhost-native` 通过（14 项模块产物固定点、68 个源文件自解析、语料 210/210、

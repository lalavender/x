# yh 编译期布局常量依赖调度方案

日期：2026-10-06。状态：已完成；验收和滚种子记录见[完成流水](../finish.md)及[完成记录](../01-finished/yh-编译期布局常量依赖调度-2026-10-06.md)。

## 目标

在 CT5A typed 布局请求现有基础上，建立同一编译单元的整数常量依赖图，使布局需要的
typed `@[comptime]` 常量可按依赖顺序求值，而不受声明遍历顺序限制；若常量之间形成
环，报告包含常量名的依赖链。

## 范围

- 只收集 pass1 已登记、未就绪、整数类型且初始化器包含 `$comptime_fn(...)` 的全局
  `const`，并且只在存在 pending 类型布局请求时参与调度。
- 依赖图覆盖单文件编译及一个模块的全部源文件；常量依赖可跨同模块源文件。
- 普通全局 `const` 的初始化顺序不变；仅布局 typed CT 候选初始化器可引用本编译单元
  后续声明的整数 const。最终未登记为请求的前向名、非候选未就绪值和不支持的初始化器
  仍安全失败，不把占位值当结果。
- 不扩展数组长度表达式语法，不接纳类型中直接 `$f(...)`、pending `sizeof`、跨模块
  编译期函数正文或一般 CT 求值请求；这些仍属于后续 CT5A/CT5B 工作。

## 设计与执行

1. typed 函数捕获后，各文件先登记布局常量请求及其初始化器中引用的未就绪常量边。
2. `compiler/comptime/` 持有请求节点、依赖边、READY 查询、可执行请求筛选及循环链路
   诊断；parser 只登记源码事实并在正确文件/导入上下文中解析可执行声明。
3. 单文件与模块 worker 反复遍历请求；每轮依赖已 READY 的请求才会执行。无进展时运行
   依赖图环检测；若无环，则沿用“编译期常量尚未就绪”拒绝未支持依赖。
4. 所有请求 READY 后，既有布局求解器再补齐数组和结构体布局，之后才进入普通全局
   初始化与函数编译。

依赖扫描只检查 const 初始化器的 token 范围；调用目标、成员名和已就绪常量不会生成
依赖边。图节点使用符号编号，跨文件仍指向模块统一符号表。重复边去重，环诊断给出一条
确定的闭环路径，例如 `ALPHA -> BETA -> ALPHA`。

## 验收

- 新增单文件正例：三层 typed CT 常量按依赖而非声明顺序求值，并用于结构体字段布局。
- 新增依赖环反例：诊断必须包含完整可读的闭环常量链。
- 新增多源文件模块正例：前置文件依赖后置文件的 typed CT 常量，模块构建和运行通过。
- 保留 fail/118 前向普通 const 诊断、fail/119 pending `sizeof` 诊断及现有递归预算行为。

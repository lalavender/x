## 1. 三个问题必须分开

| 编号 | 问题 | 现状 |
|---|---|---|
| P1 | **数据多份**：多模块（甚至同模块重复出现）各存一份字面量 | 实测：两模块同串 → 2 份 |
| P2 | **字面量可写**：`let s *char = "abc"; s[0] = 'x'` 通过 | 实测通过；`const` 绑定挡不住别名 |
| P3 | **标签身份不稳定**：跨模块 CT 闭包采纳后，注解标签指向提供方登记 | 内容比对路线已证伪（S4-2 方案 §4e-1） |

P1 与 P3 的解法可以独立；P2 是 P1 的**前置**（见 §4）。

## 2. 实测证据（2026-11-11，本机）

- 跨模块：`project.toml` + `src/a`、`src/b` 各含 `"dup-x"`，`yh build` 后
  `strings -a .build/proj2 | grep -c "dup-x"` = **2**；
  `nm -a .build/proj2 | grep LD` = 两个 `_.LD1`。
- 同模块：一个函数里两个 `"abc"` → `nm` 计数 **2**。
- 可写：`let s *char = "abc"; s[0] = 'x'` 编译并通过运行。
- const 别名仍可写：`const S *char = "abc"; let t *char = S; t[0] = 'x'` 编译并通过运行。
- `const` 现状：`G = 6` 报「赋值目标必须是可寻址的表达式」；`GP.a = 3` 报
  「不能给 const 聚合常量赋值」；`const n int = strlen("ab")` 报「函数引用不是编译期常量」。
  → **`const` 绑定已不可变，但只接受编译期常量**。
- 规模：`*char` 全仓 2,024 处（含注释/测试）；局部 `const` 声明 0 处。

## 4. 关键前置：只读化不是「改 const 绑定」

Zig 的只读性来自**字面量类型是 `*const`**，不是 `const` 关键字；
`var t = "abc"` 也写不了内容。反例已实测：`const` 绑定 + 别名仍可写（§2）。

因此 P1 要成立，必须先有「只读指针」：

1. 类型层引入 `*const T`；字符串字面量类型改为 `*const char`。
2. 兼容方向：`*T → *const T` 允许；`*const T → *T` 报错（显式转换需标注不安全）。
3. 写检查：`*const` 作为赋值目标（含下标/字段）拒绝。
4. C 互操作开口：`extern` C 调用实参允许 `*const char → *char`（C 无区别），
   否则 `printf("%s", s)` 全部失败。

## 5. 候选方案（按代价排序，均未实施）

**B：只读化 + 链接期合并（改动最小）**

- 发射改 `linkonce_odr unnamed_addr constant`，符号名用内容哈希（`.LDh<64 位>`），
  放进可合并段；lld/ld64 保留一份。
- 需要：`*const` 前置（§4）、`checked_lower_static_add_string` 的 linkage/命名/常量性、
  顺带在 `data_str_add` 做内容去重。
- 风险：只读必须是真只读，否则合并会引入跨模块写串扰。

**A：只读化 + 编译期内容寻址（收益最大）**

- 标签 = 内容序号，同一字节串在任何模块得到同一标签；跨模块靠接口闭包携带字符串池
  或独立池模块。
- 需要改：标签分配点、`.s.ct` 格式、缓存键（接口内容变则 key 变）。

**C：对象身份侧表（原 S4-5）**

- 只让「标签 ↔ 内容」在模块间稳定，供 eval 复用与影子门校验；**不减少数据份数**。
- 必须与 A 或 B 组合才有 P1 收益。

## 6. 与标准库 `string` 的关系

- **`string.String` 不能承载字面量**：它是 `handle *void` 堆所有权
  （[libs/string/api.yh](../../libs/string/api.yh:33)），无法出现在 `const`/全局初始化/
  `@[comptime]`（插值结果即 `String`，设计文档已写明这条限制）；每次出现都要分配，
  且对 P1 是**负向**（运行期各自分配）；`printf("%s")` 还需 `c_str` 转换。
- **`string.View` 可行但中性**：`{ data *u8, count u64 }` 借用视图
  （[libs/string/api.yh](../../libs/string/api.yh:26)），源码注释明确「data 不是语言层面的
  const 指针」——所以不解决 P2；也不改变静态数据份数，对 P1 中性。
- 若 P2 落地，`View.data` 可跟随改 `*const u8`，届时 View 自身带只读保证。
- `view_cstr` 现靠运行期 `strlen`
  （[libs/string/api.yh](../../libs/string/api.yh:752)）；若要让字面量零成本转 View，
  需要语言层暴露「字面量长度」（现在 `Res` 只有标签）。

## 10. 同根因的其他实例（2026-11-11 追加）

**D1（实测）`const` 聚合的只读只到绑定层，指针别名可写穿**

```yh
struct P { a int }
const GP P = P{a: 2}

fn main() int {
    let p *P = &GP
    p.a = 9
    return GP.a - 9        // 返回 0：写入生效，GP.a 变成 9
}
```

- 直接写 `GP.a = 3` 被拒（「不能给 const 聚合常量赋值」）；`&GP` 取别名后写入成功。
- 后端发射 `global` + `mutable = 1`（`module_snapshot_static.yh:107`、`:170-172`），
  const 没有传递到 LLVM；别名写不是 UB，而是**悄悄成功并改变后续读取**。
- 与 P2 同根因：缺少类型级只读（`*const T`）。

**D2（代码事实，未逐例实测）普通静态数据同样是私有 + 可变**

`module_snapshot_static.yh` 两处发射都是 `IR_MODULE_LINK_PRIVATE` + `mutable = 1`
（字符串 `.LD` 与普通静态数据）。因此非字符串的 `const` 聚合/数组也：
多模块各一份（体积问题，P1 的兄弟项）、可被别名写穿（D1）。

**D3（既有约束）CT 字符串池固定 64 段**

`ct_pool_spans [64]CtPoolSpan`（[ct_00_model.yh](../../compiler/comptime/ct_00_model.yh:34)）。
单个编译单元里被编译期函数捕获的不同字面量超过 64 段即触顶；具体诊断文案与
上限行为未逐一验证。字面量数量随项目增长，属潜在规模风险。

**D4（已见 §9）CT 与运行期只读判断分叉**：CT 指针指向只读槽池，运行期 `.LD` 可写。

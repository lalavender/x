# yh test 分阶段实施方案（提案）

日期：2026-10-23。状态：**T0–T3b 已实施；剩余 T2d 与 YT1.1**。
T0 落地语法与兼容性基线；T1 落地 `yh test --list`、文档目标绑定、
模块/文件选择、测试专用导入分类与无运行检查；T2a 把测试体降低为模块内
`pub` 无参 `void` 函数并发布对象，`$assert` 降为运行期
`__yh_test_assert(cond, line, col, msg)` 调用；T2b 增加入口模块、逐例进程、
结果协议与汇总，`yh test` 已能执行测试。执行过滤、`fail/skip`、超时与并行
仍未实现。语法与行为契约见
[设计提案](../03-design/yh-test语言内测试设计-2026-10-23.md)。
前端、断言降低与逐例调度接点见[执行模型分析](../03-design/yh-test语法块执行模型-2026-10-23.md)。

## T0 语法与兼容性基线（已实施，2026-10-23）

- 先检索 test 标识符使用，再修改 `docs/yh.g4`、关键字/成员名集合和声明索引。
- 覆盖字符串行为测试与 `test 声明名` 文档测试、空块、中文字符串名称、
  换行/显式分号边界、成员 `.test`。
- 覆盖缺名称、名称既非字符串也非标识符、限定名/计算名称、pub/属性、嵌套、
  带值 return、同种类重复名称等反例；不同种类同文字名称可共存。
  其中需要类型/作用域的规则由语义门验收，不误算成 ANTLR 语法限制。
- 生产/check 模式检查测试语法、跳过体内语义；测试模式检查全部所选模块测试体。
- `$assert` 复用既有调用语法，不新增 assert 名称；普通函数和 comptime 函数
  保持现有断言规则。test 体引入运行时断言上下文留在 T2，T0 只保留调用语法。

验证：在 `tests/yh/`、`tests/yh-run/` 添加 `.yh` 正反例；`make` 后运行 ANTLR
与编译器语法门，证明既有语料无回归。此时不往 compiler 源码添加 test 块。

**T0 实施结果**：`docs/yh.g4` 增加 `testDecl`/`testName`，`memberName` 放开
`test`；编译器增加 `TK_TEST`、顶层声明索引/跳过分支与 `parse_test_decl`。
生产 `build`/`run`/`check`/`--syntax-check` 只做测试体语法检查，测试体语义
被跳过且不发射代码。语料新增正例 `03-decl/12_test_decl.yh`、
`pass/09-test-decl.yh`、`run/206-test-decl-production-skip.yh`，反例
`rejected/47..51`、`fail/165..167`。`make test` 通过（ANTLR 正例 81/81、
反例 49/49；运行 211/212、fail 136/136、pass 9/9）。尚缺：同种类重复名称、
带值 return、文档目标绑定等需要语义/测试模式的能力，归 T1/T2。

## T1 发现、导入与无运行检查（已实施，2026-10-23）

- 为测试身份/种类/声明位置建立稳定索引；实现项目/模块/文件选择和 `--list`。
- 文档测试名称绑定到本模块顶层声明，记录目标身份；支持跨文件、前向、私有
  目标，拒绝不存在名字、import 模块名与 prelude 名字。不自动调用被测函数。
- 项目模式覆盖 main 不可达的本项目模块，依赖和标准库测试默认排除。
- 区分生产/测试 import 使用，保留未使用、别名、遮蔽和循环依赖诊断。
- 项目外文件用临时单模块上下文解析标准库；不装入相邻文件。

验证：在 `tests/modules/projects/` 添加 `.yh` fixture，覆盖跨文件私有声明、
测试专用依赖不污染生产、错误测试体仅在测试构建中报错、平台文件选择、
依赖测试不被运行、重名路径/模块与零用例；无 main 的模块可以进入测试检查。
文档测试补函数/类型/常量/全局变量目标、跨文件私有和前向目标、无效目标反例，
验证其目标元数据、列表/过滤及与字符串同名测试的区分，不泄漏生产接口。

**T1 实施结果**：新增 `compiler/cmd/test_cmd.yh` 与 `yh test` 命令；
`--list` 输出稳定身份（模块、项目相对路径、种类、名称、位置、文档目标），
`--no-run`/默认命令检查测试体语义但不发射/执行。新增
`tests/modules/test-check.py` 与 `ytest`/`ytestbad`/`ytestdup`/`ytestsem`/
`ytestempty` fixture，覆盖模块/文件选择、跨文件私有目标、函数/常量/全局变量/
类型目标、同文件重复、导入别名、零用例、平台文件筛选、测试专用导入不进入
生产、错误测试体只在测试模式报错；`make test` 与 `make selfhost-native` 通过。
**剩余**：项目外单文件临时单模块上下文未实现；`--filter` 目前只过滤 `--list`，
执行过滤、依赖项目测试排除的显式 fixture 与跨平台 CI 证据留待 T2/后续。

## T1.1 项目外单文件（已实施，2026-10-23）

- 判据：`yh test <文件>` 且该文件所在目录向上 32 层无 `project.toml`。
- 临时项目：根为 `<源文件目录>/tmp/yh-test/single/`，清单
  `name = "yh_test_single"`、`source = "<源文件目录>"`；扫描通过
  `c_scan_file_off/len` 只接受被选中的那一个文件，子目录与相邻 `.yh` 不进入。
- 模块名：文件头 `module X;` 优先，缺失时由文件名派生（`pj_synth_module_name`）。
- 标准库导入可用（`YH_STDLIB` 或安装布局）；测试产物仍在该临时项目的
  `tmp/yh-test/` 下；身份显示为 `<模块>::<文件名>::…`。
- `--list` / `--no-run` / `--filter` / `--timeout` / `--emit-llvm` 全部沿用。

**验证**：`tests/modules/single/`（`standalone.yh` 无 module 头、`with_import.yh`
导入 `string`、`neighbour.yh` 有意写坏用于证明不被装入）；`test-check.py` 增至
38 项（`single-file-test`、`single-file-options`、`single-file-stdlib-import`、
`single-file-skips-neighbours`）；`make test` 与 `make selfhost-native` 通过。

## T2a 测试体降低与运行期断言（已实施，2026-10-23）

- 测试模式下 pass1 为每条 test 登记 `__yh_test_<file>_<decl>` 的模块内
  `pub` 无参 `void` 函数；pass2 用正常函数上下文解析并捕获测试体。
- `$assert(cond[, msg])` 在 test 体内降为
  `__yh_test_assert(cond, line, col, msg)` 运行期调用；断言条件是普通运行期
  表达式，不再要求编译期常量，也不再在构建期报错。
- 测试声明作为 TK_TEST 进入 AstDecl/AstFunctionContext/CheckedModule；
  `--no-run` 走完整 CheckedModule→SSA→LLVM→对象发布（不链接、不执行）。
- 生产构建不登记测试符号、不捕获测试体；对象中不出现 `__yh_test_` 符号。
- `--emit-llvm` 可审阅测试模块的 LLVM 文本。

**T2a 实施结果**：`tests/modules/projects/ytest` 的 `tmp/yh-test/check/obj`
含 8 个 `__yh_test_*` 定义，LLVM 文本含 `call void @"__yh_test_assert"`；
生产 `.build` 对象零测试符号。`tests/modules/test-check.py` 增至 19 条断言，
`make test` 与 `make selfhost-native` 通过。

**T2a 边界**：`__yh_test_assert` 只有编译器内建声明，尚无运行时定义，
测试二进制无法链接；逐例进程/结果协议/超时/汇总属 T2b。

## T2b 最小完整执行链（已实施，2026-10-23）

- 每个含测试的模块生成入口模块 `yh_test_<mod>`（写入项目
  `tmp/yh-test/gen/<mod>/entry.yh` 并登记到项目），按 `argv[1]` 首字节选择
  用例，调用被测模块 `pub` 测试函数，正常返回后向 fd 3 写 `YHTP` 记录。
- 编译器运行时发射弱定义 `__yh_test_assert`：条件为假时向 fd 3 写
  `YHTF + line + col`（小端 int32）并 `exit(1)`。
- 父进程逐例 fork/exec（`fd 3 = 记录文件`），只有「退出码 0 且有 YHTP」判
  PASS；提前 `exit(0)`、崩溃、记录缺失/损坏一律 FAIL 且继续后续用例。
- 输出 `PASS/FAIL <identity>`、失败时的「断言位置: 行:列」与
  `结果: N passed; M failed`；失败时命令退出码 1。
- `--no-run` 保持只构建；新增 `--emit-llvm` 审阅。

**T2b 实施结果**：`ytest` 8/8 通过（rc 0）；`ytestfail` 覆盖断言失败
（位置 12:5）、提前 `exit(0)`、空指针崩溃与「失败后继续执行」，输出
`结果: 2 passed; 3 failed`（rc 1）。`tests/modules/test-check.py` 增至 23 条
断言，`make test` 与 `make selfhost-native` 通过。

**T2b 边界**：尚无执行过滤（`--filter` 只作用于 `--list`）、`--timeout`、
`testing.fail/skip`、并行、日志文件与稳定性缓存键；断言消息尚未进入失败
报告（记录只有行/列）。

## T2c 执行增强（已实施，2026-10-23）

- `--filter` 同时作用于 `--list` 与执行；过滤后零用例明确报错。
- `--timeout <秒>`（1..3600，缺省 15）：父进程 `WNOHANG` 轮询 + 单调时钟，
  超时 `kill(pid, 9)` 并回收，记为 FAIL「用例超时」。
- `libs/testing/` 新增 `fail(message)` / `skip(reason)`：写 72 字节记录后
  `exit`，父进程分别判 FAIL / SKIP；汇总增加 `M skipped`。
- 断言失败记录扩展为 72 字节：`magic + line + col + 60 字节消息`，失败输出
  「断言位置: 行:列」与「断言消息: …」。
- 新增 `tests/modules/projects/ytestskip`（fail/skip/带消息断言）与
  `ytesttimeout`（死循环 + 后续用例）；`test-check.py` 增至 27 条断言。

**T2c 实施结果**：`ytestskip` 输出 `2 passed; 1 skipped; 2 failed`（rc 1，
含两条断言消息）；`ytesttimeout --timeout 1` 输出「用例超时」并继续执行
后续用例；`--filter 跨文件` 只执行 1 例，未命中时报错。
`make test` 与 `make selfhost-native` 通过。

**T2c 边界**：无并行执行、独立日志文件、测试缓存键隔离与断言消息超过
60 字节的截断提示；项目外单文件（YT1.1）仍未实现。

- `libs/string/tests.test.yh` 新增 5 条内建测试：视图相等/比较、前后缀与查找、
  无分配切分与修剪、拥有者增长与 `c_str`、UTF-8 校验。

  `yh test string --timeout 60`；`make test` 与 `make selfhost-native`
  均已接入。
- 修复两个真实缺陷：
  - 非目标项目的 test 声明（依赖/标准库副本）此前也会登记测试函数，导致

**T3a 实施结果**：`make test-lib-tests` 连续两次运行均为
`结果: 5 passed; 0 skipped; 0 failed`；`make test` 与 `make selfhost-native`

**T3a 边界**：`compiler/` 当时仍不含 test 块——种子尚不支持 test 语法，

  `YH_LLVM_SELFHOST_FLAGS`、Darwin 的 `SDKROOT`），再逐模块执行
  `yh test <模块> --timeout 120` 并校验 `结果: … 0 failed`。
- 新 make 入口 `test-compiler-tests`，并接入 `make test` 与

## 完成标准

1. 用户能在普通 `.yh` 中写字符串行为测试和标识符文档测试，后者正确关联声明；
   无需 pub 即可测本模块私有声明，两种形式都按相同机制执行。
2. yh test 按已定义范围发现、构建、执行，失败信息、退出码和顺序可复现。
3. 用例失败、崩溃、提前退出或超时均不误报成功，不阻断后续可运行用例。
4. 生产构建不混入测试体/测试专用导入；生产缓存、测试缓存与固定点均正确。
5. 新增 `.yh` 正反与故障语料通过；本平台两大主门通过；种子迁移顺序有证据。
6. 基本断言统一 `$assert`；test 内运行时失败可定位到断言行，现有编译期
   断言行为及普通 helper 边界没有被调用来源或优化级别悄悄改变。

T0 验收“能解析 test 声明、生产构建跳过测试体”；T1 验收发现、文档目标绑定、
模块/文件选择、测试专用导入不污染生产与 `--no-run` 语义检查（完成标准 1、4 的
静态部分与 5 的本平台门）。完成标准 2、3、6 依赖 T2/T3 的执行器与运行时断言，
尚未验收；项目外单文件（YT1.1）仍开放。

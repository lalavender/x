# yh 编译期 typed 递归布局求值方案

日期：2026-10-06。状态：**已完成**。见[完成记录](../01-finished/yh-编译期typed递归布局求值-2026-10-06.md)。

## 目标

typed 布局请求不再根据函数正文里的静态调用环拒绝整数常量。布局常量按真实参数与
控制流执行 `@[comptime]` 函数：能够到达返回基例的递归允许决定后续数组/字段布局；
不终止的递归由既有编译期调用深度与执行步骤预算拒绝。

## 边界

- 仅移除 typed 布局请求的静态递归限制，不改旧 token 早期探测器的无环子集。
- 继续要求单个已声明整数 `const` 名称、同编译单元中已捕获的 typed CT 函数和已支持的
  typed 语义；不放开类型内直接 `$f(...)`、前向 const、任意布局表达式或跨模块正文。
- 函数递归不是布局依赖环。真正不终止的递归应报告现有 64 层调用限制；一般值/布局
  依赖环仍由后续 UNSEEN/VISITING/READY 请求图阶段处理。

## 实施与验收

1. 新增 run/121：递归到基例的 typed CT 函数返回 4，并用于结构体字段和全局数组长度。
2. 更新 fail/112：无基例的互递归必须实际执行并由 64 层调用预算拒绝。
3. 移除布局请求前的静态调用图扫描，复用 `ct_invoke_in_frame` 的深度/步骤预算；保留
   token 早期探测原有的无环验证。
4. 执行 `make test`、`make selfhost-native`、`git diff --check`；全绿后滚种子并冷编 `make`。
5. 更新编译期设计、CT5A 待办、测试目录说明、完成流水并新增完成记录。

## 成功标准

run/121 证明递归值实际参与布局；fail/112 证明非终止递归不挂起且诊断来自统一预算；
早期 token 子集行为不变；全量语料、自解析、固定点、模块/项目验收和种子冷编全绿。

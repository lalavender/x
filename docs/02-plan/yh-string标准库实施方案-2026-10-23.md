# yh string 标准库实施方案

> 本文件保留 ST0–ST6 的分期与验收契约；2026-10-23 已按此实施完成。

**目标：** 在现有 string 模块交付 View、可增长 String、字节查询/切分/替换与
严格 UTF-8 基础能力，保留三个旧 `*char` 接口。

**架构：** View 借用指针和长度，String 用薄句柄独占私有存储并显式释放。
查询不分配，产出新内容的变换返回拥有者；UTF-8 与字节操作分开。

**技术：** 现有 yh/LLVM、memory 分配接口、普通 `.yh` 项目断言、Python 标准库 runner。

日期：2026-10-23。状态：**ST0–ST6 均已完成并通过本平台专项门**。范围已获
用户确认，API 见[设计](../03-design/yh-string标准库设计-2026-10-23.md)。实现未
修改语法、不等待语言内 test；未滚种子、未推送、未触发发布。

**实施结果（2026-10-23）：** 实际文件为 `libs/string/00_model.yh`、
`10_view.yh`、`20_owned.yh`、`30_transform.yh`、`40_utf8.yh`、`doc.yh`、
`README.md`，旧接口保留在 `string.yh`；fixture 为
`tests/modules/projects/string{model,view,owned,transform,utf8,interop,resources}`；
专项 runner 为 `tests/string/run.py`、`tests/string/reference.py` 与
`tests/string/install.py`，并新增 `make test-string` / `make test-string-o2` /
`make test-string-install`。O0/O2 全组、分配失败注入、92 例参考差分与安装
导入均已通过；基本组已登记 `tests/modules/build-check.py` 的 `stdlib-run`。

## 1. 执行顺序与验证入口

顺序为 `ST0 → ST1 → ST2 → ST3 → ST4 → ST5 → ST6`。一次只完成一个可验收切片；
ST0 的风险结论影响后续实现，不能先把未经验证的布局写成稳定公开 API。

每个切片：添加 `.yh` 断言 → 确认失败原因 → 最小实现 → 定向用例通过 →
`make` → 更新文档和 finish。最终执行本平台 `make test` 和 `make selfhost-native`。
下面路径与 `make test-string` 均已落地；本节保留原始验收契约。

`tests/string/run.py`：支持 `--compiler ./yh`、`--stdlib ./libs`、
`--workdir tmp/string-test`、`--group`、`--opt-level 0|2`；fixture 复制到 tmp 后
构建和运行，失败用非零退出码，不往原 fixture 写 `.build`，不联网下载。
未知/空选中组、构建失败、超时、缺 fixture、断言失败均不能记 PASS。

| 组名 | 拟新增项目（均在 tests/modules/projects/） |
| --- | --- |
| model | stringmodel/src/main.yh |
| view | stringview/src/main.yh |
| owned | stringowned/src/main.yh |
| transform | stringtransform/src/main.yh |
| utf8 | stringutf8/src/main.yh |
| interop | stringinterop/src/main.yh |
| resources | stringresources/src/main.yh，使用测试工作副本注入分配故障 |

每个项目配 `project.toml`，含 os/arch=host、唯一 name 和 source="src"。
runner 检查退出码 0 和精确成功行；失败断言输出唯一编号，便于定位。

## 2. ST0：契约和风险探针

**阅读：** `libs/string/string.yh`、`libs/memory/memory.yh`、
`libs/cli/cli.yh`、`libs/toml/{00_types,20_utf8}.yh`、
`compiler/cmd/project_index.yh`、`docs/03-design/yh-模块私有类型设计.md`。
**实验：** `tmp/string-plan-probes/`，只在验证后把长期有效断言转入后续 fixture。

1. 核对全部 String、length、equals、compare 调用和类型布局依赖，记录旧接口
   兼容表；没有直接改空 String 占位布局的证据前不宣称 ABI 兼容。
2. 用当前种子和候选分别编译最小项目，验证 View/String/具体 Result 跨模块
   参数返回、零句柄、bool/enum、结构体字段和 u64 指针索引。
3. 验证薄句柄的私有状态不会泄漏到 `.s.i`；pub 类型注释能清楚说明浅复制边界。
4. 对分配器调用、运行时长度头部与指针运算核对最大长度建议；设计中溢出检查
   必须能在解引用/分配之前完成，不用伪造巨大可读区间测试实际遍历。
5. 写出自追加的源区间识别与迁移顺序；验证 ptr→u64、偏移恢复和重叠复制方案。
   若当前语言路径不可靠，用显式临时副本解决并披露额外分配，不能保留悬空读取。
6. 确定私有分配接缝与故障计数方案；与 memory/sys 分层保持一致，不新建分配框架。

**关闭条件：** 风险探针有具体命令/结果；选择的布局、长度上限和自别名策略可由
现有语言实现，或明确修订设计。不创建通过占位返回值冒充可用的公共函数。

## 3. ST1：模型、视图和旧接口兼容

**修改：** `libs/string/string.yh`，将空 String 换成提案中经过 ST0 验证的模型。
**新增：** `libs/string/10_view.yh`、model/view 两个项目、`tests/string/run.py`、
`tests/string/README.md`；暂不实现 split，留给 ST2。

1. 先写 view_bytes/view_cstr、空串、NUL、0x80/0xFF、字节序、边界和空 needle
   的断言，确认缺失新符号/行为使其失败。成功行不能掩盖未运行的断言。
2. 实现 View/Status/需要的结果类型、构造、view_equal/view_compare、前后缀、
   find/rfind/contains、半开区间 slice、trim_ascii。只写本阶段实际使用的 pub。
3. 用首尾外放置哨兵字节的缓冲验证边界；构造检查 (0,0)/(0,n)，slice 检查
   start>end、end>count 和 end==count，失败结果为空且不访问输入外部。
4. 直接重跑 `tests/modules/projects/libsbase/` 和已有 string.equals 消费者；
   原三接口签名、int 返回和 NUL 截止行为不变，新增接口保留内嵌 NUL。
5. 更新文档公开面清单，不导出只供模块内部组合使用的辅助函数。

**定向门：** `python3 tests/string/run.py --compiler ./yh --group model,view`。
**关闭条件：** 新 View 项目通过，旧 libsbase 仍精确输出 `yh libs base ok`；
完成 make，文档明确增长 String 仍未完成。

## 4. ST2：无分配切分

**修改：** `libs/string/10_view.yh`、view 项目的 `.yh` 断言。

1. 先写 split 的空源、首尾/连续分隔符、多字节分隔符、源等于分隔符、
   `aaaa/aa`、空 separator 错误与重复 end。
2. 实现 SplitIter、split 和 split_next；明确返回片段来自源，不临时复制，
   out 仅在成功时写入，片段 count 不依赖 strlen。
3. 验证迭代器复制后游标独立；不通过访问已释放源来“测试”悬空视图。
4. 核对所有路径不调用分配器，空片段与 end 使用 status 区分。

**定向门：** 同 ST1 的 view 组。
**关闭条件：** 设计中的切分矩阵和内嵌 NUL 分隔符通过；无分配证据明确。

## 5. ST3：String 生命周期、增长和 C 边界

**新增：** `libs/string/20_owned.yh`、owned/resources/interop 项目。
**修改：** 模型、runner 和文档。

1. 先写 make/from_view/clone/move/release、输入改写、两个独立副本、重复释放、
   零串释放后复用和 as_view 的 `.yh` 断言。
2. 实现私有状态及 alloc/free 接缝、只读长度/容量；所有权转移只清零被转移的
   变量，不引入全局所有者表或引用计数。模型和数据分配失败均回收。
3. 按失败原子性实现 reserve/append/append_byte/assign/clear/truncate；
   扩容提交前保存旧内容，复用容量，始终维护额外 NUL。
4. 增加两类自别名用例：预先 reserve 后不扩容；填至实际 capacity 后追加确保
   扩容。每类覆盖整串与子视图，不假设固定增长倍率；assign 覆盖重叠源。
5. 先验证溢出分支不分配，再用测试模块副本逐次令第 N 个私有分配失败；检查
   内容/长度/容量不变、旧视图仍可读、成功/失败各路径分配释放平衡。
   测试替换接点失配必须失败，不向产品模块导出 test_* 或注入开关。
6. 实现 c_str；测空串、中文、尾部额外 NUL、内容内 NUL 拒绝、失败 data=0，
   不把返回指针交给释放或写入接口。成功变更后重新获取视图，不访问旧指针。

**定向门：** `python3 tests/string/run.py --compiler ./yh --group model,owned,resources,interop`。
**关闭条件：** 所有分配点有失败用例，自别名两种容量条件均通过；容量足够时
追加无分配；失败前后状态/旧指针一致。旧 *char 消费者保持通过。

## 6. ST4：组合、替换与 ASCII

**新增：** `libs/string/30_transform.yh`、transform 项目、
`tests/string/reference.py`（Python 标准库，固定随机种子，测试数据与生成程序放 tmp）。

1. 先写 concat/join/replace/replace_all/lower_ascii/upper_ascii 断言：空片段、
   空 join、空分隔符、limit=0、无匹配、非重叠匹配、替换为自身/空串/NUL。
2. 共享最小长度检查与输出分配实现；join 先算总长，replace 先确定匹配与最终
   长度后分配，失败释放全部临时存储，不能留下部分结果。
3. 空 old 一律报错；replace_all 不用重复递归替换；无变化结果也拥有独立存储。
4. Python bytes 参考只覆盖语义相同部分；空 separator/old 的错误按本库契约
   独立断言，不能照搬 Python 的空模式行为。协议用十六进制保存 NUL/非法 UTF-8。
5. 生成长重复前缀和多个输入规模，记录直接匹配的 O(n*m) 上界与实测；只有
   出现实用阻塞才升级内部搜索算法，不增加机器速度敏感的固定耗时门。
6. 将全部新分配路径纳入 resources，检查每个失败点回收与原输入不变。

**定向门：** `python3 tests/string/run.py --compiler ./yh --group transform,resources`；
`python3 tests/string/reference.py --compiler ./yh --workdir tmp/string-reference`。
**关闭条件：** `.yh` 行为断言和字节参考差分零未知差异；失败/溢出不产出半成品；
ASCII 转换保持全部 >=0x80 字节不变。

## 7. ST5：严格 UTF-8

**新增：** `libs/string/40_utf8.yh`、utf8 项目。
**修改：** reference.py、resources 和文档。

1. 先写 1–4 字节、U+0000、U+FEFF、U+10FFFF、组合序列与非法编码矩阵。
   单列 TOML 拒绝 BOM、string 接受 BOM 的区别，不能直接复制格式规则。
2. 一个模块私有解码核心供 utf8_validate/utf8_next 共用；校验计完整标量数，
   非法结果计数为 0。字节不足时先查剩余长度，再读取续字节。
3. append_rune 使用局部 4 字节数组和既有 append；拒绝代理项/越界标量，
   测非法标量目标不变、合法标量扩容失败目标不变。
4. 验证遍历 cursor 成功推进、end 和错误不推进、越界、续字节起点错误；
   按设计核对 RuneResult.offset/width，区分 NUL 与结束。
5. 用固定边界样本、合法标量抽样和随机字节，与 Python 严格 UTF-8 解码比较
   合法性/标量序列/错误起点；编码方向比较输出字节，差异须解释或修复。

**定向门：** `python3 tests/string/run.py --compiler ./yh --group utf8,resources`；
reference.py 的 UTF-8 参考组。
**关闭条件：** 严格正反例与参考差分通过；无静默替换、locale 或新 C 依赖，
文档不把标量计数说成字素计数。

## 8. ST6：文档、分发、门禁和首期关闭

**新增：** `libs/string/doc.yh`、`libs/string/README.md`。
**修改：** `tests/modules/build-check.py`、Makefile、根 README、标准库总设计、
todo/finish 和完成报告；按既有 Gitea 调用链接入，不重复创建平台流水线。

1. interop 新增 toml.Text→view_bytes 的显式适配、NUL 长度保持和所有者释放；
   不改 TOML 公开类型，不迁移 compiler/gen 或 cli 的私有实现。
2. doc.yh 列出真实 pub 面，README 给出借用/复制/移动/释放、构建字符串、
   split、C 边界和 UTF-8 示例；标注 byte/标量单位及算法上界。
3. 接入 `make test-string`，基本 fixture 登记为 build-check.py 的 stdlib-run
   用例，确保 selfhost-native 的项目门实际覆盖新增库；较重故障/参考组由专项
   门承担，Gitea 的本平台分支门明确调用，不只在开发者手工运行。
4. 检查安装与打包按实际规则包含全部新增 `.yh`，再从 tmp 的独立目录、清空
   YH_STDLIB 验证默认发现；显式环境覆盖也需有用例。测试 fixture 不进安装包。
5. O0/O2 分别运行专项行为/参考组。执行本平台 `make`、`make test-string`、
   `make test`、`make selfhost-native`，保存命令、退出码、用例数、优化级别和宿主。
6. 更新实际接口表、限制、测试矩阵与阶段状态；完成报告放 docs/01-finished/，
   todo 只关闭有证据的阶段。跨平台结论等待 Gitea 实际结果，滚种子另按仓库流程。

**关闭条件：** ST0–ST5 全部验收、旧接口兼容、分发与专项/本平台主门通过；
完成状态与实测证据相符。此时才称 string 首期基础库完成。

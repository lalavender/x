# yh 编译器性能归因口径（阶段计时与内存采样）

日期：2026-10-26。状态：**已实施并通过门禁**（代码见 `compiler/build/{module_build,
build_scheduler,module_worker,llvm_pipeline}.yh`，工具见 `tools/perf-baseline.py`）。
对应 [性能测试方案](yh-编译器性能测试方案-2026-10-23.md) 的 PF2「定位瓶颈」。

## 1. 四段阶段计时（worker 内）

`yh build --stats` 每行追加四个纳秒字段，含义如下。四段**互斥**，都不含链接、
不含 `--emit-llvm` 的 `.ll` 文本写出：

| 字段 | 区间 | 起止 |
| --- | --- | --- |
| `time_front_ns` | 前端 | `mb_emit_indexed_module` 进入 → `check.verify_module` 通过（含 pass1/pass2/bind、编译期求值、check 缓存装载） |
| `time_lower_ns` | lowering | `lower.lower_module_cached` 的整段（含函数级 IR 缓存读取与恢复） |
| `time_irbuild_ns` | IR 构造 | `backend.llvm_emit_module` + 部署元数据（yh 侧把 IRModule 变成 LLVM IR 文本） |
| `time_bridge_ns` | 内嵌桥 | `llvm_emit_with_target`：LLVM 解析 IR 文本 → 优化 → 目标码 → 写对象 |

未归因的时间包括：父进程的装载/索引（`time_project_ns`）、调度与等待
（`time_schedule_ns`）、对象校验/发布（`time_object_ns`）、链接（`time_link_ns`）、
进程启动与退出。所以 `front+lower+irbuild+bridge` 只是**单个 worker 的后端编译工作量**，
不是构建总时间的分解。

## 2. 聚合规则（重要）

- worker 是 fork 出来的独立进程，各自打一行 `yh-stats`；父进程那一行四段为 0。
- **跨行相加 = 累计工作量（worker·秒）**，不是墙钟，也不是 CPU 时间（未含内核态）。
- 与 `time_schedule_ns` 相比得到**有效并发** ≈ 累计 / 墙钟；它包含 worker 之间的
  并行度，也受调度空转影响，不能当作加速比。
- 单轮里 `schedule` 是父进程视角的墙钟，`object/link` 与 worker 时间**不重叠**；
  但 `schedule` 包含等待 worker 的时间，因此 `worker 累计 > schedule` 是正常现象。
- 缺失字段（旧编译器/别的构建形态）一律写「不支持」，不写 0：
  `tools/perf-baseline.py` 的 `stage_missing` 标记与报告里的「不支持」都源自这一条。

## 3. 内存口径

`tools/perf-baseline.py --rss` 每 200 ms 用 `ps -axo pid,ppid,rss` 采样一次被测构建的
**进程树** RSS，取峰值：

- 这是采样峰值，真实峰值可能更高（间隔 200 ms），报告里注明；
- 父子进程共享页会被重复计入，**不等于**并行构建的内存占用；
- 采样本身（起 `ps`）有约 5–7% 的时间开销，所以**默认关闭**：时间批次与内存批次分开跑，
  时间结论一律来自 `--rss` 关闭的批次；
- 要更准的口径需要 cgroup（Linux）或 `proc_pid_rusage`（Darwin），留待 PF2 后续。

## 4. 失效矩阵口径

`tools/perf-invalidation.py` 在三个模块（leaf←mid←main）的工程上逐场景验证：

- 判据是**行为与产物**：程序输出、每个模块对象的 SHA-256 必须与同源码的清缓存构建一致；
- 计数判据来自 `--stats`（不依赖 PATH 包装器）：仅注释 → IR/check 全命中；
  私有函数体 → 只有该函数 miss；公有接口/编译期常量 → 消费者重检；
  缺对象 → 复用缓存重编；缺函数缓存 → 必须 miss 重编，不能把「缺产物的成功退出」当命中；
- priming 只删对象，**不能**删 `manifest/link.manifest`：它是「本轮可写函数缓存」的开关，
  删了会让 priming 退化成冷编（写不出 `.fir`），后续「0 命中」全是假象。

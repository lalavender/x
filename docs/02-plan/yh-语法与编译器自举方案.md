# yh 语法与编译器自举实施方案

**目标**：先证明 `.yh` 写的解析器能解析自身，再得到能编译自身且覆盖当前 yh 语言的 AArch64 Linux 编译器。定义、运行接口和验收口径见 [自举能力边界](../03-design/yh-自举能力边界.md)。

## 1. 基线、假设与路线选择

2026-09-28 的工作树已有大量未提交改动。本方案以该工作树的现状为分析基线，不覆盖或清理这些改动。最近一次 `make test`：ANTLR 语法 66/66 正例、29/29 反例；C 版 `--syntax-check` 同数通过；运行层 22/24，通过率不足以作为自举种子验收。失败为 `run/07-goto-label.yh` 编译时无法暂存 Mach-O 目标文件，以及 `run/08-recursion.yh` 运行被信号 9 终止。先定位原因，再判断是 Darwin 专有故障还是共同后端故障；不能根据此前文档的“24/24”记录推定当前通过。

约束与假设：

- 首个完整闭环只做 **AArch64 Linux ELF**，使用仓库已有的交叉构建路径、sysroot 和 Linux 容器/本机；无运行环境时验收失败，不把 SKIP 计为通过。
- “编译器自举”允许外部汇编器和链接器，禁止 stage1/stage2 通过调用旧 `yh` 或 `libtcc` 解析、类型检查或生成代码。完全去除 C 工具链依赖另立项目。
- stage1 可以用简洁的两遍解析和直接生成 AArch64 汇编，不必复刻 TCC 的值栈和 ELF 链接器。被支持的语言语义仍要与现有设计一致。
- 单个 `.yh` 源文件尽量在 500–1000 行内；先按明确顺序拼接到 `tmp/bootstrap/compiler.yh` 供各代编译器读取，避免为了组织源码立即设计模块系统。

路线比较：

| 路线 | 做法 | 判断 |
| --- | --- | --- |
| **推荐：新写 yh 前端，先输出 AArch64 汇编** | 复用现有语义文档与测试；外部工具只负责汇编/链接 | 最短的真正编译器自举路线；后续可补对象文件写入器 |
| 机械移植现有约 2.4 万行 C 核心 | 重写宏、C ABI、预处理和 TCC 内部状态 | 能保留旧架构，但首次闭环过大，且 `.c` 无法由 yh 直接编译 |
| yh 前端调用 `libtcc` | 通过 C 库代做生成 | 可作实验，不满足本文“编译器自举”的验收定义 |

## 2. 能力清单：必须、条件触发、延后

| 能力 | 当前状态 | 实施决定 |
| --- | --- | --- |
| 从任意输入读取源字节 | prelude 有 `open/write`，无 `read` | **必须**增加 `read(int,*void,u64) i64`；测试 EOF、短读和错误 |
| 写出汇编 | 已有 `write` | 复用；缓冲循环必须处理短写 |
| 核心数据结构 | 指针、struct/union、数组/切片、`malloc` 已有 | 用 `.yh` 编译/运行探针验证递归结点、动态缓冲、指针写入、函数指针与 ABI；失败才修实现 |
| 顶层前向调用 | 现有两遍扫描 | 加互递归与大源码探针；当前递归运行失败必须查清 |
| 输入路径及 `-o` | `main` 当前不能带参 | **CLI 阶段**支持 `fn main(argc int, argv **char) int`，无需新语法产生式；最早的 stdin/stdout 自举不依赖它 |
| 多文件源码 | 无 import/外部原型 | 首轮显式顺序拼接；只有直接多文件编译成为验收要求时才设计 `import`/声明语法 |
| 外部 libc 接口 | 仅内置 prelude 八函数 | 首轮只加 `read`，推荐加 `close`；不开放任意 `extern fn` |
| 输出 ELF | C 版可写 ELF，yh 版尚不存在 | 先发出确定性 `.s`，用目标汇编器/链接器生成 ELF；ELF 自写入非前置条件 |
| 规模限制 | 包装类型登记上限 128、switch 代码有固定容量 | 用编译器工作负载探针确认；命中时改为增长存储或给出明确诊断，不允许越界/静默截断 |

不增加宏、泛型、异常、切片表达式、模块命名空间、内联汇编等与首轮自举无直接关系的功能。

## 3. 代码结构与数据流

计划创建 `src/yh/` 下的 `.yh` 源文件：`model.yh`（token/类型/符号/位置结构）、`buffer.yh`（读取与输出缓冲）、`lexer.yh`、`symbols.yh`、`parse_type.yh`、`parse_expr.yh`、`parse_stmt.yh`、`parse_decl.yh`、`emit_arm64.yh`、`driver.yh`。按需要细分，避免为了凑行数合并无关职责。顶层类型先于使用处放置；函数可由现有第一遍登记机制前向调用。全局名字加 `yh_` 前缀，避免拼接后的冲突。

```text
多个 src/yh/*.yh ──按显式清单拼接──> tmp/bootstrap/compiler.yh
                                         │
                                现有 C 版 yh（stage0）
                                         ↓
                              Linux 可执行 stage1
                                         │ 读取同一 compiler.yh
                                         ↓
                              AArch64 汇编 → 汇编/链接 → stage2
                                         │ 读取同一 compiler.yh
                                         ↓
                              AArch64 汇编 → 汇编/链接 → stage3
```

编译器内部按“读取完整输入 → 词法分析 → 登记类型及顶层函数签名 → 解析函数体并检查类型 → 输出汇编”推进。对解析器，优先使用递归下降与直接发码；仅在短路表达式、复合值调用等处保留必要的临时表示。汇编标签由单调计数器生成，源文件路径和时间戳不写进输出，从而可以比较 stage2/stage3。字符串与全局数据单独汇集后发出；代码段/数据段与 AArch64 调用约定由 `emit_arm64.yh` 负责。

## 4. 分阶段任务与验证门

### B0：冻结可用种子与测试口径

- [x] 复现并定位 `07-goto-label` 与 `08-recursion`。分别在 Darwin 和 AArch64 Linux 路径运行；给实际根因增加/收紧 `.yh` 用例，只修直接相关代码。**验证**：`make`、`make test` 和 Linux 交叉运行全绿；跳过项单独报告。
- [x] 为 `tests/yh/check.py`、`tests/yh-run/check.py` 增加可选编译器路径和工作目录参数，保持默认调用方式与判定结果，生成物统一迁到 `tmp/`。**验证**：同一语料可分别针对 stage0/stage1/stage2 运行，产物均落在 `tmp/`。
- [x] 建立缺口矩阵：当前语法用例与运行用例逐项对照。**验证**：明确标出 struct/union、数组按值、切片、函数指针、变参、浮点、ABI 等尚无运行覆盖的项目；不可用语法通过率代替这些项目。

### B1：让 yh 程序读得到源码

- [x] 在 `src/core/yh_builtin.c` 登记 `read`，同步 `docs/yh.g4` 和语义边界文档；按实际需要登记 `close`。**验证**：新增 `tests/yh-run/run/` 的 `.yh` 用例从 fd 0 分块读入并写到 fd 1，分别检查空输入、超过缓冲区大小的输入、二进制零字节与短读；非法 fd 返回负值且程序正常处理。每次代码修改后执行 `make` 与相关测试。
- [x] 写最小 yh 字节缓冲封装，容量增长使用 `malloc`/`memcpy`/`free`，长度与容量用 `u64`。**验证**：1 字节、跨扩容边界、含 NUL、至少 1 MiB 输入逐字节一致；分配失败有明确错误而不是越界。
- [x] 在 `src/core/yh_decl.c` 放宽 `main` 检查为无参或 `(int, **char)` 两种签名，并在目标 ABI 上核对 `argc/argv`。**验证**：新增 `.yh` 运行正例输出参数个数及字符串，负例拒绝错误参数/返回类型；零参旧用例不退化。理论上的标准流闭环不依赖此项，但本计划在 B3 前完成，以便复用现有测试语料的文件路径。

### B2：用编译器工作负载验证语言实现

- [x] 新增 `tests/yh-run/run/` 探针：递归与互递归、`struct Node { next *Node; ... }`、局部及全局指针写入、函数指针传递/调用、字符串/字节缓冲、`u32/u64` 位移与符号扩展。**验证**：各探针在 Linux 目标运行结果与预期一致，失败项先修现有 C 版编译器。
- [x] 补齐聚合值与 ABI 探针：struct/union 字段、数组值复制和参数/返回、切片视图、类型化变参、超过 8 个整型参数、浮点参数/返回。**验证**：实际 Linux 运行用例通过，不仅是 `--syntax-check` 通过。
- [x] 对 128 个以上包装类型、129 个 switch 比较/分支、长标识符和大源文件作有界压力测试。**验证**：正常支持合理规模，或在明确规定的容量处干净报错；为自举源码实际规模设置留量，不能靠不触发上限蒙混过关。

### B3：用 yh 写出能解析自身的前端

- [ ] 建立显式的 `SELFHOST_SOURCES` 顺序与 `tmp/bootstrap/compiler.yh` 拼接规则；拼接前核对每个输入后缀为 `.yh`。**验证**：重复拼接字节一致，源文件有清楚的类型先声明后引用顺序，所有中间文件在 `tmp/`。
- [ ] 实现字节流词法器。**验证**：`tests/yh/11-lex/` 正反例和数字/转义边界与 `docs/yh.g4` 一致；包含 NUL/非法转义的输入明确失败。
- [ ] 实现类型、声明、表达式与语句解析，以及 `--syntax-check file.yh` 路径；文件路径由 B1 的 `argc/argv` 和 `open/read` 获取。**验证**：解析器读取 `compiler.yh` 自身并消费到 EOF；`tests/yh/` 的全部正例接受、全部反例拒绝；对语义错误但语法合法的用例不误拒。

**语法自举门**：stage0 编译出的 yh 解析器，在不调用 ANTLR/TCC 解析服务的情况下，解析自己的完整 `.yh` 源码；其语料结果与参考语法一致。达到此门仍不称为编译器自举。

### B4：生成可执行的自身子集

- [ ] 实现符号/类型表及两遍顶层扫描，按现有设计处理类型先声明、函数前向调用、块作用域和 const。**验证**：未定义名、重定义、错误类型被编译模式拒绝；互递归正确运行。
- [ ] 实现 `--emit-asm file.yh`，把 AArch64 Linux 汇编写到标准输出；发射器覆盖标量、指针、分支、循环、调用、栈帧、字符串和全局数据。**验证**：逐类 `.yh` 用例从源文件生成 `.s`，用目标汇编器/链接器生成 ELF，在 Linux 运行并比较输出/退出码。
- [ ] 为测试增加仅负责“调用 stage1/stage2 → 汇编 → 链接”的适配驱动，向现有运行测试提供可执行文件；适配驱动不得解析或改写 yh 源码。**验证**：同一小用例分别经 stage0 与该驱动运行，测试框架可比对输出和退出码。
- [ ] 加入 `src/yh/` 编译器自身实际使用的结构体、数组/切片、函数指针等 ABI 规则。**验证**：stage1 能把同一份 `compiler.yh` 编译成 stage2，stage2 能运行。此时仅称为“自身子集闭环”，不能替代 C 版。

### B5：补齐当前 yh 语言

- [ ] 对照 `docs/yh.g4` 和语义边界，实现尚缺的聚合值、structInit、for-in、switch、goto、类型化变参、浮点、转换与错误拒绝规则。每一项先放 `.yh` 用例，再实现。**验证**：stage1/stage2 通过全部语法、编译、运行和拒绝用例；与 stage0 的规定行为一致。
- [ ] 如果既有用例没有覆盖某个 `docs/yh.g4` 产生式的运行语义，补对应 `tests/yh-run/` 用例；对设计中明确只允许语法而不允许编译的形态增加拒绝用例。**验证**：覆盖矩阵无空白，不能仅以编译器源码能自编为完成。
- [ ] 最后接入 `-o` 等必要 CLI；文件输入在 B3 已完成，汇编/链接仍由外部工具完成。**验证**：用户无需手工管道即可得到 Linux ELF；`--emit-asm` 的标准输出模式继续用于确定性自举测试。

B5 的覆盖矩阵按下表逐行关闭；同一行至少有语法接受/拒绝与实际编译/运行两类证据，纯语法形态则以明确的编译拒绝代替运行：

| 语言部分 | 必须验证的边界 |
| --- | --- |
| 词法与顶层 | 数字基数/转义/注释/保留字、显式分号、`pub`、多个声明、EOF 后无残留 |
| 声明与作用域 | `let`、`const`、`type`、`fn`、struct/union/enum、前向调用、互递归、重定义与未定义名 |
| 类型与调用 | 标量、指针/函数指针、数组按值、切片视图、结构体布局、类型化变参、C prelude 变参、超过寄存器数的参数 |
| 表达式 | 各级优先级、短路、三元式、赋值/复合赋值、成员/下标、structInit、`.to_type(T)`、`sizeof(T)`、`len(e)` |
| 控制流 | `if`、三类 `for`、`switch` 多值/default、`break/continue`、label/goto、return、不可达代码 |
| 目标程序 | 全局数据、字符串、整型与浮点返回、进程退出码、外部符号与 ELF 运行结果 |

### B6：正式三代自举与替换门

- [ ] 增加 `make bootstrap` 或等价脚本：明确目标工具链/sysroot，按 stage0→stage1→stage2→stage3 构建，所有生成物写入 `tmp/bootstrap/`，失败即停止。**验证**：没有 Linux 可执行环境、汇编器或链接器时明确失败，不把 SKIP 计为通过。
- [ ] 对 stage1/stage2 分别运行 `tests/yh/` 与 `tests/yh-run/`，并用独立用例覆盖源码读取、错误输入、递归、聚合值和 ABI。**验证**：正例、反例、运行输出与退出码全部通过，编译器进程不崩溃。
- [ ] stage2、stage3 对固定 `compiler.yh` 和一组代表性程序生成一致的规范化汇编；由两代构建的 ELF 运行结果一致。**验证**：构建日志记录各代 SHA-256、工具链版本、测试汇总；仅删路径/时间戳后比较输出，不删实际代码或数据。
- [ ] 满足全部验证门后，才考虑把默认构建切到 yh 实现；保留 C 版 stage0 作为可复现种子和差分参照。**验证**：干净环境重复 `make`、`make test`、`make bootstrap`，并检查不再在 stage1→stage2 路径调用旧 yh/libtcc。

## 5. 风险与停止条件

1. **种子不可靠**：当前递归用例崩溃；如果 Linux 路径也重现，先修 C 版，否则后续自编结果无可信基础。
2. **语法覆盖与运行覆盖混淆**：现有 95 个语法文件可包含未定义符号；它们不能代替编译/运行测试。B5 验收按功能矩阵逐项落实。
3. **ABI 差异**：数组/切片、结构体、变参、浮点和超过寄存器数量的参数最容易在 stage1/stage2 间分歧；每项先用小型真实程序验证。
4. **现有固定容量**：自举源码比示例程序大，必须明确检查包装类型、switch 和词法缓冲容量；不能默默截断或越界。
5. **外部依赖边界**：外部汇编/链接可以保留；若 stage1 仍调用 C 版 yh、libtcc 或 C 编译器解析 `.yh`，自举门失败。

## 6. 交付物

完成时应有：`src/yh/` 中的编译器源码；`make bootstrap`；stage1/2/3 的可重复构建记录；新增 `.yh` 正反与运行用例；更新后的 `docs/yh.g4`、语义设计、README、`docs/todo.md` 和 `docs/finish.md`。每个代码改动按仓库约定执行 `make`，新增对应 `.yh` 用例并确保相关测试通过。

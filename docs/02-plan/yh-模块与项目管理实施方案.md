# yh 模块与 mod.toml 项目管理实施方案

日期：2026-09-29。状态：计划，尚未实施。

以 [模块与项目设计](../03-design/yh-模块与项目管理设计.md) 为当前规则，
取舍见 [ADR-0005](../adr/0005-yh-mod-toml与按名称导入.md)。
本方案替代上一版 PKG-U0–U8，不把旧清单或 internal 规则继续列为任务。

## 1. 成功标准

一个 mod.toml 项目包含多文件库模块和入口模块，能够按“本项目 →
标准库 → 本项目直接依赖”绑定裸名称 import，执行可见性检查并真实
链接运行。依赖源码中的导入按其所属项目解析，错误不能触发低层回退。

旧单文件、自举回归继续通过。语法通过、源码拼接成功、TOML 示例能解析
都不能代替模块构建通过。

## 2. 阶段与验证门

| 阶段 | 修改内容 | 验证门 |
| --- | --- | --- |
| MOD-U0：基线 | 确认最新单文件、调用 ABI、自举与 CLI 行为；确定项目模式兼容边界 | make、make test；适用的 selfhost-native/bootstrap/G3，不沿用旧计数 |
| MOD-U1：语法和文件身份 | module/import IDENT、限定类型／值、pub 字段、FileID 与文件导入表 | ANTLR、stage0、自举语法正反例；未知模块不影响纯语法检查 |
| MOD-U2：项目与解析 | TOML 解析和 schema、源根发现、module 索引、三层搜索与导入者上下文 | 清单错误、三层优先级、同名歧义、不回退、无网络隐式获取、传递依赖拒绝 |
| MOD-U3：模块语义 | 多文件登记、模块作用域、类型身份、pub、导入 DAG、入口与库 | 跨文件私有／递归、限定类型与字段、别名不泄漏、环路原位置诊断；internal 普通处理 |
| MOD-U4：完整本地链 | 本地第三方项目、模块对象／接口、项目限定符号、ABI 校验与最终链接 | 两项目真实运行；同名类型／符号隔离；聚合、浮点、变参、间接调用；接口不兼容拒绝 |
| MOD-U5：缓存与自举构建 | 解析缓存有效性、对象缓存、完整自举清单／目录发现与项目 CLI | 新增本地同名模块触发重绑定；冷热一致；自举 build/run 和三代验证 |
| MOD-U6：后续设计 | 按需求另定远程获取、版本规则、锁文件与工作区 | 先补设计和独立验收用例，不提前承诺旧 Go 路径或版本算法 |

第一个完整交付门为 U1–U4，U0 是前置确认。U5 单独验收完整自举项目
构建能力。U6 不阻塞本地模块交付，也不与语言语义混成同一完成状态。

## 3. 实现顺序

先定义 ProjectID/ModuleID/FileID，再接模块索引和 ImportBinding。
模块名不是机器符号身份；缓存查询必须带导入者项目上下文。

项目清单用 TOML 解析器和明确 schema。首版依赖来源只支持 path。
stage0 可用宿主已有能力，自举侧补最小输入／目录能力；不要求用户
长期手工拼接源码，也不引入完整 AST 作为前提。

头部索引与业务编译分离。绑定完成后固定提供方，检查可达模块图，先
登记同模块全部签名和类型，再检查函数体。访问失败不得重新搜索名字。

独立对象、稳定接口和最终链接一起验收。接口区分可访问名字与所需
类型闭包，保留目标、ABI、生成器与格式版本。私有名字不能靠机器 GLOBAL
绑定绕过语言检查。

当前 stage0 接入路径使用 src/core/ 下的词法、yh_decl/yh_type/yh_expr
与驱动；自举使用 compiler/ 下对应模块。只在实际实现时修改 grammar
和代码，新函数／结构体采用详细中文注释，避免顺手重构无关职责。

## 4. 测试组织

新增 tests/modules/ 项目 fixture runner，每个 fixture 用 mod.toml
和 `.yh` 源码表示真实项目；第三方和标准库候选通过可控测试来源提供。
不把多文件用例交给单文件 runner 后假装验证了 import。
产物与验证日志统一放 tmp/。

必须覆盖以下矩阵：

- 本地、标准库、第三方同时同名；缺少高层时逐层匹配。
- 高层模块解析／语义错误、缺成员：报原错误，不回退，不拼接成员。
- 两个第三方项目同名：报告提供方歧义；同模块多文件则合法合并。
- 依赖自己的本地模块和直接依赖：不被主项目同名模块覆盖。
- 传递依赖不能直接借用；清单来源缺失不能静默跳过。
- 模块名不随文件移动改变；同模块重复声明报告两个文件的位置。
- pub 值、类型、常量、字段，私有拒绝，公开接口的类型布局完整。
- 项目名／模块名参与类型和链接身份，同模块全局存储只生成一份。
- internal 目录与普通目录一致，没有特殊可见性检查。
- 自循环、直接环、间接环；同模块跨文件函数互递归允许。
- 新增本地 os、删除本地 os、改清单／标准库／第三方来源后缓存重绑定。
- 库模块无 main，入口唯一，入口模块不可作依赖导入。

每次代码修改都新增对应 `.yh` 用例并执行 make；阶段完成执行 make test
和适用的自举门。语法、拒绝、编译、运行、缓存分别报告；SKIP 不算通过。

# yh 编译期类型表达式依赖求解方案

日期：2026-10-06。状态：**首版已完成**。

## 目标

把 pass1 数组长度表达式和 typed CT 函数中的 pending `sizeof` 接入协同固定点调度。支持
既有整数表达式、显式 `$comptime_fn(...)` 与算术组合；按依赖就绪顺序完成可解请求。

## 范围

- 数组长度接受完整整数常量表达式，包括 `$f(...)`、算术、已声明或后续声明的整数 const。
- 仅明确 `$` 调用在全局类型表达式中执行 CT 函数；普通函数调用仍不作为编译期过程。
- typed `@[comptime]` 函数可捕获 pending 类型的 `sizeof(T)`，调用求值必须等待 T 布局 READY。
- 延续现有 READY/预算/整数范围检查；pending 类型不进入常规代码生成。
- 普通全局 const 的声明顺序不变；跨模块 CT 函数正文、运行期参数化类型、反射仍属于
  CT5B/CT6。

## 求解流程

1. pass1 只对含 `$`、未就绪整数 const 或 `sizeof` 的数组长度保留 token 半开区间和文件
   身份，并创建显式 pending 数组；已有可立即折叠的长度继续走原路径。
2. typed CT 函数捕获可记录 pending `sizeof` 的目标类型，不伪造大小；调用检查发现其
   IR 仍依赖 pending 类型时，调度器暂缓调用。
3. 单文件与模块 worker 每轮尝试可运行的布局 const 和数组长度表达式，再推进数组/结构体
   布局；刚完成的布局可开放后续 CT 调用，直至无待办或无进展。
4. 可确认的常量依赖环保留闭链诊断；普通非候选前向 const 保留“编译期常量尚未就绪”；
   值与布局互相阻塞时报告“编译期布局依赖环或未完成依赖”。首版不输出混合图的完整路径。

## 验收

- 新增正例：带前向 typed CT const 的 `$f(...) + 常量` 数组长度表达式。
- 新增正例：一个 pending 类型先由独立 CT 常量完成，再供另一 typed CT 函数 `sizeof`，
  最终决定后续类型长度。
- 环反例：`N = $f()`、`f` 查询 `sizeof(S)`、`S` 又以 `[N]` 为字段，诊断包含布局环类别。
- 保留普通前向 const、非整数/越界长度、递归预算和现有普通表达式语义回归。
- 执行 `make test`、`make selfhost-native`、`git diff --check`；全绿后滚种子并冷编。
- 更新过程设计、CT5A 待办、运行测试说明、完成流水与阶段记录。

# S4-2 表达式/语句语义外置实施方案（2026-11-10）

> 状态：**进行中**，本文件是 S4-2 全量的施工方案；每完成一片就在

## 1. 目标与验收

S4 的总目标是「parse 纯语法 + check 独立」：parse 只按 token 造 `ast` 节点，
语义（类型、常量、绑定）由 check 从节点算。S4-2 落的是**表达式与语句**这一层。

验收（分片累计，最终态）：

1. `compiler/parse/parse_expr.yh`、`parse_stmt.yh` 的 `check.*` 引用降为 0；
   `tests/tools/front-coupling/check.py` 的 `parse→check` 预算随之单调下调到 0。
2. 正常编译产物逐字节不变：`--emit-asm` 与种子 `bin/yh-darwin-arm64` 差分；
   诊断（消息/行列/顺序）逐字节相同。
3. `just test` 与 `just selfhost-native`（两代固定点 + 自解析）全绿。

## 2. 现状（2026-11-10 实测）

- `parse→check` 引用共 198 处（预算口径 194，剥离注释后）：`parse_expr.yh` 80、
  `parse_stmt.yh` 29、`parse_decl.yh` 25、`parse_comptime.yh` 24、`parse/api.yh` 14、
  `parse_global_init.yh` 12、`parse_interp.yh` 8、`parse_type.yh` 5、
  `parse_ct_layout.yh` 1、`iface_ct.yh` 1。
- **关键事实**：正常编译路径里 `ast_capture = 1`（`build/module_worker.yh:191`），
  所以表达式/语句节点在真实构建中**已经带着 legacy 语义注解**
  （`ast.ast_expr_set_semantics(id, res)` 把 `type_id/sym/is_const/const_bits/
  is_lit/lit_big/fval_bits/layout_type_id` 写进节点）。这给了一个零成本影子门：
  同一次运行内，「check 从节点重算」与「parse 当场算」两份结果可以逐节点比对。
- `ast` 目前只对外暴露少量 getter（`ast_expr_start/end/op_set/first_of/
  count_now/depth_*`），节点字段在模块私有数组 `ast_expr_nodes` 里。check 要
  重算就必须先有**读节点**的公开面（`kind/op/type_id/sym/const/left/right/
  child/参数表`）。
- `parse` 里的 `check.*` 调用按职责分三类，处理策略不同：
  - **(A) 折叠与类型计算**：`sem_number`、`sem_binop`、`sem_unary`、
    `sem_promote`、`sem_lit_fits`、`sem_res_const`、`sem_len`、`sem_sizeof`、
    各 `sem_reset/res_copy`。可从节点重算，是 S4-2 的主体。
  - **(B) 消歧判定**：`parse_ident_primary` 的 `sym_lookup` 判定结构体字面量、
    `sizeof_type_path`、`type_name_exists`、`type_length_sym`、`sem_lit_field_lookup`。
    这些决定**怎么解析**，不能后移；S4-2 只收敛成少量窄口入口（已经是
    `check.sizeof_type_path` 这种形态），真正消失要等 S4-4 的语法决策自足化。
  - **(C) 绑定与登记**：`sem_declare_local`、`sym_push`、`sem_check_duplicate`、
    `ct_*`。属于作用域/编译期状态，留给 S4-3（CT 展开下沉）与 S4-4。

因此 S4-2 的正确形状不是「把 80 个调用逐个换个名字」，而是：

```
parse_expr  ──造节点──▶  arena(带 token 区间与结构)
                            │
                            ▼
                     check.full 后序重算 ──▶ 节点注解（type_id/sym/常量）
                            │
                            ▼
                     lower 读注解（不再读 parse 的 Res）
```

阶段期允许 **双跑**：parse 仍算一份（供 lower 与既有诊断用），check.full 算一份，
两者必须逐节点相等——这就是影子门的判据。所有分片都在这条「双跑相等」的门下推进，
最后一片才把 lower 的读点切到注解、把 parse 的语义调用删掉。

## 4. S4-2a 具体改动（已落地）

落地时的两处关键修正（写下来避免后续分片再踩）：

1. **判定口径按「旧路径已折叠」**：旧 parse 只在 `c_fold` 上下文（const 初始化式、
   数组长度等）折常量，普通函数体里的 `1 + 2` 不折叠（注解 `is_const = 0`）。
   所以影子门只判定 `is_const != 0` 的节点；对非折叠上下文强行比对会把「旧路径
   本来就不折」误判成不一致（实测节点 6 即此类）。
2. **挂点位置**：函数体在 `mb_pass2_file(..., 0)` 子遍才解析，影子门必须挂在
   「函数体全部解析完」之后；挂在 CT 捕获子遍之后会得到空 arena（实测 nodes=0）。
3. 覆盖为空算失败（空转守卫），但按**整个构建**累计，不逐模块要求：没有折叠
   常量的模块本身合法。实测标准库里有完全不含折叠常量的项目（`libs/time`
   消费者构建），所以运行时守卫已撤，非空性由夹具保证。
4. **名字判定要绑定同一性**：局部 const/形参在影子门运行时作用域已弹出，
   重新查名可能落到外层同名符号（实测 `libs/string/api.yh` 直接报「引用了未声明
   的名字」）。先 `sym_lookup` 与注解 `sym_id` 比对，不同就跳过。

1. `compiler/ast/api.yh`：新增只读访问器
   `ast_expr_kind/op/type_of/sym_of/semantics_of/child_of/left_of/right_of/
   args_of`（均按 `id` 或 `node_id` 直接读私有数组）。
2. 新增 `compiler/check/full.yh`：
   - `pub fn full_verify_module() int`：遍历本模块全部表达式节点，调用
     `full_node` 重算，返回不一致条数（附带首个不一致的节点下标与原因）。
   - `full_node(id, *Res)`：本片只覆盖 `PRIMARY`（整数/浮点字面量）、
     `UNARY`、`BINARY`；未覆盖的种类返回技能码 `-2`（表示「本片不判定」），
     不计入不一致。
   - 折叠复用现有内核（`sem_num_is_float`/`sem_parse_number`/`sem_lit_fits`/
     `sem_promote`/`sem_fold_const_binop`/`sem_fold_const_unary`/
     `sem_res_const`），与 `check/const_eval.yh` 的求值器同一套语义。
3. `build/module_worker.yh`：`YH_AST_FULL_CHECK=1` 时在解析完当前模块后调用
   `check.full_verify_module()`，非 0 即返回 -1 并打印首个不一致节点。
4. `tests/tools/front-full/check.py`：用带常量算术/一元/字面量的夹具跑
   `YH_AST_FULL_CHECK=1 yh check`，断言通过；接入 `just test`。

本片**不改**任何既有语义调用，产物与诊断零风险；影子门只能「多发现」，不能「改行为」。

## 4b. S4-2f 施工进度（2026-11-11）

已落地：
- **回填通道**：`ast.ast_expr_fill_semantics` 写语义结果字段（不碰绑定快照），
  `check.full_fill_file` 逐文件回填，worker 用 `YH_AST_FULL_FILL=1`（先 verify 再
  fill，lower 消费回填值）；`just front-shadow` 同时开 verify+fill。
- **删除死语义调用**（parse→check 基线 161 → 110）：`sem_ternary_*`（标签栈已无消费者）、
  `sem_shortcircuit/_end`（折叠值内联）、`sem_stash_lvalue`、`sem_len`、`sem_bool`、
  `sem_forin_set_bind/check/load/step`（lowering 接管后的空实现）、
  `sem_forin_begin/end`（深度簿记内联）、`sem_struct_lit_begin/end`（上下文栈
  无消费者，目标类型改参数传递）、`sem_forin_elem_type`（元素类型内联）。
- **纯类型操作下移 `table`**：`ty_ptr`/`ty_slice`/`ty_sig_param`/`ty_add_name_attrs`/
  `sym_mangle`/`tname_mangle`/`ty_field_lookup`（ADR-0021 的「值规则」侧）。
- **FrontCtx 随删随清**：删调用后失去读者的 `tn_*`/`sc_*` 标签栈、`c_fi_*` 迭代槽、
  `c_lit_save_*`/`c_lit_tid`/`c_lit_off`、`c_temp_off` 与 `sem_init_tables` 中对应
  的分配/校验一起移除（B4 的前置收缩）。
- **类型导向重算 `full_expr_at(id, expect, out)`**（S4-2f 关键前提）：父级把目标类型
  传给子节点——调用实参按签名形参位（`sig_params[sfirst+pos]`，ARG_LIST 逆序单链）、
  聚合元素/字段值、三元两支、括号透传；聚合字面量（ARRAY/STRUCT_INIT）比对
  「上下文推导 vs 解析期记录的 `expect_type_id`」，不一致即 -1（漂移）。操作数位置
  （二元/一元/cast/index/member/slice 的子节点）保持无上下文——其类型由自身推导，
  与 parse 的 `sem_*` 同源。语料 + libs 全绿（381/383，跳过 2 个平台专属）无漂移
  报错，证明聚合目标类型可不经 parse 的 Res 独立重建——这是「先纯语法、后 fill」
  切换能保持产物不变的依据。
- 剩余 110 处是 ADR-0021 定义的「语义动作」（can_assign/sym_push/binop/push_arg 等，
  会写类型表并带 token 诊断）与绑定登记、CT、类型语法；删除它们必须先完成
  **语法决策自足化**（parse 的后缀/字面量上下文判定不再依赖当场类型），属 S4-4。

## 4c. S4-2f 施工设计（2026-11-11 定稿）

实测结论：`lower` 已只读快照注解（`support.fc()`/`check.sem_*` 零引用），所以
S4-2f 只需把「parse 算一遍」换成「check 算一遍并写回节点」，产物就不会变。

1. **补齐可重算输入**（只加数据，不改行为）：
   - `AstExpr`/`CtExpr` 末尾加 `expect_type_id`（聚合字面量的目标类型；镜像必须同步，
     `check/api.yh` 有 `sizeof` 相等的运行期守卫）。
   - `CAST`/`sizeof(Type)` 的目标类型不新增字段：按节点 token 区间在类型 arena 反查
     根类型节点（已用于 S4-2d 的 `CAST`），`type_resolve` 重解。
2. **fill 通道**：`check.full_fill_file(file_id)` 按节点升序重算并写入
   `type_id/sym/is_const/const_bits/is_lit/lit_big/fval_bits`（不写快照字段）。
   先以 `YH_AST_FULL_FILL=1` 与 parse 注解逐字段比对（影子门升级），全语料一致后
   再切为唯一来源。
3. **诊断位置**：重算时把 `token.ctx().pos` 设到节点右端（折叠内核已这么做）；
   逐个核对 `sem_*` 的诊断位置是否等价，等价前不删调用。
4. **删除顺序**（每步独立可回退）：`parse_expr` 的字面量/一元/二元/后置链
   → `parse_stmt` 的表达式型语句 → 保留 (B) 查表判定与 (C) 绑定/登记。
5. **门禁**：每步 `just front-shadow`（yh-run 语料 + `libs` 全模块，带
   `YH_AST_FULL_CHECK=1`）→ `just test`（含自举 `selfhost-native`）两代固定点，
   产物与诊断逐字节不变。

## 4d. 剩余 110 处的分类与自足化清单（2026-11-11 实测）

| 类别 | 代表调用 | parse 侧依赖 | 自足化需要 |
|---|---|---|---|
| 类型/常量计算 | `sem_binop`(8)、`sem_unary`(3)、`sem_cast`(2)、`sem_sizeof`(3)、`sem_member/index/slice`(4) | 父表达式继续计算、数组字面量上下文、`.成员` 判定 | 表达式改「先纯语法后 fill」，父级只读 fill 结果 |
| 赋值/实参兼容 | `sem_can_assign`(17)、`sem_push_arg`(7)、`sem_call*`(6) | 实参类型检查与 `c_expect_tid` 上下文 | 实参类型由 fill 提供；调用上下文按语法规格记录 |
| 绑定/登记 | `sym_push*`(9)、`sem_ident*`(5)、`sem_declare_*`(4)、`ty_declare_name`(3)、`sem_check_duplicate`(2)、`sem_add_field`(1) | 名字解析与重复检查 | 移到语法后的「登记 pass」或 table（按 ADR-0021 边界再定） |
| 类型语法判定 | `type_resolve`(1)、`sizeof_type_path`(1)、`type_array_length`(1) | 解析期歧义判定 | type_syntax 依赖 proj/comptime，不能下移；改为 parse 只记类型语法节点 |
| CT / 接口 | `iface_ct_*`(6)、`checked_*`(6)、`parse_comptime` 的 13 处 | 编译期展开决策 | 属 S4-3（结构性 `$if`/`$for` + `check.expand`） |

结论：删除顺序必须是「计算 → 兼容检查 → 绑定登记 → 类型语法/CT」，前两类需要先把
表达式树改成纯语法节点 + fill，后两类再逐个判定能否下移。每一类都可独立回退，
门禁统一用 `just front-shadow` + `just test` + `selfhost-native`。

## 4e. S4-4 改版施工普查（2026-11-11 实测，类型导向 fill 落地后）

**已验证前提（本批影子门证据）**：
- expect 机制对齐：parse 的 `c_expect_tid` 写点与 fill 的 `full_expr_at` 传递
  一一对应——数组元素（parse_expr:286 / full_array）、调用实参（:830,:1281 /
  full_call）、结构体字段（parse_expr:2072 / full_struct_init）、$打包（:1467,
  :1527,:1624）；运行期三元不设 expect、分支继承环境值（full_ternary 传同值即镜像）。
- 字面量注解不被窄化改写：u8 字段里的 `200` 注解仍是 i32，expect 只影响
  **接受性**——`full_literal` 无需 expect 感知；范围拒绝发生在父级 can_assign。
- can_assign 镜像已补两处（影子门绿，无假红）：数组元素（镜像 parse_expr:293，
  big 位实传）、结构体字段（镜像 `sem_struct_lit_field`，big 位硬编码 0）。
- 运行期 `?:` 无 parse 侧合流（结果=中支 Res 原样），分支兼容留给语句级检查。

**施工单元（不可分片，一次改完表达式层）**：
- parse_expr 链内联语义全删：`sem_binop`(8)、`sem_unary`(3)、`sem_cast`(2)、
  `sem_sizeof`(3)、`sem_member/index/slice`(4)、`sem_ident*`(4)、
  `sem_string/char/number`(3) ≈ 27 处——postfix 链的中间 Res 只喂下一级 sem_*，
  纯语法化后中间类型无需在 parse 现场存在。
- 实参/调用 ABI（`sem_push_arg`(7)/`sem_call*`(6)）随调用节点进 eval：eval 按
  parse 同序重放（`sem_call_begin` → 逐实参 `sem_push_arg` → `sem_call`），
  `c_args`/`c_call_base` 等现场由 eval 写。
- 语句/声明/全局 eval 点位 ≈ 20 处（parse_stmt 4、parse_expr_iso 9+、
  parse_type 数组长度 2、decl/global 包装），每处
  `check.sem_eval_subtree(node, expect, &res)`；语句级 `sem_can_assign`（decl/
  global/赋值/return）、绑定登记、类型语法保留在 parse。
- 净效果：预算 110 → 约 95；**度量失真**——总数不再反映目标。守卫已按类别
  计数（2026-11-11 落地）：表达式内联 A 类按符号集 × 三文件实测 **47**
  （parse_expr 34 / parse_interp 7 / parse_comptime 6）锁定只减不增、达标线 0；
  `sem_eval_subtree` 点位预算 ≤25；总数 110 保留作外帽。
- 已知风险：sem_call 实参兼容有三条特殊路径（数组→指针退化、C-ABI 回调、
  类型化变参），eval 直接调 `sem_call` 本体即可精确复刻；多错误语句的错误
  次序（eval 在表达式完成后触发，语义错误先于同语句后续语法错误）。

**fill 侧生产缺口剩余**：调用实参兼容不进影子门（特殊路径盲镜像会假红），

### 4e-2. 切换形态定稿（2026-11-11：二元层已落地）

**原设计走不通的三处，已实测确认**：

1. **「先建节点、后求值」与 `ast_expr_add` 的 type_id 约束冲突**。非结构化节点
   原先必须带语义类型，因此节点只能等语义算完再挂；而增量 eval 要读子节点注解，
   在构造顺序上必须是节点先存在。→ 新增 `ast.ast_expr_finish_pending`（只记
   `kind/op/token 范围/子节点`，`type_id` 暂缺，由 eval 回填）；`ast_expr_add_inner`
   收拢不变量，`pending=0` 的旧入口行为不变。
2. **`$for` 模板后续轮次没有节点，语义却必须照算**。`parse_comptime` 在 round > 首轮
   置 `ast_capture = 0`（AST 节点有 `ct_charge_expansion_ast_node` 计费），而
   `compile` 仍为 1：数组长度/常量初始化式按当轮 `$for` 变量取不同值，语义不能跳。
   → 每层 eval 入口必须同时支持**节点模式**（读子节点注解）与**算子模式**（用现场
   `Res`），后者是长期形态而非临时回退。因此「A 类 = 0」的可验证含义是：**parse 只
   调用少量 eval 入口，入口内部再分模式**，而不是「parse 完全不碰语义内核」。
3. **驱动不能复用影子门的折叠判定**。`full_binary` 用注解 `is_const` 反推「旧路径是否
   折过」（`c_fold` 只在 parse 现场存在，拆解后消失）；驱动模式下节点刚建、注解为空，
   反推不成立（会把折叠当运行期或反之）。→ 驱动入口直接用现场 `c_fold` 调
   `sem_binop`/`sem_unary` 等内核，`full_*` 继续只服务 `YH_AST_FULL_CHECK` 影子门。

**第一片（二元层，已落地）**：8 个二元优先级层改为
`pe_bin_eval(op, first, left_ast, right_ast, res, &rhs)`（parse 内唯一引用点）——
挂待求值 `AST_EXPR_BINARY` 节点 → `check.sem_eval_bin(op, node, lhs, rhs, &out)` →
`Res` 回写。守卫实测：`parse→check` 174 → **167**，A 类 47 → **39**，eval 点位 **2**。
门禁 `just dev` / `just test` / `just front-shadow` / `just selfhost-native` 全绿。

**影子门在此片上部分自证**：二元节点的注解由 eval 写入，`full_verify` 的重算同样走
同一内核，因此这些节点的比对不再独立（剩余价值来自其它层与回填通道）。逐层推进时
每层都要以全量语料/运行语义作主证据，不能只看影子门。

**第二片（一元层，已落地）**：`- + ! ~`、`*`、`&` 改为 `pe_un_eval(op, first, res)` →
`check.sem_eval_un(op, node, operand, &out)`——操作数取子节点注解、语义仍由
`sem_unary` 内核给出。守卫实测：`parse→check` 167 → **165**，A 类 39 → **36**，
eval 点位 **3**；门禁四条（dev/test/front-shadow/selfhost-native）全绿。

**一元层的可寻址性不需要额外通道**：`sem_unary(TK_AMP)` 依赖 `support.fc().c_res_is_addr`，
而它是 parse 现场事实、不在节点注解里。一元层的调用点紧跟操作数解析，此刻该事实正是
操作数的值，因此节点模式**不改动**它即可与旧路径看到同一事实（全量语料 + libs 已实测）。
**postfix 链与调用不具备这个性质**（链式步骤之间 `fc` 已被改写、调用还要 `c_args`/
`c_arg_n` 现场），这两类迁移前仍须定「注解携带 or 入口显式接收」的通道
（**后由 §4e-3 定案**：调用 ABI 走仅算子模式，不引入注解字段）。

## 5. 风险与对策

- **注解漂移**：节点注解在作用域弹出后才被 lower 读取，`sym_*` 快照字段已有专门
  语义（`sym_type_id` 等）。重算必须只写「语义结果」字段，不写快照字段；
  S4-2a 只读不写，风险为零。
- **arena 复用**：`ast_expr_reset` 按模块重置，影子 pass 必须在解析后、发射前
  同一模块内完成（`module_worker` 内一次调用即可）。
- **性能**：影子门仅在 `YH_AST_FULL_CHECK=1` 下跑，门禁脚本显式设置；
  生产构建不进入该分支。
- **漂移检测**：若某片影子门出现不一致，先判是「full 算错」还是「legacy 语义
  依赖了解析期上下文（如 `c_expect_tid`、`c_fold` 深度、`sc_sc_depth`）」；
  后者需要在 full 里显式重建该上下文，不得放宽比较。
- **折叠上下文不可重建（S4-2d 实测）**：`c_fold` 只存在于 parse 现场，不能由
  「操作数都是字面量」推断——函数体里的 `1 << 63` 就是运行期求值。判定旧路径是否
  折过只信注解 `is_const`：算术运行期必清位；比较在运行期也写 `(BOOL, 0)`，
  先算折叠候选值、与注解 ival 一致才算折过，否则调 `sem_binop` 本体。
- **数据标签是会话内身份（S4-2d 实测）**：字符串/静态数据的标签在跨模块 CT 重放时
  会重映射（实测注解标签 2 指向提供方 21 字节登记，本节点却是本地 `"hi"`），
  标签号与登记内容都不可比；需要按内容/对象身份的稳定侧表。
  **S4-2f 实验（2026-11-11）**：`full_string` 内容一致性校验（注解标签登记字节 vs
  节点 token 字节）在语料+libs 全绿，但 selfhost-native 的 project cases
  `ct5b-cross-module-body`/`ct5b-string-pointer-constant-closure` 假红——跨模块
  CT 闭包采纳会把注解标签改指**提供方**登记（fixture 断言字符串数据隔离在提供方
  .data），此时「登记字节 == 节点 token 字节」前提本身不成立，非真漂移。已回退
  -2。稳定侧表若要做，需按内容/对象身份另建表（`data_str` 无属主元数据，无法
  先验区分采纳节点）；跨模块语义改动必须跑 selfhost-native（`just test` 不含
  project cases）。

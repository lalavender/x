# yh 命令行用 cli 标准库重写（实施方案）

日期：2026-10-27。状态：**规划，未实施**。
背景：`libs/cli` 已完成 argparse 对齐（语义/展示/诊断三批 + 拼接兜底 + 去重），
`docs/todo.md` 里 `cmd` 的 A2d「收为 CLI 薄壳」一直挂着手写 argv 扫描；
本文把「用 cli 重写 `yh` 命令行」拆成可独立验收的切片。

## 1. 目标与非目标

目标：

1. `yh` 的参数声明、解析、usage/help 与诊断**单一真源**，删除手写扫描与逐行
   `usage()` 拼接（`compiler/cmd/driver.yh:22`）。
2. 新形态与现有调用面**逐字节等价**（退出码、可观察输出关键字、行为）。
3. 命令行可自描述：`yh --help`、`yh build --help`、未知选项给建议。

非目标：

- 不改 `build`/`testkit` 的执行逻辑（只把「argv → 请求」这段换成 cli）。
- 不改内部子进程协议 `--emit-module`（见 §4.3）。
- 不引入新命令或新语义（除 §8 待拍板的少量取舍）。

## 2. 现状盘点（实测，2026-10-27）

入口：`compiler/cmd/driver.yh`（237 行）+ `compiler/cmd/api.yh`（144 行）；
各命令自己的选项扫描在 `compiler/build/module_build.yh`（`mb_cmd_build/run/list`）
与 `compiler/testkit/test_cmd.yh`（`mb_run_test_command`）。

## 3. 目标形态

```text
yh [全局选项] <命令> [命令选项/位置参数]
```

- 六个子命令：`build`、`check`、`run`、`test`、`list`、`version`。
- **全局选项双位置**：既在 `yh --target X build` 也支持 `yh build --target X`。
  实现用 cli 的 `inherit`（公共 parent，`add_help=false`）复制到根与各子命令，
  而不是让子命令穿透读取。
- **旧形态保留**（标记 legacy，不产生运行时警告）：
  `--syntax-check`、`--emit-asm`、`<file> -o <out>`、`-o <out> <file>`、`-target`。
- 内部协议 `--emit-module` 在进入 cli 之前拦截（同今天）。

## 4. 关键设计

### 4.1 全局选项双位置

cli 的 `inherit` 在调用时深复制参数与默认值；把「全局 parent」分别继承进根与
每个子 parser，即得到「子命令前后都能写」。互斥（`-O0` vs `-O2`）用 `add_mutex`，
`--backend` 用 `choices`（只接受 `llvm`），`--target` 的取值校验仍交给
`gen.target_select`（保持现有诊断与控制流）。

### 4.2 旧形态建模

| 旧形态 | cli 声明 |
| --- | --- |
| `--syntax-check <file>` | 根选项（`store_true`，`deprecated`）+ 位置 `file`；与前缀模式互斥 |
| `--emit-asm <file>` | 同上，独立 mode 位；`--emit-llvm` 存在时按 LLVM 文本输出（保持今天语义） |
| `<file> -o <out>` / `-o <out> <file>` | 根位置 `file` + 选项 `-o`（cli 普通模式本就支持两种次序） |

模式位（syntax/asm/emit-asm）用互斥组表达，缺省无模式且无子命令时走「裸 yh」分支。

### 4.3 内部协议不改

`--emit-module <mod> <prov> <root> -o <dir> [--stats] [--check-only]
[--ir-key hex] [--iface-suffix s]` 是编译器 fork/exec 自己的私有 ABI，参数顺序与
`-o` 位置都参与语义（`api.yh:110`），且不进用户 help。**继续手写扫描**，在 cli
解析之前按首参数分派；这条豁免写入本文与 `driver.yh` 头注释。

### 4.4 执行与退出码

- 用 `cli.parse_with`（不直接 `parse_main_or_exit`），把 `Result.status` 映射为
  yh 既有退出码：`ok → 分发`、`usage_error → 2`、`config_error/resource_error → 1`。
- 分发层仍是 `api_*`：cli 只产出「请求结构」（命令 + 选项值 + 位置值），
  `api_build/api_run/api_test/...` 的签名从 `(av, n)` 改成接收结构体，
  由 driver 从 cli 结果填充——保持 `api` 作为唯一调用面（A3 契约）。

## 5. cli 能力对账

| 需要 | cli 现状 |
| --- | --- |
| 子命令 + 别名 + `dest` | ✅ |
| 全局选项双位置 | ✅ `inherit` |
| 重复选项（`--link`） | ✅ `append` |
| 整数 + 范围校验（`--timeout`） | ✅ `value_kind=integer` + `validator` |
| 枚举（`--backend llvm`） | ✅ `choices` |
| 互斥（`-O0`/`-O2`） | ✅ `add_mutex` |
| 旧形态标注 | ✅ `deprecated`（help 标 `(deprecated)`） |
| 中文帮助段标题 | ❌ 段标题硬编码英文（`positional arguments`/`options`/`commands`） |
| 未知选项建议、退出码 2 | ✅ |

因此 **CLI-R0**：给 `HelpFormat` 增加三个段标题字段（默认保持英文），`help.yh`
的 `put_title` 改用它们；`yh` 侧设成中文，从而帮助文本与现在一致。

## 6. 分期（每期独立可验收）

### CLI-R0 cli 前置：可配置帮助段标题

- `HelpFormat` 增 `section_positional/options/commands`（`*char`，空指针用英文默认）；
  `build_help_text` 三处 `put_title` 改读字段；补 1 个用例（中文标题 + 缺省英文）。
- 门禁：`cd libs && yh test`（cli:: 52 个）。

### CLI-R1 骨架 + 等价性金标

- 新增 `compiler/cmd/cli_spec.yh`：声明全部子命令/选项/位置参数 + `inherit` 全局
  parent，输出 `CliRequest` 结构体（命令枚举、模式位、路径、组名列表、超时等）。
- `driver.yh` 保留现有分派，但先跑 cli 解析并与旧结果对比（`YH_CLI_COMPARE=1`
  时双跑、不一致即失败），用于灰度和排查。
- 新增 `tools/cli-golden.py`：对固定 argv 集（约 40 条，含 §2 全部形态与错误用例）
  比较「退出码 + stdout/stderr 归一化文本」。
- 门禁：`just test`、`just selfhost-native`（固定点不变，因为行为未改）。

### CLI-R2 迁移单文件形态

  删除 `driver.yh` 里 `n == 2 / n == 3` 的形态判断。
- 门禁：CLI-R1 的金标集 + `tests/yh-run`（`--emit-asm` 65 处调用）+ `just test`。

### CLI-R3 迁移项目命令

## 7. 等价性验收（金标集）

`tools/cli-golden.py` 的用例分四组，全部比较「退出码 + 归一化输出」：

1. **正常路径**：`build`、`build -o out`、`run`、`check`、`check <file.yh>`、`test --list`、
   `list`、`list --resolve x`、`version`、`version --contracts`。
2. **选项组合**：`--target aarch64-apple-darwin build`、`build --target …`、
   `-O2 --emit-llvm build`、`--stats build`、`--link a --link b run`、
   `--backend llvm test`。
3. **单文件形态**：`--syntax-check f.yh`、`--emit-asm f.yh`、`f.yh -o out`、
   `-o out f.yh`、`--emit-llvm f.yh`、`--emit-asm --emit-llvm f.yh`。
4. **错误路径**：`[]`（裸 yh，2）、`--unknown`、`build --link`（缺值）、
   `test --timeout 0` / `99999`、`--backend legacy`、`--target linux`（简写已移除）、
   `check a.yh b.yh`、`list --link x`。

归一化：去掉临时目录绝对路径、统计耗时、编译器自身路径；只保留稳定字段
（退出码 + 首行诊断类别）。

严格度分层，避免把「有意改进」误判成回归：

- **严格等价**：退出码、命令行为（产物是否生成、统计开关、失败与否）。
- **文本宽松**：usage/help 的排版与措辞允许变化（R4 会改用 cli 生成），只断言
  「首行是 `用法`/`usage` 或诊断类别」。
- **新增能力**：`-h`/`--help`、未知选项建议、`(deprecated)` 标注是新增的，
  今天 `yh` 完全没有 `--help`，因此只做存在性断言，不参与等价性比较。

## 8. 待拍板（实施前确认）

1. `cli` 增加可配置段标题（CLI-R0）是否接受？否则帮助会变成中英混排。
2. 全局选项是否继续支持「子命令前后都能写」（用 `inherit`）？推荐是（兼容）。
3. `-target`/`--syntax-check`/`--emit-asm` 永久保留为 legacy？推荐保留，且**不**输出
   弃用警告（避免污染 tests 的 stderr 断言）。
4. 裸 `yh` 仍打印 usage + 版本并退出 2？推荐保持（现有脚本可能依赖失败码）。
5. `yh test --filter` 是否改成可重复（argparse 式 `append`）？推荐暂不（会改变
   「最后一个生效」语义）。

## 12. 实施记录（2026-10-27 第一轮）

已落地：

- **CLI-R0 完成**：`HelpFormat` 增 `section_positional/section_options/section_commands`
  （空指针用英文默认），`build_help_text` 改读字段；新增用例「帮助：段标题可配置
  （缺省英文，显式中文）」，cli 内嵌测试 51 → 52，`just test` 全绿。
- **`tools/cli-golden.py` 完成**：36 条 argv（正常/组合/单文件/错误四组），每个用例在
  独立 fixture 副本里冷跑，比较退出码 + 归一化输出（路径占位、`time_*=0`、
  `yh-stats` 值隐藏、进度行多重集合）。当前结果 **36/36 通过、0 未知差异**，
  其中 6 条为「新实现多一条诊断」的宽松项。

R1 原型（`cmdline` 模块 + cli 解析 + 分派改造）已在本机验证通过，但**尚未入库**，
原因是自举门禁暴露出三个前置问题：

1. **自举快照门的期望产物集不含标准库模块**。编译器一旦 import 标准库，
   `cc2`（由种子构建）会额外发布 6 个模块的产物：
   `iface/yh_libs-{cli,io,os,memory,string,sys}.s.i/.s.ct` 与
   `llvm/yh_libs-*.ll`。基线核对：同一个种子构建**未改动的 HEAD** 时集合完全一致
   （0 多余、0 缺失），因此这是「编译器引入标准库依赖」带来的必然结果。
   两种收口方式需选一：扩展 `tests/selfhost` 的期望集（按 import 闭包加入
   `yh_libs-*`），或规定「外部项目模块只编译不发布 iface/.ll」。
2. **编译器项目引用标准库的机制**。原型用 `[dependencies] libs = {path = "../libs"}`
   + `import libs.cli`（而不是依赖「可执行文件旁边的 libs」的默认搜索）：暂存目录
   里的二进制（`just test` 的 `yh_run`、`compiler-tests.py`）默认找不到 libs，
   原型里给 `tools/compiler-tests.py` 加了 `YH_STDLIB` 兜底。
3. **lowering 限制**：cli 声明里「紧跟聚合 `let` 的结构体字段赋值」
   （如 `let spec cli.Argument = cli.option(...)` 之后 `spec.default_value =
   cli.suppress_default()`）会触发「首片不支持此聚合初始化形态」。原型通过把
   结构体值先 hoist 到局部（或去掉不必要的 suppress 默认值）绕过；长期应在
   lowering 侧支持，或把该限制写进设计文档。

原型补丁保留在 `tmp/cli-migration/cli-r1-prototype.patch`（临时文件，不入库），
可在解决上面三条后直接复跑 `tools/cli-golden.py` 与 `just test`/`just selfhost-native`
继续 R1。

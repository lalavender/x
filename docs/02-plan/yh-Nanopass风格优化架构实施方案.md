关闭（见 [ADR-0011 定位决定](../adr/0011-yh采用Nanopass风格优化阶段契约.md#2026-10-26-定位决定)），

设计见[架构方案](../03-design/yh-Nanopass风格优化架构.md)，

## 1. 执行规则

- 每个切片先写 `.yh` 复现/验收，再实现，执行 `make` 与针对性回归。
- 每个阶段执行 `make test`、`make selfhost-native`；全绿后才执行 `make seed`。
- 代码用中文注释；函数/结构体说明所有权、不变量与失败协议。
- 仅调整本任务需要的代码；保留已有未提交工作。所有临时证据放 `tmp/`。
- 不改语法；若实现发现语义/语法变更，另立任务并先分析 `docs/yh.g4`。
- 旧种子不接收它未支持的新选项；新增结构/函数使用旧种子可编译的 yh 子集。
- 文档/统计按实际能力更新；不能把定义了指令或回退成功计为新管线支持。

## 2. 依赖与最小交付

```text
NP0 基线/语义/模式对照
  → NP1 小 pass/引用工具/分析索引
    → NP2 默认低成本优化
      → NP3 受检/Core 边界与覆盖
        → NP4 机器 IR/phi/寄存器分配
NP2 + 需要的成熟语义/分析 → NP5 发布优化（逐项验收）
```

NP0–NP2 是首个可独立验收的交付包。先保持既有 AST/SSA/栈槽后端，
不要求一次重写前端和后端。NP3/NP4 是后续结构迁移，NP5 是按测量选择的优化。
真正线程池、文件对象继续跟随既有 R2b–R6 的依赖与硬门。

## 3. NP0：可信语义与对照入口

范围：设计中引用的整数语义、现有 irfront/irverify 项目、构建配置与统计。

1. 逐项核对窄整数、unsigned 比较、除零、最小负数/-1、移位边界、
   短路及调用顺序，建立规则/实现/测试对应表；不一致另列缺陷修复。
2. 增加拟议 O0/O1 配置；默认 O1 保持当前简化，O0 只关闭可选优化，
   仍共用 check、SSA 构造与相同后端。
3. 优化模式进入函数、模块、对象、链接缓存身份；测试切换模式会正确重建。
4. 区分 SSA 构造成功、后端成功与回退，提供稳定原因码及阶段计数。
5. 在 tmp 中记录旧默认、候选 O0/O1 的输出/固定点/性能基线；
   性能用冻结 R0 与另冻的优化语料，两套结果分报。

新增 `.yh`：在 `tests/modules/projects/` 增加优化对照项目，覆盖非字面量参数
产生的窄整数/比较、分支/循环及调用效果；irverify 补边界反例。
常量表达式已被前端折叠的用例不能单独证明 SSA 优化有效。

验收：模式差分行为一致；切换 O0/O1 不复用错误模式缓存；check 的
`ir_functions=0` 且不进入后端；明确记录进入 SSA 与实际发射的函数数。
基线证据足以在同机重测，`make`、三层回归及自举主门通过。

## 4. NP1：保持输出的小 pass 拆分

范围：`compiler/ir/ssa.yh`、新增职责文件、现有 lowering 的单个简化接入点。

1. 拆出模型/校验/phi/常量折叠职责；保留 `ir_simplify` 兼容入口，
   由固定管线调用小 pass。先复现旧顺序，不新增优化。
2. 建立统一引用枚举与替换，覆盖普通操作数、phi、CALL 实参及终结值。
   在整次修改完成后校验；错误时停止，不能缓存半更新产物。
3. 建立定义/类型/块索引与函数私有分析上下文；修改默认使分析失效，
   值编号稀疏、void CALL、参数前导均保留现有约定。
4. 针对重复全表查找替换为索引读取；先维持完整校验密度，单独测量收益。
5. 新增稳定阶段 dump 与 pass 名诊断；暂不做新语言 DSL/插件机制。

新增 `.yh`：irverify 构造别名经 phi/CALL/return 多处引用的函数；
优化对照项目覆盖九参调用、循环合流、void 调用与空函数。

验收：行为保持，拆分前后同输入/配置的序列化 SSA 与汇编字节一致；
保持全部 verifier 反例拒绝。若修改输出，需要退回确认是否误引入新行为。
候选两代固定点与全门通过；记录校验/优化时间与 RSS。

## 5. NP2：默认低成本优化

依次实施以下切片，不在一次修改中同时增加全部规则：

| 切片 | 修改 | 新增 `.yh` 与验收性质 |
| --- | --- | --- |
| NP2a | COPY/phi 传播与常量折叠整理 | 所有引用类型正确；调用次数/次序不变；SSA 性质断言确认规则实际发生 |
| NP2b | 常量分支与不可达块清理 | 删除分支后的 phi 前驱完整；不可达 CALL/实参/符号表合法；保留可达效果 |
| NP2c | 保守 DCE 与表压缩 | 删除纯死链；保留忽略结果的 CALL、签名 PARAM 和未知内存操作；不留悬空 ID |
| NP2d | 固定默认顺序及边界校验 | O0/O1 冷/热、模式切换、损坏缓存恢复一致；确定性生成程序差分 |

表压缩辅助先支持当前 SSA 的全部旁表；不得只删指令或只修普通 a/b。
CFG 清理后分析全部失效；随后 phi 清理再运行，DCE 的根包含控制流与效果。
当前 LOAD/STORE 未进入前端主路径的部分用内部 `.yh` IR 探针覆盖，
不能误报为端到端内存优化已经完成。

验收：每个切片 `make` 与针对性项目通过；阶段末全门与 O0/O1 语义差分通过。
证明生成代码或 IR 有减少，同时报告优化/验证额外成本；默认端到端性能
超过 NP0 同机基线 10% 时重测归因并解决可重复回退。

## 6. NP3：受检/Core 与 lowering 解耦

范围：函数 AST 快照、`ast_ir_build.yh` 及缓存/后端协调入口。

1. 封存 CheckedFunction 的绑定、类型、符号与调用事实，生命周期由任务持有；
   不再由 lowering 随时查 parser 游标或可能被复用的 gen 槽。
2. 按控制流切片建立 Core 规范化：赋值求值、短路、循环/continue 等；
   逐项声明“移除什么形式、增加什么形式”，维护源位置与求值顺序。
3. 把源码形态的支持预检与构造分离；明确 UNSUPPORTED 与内部错误，
   缓存/后端调用移到协调适配层，ir 不向上依赖其他模块。
4. 补嵌套循环、for-in、switch/goto，再按现有自编需要补指针/内存、
   转换、聚合、浮点与各种调用；每种能力同时满足 check/Core/SSA/后端边界。
5. 受支持函数只走一次受检 → SSA → 后端；旧发射只处理预先选择的缺口。
   不改变未迁移函数的行为，不顺带改造无关语义代码。

新增 `.yh`：短路右侧效果、嵌套循环、多 break/continue、前向 goto/不可约 CFG、
聚合按值/别名与混合调用。使用现有 `tests/yh-run` 语料并添加缺失探针。

验收：所有进入新路径的函数不再预发射旧汇编；函数任务不依赖可变前端槽。
新路径覆盖自编所需全部能力并达到固定点后，才允许移除失去用途的旧入口。
R2b 的线程池/文件对象/增量验收仍须另行完成。

## 7. NP4：机器 IR 与代码质量

1. 建立 M/E/R 三阶段的机器 IR 契约与 verifier，先支持现有标量子集。
2. 抽取符号/Target/ABI/输出视图，ABI 降低与指令选择不读全局 parser 状态。
3. phi 放到对应边，拆必要临界边，保留并行复制组。
4. 计算跨块活跃性与 phi 边使用，做确定性线性扫描；调用 clobber、
   spill/reload、callee 保存和栈帧对齐逐项覆盖。
5. 分配后消解并行复制环，再发射汇编；保留栈槽实现作受控对照直到验收。

新增 `.yh`：循环两值交换、三值复制环、临界边、跨调用活跃值、
超过可分配寄存器的压力、九参调用、递归与大栈帧。

验收：运行结果与栈槽路径一致；M/E/R 非法表示分别被拒绝；
统计栈帧/load/store/spill 与实际运行时间。macOS/Linux ABI 原生分别验收，
交叉组装不算原生运行。默认管线固定点全绿后才启用新分配器滚种子。

## 8. NP5：发布优化扩展

SCCP、局部值编号、有限内联独立实施。先做 SCCP → CFG/phi/DCE 清理，
再做基本块内纯整数值编号，最后评估有指令预算的模块内小函数内联。

新增 `.yh`：循环常量/不可执行边、unsigned/窄整数不同类型不能合并、
递归不无限内联、callee 实现变化使 caller 失效；有副作用调用的次数/顺序保持。

验收：O0/O1/O2 语义差分、O2 自身两代固定点、内联函数体/摘要依赖失效通过。
输出不能受线程调度/时间预算影响。逐项报告编译成本、文本大小与运行收益；
收益不足时不默认启用。LICM/内存优化待效果/别名证明成熟后另立专项。

# yh fmt 标准库与字符串插值实施方案

**目标：** 按用户决定交付 V 风格字符串插值 `"…${expr:spec}…"`（结果
`string.String`），并交付作为其运行时的 `libs/fmt`；首版字符串格式化不使用
Go 的 `%` 格式串与 `Printf` 族（是否保留为次级 API 见待确认）。

**架构：** 语言层插值由编译器词法后扩展、解析、检查与降级实现；fmt 是普通
`libs/fmt` 模块，提供 `Value`、构造器、`append_text/append_value`、
`render` 与打印/字符串 API。编译器只合成普通模块调用，不内嵌 fmt 实现。

**技术：** 现有 yh/LLVM、标准库项目 fixture、Python runner；不引入 Go/V
工具链作为 CI 依赖。V 文档/实测只用于确定 spec golden。

日期：2026-10-23。状态：**规划（未实施，等待确认）**。
语言语义见[字符串插值设计](../03-design/yh-字符串插值设计-2026-10-23.md)，
运行时 API 见[fmt 标准库设计](../03-design/yh-fmt标准库设计-2026-10-23.md)。

## 1. 执行顺序

两条轨道并行推进，I3 依赖 R0–R2：

```text
R0 → R1 → R2 → R3        （fmt 运行时）
I0 → I1 → I2 → I3 → I4   （语言插值；I3 需要 R0–R2）
                 └→ I5 可选扩展
```

R 阶段先用直接调用 fmt 的 `.yh` fixture 验收，不依赖插值；I 阶段在 R 就绪后
做端到端。一次只完成一个可验收切片；I0 的探针结论决定 ABI 与实现机制，
不能先把未验证的 token/AST 布局写成稳定契约。

**自举约束：** 编译器源码在种子支持插值之前不得使用 `${}`，否则旧种子无法
编译新源码。实现期用旧种子构建新编译器，插值只出现在用户 fixture；滚种子
后也不强制迁移编译器源码。

## 3. R0：Value 模型与基础渲染

**新增：** `00_model.yh`、`10_value.yh`、`30_render.yh`（默认格式）、
`50_output.yh` 的 `append_text/append_value` 骨架。

1. Kind/Value/构造器：int、i64、u64、f64、bool、str、cstr；零值等于 nil。
2. `append_text`：`string.append` 转发，空文本不分配。
3. `append_value`：空 spec 时按默认格式（整数 d、浮点 g、字符串 s）追加；
   非空 spec 暂返回 `status_invalid_spec`（R1 接通）。
4. 整数/字符串/bool 的默认渲染；字符串按字节追加，不做 UTF-8 校验。
5. fixture `fmtvalue`、`fmtappend`：构造器/kind_of/零值/直接追加/失败路径。

**关闭条件：** 两个 fixture O0/O2 通过；直接 API 的整数/字符串/bool 输出
与手写期望一致；无插值依赖。

## 4. R1：V spec 与整数/文本渲染

**新增/修改：** `20_spec.yh`、`30_render.yh` 接入 flags/width/precision。

1. spec 解析：`[-+0]*`、width 数字、`.`precision、type 字符；非法输入返回
   `status_invalid_spec`；上限 1,048,576。
2. 整数：`d x X o b`、负数、`+`、`0`、`-`、最小 i64；`0` 与精度互斥规则
   按设计；width 对齐。
3. 文本：`s`、width、`-`；按 UTF-8 标量计宽，非法字节计 1；非浮点
   precision 行为（报 invalid_spec 或忽略）按设计 §9 确认后锁定。
4. bool：默认 true/false，width/`-`。
5. fixture `fmtspec`：spec 表、对齐、边界值、非法 spec、直接 render。

**关闭条件：** spec 表全绿；同一表被 R2/R3 与 I3 复用；非法 spec 不产生
半成品成功。

## 5. R2：浮点

**新增：** `40_float.yh`，接入 `f F e E g G` 与默认 g。

1. NaN、±Inf、-0；符号与特殊值。
2. `f/F` 定点：默认 6 位、precision 0–17、舍入、width/`0`/`+`。
3. `e/E`：至少两位指数、大小写。
4. `g/G`：有效数字/指数切换；V 的尾零规则（`.N` 去尾零，`.Nf` 保留）。
5. fixture `fmtfloat`：固定示例（V 文档示例）、边界、失败路径。
6. golden 来源：V 1.x 实测优先；拿不到时以文档示例锁定并在设计 §9 记录
   差额，不静默宣称一致。

**关闭条件：** 浮点组 O0/O2 通过；差额清单与设计一致；默认 g 输出稳定。

## 6. R3：打印/字符串 API 与收口

**新增/修改：** `50_output.yh` 完成 print/println/fprint/fprintln/
sprint/sprintln/render/of_string。

1. 值列表直接拼接（不加隐式空格）；println 末尾换行；零实参只换行。
2. 打印族先渲染进临时 String，再 `io.write_all`；失败保留 count；OOM →
   `os.error_other`、count=0。
3. sprint/sprintln/render 返回 TextResult；失败释放半成品并返回零句柄。
4. `of_string(*string.String)` 借用；`of_cstr(NULL)` 空串。
5. fixture `fmtprint`、`fmtresources`（无效 fd/失败路径）；surface 全 API；
   `nm -u` 无额外符号。
6. `libs/project.toml` 登记 fmt；README/doc.yh；安装导入测试。

**关闭条件：** `make test-fmt` O0/O2 通过；仓库外导入通过；fmt 单独可用
（不依赖插值）。

## 7. I0：语言探针

**阅读：** 插值设计 §4–§6；`compiler/lex/{lexer,layout}.yh`、
`compiler/gen/{model,state}.yh`、`compiler/parse/parse_expr.yh`、
`compiler/ast/ast_expr.yh`、`compiler/ast/module_snapshot_*.yh`、
`compiler/cmd/module_build.yh`。

**实验：** `tmp/interp-plan-probes/`，结论回填本方案与 `finish.md`。

1. 词法后扩展：内部 token 序列在源顺序、`lex_layout` 不在 `${...}` 内插
   分号、位置/列号指向原字符串；token 预算与扩容。
2. parser：primary 分支构造 `AST_EXPR_INTERP`/part；嵌套括号/索引/调用；
   错误恢复。
3. AST 快照/缓存：模块 worker 重建插值节点；`.s.a`/缓存键稳定；跨模块
   fixture。
4. 降级：手工 AST 或最小实现，验证 `string.make` + `append_*` + release
   的 SSA 路径，并检查旧发射器路径能否承载；比较 `fmt.interp(parts...)`
   与 append 方案在两条路径上的复杂度。
5. import/诊断：缺 `import fmt`/`import string` 的报错；类型解析
   `string.String` 的 API。
6. 不支持类型（struct/array/enum/String）在检查期报错，不进入降级。

**关闭条件：** 选定 token/AST/降级机制并记录证据；不创建返回占位值的
公共语法；若原生实现路径不可行，修订设计而不是降级为库级方案。

## 8. I1：词法扩展与解析

1. `\$` 加入转义集合；扫描 `${...}`，平衡 `()[]{}`、跳过字符字面量/
   注释；顶层 `:` 切 spec；单行限制；嵌套插值、裸双引号、空表达式、
   未闭合分别报错。裸双引号限制保证外层 `STRING` 仍是单个 token，
   `docs/yh.g4` 的 ANTLR 规则可继续匹配整个插值字面量。
2. 生成内部 token：BEGIN/TEXT/EXPR_BEGIN/EXPR_END/RAW_SPEC/END；
   用户源码不可写出；layout 边界识别。
3. parser：`parse_interp.yh` 构造 AST；文本 part 用字符串字面量节点，
   值 part 带表达式与 spec 字符串节点。
4. 语法用例：`tests/yh/interp/`（pass/reject）用 `--syntax-check` 跑；
   更新 `tests/yh/check.py` 的 ANTLR 分层（ANTLR 只验证外层字符串，
   编译器模式验证内部）；`docs/yh.g4` 加注释说明该边界。
5. 普通字符串回归：无非插值路径不变；`$`/`\${`/`\$` 转义用例。

**关闭条件：** pass/reject 全绿；`make quick`；普通字符串语料不回归。

## 9. I2：类型检查、AST 快照与缓存

1. 插值节点类型 `string.String`；解析 `string` 模块类型；缺 import 的
   明确错误。
2. 值 part 按静态类型选择 fmt 构造器（整数 sign/width、f64、bool、
   `*char`、`string.View`）；不支持类型的错误定位到表达式；顶层 const/
   全局初始化/`@[comptime]` 上下文拒绝插值。
3. spec 编译期解析与类型校验（与 R1 共用表）；错误定位到 spec 字节。
4. AST 快照/缓存：新 kind 序列化/反序列化、缓存键、跨模块 worker；
   固定点不能因插值节点不稳定而漂移。
5. 用例：`tests/modules/` 插值项目、缓存命中/失效、跨模块类型。

**关闭条件：** 模块/缓存用例通过；编译器自编固定点不因新 kind 变化而
失败（编译器源码暂不使用插值）。

## 10. I3：降级与端到端

1. 按 I0 选定机制生成 `string.String`：临时串 + `append_text/
   append_value`，失败释放并返回零句柄；或 `fmt.interp`。
2. 求值顺序左到右、每个表达式一次；与短路/三元/调用副作用用例。
3. 插值结果类型、赋值、`string.release`、`fmt.of_string` 打印。
4. 端到端用例：`tests/yh-run/run/` 插值求值/spec/转义/打印；
   `tests/modules/` 项目；O0/O2。
5. 失败语义：OOM 路径若可注入则验证零句柄；否则文档声明不可观察。

**关闭条件：** 端到端全绿；插值结果与直接 fmt 调用输出一致；无泄漏
（部分失败释放半成品）。

## 11. I4：诊断、文档与全量门

1. 错误表（插值设计 §8）逐条有 `fail-contains` 用例：空插值、未闭合、
   换行、嵌套、三元歧义、spec 非法、类型不符、不支持类型、缺 import。
2. 刷新 `docs/yh.g4` 注释、插值设计、fmt 设计、标准库设计、README；
   `docs/todo.md` 勾选、`docs/finish.md` 证据。
3. 全量门：`make`、`make test`、`make selfhost-native`、
   `make test-fmt`、O0/O2、`git diff --check`。
4. 依赖方向：`libs/{string,io,os}` 不得 import fmt；surface/`nm -u`。
5. 可选后续（I5）：嵌套插值、运行时 width/precision、`r/R`、
   `string.String`/enum 支持、自动导入；每项单独立项。

## 12. 验收与证据

- 每切片：新增 `.yh` 断言 → 确认失败 → 最小实现 → 定向通过 → `make`。
- 语法层与运行层分开验收；ANTLR 不能验证 `${...}` 内部，必须由编译器
  `--syntax-check` 覆盖，不能把 ANTLR 通过当成插值语法通过。
- 测试临时产物落 `tmp/`；fixture 不写 `.build`。
- 仅本平台门禁为必需；其他平台留给 Gitea Actions，不本地预跑。
- 未滚种子、未推送、未触发发布；滚种子仅在全绿后执行。

## 13. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 词法后扩展破坏 token 区间/布局 | I0 探针先验证；token 保持源顺序；layout 识别边界 |
| AST 快照/缓存跨 worker 不稳定 | I2 专项跨模块/缓存用例；固定点门 |
| 编译器与 fmt 的合成调用 ABI 脆弱 | 把签名写进设计契约；surface 测试；改名需同步 |
| 缺 import 造成体验倒退 | 明确诊断；I0 评估自动导入，首版不默认 |
| 插值 OOM 不可观察 | 用户已确认；文档写明；保留后续 TextResult 版本 |
| 浮点 spec 与 V 不完全一致 | 以 V 实测/文档锁定 golden，差额显式记录 |
| ANTLR 无法覆盖内部表达式 | 编译器语法测试为主；yh.g4 注明边界；v1 禁止 `${}` 内裸双引号以保住外层 STRING 可解析 |
| 旧发射器不支持多语句降级 | I0 同时验证两条路径；优先单次 `fmt.interp`，否则显式限制并立项，不能静默出错 |
| 编译器源码误用插值导致旧种子无法构建 | 实现期禁止编译器源码使用 `${}`；滚种子后也保持 |

## 14. 待确认

1. 插值必须 `import fmt`/`import string`，还是允许自动导入（首版建议必须）。
2. 首版限制（无嵌套插值、无运行时 width/precision、无 `r/R`）是否接受。
3. 浮点 `.N`/`g` 以 V 1.x 实测为准是否可接受。
4. 非浮点 precision 报错还是忽略；`print` 零实参/拼接规则。

# F2：`parse` 纯语法化（方案稿）

状态：F2-1/F2-2 已完成（2026-11-06）；F2-3 起待做
上游：ADR-0021（gen 职责拆分）、`yh-GEN4-TaskCtx拆分方案-2026-11-06.md`、`yh-F4-comptime纯执行器实施方案-2026-11-06.md`

## 1. 目标与判据

`parse` 的职责应收窄为「token 流 → 语法 AST」，语义求值归 `check`。当前
`parse` **边解析边求值**（每个表达式节点都写 `*Res`），这是历史遗留的一体化设计。

| 判据 | 现状 → 目标 |
| --- | --- |
| `parse` 代码内 `gen.*` 引用 | 718 → 0 |
| `parse → gen` 依赖符号 | 27 → 0（白名单只减不增） |
| `parse → gen` 依赖边 | 存在 → 消失 |
| 语义动作（`sem_*`）调用点 | 全部在 `parse` 内联 → 全部在 `check` |
| 入口/测试选择、接口发射 | 在 `parse` → 在 `build`/`check` |

`arch-check.py` 已加 `PARSE_SYMBOLS_FOR_GEN` 白名单（27 个，只减不增），
注入新依赖会被自测抓到。

## 2. 现状实测（`compiler/parse/`，9,618 行 / 14 文件）

代码内 `gen.*` 引用 718 处、75 个符号，按性质分四类：

| 类别 | 符号 | 处数 | 处置 |
| --- | --- | --- | --- |
| **A 常量/类型** | `F_*`/`SYM_*`/`TY_*`/`CT_DIAG_*`（约 55 个）与 `Res`/`CType`/`CSym`/`SField`/`TName`/`ModInfo`/`ModNsEnt`/`ImportEnt`/`PubAggDeferred` | ~430 | **已完成**：全部改 `support.*`（这些声明在 GEN4 已下沉 `support/model.yh`、`file_scope.yh`） |
| **B 诊断入口** | `gen.sem_err` | 148 | **已完成**：改 `token.err_tok`（两者实现完全相同：`err_tok` 取 token 游标位置） |
| **C 内核表写读** | `data_str_add`/`data_str_lookup`/`em_add`/`em_update_value` | 4 | F2-2 下沉 `support`（见 §3） |
| **D 语义动作** | `sem_can_assign`(19)、`ty_lookup_name`(11)、`sym_push`(8)、`scope_push/pop`(12)、`ty_*`(12)、`mod_*`(7)、`sym_*`(3) | 27 个符号 / 93 处 | F2-3 起：这些是「parse 必须消失」的部分 |

## 3. 分阶段

### F2-1 去噪 ✅ 已完成（718 → 93 处，75 → 27 符号）

- A 类全部改 `support.*`；B 类改 `token.err_tok`
- `parse/iface.yh`、`parse_module.yh`、`iface_ct.yh`、`iface_ct_map.yh`
  不再 `import gen`
- 新增 `PARSE_SYMBOLS_FOR_GEN` 白名单守卫（27）

### F2-2 语义内核表下沉 `support`（93 → 93 处，27 → 22 符号）✅ 已完成

- `data_str_*`（字符串标签 → 名字池偏移）与 `em_*`（枚举成员值表）从
  `gen/state.yh` 迁到 `support/kernel_tables.yh`：它们是纯存储 + 查表，
  不发诊断；`gen` 不再持有任何全局表
- 连带收益：`check.ct_bind` 的镜像槽直接绑 `support` 全局（不再经
  `gen.data_str_slots()`/`em_slots()`），`gen` 少 4 个 pub fn
- 判据：`gen/state.yh` 文件消失；`gen` 只剩 `symbols.yh`（语义动作）+
  `value_rules.yh`（带位置诊断的折叠）+ `model.yh`（别名）

**实际落地**：新建 `support/tables.yh`（`data_str_*` + `em_*` + `sym_find_enum_member`
+ `session_reset`，即原 `gen.state_init`）；`gen/state.yh` 删除；`gen` pub fn
**57 → 37**、行数 **1,750 → 1,512**；`parse→gen` 符号 **27 → 22**；
`gen.sem_init_tables()` 保留（它分配前端瞬时态缓冲，属内核初始化）。
`arch-check` 的 `taskctx_fields()` 改为「state.yh 不存在即 0」，
自测的预算注入目标从 `state.yh` 换成 `symbols.yh`（仍 6/6）。

### F2-2b 纯查询下沉（93 → 61 处，22 → 15 符号）✅ 已完成

把不发诊断的查询/谓词从 `gen/symbols.yh` 迁到 `support/symbols.yh`：
`ty_name_attrs`、`ty_is_opaque`、`ty_is_scalar`、`ty_has_opaque_value`、
`ty_lookup_name`、`mod_file_binding`、`mod_ns_lookup`、`mod_ns_lookup_pool`、
`mod_import_find`（9 个）。`ATTR_*` 常量的**源头**也移到 `support/model.yh`
（`token → support` 方向，因为 support 是叶子），`token.ATTR_*` 变成转发别名。

顺带把 `check`/`builtin`/`build` 的常量与类型引用（`gen.TY_*`/`F_*`/`Res`/
`CType`…）统一切到 `support.*`，`gen.sem_err` 统一改 `token.err_tok`：
`check` 的 gen 代码引用 308 → 30，`builtin` 只在 5 个内核写操作上，`ast` 归零。

### F2-2c 删除 `gen/model.yh`（别名表清空）✅ 已完成

`gen/model.yh` 的 **184 个导出在仓内已无任何 `gen.X` 引用**（全是历史别名）。
grep 全仓后确认：只有 gen 自己还在用其中 55 个裸名（214 处）。处理方式：

- 按「名字在哪个模块有定义」自动改前缀：82 个 → `support.`、102 个 → `token.`
- 删除 `gen/model.yh`；`gen` 只剩 `symbols.yh`（815 行）+ `value_rules.yh`（211 行）
- gen 代码引用面 190 → 0 处 `gen.` 自引用（改为 `support.`/`token.`）

顺带修 fixture 里残留的 `gen.TY_*`/`gen.CType`/`gen.TargetInfo` 引用（`llvmtarget`
的 `gen.TargetInfo` 早已是 `support.TargetInfo`）。

### F2-K1/K2 核收缩 ✅ 已完成（2026-11-06）

`gen` 从 2 文件/1,026 行/**28 pub fn** 收缩为 **2 文件/347 行/3 pub fn**：

| 留下（`gen` = 编译期值语义内核） | 迁走（→ `check/symbols.yh`，626 行） |
| --- | --- |
| `sem_can_assign`（隐式转换判定） | `ty_push`/`ty_register_builtins`/`ty_push_agg`/`ty_ptr`/`ty_array`/`ty_slice`/`ty_sig_add`/`ty_sig_param`/`ty_fn_abi`/`ty_fn`/`ty_declare_name`/`ty_add_name_attrs`/`ty_cabi_scalar`/`ty_cabi_param`/`ty_c_layout`/`ty_lookup_name_off` |
| `sem_fold_const_binop` | `sym_push`/`sym_push_lit`/`sym_push_pool`/`scope_push`/`scope_pop` |
| `sem_fold_const_unary` | `fold_unary`/`sem_parse_number`/`sym_declared_before`/`sem_promote`/`sem_init_tables`/`prelude_add` |
| （私有 `sem_err`/`fold_binop`/`sem_fold_float_binop`） | 另：`sem_lit_fits` → `support`（纯谓词） |

为什么这 3 个必须留下：`comptime` 要它们，而 `comptime → check` 会成环
（`check → comptime` 已存在）。它们又是唯一「带 token 位置诊断」的纯值规则，
所以 `gen` 的最终形态就是**值内核**——ADR-0021 里登记为「编译期值语义内核」。

**判据达成**：`gen` pub fn **28 → 3**、`import gen` **6 → 3**
（check/comptime/parse）、`parse→gen` **15 → 1**（只剩 `sem_can_assign`）、
`comptime→gen` 仍 3。`builtin` 一并脱离 `gen`（改依赖 `check`）。

### F2-3a 可行性核查结论（2026-11-06，**先做核查再动手**）

用 rg 统计 `parse` 内联语义耦合的规模（代码内、去注释）：

| 语义读取 | 处数 |
| --- | ---: |
| `res.type_id` | 104 |
| `res.ival` | 71 |
| `res.sym` | 31 |
| `res.is_const` | 30 |
| `res.is_lit` | 26 |
| `res.ct_diag` | 12 |
| `res.fval_bits` | 3 |
| **合计** | **277** |

分布：`parse_expr` 111、`parse_global_init` 60、`parse_comptime` 36、`parse_stmt` 16、
`iface` 14、`parse_decl` 10。

**结论**：AST 节点确实由 `parse` 生成（`ast_expr_finish(res, kind, op, first,
child0..2)`，`ast_capture` 门控，`parse_expr` 内 50 处），但每个节点的 `kind`
与子节点选择都建立在**已算出 `Res`** 之上（字面量定类型、`[N]T` 取 `ival`、
`parse_comptime` 按常量性分支）。也就是说语法决策**依赖**语义结果——
「parse 只建语法 AST」不是加个开关，而是把 AST schema 改成可表达「未定类型/
未求值长度」的中间形态，属前端重构级别。

**因此本方案调整**：F2-3（parse 纯语法化）**不再按原三小步推进**，改为
「核收缩」路线（见 §3.5）：把 `gen` 收缩为**只含 comptime 必需的值语义内核**，
其余语义动作迁 `check`。判据从「parse 零 `gen.`」改成「`gen` 只剩 ≤4 个 pub fn，
且 `parse`/`check` 对它只依赖值语义」。

### F2-3b 原计划（暂缓）

把「解析即求值」改成两段：

1. `parse` 只产出语法 AST 节点（`ast.AST_EXPR_*` 已存在），**不写 `Res`、
   不建符号、不做兼容性检查**
2. `check.resolve_*` 遍历语法 AST 做语义：建符号/类型、算 `Res`、发诊断

分三步落地，每步都要有双路对比（同源文件 → 两路产出的 `.s.ct`/IR 等价）：

- **F2-3a 纯语法路径**：新增 `parse_syntax_only()` 开关，只建 AST 与声明索引；
  与旧路径并存，只用于「语法树等价」差分测试
- **F2-3b 语义搬移**：把 `parse_expr.yh`（2,012 行）里的 `sem_*` 调用按算子
  分组搬到 `check/resolve_expr.yh`，逐组切换并跑全量语料
- **F2-3c 删除旧路径**：`parse` 不再 import `gen`，`arch-check` 白名单归零

### F2-4 入口/测试选择与接口发射外移

- `parse` 里的 test 块发现、入口签名校验 → `build`（`testkit` 已有 runner）
- `iface.yh`/`iface_ct.yh`（1,974 行）的接口**发射**是产物生成而非语法：
  迁 `check`（`iface` 的加载/解析可留 parse）

## 3.5 核收缩路线（取代 F2-3，推荐）

| 步骤 | 内容 | 判据 |
| --- | --- | --- |
| K1 | `gen` 只留 comptime 需要的 3 个折叠/兼容函数 + 其私有 helper | `gen` pub fn ≤ 4、行数 ≤ 200 |
| K2 | 其余 24 个语义动作（`ty_*`/`sym_*`/`scope_*`/`prelude_add`/`sem_*`/`fold_*`）迁 `check`（`parse → check` 已存在，`builtin → check` 新增一条边） | `import gen` 模块 ≤ 3（comptime/parse 只剩那 3 个函数） |
| K3 | `check` 不再依赖 `gen` 的非值语义符号；`gen` 名字在 ADR 里登记为「编译期值语义内核」 | `comptime→gen 3`、`parse→gen ≤1` |

K2 是机械搬迁（约 600 处调用点改名），风险低于 F2-3 的 AST 改造，收益等价：
「`gen` 不再是语义实现的家，只有值规则」。

## 4. 约束

- `parse` 可依赖 `check`（现状），因此语义搬移方向是 **parse → check**；
  反向绝不允许
- 每步都要保持 `.s.ct`/`.s.i` 的**语义等价**（不要求字节一致：模块身份/后缀
  会变），用固定点 + 全量语料验收
- `check` 已在 `F1/F3` 持有 `CheckedModule`，F2-3b 的落点是它的上游

## 5. 风险

| 风险 | 缓解 |
| --- | --- |
| 2,012 行的 `parse_expr` 一次性搬移 | 按算子组（算术/比较/字面量/调用/字面量构造/编译期）分 6 组，每组独立提交 + 差分 |
| 双路并存导致诊断顺序变化 | 差分测试比对「诊断序列」（行:列 + 消息），不只比成功/失败 |
| 自举种子不认新文件 | 新文件只放既有模块目录（`parse/`、`check/`），不改语法 |
| 无法本地跑 `just` | 门禁 = `yh check` + `arch-check.py`（含两条白名单）+ `build-check.py`
  （基线 88/128）+ fixture 实跑 |

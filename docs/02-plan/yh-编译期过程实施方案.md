## 0. 落地结构与依赖方向

根项目 `compiler/project.toml` 的 `source = "."` 已包含各源码模块。当前落地为：

- `comptime/ct_00_model.yh`：编译期函数、整数值、token 快照和 typed IR 节点模型。
- `comptime/ct_registry.yh`、`ct_ir.yh`：正文快照/签名登记、typed 切片导入、调用帧、局部执行、普通控制流和共享预算。
- `comptime/ct_eval_expr.yh`、`ct_eval_bool.yh`：整数表达式、直接编译期函数调用、比较/布尔条件及 if/return 执行，后者实现短路逻辑。
- `comptime/ct_diag.yh`：诊断消息解码与编译错误/警告发出。
- `parse/parse_comptime.yh`：语句位置语法接缝、常量 `$if` 选择及 `$for` 逐轮绑定。
- `parse/parse_stmt.yh`：只在完整独立表达式语句处执行普通函数诊断指令。

编译期函数诊断、函数内 `$if/$else` 和 typed `$for` 已迁入 typed IR；后续把 for-in、一般
左值及其余执行形式迁入。旧执行器暂保留给尚未迁移场景。单文件和模块路径均在全局初始化前准备 CT 函数，
普通函数遍历跳过已准备函数。

依赖方向只能是 `parse -> comptime -> gen`。comptime 不导入 parse，
不重新实现 lexer、表达式优先级或普通语义检查。parse 负责产生最小 typed CT IR；
AST 有稳定绑定与来源，再交给 comptime 检查/执行。若单文件入口缺少现成 AST
身份，先补等价的文件/声明身份，再接求值；不能另写第二套通用源代码 parser。
普通函数 IR/后端继续沿用原链路。

CT 请求不应直接嵌入 `sem_call` 普通发码流程。前端在完整类型检查实参后
把直接函数身份、typed 实参和调用源码位置交给 comptime；求值返回 typed 常量，
既不写 .text 也不生成普通函数调用。结构控制只在函数体内展开，
顶层声明索引和 import 依赖图保持原规则。

## 2. 共用开发与自举规则

1. 每个源码行为切片先在 `tests/yh-run/` 或 `tests/modules/` 增加 .yh 正反例。

   临时参考语法实验只作为历史取舍证据，不代替当前正式语料。
3. 新结构体/函数写中文注释，临时产物放 `tmp/comptime/`；修改源码后运行 make。
4. 更新相关语法、语义、流程/接口文档、todo/finish 和逐阶段完成记录。
5. 每个阶段执行 `make test`、`make selfhost-native` 与 `git diff --check`。
   全绿后执行 make seed；本轮已滚动入库种子并用新种子冷编复核。
6. 实现源码必须使用当前种子可识别的语法。新种子经过主门并滚动后，
   compiler 自身才可以采用新的 `$if/$for/@[comptime]`。

syntax-check 只验证结构，不执行编译期函数；check 完成必须的语义求值，
但不调用汇编器/链接器。单文件与项目的 check/build/run、emit-asm 必须一致。

## 3. CT0：先锁定契约与正式用例

预计修改：本组设计文档、docs/yh.g4、tests/yh 与运行语义用例。
拟新增 `tests/selfhost/comptime.py` 作为展开/无发码/预算验收入口。

- 确定 `$if (...)`、`$else $if`、`$for i in (lo..hi)` 的块与位置规则。
- 只增加 $ token；$if/$for 接入 stmt，$名字(...) 接入 primaryExpr，
  删除独立诊断语句产生式，具体调用参数/位置由语义约束。
  诊断名仅在 $ 调用位置保留，CT 函数拒绝三个内建名。
- 锁定函数内条件的许可值、未选分支规则、展开作用域和跳转边界；
  对顶层控制/诊断分别建立语法拒绝用例。
- 对定宽整数提升、转换、比较、除余/移位与溢出错误建立规则；
  不以宿主 i64 的偶然结果作为目标整数语义。
- 已修复全局数组读取 const 占位零、前向 const 静默得零：未就绪值统一干净拒绝；
  前向引用继续按既定顺序检查，不扩为自动常量依赖排序。CT5A 的 token 早期预探仍只支持简单整数函数及无环嵌套调用；另有 typed 布局请求可运行已捕获函数（包括可终止递归）并求出后续数组/字段长度。前向/循环布局依赖仍待后续。

退出：每个允许操作有明确结果，每个拒绝场景有诊断类别；
语法正反例覆盖仅语句位置、嵌套、保留普通同名标识符与非法顶层位置。

## 4. CT1：条件选择

预计接缝：lex token、parse 语句/块解析、目标上下文、AST 捕获和检查模式。

- 声明索引和依赖图按现有流程建立；完整检查函数内所有分支结构，
  在函数体检查时选择块，只有选中块参与名称/类型检查和 IR 生成。
- 条件可用 linux/darwin/arm64、已就绪常量与 sizeof 等常量表达式；
  未接入的 CT 函数调用仍明确拒绝，普通参数/let 不当成编译期值。
- 保留普通块作用域、原源码位置；未选支不绑定名字、不生成 IR。
- 目标标记来自输出任务，不能直接复用宿主平台文件过滤结果。
- 项目依赖图使用已有 import；选中使用情况再做未使用检查。
  平台函数/类型/导入继续使用平台源文件，不新增声明选择阶段。
- 缓存身份包含目标信息与选择语义版本。

退出：未选分支的未知类型/符号、分支局部作用域、嵌套 else-if、错误条件、
非法顶层位置、未选支坏语法/选中支类型错均有正反例；
汇编无条件选择跳转，声明和依赖行为保持原规则。

## 5. CT2：展开与诊断

预计接缝：parse_stmt、typed 常量请求、展开来源/绑定模型、AST verifier、缓存。

- 求值整数区间，在每次独立作用域绑定只读 int；检查值范围与空区间。
- 每个实例有独立绑定身份，引用保留原源码范围和展开值；
  不能复用失效的 sym_id，也不能绕过 verifier。
- 支持嵌套控制，`$if/$for` 共享 32 层上限；拒绝修改/取地址循环变量、顶层展开和跨展开边界跳转。
  `break/continue` 只能落在展开体内新建的运行期循环，不能跳到 `$for` 外部。
  体内普通 for 的 break/continue、所在函数的 return 保持普通规则。
- 在复制前检查单区间 1024 次、模块 100000 实例和深度 32；当前 parser
  已实现共享结构嵌套上限。新增 AST 节点 100000 上限尚未实现，需随 typed AST
  展开路径落地；区间基数计算不得溢出。
- `$for` 体中诊断记录原源码位置和外层到内层的迭代值链；每层只在首次进入实际
  迭代后加入来源，退出嵌套区间时恢复外层链。该诊断上下文已有回归。
- 接入统一 $名字(...) 解析与函数内 assert/error/warn；普通函数检查时执行，
  CT 函数实际调用路径已按执行路径接入。消息先限字符串文字量，
  诊断作为值/嵌套调用须在执行前由语义门拒绝。
  普通函数前端检查执行指令，未选 `$if` 指令不触发。
- 常量就绪检测拒绝读占位值；保持现有前向 const 顺序限制。

退出：输出顺序与重复局部名正确；嵌套/空区间/越界/预算和跳转反例有效；
汇编显示展开调用，不出现这项区间循环的运行期回边。

## 6. CT3：编译期函数

预计接缝：gen 属性/调用/常量事实、parse_decl/global_init/expr、
新 ct_model/ct_prepare/ct_eval、SourceStore 与单文件源身份、模块 worker。

- 增加函数属性和来源登记；首版拒绝 pub/extern/inline/noreturn、
  main、函数值、无返回值和不受支持签名。
- 显式 $f 绑定到带属性的直接函数；普通 f 绑定到 CT 函数时给出缺标记诊断，
  $普通函数/变量/函数指针拒绝。按原名字空间与词法遮蔽规则解析。
- 在全局初值前准备受检函数体，复用无发码能力并建立独立检查状态；
  不把符号参数错误当常量，也不冻结 const 占位零。
- 解释标量 let/const、赋值、普通 if/for、break/continue/return，
  显式 $f 直接 CT 调用、递归与短路；完整静态检查和按实际路径执行分开。
- 结构性 `$if/$for` 在准备时处理，不依赖调用参数；编译期函数内
  assert/error/warn 是受检求值指令，可依赖参数并按调用路径触发。
- 调用帧隔离，嵌套共用 100000 步/64 帧；空循环也消耗预算。
  函数准备状态、执行递归和常量依赖环分开记录。
- typed 返回值供 const、标量全局初值、局部数组、case、普通表达式，
  以及函数内 `$if/$for` 使用；输出常量，不发 CT 符号或调用。
- 同模块多文件按定义文件的环境求值；公开结果暂用 pub const。
  所有 CT 函数体均检查，包括没有调用的函数。

退出：设计示例结果正确；定义在调用之后、多次调用隔离、短路与未执行错误、
窄整数/无符号边界、无效实参、普通运行期调用与预算都有正反例。
补 $f/f 属性匹配、诊断值位置/嵌套拒绝与内建名冲突，不能只测结构可解析。
nm/汇编确认无 CT 函数；冷/热编和 CLI 一致；完整主门通过。

## 7. 后续阶段

CT4 先给枚举保留成员来源和声明顺序，再增加元信息绑定。
字段遍历复用 SField 与 READY 布局；名字进入目标程序时物化字符串，
不得泄露编译器指针。成员/布局参与缓存；动态字段选择不混入这一阶段。

CT5A 已允许有限的早期单 return CT 整数常量探测、pass1 数组长度待完成请求、完整整数长度
表达式与 pending `sizeof` 固定点调度。值/布局依赖环现按值常量和类型布局节点输出闭链，
例如 `N → S → 数组长度(N) → N`；无法确认闭环时继续报告未完成依赖。先开放全局数组与字段，
再逐项验收签名位置；不能把局部类型位置可用等同于全局可用。其他一般 typed CT 请求仍待后续。

CT5B 设计版本化 .s.ct：受检正文、规范类型、定义环境、源映射、可达私有闭包。
同轮发布接口/正文/指纹后再放行依赖 worker；正文、传递依赖、目标模型与
求值版本进入缓存，伴随文件也进入两代固定点。

CT6 每个能力单独设计；条件 import 必须解决依赖登记，
动态成员和类型选择必须解决展开后绑定/检查。

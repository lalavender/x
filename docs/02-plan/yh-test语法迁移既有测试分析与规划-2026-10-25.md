## 1. 结论

本节为分析结论；具体取舍已由用户逐项确认，见 §11 决策记录（D1–D16），
实施顺序以 §8 为准。

1. **值得迁移，而且应优先做 json / toml / string / cli 四个套件**。它们合计
   在门禁里花 16.1 + 17.1 + 15.3 + 34.8 ≈ 83 秒（串行构建 fixture），
   迁成 `tests.test.yh` 后预计只剩 5–8 秒（冷跑）或 1–2 秒（热跑）。
2. **收益有两条**：
   - 门禁时间：`make test` 当前 86.6s，其中 toml+json 33s；
   - 覆盖缺口：`libs/cli/test/run.py`、`libs/os/test/run.py`、
     `libs/libc/test/run.py` **没有接进任何 Makefile/CI 门**。按 D3/D10，
     test 块进主门（`make test`/`selfhost-native` 的无选择器 `yh test`），
     三个外部 runner 与 O2 进新的独立 `make libs-test`/`libs-test-o2`
     （CI 三端各加同一 step）。
3. **不迁移“编译器契约”**：语法/反例/诊断、运行语料（stdout/argv/stdin/
   退出码）、conformance/注入/安装/差分、自举与性能探针。
4. **迁移粒度按行为组**（每例 5–20 条断言），不按单条断言拆例：逐例 fork
   在批量测试里很便宜，但重复 setup 不便宜。
5. **每个库保留一个外部消费者 smoke**：语言内测试绕开 `.s.i` 导出面和链接
   边界；对 toml 可由 `tomltestdecoder`（conformance）承担，json/string/cli
   需要保留一个薄夹具。

## 2. 判定标准

一条现有用例适合 `test` 块，需同时满足：

1. 断言对象在同一模块/项目内可命名；
2. 期望是“值与状态正确”，不是“编译器必须报某条诊断”；
3. 不把 argv、stdin、stdout/stderr 文本、进程退出码当契约；
4. 不要求特定后端/目标；平台差异只用文件名筛选（`*.linux.yh`）；
5. 不需要改写源码重建（失败注入）、下载语料、安装树或仓库外运行；
6. 不检查编译产物（IR/对象/接口/符号/缓存键/耗时）；
7. 不依赖用例之间的进程内状态（每例独立进程）。

新增两条约束（本轮实测发现，见 §7）：

8. 测试文件的文件名必须排在它引用的**类型声明**之后；
9. 同一项目的两个 `yh test` 不能并发执行（当前产物路径共享）。

## 5. 候选清单

### P1 `json`（最高性价比：17.1s、无内建测试、断言机械）

- 来源：`tests/modules/projects/json{model,strings,numbers,containers,errors,files}`
  （864 行、114 `ok()`）。
- 目标：`libs/json/tests.test.yh`，按 model/strings/numbers/containers/errors
  分 6–10 个 `test`；`files` 组**一起迁**（D2）：`/tmp` 下按用例名区分
  的路径，照 `libs/io` 先例。
- 保留：`jsonmodel` 作消费者 smoke（D15：在 `build-check.py` 新增一例）；
  `tests/json/run.py` 全部迁走后删除。
- 预期：`make test` 减少约 14–15s。

### P2 `toml`（16.1s、146 `ok()`）

- 来源：`toml{model,strings,scalars,tables,errors,files}`（全部）；
  `tomlfiles` **一起迁**（D2），`/tmp` 用例路径 + 自建自清。
- 目标：`libs/toml/tests.test.yh`（文件名 `99_` 已排在 `90_api.yh` 之后，安全）。
- 保留：`tomltestdecoder`（conformance，天然的外部消费者）、`injection.py`、
  `install.py`；`tests/toml/run.py` 全部迁走后删除。
- 预期：`make test` 减少约 13s。

### P3 `string`（行为组 15.3s）

- 来源：`string{model,view,owned,transform,utf8}`；`stringinterop` 保留为
  跨库 smoke（`tests/string/run.py` 的 `interop` 组继续跑）。
- 目标：扩充 `libs/string/tests.test.yh`（现有 5 例扩到 15–20 例；文件已排在

  `complexity.py`、`install.py`、`build-check.py` 的 `st1-string-model`。
- 预期：`make test-string` 从 26.6s 降到约 13s。

### P4 `cli`（34.8s，且未接门禁）

- 来源：`clibasics`/`cliactions`/`clicommands`/`cliextensions`/`clihelp` 的
  `--selftest` 主体（约 3625 行、约 440 个编号返回）。
- 目标：`libs/cli/tests.test.yh`（**必须用 `zz_` 等排在 `cli.yh` 之后的名字**，
  见 §7.3）；按现有 `case_*`/`run_all` 分组，每组一个 `test`；建议拆成

- 保留：`cli1-pack-run`/`--help`/缺失参数（argv/退出码/stderr）、

  这些继续由 `libs/cli/test/run.py` 跑，并把该 runner 接入 `make test`。
- 预期：接入后新增约 3–5s 冷跑，替代 34.8s；同时第一次进入门禁。

### P5 `os` / `sys` / `time`（2.1s，未接门禁）

- 来源：`libs/os/test/main.yh` 的纯模型/错误分类断言；
  `tests/modules/projects/{sysresult,osmodel,sysmemory,systime}`。
- 目标：`libs/os/99_tests.test.linux.yh` / `99_tests.test.darwin.yh`（文件名筛选平台）、
  `libs/sys/99_tests.*.yh`、`libs/time/tests.test.yh`。
- 保留：文件/目录/进程/环境/管道的 E2E（自建自清临时目录的成本高、易受
  环境影响）、`libs/os/test/run.py` 的 Linux 目标类型检查（交叉编译检查）。
- 预期：把 `libs/os/test/run.py` 接进 `make test`；迁移本身时间收益小，
  主要是覆盖与失败定位。

### P6 编译器内部（36.7s 已是最大单项，先测后迁）

- 来源：`irverify`(747)、`astcheck`(234)、`irfront`(410)；
  `compiler/lower/module_snapshot_lower_selftest.yh` 目前是“pub 探针 + fixture
  调用”，可改成 `test` 块并删掉探针导出。
- 目标：`compiler/ir/*`、`compiler/ast/*`、`compiler/check/*` 的 `test` 块；
  `tools/compiler-tests.py` 的 `DEFAULT_MODULES` 增列对应模块。
- 保留：`llvmlower`/`llvmchecked`（依赖 `input/*.yh` 与真实前端组合）、
  `copy_proj` 的复制逻辑。
- 门槛：先测新增一个模块测试二进制的链接成本（当前 3 模块 36.7s）；
  若增量 > 5s，则只做 `module_snapshot_lower_selftest` 与 `irverify`。

### P7 新库策略（防止新的 fixture 债）

- `libs/num`（958 行、零测试）：先加 `libs/num/tests.test.yh` 覆盖解析/格式化
  边界；最短往返与 Python `repr` 的差分放 `tests/num/reference.py`（外部）。
- `memory` M0–M4、`math` P1–P7、HTTP2–HTTP7、IO5–IO7、fmt I5：
  **默认先写 `tests.test.yh`**；外部 fixture 只用于差分/注入/安装/跨平台/进程级。

## 6. 不迁移清单

> D10 已确认长期方向是“所有测试逐步收敛到 `yh test`”。下表是**当前 `yh test`
> 能力下**不迁移的类别；其中若后续扩展了“预期失败/诊断断言”等能力，
> `fail` 类与 `tests/fmt/interp.py` 可重新评估（见 §9 第 1 项）。

| 用例族 | 理由 |
| --- | --- |
| `tests/yh/`、`tests/modules/{accept,reject}` | 期望是接受/拒绝，不是值断言 |
| `tests/yh-run/{run,fail,pass}` | 契约是 stdout/argv/stdin/退出码/诊断 |
| `tests/toml/conformance.py`（681） | 外部语料 + 逐字节比较 |
| `tests/{toml,string}/injection.py`、`TOML_TEST_FAIL_AFTER` | 需要改写源码重建 |
| `tests/{toml,string,fmt}/install.py` | 安装树 + 仓库外导入 |
| `tests/string/reference.py`、`complexity.py` | Python 语义差分 / 计时 |
| `tests/fmt/interp.py`（8 例） | 编译器必须报指定诊断 |
| `tests/selfhost/`、`tests/perf/`、`tests/tools/` | 编译器产物/目标/链接/统计/耗时 |
| `libs/libc/test/` | C ABI 与 C 源参与链接 |

## 7. 前置条件与约束（本轮实测更新）

### 7.1 YT2d 已完成，剩余是优化

- 测试构建目录与生产隔离（`tmp/yh-test/check`），键里含 target/opt/
  编译器指纹/本轮选中测试摘要；逐例日志已落地。
- **YT2d-2 剩余**：函数级 IR 与 check 切片缓存仍不用于测试构建；改一个
  `test` 会整模块重编。迁移后单模块测试文件变大，这一项的影响会放大，
  建议与 P1 同期或紧随完成后评估（不作为迁移阻断）。

### 7.2 同项目并发 `yh test`（YT2d-3，已修）

原现象：测试二进制固定为 `tmp/yh-test/bin/<项目>-<模块>`，日志/记录也按
`<模块>-<序号>` 命名；两个 `yh test` 在同一项目并发执行会互相覆盖，实测出现

```text
结果: 2 passed; 0 skipped; 3 failed
  用例崩溃或缺少结果记录
string/string.yh:1:1: 错误: 项目源码内的文件必须以 module 声明开头
```

处理（2026-10-25 已交付）：`yh test` 在 `tmp/yh-test/.lock` 上用
`O_CREAT|O_EXCL` 建锁并写入 pid，同项目运行串行化；持有者退出后用
`kill(pid, 0)` 清理陈旧锁，等待上限约 30 秒。不同项目/项目副本互不影响，
因此 `make test` 与 `make selfhost-native` 可并行。约定见
[测试布局与运行约定](../03-design/yh-test测试布局与运行约定-2026-10-25.md) §6。

### 7.3 测试文件名必须排在所引用类型声明之后（新增发现）

`libs/cli/tests.test.yh` 用 `*Parser` 参数会报“未知类型（类型必须先定义）”，
因为 `99_` 排在 `cli.yh` 之前；改名为 `tests.test.yh` 即通过。规则：

- 模块已有 `00_types.yh`/`00_model.yh`（toml/json/string/io/net/os/sys）：
  `tests.test.yh` 安全；
- 类型分散在字母序文件里的模块（cli）：用 `*.test.yh`；
- 新增测试文件先跑 `yh test <mod> --no-run` 验证。

### 7.4 门禁入口与 `libs-test`（D3/D4/D10/D12/D13）

已确认：

- 主门（`make test` / `make selfhost-native`）保留一次无选择器
  `cd libs && yh test --timeout 60`（O0，当前 33 例 3.0s，比 4 次串行 9.3s
  更快）；
- 新增独立 `make libs-test`：`yh test`（O0）+ `libs/cli/test/run.py` +
  `libs/cli/test/diff.py` + `libs/os/test/run.py` + `libs/libc/test/run.py`；
  不并进 `make test` / `make selfhost-native`；
- 新增 `make libs-test-o2`：`yh -O2 test`（不同 workdir/缓存根，避免互相
  冲刷）；
- CI 保持现有 3 个平台 job，各加同一个 `make libs-test`（O2 按需）step，
  平台差异全部由编译器按 `*.linux.yh`/`*.darwin.yh` 选择，runner 不再做
  `if darwin/linux` 分支；需要 `-target` 的交叉类型检查留在 Linux job 或
  独立 target。

### 7.5 外部消费者 smoke（D1/D15）

语言内测试不经过 `.s.i`/链接边界。迁移后 `build-check.py` 保留：

- string：`st1-string-model`、`st6-string-interop`；
- 基础/IO：`s2-libs-core-modules`、`s1-libs-io-write`；
- fmt：`fmt-interp`（插值正例）；
- os/sys：`os0-os-result-model`、`os5-io-write-result`；
- net：`net0-sys-socket-loopback`、`net1-net-tcp-loopback`；
- json：新增 `jsonmodel` 一例。

删除 `st2`–`st5` 与 `sysresult`（断言迁入 `libs/string`、`libs/sys`）；
Linux 11 例全部保留（真实 FS/进程/环境 E2E）。

### 7.6 测试辅助函数是普通声明

`test` 块不能声明局部函数；`tests.test.yh` 里的 helper（`test_view`、
`fill` 等）是模块私有普通 `fn`，生产构建会编译（不进 `.s.i`）。
沿用现有风格，但控制数量；纯一次性逻辑直接写进 `test` 体内。

### 7.7 文件类测试的资源约定（D2）

已确认 toml/json 的 `files` 组**一起迁**。约定照 `libs/io/tests.test.yh`：
`/tmp` 下按用例区分的固定路径，逐例自建自清；逐例独立进程
（`YH_TEST_JOBS` 默认 4）互不冲突。注意沙箱可能拦截建目录/批量删除
（仓库已有两个修复提交），失败时要给出可操作提示；若宿主无 `/tmp` 写权限，

## 11. 决策记录（逐项用户确认）

| 编号 | 议题 | 决定 | 约束/落地 |
| --- | --- | --- | --- |
| D1 | 纯断言部分的旧 runner/夹具何时删 | **A 同版本删除** | 硬条件：①迁移提交附断言对照表（旧 `ok()`/`return N` → 新 `test` 名，数量一致）；②每库保留 1 个外部消费者 smoke（toml 用 conformance decoder，json 留 `jsonmodel`，string 留 `stringinterop` + `build-check` 的 `st1-string-model`）；③当轮 `make test`、`make selfhost-native`、相关专项门全绿 |
| D2 | toml/json 的 `files` 组 | **A 一起迁** | 照 `libs/io/tests.test.yh` 先例：`/tmp` 下按用例区分的固定路径，逐例自建自清；`tests/{toml,json}/run.py` 收缩为仅 `files`（若迁移后无剩余则删除） |
| D3 | cli/os/libc runner 怎么进门禁 | **新增独立 `make libs-test`，覆盖 libs 下所有模块，作为 CI 独立阶段** | `libs-test` = `cd libs && yh test --timeout 60` + `libs/cli/test/run.py` + `libs/cli/test/diff.py` + `libs/os/test/run.py` + `libs/libc/test/run.py`；不并进 `make test` / `make selfhost-native` |
| D4 | `libs-test` 的 O2 | **B 单独 `libs-test-o2`，CI 独立 step** | O0/O2 用不同 workdir/缓存根，避免共享 `tmp/yh-test` 互相冲刷；与现有 `test-string-o2` 口径一致 |
| D5 | 编译器 fixture 迁到哪层 | **B 分两步**：先 `module_snapshot_lower_selftest` + `irverify` + `irfront`（`compiler/ir`），再 `astcheck`（`compiler/ast`/`check`） | 门槛：`test-compiler-tests` 增量 ≤ 10s 才做 `astcheck`，超过就停；`llvmlower`/`llvmchecked` 暂留；每加一个测试模块约 +6s |
| D6 | 断言粒度 | **A 按小节/`case_*` 分组** | 每例 5–20 条断言；cli 按 `zz_tests_10_*` 等多文件拆，单文件 500–1000 行 |
| D7 | 测试是否可调私有 `fn` | **A 迁移阶段只调 pub** | 断言对照表可逐条核对；内部边界另开 `test "内部: …"` 并在 PR/注释说明原因 |
| D8 | 新库/新功能测试策略 | **每个标准库都必须有自己的测试用例** | 位置固定为 `libs/<库>/*.test.yh`（不集中到统一大套件）；外部 suite 只做差分/注入/安装/跨平台/进程级；新功能切片必须同步提交本库测试 |
| D9 | “每库有测试”是否硬门禁 | **B 只提示，不阻断** | `make libs-test` 对缺 `*.test.yh` 的库打印一条提示清单（含当前未补齐的 num/os/sys/time/cli/json/toml/math/memory/libc/testing），后续各库自行补；不设白名单，也不因缺测试红门 |
| D10 | 长期方向与门禁分工 | **所有测试逐步收敛到 `yh test`** | 主门（`make test`/`selfhost-native`）与 `libs-test` 都以无选择器 `yh test` 为入口；外部 runner 仅作过渡，按 D1 逐步删；编译失败/外部语料/注入/安装/交叉/性能类先保留，再单独评估是否扩展 `yh test` |
| D11 | 是否现在给 `yh test` 加“预期失败/诊断断言” | **B 另立项** | 本轮只迁纯逻辑断言；`tests/yh-run/fail`、`tests/fmt/interp.py` 等负例继续外部跑，待新能力落地后再收敛 |
| D12 | `libs-test` 的平台差异 | **编译期区分，三端统一成一个** | 平台差异写进 `*_tests.linux.yh`/`*_tests.darwin.yh`，由编译器按文件名选择；`libs-test` 不带平台参数、不用 `// platform:` 注释 |
| D13 | CI 里怎么“统一成一个” | **A 一个目标、三端各自调用** | Makefile 只保留一份 `libs-test`/`libs-test-o2`；CI 现有 3 个平台 job 各加同一个 step，不改并行结构；`-target` 交叉类型检查留在 Linux job 或独立 target |
| D14 | `libs/num` 的测试配置 | **A 内建单测 + Python 差分** | `libs/num/tests.test.yh` 管契约/错误分类；`tests/num/reference.py` 用 Python `repr`/`float` 做往返对照；差分放独立目标/CI step，不进 `libs-test` 快跑 |
| D15 | `build-check.py` 的 `stdlib-run` 收缩 | **A 按表收缩** | 跨平台 14 → 10：保留 `st1`/`st6`/`libsbase`/`libsio`/`fmtinterp`/`osmodel`/`osio`/`netsys`/`netecho`，新增 `jsonmodel`；删 `st2`–`st5` 与 `sysresult`；Linux 11 例全留 |

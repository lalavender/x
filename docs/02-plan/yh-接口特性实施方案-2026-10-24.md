# yh 接口特性实施方案（interface / impl）

日期：2026-10-24。状态：**方案，未实施**。
范围：给 yh 语言增加语言级 `interface`（多态契约）与 `impl`（实现检查）。
既定取向（用户 2026-10-24 确认）：**显式 vtable 语法糖、零运行时魔法**；
不做 Go 式隐式动态派发（装箱 + itab 查表），不做泛型单态化。

## 1. 结论

一句话：**`interface` 编译成一个"`self` 指针 + 每方法一个函数指针字段"的普通
struct；`impl` 只做编译期契约检查、不生成任何代码；`s.m(args)` 是
`s.m(s.self, args)` 的语法糖。**

这样接口值、方法表、派发全部落在编译器**已经完整支持**的能力上：

| 需要的机制 | 现状 | 证据 |
| --- | --- | --- |
| 函数指针作为一等值 | 已有 | `tests/yh-run/run/22-fnptr.yh` |
| 函数指针字段 + 间接调用 | 已有 | `tests/yh-run/run/llvm-fnptr-null-cast.yh` |
| 聚合字面量/按值传递/返回 | 已有 | `tests/yh-run/run/llvm-global.yh` |
| 成员访问 + 调用后缀 | 已有 | `compiler/parse/parse_expr.yh:726-955` |
| AST 捕获合成实参 | 已有先例 | `compiler/ast/ast_expr.yh:282-301`（`$assert` 合成实参链） |

因此**不新增类型种类、不新增 IR 指令、不新增静态数据重定位**。唯一的新解析
行为是方法调用的接收者插入。

## 2. 现状（改动落点的事实基础）

### 2.1 前端与后端链路

`compiler/` 是一个 yh 项目，模块为 `gen/lex/parse/ast/comptime/check/ir/backend/cmd`。

- **语义与发射同遍**：`parse/` 边解析边调用 `gen/sem_*` 做类型检查并直接发射
  （旧路径），同时并行捕获 AST（`ast/`）；受支持函数再由
  `ast/module_snapshot_lower*.yh` 降低为 SSA，经 `ir/` → `backend/llvm_*` 出 LLVM。
  两条路径必须同时支持新语法，否则"未降低函数仍走旧发射器"的承诺会被打破。
- **类型种类**：`compiler/gen/model.yh:201-220` 只有 20 种 `TY_*`，没有
  interface / 方法 / 泛型。
- **类型名空间**：`TName.form` 取值 `0=别名 1=struct 2=union 3=enum`
  （`compiler/gen/model.yh:325-334`），`parse/iface.yh:236-330` 按 form 分支发射。
- **关键字编号**：`compiler/gen/model.yh:14-32` 规定分组；16..40 是语言关键字、
  41 已移除 C 关键字、42/43 `module`/`import`、44 `@`、45 `test`、50..63 内建类型、
  64..96 运算符、97 `$`。**46..49 空闲**，可直接放新关键字；
  `is_member_name` 只放开 16..39、41、45 与内建类型名
  （`compiler/parse/parse_type.yh:67-84`），新关键字不会意外成为字段名。

### 2.2 接口文件（`.s.i`）

`parse/iface.yh` 把 pub 声明发射为**合法 yh 源码**，加载就是重新词法/解析：

- 头行 `// yh-iface v1|v2|v3 arch=arm64 suffix=...`（`parse/iface.yh:9,169-196`）；
- 正文按 `TName.form` 1/2（struct/union 字段行）、3（enum 成员）、其他（type 别名）
  分支发射（`parse/iface.yh:236-330`）；
- 加载侧只认 v1/v2/v3 魔数（`parse/iface.yh:431-446`）。

接口声明要让**跨模块也能用方法调用糖**，就必须在 `.s.i` 里保留"这是 interface"
的身份，因此需要 **v4**；把 interface 展开成普通 `pub struct` 会让下游丢失
form=4，`s.m()` 会退化成"函数指针字段调用少传一个参数"。

### 2.3 函数指针与"全局函数地址"的真实边界

- 函数名可以赋值给同签名 `fn` 类型、可作参数/返回值/字段、可间接调用
  （`tests/yh-run/run/22-fnptr.yh`、`llvm-fnptr-null-cast.yh`）。
- **但全局初始化里的函数引用不是常量**：实测

  ```yh
  struct Vt { m fn(int) int }
  const VT Vt = Vt{ m: inc }   // 错误: 函数引用不是编译期常量
  let   vt Vt = Vt{ m: inc }   // 同一错误（全局初始化走 fold 模式）
  ```

  拒绝点是 `compiler/gen/sem_value.yh:317-322`。静态数据重定位
  （`gen/static_data.yh:112`）只支持"符号或数据标签"，且 lower 时
  `target_sym` 只查数据全局 `global_map`（`ast/module_snapshot_static.yh:197-221`），
  函数符号没有对应行。

**结论**：以"共享 vtable 指针 + 全局静态方法表"为首版会牵动常量模型、全局
重定位、接口发射、缓存与固定点，收益只是省 8 字节/方法。首版用**内联函数
指针字段**，把共享表列为后续可选优化（§7）。

### 2.4 聚合字面量省略字段不清零（必须写进用户约束）

实测 `struct P { x int; y int }` 用 `P{ x: 1 }` 构造后 `y` 读到 `1`（栈上残留），
不是 0。因此接口字面量**必须写全所有字段**，文档与诊断要强调。

### 2.5 自举约束

新关键字进入词法表只是普通 yh 代码，当前种子能继续编译编译器源码；
但**编译器源码自身不得使用 `interface`/`impl`**，否则下一代无法用旧种子构建。
只有 `tests/` 语料、`libs/`、`examples/` 可以用（在种子已升级后）。

## 3. 语言设计

### 3.1 接口声明

```yh
// 接口：pub 可选；块内只有"方法槽"，语法与 struct 字段完全一致。
// 编译器隐含补第一个字段 self *void。
pub interface Shape {
    area fn(*void) f64;
    name fn(*void) *char;
}
```

语义：

- `interface I` 在类型表登记一个 `TY_STRUCT`，同时 `TName.form = 4`；
- 字段 0 是编译器补的 `self *void`（名字池里 intern 固定名 `self`）；
- 其余字段按声明顺序，名字是方法名，类型是**源码里写的 fn 类型**；
- 方法槽必须是 `TY_FN`（否则报"interface 成员必须是函数类型"）；
- 方法名不能是 `self`（报"self 是接口保留的接收者字段名"）；
- `pub` 与否沿用 ADR-0013：`pub interface` 进接口文件，私有接口只在本模块可见，
  且不得出现在本模块 pub 签名/字段/别名体里。

方法槽显式写 `*void` 而不是"隐含接收者"，是为了让机器契约透明：
`impl` 映射的函数就是同签名函数，**零转换、零生成代码**。

### 3.2 实现声明（纯检查）

```yh
impl Shape for Circle {
    area = Circle_area;
    name = Circle_name;
}
```

- 语法：`impl` 类型名 `for` 类型名 `{` 若干 `方法名 = 函数名 ;` `}`；
- `impl` 只能在顶层，`pub` 不支持（不产生任何导出物）；
- 检查项：
  1. 左名必须是 form=4 的接口类型（否则"impl 左侧不是接口类型"）；
  2. 右名必须是已登记具名类型；
  3. 每个方法名必须存在于接口方法集；恰好覆盖全部方法，缺失/多余/重复分别诊断；
  4. 映射名必须是本模块可见的 `SYM_FN`，且 fn 类型与槽类型**严格相等**
     （参数、返回、ABI、变参种类全同）。因为槽类型含 `*void`，具体函数也必须
     以 `*void` 接收；
  5. 不生成符号、不生成数据、不写 `.s.i`。

`impl` 的价值是把"哪个函数实现哪个方法"写成可检查的契约；构造与调用仍是
普通语言构造。

### 3.3 具体实现函数

```yh
pub fn Circle_area(self *void) f64 {
    let c *Circle = self.to_type(*Circle)   // 实现者显式收窄
    return c.r * c.r * 3.1415926
}
```

首版不生成 thunk、不做 `*Circle ↔ *void` 的自动转换，避免新增"签名同构放宽"
规则和 lowering 插入 cast。显式 cast 与现有语言风格一致（指针间转换要
`.to_type`）。

### 3.4 构造

```yh
let c Circle = Circle{ r: 2.0 }
let s Shape = Shape{ self: &c, area: Circle_area, name: Circle_name }
```

- `&c` 是 `*Circle`，赋给 `*void` 字段沿用现有隐式规则
  （`gen/symbols.yh:914-920`：elem 是 `TY_VOID` 时允许）；
- **必须写全字段**（§2.4）；漏字段不会清零；
- 生命周期语义与手写 `{ptr, vtable}` 完全一致：接口值不拥有对象，`s` 比 `c`
  活得久就是悬垂指针，与 C 的 context 结构一致（不引入隐式所有权）。

### 3.5 方法调用

```yh
let a f64 = s.area()        // 等价于 s.area(s.self)
let f fn(*void) f64 = s.area  // 不带 `(`：普通字段值，不插参
let a2 f64 = s.area(&x)     // 错误：签名是 fn(*void) f64，多传一个实参
```

精确规则（三条同时成立才插接收者）：

1. 成员访问的基类型是 `TY_STRUCT`/`TY_UNION`，其 `TName.form == 4`；
2. 成员名是接口的方法字段（不是 `self`）；
3. 成员后面紧跟 `(`。

插入的是**值** `s.self`（类型 `*void`），位置是实参表第 0 个。

**首版接收者限制**：接收者必须是简单变量名（`PRIMARY` 标识符，允许是
`*Shape` 变量）。`p.shape.area()`、`f().area()` 报
"接口方法调用要求接收者为变量名（首版限制）"。原因：插参需要对接收者做
第二次取址；限定为变量名可保证两次求值无副作用，且旧发射路径不需要新增
临时槽机制（详见 §4.2）。

### 3.6 跨模块

- `pub interface` 进 `.s.i`（v4），下游加载后同样是 form=4，可构造、可 `s.m()`；
- `impl` 不导出；下游要构造跨模块接口值有两种写法：
  1. 直接字面量（字段公开，`Shape{ self: ..., area: ... }`）；
  2. 调用类型所属模块导出的普通包装函数（推荐，避免字段顺序绑死）。
- 首版不支持"impl 属于类型模块、消费方只写 `Shape.of(&c)`"这类隐式构造；
  需要时再加约定函数，不改语言。

### IF2 方法调用糖

两条路径分别实现，行为必须一致。

**旧发射路径**（`parse/parse_expr.yh` + `gen/sem_expr.yh`）：

- `Res` 增加两个字段：`iface_recv_sym int`（接收者符号下标，-1 表示无）、
  `iface_recv_ptr int`（1 = 接收者是 `*Shape` 变量）。
- `parse_postfix` 的 `.` 分支（`parse_expr.yh:861-952`）：调 `sem_member` 前
  用 `p_peek(1) == TK_LPAREN` 预判调用；对象是 form=4 且成员是方法时，
  记录接收者符号（基表达式必须是 `PRIMARY` 且 `sym >= 0`，否则报 §3.5 的限制），
  然后正常 `sem_member`。
- `parse_postfix` 的 `(` 分支（`parse_expr.yh:736`）：若 `res.iface_recv_sym >= 0`，
  在 `sem_call_begin` 之后、解析用户实参之前，按符号重新求值 `s.self`
  （值基：`lea s` + load 字段 0；指针基：load 指针 + load 字段 0），
  用 `sem_push_arg` 推入。随后清标记（嵌套安全靠"每个后缀调用就地消费"）。
- 错误：`s.self()` 保持普通调用路径（自然报 `*void` 不可调用）。

**AST 捕获 + lower 路径**：

- `.` 分支捕获 MEMBER 节点时记下同两个标记（可将标记放进 `Res` 即可，AST
  节点无需新字段；在 `(` 分支直接用）。
- `(` 分支：在追加用户实参之前，构造**合成的 self 访问节点**并
  `ast_expr_args_append(&args, self_ast)`。复用 `AST_EXPR_CTFIELD`
  （`op` = 字段行号，`child0` = 基节点，token 范围取基节点的
  `first/after`）——lower 的 `checked_lower_lvalue_ptr` 已按 `node.op`
  取字段（`ast/module_snapshot_lower_place.yh:637-660`），无需新节点种类，
  因此 **`CHECKED_SLICE_VERSION`/IR 版本都不必升**。
- 注意 `ast_expr_args_append` 的链表是"先追加 = 先求值"，先追加 self 即
  实参第 0 位。

**comptime**：`$` 函数体里的接口方法调用首版显式拒绝
（`gen/sem_expr.yh` 的 fold 分支报"编译期不支持接口方法调用"），
避免 `ct_*` 执行器对合成实参产生半支持行为。

验收：`tests/yh-run/run/` 行为用例（单模块 + 字段/参数/返回/返回值派发）；
负例覆盖实参数量/类型错误、非变量接收者。

## 5. 关键取舍

1. **内联表 vs 共享 vtable**：内联表 = 每方法 8 字节、接口值复制成本随方法数
   线性增长；共享表 = 4/8 字节指针 + 静态表，但需要"函数地址常量 + 静态重定位"
   （§2.3 实测被拒）。首版取下限改动；共享表作为可选优化，触发条件是
   接口方法数或接口值复制被实测证明是瓶颈。
2. **impl 不生成代码**：生成转换函数要么合成 AST/IR（脆弱、影响缓存），
   要么引入源码级模板（yh 没有）。纯检查把"零魔法"落到实处。
3. **方法槽显式 `*void`**：不引入"接收者自动收窄"，避免签名同构放宽与
   隐式 cast 规则扩散。
4. **接收者限变量名**：换来旧发射路径零临时槽、两条路径行为一致；
   缺点是最常见的 `p.shape.area()` 需要先落到局部变量。
5. **不做方法语法**：具体类型仍写 `Circle_area(&c)`；方法只存在于接口语境，
   不触碰"字段访问 vs 方法调用"的既有解析。

## 6. 风险与未决

- **省略字段不清零**（§2.4）：接口字面量必须写全；是否顺带修零初始化是独立
  议题，不并入本方案。
- **接口值按值传递**：现有聚合 ABI 会按值复制（`gen/model.yh` 聚合按值 ABI），
  大接口建议传 `*Shape`；文档示例优先 `*Shape`。
- **C ABI 方法**：槽是 ABI_YH；`@[extern]` 函数是 ABI_C，签名不相等会被
  impl 检查拒绝。首版不做 C 回调实现接口。
- **接口与模块私有类型**：私有 interface 出现在 pub 签名时沿用既有
  "pub 接口引用了非 pub 类型"诊断（`parse/iface.yh:163-167`）。
- **impl 与跨模块类型**：`impl Shape for Circle` 要求两者在本模块可见；
  Circle 来自其他模块时，impl 放在哪个模块需要约定（建议放在导入方模块，
  不导出）。
- **诊断质量**：签名不匹配要打印槽签名与候选函数签名（沿用 `sem_err` 位置）。

## 7. 明确不做

- Go 式隐式 iface（装箱、运行期 itab、类型断言）；
- 泛型/单态化、具体类型方法、接口继承；
- `impl` 导出、跨模块 impl 合并、孤儿 impl 规则；
- 共享 vtable 静态表（留到 §5.1 的触发条件出现）；
- comptime 接口方法调用；
- 接口的 C ABI 互操作。

# yh 多线程标准库实施方案

制定时间：2026-11-11
状态：**L1（Darwin）与 L2 Linux（pthread）已交付**（2026-11-11）；
L0 剩 Windows 导入，L2 Windows 与 L3/L4 待排期
设计：[03-design/yh-多线程标准库设计](../03-design/yh-多线程标准库设计.md)
总原则：**不改语言**。所有改动都在 `libs/sync` 与测试目录；库只使用现有语法，
当前种子即可构建。Linux 已确认链接 libc（链接模板含 crt1 + `-lc`），直接用
pthread，不需要编译器运行时垫片。

## 0. 全局约束

- 不新增关键字/语法；不动 `docs/yh.g4`、词法、AST、检查器、降级。
- 不动 IR 指令、序列化版本、函数级缓存。
- 不滚种子；不需要「两代固定点」等待。
- 每阶段完成定义：`just test-libs`（O0/O2）全绿 + 库内测试 O0/O2 通过 +
  `just test` 全绿 + 文档同步 + `docs/todo.md` 勾项。
- 平台差异只落在 `libs/sync/prim.<os>.yh`；公共层只写一份。

## 2. L0：探针（已完成部分）

### 2.1 已通过（2026-11-11，Darwin/arm64，仓库根 `./yh` 0.0.14）

| 探针 | 命令 | 输出 |
| --- | --- | --- |
| pthread 创建/汇合 + 参数指针 | `./yh tmp/sync-probe/pthread.yh -o /tmp/p && /tmp/p` | `7` |
| 不透明 mutex 块 + 2 线程计数 | `./yh tmp/sync-probe/mutex.yh -o /tmp/m && /tmp/m` | `200000` |
| 通用跳板（C 入口 → yh 函数指针） | `./yh tmp/sync-probe/dispatch.yh -o /tmp/d && /tmp/d` | `41` |

函数指针字段间接调用都能在**未改编译器**的情况下工作。

## 3. L1：Darwin 核心库

### 3.1 文件（已落地）

```
libs/sync/
  api.yh           # 类型、状态码、互斥/条件变量公开面、Dispatch（内部）
  thread.yh        # Thread 状态机与派发块分配
  waitgroup.yh     # 基于 Mutex/Cond（公共）
  once.yh          # 基于 Mutex/Cond（公共）
  prim.darwin.yh   # pthread 线程/互斥/条件原语 + C ABI 跳板
  prim.linux.yh    # L1 占位：platform_ready=0，创建/初始化显式失败
  prim.windows.yh  # L1 占位：同上
  doc.yh           # API 契约与未定义行为
  README.md        # 加载方式、示例、平台支持矩阵
  sync.test.yh     # 尺寸/状态码/空指针约定
  thread.test.yh   # 线程行为 8 例
```

公共层只依赖 `prim.*.yh` 的私有原语：
`thread_native_create/join/detach/self`、`mutex_native_*`、`cond_native_*`。
L1 只实现 Darwin；Linux/Windows 的文件保留同名占位，**显式失败**而不是空实现。

**文件序教训**：模块内类型按文件名字节序生效，`prim.darwin.yh` 排在
`thread.yh` 之前，所以 `Dispatch` 必须定义在 `api.yh`（第一个文件），
不能放在 `thread.yh`。首次编译就踩到「未知类型（类型必须先定义）」。

### 3.2 任务（已全部完成）

1. `api.yh`：`Thread/Mutex/Cond/WaitGroup/Once`、状态码、`Dispatch`。
2. `prim.darwin.yh`：pthread 声明 + `tramp`（C ABI）+ 原语封装；`tramp`
   负责 `memory.release` 派发块。
3. `thread.yh`：`thread_spawn` 申请派发块 → 平台创建 → 失败释放并返回 -1；
   `thread_join`/`thread_detach` 维护 0/1/2/3 状态机。
4. `waitgroup.yh`：`Mutex` + `Cond` 计数（`count i64`）；`add` 负计数返回 -1；
   `wait` 在计数为 0 前循环等待。
5. `once.yh`：状态机（0 未开始 / 1 执行中 / 2 完成），用户函数在锁外执行。
6. `doc.yh` + `README.md`：API 契约、误用、平台矩阵。

### 3.3 语料（实际）

- `libs/sync/sync.test.yh`：尺寸/状态码、空指针参数被拒绝。
- `libs/sync/thread.test.yh`：互斥计数、WaitGroup、Once、join 可见性、
  线程 id、分离线程、句柄状态机、try_lock。
- `tests/yh-run` **不加**并发语料：单文件模式不接标准库（`import sync`
  解析不到符号），全部行为测试在库内执行（见设计 §7.2）。

### 3.4 验证（已执行，2026-11-11）

```bash
cd libs && ../yh test --filter sync        # 10 passed, 0 failed
cd libs && ../yh -O2 test --filter sync    # 10 passed, 0 failed
cd libs && for i in $(seq 1 20); do ../yh test --filter sync; done   # 20 次 0 失败
# 真实项目端到端（带 [dependencies] 的 yh_libs）：200000
```

## 4. L2：平台对等

### 4.1 Windows

1. `vendor/windows-sdk/manifest.json` + `def/kernel32.def` 补
   `CreateThread`、`GetCurrentThreadId`、`AcquireSRWLockExclusive`、
   `ReleaseSRWLockExclusive`、`TryAcquireSRWLockExclusive`、
   `SleepConditionVariableSRW`、`WakeConditionVariable`、
   `WakeAllConditionVariable`（按 T0.3 清单）。
   同步更新 `def_sha256` 与 `exports`。
2. `libs/sync/prim.windows.yh`：`CreateThread` + SRW/条件变量；
   `tramp` 返回 `u32`。
3. Windows 上位 `platform_ready()` 仍返回 0，库内线程用例会跳过；接好
   `prim.windows.yh` 后把 `platform_ready()` 置 1，并用
   `test-windows-corpus` + 真机 `run-windows-corpus` 验证。

### 4.2 Linux（已交付：libc pthread）

**结论**：Linux 目标链接 libc（ELF 模板由 `tools/llvm-sdk.py` 从 GCC 的
`collect2` 参数生成，含 crt1/crti/crtn 与 `-lc`），因此直接用 pthread，
不引入 clone 垫片。

1. `libs/sync/prim.linux.yh` 与 Darwin 同形：`pthread_create/join/detach/self`、
   `pthread_mutex_*`、`pthread_cond_*`，`tramp` 仍是 yh 侧 C ABI 跳板；
   `platform_ready()` 返回 1。
2. 尺寸：glibc x86_64 mutex 40B / aarch64 48B，cond 48B；64B/48B 块覆盖，
   `sync.test.yh` 的尺寸断言同时守住。
3. 版本前提：glibc ≥ 2.34 或 musl（pthread 在 libc 内）。

**已执行证据（2026-11-11，Darwin 宿主交叉）**：

```bash
cd tmp/sync-probe/proj
../../../yh check --target aarch64-unknown-linux-gnu   # 检查通过
../../../yh check --target x86_64-unknown-linux-gnu    # 检查通过
../../../yh build --target aarch64-unknown-linux-gnu --emit-asm   # 链接在宿主失败（无 Linux -lm），但 .s 已生成
# .s 中可见：bl pthread_create / bl pthread_join / b pthread_mutex_lock /
#            bl pthread_cond_wait / b pthread_self
```

**运行期验证**：由 `.github/workflows/stdlib.yml` 的 `linux-x64` /
`linux-arm64` 任务在原生 Linux runner 上执行 `just test-stdlib-unix`
（含 10 次 `--filter sync` 压力）；本机不再承担 Linux 运行验证。

验证：

```bash
just test
just test-libs
just test-llvm-linux-arm64     # 需 Linux/aarch64 环境
just test-windows-target       # Windows 仍占位
just test-windows-corpus
```

## 5. L3：`Chan`

1. `libs/sync/chan.yh`：环形缓冲 + `Mutex`/`Cond`；无缓冲直接交接槽。
2. `chan_init` 哨兵 + `chan_release` 归零；元素宽度/容量校验。
3. 语料：run/218 ping-pong、219 有缓冲 FIFO、220 close/排空、
   221 多生产/多消费。
4. 压力：4 线程 × 100000 条，FIFO 顺序断言。

验证：`just test-libs` + `just test`；ping-pong 用例循环 20 次。

## 6. L4：可选能力（不阻塞发布）

按真实需求排期，每项单独评估：

- `RwLock`（Windows SRW 共享模式；Darwin `pthread_rwlock_t` 需要更大块）；
- `Semaphore`、`Pool`（短任务复用线程）；
- `atomic_*`（平台 interlocked 或编译器运行时帮助函数）；
- TSan（`-race` 等价物）预研。

## 7. CI：标准库专项工作流（2026-11-11）

新增 `.github/workflows/stdlib.yml`，专门跑标准库，不再依赖本地 Linux/Windows：

| job | runner | 执行 |
| --- | --- | --- |
| `linux-x64` | `ubuntu-24.04` | `just test-stdlib-unix` |
| `linux-arm64` | `ubuntu-24.04-arm` | `just test-stdlib-unix` |
| `darwin-arm64` | `macos-15` | `just test-stdlib-unix` |
| `windows-x64` | `windows-2022` | `just test-stdlib-windows` |

justfile 里对应新增：

- `test-libs-core`：跨平台核心（`yh test` O0 + O2 拷贝）；
- `test-libs-extras`：Unix 专属（cli/os/libc runner、TOML/string/num/fmt、安装布局）；
- `test-libs` = core + extras（原有行为不变）；
- `test-sync-stress`：`SYNC_REPEAT`（默认 10）次 `--filter sync`，抓偶发死锁/丢失唤醒；
- `test-stdlib-unix` = core + extras + stress；
- `test-stdlib-windows` = core + stress（安装布局验收仅 Unix）。

触发路径限于 `libs/**`、`tests/{string,toml,fmt,num}/**`、
`tests/modules/projects/**`、`justfile` 与本工作流；编译器改动仍由 `ci.yml`
的 `just test`（含 libs 的 `yh test`）兜底。种子、LLVM 闭包与缓存 key
与 `ci.yml` 完全一致，四端可直接命中同一份闭包缓存。

Windows 的 `sync` 在 `prim.windows.yh` 落地前 `platform_ready()==0`，
库内并发用例跳过；CI 仍会编译并运行其余标准库测试。

## 9. 回退预案

| 触发 | 回退 |
| --- | --- |
| Linux 运行期在 CI 上暴露问题 | 用 stdlib.yml 的 Linux 复现；必要时在链接模板补 `-lpthread`；不改公共 API |
| Windows 导入表补不齐 | Windows 只提供 `Mutex/Cond`（用户态不依赖缺失符号），线程 API 文档标注暂不支持 |
| `Chan` 无缓冲实现有竞态 | 首版只发布有缓冲通道（cap > 0），无缓冲返回 -1 |
| pthread 尺寸假设被推翻 | 改大 `words` 数组并加尺寸断言，公共 API 不变 |

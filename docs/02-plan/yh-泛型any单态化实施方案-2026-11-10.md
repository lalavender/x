# yh `$any` 编译期类型参数与单态化实施方案

日期：2026-11-10。状态：**规划（未开工）**。

关联：架构 §8.2 P0-2「comptime 类型参数 + 单态化命名」、§8.3「明确不做泛型」需同步修订；
编译期过程设计（`$if/$for`、CT 执行器、`.s.ct` 闭包）；ADR-0021（语义归 `check`）。

## 1. 目标与非目标

用户可见目标：`$any` 是编译器类型占位，编译过程中展开为实参的实际类型；同一套机制
同时承载具名类型参数（Odin/Zig 风格）：

```yh
// max：$T 同名同变量，两个实参必须是同一类型，返回同类型（由实参推断）
fn max(a $T, b $T) $T {
    if (a > b) { return a }
    return b
}

// swap：类型参数可出现在指针元素位置；同名的 $T 指同一类型
fn swap(a *$T, b *$T) {
    let t $T = *a
    *a = *b
    *b = t
}

// observe：$any 匿名，每处独立；函数体内不能引用该类型，返回类型也不能用
fn observe(x $any) int {
    return 1
}

// size_of：单态化观测点——同一泛型对不同实参类型生成不同实例
fn size_of(x $T) int {
    return sizeof($T)
}
```

判定标准（可观测）：

1. `max(1, 2)`、`max(1.to_type(u8), 2.to_type(u8))` 各自生成一个具体函数符号，
   行为正确；`size_of(1)` 返回 4、`size_of(1.to_type(u8))` 返回 1，证明两实例独立。
2. 类型不一致（`$T` 冲突）、无法推断、泛型上下文外使用 `$T` 均报确定诊断。
3. 既有 224 个 `run/` 用例与全部门禁不变红；两代自举固定点产物逐字节一致。

非目标（本方案不引入）：运行期 `any`/装箱/动态派发；trait/约束求解；类型级容器
（`Vec($T)`、`Map($K,$V)`）；宏系统；`$any` 下推到结构体字段或 `type` 别名。

## 2. 语义决策（需签字）

| 编号 | 决策 | 推荐 | 理由 |
| --- | --- | --- | --- |
| D1 | 类型参数形式 | 类型位置任意 `$IDENT` 即类型参数，**同名同变量**；`$any` 保留为匿名形式：每次出现一个新变量，不得出现在返回类型、函数体内不可再次引用 | 用户要 `$any`；具名变量是返回类型与容器（阶段 3）的必要条件；Odin 已验证 |
| D2 | 作用域 | 泛型函数签名 + 函数体；函数级 | AST/类型表最小改动；struct 级要动布局与 `.s.i`，另阶段 |
| D3 | 推断来源 | 只从实参**精确**推导，支持 `$T`、`*$T`、`[]$T`、`[N]$T` 的结构匹配；保留既有「数组实参 → `*T` 形参」退化；不做隐式整数加宽、不做返回类型反向推断；v1 无显式类型实参 | 加宽会破坏「同一 `$T` 只有一个类型」；显式类型实参先留给 G3，避免实参列表歧义 |
| D4 | 检查时机 | 声明期只登记模板，不检查函数体；实例化期用具体类型做完整检查；诊断定位到定义处（C++ 模板语义） | 一次性架构下没有「先建约束再检查」的位置；先交付正确性，诊断体验后续补调用点备注 |
| D5 | 实例归属 | 实例在**定义模块内**生成；符号名 = 模板名 + 结构类型键；v1 泛型函数必须**模块私有**（拒 `pub`） | 跨模块要动 `.s.i/.s.ct` 格式与实例所有权，单独立阶段 |
| D6 | 预算 | 类型参数 ≤ 16/函数；实例 ≤ 1024/模块；实例体计入现有 100000 节点/单元预算；同键递归复用、异键递归受实例上限保护 | 防模板膨胀；与 CT 预算口径一致 |
| D7 | 禁止组合 | `pub`、`extern`/C ABI、`@[comptime]`、`@[noreturn]`、类型化变参、取地址/作函数值、`main`、`test` 块外的 `$T` | 每一条都对应未定义或会破坏既有契约（`.s.i` 导出、CT 执行器、ABI、符号身份） |

诊断文本（固定，测试按片段断言）：

- `类型参数只能用于泛型函数（$T 需要出现在该函数的参数类型中）`
- `无法从实参推断类型参数 T`
- `类型参数 T 已绑定为 int，与 u8 实参冲突`
- `返回类型不能使用匿名类型参数 $any`
- `泛型函数暂不支持跨模块使用`
- `泛型函数不能是 pub/extern/comptime`
- `泛型实例过多（本模块上限 1024）`

## 3. 语法（docs/yh.g4）

`typeRef`（当前 `docs/yh.g4:648`）增加一条：

```antlr
typeRef
    : '$' IDENT                  // 类型参数：$any 匿名，$T/$K 具名（同名同变量）
    | '*' typeRef
    | ...
```

判定器同步：`parse_type.yh:81` 的 `is_type_start`、`:92` 的 `sizeof_starts_type`
加入 `token.TK_DOLLAR`；`parse_type.yh:149` 的 `parse_type_ref` 在 `$` 分支读取
`IDENT`。词法无需改动（`$` 已是独立 token `token.TK_DOLLAR`）。

无歧义论证：`typeRef` 只出现在类型位置，而 `$` 在类型位置没有其他产生式；
`$if/$for/$else/$is_type` 中 `if/for/else` 是保留字、`is_type` 只在表达式位置被
`$` 调用规则消费，因此 `'$' IDENT` 不会与它们混淆。类型参数名限定为非保留字
标识符，`$any` 是普通标识符，不与任何关键字冲突。

## 4. 语义与数据模型

### 4.1 类型变量

`compiler/support/api.yh` 的 `TY_*` 常量区新增 `TY_PARAM = 20`，条目
`kind=TY_PARAM, sub=函数内序号, size=-1, align=1, elem=-1, len=-1`，
由 `check.ty_param(ordinal)` 按 `sub` 去重。约束：

- `ty_is_integer/ty_is_float/ty_is_aggregate/ty_has_opaque_value` 对 `TY_PARAM` 返回 0；
- 布局、C ABI、`.s.i`/`.s.ct` 发射、lowering 遇到 `TY_PARAM` 一律走
  「内部错误：类型参数未绑定」防御分支（正常路径不应到达）；
- `ct_type_layout_ok()` 只断言既有常量，新增常量不改变 `CType` 布局，无需导出。

### 4.2 模板记录（pass1 登记）

`parse_decl.yh:581` 起：参数类型解析时用「收集上下文」把 `$T` 登记为模板的类型参数
（名字 → 序号），随后 `check.ty_fn_abi` 得到含 `TY_PARAM` 的模板签名并登记符号。
新增 `F_GENERIC` 标志；模板记录字段：

```
sym, file_id, body_first, body_after, ptypes[], np, ret,
tp_name_off[], tp_name_len[], tp_n, is_pub(恒 0)
```

存放：`support.ModelStore` 追加平行数组（沿用 `model_store.yh` 的存储/操作分离），
操作放 `check`（`generic_tpl_add/find`），避免新模块与循环依赖。

pass2（`parse_decl.yh:655`）遇 `F_GENERIC` 直接跳到声明末尾，**不编译模板体**；
未实例化的私有泛型仍由现有 UF1「函数未使用」拦住，不会静默漏检。

### 4.3 调用点绑定与实例

`check.sem_call`（`check/api.yh:2306`）在实参类型检查前分支：

1. 被调符号 `F_GENERIC`：按模板签名逐一**合一** `sig_params` 模式与
   `c_args[base+i].type_id`。模式只含 `TY_PARAM` 与结构（`PTR/SLICE/ARRAY`）；
   数组实参对 `*T` 形参按既有规则取元素类型绑定。
2. 同一 `TY_PARAM` 序号必须始终绑定到同一具体类型，冲突即报错；匿名 `$any`
   互补干扰。
3. 全部绑定后 `check.ty_subst(tpl_tid, bindings)` 得到具体签名与返回类型；
   返回类型仍含 `TY_PARAM` → 「无法推断」。
4. 以「模板符号 + 具体类型 id 序列」查实例表；未命中则：
   - 生成结构键文本与符号名（见 4.4），`sym_push_pool` 登记 `F_GENERIC_INSTANCE`
     符号（`F_GLOBAL`，不 `pub`，不做全局重名检查）；
   - 追加合成 `AstDecl`（见 4.5）；
   - 把实例入 FIFO 队列（记录模板符号、绑定快照、实例符号、请求位置）。
5. 以实例符号与具体签名继续走现有实参/结果路径（`sem_call` 其余代码不变）。

### 4.4 实例命名

`模板名$<结构键>`，键只由**源语言结构**决定，禁止出现类型表编号：

```
i8 i16 i32 i64 u8 u16 u32 u64 f32 f64 bool char void
P<T>            指针
S<T>            切片
A<N><T>         定长数组，如 A5<i32>
T<模块后缀_类型名>  具名类型，如 T__proj__mod__Point
F<参数序列>-><返回>  函数类型（G3 若允许）
```

示例：`max$i32`、`contains$S<i32>`、`size_of$u8`。总长 > 200 字节直接报
「泛型实例符号名过长」（不做哈希截断，保证可读与可复现）。lowering 仍按
`checked_lower_name`（`lower/module_snapshot_lower.yh:71`）追加既有 `$yhllvmv1`
与模块后缀，无需改动。

### 4.5 合成函数身份（最贵的一块）

`CheckedFunction` 由 `AstFunctionContext`（`ast/api.yh:715`）产生，lowering 以
`declarations[decl_row]` 取函数符号（`module_snapshot_lower.yh:532/565`），因此实例
必须有 `AstDecl` 行与函数上下文：

- `ast`：新增 `ast_decl_add_instance(...)` 追加 synth 声明（`kind=TK_FN`,
  `decl_index = -1 - serial`、`file_id` 为定义文件、`first/after` 为模板体区间、
  `sym_id/type_id` 为实例）；`ast_function_find_decl`（`ast/ast_function.yh:17`）
  对负 `owner_decl` 改为线性查找；新增 `ast_function_begin_instance/end_instance`。
- `check/verify.yh:26`、`verify_checked.yh:363/400`：负 `decl_index` 放行，但追加
  内部不变量（实例行必须 `F_GENERIC_INSTANCE`、`owner_decl<0`、符号类型为具体签名）。
- lowering：`checked_lower_mark_taken` 用 `decl_index` 匹配绑定，负值天然隔离；
  `checked_function_key`（`lower/module_snapshot_lower_cache.yh:130`）对实例返回 -1，
  **v1 实例不进函数级缓存**（同 token 区间的两个实例否则会撞键）。

### 4.6 实例驱动与顺序

`parse.parse_generic_run()`（新文件 `compiler/parse/parse_generic.yh`）：

```
while 队列非空:
    e = pop()
    保存 active_file/token 游标/指令侧上下文
    mb_restore_front_file(e.file)            // 同模块任意文件（build/api.yh:1211）
    check.generic_begin(e.tpl, e.bind)       // 置绑定上下文、模板名表
    sem_fn_begin(e.sym); 逐参 sem_declare_param(..., ty_subst(ptypes[i]))
    parse_block(); sem_fn_end(); ast_function_end_instance()
    恢复现场
```

- 调用点：`build/module_worker.yh` 的函数子遍与测试体子遍之后、`verify_module` 与
  `checked_module_capture` 之前；单文件路径 `build/llvm_emit.yh:106` 之后同样调用。
- 同键递归：入队时即登记「在建」状态，递归调用直接复用该符号（不再入队）；异键
  递归继续入队，受实例上限与深度上限保护。
- 实例体里再调用泛型 → 继续入队，循环到队列空；失败首错即停。

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 一次性「解析即检查」架构：模板体只能在模块函数子遍之后编译 | 队列 + 固定顺序驱动；G1 单独滚种子；两处调用点显式收尾 |
| 合成 AST 身份触及 ast/verify/lower 三处 | 负 `decl_index` 单点定义 + 内部不变量断言；先补 verify 测试再放开 |
| 缓存键：check 键混入整张类型表，实例按需建类型会改变后续函数键 | 可接受（只影响命中率）；IR 函数键对实例禁用，G4 再补绑定键 |
| 固定点/可复现：名字、类型表顺序不得依赖运行序 | 结构文本命名；实例顺序 = 调用出现顺序（确定性）；两代 `.s` 逐字节门 |
| 诊断体验：模板体错误只在实例化出现 | 私有泛型未实例化由 UF1 拦住；后续加「实例化自此处」调用点备注（G1 后补） |
| `.s.i/.s.ct` 格式漂移 | v1 不导出 `TY_PARAM`/模板；G2 才升版本并同步 `ct_type_layout_ok` |
| 模板膨胀 | 参数/实例/节点三重预算 + 上限诊断 |

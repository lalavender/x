# yh `$any` 编译期类型变量与单态化实施方案

日期：2026-11-10。状态：**规划（未开工）**。
修订：2026-11-10 第二轮——按用户裁定收敛为**只支持 `$any`**，不引入 `$T/$K` 具名类型参数。

关联：架构 §8.2 P0-2「comptime 类型参数 + 单态化命名」（§8.3「明确不做泛型」需同步修订）；
编译期过程设计（`$if/$for`、CT 执行器、`.s.ct` 闭包）；ADR-0021（语义归 `check`）。

## 1. 目标与非目标

唯一语法：类型位置写 `$any`。**一个函数里所有 `$any` 是同一个类型变量**，
类型由本次调用的实参推断，编译期展开为具体类型（单态化生成具体函数）。
不提供 `$T/$K` 之类的命名参数，也不提供显式类型实参。

```yh
// max：两个实参必须同类型；返回 $any 即该类型
fn max(a $any, b $any) $any {
    if (a > b) { return a }
    return b
}

// swap：函数体里 $any 同样指该具体类型，可声明同类型局部变量
fn swap(a *$any, b *$any) {
    let t $any = *a
    *a = *b
    *b = t
}

// contains：[]$any 绑定元素类型，needle 自然是同一类型
fn contains(xs []$any, needle $any) bool {
    for i in 0..len(xs) {
        if (xs[i] == needle) { return true }
    }
    return false
}

// size_of：sizeof($any) 在实例化后取到具体大小，是最直接的观测点
fn size_of(x $any) int {
    return sizeof($any)
}
```

判定标准（可观测）：

1. `max(1, 2)` 与 `max(1.to_type(u8), 2.to_type(u8))` 生成两个具体符号，行为正确；
   `size_of(1) == 4`、`size_of(1.to_type(u8)) == 1`，证明单态化独立。
2. 参数类型不一致（`max(1, 2.to_type(u8))`）、无法推断、非泛型函数用 `$any`
   均给确定诊断。
3. 既有 224 个 `run/` 用例零改动通过；`just test`、`just build`、
   `just selfhost-native` 全绿；两代固定点产物逐字节一致。

非目标（本方案不引入）：运行期 `any`/装箱/动态派发；具名类型参数与显式类型实参；
trait/约束求解；struct 级泛型（`Vec($any)`）；宏系统；`$any` 作为结构体字段/别名。

## 2. 语义决策（需签字）

| 编号 | 决策 | 内容 | 理由 |
| --- | --- | --- | --- |
| D1 | 单一类型变量 | 签名与函数体内所有 `$any` 是同一变量；调用时由实参推出唯一具体类型 | 用户裁定「只支持 `$any`，类型由实际传入决定」；单变量使 `max/swap/contains` 这类真正的泛型可用；若每处独立则任何「同型两参」都无法表达 |
| D2 | 作用范围 | 泛型函数的签名（参数 + 返回）与函数体；函数体内 `$any` 表示同一具体类型，可用于 `let t $any`、`sizeof($any)`、`to_type($any)` | 「编译期直接展开」的自然含义：把 `$any` 展开成实际类型，而不只是参数占位 |
| D3 | 推断来源 | 只从实参推断：`$any`、`*$any`、`[]$any` 结构匹配；保留既有「数组实参 → `*T` 形参」退化（绑定元素类型）。精确匹配，不做隐式整数加宽；首次绑定即定类型，后续实参不同即报错。`$any` 本身可绑定函数类型；`[N]$any` 与 `fn($any)` 这类**内嵌**匹配暂不支持（G3） | 加宽会让「同一类型」名存实亡；调用点必须唯一确定类型 |
| D4 | 检查时机 | 声明期只做签名登记（`$any` 记为占位类型），**不检查函数体**；实例化期用具体类型完整检查函数体与返回 | 一次性「解析即检查」架构没有「先约束、后检查」的位置；与现有 `$if/$for` 模板/CT 的延迟展开同构 |
| D5 | 实例归属 | 实例在**定义模块内**生成；符号名 = `模板名$具体类型键`；v1 泛型函数必须模块私有（拒 `pub`）；实例不导出 | 跨模块要动 `.s.i/.s.ct` 格式与实例所有权，单独立阶段 |
| D6 | 预算 | 实例 ≤ 1024/模块；实例体计入现有 100000 节点/单元预算；同键递归复用、异键递归受上限保护 | 防模板膨胀，与 CT 预算口径一致 |
| D7 | 禁止组合 | `pub`、`extern`/C ABI、`@[comptime]`、`@[noreturn]`、类型化变参、取地址/作函数值、`main`；返回类型只有 `$any` 而参数中没有 `$any` | 每条都对应未定义行为或会破坏既有契约（`.s.i` 导出、CT 执行器、ABI、符号身份、无法推断） |

固定诊断文本（测试按片段断言）：

- `$any 只能用于泛型函数（函数签名或函数体内的 $any 表示同一类型）`
- `$any 无法推断：请至少让一个参数类型包含 $any`
- `$any 在本调用中已由实参推断为 int，该实参为 u8`
- `$any 形参需要指针实参`
- `泛型函数暂不支持跨模块使用`
- `泛型函数不能是 pub/extern/comptime/noreturn`
- `泛型实例过多（本模块上限 1024）`
- `$any 暂不支持出现在 fn 类型内部或定长数组元素（如 fn($any) void、[4]$any）`
- `$any 不能用于结构体字段、类型别名或非泛型函数`

## 3. 语法（docs/yh.g4）

`typeRef`（当前 `docs/yh.g4:648`）增加一条：

```antlr
typeRef
    : '$' IDENT                  // 目前只允许拼写 $any（语义检查限定）
    | '*' typeRef
    | ...
```

为什么写 `'$' IDENT` 而不是 `'$' 'any'`：`any` 仍是普通标识符，不升级为保留字，
用户可继续用 `any` 作变量/字段名；`$foo` 在语义检查里报「类型参数目前只支持 `$any`」，
比语法错误更好定位。

判定器同步：`parse_type.yh:81` `is_type_start`、`:92` `sizeof_starts_type` 加
`token.TK_DOLLAR`；`parse_type.yh:149` `parse_type_ref` 在 `$` 分支读 `IDENT` 并校验拼写。
词法无需改动（`$` 已是独立 token `token.TK_DOLLAR`）。

无歧义论证：`typeRef` 只出现在类型位置，`$` 在类型位置没有其他产生式；
`$if/$for/$else` 的后续是保留字、`$is_type/$f(...)` 只在表达式位置消费，因此
`'$' IDENT` 不与之冲突。`$any` 出现在表达式位置时仍按现有规则处理（未知编译期函数），
不会误判为类型。

## 4. 语义与数据模型

### 4.1 类型变量

`compiler/support/api.yh` 的 `TY_*` 常量区新增 `TY_PARAM = 20`：
`kind=TY_PARAM, sub=0, size=-1, align=1, elem=-1, len=-1`。一个编译单元里所有模板共用
同一个 `TY_PARAM` 条目（实例化绑定在上下文里，不在类型条目里）。约束：

- `ty_is_integer/ty_is_float/ty_is_aggregate/ty_has_opaque_value` 对 `TY_PARAM` 返回 0；
- 布局、C ABI、`.s.i`/`.s.ct` 发射、lowering 遇 `TY_PARAM` 一律走
  「内部错误：类型参数未绑定」防御分支（正常路径不应到达）；
- 不改变 `CType` 布局，`ct_type_layout_ok()` 无需新增断言。

### 4.2 模板登记（pass1）

`parse_decl.yh:428` `parse_fn_decl` 解析签名时打开「`$any` 收集上下文」：

- 参数与返回类型里的 `$any` 都记为 `TY_PARAM`；
- 记录 `has_any_param`（参数类型里是否出现）；返回含 `$any` 而参数不含 → 立即报
  「无法推断」；
- 含 `$any` 即 `F_GENERIC`；`pub`/`extern`/`comptime`/`noreturn`/类型化变参即报错；
- 模板记录字段：`sym, file_id, body_first, body_after, ptypes[], np, ret`；
- 存放：`support.ModelStore` 追加平行数组（沿用 `model_store.yh` 的「存储/操作分离」），
  操作放 `check`（`generic_tpl_add/find`），不新增模块，避免循环依赖。

pass2（`parse_decl.yh:655`）遇 `F_GENERIC` 跳到声明末尾，**不编译模板体**；
未实例化的私有泛型由现有 UF1「函数未使用」拦住，不会静默漏检。

注意：模板体被跳过后其 `AstDecl.body_stmt` 保持 -1。`check/verify.yh` 的 `check_decl`
（`:291` 起）现在要求 `TK_FN` 必须有函数体根，`verify_checked.yh` 同样校验；两处必须
放行 `F_GENERIC` 的无体声明（并断言它不进入函数上下文/不发码）。

### 4.3 调用点推断与实例

`check.sem_call`（`check/api.yh:2306`）在实参类型检查前分支：

1. 被调符号 `F_GENERIC`：遍历参数模式 `sig_params[...]`，与
   `c_args[base+i].type_id` 做结构匹配找出 `TY_PARAM` 处的具体类型；
   `*$any` 接受指针（绑定被指类型）或数组（按既有退化绑定元素类型），
   `[]$any` 接受切片（绑定元素类型），`$any` 接受任意类型。
   （`[N]$any`、`fn($any)` 在声明期已拒绝，不进入匹配。）
2. 第一次得到的绑定即定类型；后续参数算出不同类型 → 报
   「`$any` 已由实参推断为 A，该实参为 B」。
3. 全部完成后 `check.ty_subst(tpl_tid, T)` 得具体签名与返回类型；
   `T` 仍未绑定（例如只有返回 `$any`，声明期已拒绝，这里是防御）→ 报错。
4. 以「模板符号 + 具体类型」查实例表（≤1024 条，线性查找可接受）；未命中则：
   - 生成结构键文本与符号名（4.4），`sym_push_pool` 登记
     `F_GENERIC_INSTANCE`（`F_GLOBAL`，非 `pub`，跳过全局重名检查）；
   - 追加合成 `AstDecl`（4.5）；
   - 实例入 FIFO 队列（模板符号、绑定类型、实例符号、请求位置）。
5. 用实例符号与具体签名继续走现有实参检查与结果类型路径。

### 4.4 实例命名

`模板名$<结构键>`，键只由**源语言结构**决定，禁止出现类型表编号：

```
i8 i16 i32 i64 u8 u16 u32 u64 f32 f64 bool char void
P<T>               指针
S<T>               切片
A<N><T>            定长数组，如 A5<i32>
T<模块后缀_类型名>   具名类型，如 T__proj__mod__Point
F<参数序列>-><返回>  函数类型（`$any` 本身绑定到函数类型时使用；`fn($any)` 内嵌不在此列）
```

示例：`max$i32`、`size_of$u8`、`swap$i32`、`contains$u8`（绑定的是元素类型）。
总长 > 200 字节直接报「泛型实例符号名过长」，不做哈希截断（可读 + 可复现）。
lowering 仍由 `checked_lower_name`（`lower/module_snapshot_lower.yh:71`）追加既有
`$yhllvmv1` 与模块后缀，无需改动。

### 4.5 合成函数身份（最贵的一块）

lowering 以 `AstDecl`/`AstFunctionContext` 枚举函数
（`lower/module_snapshot_lower.yh:532/565` 取 `declarations[decl_row]` 的符号），
实例没有源码声明，必须补合成行：

- `ast`：新增 `ast_decl_add_instance(...)` 追加 `kind=TK_FN` 的合成声明，
  `decl_index = -1 - serial`（文件内唯一）、`file_id` 为定义文件、
  `first/after` 为模板体区间、`sym_id/type_id` 为实例；
  `ast_function_find_decl`（`ast/ast_function.yh:17`）对负 `owner_decl` 改为线性查找
  （正常声明仍走 `file_first + decl_index` 的 O(1) 表，合成行追加在表尾不移动旧行）。
- 实例上下文把 `ast.store().file_decl_i` 临时设为该负号：表达式/绑定的
  `owner_decl` 因此与合成声明一致；`parse_stmt.yh:101` 的 `file_decl_i >= 0`
  条件需放行实例负号（其余路径仍是 -1 = 无声明）；`ast_function_begin` 的
  `owner_decl == file_decl_i` 断言在实例上下文自然成立。`ast_decl_attach_body`
  （`ast/api.yh:399`）按 `decl_index` 匹配，负号可直接用。
- `check/verify.yh` 的 `check_decl`（`:291`）与函数闭包检查（`:357`）、
  `verify_checked.yh:363/400`：`decl_index`/`owner_decl` 为负时放行，并加内部
  不变量（合成行必须 `TK_FN` + `F_GENERIC_INSTANCE`、符号类型为具体签名、
  `declaration.decl_index == ctx.owner_decl`）。
- lowering：`checked_lower_mark_taken` 以 `decl_index` 匹配绑定，负值天然隔离；
  `checked_function_key`（`lower/module_snapshot_lower_cache.yh:130`）对实例返回 -1，
  **v1 实例不进函数级缓存**（模板体 token 区间相同，不区分绑定会串用）。
- 实例函数上下文追加在所有普通函数之后，`checked_verify_functions` 的
  「函数 arena 范围单调递增」前提仍成立；实例不进 `checked_slice` 导出（它按 PDecl 切片）。

### 4.6 实例驱动与顺序

新增 `compiler/parse/parse_generic.yh`，公开 `parse_generic_run()`：

```
while 队列非空:
    e = pop()
    保存 active_file / token 游标 / 相关指令状态
    mb_restore_front_file(e.file)                 // 同模块任意文件（build/api.yh:1211）
    check.generic_begin(e.tpl, e.typ)             // 置绑定上下文
    ast_decl_add_instance(...); ast.store().file_decl_i = 合成负号
    sem_fn_begin(e.sym)
    逐参 sem_declare_param(名字, ty_subst(ptypes[i]))
    复用抽取出的 p_compile_fn_body(...)            // ast_binding_begin_function + parse_block
    sem_fn_end(); ast_function_end(); ast.store().file_decl_i = -1
    恢复现场
```

- 把 `parse_fn_decl` 的 pass2 尾部（`ast.ast_function_begin` 之后到
  `ast.ast_function_end`）抽取为 `p_compile_fn_body(...)`，普通函数与实例共用。
- 调用点：`build/module_worker.yh` 的函数子遍与测试体子遍之后、
  `verify_module`/`checked_module_capture` 之前；单文件路径
  `build/llvm_emit.yh:106` 之后同样调用。
- 同键递归：入队即登记「在建」，递归调用直接复用该符号（不再入队）；
  异键递归继续入队，由实例上限与深度上限保护。
- 实例体里再调用泛型 → 继续入队，直到队列空；错误首错即停。

| 一次性「解析即检查」架构：模板体只能在函数子遍之后编译 | 队列 + 固定顺序驱动；G1 单独滚种子；两处调用点显式收尾 |
| 合成 AST 身份触及 ast/verify/lower 三处 | 负 `decl_index` 单点定义 + 内部不变量断言；先补 verify 测试再放开 |
| 缓存键：check 键混入整张类型表，实例按需建类型会改变后续函数键 | 可接受（只影响命中率）；IR 函数键对实例禁用，G4 再补绑定键 |
| 固定点/可复现：名字与类型表顺序不得依赖运行序 | 结构文本命名；实例顺序 = 调用出现顺序（确定性）；两代 `.s` 逐字节门 |
| 诊断体验：模板体错误只在实例化出现（C++ 模板式） | 私有泛型未实例化由 UF1 拦住；后续加「实例化自此处」调用点备注 |
| `.s.i/.s.ct` 格式漂移 | v1 不导出 `TY_PARAM`/模板；G2 才升版本 |
| 模板膨胀 | 实例/节点预算 + 上限诊断 |
| 单变量语义的可用性上限 | 异构实参需拆成多个函数或具体类型参数；这是「只支持 `$any`」的既定取舍 |

## 8. 待签决策

1. 确认 D1：一个函数内所有 `$any` 是**同一类型**（推荐，`max/swap/contains` 可用）。
   若你要的是每个 `$any` 各自独立（允许异型实参），`max/swap/contains` 全部不可写，
   见附录差异。
2. 确认「编译期直接展开」= **按实参类型生成具体函数**（调用点仍是普通调用），
   不是把函数体文本内联到调用点（后者要处理 `return`/递归/调试信息，另立方案）。
3. G2 实例归属：使用方各生成一份（推荐先做）还是定义方 linkonce？
4. struct 级泛型是否确定进 G3（架构 §8.3 需同步改口径）。

## 附录：如果 `$any` 改为「每处独立」

差异点：每个 `$any` 出现处一个变量；`*$any`/`[]$any` 各自绑定；返回类型不得写
`$any`；实例键是类型序列。代价：`max(a $any, b $any)` 无法表达同型约束，
`contains(xs []$any, needle $any)` 的 `==` 只能在实例化时偶然成立；实现上反而更简单
（无跨实参一致检查），但可用性大幅下降。本方案不采用。

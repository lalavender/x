# yh `gen` 职责拆分实施方案（2026-11-06 重新分析，收窄版）

状态：**GEN0/GEN1/F1 完成；GEN2/F3 首片完成（语义动作与 ABI 算法迁 check）；F2 与 F4 待做**。
决策见 [ADR-0021](../adr/0021-yh-gen职责拆分.md)；前端两遍化的 F0–F7 见
[todo](../todo.md)。

## 0. 范围与结论

按用户 2026-11-06 反馈收窄：**只新增 `support`/`token` 两个模块**；
`sema` 不建，**语义分析全部归 `check`**；`diag`/`target` 并入 `support`；
`state`/`hir` 不建；复用现有 `lex`/`check`/`comptime`/`proj`/`builtin`。
`token` 从 GEN1 开始（词汇 + `PDecl` + token 数组/游标；`err_tok` 随诊断迁移）；
`builtin` 保留内置函数/内置类型登记表。

关键结论：

1. **模块数 17→18**：新增 `support`/`token`，删除 `gen`；`sema`/`diag`/`target`/
   `state`/`hir` 都不建。`check` 变大，但它是唯一语义入口。
2. **`check` 拥有全部语义**：CType/CSym/TY_*/F_*、类型规则、布局、C ABI、
   静态数据、名字/类型检查、`resolve → expand → full`、`CheckedModule`。
3. **`comptime` 收窄为纯 CT IR 执行器**：只执行 `check.expand` 构造的 CT IR；
   不得 import `check`/`gen`/`ast`。这是避免 `check ↔ comptime` 环的前提。
4. **`support` 是 L0 基础层，不是流水线阶段**：缓冲/源/池/统计/宿主/诊断/
   目标身份/ABI 常量；会话初始化时绑定，之后各阶段按需调用。
5. **`token` GEN1 就搬**：`c_toks`/`c_pos`/`c_tok_n`/`PDecl` 已进 `token`；
   `err_tok`/`sem_err` 随诊断迁移；parse 的 308 处 `c_pos` 只改一次。
6. **不建 `hir`**：`CheckedModule` 就是 `check` 的受检输出契约，`lower → check`。
7. **跨模块搬家不要求编译器自身 `.s.i` 逐字节一致**：用固定点 + 全量语料等价；
   同模块内文件搬家才要求字节一致。

### 3.1 归属后的导出面

- `support` 只导出基础窄口（缓冲/池/源/统计/诊断/宿主/目标/ABI 常量）。
- `token` 只导出词汇、`PDecl`、token 游标；`err_tok`/`sem_err` 暂留 `gen`。
- `check` 导出语义模型/规则/分析入口；`ABIValue`/`ABIArg`/`DATA_STR_CAP` 等内部
  类型不导出。
- `gen` 的导出面逐阶段减少，GEN2/F5 后只剩 `sem_*` 动作 + `task()`/残余状态。

- 退出指标：`import gen` ≤ 10（`ast/backend/build/builtin/check/cmd/comptime/
  lower/parse/testkit`）；`cmdline/cache/link/proj/lex` 不再 import `gen`；
  `gen` 行数约 4,200；arch-check 全绿。
- 若 token 状态改写超出预估，允许先合入“词汇 + PDecl”，但 token 状态必须在
  GEN1 内完成，不得留到 GEN4。

### GEN2：`check` 收全部语义（= F1–F5，**本阶段的主体**）

这一阶段不再有 `sema` 搬家，直接把语义分析做成 `check`：

- **F1**：`ast` 回归纯语法；`CheckedModule`/快照/切片键迁
  `check/check/base` + `check/checked_module`（不建 hir）。
- **F2**：`parse` 纯语法；删 `gen.sem_*` 调用；`iface`/`iface_ct`/
  `parse_ct_layout` 移出 parse；`PDecl` 索引上移 build/check。
- **F3–F5**：`check.resolve → 检查 CT 函数 → check.expand → check.full`；
  `CType/CSym/...`、类型/符号/折叠/布局/ABI/静态数据、`sem_*` 动作全部在
  `check` 内；`Res`、`CheckCtx`、`front_stage` 归位。
- **CT 执行器收窄**：`comptime` 只执行 `check.expand` 构造的 CT IR；
  删除 `comptime` 对 `sem_can_assign`/`sem_fold_*`/`sem_struct_finish`/`ty_*`/
  `CSym`/`static_data_*`/`em_*`/`sym_*`/`data_str_*` 的调用；类型/布局/静态
  数据事实由 CT IR 节点携带，由 `check` 落表。**否则 `check ↔ comptime`
  成环**。
- **残余字段收口**：`c_ast_capture`/`c_stats_ast_*` → `support.SessionCtx`；
  `c_active_file` → `support.SessionCtx`；`c_file_decls*` → `ast.AstStore`；
  `c_compile`/`c_pass`/`c_check_only`/`c_test_mode`/`c_legacy_system` →
  `support.SessionCtx`；`c_ct_*`/`c_res_is_addr`/`c_fold`/`c_data_n`/
  `c_iface_*` → `comptime.CtCtx`/`check`。
- 退出指标：`parse`/`ast` 不再 import `gen`；`check`/`comptime` 不再 import
  `gen`；`lower`/`backend`/`builtin` 不再 import `gen`；`gen` 只剩残
  余 `TaskCtx`（目标 ≤2 个 importer：`testkit`/`cmd`）。
- 测试：新增 `tests/modules/projects/gen-split/`（直接 import
  `support`/`token`/`check`，验证池/token 游标/类型/目标/诊断窄口）；
  `tests/modules/build-check.py` 的五个 fixture 改拷/改 import。

### GEN3：`gen` 语义残片清理 + 调用面切换

- 把仍留在 `gen` 的类型/符号/布局/ABI/静态数据/`sem_*` 动作迁 `check`
  （若 F5 已迁完，本阶段只删空壳）。
- `lower`/`builtin` 改 import `check`；`backend` 用 `support.ABI_*`；
  `build`/`cmd` 改调 `check` 的 `resolve/expand/full` 与结构 verifier。
- 删除 `gen.front_stage`、`gen.sem_*`、`gen.ty_*`、`gen.sym_*` 等空壳；
  `arch-check` 收紧 `gen` 预算。
- 退出指标：`import gen` = 0（除 `gen` 自身）；`gen` 行数 < 500（只剩
  残余 `TaskCtx` 访问口）。

### GEN4：状态收尾 + 删除 `gen`

1. 重盘 `TaskCtx`；删除已死字段（`c_lbl_n`、`c_em_suppress` 已无读点；
   `c_fp_*`/`c_temp_off` 先确认）。
2. 拆剩余簇：`ParseCtx`/`AstStore` → `parse/ast`；`CheckCtx` → `check`；
   `BuildCtx`/`SessionCtx` → `build`；`LinkCtx` → `link`。
3. 删除 `GenState` 与 `gen` 模块；`arch-check` 删除 `gen` 行与预算；
   `state_init` 残余默认值并入各所有者。
4. 文档/README/统计刷新；`just test`/`selfhost-native` 全绿后滚种子。
- 退出指标：无 `import gen`；`rg gen\. compiler` 仅剩注释/历史；
  `TaskCtx` 不再存在或只剩 `CheckCtx` 的别名；模块数 18（`gen`/`comptime`
  之一被删或保留，见 §10）。

## 6. 测试与验收

### 6.1 门禁命令

```bash
just                     # 种子冷编当前树
just test                # 三层回归（ANTLR 可选 + 语法 + 运行 + 模块/缓存/库）
just selfhost-native     # 固定点 + 自解析 + 全量语料 + 模块/项目验收
python3 tools/arch-check.py
python3 tests/tools/arch-check/check.py
```

`just test` / `selfhost-native` 默认 `YH_CACHE=off`；不要用全局缓存结果代替门禁。

### 6.2 纯移动与跨模块移动

| 变更 | 门 |
| --- | --- |
| 同模块内文件搬家/改名 | 该模块 `.s`/`.s.i`/`.s.ct` 逐字节一致（`cmp`） |
| 跨模块搬家（新增模块/改 import） | 旧/新编译器分别编译 `tests/yh-run` 与 `tests/modules`，退出码/stdout 一致；cc3/cc4 固定点；全量 `tests/yh` 正反例 |
| 状态字段搬家 | 用户语料产物一致 + 编译器固定点；不比较编译器自身 `.s.i` |
| 行为变更 | 单独提交 + 新增 `.yh` 用例；不与纯移动混在一起 |

跨模块移动后构建缓存/模块接口会失效，属于预期；`tests/build-cache` 需全绿。

### 6.3 新增/修改的测试

- `tests/modules/projects/gen-split/`：直接 import `support`/`token`/`check`，
  覆盖池/源/token 游标/类型兼容/目标解析；加一个越界依赖负例（`support`
  import `check` 应被 arch-check 拒绝）。
- `tests/tools/arch-check/check.py`：预算单调、反向边注入、递归扫描。
- `tools/compiler-tests.py`：`DEFAULT_MODULES`/`--modules` 加 `support`/`token`；
  `gen/buffer.yh` 的 `hexval`/`is_assign_op` 测试块随函数迁移。
- `tests/modules/build-check.py`：fixture 模块拷贝清单改为按依赖闭包生成；
  `llvmtarget`/`llvmfront`/`llvmchecked`/`llvmlower`/`astcheck` 的
  `import gen`/`gen.*` 改新模块。
- `tests/selfhost/native-selfhost.py` 的自解析/语料门不变；新增模块自动进入
  `compiler/` 扫描。

## 7. 风险与缓解

| 风险 | 证据/触发 | 缓解 |
| --- | --- | --- |
| `check` 变大、文件过多 | 语义模型+规则+分析+CT 驱动同模块 | 按 `check/base…full` 分文件；`arch-check` 只守依赖，不按行数阻断；公开面只留分析入口 |
| `comptime` 仍依赖类型规则 → 环 | ct_ir 调用 `sem_can_assign`/`ty_*` | F4 把类型/布局事实写进 CT IR；`comptime` 只执行；CI 用 `arch-check` 禁止 `comptime→check` |
| `support` 变成“小 gen” | 塞入类型/符号/分析 | support 只放基础数据/工具/目标/诊断；`arch-check` 边守卫 |
| 种子不认识新模块/新 import | 种子 0.0.12 | GEN1 第一提交先建空 `support` + 一个 `pub fn`，用种子冷编验证模块发现；失败则停 |
| `TaskCtx` 机械改写引入语义差 | 281 `np_data`/166 `c_src`/330 `c_pos` | 一簇一提交；GEN1 内完成 token 状态；每步 `just` + 语料 |
| fixture 拷贝漏新模块 | `build-check.py` 有 5 处模块清单 | GEN1 改为依赖闭包 helper；五个 fixture 先改 |
| 缓存键大面积失效/误命中 | 模块身份/接口字节变化 | 门禁 `YH_CACHE=off`；跨模块提交后跑 `tests/build-cache` |
| `.s.i` 字节一致门不可达 | 模块身份/符号后缀 | 用固定点+语料；不把编译器自身 `.s.i` 作为跨模块门 |
| 文档/统计再次漂移 | README 曾多次过期 | 每阶段同步 `compiler/README.md`、架构设计 §6、`just code-stats` |

## 8. 非目标

- 不改变语言语法、`.yh` 语义、ABI、诊断文案或退出码。
- 不引入线程池、LSP、查询系统或新后端。

- 不把 `builtin` 并入 `check`；保留内置函数/内置类型登记表。

- 不承诺编译器内部模块 `.s.i` 跨版本兼容。

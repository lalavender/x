# yh `gen` 职责拆分实施方案（2026-11-06 重新分析）

状态：**计划；GEN0–GEN2 待确认后开工，GEN3/GEN4 以 F5 为前置**。
决策见 [ADR-0021](../adr/0021-yh-gen职责拆分.md)；前端两遍化的 F0–F7 见
[todo](../todo.md)。

## 0. 范围与结论

本方案把 `compiler/gen` 的六类职责（token 词汇、语义模型、语义动作、每任务状态、
基础设施、目标/ABI）拆到 `token`/`sema`/`check`/`support`/`diag`/`target`，
并把状态按所有者移出 `TaskCtx`。**不新建万能 `state` 模块**；`gen` 在 GEN3/GEN4 删除。

重新分析后的关键结论：

1. **先拆叶子，后拆语义动作**。`support`/`diag`/`target`/`token`/`sema` 可先行；
   `sem_*` 必须等 F5 重写后再进 `check`，否则 `parse → check` 临时环且白做搬家。
2. **状态是主要成本，不是文件**。189 字段 `TaskCtx`、63 个文件引用；叶子状态
   （源/池/统计/诊断）必须随所属模块一起搬，剩余的 parse/check 状态等 F5 后拆。
3. **三处旧映射需修正**：`fail` 归 `support`（不是 `diag`）；`PDecl` 归
   `token`（不是 `ast`）；`sema` 依赖 `support, diag, target, token`（不只是 `support`）。
4. **跨模块搬家不能要求 `.s.i` 逐字节一致**。模块身份/符号后缀会变；用固定点 +
   全量语料等价作为门，同模块内文件搬家才要求字节一致。
5. **`gen` 的 183 个 `pub fn` 不是要平均切分**：按所有权分文件；
   `symbols.yh` 拆成 `support`（名字池）+ `sema`（类型/符号/折叠/命名空间）。

## 3. 归属表

| `gen` 符号/簇 | 去向 | 前提/说明 |
| --- | --- | --- |
| `TOK_*`、`TK_*`、`Tok` | `token` | 词法/语法共享；`token` 无 import |
| `PDecl` | `token` | 避免 `proj → ast` 与 `ast → proj` 成环 |
| `ATTR_*` | `sema` | 声明属性是语义标志；parse 经 `sema` |
| `is_assign_op` | `token` | 纯 token 区间判定 |
| `hexval` | `support` | 通用字节工具（从退役发射器迁入） |
| `Res` | `sema`（过渡） | `ast`/`comptime` 在 F1/F5 前消费；最终删除或 HIR |
| `CType`/`SField`/`TName`/`CSym`/`ModInfo`/`ImportEnt`/`ModNsEnt`/`PubAggDeferred` | `sema` | 语义模型 |
| `TY_*`/`SYM_*`/`F_*`/`ABI_*`/`CT_DIAG_*` | `sema` | 枚举/标志 |
| `name_intern`/`tml_intern_str`/`np_cstr`/`append_np` | `support` | 名字池是通用 intern 池；`proj/link/build/testkit` 也用 |
| `ty_*`/`sym_*`/`scope_*`/`em_*`/`data_str_*`/`static_data_*`/`abi_c_*` | `sema` | 类型/符号/常量/布局/ABI |
| `fold_*`/`sem_parse_number`/`sem_lit_fits`/`sem_can_assign`/`sem_promote` | `sema` | 纯规则；`comptime` 依赖 |
| `tg_layout_struct` | `sema` | 读 `CType/SField`；`target` 不能反向依赖 |
| `mod_ns_lookup*`/`mod_file_binding`/`mod_import_find` | `sema` | 命名空间解析；模块接口加载仍在 parse/check |
| `sem_call_*`/`sem_assign`/`sem_forin_*`/`sem_break`/`sem_declare_local`/`sem_struct_lit_*` 等动作 | `check`（F5 后） | 依赖 parser 游标/动作状态；F5 前留 `gen` |

| `err_lc`/`warn_lc` | `diag` | 带位置渲染；`diag → support` |

| `front_checked_*` | `check` | 受检阶段守卫 |
| `TargetInfo`/`TARGET_*`/`TG_*`/`target_*`/`tg_host_*` | `target` | 目标身份/数据模型/宿主探测 |
| `TargetCfg`/`target_cfg_defaults`/`bind_cfg` | `target`（类型/绑定）；`proj`（存储） | 唯一存储，fork 前绑定 |
| `clock_ns`/`console_*`/`argv_*` | `support` | 宿主平台 |
| `builtin` prelude 登记 | `builtin` 保留，`builtin → sema` | `prelude_add` 归 `sema` |

### 3.1 归属后的导出面

迁移时按消费者收紧 `pub`：

- `sema` 内部（`ABIValue`/`ABICursor`/`ABIArg`/`GLabel`/`DATA_STR_CAP` 等）不导出；
- `support` 只导出缓冲/池/源/统计/宿主的窄口，不重导出 `diag`；
- `token` 只导出词汇与 `PDecl`，不导出 token 状态（GEN1 阶段）；
- `gen` 的导出面逐阶段减少，GEN2 后只剩 `sem_*` 动作 + `task()`/`err_tok`/`front_stage`。

`just selfhost-native`。跨模块移动的提交不要求 `.s.i` 字节一致，按 §6 的语料等价门。

### GEN1：基础层 `support`/`diag`/`target`/`token`（1–2 周）

顺序与提交边界：

1. **support（纯工具 + 统计 + 宿主 + 基础错误）**
   - 新建 `support/support_00_model.yh`（`SourceCtx`/`PoolCtx`/`CompileStats`）、
     `support_10_buffer.yh`（`append_*`/`write_all`/`alloc`/`out_grow`/`cstr_eq`/
     `arr_cstr`/`fail`/`fail_path`）、`support_90_init.yh`；
   - 迁 `buffer.yh` 的追加/写出/分配/基础错误、`state.yh` 的 `CompileStats`、
     `clock/console/argv.*`、`hexval`；
   - 调用面：`gen.append_*`/`gen.write_all`/`gen.alloc`/`gen.cstr_eq`/
     `gen.arr_cstr`/`gen.out_grow`/`gen.hexval`/`gen.stats()`/`gen.fail`/
     `gen.fail_path` → `support.*`；`cache_store` 的 `task().cache_store` 改为
     `cache` 模块自持绑定。
2. **support（源 + 池）**
   - `SourceCtx`/`PoolCtx` 搬 `c_src*`/`c_path*`/`np_*`；
   - `read_source`/`set_source_path`/`name_intern`/`name_intern_lit`/
     `tml_intern_str`/`np_cstr`/`append_np*` → `support`；
   - 调用面：`gen.np_*`/`gen.tml_intern_str`/`gen.read_source`/
     `gen.set_source_path` → `support.*`；`gen.task().c_src`/`np_data` →
     `support.src()`/`support.pool()`；
   - `state_init` 拆出 `support.source_init`/`stats_init`。
3. **diag**
   - `DiagCtx`（`c_spec`/`c_errors`/`c_diag_line_bias`/`c_ct_expand_*`）+
     `err_lc`/`warn_lc` → `diag`；
   - parse 的推测解析改 `diag.spec_enter/leave`；
   - `err_tok`/`sem_err` 暂留 `gen`（GEN3/GEN4 迁 `check`）。
4. **target**
   - `TargetInfo`/`TARGET_*`/`TG_*`/`target_*`/`tg_host_*`/`target_arch_token`/
     `tg_darwin`/`TargetCfg`/`target_cfg_defaults`/`bind_cfg` → `target`；
   - `proj` 保留 `TargetCfg` 存储，`proj.init()` 调 `target.bind_cfg`；
     `cmd/common.yh` 的会话前奏改为按新 init 顺序调用
     `support/diag/target`（`state_init` 的残余等 GEN2/GEN3 再并）；
     `state_init` 的 fallback 留在 `target`（只服务单模块测试）；
   - `TargetCfg` 的 `module_mode`/`is_entry_mod`/`emit_*` 是构建/CLI 配置，

   - `tg_layout_struct` 暂留 `gen`（GEN2 迁 `sema`）。
5. **token（词汇）**
   - `Tok`/`TK_*`/`TOK_*`/`PDecl`/`is_assign_op` → `token`；
   - **不搬** `c_toks`/`c_tok_n`/`c_tok_cap`/`c_pos`；`err_tok` 留 `gen`；
   - `parse`/`ast`/`check`/`build`/`testkit`/`lex` 改 `gen.Tok`/`gen.TK_*` →

3. **折叠/兼容/布局/ABI/静态数据**：`fold_*`/`sem_parse_number`/`sem_lit_fits`/
   `sem_can_assign`/`sem_promote`、`tg_layout_struct`（改名 `ty_layout_struct`）、
   `abi_c_*`、`static_data_*`。
4. **模块命名空间**：`mod_ns_lookup*`/`mod_file_binding`/`mod_import_find` +
   `mod_*`/`c_mods*`/`c_sym_sfx_*`/`t_home*` 进 `SemaCtx`。
5. **隐藏 parser 状态显式化**：`ty_declare_name` 不再读 `c_toks[c_pos]`/
   `c_decl_*`；改为 `SemaCtx` 的 `decl_pub/attrs/form/def_line/def_col`，由
   parse/check 在调用前设置；`sem_err` 用 `diag.err_at(sema.here())`。
6. **消费者切换**：`comptime` 先改 `gen → sema`（uses `sem_can_assign`/
   `sem_fold_*`/`sem_res_const`/`sem_struct_finish`/`em_*`/`static_data_*`）；
   然后 `ast`/`check`/`lower`/`backend`/`builtin` 改 `sema`；`proj/link/cache`
   已在 GEN1 脱 `gen`。
7. **`sem_*` 留在 `gen`**；`gen` 顶部 `import sema`，`sem_*` 内的纯规则调用改
   `sema.*`；`build/module_worker`/`cmd/common` 的 `gen.sem_init_tables()`
   改为 `sema.init()` + 残余表初始化；`Res`/`sem_err` 的过渡路径记录在 ADR。

- 退出指标：`import gen` 仅 `parse/lex/build/testkit/cmd`；`gen` 行数约 2,700；
  `gen` 的 `pub fn` 仅 `sem_*`（约 67）+ `task()`/`err_tok`/`sem_err`/
  `front_stage`；`comptime`/`ast`/`check`/`lower`/`backend`/`builtin` 不再 import
  `gen`。
- 测试：新增 `tests/modules/projects/gen-split/`（`main` 直接 import
  `support`/`token`/`sema`/`target`，验证池/类型/目标/诊断窄口）；
  `tests/modules/build-check.py` 的 `llvmtarget`/`llvmfront`/`llvmchecked`/
  `llvmlower` fixture 改拷 `sema` 等新模块；`arch-check` 预算收紧到新值。

### GEN3：`check` 接语义（与 F1–F5 合并；**不得单独开工**）

- **F1**：`ast` 回归纯语法；`CheckedModule`/快照/切片键迁 `check`（或 F0 决定的
  `hir`）；移除 `ast → ir`/`ast → comptime`/`ast → sema`。
- **F2**：`parse` 纯语法；删 `gen.sem_*` 调用；`iface`/`iface_ct`/`parse_ct_layout`
  移出 parse；`PDecl` 索引上移 build/check。
- **F3–F5**：`check.resolve → 检查 CT 函数 → check.expand → check.full`；
  `sem_*` 在原文件上重写/迁 `check`；`Res`、`CheckCtx`、`err_tok`/`sem_err`、
  `front_stage` 归位；`build`/`cmd` 改调 `check` API。
- GEN3 只在 F5 验收通过后开始“删除旧路径”的提交；之前可以并行写新实现，但不得
  把旧 `sem_*` 先搬进 `check`。
- 退出指标：`parse` 不再 import `gen` 的语义动作入口（F2）；`ast` 只 import
  `token/support`；`lower` 只消费 `check/HIR`；`gen` 只剩 `TaskCtx`
  残余 + `err_tok`（token 状态在 GEN4 迁走）。

### GEN4：状态收尾 + 删除 `gen`

1. F5 后重新盘点 `TaskCtx`；删除已死的 parse/发射字段（`c_fp_*`/`c_temp_off`/
   `c_lbl_n` 等先确认无消费）。
2. 拆剩余簇：`TokenCtx`（`c_toks/c_pos`）→ `token`；`LexCtx` →
   `lex`；`err_tok`/`sem_err` → `check`（parse 用 `diag.err_at`）；`ParseCtx`/
   `AstStore` → `parse/ast`；`CheckCtx` → `check`；`BuildCtx`/`SessionCtx` →
   `build`；`LinkCtx` → `link`。
3. 删除 `GenState` 与 `gen` 模块；`arch-check` 删除 `gen` 行与预算；
   `state_init` 的残余默认值并入各所有者。
4. 文档/README/统计刷新；`just test`/`selfhost-native` 全绿后滚种子。
- 退出指标：无 `import gen`；`rg gen\. compiler` 仅剩注释/历史；
  `TaskCtx` 不再存在或只剩 `CheckCtx` 的别名。

## 6. 测试与验收

### 6.1 门禁命令

```bash
just                     # 种子冷编当前树
just test                # 三层回归（ANTLR 可选 + 语法 + 运行 + 模块/缓存/库）
just selfhost-native     # 固定点 + 自解析 + 全量语料 + 模块/项目验收
python3 tools/arch-check.py
python3 tests/tools/arch-check/check.py
```

`just test` / `selfhost-native` 默认 `YH_CACHE=off`；不要用全局缓存结果代替门禁。

### 6.2 纯移动与跨模块移动

| 变更 | 门 |
| --- | --- |
| 同模块内文件搬家/改名 | 该模块 `.s`/`.s.i`/`.s.ct` 逐字节一致（`cmp`） |
| 跨模块搬家（新增模块/改 import） | 旧/新编译器分别编译 `tests/yh-run` 与 `tests/modules`，退出码/stdout 一致；cc3/cc4 固定点；全量 `tests/yh` 正反例 |
| 状态字段搬家 | 用户语料产物一致 + 编译器固定点；不比较编译器自身 `.s.i` |
| 行为变更 | 单独提交 + 新增 `.yh` 用例；不与纯移动混在一起 |

跨模块移动后构建缓存/模块接口会失效，属于预期；`tests/build-cache` 需全绿。

### 6.3 新增/修改的测试

- `tests/modules/projects/gen-split/`：直接 import 新模块，覆盖
  `support.append_*`/池/源、`token` 常量、`sema` 类型兼容、`target` 解析；
  加一个故意越界依赖的负例（`support` import `sema` 应被 arch-check 拒绝，
  不是编译失败）。
- `tests/tools/arch-check/check.py`：预算单调、反向边注入、递归扫描。
- `tools/compiler-tests.py`：`DEFAULT_MODULES`/`--modules` 加
  `support`/`token`；`gen/buffer.yh` 的两个 `test` 块随 `hexval`/`is_assign_op`
  迁移。
- `tests/modules/build-check.py`：fixture 模块拷贝清单改为按依赖闭包生成；
  新增 `support/diag/target/token/sema` 后不需要逐 fixture 补。
- `tests/selfhost/native-selfhost.py` 的自解析/语料门不变；新增模块自动进入
  `compiler/` 扫描。

## 7. 风险与缓解

| 风险 | 证据/触发 | 缓解 |
| --- | --- | --- |
| 种子不认识新模块/新 import | 种子 0.0.12 | GEN1 第一提交先建空 `support` + 一个 `pub fn`，用种子冷编验证模块发现；失败则停 |
| `TaskCtx` 机械改写引入语义差 | 281 `np_data`/166 `c_src`/330 `c_pos` | 一簇一提交；每步 `just` + 语料；用 `rg` 统计剩余旧访问 |
| `sema` 偷读 parser 状态 | `ty_declare_name`/`sym_push` 读 `c_toks[c_pos]` | `SemaCtx` 显式位置/标志；`sema` 的 `ALLOWED` 不含 `gen/parse/proj` |
| `comptime ↔ check` 环 | `ct_call` 用 `Res`/`sem_*` | 纯规则进 `sema`；`comptime` 只依赖 `sema`；GEN3 前不搬动作 |
| fixture 拷贝漏新模块 | `build-check.py` 有 5 处模块清单 | GEN1 改为依赖闭包 helper；`llvmtarget`/`llvmchecked`/`llvmlower` 先改 |
| 缓存键大面积失效/误命中 | 模块身份/接口字节变化 | 门禁 `YH_CACHE=off`；跨模块提交后跑 `tests/build-cache`；版本键已含模块身份 |
| `.s.i` 字节一致门不可达 | 模块身份/符号后缀 | 按 §6.2 用固定点+语料；不把编译器自身 `.s.i` 作为跨模块门 |
| `target` 出现第二份可写 cfg | `proj` 存储 + `target` fallback | 绑定前只允许单模块测试用 fallback；worker fork 前 `proj.init()` 绑定；arch-check 统计模块级 `let` |
| 文档/统计再次漂移 | README 曾多次过期 | 每阶段提交同步 `compiler/README.md` 模块表、架构设计 §6、`just code-stats` 数值 |

## 8. 非目标

- 不改变语言语法、`.yh` 语义、ABI、诊断文案或退出码（行为变更单独切片）。

- 不把 `symbols.yh` 按 `pub` 数平均拆成多个小模块；按所有权分文件。
- 不把 `comptime` 并入 `check`；`comptime` 保持独立模块。
- 不把 `builtin` 并入 `sema` 作为本项前置；先保留薄表。
- 不承诺编译器内部模块 `.s.i` 跨版本兼容。

# yh V 风格编译诊断（源片段 + 精确 caret）实施方案

- 日期：2026-11-11
- 状态：规划（待确认后按 D0→D4 增量实施）
- 范围：`compiler/errors`、`compiler/token`、`compiler/lex`、`compiler/parse`、
  `compiler/check`、`compiler/testkit` 的诊断路径；不改语言语义、不改 AST 契约。
- 一句话：把当前 `path:line:col: 错误: 文案` 的单行诊断升级为 V 风格
  「错误行 + 上下各 2 行源码 + `~~~` 精确下划线 + 说明行」，同时修正
  「列号指向出错 token 之后」的系统性问题。

---

## 1. 目标与非目标

### 1.1 目标

1. 编译失败时，用户不用打开源文件就能看到出错的那一行、上下文和出错范围。
2. 下划线落在**真正出错的 token/表达式**上，而不是它后面的 `)`、`{`、行尾。
3. 所有现有诊断入口（`err_lc` / `err_tok` / `ct_err` / `testkit`）一次接入，
   不要求每个调用点重复拼格式。
4. 多文件模块、并行 worker、`.s.ct` 来源映射都有明确回退，不输出错行/错文件。
5. 保持 `errors` 为叶子模块、错误路径零堆分配；成功编译路径无额外开销。

### 1.2 非目标（本方案不做）

- 不做错误恢复后「一次报多个错误」；仍保持首个错误即停（见 §9 待确认）。
- 不做完整 V 诊断生态（backtrace、`Details`、`-error-limit`、多语言）。
- 不默认输出 ANSI 颜色；颜色放到 D5（可选，仅 TTY）。
- 不改列号语义：仍是 **1 基字节列**（与现有脚本、编辑器跳转兼容）。
- 不为链接器（ld/lld）原始输出做源码映射。

### 1.3 关键假设

- 允许把部分诊断的 `line/col` 从「解析游标位置」改为「出错构造的起始 token」。
  现有测试只断言「编译失败 / 包含某段文案」，不依赖具体列号（已核实：
  `tests/yh-run/fail` 只看失败与 `fail-contains`；只有一处正则要求
  `path:\d+:\d+` 头存在）。
- 片段渲染只在 `diag().line_bias == 0` 且源槽有效时启用；其余回退单行头。

## 2. V 的实测基线（本机 `/opt/homebrew/bin/v`）

错误示例（本机 V 0.5.1，2026-11-11）：

```text
vdiag5.v:4:10: error: infix expr: cannot use `int literal` (right expression) as `string`
    2 | 
    3 | fn main() {
    4 |     println("中文" + 1)
      |             ~~~~~~~~~~
    5 | }
```

从 `vlib/v/util/errors.v` 与实测确认的规则：

| 规则 | V 行为 | yh 采用 |
| --- | --- | --- |
| 上下文 | 出错行前 2 行、后 2 行 | 相同 |
| 行号栏 | `${line:5d} \| `，最小宽 5 | 相同，超过 5 位自动加宽 |
| caret 行 | 6 空格 + `\| `（与行号栏对齐） | 按行号栏宽度计算 |
| 单字符 | `^` | 相同 |
| 多字符 | `~` 重复「可见宽度」次 | 相同 |
| Tab | 源行与 caret 都替换为 4 空格 | 相同（固定 4，非 tab stop） |
| UTF-8 | 中日韩按显示宽 2 对齐 | 相同 |
| 行列语义 | 头行列号按字节；caret 按显示宽 | 相同 |
| 说明 | `Details:` / 后续建议行 | `说明:` 行（D3/D4） |

> 结论：格式可以直接对齐 V，且实现量集中在 `errors` 一处。

## 3. 现状普查（2026-11-11）

### 3.1 诊断入口

| 入口 | 调用点数 | 说明 |
| --- | ---: | --- |
| `token.err_tok` | 331 | 解析/语义检查最常用，位置取当前游标 |
| `ct_err` | 186 | 编译期执行，内部转 `err_tok` |
| `errors.err_lc` | 35 | 直接带行列 |
| `errors.warn_lc` | 2 | 警告 |
| `errors.fail` | 415 | 无位置；多数为内部错误/分配失败/IO |
| `errors.fail_path` | 88 | 无位置；IO/路径 |

现有 `tests/yh-run/fail` 共 143 例：

- 142 例输出 `path:line:col: 错误:` 头，只有 1 例是纯 `yh: ...`
  （`12-wraps-too-many.yh`，聚合登记上限）。
- 说明「拿不到位置」不是主要矛盾；**位置准不准、看不看得见**才是。

另一个旁路：约 20 处直接 `support.write_all(2, ...)`（link/build/testkit/
proj/check/iface），其中 `testkit/tc_diag` 已经自己拼了 `path:line:col`，
应统一收编到 `errors`（对应 `docs/todo.md` 现有条目）。

### 3.2 位置质量实测

对 142 个带位置的 fail 用例，取错误头行列号，看该列在源码中的字符：

- **65 例（46%）列号等于「行尾 + 1」**，即指向出错构造之后；
- 14 例指向 `{`，5 例 `)`，12 例 `$`，还有 `;`/`=`/`,` 等；
- 典型：

```text
$ ./yh tests/yh-run/fail/01-undeclared-var.yh -o /tmp/x
tests/yh-run/fail/01-undeclared-var.yh:3:18: 错误: 引用了未声明的名字
# 源行第 3 行：    let y int = z
#                                  ^ z 在第 17 列；18 已是行尾
```

```text
$ ./yh tests/yh-run/fail/02-bad-assign.yh -o /tmp/x
tests/yh-run/fail/02-bad-assign.yh:3:20: 错误: 不能把指针赋给非指针（用 .to_type）
# 源行：    let x int = "s"
#                             ^ 字符串是 17..19 列；20 已是行尾
```

```text
$ ./yh tests/yh-run/fail/05-redeclare.yh -o /tmp/x
tests/yh-run/fail/05-redeclare.yh:5:14: 错误: 顶层符号重定义（首次声明于 2:14）
# 第 5 行：fn dup() int {
#                     ^ 14 列是 `{`，不是重复的 `dup`
```

根因：大量 `err_tok` 在「已消费完名字/字面量/表达式」之后调用，游标已经
指向下一个 token；`sem_ident(start,len,...)` 等函数只拿到源字节区间，没有
token 下标，无法回报起始位置。

### 3.3 结构性问题

1. `errors` 是叶子模块，不持有源码，无法画片段；源字节在
   `support.src_ctx().data/length`，且会随 `read_source`/`mb_restore_front_file`
   整体换指针。
2. `err_lc` 只有一个 `col`，没有跨度；`tok.len` 明明可用但 331 处
   `err_tok` 全部丢弃。
3. 单行 2048 字节栈缓冲放不下 5 行源码；但并行 worker 共享 stderr，
   多行诊断必须尽量「一次写、块小」，否则会交错。
4. `check/convert.yh` 已经会跨文件临时切 `path`，但没有切 `source`，
   片段会读到另一个文件的内容。
5. `.s.ct` 跨模块来源映射只有路径与 `line_bias`，没有原始源码；必须回退。

## 4. 目标输出规范

### 4.1 完整格式

```text
tests/yh-run/fail/02-bad-assign.yh:3:17: 错误: 不能把指针赋给非指针（用 .to_type）
    1 | // fail: 类型不匹配，字符串字面量（*char）不能初始化 int 绑定
    2 | fn main() int {
    3 |     let x int = "s"
      |                 ~~~
    4 |     return 0
    5 | }
  说明: 字符串字面量的类型是 *char；用 value.to_type(int) 显式转换。
```

- 头行格式不变：`path:line:col: 错误: 文案`，脚本/正则兼容。
- 片段最多 5 行；出错行必须有下划线。
- `说明:` 行可选，缩进 2 空格，放在片段之后（无片段时紧跟头行）。
- 警告：`path:line:col: 警告: 文案`，同样渲染片段，不增加错误计数。
- 无源码/来源映射/行号越界：退化为今天的单行头，绝不猜内容。
- 编译期展开轨迹 `[编译期展开值: ...]` 仍追加在头行文案后（现状保留）。

### 4.2 宽度规则

1. 头行 `col`：1 基**字节**列（现状）。
2. 源行：`\t` 一律展开为 4 个空格；去掉行尾 `\r`（兼容 CRLF）。
3. caret 起始显示列：把出错行 `[0, col-1)` 的字节按 UTF-8 解码后累加
   可见宽度；tab 记 4；CJK/全角记 2；组合字符记 0；非法字节记 1。
4. 下划线长度：`[col-1, col-1+width)` 的可见宽度；`=1` 用 `^`，
   `>1` 用 `~` 重复；越界则夹到行尾；行尾错误允许 caret 落在最后一个
   字符之后（但 D2 后应极少出现）。
5. 长行：单行最多显示 512 字节/约 160 显示列；超长时围绕出错列开窗，
   首尾加 `…`，caret 偏移按窗口重算。保证单条诊断块 ≤ 4 KiB（PIPE_BUF 以内，降低并行交错）。

### 4.3 回退矩阵

| 情况 | 行为 |
| --- | --- |
| 未登记源槽 / 源为空 | 仅头行 |
| `line <= 0` 或行号超出源文件 | 仅头行 |
| `diag().line_bias != 0`（.s.ct 行号映射） | 仅头行 |
| `diag().plain != 0`（跨模块 CT 来源/强制单行） | 仅头行 |
| CT 来源路径已切、源仍是 sidecar | `plain=1`，仅头行 |
| 片段缓冲写满 | 截断并补 `…`，保证换行 |
| 并行 worker 同时报错 | 单次 `write_all`，块 ≤ 4 KiB（PIPE_BUF 以内） |

## 5. 架构设计

### 5.1 `errors` 模块（叶子、零分配）

新增两个「槽位」全局，与现有 `g_path_slot` 同构：

```yh
// errors/api.yh
let g_src_slot **u8   // 指向 support.src_ctx().data 的槽位
let g_src_len_slot *int // 指向 support.src_ctx().length 的槽位
let g_diag_buf [4096]u8 // 渲染块缓冲（BSS，不分配；≤ PIPE_BUF）

pub fn set_source_slot(data **u8, len *int) void
pub fn set_plain(on int) void // 1 = 关闭片段（CT 来源映射期间/兼容开关）
```

槽位而不是快照：`read_source` 会换指针，`mb_restore_front_file` 会切快照；
读槽位自动跟随，不会悬空。`support.state_init` / `support.session_reset`
在登记 `set_path_slot` 的同一处登记源槽。

### 5.2 诊断 API

```yh
// 带跨度：width 是同一行内的源字节数（<=0 视为 1）
pub fn err_span(line int, col int, width int, msg *char) int
pub fn warn_span(line int, col int, width int, msg *char) int
pub fn err_span_note(line int, col int, width int, msg *char, note *char) int

// 兼容层：旧调用点不改也能立即获得单行片段
pub fn err_lc(line int, col int, msg *char) int {
    return err_span(line, col, 1, msg)
}
```

`token` 模块（同模块内可直接调 `errors`）：

```yh
pub fn err_at(index int, msg *char) int       // 指定 token，宽度 = tok.len
pub fn err_tok(msg *char) int {               // 现有 331 处自动受益
    return err_at(ctx().pos, msg)
}
pub fn err_range(first int, after int, msg *char) int // 半开区间
pub fn index_at_offset(off int) int           // 按源字节偏移找 token
```

`check` 阶段跨文件（token 快照在 `proj.file(file_id)`）：

```yh
// 新增 compiler/check/diag.yh
pub fn file_span(file_id int, first int, after int, msg *char) int
// 内部：保存/切换 path + src_ctx().data/length，再 errors.err_span，最后恢复
```

### 5.3 渲染器

放在 `errors/render.yh`（私有函数，`api.test.yh` 同模块可直接测）：

```text
fmt_diag(buf, cap, line, col, width, msg, note) -> n
  ├─ 头行：path:line:col: 错误/警告: msg [+ CT 轨迹]
  ├─ 若 snippet 可用：定位行首/行尾
  │    ├─ 行号栏宽 W = max(5, digits(max_line))
  │    ├─ 前 2 行 + 出错行 + 后 2 行
  │    │    source: %*d | <展开 tab、去 \r 的行>
  │    │    caret : W+1 空格 | <显示列空格><^/~~~>
  │    └─ 长行开窗、UTF-8/制表符宽度换算
  └─ note: "  说明: ..."
```

约束：

- 不分配；只用 `g_diag_buf` 或调用方栈缓冲。
- 不改 `fail` / `fail_path` 的既有 `yh: ...` 形式。
- `fmt_diag` 是纯函数（只读全局槽位），便于单测。
- 单次 `write_all(2, buf, n)` 输出整块，降低并行交错概率。

### 5.4 文件上下文切换点

| 位置 | 现状 | 方案 |
| --- | --- | --- |
| `support.state_init` / `session_reset` | 登记 path 槽 | 同时登记源槽 |
| `parse` 每文件 `read_source` | 自动换 `src_ctx` | 源槽自动跟随 |
| `mb_restore_front_file` | 换 source/tokens/path | 源槽自动跟随 |
| `check/convert.diag_file_at` | 只切 path | 切 path + source，改用 `check.diag.file_span` |
| `check/iface_ct_origin_begin` | 切 path 到定义源、line_bias | `errors.set_plain(1)`；`origin_end` 恢复 0 |
| `testkit/tc_diag` | 自拼单行 | 改用 `errors.err_span`（有快照时带片段） |
| 其余 `write_all(2,...)` | 直写 | 能带位置的收编；纯链接输出保留 |

### D2：位置审计（2–3 天，主要工作量）

- 新增 `check/diag.yh`，`convert.diag_file_at` 迁移；AST 节点用
  `first..after` 生成跨度。
- 按调用密度审计：
  1. `check/api.yh`（100 处 `err_tok`）：类型不匹配、字面量越界、重复定义、
     调用参数个数/类型、未知名字/类型；
  2. `parse/parse_expr.yh`（50）：裸名字/模块成员/调用目标；
  3. `parse/parse_decl.yh`（44）、`parse/parse_global_init.yh`（34）、

  5. `check/iface_emit.yh`（14）、`check/sem_*`：保持当前 token 语义。
- 规则写入诊断规范：
  - 「当前 token 就是问题」→ `err_tok`；
  - 「刚解析完的构造是问题」→ `err_range(first, after)`；

   有界编辑距离（候选长度 ≤32，距离 ≤2，最多 3 个建议）。
4. `fail-contains` 文案保持不变，只追加行，避免大范围改测试。

## 7. 测试计划

### 7.1 单元测试（`compiler/errors/api.test.yh`）

直接调 `render.fmt_diag`（同模块私有可访问），断言完整字符串：

## 8. 风险与回退

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 位置审计范围失控 | 工期膨胀 | 先修「行尾 65 例 + 高频语义错误」；用 corpus 指标收敛；保留白名单 |
| 改正列号改变现有输出 | 脚本/用户预期 | 头行格式不变；已核实测试只依赖 `错误:`/`path:\d+:\d+` |
| 并行 worker 多行交错 | 诊断难读 | 整块单次 `write_all`；单行 512B、块 ≤4KiB；`just selfhost-native` 验证 |
| UTF-8/tab 对齐错 | caret 漂移 | V 实测样例做单测；CJK/组合字符/CRLF 全覆盖 |
| 跨文件/CT 显示错源码 | 误导用户 | 源槽 + `check/diag.file_span`；`line_bias`/`plain` 双开关回退 |
| 静态缓冲溢出 | 崩溃/截断 | 所有追加带容量；截断补 `…`；边界单测 |
| 错误路径变慢 | 可忽略（仅失败时扫描源码） | 成功路径不触碰；如需可加行号索引（后续） |
| 多错误需求 | 用户期待落差 | 明确首错即停；D5 单独立项，不混入本次 |

回退开关：

- `errors.set_plain(1)`：全局关闭片段（调试/兼容）；`DiagCtx` 零初始化即为富格式，避免漏初始化。
- 环境变量 `YH_DIAG_PLAIN=1`（D1 加入，读取一次）：强制今天的单行格式，
  便于对比与紧急回退；不写入用户文档，仅作为内部保险。

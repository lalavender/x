# yh 编译器代码统计工具方案

日期：2026-10-20。状态：**首版实现完成**。

用户已确认首版关注代码规模：代码行、注释、模块占比与大文件。
工具拟放在 `tools/yh-code-stats.py`，沿用仓库已有 Python 工具的方式。

## 1. 目标与实现选择

运行一次命令，回答编译器有多少 yh 源码、各职责模块占比多少、哪些文件过大。

| 方案 | 优点 | 代价 | 建议 |
| --- | --- | --- | --- |
| Python 标准库脚本 + yh 注释边界扫描 | 无新增依赖；可在编译器无法构建时运行；口径可控 | 维护少量扫描逻辑和边界用例 | 首版采用 |
| 接入第三方行数统计器 | 可利用已有报表能力 | 增加工具依赖，需要适配与验证 yh 词法口径 | 暂不采用 |
| 独立 yh 工具项目 | 工具也使用 yh | 需要编译与分发产物，不利于快速查看源码规模 | 有明确自托管需求时再考虑 |

首版采用一个脚本，不建立插件、数据库、服务或前端页面。
函数复杂度、死代码、注释质量、Git 增减和历史趋势另有需求时再设计。

## 3. 扫描范围

- 以脚本自身位置定位仓库根，递归统计 `compiler/` 内的 `.yh` 普通文件。
  从其他工作目录调用绝对脚本路径，结果也应一致。
- 统计工作区实际内容，包含尚未提交的新 `.yh` 文件；无需 Git、编译器或构建产物。
- 遍历时跳过 `.build/`、`tmp/`、`.git/` 和符号链接，避免重复及缓存污染。
- 所有平台变体一起统计，例如 `clock.darwin.yh`、`clock.linux.arm64.yh`。
  这是整个源码树的规模，不代表某个目标实际参与编译的代码量。
- `tests/`、冻结性能语料、`tools/`、`bin/`、`vendor/`、SDK 和生成汇编不在范围内。
- C/C++ 桥与头文件不计入该总数。报告明确标注“yh 编译器的 yh 源码规模”；
  完整工具链及第三方依赖体量不由这个数字代表。
- 每个文件按相对 `compiler/` 的第一层目录归组；直接放在根下的文件归入
  `(root)`。新增职责目录自然出现在报表中，无需硬编码八个目录。

## 4. 行数定义

按物理行统计，一行有多个语句也只计一行；花括号、声明头和属性均属于代码。

| 指标 | 定义 |
| --- | --- |
| 物理行 | 以 LF 分行，CRLF 计一次；文件末尾无换行的非空尾段计一行 |
| 空白行 | 除换行外只有空格、制表符、CR、换页符或垂直制表符的行 |
| 代码行 | 去除注释后仍有代码或字面量的行，包括代码与注释混合的行 |
| 纯注释行 | 非空白，且除空白外只有注释的行 |
| 混合行 | 同时包含代码与真实注释的行，是代码行的子集 |
| 注释占比 | `(纯注释行 + 混合行) / (物理行 - 空白行)` |
| 代码占比 | 某职责目录代码行 / 全部职责目录代码行 |

必须满足：`物理行 = 代码行 + 纯注释行 + 空白行`。
混合行单独展示，不再加进总行数。纯空白行即使处在块注释内也归为空白行。
空文件为 0 行；末尾换行不额外产生一行；孤立 CR 按空白处理，不视为新行。
比例分母为 0 时，文本显示 `—`，JSON 使用 `null`。
注释占比只反映文本分布，不表示注释是否充分、正确或有用。

## 5. yh 扫描规则与错误处理

依据 `docs/yh.g4` 的 COMMENT / STRING / CHAR 规则与
`compiler/lex/lexer.yh` 的实际行为，只识别统计需要的词法边界：

1. 普通代码中识别 `//` 行注释与 `/* ... */` 非嵌套块注释。
2. 字符串和字符字面量内的注释标记按代码处理。
3. 字面量中的反斜杠转义防止引号被提前关闭；注释内的引号不改变状态。
4. 跨行块注释、同一行多段注释、注释结束后继续出现代码均正确归类。
5. 不解析表达式、类型或函数，不验证语法与语义；只对未闭合字面量、
   未闭合块注释等导致统计边界不可信的情况报错。

读取失败、非法 UTF-8、未闭合词法边界或没有找到源文件时，以 stderr 输出
具体路径及可用行号，返回非零；不发布看似完整的部分统计。
不要采用“按行以 // 开头判断”或“正则先删除全部注释”的实现。

## 6. 命令与报告

可直接运行以下命令：

```sh
python3 tools/yh-code-stats.py
python3 tools/yh-code-stats.py --top 20
python3 tools/yh-code-stats.py --format json > tmp/yh-code-stats.json
make code-stats
```

默认文本报告包含：

1. 统计范围和全平台源码口径。
2. 总文件数、物理行、代码行、纯注释行、空白行、混合行与注释占比。
3. 按职责目录汇总的同口径表格，附代码占比。
4. 默认前 10 个大文件：相对路径、物理行与代码行。
5. 超过 1,000 物理行的文件数，作为整理提示，不阻断退出码。

大文件按物理行降序、同值按相对路径升序；职责目录按名称升序。
`--top N` 要求非负整数，0 表示隐藏排行。
首版只支持 `--format text|json` 与 `--top`，不加筛选表达式与通用配置文件。

JSON 包含 `schema_version: 1`、统计口径、总计、职责目录汇总与全部文件记录。
文件记录携带仓库相对路径、职责目录和五类行数；`--top` 只影响文本排行，
不裁剪 JSON 文件明细。输出不包含机器绝对路径和易变时间戳，便于后续复用。

成功退出 0；读取或扫描失败退出 1；命令行参数错误退出 2。
`make code-stats` 只调用脚本，不依赖 `make` 或编译器构建。

## 7. 实现结构

一个脚本内保持四个清楚的步骤：

`发现源文件 → 逐文件状态扫描 → 按职责目录求和 → 输出文本或 JSON`

逐文件只保留行分类与计数，整次执行保存文件记录用于排行和汇总。
总扫描工作量与源码字节数成正比；无需并行、缓存或复用编译器内部全局状态。
函数与数据结构写中文说明，保持现有 Python 工具风格，不为凑行数拆文件。

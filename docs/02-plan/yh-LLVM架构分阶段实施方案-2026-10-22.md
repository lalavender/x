# yh LLVM 架构分阶段实施方案

> 执行说明：后续使用 writing-plans 对应的 executing-plans 工作流逐任务执行，
> 每项有独立验证结果；本次只交付计划，不启动实现、不自动提交现有工作区。

**目标（Goal）**：在保持 yh 语义、LLVM 唯一后端与滚动自举稳定的前提下，收口编译入口，
建立函数粒度 lowering 接缝，再逐项推进增量复用与并发隔离。

**架构（Architecture）**：保留 CheckedModule → yh IR → LLVM IR → 内嵌 LLVM/lld。
Nanopass 用于逻辑阶段的小变换和契约验证；通用优化、机器 IR、phi 消解与分配继续由 LLVM 承担。
先在现有模块内组织职责，不引入新 Core 表示、pass 插件或另一套通用优化器。

**技术（Tech Stack）**：yh、现有固定 LLVM/lld 与 C/C++ 薄桥、Python 回归脚本、Make、自举门。

**依据（Spec）**：[架构设计 §4.1/§7](../03-design/yh-架构设计.md)、
[ADR-0014](../adr/0014-yh采用LLVM作为正式代码生成后端.md)、
[LLVM 语义与 ABI 契约](../03-design/yh-LLVM语义与ABI契约.md)。

日期：2026-10-22。基线：`llvm` / `895140a`，另含当前未提交的 builtin 迁移。
状态：LA0–LA3 已完成；LA4/LA5 专项设计已交付、实现待启动，
见 [LA0–LA2 报告](../01-finished/yh-LLVM架构LA0-LA2-2026-10-22.md)、
[LA3 报告](../01-finished/yh-LLVM架构LA3-2026-10-22.md) 与 LA4/LA5 设计。
2026-11-06：LA4 文件级对象已撤销（[ADR-0020](../adr/0020-yh对象粒度停在模块级.md)），
本文 LA4 仅保留历史设计；LA5 线程池仍有效。

## 1. 全局约束

- 保持现有 `.yh` 语法、语义、模块可见性、ABI、诊断规则与 O0 默认/O2 显式配置。
- LLVM 是唯一代码生成后端；不恢复 legacy，不增加 O1，不自研机器 IR/寄存器分配。
- 普通 AOT 产物与嵌入 LLVM 的编译器分别审计依赖；不扩大薄桥职责。
- 代码使用上一代宿主种子可编译的 yh 子集；只导出真实跨模块消费者需要的声明。
- 快照所有权、借用视图的生命周期、IR verifier、目标身份和原子提交继续作为硬边界。
- Linux 为实施主线；本地仅跑本平台门，完整多平台由 Gitea Actions 承担。
  RS2/RS3 专项优先在 Linux 开展，不在 Mac 上为计划预跑其他平台。
- 每个代码切片添加或扩展 `tests/yh-run/` 或 `tests/modules/` 的 `.yh`，执行 make
  和针对性验证；阶段结束执行 make test 与 make selfhost-native。
- 当前 builtin 改动是执行输入的一部分。实施时保留它，不自动 stash/reset/提交用户改动，
  不从仅有 HEAD 的新 worktree 开始后误以为已有 builtin。
- 临时产物放 `tmp/llvm-architecture/`；不清理 `tmp/llvm-migration` 的固定闭包缓存。
- 全绿后才允许 make seed；纯搬迁与行为修复分成不同切片，不混入语法变更。
- 不用墙钟超时或线程完成顺序决定产物；块/符号/诊断/对象清单保持确定顺序。

## 2. 范围与交付包

| 包 | 编号 | 内容 | 完成后的能力 |
| --- | --- | --- | --- |
| 第一包：职责收口 | LA0–LA2 | 入口回归、统一发射、check 对齐、拆 lowering、分离模块准备与函数构造 | 现有行为保持，函数粒度边界可独立验证 |
| 第二包：增量复用 | LA3–LA4 | 可重绑定的函数 IR 缓存、文件对象与 manifest | 分别减少 lowering 和 LLVM 对象生成的重做范围 |
| 第三包：并发隔离 | LA5 | 显式前端/AST/CT 上下文、宿主线程与确定性 | 满足并发前提后引入真正线程池 |

依赖顺序：

```text
LA0 → LA1a 发射收口 → LA1b 单文件 check 对齐 → LA2a 文件拆分 → LA2b 函数接缝
                                                                   ↓
                                                          LA3 IR 复用 → LA4 文件对象
LA2b + 宿主线程/标准库前提 → LA5（后续专项）
```

第一包不承诺降低毫秒数，也不宣布 RS2/R2c 完成。第二包的函数 IR 缓存首先减少 lowering，
尚不等于跳过函数类型检查或整模块 LLVM 编译。性能比较由现有专门任务接收阶段计数与产物，
本计划不另建一套 20 轮性能工程。

## 3. Review Focus：五项优先回归

| 输入/条件 | 必须保持的行为 | 归属 |
| --- | --- | --- |
| 无 main 的库文件，含编译期函数/布局常量 | check 成功；程序构建仍要求入口；check 不进入 LLVM | LA0、LA1b |
| 路径有空格/中文，失败前存在有效产物 | argv/路径不被拆词；失败不提交坏对象/manifest/程序 | LA0、LA1a |
| 嵌套控制流、取址、聚合副本、CT 展开来源 | 运行结果和定位保持，phi/所有权校验通过 | LA2 |
| 前面插入声明或仅调整注释/行号 | 复用的 IR 不引用旧模块 ID，诊断位置按当前源码更新 | LA3 |
| 跨文件私有函数/全局与运行时 helper | 对象之间可解析；跨模块仍私有；无重复定义 | LA4 |

## 5. LA0：冻结可核对的入口行为

**文件**：新增上述 Python harness、`llvmarchitecture/project.toml`、
`llvmarchitecture/src/main/main.yh`、`src/main/helper.yh`，以及
`llvmarchitecture/cases/library.yh`、`invalid.yh`、`lowering.yh`；修改 Makefile。
project 的 source 明确为 `src`，反例放 cases，避免被正常项目扫描。

**测试接口**：harness 接受 `--compiler-path`、`--case entries|check|lowering|all`、
`--opt-level 0|2` 和可选 `--baseline-compiler`；省略级别时分别验证 0/2。
未传 --target，让候选使用自身默认目标，不写死 x64，不执行跨目标产物。
基线和候选使用同一源码绝对路径、SDK/标准库环境及构建参数。

- [x] 写入口 fixture：`product(6, 7)` 的 main 返回 42；项目额外跨文件调用 helper。
  比较单文件/项目/run 的退出码；文本输出含 target/函数定义，汇编输出非空。
- [x] 写库正例和未声明名字反例：库 check 返回 0；反例返回非 0 且保留路径/行/列。
  PATH 置为无工具目录时，check 仍成功且不生成 LLVM、对象或最终程序。
- [x] 写失败发布回归：先成功构建并记录输出摘要，再引入源码错误或无效链接输入；
  本轮失败，旧有效程序不变，没有新的成功 manifest；恢复后能再次构建。
- [x] 工作目录含中文/空格；harness 用 argv 调用，收集 stdout/stderr 和文件清单。
- [x] 在现状上运行用例，保存可执行基线及环境/输入摘要到 `tmp/llvm-architecture/baseline/`。
  组织重构比较冻结 fixture 的 `.ll`，不比较不同编译器源码对应的自编汇编。
- [x] 验证 oracle：临时让 fixture 返回 41 或破坏一个预期产物，harness 必须失败；
  恢复后通过。它验证外部行为，不以函数名/文件布局断言实现。
- [x] 接入 selfhost-native。若现状已有语义差异，先保存复现并单列缺陷，
  不降低断言，也不把未定位差异混进重构。

**验收命令（harness 创建后可用）**：

```bash

python3 tests/selfhost/llvm-architecture.py --compiler-path ./yh --case all
python3 tests/selfhost/check-command.py --compiler-path ./yh

```

期望：命令退出码均为 0；harness 各项通过，故意扰动失败；保存基线后才进入 LA1。

## 6. LA1a：统一快照到产物的驱动

**文件**：新增 `cmd/llvm_pipeline.yh`；修改 `cmd/llvm_emit.yh`、
`cmd/module_worker.yh` 与 LA0 fixture/harness。

**内部接口，保留现有调用名，不新增 pub**：

```text
llvm_emit_module_to(unit *ast.CheckedModule, kind int, out_path *char,
                    text_path *char, stats *LLVMEmitResult) int
llvm_emit_text_only(unit *ast.CheckedModule, text_path *char,
                    stats *LLVMEmitResult) int
llvm_prepare_module(unit *ast.CheckedModule, mod_ir *ir.IRModule,
                    output *backend.LLVMOutput) int
```

`llvm_prepare_module` 是新增私有 helper：输入为已验证且未修改的借用快照，两个出参
初始为零；成功返回 0 并交出独占的模块 IR/LLVMOutput，失败释放候选并保持出参为零。
前两个接口共用它，完成后释放临时 IR/Output；快照始终由调用方释放。
kind 继续为 0=对象、1=汇编。文本专用路径不调用桥；CLI 的 stdout/链接协调仍由外层处理。

- [x] 扩展 entry 用例，分别覆盖 O0/O2、单文件、项目、纯文本、汇编与失败路径。
  明确项目 `--emit-llvm` 的现有对象生成行为，按真实基线保持，不由旧注释推导新规则。
- [x] 先抽取 prepare/release 与文本写出共用部分，保持阶段执行顺序和诊断策略。
- [x] 模块 worker 改调用 `llvm_emit_module_to`；去除本次造成的重复主体，
  保留模块前端与接口/缓存提交职责。统计只在实际成功发射后累计一次。
- [x] 将对象临时写入、machine 校验和发布收口；复用已有桥原子写入能力，
  正式对象只在完整成功后替换。只清理本轮临时文件，不顺带修改链接政策。
- [x] 对照 LA0：冻结 fixture 的 LLVM 文本相同，运行/诊断与失败发布一致；
  引入 `.yh` 新增覆盖，不只用搜索“有一个调用点”作为验收。

**验证**：make → harness `--case entries` → make test → make selfhost-native。
若发现原路径已有失败发布缺陷，先用新增用例复现，再独立修复并记录行为变化。
LLVM source map 的细粒度诊断接线不是本次搬迁的前置，留作公共驱动建立后的独立小任务。

## 9. LA2b：分离模块准备与逐函数构造

**文件**：上一步的 lowering 文件、`module_snapshot_ctx.yh`，以及现有 llvmlower
项目 `.yh` 探针和 LA0 harness；此步不读写函数缓存。

保留公开入口 `ast.lower_module(unit *CheckedModule, out *ir.IRModule) int`。
在 ast 内抽出私有函数，先不导出未被生产消费者使用的 session API：

```text
checked_lower_prepare_tables(l *CheckedLower, types *ir.IRType) int
checked_lower_declare_functions(l *CheckedLower) int
checked_lower_build_functions(l *CheckedLower, types *ir.IRType) int
checked_lower_release(l *CheckedLower) void
```

`lower_module` 初始化私有上下文并依次调用；复用已有 `checked_lower_function`。
prepare 负责来源/类型/静态数据/全局映射，declare 按原顺序登记全部运行期签名，
build 按原顺序逐函数构造，release 只释放本次上下文，模块所有权仍按成功提交/失败回收处理。

- [x] 扩展 `.yh`：同模块多个同名局部绑定、互递归、函数内字符串/静态数据、
  中间函数 lowering 失败；合法路径的完整模块 verifier 通过，失败不交出半成品。
- [x] 分别抽取 prepare、declare、build 和 cleanup，每步保持原有顺序与返回协议。
  不能在 declare 阶段顺带产生函数体，也不能遗漏函数 lowering 追加的字符串/运行时符号。
- [x] 封存函数所读的布局、绑定、调用/副本策略和 CT 已展开事实的来源说明；
  保持现有 helper 规则，暂不新增 Core 结构或复制整份 AST。
- [x] 对比 CT/运行期及 O0/O2：窄整数、bool 字节、移位、转换、聚合/切片别名。
  只比较两侧均有定义的输入；编译期专属报错规则单列，不能强制抹平差异。
- [x] 输出下一阶段的函数依赖/贡献清单：签名、类型布局、符号/常量、CT、
  匿名全局/重定位和来源。清单是缓存单元设计依据，此步尚未实现复用。

**验收**：旧公开 lowering 入口行为不变、引用闭包完整、冻结 fixture 对照及全门通过。
此时第一包完成；完成报告明确“函数接缝已建立，函数 check/IR 缓存仍未完成”。

- 规范化忽略注释/空白及瞬时 arena ID，保留名称/绑定关系、常量位型、有效操作和布局事实。
- 来源保存可在当前源码解析的稳定位置描述；命中后重建当前 IRModuleLoc，不输出旧行号。

- 统计区分模块对象命中、函数 IR 命中/未命中、实际检查/降低函数数及 LLVM 模块调用数。

缓存损坏只重建对应记录；变布局/ABI/CT 依赖正确失效；源码位置更新、全模块 verifier 通过。

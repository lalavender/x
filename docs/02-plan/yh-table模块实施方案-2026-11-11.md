# yh `table` 模块实施方案（2026-11-11）

状态：**方案，待评审/待排期**。用户已定方向：新建底层 `table` 模块集中语义存储，
参考 V 语言 `ast.Table`，消掉分散的 `model_store`。

> 不直接放 `ast`：yh 的 `ast → comptime`（CT 零拷贝镜像，[ast/api.yh] 断言
> `sizeof(AstExpr)==sizeof(comptime.CtExpr)` 并调 `ct_ir_import`），且 support 自身
> 读 `ms()`。放 ast 会同时造成 `comptime→ast→comptime` 与 `support→ast→support`
> 双环。V 的 ast 在底层、yh 的 ast 在 comptime 之上，层序相反，故取**新底层模块**。

## 1. 目标与层序

新增 `compiler/table/`（`module table`），集中「编译期语义存储 + 表操作 + 值规则」：

```
types  errors  token  support（基础设施：缓冲/池/源/会话/目标/诊断）
   ↑
 table（ModelStore + 符号/签名/类型/枚举/字符串标签表 + 值规则 + C ABI 标量分类）
   ↑
 comptime  ast  builtin  check  parse  build（全部向下依赖 table）
```

- `table → types, support, token, errors`（池/缓冲/源字节/TK_*/ATTR_*/诊断）。
- **support 不得 import table**：搬完后 support 残留代码不能引用 `ms()`/`SYM_*`/
  `F_*`/`VK_*`/被搬函数。这是无环的关键约束。
- lower/backend 不依赖 table（只读 CheckedStorage 快照），不变。

## 2. 搬迁清单（原子簇）

support 不能 import table，所以**读 `ms()` 的整簇必须一次搬完**（不能先搬存储后搬操作）。

### 2.1 存储与结构
- `ModelStore`、`CSym`（符号行）结构（现在 support/api.yh）。
- `g_model` 单例、`ms()`、`mstore_reset()`、`AGGTYPE_LIMIT`（现在 model_store.yh）。
- `CType/SField/TName` 已在 types，不动；ModelStore 字段引用 `types.*`。

### 2.2 表操作（support/api.yh 中读 ms() 的 32 个函数）
`scope_push/scope_pop`、`model_type_push/_agg`、`model_layout_struct`、`ty_push`、
`ty_count`、`ty_name_attrs`、`ty_is_scalar/integer/signed/float`、`ty_is_opaque`、
`ty_has_opaque_value`、`ty_lookup_name/_pool`、`sym_lookup/_off`、`sym_ct_lit_text`、
`sym_find_enum_member`、`sig_add`、`fn_abi`、`sem_struct_finish`。

### 2.3 值规则
- `value_kernel.yh` 整体（`vk_fold_binop/unary`、`vk_can_assign`、`fp64_norm_bits`、
  `sem_fold_norm`、`sem_fold_fp_to_int`、`sem_fold_float_convert`、`sem_lit_fits`）。
- `VK_*` 错误码常量。

### 2.4 C ABI 标量分类（并行会话新加，读 ms()）
`cabi_scalar`、`cabi_param`、`c_layout`。**须与并行会话协调**（见 §5）。

### 2.5 编译期表（tables.yh）
- `em_*` 枚举成员表 + `em_add`（读 ms()）→ table。
- `data_str_*` 字符串标签表：**建议一并进 table**（同属编译期存储，comptime 经槽镜像读），
  保持「语义存储都在 table」的内聚。若拆分会让 support 残留 data_str、table 持有 em，
  两表分离无收益。→ 决策点 D1。

### 2.6 常量
`SYM_*`、`F_*`（47 个符号种类/标志）→ table。`ATTR_*` 留 support/token（词汇层，
ty_name_attrs 经 token.ATTR_* 读）。`CT_DIAG_*`/`CT_TY_*` 等 comptime 镜像常量留 comptime。

## 3. support 残留（搬完后）

缓冲/池/源（`append_*`/`pool_ctx`/`src_ctx`/`read_source`）、会话/目标
（`session()`/`cfg()`/`TargetInfo`）、`ModuleSym`（msym）、`FrontCtx`（fc）、`Res`、
`static_data_*`、诊断转发、平台无关基础设施。

**残留校验**：搬完后 `rg "ms\(\)|SYM_|F_|VK_|ty_|sem_fold|vk_" compiler/support`
应只剩注释/无关项；`session_reset`/`state_init` 若调 `mstore_reset` 须改由
`check.sem_init_tables` 调 `table.mstore_reset`（support 不再调）。

## 4. 消费方改限定名（约 1000+ 处）

`support.ms()→table.ms()`、`support.CSym→table.CSym`、`support.SYM_*/F_*/VK_*→table.*`、
`support.ty_*/sem_fold_*/vk_*/scope_*/sym_lookup*/cabi_*→table.*`。
涉及 check/parse/ast/comptime/build/builtin，逐文件补 `import table`。

关键耦合点：
- **CT 零拷贝镜像**：`comptime/ct_facts.yh` 的槽绑定改指 `table.ms()`；
  `ct_facts_sync`（cmd/common、check/api、build/module_worker、comptime/api）随之改。
- **布局断言**：`check.ct_type_layout_ok` 的 `sizeof(support.CSym)` → `sizeof(table.CSym)`；
  `sizeof(support.ImportEnt)` 已是 proj（ADR-0024）。
- `.s.i`/`.s.ct` 编码值不变（常量值逐一保持），用户程序产物应逐字节一致。

## 5. 排期与并行协调（硬约束）

- 并行会话正在大改 `support/api.yh`（新增 `cabi_*`、ms() 引用 79→99，行号漂移）。
  本方案与它**改同一文件**，且 `cabi_*` 属搬迁清单 → **必须错开**：
   either 等并行会话落地并调和 types 限定后开工，or 在独立 worktree 做本搬迁再合并。
- 当前完整门禁被并行 `cabi_*` 裸 `TY_*` 挡住（见 finish 遗留）；本搬迁开工前应先复跑
  确认基线绿。

## 7. 待决策
- D1：`data_str_*` 字符串标签表是否随 em_* 一并进 table（推荐：是）。
- D2：`Res` 是否随迁（推荐：留 support，它是表达式结果描述符，非存储表）。
- D3：开工时机——等并行会话 vs 独立 worktree（推荐：独立 worktree，避免 support/api.yh 撞车）。

## 8. 风险
- 原子簇大（~600+ 行移动、1000+ 调用点改限定），一次冷编暴露所有接线错误，需逐模块修。
- CT 镜像槽指针改指 table 后，comptime 读路径必须同步，否则 CT 求值读空表。
- 与并行会话合并冲突高（同文件）；务必先协调。

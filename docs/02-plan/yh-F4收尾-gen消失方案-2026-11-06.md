# F4 收尾：让 `gen` 消失（方案稿）

状态：方案待评审（2026-11-06）
前置：GEN4（`TaskCtx` 归零）、F2-K1/K2（`gen` 收缩为 3 个值内核函数）

## 1. 现状

`gen` 现在只剩 **1 个文件 / 337 行 / 3 个 pub fn**：

| 符号 | 用途 | 依赖 |
| --- | --- | --- |
| `sem_can_assign(dst, src, is_lit, ival, big)` | 隐式转换判定（C 侧 `support.sem_lit_fits` 已下沉） | `support.ms()` 类型表、`sem_err` |
| `sem_fold_const_binop(op, tid, left, right, *result)` | 常量二元折叠（整数溢出/除零/移位/浮点比较） | `support.*` 值规则、`sem_err` |
| `sem_fold_const_unary(op, tid, value, is_lit, *result)` | 常量一元折叠 | 同上 |

三个符号的消费方：`comptime`(3 符号)、`parse`(1 符号：`sem_can_assign`)、
`check`(3 符号)。`arch-check` 两条白名单已齐平。

**唯一的阻塞点**：这三个函数一共 **23 处 `sem_err(msg)`**，而 `sem_err` 就是
`token.err_tok(msg)`——它要读 token 游标拿 `line/col`。`support` 是叶子模块，
不能 `import token`，所以这三个函数无法直接下沉 `support`；而迁 `check` 又会
让 `comptime → check` 成环（`check → comptime` 已存在）。

## 2. 两条路线

### A（推荐）：函数返回**错误码**，调用方格式化诊断

把「算」与「报」拆开：

```yh
// support/value_kernel.yh（新增）
pub const VK_OK int = 0
pub const VK_AGG_MISMATCH int = 1 // 聚合类型不匹配
pub const VK_PTR_MISMATCH int = 2 // 指针类型不匹配（需要 .to_type 显式转换）
...
pub fn sem_can_assign(dst int, src int, is_lit int, ival i64, big int) int // 0=可赋；>0=错误码
pub fn sem_fold_const_binop(op int, tid int, left i64, right i64, result *i64) int
pub fn sem_fold_const_unary(op int, tid int, value i64, is_lit int, result *i64) int
```

调用方用一张错误码 → 消息表 + 自己的诊断入口：

- `check`：`check.err_code(code) == token.err_tok(msg_of(code))`
- `comptime`：`ct_err(msg_of(code))`（已有，取 CT 目标/token 位置）
- `parse`：`token.err_tok(msg_of(code))`

消息表放在 `support`（纯字符串，无诊断），三层共用，避免文案漂移。

**改动量**：3 个函数 ~340 行改写 + 消息表 ~25 行 + 三处适配器 + 约 20 个调用点
改成「取码后报错」。**收益**：`gen` 目录整体删除，`import gen` 归零，
`comptime→gen`/`parse→gen` 白名单归零。

**风险**：诊断文案与位置必须逐字保持（`tests/yh-run/fail/73..79` 断言文案）。
缓解：先把 23 条消息抽成常量表，改完后用 `yh test`（fail 用例）+ 全量语料比对。

### B（原 F4-5 路线 B）：CT IR 增加折叠节点

让执行器只产出操作数，由 `check` 求值回填。问题是**折叠发生在求值中途**
（后续表达式依赖结果），`check` 无法在下层被回调，只能把整个 CT 求值改成两段
（先建 IR、后求值），改动面远大于 A，且要重写 `ct_ir*` 的调度。**不建议**。

## 3. 实施步骤（路线 A）

| 步骤 | 内容 | 验证 |
| --- | --- | --- |
| A1 | 新建 `support/value_kernel.yh`：错误码常量 + 消息表 + 三个返回码的函数（从 `gen/value_rules.yh` 移植，把 23 处 `sem_err(...)` 改成 `return VK_*`） | `yh check` |
| A2 | `check/errors.yh` 加 `err_code(code int) int`（映射 + `token.err_tok`）；`comptime` 加 `ct_err_code`；`parse` 直接用 `token.err_tok(msg_of(code))` | `yh test`（fail 用例） |
| A3 | 三个消费层的调用点切换：`gen.X` → `support.X` + 各自报错；`import gen` 逐模块移除 | `yh check` + `build-check.py` 基线 88/128 |
| A4 | 删除 `compiler/gen/`；`arch-check` 删掉两条白名单（改为断言「不得 import gen / gen 目录不存在」）；刷新架构文档与 ADR-0021 | `arch-check` 自测 6/6 |
| A5 | 滚种子（`just seed`，需 `just` 可用） | `just test` + `just selfhost-native` |

| 判据 | 目标 |

## 5. 风险

| 风险 | 缓解 |
| --- | --- |
| 诊断文案/位置漂移 | 23 条消息抽成 `support` 常量表，改完逐条跑 fail 用例 |
| `comptime` 的 `ct_err` 与 `token.err_tok` 位置语义不同 | 现状已如此（CT 有自己的位置来源），保持各层原有入口不变 |
| 自举种子不认新文件 | `support/value_kernel.yh` 只放在既有模块目录内，不改语法 |
| 无法本地跑 `just` | 门禁用 `yh check` + `arch-check`（含自测）+ `build-check.py` + fixture 实跑 |

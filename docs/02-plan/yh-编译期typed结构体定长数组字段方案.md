# yh 编译期 typed 结构体定长数组字段方案

日期：2026-10-06。状态：已完成。

## 目标

让 `@[comptime]` 函数中的本地具名结构体可包含定长整型数组字段；字段初始化、结构体复制和数组变量赋值遵循按值语义，字段可通过已有的下标读写与整数复合赋值访问。

## 边界

- 字段仅接受定长数组，元素必须是现有 `ty_is_integer` 支持的标量。
- 结构体嵌套和其数组字段继续由现有 32 层递归限制约束。
- 不支持切片字段、嵌套数组字段、聚合参数/返回、指针或联合体。
- 数组表达式仍按当前语法通过已定类型的局部变量传入结构体字段初始化；不增加字段上下文推断语法。

## 实施步骤与验证

1. 新增单文件和同模块跨源文件 `.yh` 回归；单文件首先在结构体字段类型检查处失败，模块项目首先暴露 AST 切片间合法空洞被误判为不连续。
2. 在 `compiler/comptime/` 增加受校验的定长整型数组复制，并让结构体字段检查、初始化、复制、下标基址解析和写入沿用此复制语义；AST arena 导入保留既有稳定节点编号，并允许函数切片间有未导入的合法空洞。
3. 单文件输出 `comptime-struct-array-fields=102`，模块项目 `comptimelocal` 运行成功；`make`、`make test`（174/174）、`make selfhost-native`（固定点 14/14、自解析 64、模块 17/17、项目 82/82）全部通过，`git diff --check` 通过。

## 实施决策

- Ruling：typed AST 源切片可非连续，但必须按原始编号存入 comptime arena；`ct_ir_import` 只拒绝重叠切片，并把 arena 长度更新到当前切片终点。这样无需改写所有节点内部索引；代价是 arena 保留切片间空洞，若源 AST 大量夹杂未导入函数会多占一段与前端索引空间相等的内存。

## 成功标准

新增 `.yh` 用例输出 `comptime-struct-array-fields=102`；原数组修改不影响结构体字段，复制后的字段修改不影响原结构体；完整编译/自举门全绿。种子只按仓库策略在所有主门通过后滚动。

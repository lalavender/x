# yh 混合参数调用修复方案

- 日期：2026-10-02。
- 状态：已实施，新增回归、Linux/AArch64 探针及本机主门全部通过。
- 来源：用户要求先修复 libc 分析中复现的十个交错标量参数调用错误。

## 根因与范围

`compiler/gen/sem_call_literal.yh` 按总实参数量计算超过八个的栈实参，
但 AArch64 的整数/指针与浮点参数分别使用 x0–x7 和 v0–v7。
五个整数加五个浮点参数应全部进寄存器，现有逻辑却先弹出末尾两个
实参，随后混合路径再次弹出十个实参。整数寄存器耗尽后，栈参数也
不一定是源码实参的连续后缀。

本次修复固定参数调用分类及搬运，覆盖普通 yh、C ABI 与函数指针调用。
沿用现有纯整数、Darwin 裸变参和类型化变参约定；不修改语法，不扩展
浮点参数溢出、C 裸变参或聚合 C ABI 的支持范围。

## 步骤与验收

1. 新增正式 `.yh` 运行用例与 C 混编双向用例。用非交换的加权结果
   检查十个交错参数、整数溢出后仍有浮点参数、间接调用与嵌套调用。
   验证：修复前旧编译器成功编译，但回归以错误返回码失败。
2. 调用点分别统计整数和浮点参数。混合路径每个实参只弹出一次，
   按类别分配寄存器，整数溢出槽按整数参数顺序暂存并回填。
   验证：新编译器通过新增回归；原 Linux/AArch64 探针从 41 变为 0。
3. 运行 `make`、`make test`、`make selfhost-native`，检查两代固定点、
   全量语料和模块项目验收。完成后更新 todo、finish 与 libc 阻塞状态。
   本次不滚入库种子。

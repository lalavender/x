# yh 语法与编译器自举统一方案

> **历史文档**：B0–B8 已全部完成、G3 已达成。文中「后续自举工作以本文为准」已被
> 0.0.3 的滚动自举取代，现行决定见 [ADR-0007](../adr/0007-yh编译器使用源码模块.md)，
> 现行门为 `make selfhost-native`。
> 2026-09-28 按已完成的 B0–B2 和当前代码重新制定。本文统一记录能力边界、技术路线、任务和验收；后续自举工作以本文为准。

## 1. 目标与当前基线

目标是在 **AArch64 Linux ELF** 上完成三代编译器闭环：现有 C 版 `yh`（stage0）编译 `.yh` 写的新编译器得到 stage1；stage1 编译同一份源码得到 stage2；stage2 再编译得到 stage3。stage1/stage2 必须实现当前语言的全部已定案语法和语义，通过同一批语法、拒绝及运行测试。外部汇编器/链接器可用；stage1 之后不得调用旧 `yh`、`libtcc` 或 C 编译器来解析或生成 `.yh` 程序。

本轮核对的基线（提交 `b5b57d9`）：工作树干净；`make` 成功；`make test` 的 ANTLR 与 C 版语法检查各通过 66 正例、29 反例，Darwin 运行层 44/44；AArch64 Linux ELF 容器运行层 44/44。`read`、`close`、`main(argc int, argv **char)`、编译器工作负载与容量探针已经落地。仓库尚无 `src/yh/*.yh` 编译器源码，也没有 `make bootstrap`。因此种子已可用，但尚未发生任何一代自编。

本文把目标分三级，不能互相替代：

| 门 | 必须观察到的结果 | 允许的称谓 |
| --- | --- | --- |
| G1 | stage0 编出的 `.yh` 解析器按 `docs/yh.g4` 解析自身源码、消费到 EOF，并正确判断全部 95 个语法正反例 | 语法自举 |
| G2 | stage1 编译自身得到可运行 stage2，stage2 再编译得到 stage3；先覆盖编译器自身使用的语言子集 | 自编闭环，不称完整 yh 编译器 |
| G3 | stage1、stage2 对当前全部语法和运行语料同样通过；两代对固定输入发出逐字节相同的汇编 | 完整编译器自举 |

G1 只证明解析能力，G2 只证明编译器自身使用的语言子集闭环；均不能替代 G3。**工具链完全自给**另立目标，指构建时连宿主 C 编译器、外部汇编器、链接器和 C 运行时也不再需要；本方案不以此为验收条件。Darwin arm64 和其他目标架构也不在首轮验收范围内。

## 2. 路线选择与语言边界

推荐 **用 yh 新写编译器，发出确定性的 AArch64 Linux 汇编**。现有 C 版只作为 stage0 种子和差分参照。汇编器负责指令编码和重定位，链接器负责 CRT/libc；它们不解析 yh。直接移植约 2.4 万行 TCC C 代码会把宏、C 内部状态和兼容层一并带入，首次闭环规模过大；通过 `libtcc` 做 yh 前端则不能证明新编译器独立完成编译。输出 C 再调用 C 编译器可以做实验，但不计入 G2/G3。

**目前没有必加的新语法。** 现有函数、显式类型、指针、结构体/联合体、数组/切片、函数类型、递归、控制流、位运算、`sizeof(T)` 和 libc prelude 足以表达编译器；`read`、`close`、带 `argc/argv` 的 `main` 已实现。第一版不增加 `import`、`extern fn`、宏、泛型、动态数组字面量、`sizeof(expr)` 或内联汇编。源码分成多个职责单一的 `.yh` 文件，在构建时按显式顺序拼接为 `tmp/bootstrap/compiler.yh`；每个源文件尽量保持 500–1000 行。拼接只连接完整顶层声明，保留换行，不做条件替换。类型声明在使用前出现，函数可前向调用；所有代次都编译同一份拼接产物。若实际实现证明某个语言能力是硬阻塞，先提交最小 `.yh` 复现，再在 `docs/03-design/` 定案语义、实现与测试；不能仅因写法不方便而扩语法。

输入/输出契约：`fn main() int` 与 `fn main(argc int, argv **char) int` 都有效。新编译器用 `open/read/close` 读取完整源文件，`read` 返回实际字节数、EOF 时返回 0、错误时返回负数；必须处理短读、NUL 字节和容量增长。输出由 `write` 循环处理短写，标准输出只放汇编，诊断写文件描述符 2 并以非零码退出。首轮只承诺 Linux 的 POSIX 文件描述符行为。运行时函数由 prelude 登记，源码不能自行声明无函数体原型。

## 3. 新编译器结构

计划在 `src/yh/` 建立以下边界，具体文件可按实际行数再拆：

| 文件 | 唯一职责 | 对外结果 |
| --- | --- | --- |
| `model.yh` | Token、TypeId、SymbolId、位置和编译上下文的数据表示 | 后续文件共用的类型 |
| `buffer.yh` | 从 `open/read` 读取完整源文件；可增长的输出缓冲；短读/短写处理 | 字节序列与写出函数 |
| `lexer.yh` | 把源字节一次性变为 token 表；token 引用原缓冲的起点/长度 | token 表、词法诊断 |
| `parse_type.yh`、`parse_expr.yh`、`parse_stmt.yh`、`parse_decl.yh` | 共用一套递归下降产生式，支持纯语法与编译模式 | 消费到 EOF、类型化表达式 |
| `symbols.yh` | 类型表、顶层签名、块作用域与名字查找 | 类型和符号编号 |
| `emit_arm64.yh`、`emit_data.yh` | AArch64 指令、栈帧、ABI、全局数据与符号发射 | Linux 汇编文本 |
| `driver.yh` | `--syntax-check`、`--emit-asm`、退出码和诊断 | `main(argc, argv)` |

内部采用 **token 表 + 两遍顶层处理 + 函数体边解析边发码**，不复制 TCC 的预处理器或值栈。Token 保存 kind/start/len/line/column，避免为每个词复制字符串；类型和符号用整数编号引用可增长表，降低互相递归的结构体声明需求。第一遍登记顶层类型和函数签名；第二遍检查函数体并发汇编，遵守现有 `pub`、`const`、块作用域和类型先声明规则，并支持互递归。表达式返回类型和“可写地址/值”的描述，短路与三元式用汇编标签，局部变量和临时值使用明确的栈槽。所有汇编先写到缓冲区，编译成功后才写标准输出；错误不会留下看似成功的部分汇编。

编译器自身源码在 G2 前遵守一个明确的**自编子集**：整数/字节/指针、结构体字段、堆缓冲、全局/局部变量、普通函数、递归、`if` 与条件 `for`、赋值、位运算、`open/read/write/malloc/free/memcpy/strlen/exit`。各函数尽量用上下文指针传状态，避免结构体按值返回与大量实参。浮点、联合体、数组按值、类型化变参、`for-in`、goto、复杂聚合 ABI 可在 G2 后实现，但 G3 必须覆盖；编译器自身不使用它们不等于语言可以不支持。

输出接口固定为 `--syntax-check file.yh` 和 `--emit-asm file.yh`；后者把 GNU AArch64 Linux 汇编写到标准输出。`make bootstrap` 负责用固定目标工具链汇编/链接，并把全部生成物放在 `tmp/bootstrap/`。`-o` 与直接 ELF 写入不是 G3 前置要求；若要替换现有命令行编译器，再单独做兼容性验收。

## 4. 执行阶段与验证门

### B0–B2：已完成的种子准备

现有工作已验证输入接口、命令行参数、递归、函数指针、结构体/数组/切片 ABI、浮点与容量边界。`docs/02-plan/yh-运行覆盖缺口矩阵.md` 记录 G01–G17 的用例。除非后续自举代码触发新的具体缺陷，不重做 B0–B2，也不顺手扩展 C 版功能。

### B3：构建壳与字节词法器

- [x] 在 Makefile 显式列出 `SELFHOST_SOURCES`，按类型声明依赖顺序拼接为 `tmp/bootstrap/compiler.yh`；源文件只用 `.yh`，中间文件只放 `tmp/`。**验证**：两次拼接 SHA-256 相同；stage0 能编译当前最小 `driver.yh`，Linux 上可运行。
- [x] 实现读源文件与诊断、可增长缓冲、token 表。**验证**：`tests/yh/11-lex/` 逐文件正反例、NUL、长标识符、1 MiB 输入；非法输入非零退出且包含位置，不崩溃。
- [x] 实现数字、字符串/字符转义、注释、保留字和运算符的完整词法。**验证**：新词法器的 token/错误位置与固定探针期望一致，并能把自己的拼接源码扫描到 EOF。

### B4：纯语法解析与 G1

- [x] 先实现 `typeRef`、顶层声明、块与简单语句，再实现完整表达式优先级和 `if/for/switch`。同一 parser 在 `--syntax-check` 模式不解析符号、不发码。**验证**：每组新增 `.yh` 用例；不允许为了让解析器过关而缩小 `docs/yh.g4`。
- [x] 用 `tests/yh/check.py --compiler --compiler-path <容器包装器>` 跑全部 66 正例/29 反例；包装器只把路径映射到挂载的仓库并在 Linux 容器内执行 stage1，不解析或修改源码。新增自解析用例：新解析器读取 `tmp/bootstrap/compiler.yh` 并消费到 EOF。**验证**：语法合法但名字未定义的正例仍被接受；末尾垃圾、缺括号和非法转义被拒绝。达到 **G1**。

### B5：语义检查与最小 AArch64 后端

- [x] 实现顶层签名、类型布局、局部作用域、隐式/显式转换及编译模式诊断。**验证**：`tests/yh-run/fail/` 的未定义名、重定义、类型不匹配等先逐项通过；语法模式结果不变。
- [x] 按“整数与指针 → 控制流 → 调用约定 → 内存与全局数据 → 编译器源码所用结构体”的顺序实现汇编发射。每类先写小型 `.yh` 运行例，再接入发码。**验证**：输出 `.s` 经目标汇编器/链接器得到 AArch64 Linux ELF，在容器运行，输出和退出码与 stage0 一致。
- [x] 在 Linux 容器内给现有运行测试提供一个薄包装：接收原有测试命令，调用新编译器 `--emit-asm`，再汇编/链接；包装不能读取或改写 yh 语法。**验证**：至少基础运算、递归、指针、输入缓冲及编译器源码使用的结构体用例经 stage1 通过。

### B6：自身子集闭环与 G2

## 5. 贯穿规则与风险控制

G3 的语言验收按下表逐行关闭。每一行同时核对语法接受、非法输入拒绝和实际运行结果；纯语法形态以明确的编译拒绝代替运行。已有 `tests/yh/`、`tests/yh-run/` 和语义设计是基线，缺口补 `.yh` 用例。

| 语言部分 | 必须核对的边界 |
| --- | --- |
| 词法与顶层 | 数字基数、转义、注释、保留字、显式分号、`pub`、多个声明、EOF |
| 声明与作用域 | `let`、`const`、`type`、函数、结构体、联合体、枚举、前向调用、互递归、重定义和未定义名 |
| 类型与调用 | 标量、指针、函数指针、数组按值、切片、聚合布局、类型化及 C 变参、超过寄存器数的参数 |
| 表达式 | 优先级、短路、三元式、赋值、成员/下标、structInit、转换、`sizeof` 和 `len` |
| 控制流 | `if`、各类 `for`、`switch`、`break/continue`、label/goto、return |
| 目标程序 | 全局数据、字符串、整型与浮点返回、进程退出码、外部符号和 ELF 运行结果 |

诊断也属于验收：非法源文件必须非零退出，给出文件位置和错误类别，不崩溃、不无限递归、不在标准输出留下可被当作成功产物的汇编。

- 每次改编译器代码都在 `tests/` 加 `.yh` 用例，执行 `make` 和相关测试；阶段门前跑全量 `make test` 与 Linux 交叉运行。结构体、函数须有中文详细注释；只修改当前阶段需要的文件。
- 新 `.yh` 编译器的每个源文件尽量维持 500–1000 行；大压力语料可由测试生成，但生成物写 `tmp/`。保留当前 512 包装类型和 switch 分支上限的明确报错，只有真实自编负载命中时才扩容。
- 风险最高的是 AArch64 调用约定：超过 8 个参数、浮点寄存器、16 字节以内聚合值、大结构体隐藏返回指针、切片和类型化变参。B5 不假装已覆盖；B7 每项用真实 Linux ELF 程序验证。
- 语法通过不代表类型或代码生成正确；自编成功也不代表支持完整语言。G1/G2/G3 分别报告，任何阶段失败都停在该门修复，不越级宣布完成。
- 首轮保持单目标、单编译单元，不并行推进多平台/模块系统。若拼接源文件的类型声明顺序成为实际阻碍，先用最小复现证明，再决定是否加入前向类型声明；不要提前设计完整 `import`。

## 6. 交付清单

交付时应包含 `src/yh/` 的新编译器、明确的源码拼接清单、Linux 汇编输出、`make bootstrap`、三代产物与日志、更新后的 `.yh` 语法及运行测试、README 和 `docs/finish.md` 的实际验证命令。本文的勾选项只有在对应验证门通过后才能标记完成。

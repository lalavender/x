# yh LLVM LL5 全量收尾实施方案

日期：2026-10-16  
范围：完成 `yh-LLVM后端替换实施方案.md` 的 LL5「内存、聚合与模块数据」验收项。

状态：**2026-10-17 全部成功标准通过。** 实际代码、测试与结果见
[LL5 全量完成记录](../01-finished/yh-LLVM-LL5全量收尾-2026-10-17.md)。

## 成功标准

- 前端将普通全局、字符串、零初始化、切片 backing、CT 临时/全局对象和指针初始化收集为有类型且独立拥有的数据记录；CheckedModule 深拷贝记录后不再依赖 GenState、AST 或 CT arena。
- LLVM 模块数据接受完整字节和静态指针重定位；重定位目标、偏移、宽度、加数、对象大小与对齐由 IR verifier 核对，非法记录不得发射。
- 模块 lowering 能寻址本模块全局，并以消费方独立副本的既有语义物化导入 `pub const` 聚合；私有名称和内部对象不会变成导出符号。
- 全局切片的长度和 backing 指针正确；CT 产生的聚合/切片在其临时值池释放之后仍可捕获、序列化、反序列化、发射并运行。
- 聚合赋值的重叠复制有明确安全语义并通过同址、前向、反向重叠测试；显式运行时 `memcpy` 的既有不重叠契约不被混淆。
- 每项语义至少有 `.yh` 回归用例；O0/O2 对照旧后端运行。真实多模块测试需通过 `iface_emit`/`iface_load`、分别捕获/lower、序列化文件读回、分模块 LLVM 对象和链接运行，验证导入常量副本及私有隔离。
- 刷新 LL5 设计/实施/完成记录和 `docs/todo.md`；只保留真实尚未实现的后续阶段事项。

## 实施步骤与验证

1. [x] 增加独立拥有的静态数据/重定位目录和 CT 数据图导出；序列化期间借用视图关系还原 owner 与目标字节偏移，持久数据不含 CtAggregate 指针。
2. [x] 在全局字面量、字符串、指针、切片与导入聚合重放路径登记字节及重定位，按现有 `.s.i/.s.ct` 语义建立消费者本地副本。
3. [x] CheckedModule capture/release/verify 深拷贝静态对象，并在纯 lowering 中物化全局/字符串/导入对象、GLOB_ADDR、slice header 和重定位。
4. [x] IR verifier 与 LLVM emitter 校验/发射静态字节及 addend 重定位；聚合复制发射允许重叠的 memmove。
5. [x] 加入 O0/O2、旧后端 `.yh` 回归、真实多模块 `.s.i/.s.ct` 发射/读回和分模块对象链接门；`llvm-ir.py --suite memory` 汇总全部 LL5 专项。
6. [x] WSL Linux 优先门全部通过；检查了数据布局、链接可见性、CT 临时值池生命周期、接口副本和私有隔离。未运行 `make seed`。

## 边界与记录

- 不新增语言语法。当前语言明确不支持的全局 union 初值、CT 任意指针返回/字段、浮点全局字段，以及现有地址越界限制须通过负例锁定并记录。
- 生产 CLI 全模块 LLVM 构建、最终链接键和 LLVM 专属热缓存命名空间属于 LL9；LL5 的多模块闭环由真实测试前端执行，但不得据此宣称 LL9 已完成。
- 默认后端、入库种子和 ABI 不因 LLVM 探索切片变更；不运行 `make seed`。

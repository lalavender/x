# yh io 标准库实施方案

> 本文件保留 IO0–IO6 的分期与验收契约；IO0–IO4 已于 2026-10-24 实施完成。

**目标：** 在 `libs/io` 交付字节流的完整读写层：整段读写（`read_all`/
`read_file`/`write_bytes`/`write_file`）、调用方缓冲的 `Reader`/`Writer`
（含按行读取与显式 flush），保留 `write_all_result`/`write_all`/`print`/
`println` 的原签名与返回值。

**架构：** `io` 只依赖 `os`，在 `os` 的单次原语之上做循环、缓冲、进度与行语义；
缓冲由调用方提供（与 `os.open_dir`/`os.get_cwd` 同风格），因此零分配、无隐藏
所有权、无 OOM 分支。fd 所有权始终属于调用方。

**技术：** 现有 yh/LLVM 编译器与种子、`os` 的 `read_some`/`write_some`/
`open_path`/`close_file`/`IoResult`/`Error`、语言内 `test` 块
（`libs/io/tests.test.yh`）。

日期：2026-10-24。状态：**IO0–IO4 已完成**，本平台 `make test` 通过；
IO5–IO6 未开始。API 与取舍见[设计](../03-design/yh-io标准库设计-2026-10-24.md)。

**实施结果（2026-10-24）：** 实际文件为 `libs/io/base.yh`（类型与构造辅助）、
`read.yh`（读取）、`write.yh`（写入，含从 `io.yh` 迁入的
`write_all_result`/`write_all`）、`io.yh`（`print`/`println`）、
`tests.test.yh`、`doc.yh`、`README.md`。门禁新增 `yh test io`，接入
`make test`、`make selfhost-native` 与 `make test-lib-tests`。
`libs/io/tests.test.yh` 的 7 个用例全部通过；既有 `libsio`/`osio`/`syseintr`
验收未改动。未滚种子、未推送、未触发发布。

## 1. 执行顺序与验证入口

顺序为 `IO0 → IO1 → IO2 → IO3 → IO4 → IO5 → IO6`。IO1 先立类型，IO2/IO3 各自
可独立验收，IO4 才接入门禁；IO5 用真实消费者（toml 读文件）验证 API 是否够用，
IO6 依赖 `os` 先补 `lseek`/`fstat`。

每个切片：写断言 → 确认失败原因 → 最小实现 → 定向用例通过 → `make` →
`cd libs && ../yh test io` → 更新文档。最终执行本平台 `make test` 与
`make selfhost-native`。

## 2. IO0：基线盘点与语言探针（已完成）

**阅读：** `libs/io/io.yh`、`libs/os/{base,file,os}.yh`、`libs/sys/file.*.yh`、
`libs/toml/file.{linux,darwin}.yh`、`libs/string/base.yh`、
`tests/modules/projects/{libsio,osio,syseintr}`。

1. 统计 `io.*` 的既有调用点，确认只有写侧（`print`/`println`/`write_all`），
   因此本设计不改变它们的签名。
2. 确认读取侧缺口：`toml/file.*.yh` 各手写约 100 行短读循环。
3. 语言探针（`tmp/io-probe`）：`[]u8` 结构体字段、切片形参、`&slice[i]`、
   `memcpy`、`os.Error` 字段、结构体字面量、`bool` 字段全部可用。
4. 确认 `os` 没有 `lseek`/`fstat`，因此首版不做 seek/peek 公共接口。

**关闭条件：** 调用点清单与探针结果可复现；API 形状不受语言能力阻断。

## 3. IO1：模型（已完成）

**新增：** `libs/io/base.yh`。

- `Status`（`status_ok`/`status_eof`/`status_truncated`/`status_invalid_argument`/
  `status_io_error`）、`ReadResult`、`ByteResult`、`Reader`、`Writer`、
  `IO_BUFFER_SIZE = 8192`。
- 私有构造辅助 `read_ok`/`read_eof`/`read_truncated`/`read_failed`/
  `byte_ok`/`byte_eof`/`byte_failed` 不进入导出面。
- 复用 `os.Error`/`os.IoResult`，不新建错误类型。

**验收：** `libs` 项目可编译；`io` 的 `.s.i` 只导出上述公开声明。

## 4. IO2：读取（已完成）

**新增：** `libs/io/read.yh`。

- `read_all`：循环 `os.read_some` 到 EOF 或输出满；EOF → `status_ok`，
  输出恰好填满 → `status_truncated`（不猜测 EOF）。
- `read_file`：`open_path(read_options)` → `read_all` → `close_file`；
  读取结果优先，读取成功时才用关闭错误覆盖。
- `reader_init`/`reader_read`/`reader_read_byte`/`reader_read_line`/
  `reader_buffered`：缓冲借用调用方存储，`reader_fill` 统一预读并把错误粘滞
  到 `reader.error`。
- 行语义：只认 `\n`，`\r` 保留，换行包含在结果里；超长行填满输出后
  `reader_discard_line` 丢弃该行剩余字节，保证每次调用恰好消费一行。

**验收：** 分行/空行/末行无换行/超长截断/EOF/单字节读取用例通过；
空缓冲 `init` 返回 `error_invalid_argument`。

## 5. IO3：写入（已完成）

**新增：** `libs/io/write.yh`；`write_all_result`/`write_all` 从 `io.yh`
**原样迁入**（签名、注释、返回值不变），`io.yh` 只留 `print`/`println`。

- `write_bytes`：循环 `os.write_some`，返回已写进度；零进度报 `error_other`
  防空转。
- `write_file`：`write_options()` + `truncate = true` → `write_bytes` →
  `close_file`；写入错误优先。
- `writer_init`/`writer_write`/`writer_write_byte`/`writer_flush`/
  `writer_pending`：缓冲满自动 flush；flush 失败把未写出字节前移保留并粘滞
  错误；`error_interrupted` 允许显式再次 flush 重试剩余字节。

**验收：** 小写入不落盘、`writer_pending` 计数、跨缓冲大写入、flush 后文件
内容正确；坏 fd 报错且 `count == 0`。

**验收：** `cd libs && ../yh test io --timeout 60` 7/7 通过；

## 7. IO5：迁移 toml 读文件（规划）

**修改：** `libs/toml/file.linux.yh`、`libs/toml/file.darwin.yh`
删除手写短读循环，改用 `io.read_file`（仍需保留 `TOML_MAX_INPUT` 上限语义与
`parse_io_error`/`parse_resource_error` 的分类映射）。

**风险：** 现有实现用"恰好读满上限时单字节探测 EOF"区分超限与刚好读满；
`read_all` 的 `status_truncated` 语义正好对应"未确认 EOF"，但需要给缓冲多留
1 字节才能区分"恰好读完"与"还有数据"。迁移前先在 toml 侧加断言锁定现状。

**验收：** `make test-toml`、`make test-toml-conformance` 全绿；toml 读文件
不再出现 `os.read_fd`/`os.read_some` 循环。

## 8. IO6：seek 与 copy（规划，依赖 os）

前提：`os` 补 `lseek`/`fstat`（当前 `sys` 无对应原语）。届时评估：

- `Reader` 的 `peek`/`seek`/`unread`（无 seek 时只能靠内存回退，首版明确不做）；
- `io.copy(dst_fd, src_fd, buffer []u8) os.IoResult`（零分配拷贝，替代
  `examples/os-demo` 的手写循环）；
- 是否需要 `writev`/`readv` 的批量封装。

**验收：** 先出设计增量，再实施；不在 IO6 之前对外承诺这些 API。

## 9. 风险与边界

- `read_all` 的 `status_truncated` 不区分"恰好读满"与"还有数据"：调用方需要
  精确判断时多留 1 字节。这是零分配设计的取舍，写入文档与 README。
- `Reader`/`Writer` 是浅拷贝的状态对象：复制句柄会共享缓冲与游标，属于调用
  契约而非语言可检测错误（与 `string.String` 的句柄语义一致）。
- 不自动重试 EINTR 会把这些错误暴露给调用方；toml 迁移（IO5）时必须显式处理，
  不能静默降级。
- `writer_flush` 失败后保留未写出字节，但错误粘滞期间 `writer_write` 不可用；
  调用方须先处理 `interrupted` 或放弃该 Writer。

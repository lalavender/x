# yh Go 风格模块化实施方案

> 执行清单已被 [mod.toml 模块实施方案](yh-模块与项目管理实施方案.md) 替代。
> 旧 PKG-U0–U8 未实施，不继续执行旧清单、路径导入或 internal 任务。

日期：2026-09-29。状态：计划，尚未实施。

语言与工具行为以 [模块与包设计](../03-design/yh-Go风格模块与包设计.md)
为准；架构取舍见 [ADR-0004](../adr/0004-yh-Go风格模块与包.md)。
此处实现的是用户代码的 package/import/module 能力。

## 1. 成功标准

首个可用版本必须能构建一个入口包、一个多文件库包、一个本地依赖模块，
正确处理 pub、文件级导入、跨包类型身份、循环依赖和包限定链接符号。
旧单文件用例继续通过。只改语法、只通过 syntax-check、或把文件裸拼接
成功，都不满足成功标准。

发布阶段号 U0–U8 是实施顺序，不是日历工期。实际需要修改的 C／yh
文件按既有职责就地扩展或合理拆分，不要求先执行旧内部重构方案。

## 2. 阶段顺序与验证门

| 阶段 | 具体任务 | 交付与验证门 |
| --- | --- | --- |
| U0：可靠基线 | 复核正在修复的调用 ABI；冻结单文件行为、数组／切片与 prelude 规则；确认 package 模式版本 | make/test；参数位置和副作用测试；适用的 bootstrap/G3，SKIP 不算通过 |
| U1：语法与文件身份 | 新增 package/import、别名／分组、限定类型、pub 字段；文件头扫描；FileID 和每文件 import 表 | 两套 parser 与 ANTLR 正反例；语法检查不读取依赖、不因缺包失败 |
| U2：同包多文件 | 目录收集；统一顶层登记；跨文件签名／类型／常量；库包不要求 main；重复声明 | 两文件前向调用、类型与常量依赖；排序变化结果不变；正确原文件诊断 |
| U3：当前模块跨包 | 最小 yh.mod、路径映射、包 DAG、限定值／类型、pub 检查、internal、唯一类型身份 | 主模块内库调用与公开类型运行；私有／循环／别名泄漏／main 导入拒绝 |
| U4：本地外部模块与独立产物 | require/replace；逐包 .o；接口表与 .yhi；符号限定；跨包 ABI；入口包装 | 两模块真实链接；同名符号不冲突；聚合／浮点／变参／函数指针；不兼容产物拒绝 |
| U5：缓存与完整自举构建 | 内容缓存键、接口版本检查、原子发布；自举文件发现和宿主工具链；自身包化试点 | 冷／热构建行为一致；源码／接口／target 改动正确失效；自举 CLI 真实 build/run；三代验证 |
| U6：远程版本 | SemVer、完整 MVS 图、源获取、yh.sum、download/get/tidy | 多来源最低版本选择；v2 路径；离线缓存；摘要不符／缺失／损坏拒绝 |
| U7：工作区 | yh.work/use、多个根模块、解析优先级与冲突诊断 | 两模块共同开发无需改 import；相同模块双源拒绝；离开工作区按清单恢复 |
| U8：后续包生命周期 | 按需求加入 init/空白导入、测试发现、平台文件筛选 | 各项单独设计与测试；初始化顺序／次数；文件集合影响缓存 |

第一里程碑是 U1–U4 的完整本地包与模块链；U0 是必须前置的基线确认。
U5 之后才能宣布自举编译器的项目构建入口完全接通。远程包与工作区
需要独立验证，不能因 yh.mod 有版本文本就勾选完成。

## 3. 核心实现顺序

### U1：语法不能冒充构建

更新 `docs/yh.g4` 的包／旧模式入口和限定类型；同步 `tcctok.h/tccpp.c`
与 `compiler/model.yh/lexer.yh`。检查 `is_member_name` 等编号区间假设，
新增 keyword 时不使已有字段／成员规则失效。

把文件头扫描与业务语义分开：纯语法模式接受形态正确的未知包导入，
目录构建才确认存在、名称一致和可见性。新测试数量由实际发现计算，
不得沿用 G3 硬编码的 66/29。

### U2–U3：先身份，再查询

先引入 PackageID/FileID、声明引用和每文件 import 绑定，再扩展符号
查找。所有文件登记后才能解析函数体；具名类型先占位再计算布局。
别名不是全局 Sym，也不是可生成运行值的表达式。

调整 `yh_compile` 与自举 `sem_compile` 的会话：一个包处理多个文件，
依赖包以接口提供名字和类型，不通过复制私有源码到主包解决跨包调用。
包图先检查循环和 internal，再按拓扑顺序编译。

### U4：接口与调用必须一起验证

导出接口记录稳定类型身份及所需闭包；公开名字表仅记录允许访问的名字。
pub const 的值、pub type 的别名身份不依赖生成机器符号。
同包生成一个对象，避免同包私有函数跨对象不可见的问题。

依赖包产物与调用者使用同一生成器／ABI／target；把当前 C 和自举的
聚合表示差异纳入元数据校验。最终入口包装唯一，普通包里的同名符号
使用限定编码，不能让任何源函数仅凭名字 main 获得平台入口待遇。

### U5：自举能力要按真实入口验收

当前 prelude 没有目录枚举等项目加载设施。开始可用宿主驱动准备包输入，
之后补最小宿主适配，让自举 build 真正完成 yh.mod 读取、文件发现、
包图、接口、对象和最终链接。不能长期要求用户手工拼接源码。

先迁一个低依赖编译器包作为试点；三代使用同一项目定义和文件选择。
每个包发射与最终程序都要确定，但带不同编译器家族的对象不要求一致。

### U6：依赖求解与源获取分开

先用本地模拟模块图测 MVS，再接具体远程来源。实现图中的每个可达
版本节点加载；缓存、摘要和版本路径都验证后再开放下载命令。
发布的首个远程实现须写明支持的托管路径／仓库根规则，不假定任意
example.com 路径都可自动映射成一个 Git 仓库。

## 4. 测试目录与用例

新增 `tests/modules/` fixture runner，目录就是项目，不把多文件用例
塞进现有单文件 runner 后假装 import 已被执行。测试说明／期望保存在
fixture 的小型元数据中，源程序仍全部使用 `.yh`；构建产物进 tmp/。

```text
tests/modules/
  check.py
  pass/
    same-package-files/
    local-module-replace/
    exported-types/
    shared-package-state/
    cross-package-abi/
  fail/
    mixed-package-names/
    duplicate-declaration/
    import-file-scope/
    private-access/
    import-cycle/
    internal-boundary/
    incompatible-interface/
  resolver/
    version-graph/
    workspace/
```

上面目录尚未创建，每项属于未来代码任务。每次代码修改新增 `.yh`
回归源文件并执行 `make`；模块 runner 接入 `make test` 后按语言／构建／
依赖解析分组报告，不用一次总退出码掩盖未运行项目。

| 类别 | 必须断言 |
| --- | --- |
| 同包 | 跨文件私有函数／变量可见、前向类型、互递归、重复名字诊断双位置 |
| 文件导入 | 当前文件导入有效，其他文件不可借用；别名默认取 package 声明；未使用导入 |
| 包身份 | 两包同名函数／类型不冲突；同一包经两个导入链只编译／拥有一份全局存储 |
| pub | 私有值／类型／字段拒绝；公开类型、常量、可变全局可用；私有类型闭包不泄漏名字 |
| 字面量 | 限定类型正确解析；私有字段外部访问／位置式初始化拒绝；遗漏字段正确零值 |
| 图和路径 | 直接／间接／自循环；完整链诊断；relative/file import、nested module、internal 边界 |
| ABI | 位权参数位置、浮点混合、数组按值、结构体返回、切片、类型化变参、间接调用 |
| 产物 | 公开类型无 .globl 也可导入；限定符号；接口损坏／target／ABI／生成器不匹配拒绝 |
| 缓存 | 冷热一致；只改 mtime 不改内容；改源码、replace、编译器、选项、依赖接口正确失效 |
| 版本 | A 要求 v1.2、B 要求 v1.4 选择 v1.4；模块图环与包环区分；v1/v2 共存 |
| 下载／工作区 | 离线缓存、同版本内容变化拒绝、冲突映射、多个本地根不改源 import |
| 兼容 | 当前单文件语法／运行语料、自举拼接链仍通过；新增 package 文件不会被旧入口遗漏编译 |

syntax-check 通过、库包编译通过、链接通过、程序运行通过分别计数；
信号崩溃、超时、正常拒绝也分别计数。Linux／Darwin／WSL 的验证要
记录具体 target，无法运行的目标不得计为运行通过。

## 5. 提交与回退

每个阶段按 grammar、文件／包身份、符号查询、接口、ABI、构建工具分别
提交；先恢复可靠基线再迁移。版本格式与 ABI 变化会使缓存失效，要有
明确的格式版本，不能继续读旧 .yhi。

完成一项更新 `docs/todo.md`；实际命令、结果和局限写 `docs/finish.md`
与 `docs/01-finished/`。新结构体／函数用中文说明生命周期、字段意义与
失败行为；文件通常控制在 500–1,000 行附近，职责较短时不凑行数。

本次是方案文档，没有实施 U0–U8，也没有生成或运行模块 fixture。

# yh 编译期数组长度函数求值实施方案

日期：2026-10-06。状态：**早期常量探测的分支、只读局部值和 typed 布局请求首个竖切已交付**。

## 目标

让类型数组长度的常量表达式可以显式调用 `@[comptime]` 整数函数，复用 `$f(...)` 的签名、常量边界和错误传播规则。首片复用已有的直接调用数组长度路径，并提前折叠函数体为单个受限 return 表达式的整型 CT 全局常量，供后续全局类型布局使用；复杂 CT 函数常量仍待 typed AST 请求阶段。

## 边界与验收

1. `run/91` 固定直接 CT 整数函数用于结构体字段、全局和局部数组长度的现有能力；`run/92` 验收简单参数化 CT 函数初始化全局整数 const 后供全局布局使用。
2. 初始切片以 `fail/108` 确认复杂 CT 函数常量不会被 token 兼容解释器误执行；该用例
   已在后续 typed 布局请求阶段升级为 run/108，改由 typed IR 正确执行分支局部值。
3. 保持数组长度必须为正数且不超过 i32；前向依赖、循环依赖、复杂 typed 函数及其他全局 const 不因本片伪造 READY 状态。

## 首片结果

- pass1 仅在整型全局 `const` 初始化器以 `$` 开始、目标已登记且其函数体是兼容解释器可安全处理的单 return 算术表达式时预求值；成功后标记该 const READY，后续数组布局可读。
- 首片目标函数表达式限制为参数、整数/bool 字面量、括号和 `+ - * / %`；复杂正文、全局值引用及嵌套 CT 调用当时不会进入早期探测，继续走原声明次序与 CT5A 阶段限制。
- `make test`：语法 71/71 + 44/44；运行 91/91、拒绝 91/91、通过 8/8，共 190/190。`make selfhost-native`：固定点 14/14、自解析 64 文件、模块 17/17、项目 82/82 与全部探针通过。

## 后续切片：全局常量的嵌套简单调用

### 目标与边界

扩展 pass1 的安全探测，使全局整数 `const` 可以由一组无环、简单单 `return`
整数 `@[comptime]` 函数嵌套计算，并供其后的全局数组和结构体字段布局使用。
继续复用 `compiler/comptime/` 中已有的 token 求值器；不放宽到局部变量、分支、循环、
非整数结果、未就绪全局常量或跨模块函数正文。此切片不是 CT5A 的最终请求求值器。

探测器沿函数调用图验证所有目标函数均满足同一简单表达式子集；若遇到调用环、
未登记目标或不支持的函数体，则不提前执行，保留既有“编译期常量尚未就绪”诊断。
调用树继续共享原有 64 层调用限制与 100000 步执行预算。

### 验收与文件

1. `tests/yh-run/run/111-comptime-array-length-nested-call.yh`：两层简单 CT 调用初始化
   全局整数 const，该值用于后续全局数组和结构体字段长度。
2. `tests/yh-run/fail/112-comptime-array-length-call-cycle.yh`：互相递归的单 return
   CT 函数不能进入 token 早期探测；后续 typed 布局阶段改为实际执行，并由递归预算拒绝。
3. `compiler/comptime/ct_registry.yh`：对简单函数体做有界、无环的递归调用图验证；
   `compiler/parse/parse_global_init.yh` 保持现有探测与常量赋值边界。
4. `make test` 与 `make selfhost-native` 全绿；滚种子后冷编 `make`；刷新计数、设计文档、
   `docs/todo.md`、`docs/finish.md` 和完成记录。

状态：该切片已完成，详见[完成记录](../01-finished/yh-编译期全局数组长度嵌套调用-2026-10-06.md)。

## 下一阶段：带条件分支的早期常量探测

日期：2026-10-06。状态：已完成，详见[完成记录](../01-finished/yh-编译期数组长度条件分支早期探测-2026-10-06.md)。

### 目标与边界

把 CT5A 的安全早期探测从“单 return 表达式”扩到只含 `if/else` 与
`return` 的标量控制流，使无环整数 `@[comptime]` 函数可按参数选择返回表达式，
并在后续全局数组/结构体字段布局前初始化全局整数 const。求值复用现有 token
解释器，仍要求目标和嵌套目标均通过有界、无环正文验证。

本阶段不允许局部变量、赋值、循环、聚合/非整数值、全局值读取、诊断指令或
跨模块函数正文参与早期探测；非穷尽返回路径不进入探测。未命中安全子集的函数
保留既有未就绪行为。该阶段不替代后续 typed IR 布局请求、依赖环检测，也不放宽
全局 const 的声明次序规则。

2. 扩展 `compiler/comptime/ct_registry.yh` 中早期探测器：递归验证受限语句块、
   整数参数/返回值、表达式 token 子集、嵌套目标及无环调用图；解释执行仍由现有
   `ct_eval_body` 完成。
3. 保持 `fail/112` 的递归拒绝与前向 const 未就绪诊断；`fail/112` 后续改由递归预算
   拒绝，`fail/108` 的复杂正文则由 typed 布局请求阶段执行。
4. 运行 `make test`、`make selfhost-native`，通过后滚种子并冷编；同步设计、待办、
   完成流水和测试目录说明。

## 后续阶段：函数顶部的只读局部整数

日期：2026-10-06。状态：已完成，详见[完成记录](../01-finished/yh-编译期数组长度局部值早期探测-2026-10-06.md)。

### 目标与边界

继续拓展早期探测：允许整数 CT 函数在顶层控制流之前声明带显式整数类型和初始化式的
`let`，后续 `if/else` 条件与 `return` 可读取这些值。求值环境按函数调用独立保存，
局部值按 yh 类型赋值规则检查。只支持简单整数类型，不支持局部数组/结构体、局部 const、
赋值和复合赋值、分支内声明、循环及跨模块目标。

此阶段仍是 `compiler/comptime/` 中受限 token 解释器的早期布局探测能力，不等同于通用
typed IR 请求求值。未满足验证器约束的函数不会由 token 探测器提前执行；之后 typed
布局请求可执行已捕获函数，并按真实路径与递归预算求值。

### 实施与验收

1. 新增 `run/115-comptime-array-length-local-values.yh`，验证多个调用帧中的局部值、
   条件分支、全局数组和结构体字段布局。
2. 初始只读探测阶段新增 `fail/116-comptime-array-length-local-mutation.yh`，确保可变
   局部赋值不会进入 token 子集。后续 typed 布局请求阶段将此用例升级为
   `run/116-comptime-array-length-local-mutation.yh`，由 typed IR 执行赋值。
3. `compiler/comptime/ct_00_model.yh` 为 token 执行帧保存局部值；`ct_eval_expr.yh`
   读取和初始化局部值；`ct_registry.yh` 只接纳顶层已初始化局部声明且检查引用顺序。
4. 运行完整测试和自举主门，通过后滚种子并冷编，刷新设计、待办、完成流水和测试说明。

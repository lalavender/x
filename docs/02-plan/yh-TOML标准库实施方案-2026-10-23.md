# yh TOML 标准库实施方案（待评审）

> 2026-10-23 实施状态：T0–T5 完成并收口（含分配失败/预算门与安装/仓库外
> 导入），T6/T7 未开始。逐项证据见本文第 11 节与 [finish](../finish.md)。

**目标：** 在 `libs/toml/` 交付完整 TOML 1.1 reader，随后单独迁移编译器清单消费者。

**架构：** 普通 yh 模块，Document 独占存储，Value 为只读视图；通用语法和项目 schema
分离。解析核心无全局可变状态，文件读取复用 os，所有权显式释放。

**技术：** 现有 yh、LLVM 后端、普通 `.yh` 项目用例、Python runner、固定 toml-test。

日期：2026-10-23。状态：**T0–T5 reader 已实施并收口；T6/T7 未开始**。
用户已确认完整 1.1 reader 优先、写入后置，见
[设计](../03-design/yh-TOML标准库设计-2026-10-23.md)。本方案不修改 yh 语法、
不等待语言内测试提案、不自动滚种子或触发发布。

## 1. 顺序与阶段关闭原则

`T0 → T1 → T2 → T3 → T4 → T5` 交付 reader；T6 是独立消费者迁移；T7 是后续生成器。
每阶段以可运行用例和证据关闭，不能因为 API 名字已存在就标完成。
实现一个行为的最小循环是：新增 `.yh` 断言 → 运行确认失败原因 → 实现 → 定向运行
通过 → `make` 构建 → 更新对应文档与 finish。合并切片执行本平台完整门。

新增测试统一放 `tests/`。拟建 runner 为 `tests/toml/run.py`，fixture 为
`tests/modules/projects/toml*/`；运行时复制到 `tmp/toml/`，不污染 fixture 的
`.build`。所有命令必须能指定 `--compiler ./yh` 和 `--workdir tmp/toml`。
下列专项命令均是待实施入口，不是当前已有命令。

## 2. T0：契约与风险探针

**新增：** `tests/modules/projects/tomlmodel/{project.toml,main/main.yh}`、
`tests/toml/run.py`、`tests/toml/README.md`。
必要的实验辅助 `.yh` 放 fixture 或 `tmp/toml/probes/`。

1. 用最小项目锁定 `Text`、`Document`、`Value`、具体 Result、枚举名称和跨模块返回。
   检查零长度/空指针约定、NUL 字节视图、稳定节点及 union 的声明顺序。
2. 验证池释放、私有节点间引用、容器扩容后句柄稳定；不依赖裸指针切片构造。
3. 建立纯 yh 十进制→binary64 精确转换原型，先对最小次正规数、半途舍入、最大
   有限值、长尾数配负指数和负零做独立参考差分。不得用 CLI 算法充当验收。
4. 固定 1.1 ABNF、toml-test v2.2.0 与获取/校验方式；整理能力→正例→反例矩阵。
5. 实测预算草案（16 MiB / 128 层 / 128 MiB），列清累计分配和深度计数规则，
   按结果修订设计。若精确浮点或现有语言能力阻塞，应记录具体差距后再定替代。

**验收：** 模型项目可由当前种子和候选构建；关键浮点原型有红绿与参考证据；
设计中的未验证布局/数值假设已解决，不先导出尚不能兑现的 API。

## 3. T1：存储、字符串与最小解析

**新增：** `libs/toml/{toml,storage,parse,strings,query}.yh`，
`tests/modules/projects/tomlstrings/{project.toml,main/main.yh}`。
**修改：** `libs/project.toml` 登记模块。

1. 先写空文档、简单键值、非法 UTF-8 和不同输入生命周期的 `.yh` 用例。
2. 实现私有池、稳定节点、ParseResult、release 和基本查询；失败完整回收，诊断
   不依赖仍然存活的输入。模型错误先由测试暴露。
3. 分小批实现四种字符串、Unicode 标量、转义、NUL、首换行与多行续行。
   每批先添加对应非法边界，不能只测常见英文文本。
4. 实现带引号键和字节长度比较；测试空键、解码后重复键、`\xE9` 输出 UTF-8
   而不是直接当单字节、代理项与截断转义拒绝。
5. 分离不同上下文的空白处理，测试 LF/CRLF、裸 CR、同行额外赋值和 EOF。

**定向验证：** `python3 tests/toml/run.py --compiler ./yh --group strings`。
**关闭条件：** 输入改写后文档值不变，两个文档互不覆盖；释放同一清零句柄安全；
全部字符串正反例与位置断言通过。阶段文档明确仍不是完整 reader。

## 4. T2：数值、布尔与日期时间

**新增：** `libs/toml/{numbers,datetime}.yh`，
`tests/modules/projects/tomlscalars/{project.toml,main/main.yh}`，
`tests/toml/numeric-reference.py`。

1. i64：先测最大/最小值及越界、十六/八/二进制、符号、前导零与下划线位置。
2. 把 T0 验证过的精确浮点转换收进私有实现；测试正常/次正规/下溢、舍入临界、
   `-0.0`、inf/nan、有限值上溢与超长指数。对大量确定种子样本比较独立参考位模式。
3. 实现严格布尔；`true1` 等尾随字符不能被吞掉。
4. 实现四种时间验证与保留文本：有效/无效日期、偏移、分隔符、省略秒、任意小数秒。
   对闰秒等 RFC 3339 边界先固定规范依据和上游用例，不能默默借用宿主日期库规则。
5. 实现各标量查询，断言类型不符时不修改 out 参数。

**定向验证：** `python3 tests/toml/run.py --compiler ./yh --group scalars`；
`python3 tests/toml/numeric-reference.py --compiler ./yh --workdir tmp/toml/numbers`。
**关闭条件：** 类型和值正确，数值参考差分全绿；没有 locale 依赖或未经披露的新 C
转换依赖；四种时间仍是独立 ValueKind，不丢小数文本。

## 5. T3：数组、点键与完整表语义

**新增：** `libs/toml/tables.yh`，
`tests/modules/projects/tomltables/{project.toml,main/main.yh}`。
**修改：** parse/storage/query 的容器路径。

1. 实现混合/嵌套数组、数组尾逗号与注释，测试索引越界与空数组。
2. 实现私有表状态与键索引，先测重复键、标量转表、隐式父表后显式定义、点键
   定义身份及重复表头，分别验证错误码和两个来源位置。
3. 实现内联表封闭语义、点键子表、1.1 的多行/注释/尾逗号；花括号外不能补成员。
4. 实现数组表与嵌套归属；验证后续子表绑定最近元素、跨段回到另一数组表及
   普通数组与数组表冲突，不能只测试相邻 `[[item]]`。
5. 固定 `get` 直接键名行为；测试 `"a.b"` 与路径 `a.b` 同时存在、空键、NUL 键、
   首次引入顺序、容器扩容后视图稳定。

**定向验证：** `python3 tests/toml/run.py --compiler ./yh --group tables`。
**关闭条件：** 表定义状态矩阵全部正反例通过；上游 strings/scalars/tables 相关
组均能输出正确值树。未实现组不得被 runner 静默算作通过。

## 6. T4：文件入口、资源与公共 API 收口

**新增：** `libs/toml/files.yh`，
`tests/modules/projects/tomlerrors/{project.toml,main/main.yh}`，
`tests/modules/projects/tomlfiles/{project.toml,main/main.yh}`。

1. 补齐 get/table_get/array_get/count/table_entry 与标量查询契约及无效参数断言。
2. 测试嵌套/输入/累计分配上限的边界内、边界值和越界值；校验长度计算先查溢出。
3. 测试支持路径上的各次分配失败，验证没有半成品、双重释放或依赖分配成功的诊断。
   注入使用测试构建，不向已安装模块导出 test_* 产品 API。
4. 文件入口处理短读、interrupted、EOF、失败关闭与错误优先级；用测试构建替换
   私有读取接缝，另外以真实文件核对 os 集成和描述符回收。
5. 核对每个 pub 声明确有外部消费者；更新 doc.yh 与初版 README。

**定向验证：** `python3 tests/toml/run.py --compiler ./yh --group api,resources,files`。
**关闭条件：** 成败生命周期一致、错误有稳定分类和字节位置、读取路径没有 fd 泄漏；
验证结果只声明实跑的平台。

## 7. T5：标准一致性、分发与 reader 发布门

**新增：** `tests/modules/projects/tomltestdecoder/{project.toml,main/main.yh}`、
`tests/toml/conformance.py`、上游版本与校验记录。
**修改：** Makefile、Gitea 分支/tag 工作流、标准库总设计、根 README 及库 README。

1. 实现最小测试桥：stdin 读字节，成功遍历值树输出 tagged JSON，失败非零。
   JSON 转义必须保留 NUL，整数不能经浮点中转，时间表示由适配层规范化。
2. 先用故意改错整数/丢键/放行非法输入验证 oracle 确实失败，再跑固定 1.1 语料。
3. 为 runner 提供 `--conformance` 与显式语料准备入口；固定版本校验，常规运行
   不静默下载。完整门缺少工具/语料必须失败并说明准备方法。
4. 接入 `make test-toml`（API）和 `make test-toml-conformance`（一致性）的拟议门。
   本平台全门调用的基本 API 组必须常驻；CI 明确调用完整一致性门。
5. 运行大表/长字符串/深层失败样本，记录时间与峰值内存；预算内不能出现失控扩容。
6. 检查 make install 与 Release 打包实际包含 TOML 源码，安装后从仓库外导入运行。
   测试 fixture 只在 tests/，不进入标准库安装目录。
7. 执行本平台 `make`、`make test`、`make selfhost-native`、两个 TOML 专项门；
   更新功能矩阵、限制、所有权、中文注释和完成报告。

**关闭条件：** 固定 1.1 decoder 集零失败、零跳过；API/资源/文件/安装验收通过；
本平台全门有新证据，其他平台按 Gitea 结果披露。此时才标记完整 reader 完成。

## 8. T6：编译器 project.toml 迁移（单独批准与验收）

**修改：** `compiler/project.toml`、`compiler/cmd/project_index.yh`、
`compiler/cmd/project_link.yh`、`project_c.yh` 等经调用搜索确认的消费者；
最终删除无剩余引用的旧 `compiler/cmd/toml.yh`。
**新增：** `tests/modules/projects/tomlmigration/` 的 `.yh` 项目及清单数据，
`tests/selfhost/toml-migration.py`；按需扩展既有 tomlbad/tomlunknown 等用例。

1. 先冻结现有清单正反例、错误类别、链接顺序和解析结果；定义新语法与旧 schema
   的兼容矩阵。未知字段/必填字段等仍由编译器拒绝。
2. 增加或复用显式 yh_libs 依赖；确认旧种子可从原布局冷编候选。
3. 一个消费者一个切片替换为 toml API；显式复制需要长期保存的名字池数据。
   文件名/路径/模块名消费转义 NUL 时必须报错。
4. 以父子孙依赖各有同名键的项目验证递归重入和父文档生命周期，再移除全局快照。
5. 测试标准库内容改变后构建失效、缓存身份与发布布局；不要只验证热缓存构建。
6. 运行旧种子→候选→两代固定点、自解析、现有全部模块/项目验收和本平台全门。
   删除旧解析器前 `rg` 检查所有调用；全绿后按仓库流程另行决定滚种子。

**关闭条件：** 原清单兼容矩阵与新 reader 一致，schema 未被绕过；递归加载、冷编/
缓存/分发均通过；固定点与模块/项目语料全绿。库完成与迁移完成分别记账。

## 9. T7：生成器候选（后续按需）

有明确写配置需求后再设计独立文档构建器与 `encode`，确定输出文本所有权、确定性
排序/布局、浮点格式化与四种时间输出；用 toml-test encoder 和 decode/encode/decode
的值树等价验证。语义生成不保留原注释/排版，保真编辑另立任务。
本阶段不预加空函数、构造 API 或失败占位实现，也不据此阻塞 reader。

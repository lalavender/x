## 1. 如何使用清单

- **已确认缺口**：当前源码可直接核对的架构或能力缺口，不等于已复现的运行错误。
- **待复现风险**：存在实现差异或危险边界，尚不能断言当前程序已经出错。
- **待评审取舍**：替换过程中必须明确的产品或架构规则，不列作语言 bug。
- **P0**：阻挡完整 LLVM 后端或默认切换；**P1**：阻挡正式发布质量；
  **P2**：后续平台的接入条件，不阻挡 Linux/x86_64 首片。
- 每项必须留下“源码/文档坐标 → `.yh` 探针 → 实测结果 → 契约/修复 → 验收证据”。
  固定点通过不能代替语义验证；全量测试通过不能代替 LLVM 实际覆盖验证。
- 问题只有在对应任务验收通过后才可关闭。本轮所有代码问题保持未关闭。

## 3. 第一批：语义探针先于修复（LLVM-01、LLVM-05）

建议新增 `tests/yh-run/run/llvm-integer-boundaries.yh`、
`llvm-bool-memory.yh`、`llvm-float-boundaries.yh`；拒绝层对应文件放 `fail/`。
第一轮先用现行种子/旧后端记录观察值，不伪造尚未存在的 LLVM 结果。

| 探针类 | 必须覆盖的输入与路径 | 处理规则 |
| --- | --- | --- |
| 移位 | i8/i32/u32/i64/u64；量为 -1、0、31、32、63、64、65；常量与变量 | 当前代码按 64 位中间量和 `&63` 计算，窄结果随后归一化；不能偷偷改成 `&31` |
| 除法/取模 | 0 除数；各宽度最小负数与 -1；有符号负余数；u64 高位 | 区分源类型、提升后的计算宽度与最终截断；不能把 ARM64 的一条 SDIV 等同于所有源类型规则 |
| 溢出/转换 | 最大/最小值的加减乘；符号/零扩展；高位字面量 | 保留已定义定宽规则；未证明前不加 `nsw/nuw/exact` |
| bool | 正常 0/1；从整数转换；bool 的数组/字段、C 返回；非规范字节 | 内存表示和真值转换分别核对；`trunc`、掩码、非零比较不是可随意互换的规则 |
| 浮点 | NaN、±0、±Inf、比较、f32 舍入、整浮转换边界 | 初期禁用 fast-math；比较谓词与转换契约由文档和实测确定 |
| 内存 | 地址已知对齐、未知对齐、重叠复制、切片共享、聚合副本、逃逸 | 有证明才提高 alignment/加 noalias；未知有效对齐保守处理；memcpy/memmove 按真实重叠契约选择 |
| 效果 | `&&/||` 右侧调用、函数实参求值次序、noreturn 返回违约 | 保留短路与顺序；要求硬陷阱的场合必须显式 trap，不仅写 unreachable |
| 未初始化 | 正常初始化、未初始化读、部分初始化聚合 | 不在迁移中自行增加零初始化或拒绝规则；若现行规则未定义，先形成单独语义决定 |

如果探针发现既有 bug，先在本清单追加独立复现编号，修旧路径并跑完整门；
不能拿 LLVM 的结果作为语言定义，也不能把历史偶然的栈垃圾固定为契约。
仅当语义政策确实变化时，按 AGENTS.md 检查 `docs/yh.g4` 是否受影响并刷新对应语义文档。

## 4. 前端与覆盖的关闭方法（LLVM-02、LLVM-03、LLVM-04）

1. 冷编重测 compiler/ 的 checked、SSA 成功、真正新后端发射、拒绝原因；历史 991/22
   仅用于说明规模，不能当成此轮实时覆盖率。
2. LLVM 模式禁止同模块/同函数自动回退。未支持形态给出 `.yh` 文件、行列、函数和原因，
   不发布可执行文件；旧模式在过渡期单独使用。
3. 建立受检模块快照：逻辑符号、类型/布局、全局与初始化、函数体、目标身份、来源位置。
   语义完成后的快照由 lowering 消费，输出缓冲不再是阶段之间的通信协议。
4. 聚合优先采用有类型的位置、显式副本和存储，不要求每个 struct/array 值先做复杂聚合 SSA。
   可变标量先用入口 alloca/load/store，允许 LLVM 提升；保留已有有效 SSA/phi。
5. 各覆盖切片同时检查 build/run、单文件、check、导出 CT 正文；
   check 不能因函数不在 LLVM 子集而错误拒绝原来合法的程序。

## 5. 运行时、缓存与种子的关闭方法

- 普通模块对象有导入其他模块的符号是正常的。现有“对象无未定义符号”断言针对
  `runtimebytes` 自包含 fixture，不能扩大为所有模块都必须独立无导入。
- 保留 `runtime-memory.py` 当前禁止从 C runtime 导入 malloc/free/memcpy/strlen/printf
  的门；新增 memset 等辅助入口与最终链接审计。不能靠删除断言解决 LLVM 插入调用。
- 不认为 `-ffreestanding/-fno-builtin` 能禁止任意 LLVM IR 生成 libcall；用 O0/O2、
  大块复制/清零、低优化运行时实现和符号/反汇编证据确认无自递归与外部依赖泄漏。
- check/前端 IR 键只纳入其真实语义依赖；对象和链接键纳入完整代码生成/工具链输入，
  不把所有 LLVM 选项盲目塞进纯语法缓存。
- 候选及各代产物放 `tmp/llvm-migration/`；旧种子保留在 bin/，验证期间不覆盖。
  默认切换前必须通过 `make test`、`make selfhost-native` 及 LLVM 专项门。
  Windows/WSL 启动阶段显式使用 `bin/yh-linux-arm64`；原生 x64 候选全门通过后
  滚入 `SEED_DEST=bin/yh-linux-x64`，保持 ARM64 种子及哈希不被覆盖。

## 6. 处理顺序与状态

**LL0 基线/取舍 → LL1 语义与 ABI 契约 → LL2 受检边界/目标模型 → LL3 严格 LLVM 首片
→ LL8a 内存 helper → LL5 存储/数据 → LL4 控制流 → LL6 浮点 → LL7 调用
→ LL8b x64 完整运行时/宿主桥 → LL9 原生驱动/缓存 → LL9L 内嵌 lld 链接器
→ LL10 x64 原生自举/既有硬门
→ LL11 性能与 x64 默认切换 → F1 Linux/AArch64 LLVM 回归 → LL12 退役旧机器代码生成。**

LL4–LL8 每个切片都可独立验收；跨函数聚合在 LL7、浮点字段在 LL6 汇合。
第一轮执行按上述顺序推进，不默认创建并行子代理。
遇到源码行为与方案矛盾时，先更新探针/记录，不悄悄扩大语言或变更 ABI。
Linux/x86_64 原生切换完成后才进入 F1–F4；LLVM-14/15 的 x64 部分已前移为首期阻塞项。
从 LL3 起先让生成的 x64 测试程序原生运行，LL10 再完成编译器 B/C/D 原生连续自编。

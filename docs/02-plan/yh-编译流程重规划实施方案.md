# yh 编译流程重规划实施方案

日期：2026-09-30。状态：待实施建议稿。本次完成现状核对和方案交付，
不表示下列代码任务已经完成。

设计见[编译流程重规划](../03-design/yh-编译流程重规划.md)，路线见
[ADR-0008](../adr/0008-yh编译流程分阶段整理.md)。采用现有 token 驱动
流程逐阶段整理，AST/IR 作为有明确需求后的独立决策。

## 1. 执行约束

每阶段先新增 `tests/yh-run/` 或 `tests/modules/` 中的 `.yh` 正反/运行
用例，再修改代码。测试脚本修改可另加 Python 门测试，但不替代 `.yh`
端到端语料。函数、结构体注释用中文；临时文件在 `tmp/`。

每阶段至少跑 `make`、相应语料和修正后的 `make selfhost-native`；
阶段结束跑 `make test`。Windows 验证在 WSL 内进行。保留现有源码
可被上一代种子编译的子集，不把新增语法或种子未知的运行时 API 混入
流程重构；若无法保持，先独立设计兼容桥，不能直接污染 `bin/yh`。

不改 `docs/yh.g4`；若实现中发现需要改变语言规则，暂停该变化，按
仓库约定另立语法设计、计划与语料。

## 2. 分阶段任务

### CF-0：建立可信基线（最高优先级）

修改范围：`tests/selfhost/native-selfhost.py`、`tools/selfbuild-gate.py`、
`Makefile` 及直接相关的当前流程文档。

1. 每代构建结束立即保存独立字节快照，下一代不能覆盖上一代证据。
2. 断言产物集合非空、与预期模块一致；现有编译器是
   `gen/lex/parse/main` 四模块、8 个 `.s/.s.i`。
3. 增加快照内容扰动、缺失接口与空集合反例，证明门确实能拒绝差异。
4. Makefile 的冷编清理指向实际 `.build`，`clean` 同步；冷编策略保持
   保守，热构建能力在 CF-3 独立验收。统一当前 README 的流程入口，
   历史文档标记适用阶段，不删除历史记录。
5. 新增 `.yh` 固定点探针：同时包含前向函数调用、聚合和浮点；逐代
   比较生成的汇编并运行，避免仅用空程序判断闭环。

验收：`make`、`make test`、修正后的 `make selfhost-native` 和
`python3 tools/selfbuild-gate.py` 全绿；人为扰动门必须失败。
源码实现不变时，修正门前后的独立模块快照相同。

### CF-1：统一单文件与模块编译编排

修改范围：`cmd/compile.yh`、`cmd/driver.yh`、`cmd/module_build.yh`。

1. 一个入口负责语义初始化、声明登记、全局、函数和 `.bss` 收尾；
   单文件与模块调用同一核心，文件准备与导入绑定由薄适配层处理。
2. 全模块登记结束后才编译函数体，保留跨文件前向调用。初始化与
   声明顺序保持原行为；类型前向可见性不借重构扩大。
3. 按文件累计导入使用，覆盖全局和函数阶段。纯语法模式继续只检查
   语法；成功编译后才能写汇编 stdout。
4. 显式模块构建区分库模块与 `main` 程序模块：库生成对象/接口，
   程序才校验 main 并链接。该行为需新增用例，不静默改变 CLI。

新增 `.yh` 语料：同一函数负载分别通过单文件/项目编译；多文件互递归；
全局初始化顺序的正反例；仅在全局使用导入的模块；缺 main 的纯语法
正例与程序编译反例；显式库模块构建正例。

验收：上述语料的退出码、诊断与已定义行为符合契约；阶段前后现有
语料全过。行为保持部分比较汇编；有意修复部分以明确期望验收。

### CF-2：统一目标、工具链和产物提交

修改范围：cmd 内驱动/项目临时状态/产物代码、`parse/iface.yh`。
按职责提取文件，继续属于 `module main`，不新增语言模块。

1. 目标仅规范现有两方言；拒绝未知值，子进程显式继承。接口格式
   识别目标 ABI；版本升级使旧缓存失效。
2. 同一处拼装工具链命令，所有路径统一引用；检查每次外部命令的
   退出状态，修正全局共享 scratch 为 `tmp/` 内本次构建独有状态。
3. 完整函数体成功后才提交接口和汇编。临时完成、撤销旧标记、
   替换 payload、最后提交 manifest；消费者要求有效完成标记。
4. 对象和程序也按成功后发布处理；失败保留旧用户输出，`yh run`
   构建失败不得执行旧程序。首次只支持串行构建，不宣称支持并发。

新增 `.yh` 语料：目标切换的同一负载、函数体含语义错误但有 pub
声明的模块、空格/单引号路径下项目、可识别退出码的旧程序与失败
重建。测试驱动模拟写入/汇编/链接失败与中断，检查完成标记。

验收：错误后不会命中新旧混合产物；不同目标不混用接口；本机可
运行，异宿主汇编输出符合方言且链接边界给出诊断。重新跑全量门。

### CF-3：补齐编译、汇编、链接三层缓存

修改范围：cmd 缓存记录与构建执行，不更改语言语义。

1. 升级带字段边界的缓存输入记录，包含文件路径/顺序、解析绑定、
   目标/ABI、编译器身份。一次构建只计算一次编译器身份。
2. 为 `.o` 增加汇编输入记录，为程序增加链接输入记录；工具链身份
   与实际参数进入相应记录。缺产物或完成标记均重建。
3. 仍每轮扫描与重绑定；依赖实现变化与接口变化分别决定失效范围。
4. 增加阶段日志或测试计数，不能只靠 `[缓存]` 判断完全热构建。

新增 `.yh` 项目探针及变体：冷/热同负载、只改依赖私有函数、修改
pub 签名并同步调用方、新增本地同名模块、更换编译器/目标、删除
`.o`、构造不同文件分组但字节拼接相同的输入。

验收矩阵：

| 变化 | 编译 | 汇编 | 链接 |
| --- | --- | --- | --- |
| 无变化且产物完整 | 跳过全部 | 跳过全部 | 跳过 |
| 依赖私有实现变化 | 重编依赖；调用方接口不变可复用 | 重建改变的汇编 | 更新程序 |
| 依赖公开接口变化 | 重编依赖及受影响调用方 | 按汇编内容更新 | 按对象内容更新 |
| 仅删除一个对象 | 复用汇编和接口 | 重建该对象 | 对象内容相同且旧程序完整可复用 |
| 编译器/目标变化 | 对应编译输入失效 | 按内容/目标判定 | 按内容/目标判定 |

所有场景的运行结果符合期望；工具链调用计数与阶段日志一致。
自举验证继续冷编，热缓存不替代固定点证据。

### CF-4：测量后复用源码与收紧后端接口

前置：CF-0–CF-3 完成并保持全量门通过。

1. 测量编译器项目和代表多文件项目的冷/热耗时、读源/词法次数与
   内存占用。先确定重复词法是否是值得处理的成本。
2. 若值得处理，保存模块进程内每文件源字节/token，三个遍历切换
   文件视图。释放责任和导入状态明确，不增加磁盘 token 缓存。
3. 为现有语义中的直接 AArch64 字符串补最少的后端原语，迁移调用；
   不同时实现新 ISA，不为可能的未来目标添加通用框架。

新增 `.yh` 语料：多文件不同字符串/长标识符、跨文件聚合与浮点
调用、不同文件同名局部；反例检查错误仍指向实际文件和行列。

验收：源码/token 生命周期正确，自举与全部语料通过；原语迁移前后
汇编固定；性能报告给出实际数据，收益不足则保留已有实现。

## 3. 各阶段完成记录

未实施阶段保留在 `docs/todo.md`。每阶段结束记录修改范围、新增
`.yh` 用例、执行命令和结果到 `docs/finish.md` 与 `docs/01-finished/`，
只将实际通过验收的任务标记完成。

CF-0 是其余代码阶段的前置条件。每阶段保持可回退的独立变更；
`make seed` 仅在新验证门和 `make test` 同时通过后进行，不能作为
开发中绕过旧种子编译失败的常规操作。

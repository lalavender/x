# yh 编译流程重规划实施方案

日期：2026-10-01。状态：D1–D15 与完整方案均已确认，R0–R6 实施中。
原 CF-0–CF-4 路线撤回；本计划改为早期 check、SSA、线程池与增量。

设计见[编译流程重规划](../03-design/yh-编译流程重规划.md)，
选择依据见[ADR-0009](../adr/0009-yh采用check与IR及早期并行.md)，
已答问题见[决策树](../03-design/yh-编译流程设计决策树.md)。
任务进度以[todo](../todo.md)和[finish](../finish.md)为准。

## 1. 执行与分期边界

- 不改语法。若发现需要变更语言规则，另立设计、计划、.yh 正反
  用例，先分析 docs/yh.g4 歧义，再实施并刷新相关文档。
- 每项行为变更先在 tests/yh-run/ 或 tests/modules/ 添加 .yh 用例；
  测试基础设施可另加门测试，但不代替 .yh 端到端语料。
- 每次代码修改执行 make 与针对性验收；阶段结束执行 make test
  和修正后的 make selfhost-native。函数/结构体使用中文详细注释，
  文件拆分服从仓库规模约定，临时文件均在 tmp/ 中。
- 保持 bin/yh 滚动自举，源码迁移先遵守上一代支持的 yh 子集，
  新宿主服务用经过验证的兼容桥引入，不恢复 C stage0。
- 计划按依赖执行，不假定完成日期。自有工具链不阻塞前端/SSA
  初期验证；线程池、增量契约与状态隔离不推迟到自有工具链之后。
- Linux/macOS 的执行验收各自在相应宿主完成；异宿主先验证汇编/
  对象，不据此声称运行通过。Windows 阶段开发命令在 WSL 执行，
  生成的 Windows 程序仍需 Windows 执行证据。

## 2. 里程碑与依赖

| 编号 | 里程碑 | 完成界限 |
| --- | --- | --- |
| R0 | 可信自举门、性能基线与隔离基础 | 真正比较独立代、建立计数、取消共享临时路径 |
| R1 | AST 与完整 check、任务私有前端 | yh check 不进入 IR/后端，文件只解析一次 |
| R2a | typed SSA 与双 arm64 后端 | 新流水线可自编、语义正确，阶段性串行调试可用 |
| R2b | 首个完整 SSA 版本 | 线程池、接口就绪推进、函数缓存和文件对象全过门 |
| R3 | 自有运行时与 OS 接口 | 编译器不调用 shell，独立配置不提供隐式 system |
| R4 | Linux arm64 独立工具链 | 自有汇编/静态 ELF 链接、运行时、编译器连续自编 |
| R5 | macOS arm64 独立工具链 | 自有 Mach-O 汇编/链接/装载元数据，OS API 清单通过 |
| R6 | x64 与 Windows | ISA、ABI、对象格式和平台运行证据逐项通过 |

R1 从 R0 开始；R2a 与 R2b 的调度/缓存结构从 R1 同时设计，
R2a 只是便于定位问题的中间验收，不作为完成的首版 SSA 发布。
R3 的 OS/运行时适配可在契约确定后与 R2 开发交错，但 R2b 的
线程池实现必需的宿主桥须在该阶段就绪，不能等 R3 才增加线程。
R4 依赖 R2b、R3；R5 复用 R4 的通用对象/链接设施并补平台实现；
R6 在双 arm64 闭环与测量稳定后逐目标推进。

## 3. R0：可信验证与基础契约

范围：tests/selfhost/native-selfhost.py、tools/selfbuild-gate.py、
Makefile，以及编排/临时目录的必要修改。

1. 每代冷编后立即保存独立字节快照；比较非空、完整、预期集合。
   集合由当前项目发现，不写死原四模块/25 文件。
2. 增加字节扰动、缺接口、缺汇编和空目录反例，确认门返回失败。
   修正过时 stage0 注释及真正的 .build 冷编清理路径。
   统一 make、自举门与滚种子的显式种子选择，核对平台、路径和哈希；
   自举脚本不能忽略 make 传入的 SEED。
3. 取消 /tmp/yh-proj-scratch.txt 共享路径，为构建/worker 分配
   tmp/ 会话目录；不顺带清理无关代码。
4. 冻结当前约 1.3 万行性能语料，补真实函数实现变化的语料与脚本。
   输出端到端时间、阶段次数、工具调用次数和峰值内存。
   独立配置所需的 API 迁移记录为语料修订，另冻可构建版本；
   保留旧基线，不直接比较不同语料推导加速，另报实际编译器规模。
5. 写清 SourceStore、ModuleEnv、FunctionContext、TargetContext
   归属以及 InterfaceReady/ModuleChecked/ObjectReady 事件契约，
   为后续接口和代码迁移提供边界。

新增 .yh：前向调用、聚合/浮点的固定点运行探针；实际函数实现
修改使输出变化的增量探针。门测试验证快照扰动，不只比较空程序。

验收：make、make test、修正后的 make selfhost-native 与
tools/selfbuild-gate.py 全绿；所有故意扰动必须失败。
旧行为不变部分的独立快照一致；基线记录三种构建负载的真实含义。

**实施进度（2026-10-01）**：已完成 R0 固定点门、平台种子校验、
项目索引临时文件隔离和固定性能基线：两套自举门在每代构建后保存到独立快照

## 4. R1：一次解析、受检表示与 yh check

范围：现有 lex/parse/gen 语义代码、cmd 编排，按职责迁入 front/core；
保留可被种子构建的迁移路径。

1. 源文件一次读取/词法/语法，建立文件 AST、声明与函数索引。
   项目只统一索引一次，worker 不重新发现全部项目。
2. 将符号/类型/作用域/诊断状态迁入模块或函数上下文；发布的 AST、
   模块环境只读，生命周期覆盖全部使用者。
3. 将名称/类型解析和完整合法性检查从汇编发射中分离；
   CheckedFunction 携带可复用的控制流及源映射。
4. 增加 yh check 的单文件/项目入口，库检查不要求程序入口；
   继续保留纯 --syntax-check 的含义。
5. 建立声明、类型、公开常量及依赖闭包检查后的 InterfaceReady，
   仅在本次会话发布；阶段事件可先由串行/进程执行器驱动。
6. 保持类型/声明顺序、导入使用、前向调用、数组/切片与当前返回
   行为；不借迁移新增语言限制。

新增 .yh：语法合法但类型/可见性/控制流非法的 check 反例；前向调用、
多文件互递归、公开常量与类型依赖、库无入口正例、程序错误入口反例。
测试计数证明 check 无 IR/发射/工具调用，文件不重复解析。
连续处理不同函数/模块应无状态串扰。

验收：相关正反用例及现有全量门通过。受检表示里没有 ISA 指令/
寄存器；单文件和项目前端检查结果一致。同步现行使用文档。

**阶段性进度（2026-10-01）**：已完成 worker 源/token 快照、顶层声明范围
索引两个切片：pass1 按声明边界跳过函数体，globals/functions pass 只解析
自己负责的顶层声明。索引保留源区间，不是完整表达式 AST。项目矩阵覆盖公开
声明相邻边界，新增计数显示函数体变化 53 次词法扫描、736 个声明索引；冷编
131 次词法、2,944 个声明索引。固定语料 20 轮中位数为 1.717/1.869/2.217 秒
（无改动/函数体变化/冷编），仍有四次外部汇编和一次链接。语义/check 与发射
仍交织。`yh check [module]` 已提供第一个可运行入口：正例通过，类型错误项目
失败；测试确认不会调用 gcc/clang 或留下 `.s/.o/.s.i/manifest`，并使用独立
`.build/check/` 避免触碰正常构建缓存。check worker 现同步收集表达式 AST 与语句/声明
树：文件级声明节点复用 PDecl 索引，函数体挂接语句根；语句节点保存源范围、父子链、
表达式根和局部绑定引用，worker 结束时校验结构。token replay `.yh` 用例覆盖表达式、if/else、
循环、switch、赋值和控制流。表达式节点保存已解析符号及类型/常量快照；参数、局部变量/常量
与 for-in 隐式绑定使用 `(file_id, owner_decl, binding_id)`，表达式通过稳定 arena 行关联
具体声明，避免旧作用域弹出并复用符号槽造成身份冲突。赋值节点保留实际运算符。普通 build/check
均由旧 parser 遍历生成 AST，尚未成为独立语法阶段产物；build 在受检与 AST 校验后，把有限的
标量参数、顺序单绑定 `let` 初始化/有限同类型标量赋值、表达式 return、双臂 `if/else` 单 return，
以及单层分支更新参数或分支前初始化的局部值后合流 return 构造为 typed SSA 并验证。参数由入口块连续
`PARAM` 指令定义；局部初始化与赋值按声明顺序映射到新 SSA 值，分支间变化用双前驱 phi 表达；其他函数
仍由旧发射器处理。
独立 CheckedFunction/语义状态、任务私有上下文、接口就绪调度和函数级缓存均未实现。
详见
[词法快照报告](../01-finished/yh-编译流程R1词法快照复用-2026-10-01.md)与
[声明索引报告](../01-finished/yh-编译流程R1顶层声明索引-2026-10-01.md)。

**函数任务输入切片（2026-10-01）**：新建 `AstFunctionContext` 记录函数在 AST
各 arena 中的稳定范围，函数结束时检查表达式、语句、边和绑定没有越过该范围；IR
lowering 现在遍历这些上下文，只访问当前函数的参数和局部绑定，并按函数表达式规模分配
临时 SSA 指令缓冲。`.yh` 用两个同名局部绑定函数验证函数内编号不会串用，build/check
均必须封存十个函数上下文。该切片建立了只读函数输入视图，尚未移除解析/语义全局，也
不能作为线程安全或完整 CheckedFunction 的证据。

**单文件 check 入口（2026-10-02）**：新增 `yh check <file.yh>`，与项目形式共用
完整声明、全局初始化和函数体语义遍历，允许不定义 `main` 的库文件；输入加载和语义表
初始化在词法分析前执行，避免从早期命令分派进入空 token 流。`.yh` 正反例覆盖库函数
通过和未声明名称失败，回归确认不创建产物、不调用外部汇编器/链接器。该入口仍复用
多遍旧 parser，不独立产出完整 AST/CheckedFunction；R1 的一次解析与语义/check 分离尚未完成。

## 5. R2a：SSA、校验与双 arm64 后端

范围：ir、backend、目标契约；旧直发射实现仅用于迁移对照，
成功替换后移除因此孤立的入口，不清理无关遗留。

1. 定义 typed 值、基本块/边、phi、显式内存、调用/返回与聚合契约；
   先完整覆盖编译器自举和现有语料需要的指令。
2. 构造正确 CFG/SSA，处理前向 goto、循环、break/continue、switch
   和不可约控制流；不能过早封闭块，按需算法保证 filled/sealed 契约。
   显式内存/调用保守保持可能别名的可观察顺序，不错误复用 load。
3. 增加内部 verifier 和稳定序列化；默认常量折叠、平凡 phi 消除、
   局部简化，昂贵优化不进入默认构建。
4. 将 AArch64 发射迁到 SSA 后端，分离 Linux/macOS ABI、数据布局、
   符号和方言；实现 phi 并行复制与寄存器/栈分配。
5. 单文件/项目/--emit-asm 共用新核心；过渡使用系统汇编/链接。
   check/IR 按目标隔离，AST 可共享。
   建立开发阶段 Linux 交叉工具链，以已验证 macOS 候选生成 Linux
   汇编和 ELF 候选，原生通过全门后保存第一代 Linux 种子与哈希。

新增 .yh：分支合流、回边、前向/跨分支 goto、多标签、switch 和
continue；取地址/别名写入、调用副作用；浮点、递归、聚合/数组/切片
按值与大型栈帧。内部构造非法 IR 作为 verifier 反例。
phi 复制环用运行结果验收，不只检查字符串。

验收：当前语料行为全过，新编译器连续自编达到固定点；
Linux/macOS 汇编/对象与各宿主运行证据齐备后才标双平台完成。
串行 SSA 路径通过只是中间门，R2b 未完成时不宣布首版交付。

**阶段性进度（2026-10-01）**：已新增 `compiler/ir/`（初为独立 yh 子项目，
2026-10-02 起并入根项目普通模块），
定义目标隔离的类型、普通指令、基本块终结、phi 输入与函数容器；基础校验器
覆盖值定义唯一性、类型、访存元素类型、CFG 终结形式、phi 前驱集合与可达块
支配关系。独立 `ir_simplify` 可折叠定宽整数常量运算，并把同值 phi 变为别名/拷贝；
模块 `.yh` 运行分支合流、检查简化前后 verifier 与返回值。另有稳定编码切片，使用
带版本/目标编号的固定字段序 little-endian 格式；往返逐字节一致，错目标、错版本、
截断和 verifier 拒绝的 CFG 输入均有测试。verifier 也拒绝 CONST 隐藏操作数、除 CONST 位型与
PARAM 形参序号外的非零 immediate、phi 保留字段和算术 aux；PARAM 只允许在入口块连续前导区。
该 IR 已接入根 compiler 项目（初为 path 依赖，2026-10-02 起为普通模块）；普通 build
的受限 AST 子集会实际生成并验证 SSA，`yh check` 仍在 IR 前结束。

**阶段性进度（2026-10-02）**：受限 SSA 已驱动 arm64 后端，覆盖标量参数、
局部定义/赋值、简单分支与 phi、整数算术及比较。本轮增加同类型整数除法、取模、
位与/或/异或和左右移位，校验有符号/无符号运算，默认折叠非异常常量表达式，
升版函数 IR 序列化和缓存键。`.yh` 项目用例验证生成程序的正负数结果、
右移符号扩展、零除数的运行行为，以及错型 IR 的拒绝。编译器自编项目
512 个函数 AST 上下文中仅 1 个进入当时的 SSA 子集；调用、复杂控制流、
聚合/内存语义及完整单文件后端仍缺失，R2a 不视为完成。

**直接调用进度（2026-10-02）**：SSA 新增稳定符号名与变长带类型实参，verifier
检查调用表连续性、参数类型及定义对调用点的支配关系，序列化升至 v4、函数缓存键
升至 v8。arm64 后端对固定参数整数/布尔调用发射 x0–x7 和对齐栈实参；AST
降低覆盖嵌套调用，并将符号名和签名事实纳入函数缓存键。`.yh` 项目运行验收
包括无参、九参、两次副作用调用、导入模块调用及提供模块体变化后的精确重链接。
本机自编项目 528 个函数上下文有 5 个进入 SSA，较前一切片的 1/512 增加，
但占比仍很低；间接/浮点/聚合/变参/void 调用和复杂 CFG 未接入，完整速度目标
仍需后续改造。冻结 25 文件语料的 20 轮测量结果为无改动 37.7/54.4ms、
单函数修改 728.3/1112.2ms、冷编 2029.0/2371.4ms（中位数/p95，含汇编和链接）；
该切片未证明提速，后两项目标仍未达到。详见[直接调用 SSA 报告](../01-finished/yh-编译流程R2a直接调用SSA-2026-10-02.md)。

**void 调用与语句级调用进度（2026-10-02）**：表达式语句只接受已检查的直接
调用——void 返回发射无结果 CALL（verifier 值编号允许稀疏），标量返回可被
语句丢弃，顺序路径与 if/else 分支块均按源码顺序发射。void 函数本身可由 SSA
降低，支持裸 `return;` 与隐式结束，空函数为单块零指令 CFG；后端允许 void
返回与零指令函数。`irfront` 48 个函数上下文 46 个进入 SSA；`ircallmodule`
覆盖跨模块 void 调用与提供模块体变化后的精确重链接。循环、switch、goto、
间接/浮点/聚合/变参调用仍走旧发射路径，R2a 不视为完成。
详见[void 调用报告](../01-finished/yh-编译流程R2a-void调用与语句级调用-2026-10-02.md)。

**条件循环进度（2026-10-02）**：`for cond { 顺序体 }` 以四块 CFG 降低：
入口→循环头（携带值 phi + 条件 + 条件分支）→体（顺序语句 + 回边）→退出。
体内被赋值的外部绑定在循环头建双前驱 phi，入口输入创建时填写、回边输入
在体降低后回填；体内 let 重新定义不携带，携带绑定去重上限 16。顺序语句
检查/降低抽取为 `ast_ir_straight_scan`/`ast_ir_straight_emit` 共享辅助。
`irfront` 53 个函数上下文 51 个进入 SSA，覆盖双 phi 携带、体内 let、
尾随语句与 void 循环调用。体内嵌套控制流、break/continue（需多前驱
phi 与动态块序）、for-in 与 `for {}` 仍回退旧发射器，R2a 不视为完成。
详见[条件循环报告](../01-finished/yh-编译流程R2a-条件循环-2026-10-02.md)。

**通用构造器进度（2026-10-02）**：受限的固定形态匹配替换为通用递归

verifier 块区间改为覆盖检查。if/else 任意嵌套与 else-if 链、条件循环、
break/continue 与 return 任意组合进入 SSA；循环采用发现趟+真实趟两趟
协议（发现趟在主 builder 上回滚式执行），header phi 按「入口 +

仍回退。详见[通用构造器报告](../01-finished/yh-编译流程R2a-通用构造器与break-continue-2026-10-02.md)。

**短路求值进度（2026-10-02）**：`||`/`&&` 降为条件块 + 右臂块 + 合流块

## 7. R3：运行时、显式 OS API 与兼容迁移

范围：runtime、toolchain 外部进程适配、prelude 和 CLI。
不改变 module/import 语法。

1. 目录枚举、路径创建、环境、程序启动/等待和线程改用显式 OS API，
   编译器不再通过 system/ls/mkdir/echo 或 shell 拼装实现这些功能。
2. 自有内存分配、字节/字符串、格式化、I/O、退出与参数入口；
   目标程序按需求带入运行时，自举工具带入宿主能力。
3. 独立配置不隐式登记 system；兼容配置明确保留旧行为与依赖，
   新接口与源码迁移在文档中给出替换示例。
   prelude/运行时接口配置进入模块环境、check/IR 与链接缓存身份。
4. Linux 实现对应架构 OS 入口；macOS 明列审核后的 libSystem OS
   函数与 dyld，禁用通用 C 服务直接导入。
5. 保持种子能够构建中间版本：先完成兼容桥、自编与全门，
   再迁入新宿主实现，不随意修改 bin/yh。

目录枚举由平台源文件实现 `pj_os_dir_list` 适配，接收调用方拥有的条目向量，
直接收集后交给共用扫描器排序与递归；不经 `opendir/readdir` 等通用 C runtime
接口。Darwin 用已公开的
`getattrlistbulk`，请求 `ATTR_CMN_RETURNED_ATTRS | ATTR_CMN_NAME |
ATTR_CMN_OBJTYPE` 并按返回记录长度遍历；当前 SDK 会将 64 位 inode 模式下的
`getdirentries` 故意编译成链接错误。Linux arm64 用 `getdents64` syscall
（编号 61）与 Linux UAPI 的 `linux_dirent64` 布局。两端都须把名称和目录类型
收集到任务私有缓冲，按字节序排序后再递归，以保持确定性；测试覆盖空格、引号、
非 ASCII、点开头和包含换行的文件名，以及条目缓冲跨批读取。

Darwin API 的最小 C 探针已在开发机目录运行成功：属性位必须包含
`ATTR_CMN_RETURNED_ATTRS` 与 `ATTR_CMN_NAME`，每条记录从 8 字节对齐的总长度
开始，名称由 `attrreference_t` 相对偏移定位。实现还须将该调用登记为 macOS
允许的 OS API；Linux 必须走自有 syscall 封装，不能为了共用 API 引入 glibc/CRT。
参考：[Apple XNU `getattrlistbulk(2)`](https://github.com/apple/darwin-xnu/blob/main/bsd/man/man2/getattrlistbulk.2)、[Linux AArch64 syscall 表](https://github.com/torvalds/linux/blob/master/arch/arm64/include/uapi/asm/unistd_64.h)、[Linux `getdents64` 实现](https://github.com/torvalds/linux/blob/master/fs/readdir.c)。

新增 .yh：分配/扩容/复制/格式化、短读写与坏句柄、argc/argv、
进程退出码、线程任务隔离；独立配置拒绝隐式 system，兼容配置行为
符合原契约；切换两配置必须重检，不能复用允许 system 的缓存。
坏路径、空格/引号路径不被 shell 解释。

验收：编译器操作记录无 shell；自有服务用例通过；OS 导入清单符合
配置。运行时用目标宿主验证；阶段结束全门通过后才可滚种子。
外部汇编/链接仍属于过渡依赖，不能在此宣布工具链已独立。

**阶段性进度（2026-10-01）**：已完成兼容配置、显式 argv 进程调用和
输出捕获迁移切片。
默认语义 prelude 不登记 `system`，CLI `--legacy-system` 可显式启用；模块
manifest、SSA 缓存键和链接缓存键均含配置身份。新增的 `.yh` 项目验收覆盖
默认拒绝、兼容 build/check/run，以及由兼容配置切回默认配置时不能复用旧缓存。
汇编器、链接器和已构建程序通过显式 argv 启动进程；目录枚举现由 OS API
完成，不再启动 `ls` 子进程。构建与临时目录由宿主
`mkdir` OS API 逐段创建，交叉目标项目检查覆盖宿主文件标志。滚动自举改在
默认 systemless 配置下构建，不再主动传 `--legacy-system`。编译器入口已接收
`envp` 并直接读取 `PATH`、`YH_STDLIB`，`printenv` 依赖已移除。项目目录枚举
现由 Darwin `getattrlistbulk` 与 Linux arm64 `openat/getdents64/close` 适配提供，
不再调用 `/bin/ls`；Linux syscall intrinsic 直接发射 `svc #0`。扫描器把文件名
与目录类型收集到本次调用的动态向量，按字节序排序后递归；项目 `.yh` 用例覆盖
空格、引号、非 ASCII、换行文件名、隐藏文件过滤与 512 项以上目录。`memcpy` 与
`strlen` 已由 arm64 自有汇编入口实现，覆盖直接调用、函数值调用、零长与边界长度、
返回指针、UTF-8 字节长度和非对齐字符串扫描；实现先逐字节对齐再按机器字扫描，
避免未对齐的跨页读取。`malloc/free` 也已改为本地汇编入口：每次申请单独映射，映射头
保存长度，用户指针偏移 16 字节；Darwin 调用审核后的 `mmap/munmap`，Linux arm64
直接发射对应 syscall。`.yh` 回归覆盖零长度、对齐、读写、释放、空指针与函数值调用。
普通程序和自编编译器均不导入 `malloc/free/memcpy/strlen`，Linux arm64 对象已交叉组装
且无未定义符号。`printf` 已有本地 arm64 入口，支持 `%%`、整数、字符串和字符格式，
以缓冲区分段调用 OS `write`；`.yh` 用例覆盖负数、变参寄存器、长字符串刷新和精确输出。
运行时 stub 在模块收尾按调用/取址标记发射；无相关调用的普通程序不导入 `mmap/munmap/write`。
自举门对最终候选相邻两代验收。滚种子前后 `make`、`make test`、`make selfhost-native`
均通过；根 `nm -u yh` 只剩显式登记的 OS API。printf 尚不支持宽度、精度、浮点与 locale；
线程 API、Linux 原生运行和完整导入审计仍未完成；过渡汇编/链接继续依赖系统工具，因此
R3 不通过。性能数据见[自有运行时报告](../01-finished/yh-编译流程R3自有分配器与性能-2026-10-01.md)。

**更新复测（2026-10-01）**：延迟发射运行时入口后，在 Apple M1 冻结 25 文件语料
进行 20 轮端到端测量（含汇编和链接）。无改动 32.2/37.9ms、函数体修改

1. 冻结后端/运行时产生的汇编子集和指令/伪指令、符号表达式、
   数据段、对齐与重定位契约；不实现未需要的完整 GNU 语法。
2. 自有汇编器生成有效 ELF 对象；支持上述子集需要的全部编码、
   分支距离处理与重定位，遇到不支持项明确报错。
3. 自有链接器解析约定 ELF 普通对象，完成符号、布局、重定位、
   入口与静态 ELF 程序。首版不要求第三方库/归档/动态链接兼容。
4. 将 Linux 自有入口/运行时与编译器一起接入，工具链 API 在 yh
   进程内调用；对象与链接缓存保持 R2b 契约。
5. 使用 R2 阶段归档并经原生验证的 Linux ELF 种子，迁移到自有工具链
   候选；make、自举门与滚种子统一平台/路径/哈希，保留各平台资产。
   恢复相应平台日常开发/CI 验收，打包明确目标与哈希。

新增 .yh：多对象私有/公开符号、全局数据、地址与函数指针、近/远分支、
大数据/对齐、启动参数、完整编译器自编；测试对象重定位范围与溢出，
未定义符号/重复定义/损坏对象必须拒绝。
开发测试可用官方格式工具交叉核对，不作为产品运行依赖。

验收：Linux arm64 在无需外部汇编/链接、shell、libc/CRT 的受控环境
中构建并运行全部普通语料与下一代编译器；导入/装载记录通过。
连续自编固定点、串并行一致与增量矩阵通过。
按固定语料测 50ms/200ms/1s；未达目标必须列出实际瓶颈和差距。

## 9. R5：macOS arm64 自有工具链

1. 复用通用指令/符号设施，补 Darwin 汇编与 Mach-O 对象/重定位。
2. 自有链接器实现入口、段布局、装载命令、所需系统 API 导入及
   可运行 arm64 程序要求的签名/元数据，不要求安装 SDK/外部 codesign。
3. 接入自有语言启动与基础运行时，保留披露的 dyld/libSystem OS
   边界；按 API 允许清单检查，不能只检查动态库名称。
4. 源码、汇编/对象与缓存都携带目标契约；Linux 静态 ELF 路径继续
   回归，不因 Mach-O 实现改变原平台行为。

新增 .yh：启动参数、I/O/内存/线程、跨对象调用/地址、浮点/聚合 ABI、
普通程序与编译器自编；另测 Mach-O 格式错误、导入越界和装载失败。

验收：macOS arm64 无外部编译工具和 shell、无直接通用 C 服务/
CRT 依赖，自有工具链连续自编和语料通过；明确 OS 库与导入 API。
按相同端到端口径测目标，记录系统版本和装载/签名限制。
只有 Linux 与 macOS 各自满足闭环才能宣布首批独立工具链完成。

## 10. R6：x64 与 Windows

顺序按已确认的 arm64 优先推进，复用前端/SSA/调度/缓存；
check/IR 默认仍按目标安全隔离。

逐目标实现 x64 指令选择/编码与调用约定，再补对象格式、入口、
运行时、OS 进程/线程和工具链；Windows 覆盖 PE-COFF 与 Windows ABI。
平台 .yh 用例覆盖浮点、聚合、递归、栈、跨对象符号和编译器自编。
Windows 开发命令在 WSL；运行验收须包含真实 Windows 目标环境。

验收：每一目标有可保存种子、独立工具链、自举固定点、全量适用
语料、导入依赖审计、串并行/增量矩阵和平台性能基线。
未验收目标不能仅凭后端文件存在标为支持。

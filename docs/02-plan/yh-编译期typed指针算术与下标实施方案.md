# yh 编译期 typed 指针算术与指针下标实施方案

日期：2026-10-07。状态：已完成；滚动种子、冷编与自举主门均通过。

## 目标

编译期指针此前只能取址、解引用与传参，`p + i`、`i + p`、`p[i]` 一律不可用
（typed 执行器把指针值当作非整数直接拒绝）。本片补齐指针算术与指针下标读写，
让编译期函数可以按偏移遍历调用方帧的聚合元素。

## 设计要点

- 槽步进语义：编译期聚合元素本身就是 `CtValue` 槽，因此「指针 + 1」按**槽**前进
  恰好等于语言上「指向下一个元素」（f32 元素也只占一个槽）。新增
  `ct_ir_pointer_offset` 统一计算偏移地址，步数绝对值超过 100000 直接拒绝。
- 目标校验不变：偏移结果仍然只是地址值，解引用/下标写入时统一交给
  `ct_ir_pointer_target` 按存活帧（局部槽 + 帧拥有聚合元素块）逐类型匹配解析，
  越界地址自然被拒绝，不会访问帧外内存。
- 下标复用：`ct_ir_index_place` 增加指针基址分支，返回 `place.direct`；
  读路径（`ct_ir_index_read`）与写路径（`ct_ir_lvalue` → STORE 的 direct 分支）
  因此同时支持 `p[i]` 读取与写入。
- 分支顺序：typed 执行器的整数二元分支会截获 `i + p`（左操作数是整数），
  因此指针算术分支必须排在整数分支之前，且只匹配 `+`/`-`，
  指针比较仍走 `==`/`!=` 分支。

## 顺带修复的既有缺陷

- 前端 `i + p` 结果类型漏设：`sem_binop` 的「整数 + 指针」分支只发码不设
  `lhs.type_id`，导致 `let q *T = 1 + p;` 报「不能把非指针值赋给指针」。
- `*out = *place.direct;` 这类「解引用赋给解引用」的整体结构体赋值会让编译器
  在编译期执行时段错误；`ct_ir_index_read` 改为逐字段复制规避。
  后端对该形态的缺陷已记入 `docs/todo.md`。

## 边界

- 仍拒绝：指针之间的算术（`p + q`，前端即报「指针/数组不参与该运算」）、
  指针乘除、指针比较大小、指针返回逃逸。
- 偏移只在解引用/下标写入时校验，因此「算出越界地址但不访问」是允许的常数值行为。

## 实施步骤与验收

1. `ct_ir_pointer_offset` / `ct_ir_pointer_slot`；`ct_ir_index_place` 指针基址分支；
   `ct_ir_index_read` 与 `ct_ir_lvalue` 的 direct 处理；typed 执行器指针算术分支。
2. 用例：run/138（`p + i`、`i + p`、`p - i`、`p[i]` 读写、指针比较、跨帧形参遍历）、
   fail/140（越界地址解引用被拒）、fail/141（指针 + 指针被拒）。
3. `comptimelocal` 增加跨源文件指针下标累加与指针算术断言。
4. 验证 `make`、`make test`、`make selfhost-native`；全绿后滚种子。

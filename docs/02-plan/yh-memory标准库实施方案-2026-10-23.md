# yh memory 标准库实施方案

**目标：** 按 Zig `std.mem.Allocator`/`std.heap` 的能力分层，在 `libs/memory`
固化现有堆 API，并按序交付 `reallocate`、`FixedBuffer`、增强 `Arena`、
基于 Arena 的 `FixedPool`，最后按触发条件评估统一 `Allocator` 接口。
设计见 [memory 标准库设计](../03-design/yh-memory标准库设计-2026-10-23.md)。

**架构：** 普通 yh 模块 `libs/memory`，不新增依赖。`alloc`/`release`/`copy`/
`reallocate` 直接使用 prelude 堆；`FixedBuffer` 在调用方缓冲区上分配；
`Arena` 的块取自 prelude（M5 可换 child `Allocator`）；`FixedPool` 由内部
Arena + 空闲链组成。不修改 `docs/yh.g4`，不新增 prelude 内建，不改
`string`/`toml`/编译器。

**技术：** 现有 yh/LLVM、标准库项目 fixture、Python runner（参考
`tests/string/run.py`）、失败注入（参考 `STRING_TEST_FAIL_AFTER`）。
不引入测试框架；M5 的函数指针适配器沿用 `libs/cli` 的回调字段模式。

日期：2026-10-23（第二版）。状态：**设计完成，未实施**。API 与语义以设计
为准；本文只定义切片顺序、文件、测试与验收。

顺序为 `M0 → M1 → M2 → M3 → M4`；`M5` 在触发条件成立时插入，`M6` 按需。
一次只完成一个可验收切片；每个切片：新增 `.yh` 断言 → 确认失败原因 →
最小实现 → 定向用例通过 → `make` → 更新设计/本文/`docs/finish.md`。
最后一律执行本平台 `make test` 与 `make selfhost-native`，全绿后才允许

## 2. M0：基线固化（不改行为）

**阅读：** 设计 §3/§7.1；[`libs/memory/memory.yh`](../../libs/memory/memory.yh)、
[`compiler/builtin/prelude.yh`](../../compiler/builtin/prelude.yh) 56–72 行、
[`compiler/backend/llvm_runtime.yh`](../../compiler/backend/llvm_runtime.yh)
167–190 行、[`llvm_apple_runtime.yh`](../../compiler/backend/llvm_apple_runtime.yh)
23–40 行。

**测试先行：** 新建 `memoryheap` fixture，覆盖：

- `alloc(0)` 返回非 0；`alloc(1)` 可写、`copy` 后内容正确；
- `release(0)` 不崩溃；
- 最大 `u64` 请求返回 0（prelude 的溢出检查）；
- `alloc(1)` 地址 `% 16 == 0`。

先确认这些断言在当前实现下全绿（M0 是**固化**而非修复）；若与设计不符，
先记录差异再决定改设计还是改实现。

**验收：** `memoryheap` 在 O0/O2 通过；`make test` 通过；无源码改动。

## 3. M1：`reallocate` 与堆语义

**实现：** 按设计 §7.2：

1. `data == 0` → `alloc(new_size)`（优先于下一行）；
2. `data != 0 && new_size == 0` → `release(data)`，返回 0；
3. 否则 `fresh = alloc(new_size)`；失败直接返回 0（旧块保留）；
4. `copy(fresh, data, old_size < new_size ? old_size : new_size)`；
5. `release(data)`；返回 `fresh`。

不读 prelude 头部；`old_size` 是调用方契约。不新增 heap 的 `resize`/`remap`
（设计 §7.3）。

**测试（扩 `memoryheap`）：**

- 增长：写满旧块 → `reallocate` → 旧内容保留、新区域可写；
- 缩小：只保留前 `new_size` 字节；
- `new_size == 0`：返回 0，旧块已释放；
- 失败：`reallocate(ptr, n, 最大 u64)` 返回 0，旧指针内容仍可读；
- `data == 0`：等价 `alloc`。

**文档：** 更新 `libs/memory/README.md`，写清三个兼容 API、`reallocate` 的
`old_size` 要求、0 长度/失败/对齐/重叠边界，以及 heap 不支持 `resize`/`remap`
的原因。

**验收：** `memoryheap` O0/O2；`make test`；`libsbase` 仍通过。

## 4. M2：FixedBuffer

**实现（`10_fixed_buffer.yh`）：**

1. `fixed_buffer_init(buffer, capacity)`：零值无效；
2. `fixed_buffer_alloc_impl`：按绝对地址对齐、容量检查、溢出检查；
3. `fixed_buffer_resize`：最近分配（`data + old_size == buffer + used`）原地
   调整；非最近只允许缩小返回 1；其余 0；
4. `fixed_buffer_free`：最近分配回收 `byte_count`；否则 0；
5. `fixed_buffer_reset`：`used = 0`；
6. `fixed_buffer_owns`：地址范围检查；`capacity`/`used` 查询。

**测试（`memoryfixedbuffer`）：**

- 16/64/256 对齐；
- 空间不足返回 0，`used` 不变；
- 最近分配 resize 扩大/缩小、free 回收；
- 非最近 free 返回 0；非最近缩小 resize 返回 1 但不回收；
- `reset` 后从缓冲区起点复用；
- `owns` 边界（起点、末尾前、末尾、外部）；
- 0 长度返回非空且不推进；
- `capacity == 0`/`buffer == 0` 的零值行为。

**验收：** O0/O2；`make test`；无系统调用（该 fixture 只依赖内存操作）。

## 5. M3：Arena

**实现（`20_arena.yh`）：**

1. 私有 `arena_block`（`next`/`size`/`used`），payload 16 对齐；
2. `arena_init`：0 用默认 64 KiB，非零向上取整到 16；返回空 Arena；
3. `arena_alloc_impl`：绝对地址对齐 → 容量判断 → 必要时新建块；新块大小取
   `block_size`、当前块 1.5 倍、需求三者的较大值；所有加法/对齐溢出检查；
4. `arena_resize`/`arena_free`：最近分配语义（`data + size == payload + used`）；
   非最近缩小返回 1、扩大/回收返回 0；
5. `arena_reset(free_all/retain)`：`free_all` 释放全部；`retain` 保留 `head`
   （最新块）并释放其余，`used = 0`；
6. `arena_release`：释放全部，`head = 0`；
7. `arena_capacity`：遍历块累加 payload 容量；
8. `MEMORY_TEST_FAIL_AFTER` 注入点在块映射函数内，产品源码保持 `-1`。

**测试（`memoryarena`）：**

- 同块连续分配地址递增、16 对齐；
- 请求超过块容量：跨块、两段内容互不覆盖；
- 几何增长：第二块容量大于第一块；
- `arena_alloc_aligned(64/256)` 地址对齐；`alignment=0`/`3` 返回 0；
- `arena_alloc(0)` 非 0；
- 超大请求（最大 u64）返回 0，已有内容仍可读；
- 最近分配 resize/free；非最近 free 返回 0；
- `reset(retain)` 保留最新块并复用；`reset(free_all)` 释放全部；
- `arena_capacity` 在分配前后变化；
- `arena_release` 后可再次分配。

**注入（`run.py --inject`）：**

复制 `libs/` 到 workdir，把 `MEMORY_TEST_FAIL_AFTER` 依次设为 `0..3`，
构建并运行 `memoryarena` 的失败场景；要求：映射失败时返回 0、旧块内容仍
正确、进程不崩溃。产品源码不改。

**验收：** 普通组 + 注入组全绿；O0/O2；`make test`、`make selfhost-native`。

## 6. M4：FixedPool

**实现（`30_pool.yh`）：**

1. 内部 `Arena`（默认块大小）承载块，空闲链存在块首 8 字节；
2. `pool_init`/`pool_init_aligned`：`block_size` 对齐到 `max(16, alignment)`；
   零值拒绝；
3. `pool_reserve`：循环 `arena_alloc_aligned` 并把块压入空闲链；失败返回 0，
   已分配块保留；
4. `pool_alloc`：先弹空闲链，空则从 Arena 分配；
5. `pool_free`：压链；空指针/零值池 no-op；
6. `pool_reset(mode)`：清空空闲链并 `arena_reset`；
7. `pool_release`：`arena_release`，保留 `block_size`/`alignment`。

**测试（`memorypool`）：**

- `block_size=1` 向上取整到 16；
- `pool_reserve(8)` 成功后连续分配 8 块；另分配超过 Arena 单块容量的块数
  （例如 2000 个 48 字节块），验证跨 Arena 块；
- `pool_free` 后同块复用（地址比较用 `to_type(u64)`）；
- `reset(retain)` 后全部块可再分配；`reset(free_all)` 同样可用；
- `release` 后可再次 `pool_alloc`；
- `block_size=0`/非法 alignment 拒绝；
- `pool_alloc` 映射失败注入返回 0，已发放块仍可用；
- `pool_reserve(0)` 返回 1。

**验收：** 同 M3；若迁移消费者，另加对应用例并保持其原有失败注入。

## 7. M5：`Allocator` 统一接口（可选）

**触发条件（任一）：**

- 需要让多个容器/模块共享同一分配器接口；
- 需要 `Arena` 用 `FixedBuffer` 作 child（固定缓冲区 + 批量分配）；
- 需要 `StackFallback`（M6）。

没有触发条件时，保留设计契约、不实现，并在 `docs/todo.md` 记录“按需”。

**实现（`40_allocator.yh`）：**

1. `AllocFn`/`ResizeFn`/`RemapFn`/`FreeFn` 类型别名与 `Allocator` 结构；
2. `allocator_valid/alloc/alloc_aligned/resize/remap/free/reallocate` 包装；
3. `heap_allocator`：alloc/release 包装；resize/remap 恒失败；alignment >16
   返回 0；
4. `arena_allocator`/`fixed_buffer_allocator`：转发到具体 API；
5. `pool_allocator`：固定块；`failing_allocator`：分配恒失败；
6. `allocator_reallocate` 按 `resize → remap → alloc+copy+free` 组合；
7. 所有适配器函数只构造值，不分配内存。

**测试（`memoryallocator`）：**

- `allocator_valid`；failing 分配返回 0；
- heap 适配器的 alloc/free；alignment 8/16 成功，64 返回 0；
- arena 适配器的 alloc/resize/free 最近分配；非最近 free 后内容仍可读；
- fixed_buffer 适配器；
- `allocator_reallocate` 增长/缩小/失败保留旧块；
- 跨适配器 free 不测试（UB）。

**验收：** O0/O2；若 M5 未触发，不创建 fixture，设计状态保持“契约已定、未实现”。

## 8. M6：后置候选（按需求）

不在首版承诺。有真实需求时逐项设计：

- heap 上的任意对齐分配（`Allocator` 适配器内的过分配 + 原始指针头部）；
- 简化 `DebugAllocator`（魔数/泄漏/野指针；重复释放受 prelude 立即 `munmap`
  限制）；
- `StackFallbackAllocator`（依赖 M5 + `FixedBuffer`）；
- `PageAllocator` 适配器（依赖 `sys`；核心 `memory` 不引入该依赖）；
- 统计/上限（`total_requested_bytes`、`requested_memory_limit`）；
- `ThreadSafeAllocator`（等 J4 的 mutex/原子原语）。

每项都必须先回答“谁消费、验收断言是什么”，否则保持不做。

## 9. 风险与回退

| 风险 | 应对 |
| --- | --- |
| Arena 块来自 prelude，每次块映射仍是一次 `mmap` | 几何增长减少块数；用映射计数对比“逐个 alloc”与 Arena，记录但不设固定门 |
| 1.5 倍增长导致峰值内存偏高 | 默认块 64 KiB 可配；基准后调整，不改变 API |
| 默认 64 KiB 在 16 KiB 页/64 KiB 页平台表现不同 | 块大小可配；页内浪费只影响 RSS/虚拟地址，不影响正确性 |
| `old_size`/`size` 传错会越界 | 文档与测试显式覆盖；不尝试从头部猜长度 |
| 非最近 `free` 为 no-op，调用方误以为已释放 | README 与 doc.yh 标注 LIFO 语义；测试覆盖返回 0 |
| 非最近 `resize` 缩小返回 1 但不回收 | 与 Zig 一致；文档说明空间在 reset 前不复用 |
| 误用（双释放/跨池 free）无法检测 | 文档列 UB；`fixed_buffer_owns` 只作断言；DebugAllocator 后置 |
| M5 vtable 间接调用与 heap 对齐限制 | 仅在触发条件成立后实施；heap 适配器 >16 对齐全返回 0 |
| 失败注入依赖源码文本改写 | 沿用 `string` 的既有模式，常量唯一、产品值 `-1`；注入脚本找不到常量即失败 |

回退：每个切片独立；M1 只加函数，M2/M3/M4 只加新文件与 fixture，M5 只加
新文件；回退即删除对应文件与登记，不影响现有三函数与其它标准库模块。

# yh fmt 标准库设计

日期：2026-10-23。状态：**R0–R1 已实施（2026-10-24）；R2–R3 与语言插值待实施**。
用户决定：字符串格式化采用 V 风格插值，插值结果类型 `string.String`。
本文件把 `libs/fmt` 定义为**插值的运行时格式化引擎**与值打印 API；语言层
插值见[字符串插值设计](yh-字符串插值设计-2026-10-23.md)，分期见
[实施方案](../02-plan/yh-fmt标准库实施方案-2026-10-23.md)。

**改版说明：** 2026-10-23 前一版按 Go `fmt` 的 `%` 格式串设计（Printf/
Sprintf/动词/flags），已被本版取代：字符串格式化不走 `%` 格式串，而走
`${expr:spec}` 插值；fmt 不再提供 `printf/sprintf/appendf`。

## 1. 范围

首版交付：

- 插值运行时：`Value`、构造器、`append_text`、`append_value`；
- 显式格式化：`render(value, spec)`；
- 打印：`print`/`println`/`fprint`/`fprintln`（值列表，V 式拼接）；
- 字符串：`sprint`/`sprintln`；
- 插值结果的借用构造器 `of_string(*string.String)`。

首版不做：

- `printf/sprintf/appendf` 与 `%` 格式串：与 V 式插值重复，且 yh 的
  字符串格式化已由插值承担；
- `Scan`/`Sscan`/`Fscan`：需要通用目标写入与运行时类型信息，另立项；
- `Errorf`：没有 `error` 接口与错误包装；
- 结构体/数组/切片/映射自动打印：没有反射；后续可另加自定义回调；
- 运行时宽度/精度 `(expr)`、`r/R` 重复：V 子集之外，后续评估。

## 2. 与语言插值的关系

编译器把

```yh
"x=${value:04d}"
```

降级为对 fmt 的普通模块调用（细节见插值设计 §5）。fmt 是普通
`libs/fmt` 模块，编译器不内嵌其实现，也不在 fmt 不可用时静默退化。
首版要求源码 `import fmt` 与 `import string`；缺失时报明确错误，
不自动导入。

编译器契约（名字与签名稳定；修改需同步编译器）：

```yh
pub fn of_int(value int) Value
pub fn of_i64(value i64) Value
pub fn of_u64(value u64) Value
pub fn of_f64(value f64) Value
pub fn of_bool(value bool) Value
pub fn of_str(text string.View) Value
pub fn of_cstr(text *char) Value
pub fn of_string(text *string.String) Value

pub fn append_text(target *string.String, text string.View) Status
pub fn append_value(target *string.String, value Value, spec string.View) Status
```

`append_*` 成功返回 `status_ok`，其余成员为失败分类。插值降级在任一步失败
时释放临时串并返回零句柄（用户确认的“OOM 空串”语义）；`render` 等显式 API
仍返回 `TextResult`，失败可观察。若 I0 探针证明
`fmt.interp(parts ... Part)` 更简单，可替换上述 append 契约，但必须同时
修改插值设计与编译器；首版默认 append 契约。

## 3. 模型

```yh
// Kind 是 Value 的载荷分类；零值 Value 为 kind_invalid（等价 nil）。
pub enum Kind {
    kind_invalid
    kind_int
    kind_uint
    kind_f64
    kind_bool
    kind_str
}

// Value 是不可变的格式化实参；字符串借用 View，不拥有存储。
// 字段公开是语言规则（pub struct 字段一律公开）；布局不是接口，
// 只通过构造器建立值。
pub struct Value {
    kind Kind
    integer i64
    number u64
    real f64
    truth bool
    text string.View
}

// Status 是渲染/追加的失败分类；status_unsupported 表示该类型默认渲染尚未接通。
pub enum Status {
    status_ok
    status_out_of_memory
    status_overflow
    status_invalid_spec
    status_unsupported
    status_other
}

// TextResult 返回独占字符串；失败时 value 为零句柄。
pub struct TextResult {
    status Status
    value string.String
}
```

打印族复用 `os.IoResult`（count + error）。`Status` 不复用
`string.Status`：非法 spec 不是 string 的错误分类，且 fmt 需要明确的
格式化失败边界。

## 4. 公开 API

### 4.1 构造器

| API | 契约 |
| --- | --- |
| `of_int(value int) Value` | 有符号 64 位存储 |
| `of_i64(value i64) Value` | 有符号 64 位存储 |
| `of_u64(value u64) Value` | 无符号，覆盖 u8/u16/u32/u64 |
| `of_f64(value f64) Value` | IEEE binary64 |
| `of_bool(value bool) Value` | `true`/`false` |
| `of_str(text string.View) Value` | 借用字节文本，不复制 |
| `of_cstr(text *char) Value` | NUL 结尾转 View；NULL 视为空串 |
| `of_string(text *string.String) Value` | 借用一个独占字符串（内部 as_view） |
| `kind_of(value Value) Kind` | 读取分类 |

### 4.2 格式化与追加

| API | 契约 |
| --- | --- |
| `render(value Value, spec string.View) TextResult` | 按 V spec 渲染单个值；空 spec 用默认格式 |
| `append_text(target *string.String, text string.View) Status` | 追加字面文本；`status_ok` 成功 |
| `append_value(target *string.String, value Value, spec string.View) Status` | 按 V spec 追加；`status_ok` 成功 |

`render` 供动态 spec 与测试使用；插值降级可直接用 append 系列，避免
中间 `Part` 结构。`append_*` 失败可能已写入前缀，不承诺原子性。

### 4.3 打印与字符串

| API | 契约 |
| --- | --- |
| `print(values ... Value) os.IoResult` | 标准输出，值按 V 规则直接拼接，不加分隔符 |
| `println(values ... Value) os.IoResult` | 同上，末尾追加 `\n`；零实参只输出 `\n` |
| `fprint(fd int, values ... Value) os.IoResult` | 指定 fd |
| `fprintln(fd int, values ... Value) os.IoResult` | 指定 fd + 换行 |
| `sprint(values ... Value) TextResult` | 新建字符串 |
| `sprintln(values ... Value) TextResult` | 新建字符串 + 换行 |

- 与 Go 的 Print 空格规则不同：V 风格直接拼接，不加隐式空格；需要
  空格由插值文本或字面量显式给出。该差异写入 README。
- 打印族先把所有值渲染进一个临时 `String`，再 `io.write_all` 一次写出；
  `count` 为已写字节数，失败时保留进度。构造临时串失败返回
  `os.error_other`（native 0）且 count=0。
- 每个值用空 spec（默认格式）渲染；需要格式说明符时先用插值构造字符串，
  再 `fmt.of_string(&text)`。

## 5. V 格式说明符子集

```text
[flags][width][.precision][type]
```

- flags：`-` 左对齐、`0` 零补齐、`+` 非负显示正号；`-` 优先于 `0`；
  不支持 `#`、空格 flag、`'` 分组（与 V 一致）。
- width：十进制字面量，最小字段宽度；上限 1,048,576。
- precision：`.` + 十进制字面量，仅首版浮点使用；整数忽略；上限
  1,048,576。浮点 `.N` 四舍五入到 N 位并去掉无意义尾零，`.Nf` 保留
  尾零（V 语义）。
- type：`d x X o b f F e E g G s`；省略时整数 `d`、浮点 `g`、字符串 `s`；
  bool 只允许 width/`-`。
- 大写 type 强制大写十六进制/指数；`F` 与 `f` 数值等价。
- 整数：`d` 十进制、`x/X` 十六进制、`o` 八进制、`b` 二进制；负数先
  输出 `-` 再输出绝对值；`i64/u64` 最小值安全。
- 字符串：`s` 输出字节；width 按 UTF-8 标量计，非法字节每个计 1；
  precision 对字符串无效（首版拒绝非浮点 precision 还是忽略，见 §9）。
- 浮点：`f/F` 定点、`e/E` 科学计数、`g/G` 有效数字切换；NaN/±Inf/-0
  按 Go/V 惯例输出 `NaN`、`+Inf`、`-Inf`、`-0`；指数至少两位。
- 非法 spec 由编译器在插值处报错；直接调用 `render`/`append_value` 的
  非法 spec 返回 `status_invalid_spec`，不崩溃、不输出半成品。

## 6. 渲染实现

- 整数取位使用 `u64` 绝对值，缓冲 24 字节；二/八/十六进制按 64 位上限，
  负号与绝对值分开。
- 字符串宽度按 `string.utf8_next` 遍历；非法序列按 1 个 rune 计。
- 浮点首版优先级：
  1. 特殊值、符号、零；
  2. `f/F` 定点（精度 0–17，舍入按目标十进制位）；
  3. `e/E` 科学计数；
  4. `g/G` 有效数字与指数切换；
  5. 默认 `g` 的尾零规则按 V 文档示例锁定。
- 浮点最短往返（Go `%v` 级别）不作为首版目标；V 的 `g` 默认也不等于
  Go 最短表示。实现前用 V 1.x 输出或 V 文档示例建 golden，差额显式
  记录；不宣称为“完全一致”。
- 对齐与补齐在渲染阶段完成：先算字段宽度，再决定左/右补空格或零；
  `+` 号占宽度。
- 直接调用 `render`/`append_value` 时，spec 在运行期解析；编译器插值
  路径已在编译期校验，运行期解析作为防御并覆盖动态 spec 用户。

## 7. 所有权与错误

- `Value` 浅拷贝；`text` 借用源字节，调用期间源必须存活。
- `append_*` 目标由调用方持有；成功的可变操作可使旧 View/C 指针失效
  （沿用 `string`）。
- `append_*` 失败可能留下前缀，不保证原子性；调用方在失败时应释放或
  丢弃目标内容。
- `sprint`/`sprintln`/`render` 失败时释放内部半成品并返回零句柄，调用方
  只释放成功结果。
- 打印族失败保留已写进度；`count` 与 `io.write_all_result` 一致。
- 不引入全局错误状态；失败经返回值或 `Status` 传递。

## 8. 与 V / Go 的差异

1. 需要显式 `import fmt`/`import string`；V 的插值和 `println` 是内建。
2. 没有 GC：插值结果是 `string.String`，必须显式 `release`；V 自动管理。
3. 插值 OOM 返回零句柄且不可观察；V 走 GC/panic。
4. 无反射：结构体/数组/切片不能直接插值；V 的 `str()` 支持更多类型。
5. 首版不做运行时 width/precision、`r/R`、嵌套插值、跨行插值。
6. 没有 `printf` 族与 `%` 格式串；动态格式用 `render`/`append_value`。
7. 没有 `io.Writer` 接口，打印族用 `fd int`。
8. `print` 不加隐式空格（V 式拼接）；Go 的 Print 会加空格。
9. 浮点 `g` 的往返/尾零细节以 V 实测为准，不承诺与 Go `strconv` 相同。
10. 诊断是编译期错误或 `status_invalid_spec`，不做 Go 的 `%!` 文本。

## 9. 待确认

1. 字符串 precision 的首版行为（R1 已定）：整数忽略，字符串/bool 返回
   `status_invalid_spec`；插值编译期同样报错。
2. 浮点 `g`/`.N` 的 V 细节无法从文档完全确定，是否允许以 V 1.x 实测
   为准并记录差额。
3. `print` 的零实参、单实参与分隔规则（本设计：直接拼接）。
4. 是否需要 `fmt.of_string` 之外的 `fmt.release` 包装以减少 `import string`。
5. 是否保留 Go 风格的 `printf/sprintf` 作为动态格式串的次级 API；首版
   建议不做（与插值重复，且需要另一套 `%` 动词实现）。

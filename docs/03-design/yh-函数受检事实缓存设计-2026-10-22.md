# yh 函数受检事实缓存设计（LA3.3）

日期：2026-10-22。性质：LA3 交付 3 的独立设计，**本次不实现跳过函数 check**。
依据 [LA3 实施方案 §10](../02-plan/yh-LLVM架构分阶段实施方案-2026-10-22.md)
与 [RS2 实施修订](../02-plan/yh-RS2-LLVM函数级IR缓存设计.md)。LA3 交付 1–2
（函数级 IR 缓存）已完成；本设计只定义后续“函数级 check 复用”的边界与门。

## 1. 目标与非目标

**目标**：模块环境、布局/ABI 与函数 token 流未变化时，跳过该函数的
`pass 2b` 解析/语义检查与 AST 捕获，直接导入上次的受检事实；未命中函数仍走
现有完整检查。最终 `CheckedModule` 必须与冷编等价，模块 verifier 通过。

**非目标**：

- 不跳过模块头、import、类型/结构体/全局常量/pass 1 声明检查；
- 不缓存编译器进程状态、GenState、文件句柄或旧源码路径；
- 不改变语言规则、诊断规则、ABI 或 IR 表示；
- 不把函数级 check 复用与 IR 复用混成一个缓存；两者共享键但不共享记录；
- 不在本设计内启动 LA4/LA5。

## 2. 当前边界与缺口

当前前端是模块级流水线：

```text
pass1 声明/类型/签名
  → pass2a 全局常量与 CT 布局
  → pass2b 逐函数解析/语义检查/AST 捕获
  → CheckedModule 快照
  → check.verify_checked_module
  → ast.lower_module_cached（LA3.2 已可复用函数 IR）
```

`AstFunctionContext` 已经按函数记录 expr/stmt/edge/binding 的 arena 范围，
是函数级 check 复用的天然切片边界；但 `CheckedStorage` 的行 ID 是模块全局
下标，函数切片内部大量 `child0/child1/next/binding_row/type_id/sym_id`
引用这些行，不能把旧行号直接挂到新模块。

LA3.2 只跳过 lowering；`parse_source_fns` 仍对每个函数执行完整 pass2b。
因此单函数修改时，前端 check 成本没有下降。

## 3. 受检事实单元

新增 `ast/checked_function_cache.yh`（纯序列化/重绑定，不读 GenState）：
一个受检函数单元包含：

| 区块 | 内容 | 说明 |
| --- | --- | --- |
| header | schema/版本/目标/环境键/函数名/文件路径/token 范围 | 与 IR 函数缓存同源键 |
| function | `CheckedFunction` 的范围与 body 根（局部 ID） | 导入时重绑到当前 arena |
| expr | `AstExpr` 行（kind/op/type_id/child0/child1/file_id/token/sym_*） | 局部 ID |
| stmt | `AstStmt` 行（kind/op/first/first_expr/body/child 链） | 局部 ID |
| edge | `AstStmtExpr` 行（expr_id/next） | 局部 ID |
| binding | `AstBinding` 行（id/sym/type/owner/name_token/is_param/next） | 局部 ID |
| template | 本函数新增的 `AstComptimeFor`（若有） | 初期可排除含模板函数 |
| sources | 文件路径 + token 下标，不写字节偏移 | 命中后按当前 token 表重建 |
| facts | 函数签名符号/ABI、布局版本、关键类型 ID | 只读校验 |

**不包含**：模块类型/字段/签名表（由 prepare 重建）、模块符号表（由 declare
重建）、全局常量/静态数据（由 prepare 重建）、其他函数体、源码正文。

### 3.1 局部 ID 与重绑定

序列化时把切片内的行号改成 `[0,count)` 局部下标；导入时：

1. 在当前 arena 末尾分配同规模行，得到 `base`；
2. 所有行号字段 `local + base`；
3. `type_id/sym_id` 保持模块级 ID，但导入前用当前签名/类型表核对；
4. `file_id` 按当前文件路径映射；`token` 保持文件内 token 下标；
5. `owner_decl/decl_row` 按当前 `AstDecl` 查找；
6. 导入后调用现有 `check.verify_module` 与 `check.verify_checked_module`
   双重校验；任一失败按 miss 重建，不能把半成品交给 lowering。

### 3.2 诊断位置

token 下标在“注释/空行/前置声明”变化下保持稳定；命中后诊断用当前 token
的 `line/col`，不写旧字节偏移或旧行号。若当前文件 token 表无法解析该下标，
记录按 miss 处理。

## 4. 键与依赖

函数 check 键与 IR 函数键共享以下事实（避免两套规范化分叉）：

- schema/格式版本；
- 模块环境键（依赖接口、目标、O 级别、编译器指纹、桥版本）；
- 目标/指针位宽/布局版本/ABI；
- 源路径；
- 类型/字段/签名布局哈希；
- 本模块非函数声明 token 流；
- 本函数声明+body token 流。

**不进入键**：其他函数体、注释/空白、瞬时 arena ID、字符串标签。

依赖规则：

- 被调函数签名变化 → 模块接口/签名布局哈希变化 → 全部函数 miss；
- 私有结构体布局变化 → 布局哈希变化 → 全部函数 miss；
- 全局/常量初始化变化 → 非函数声明 token 流变化 → 全部函数 miss；
- 单函数 body 变化 → 只该函数 miss；
- 注释/空行变化 → 全 hit，但模块对象键仍变化，worker 仍运行；
- CT 函数正文变化 → `.s.ct` 环境键变化 → 全部 miss（保守）。

## 5. 跳过协议

在 `module_worker` 的 pass2b 之前：

1. 装载 check 缓存索引（目录 `<build>/fcache/<tag>/`，与 IR 缓存分开）；
2. 对每个函数用 pass1 后的签名/token/环境事实算键；
3. `parse_indexed_decls(mode=2)` 逐声明时：
   - 键命中且记录通过头部/目标/版本/函数名校验 → 导入受检切片，跳过
     `sem_fn_begin`/参数声明/`parse_block`/`sem_fn_end` 与 AST 捕获；
   - 键未命中/记录损坏/导入手失败 → 走现有完整解析检查；
4. 模块成功结束后才原子提交本轮新记录与索引；模块失败不提交；
5. 命中函数不写新记录；未命中函数在检查成功后 capture。

**初期安全子集**：只跳过普通运行期函数；以下函数不跳过：

- `@[comptime]` 函数（影响全局布局/CT 展开）；
- 含 `$if/$for` 模板或会改写模块级模板目录的函数；
- `inline`/`extern`/`noreturn` 属性组合尚未验证的函数；
- 含模块级副作用登记（布局请求、内联请求、静态数据新增）的函数。

这些排除是保守策略，不是永久规则；扩展前必须逐项补依赖。

## 6. 失败与一致性

- 记录损坏/版本不符/目标不符/函数签名不符/切片范围非法 → 按 miss 完整检查；
- 导入后 `verify_module` 或 `verify_checked_module` 失败 → 不能静默 miss
  继续使用已写入的半成品；必须先回滚本次 arena 追加再完整检查；
- 当前模块 verifier 失败且无法归因到缓存 → 停止构建，不把内部错误当 miss；
- 只有模块完整成功后提交 check 缓存；失败构建不得留下可命中的新记录；
- 缓存写失败只报告，不改变构建结果。

## 7. 统计

新增字段（或复用现有统计并明确命名）：

- `check_cache_hits` / `check_cache_misses`：函数 check 命中/未命中；
- `check_skipped_functions`：实际未执行 pass2b 的函数数；
- `checked_functions`：实际检查的函数数；
- `ir_cache_hits` / `ir_cache_misses` / `ir_lowered` 继续表示 IR 侧。

统计只在真正跳过/执行后累计；不能把“载入了记录”算作命中。

## 8. 门与实施切片

**C0 设计门（本文件）**：接口、键、失败协议评审通过。

**C1 键与测量（无行为变化）**：在完整检查后计算 check 键，与 IR 缓存键
逐函数比对；统计候选命中数，不跳过检查。验证键对注释/单函数/接口变化的
稳定性。

**C2 切片往返（离线探针）**：✅ 2026-10-22 已完成。新增
`ast/module_snapshot_check_slice.yh`：从 `CheckedModule` 捕获 expr/stmt/edge/
binding 局部切片，清空 AST arena 后导入并重建快照，两次 lowering 的模块身份
一致；llvmlower 的 `checkcache` 探针覆盖标量/字符串/全局/切片/聚合/goto。

**C3 生产跳过（安全子集）**：只对普通非 CT 函数启用；矩阵：

- 冷编 0 hit / N miss；
- 仅注释/空行：N hit / 0 miss；
- 改一个函数体：N-1 hit / 1 miss，且 lowering/IR 仍正确；
- 改签名/私有布局/全局常量：全部 miss；
- 损坏一条记录：只重建该记录；
- 含 CT/inline/extern 的函数按排除规则保持完整检查；
- 全模块 verifier、运行语料、自举固定点通过。

**C4 扩展**：逐项放开 CT/inline/模板函数，必须补充对应依赖与失败用例。

## 9. 主要风险

1. **arena 重绑定**：`child0/child1/next/binding_row` 的局部/全局混用是最容易
   产生悬空引用的地方；先用 C2 离线比较，再接生产。
2. **模块级副作用**：函数检查可能登记模板、布局请求或内联事实；未审计前
   只用安全子集。
3. **CT 展开**：`$if/$for` 展开结果已在 AST/IR，但检查阶段可能依赖模块级
   CT 状态；CT 函数与含模板函数先排除。
4. **诊断位置**：必须保存 token 下标而非字节偏移；导入后统一重建。
5. **部分提交**：跳过/导入失败会留下 arena 行；必须先回滚再完整检查。
6. **缓存键分叉**：check 键必须复用 IR 键的规范化实现，不能复制一份易漂移
   的哈希逻辑。

## 10. 结论

LA3.3 的可行路径是“函数级受检 AST 切片 + 局部 ID 重绑定 + 保守安全子集”，
不是简单跳过 `parse_block`。在 C1/C2 证据齐全前，生产构建继续执行完整
前端检查；J1/RS2 的完整目标保持未完成。本设计不改变当前 LA3.1/3.2 的行为。

## 11. C3 实施记录（2026-10-22，已启用）

C3 已按方案 A 启用：

- **session ready 标记**：worker 先写 `.s.ct`、再写 `.s.i`、最后写 `ready`；
  父调度器只把 ready 视为接口就绪，消费者只读同一 session 的 `.s.i/.s.ct`。
- **CT 哈希门**：依赖处于早期状态时，比较 session `.s.ct` 与持久 `.s.ct`；
  CT 不同/首次出现 CT 时等待依赖完整提交，CT 相同或没有 CT 时才允许提前启动。
- **函数键约束**：pass2b 前的 check 键除环境/布局/token 外，还混入源码级
  `const` 的 `cval/flags/const_ready`；依赖 CT 变化导致的 `ANSWER` 折叠值变化
  会直接让导入方函数键失效，不再依赖接口路径时序。
- **内存上限**：单函数切片 >1 MiB 跳过；单模块 check 记录装载/捕获总预算
  16 MiB，避免编译器自举的超大函数把 worker 内存峰值拉爆。
- **启用**：`module_worker` 正常装载/提交 check 缓存；`--stats` 输出真实的
  `check_cache_hits`/`check_cache_misses`/`check_skipped`。

验收矩阵（`tests/selfhost/llvm-function-cache.py`）：

- 冷编 check 0/4/0；注释 4/0/4；单函数 3/1/3；插入第 5 个 4/1/4；
  损坏记录 4/1/4；接口变化 0/5/0；重建后 5/0/5。
- `ct5b-transitive-body-invalidates-importer` 在 C3 启用下通过；

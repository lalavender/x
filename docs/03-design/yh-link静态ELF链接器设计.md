# yh_link 静态 ELF 链接器设计

- 状态：实施中（TC4 主体已落地并通过验收门，集成到编译器待后续任务）
- 项目位置：`link/`（独立 yh 多模块项目，产物 `link/.build/yh_link`）
- 入口命令：`yh_link link [-o out] [--entry SYM] [--max-page-size N] [--verbose] in1.o ...`
- 平台：Linux/aarch64 优先（与仓库平台顺序一致），非 Linux 目标暂不实现
- 相关文档：`docs/02-plan/yh-link静态ELF链接器实施方案.md`（任务分解）、
  `docs/adr/`、`asm/README.md`（汇编器侧契约）

## 1. 范围与定位

### 1.1 做什么

把若干 **ELF64 `ET_REL`（AArch64）可重定位对象**链接成一个**静态、非 PIE 的
`ET_EXEC` 可执行文件**，纯用户态、不依赖任何外部链接器：

- 读取与校验输入对象（ELF 头、节头、符号表、RELA 重定位表）；
- 合并同名的内容节，按目标 ABI 生成三个 `PT_LOAD` 段（RX / R / RW）；
- 解析符号：跨对象定义/引用、重复定义检测、未定义引用检测；
- 应用 AArch64 静态重定位白名单（含 GOT 类）；
- 输出合法的 ELF64 可执行映像，含节头表、`.symtab`/`.strtab`、`.shstrtab`。

### 1.2 不做什么（首版明确排除）

| 排除项 | 原因 |
| --- | --- |
| 动态链接（`PT_INTERP`/`PT_DYNAMIC`/`.dynsym`） | 静态链接优先，动态是独立任务 |
| PIE / 共享库（`ET_DYN`、`-shared`） | 需要 GOT/PLT 与自举重定位，收益低 |
| TLS、弱符号、COMMON、符号可见性 | 与静态单映像语义冲突，遇到即**报错**而非静默处理 |
| 链接脚本、节排序参数、`--gc-sections` | 首版用固定布局，够用且可预测 |
| 跳板（thunk）：超出 ±128 MiB 的分支 | 首版直接报错；真需要时再加 |
| 归档库（`.a`）、`-l` 搜索路径 | 只接受显式列出的 `.o` 文件 |
| 内置启动代码（`_start` 的 `argc/argv` 处理） | 链接器不"发明"代码；由编译器的运行时提供 |
| 反汇编、映射符号（`$x`/`$d`）语义 | 链接器不做反汇编 |

### 1.3 与 `asm/`、`compiler/` 的关系（关键约束）

用户明确要求 **link 与 asm 解耦合、当前独立开发**，因此：

- `link/` **不 import** `asm/` 的任何模块，也不在编译期依赖它；
- 两者只通过 **ELF `ET_REL` 对象**这一份公开格式通信；
- 验收门通过**命令行**调用 `yh_asm` 产出对象（`link/tests/link_accept.py`），
  不 import 汇编器的 Python 模块；
- `compiler/` 当前**不做任何改动**：不接 `--toolchain=self`，不改 driver，
  不动 `Makefile` 的 `all`/`test` 目标。

> 为什么不把产物放到仓库根 `yh_link`：编译器现在按 `yh_link` 这个名字发现
> **汇编器**（`compiler/cmd/link_cache.yh` 的 `mb_asm_tool` 会调用
> `yh_link asm -t ... -o ...`）。真链接器一旦占用该名字，现有 `make` 会立刻
> 坏掉。集成顺序必须是「先把编译器的工具查找改成 `yh_asm`，再把 `yh_link`
> 指向真链接器」，见实施方案的集成任务。

## 2. 目标 ABI 与映像形态

### 2.1 目标规格（`obj.TargetSpec`）

| 项 | 值 | 说明 |
| --- | --- | --- |
| 机器 | `EM_AARCH64`(183) | 只做 AArch64 |
| 类型 | `ET_EXEC`(2) | 非 PIE |
| 镜像基址 | `0x400000` | 与 LLVM lld / GNU ld 的 `-static -nostdlib` 同量级 |
| 头部预留 | `0x10000` | ELF 头 + 程序头所在区，按页向上取整后作为文件起点 |
| 页对齐 | `--max-page-size`，默认 65536，最小 4096，必须 2 的幂 | 决定 `p_align` 与段起始 |
| 入口符号 | `--entry`，默认 `_start` | 必须存在、已定义、且落在可执行节 |

`p_align` 取「目标最大页大小」而不是运行内核的实际页大小，是 ELF 的常规做法
（GNU ld 的 `-z max-page-size` 同义）：产物在 4 KiB 与 64 KiB 页内核上都能装载。

### 2.2 三个 `PT_LOAD` 段

| 段 | 权限 | 内容 | 文件尺寸 |
| --- | --- | --- | --- |
| `SEG_RX` | `R+X` | `.text` | `.text` 长度 |
| `SEG_RO` | `R` | `.got`（若有）+ `.rodata` | 两者之和 |
| `SEG_RW` | `R+W` | `.data`，后随 `.bss`（`NOBITS`，只涨 `memsz`） | `.data` 长度 |

硬约束（`ew_verify` 与验收门都逐条断言）：

1. `p_filesz <= p_memsz`；
2. `p_offset ≡ p_vaddr (mod p_align)`；
3. **段起始虚拟地址页对齐**；
4. RW 段不带可执行权限（`PF_X` 不置位）；
5. 入口地址落在 `.text` 范围内。

> 第 3 条是实测踩出来的：早期版本让段起点紧贴上一段末尾（例如 R 段落在
> `0x401014`），同余条件满足、`readelf` 看着也正常，但在 qemu-user/binfmt 下
> 一访存就段错误。改成「每段虚拟地址按页向上取整、文件偏移由虚拟地址反推」
> 之后通过。反推公式：`off = vaddr − delta`，
> `delta = IMG_BASE − 头部预留按页取整`。

### 2.3 输出节与节头表

输出节头表是**变长**的：`.got` 只在实际用到 GOT 类重定位时才出现。

| 无 `.got` | 有 `.got` | 节 |
| --- | --- | --- |
| 0 | 0 | `NULL` |
| 1 | 1 | `.text`（`PROGBITS`，`AX`） |
| 2 | 2 | `.rodata`（`PROGBITS`，`A`） |
| 3 | 3 | `.data`（`PROGBITS`，`AW`） |
| 4 | 4 | `.bss`（`NOBITS`，`AW`） |
| — | 5 | `.got`（`PROGBITS`，`A`） |
| 5 | 6 | `.strtab` |
| 6 | 7 | `.symtab`（`sh_link` → `.strtab`） |
| 7 | 8 | `.shstrtab`（`e_shstrndx` 指向它） |

`.symtab` 保留全部有定义的符号（本地在前、全局在后，`sh_info` = 首个全局
符号下标），便于 `readelf`/`objdump` 与差分验收使用；`e_shstrndx` 与
`.symtab.sh_link` 必须指向**真实下标**，否则外部工具读节名/符号名是乱码
（早期硬编码常量就踩过这个坑，见 §7）。

## 3. 模块划分

```
link/src/
  main/main.yh        命令行入口：参数解析、读入、调用、写出、退出码
  obj/10_bytes.yh     字节/位原语、缓冲、字符串池、小端读写、整数转字符串
  obj/20_model.yh     全部常量与数据结构、LinkCtx、全局符号表、诊断
  obj/21_state.yh     （占位）
  elf/30_read.yh      读取与校验输入对象（含拒绝路径）
  elf/40_symtab.yh    符号收集、引用绑定、未定义诊断、解析与定址
  elf/50_layout.yh    节合并、GOT 分配、段布局、入口查找、布局报告
  elf/60_reloc.yh     重定位白名单与会话（表单/位段/分支/GOT）
  elf/70_write.yh     输出映像：头、程序头、段、符号表、节头表、自检
  link/80_link.yh     链接主流程（阶段编排）与阶段名
  selftest/80_selftest.yh  自检：算子原语、拒绝路径、单对象、多对象
```

设计要点：

- **单向依赖**：`main → link → elf → obj`，无环、无跨层回调；
- `obj` 层不依赖任何其他模块，因此可以被 `elf`/`selftest` 自由使用；
- 链接器的**所有**地址计算都在 `obj` 的取位原语上做（见 §6）。

## 4. 链接流程

`link.li_link` 按固定阶段推进，每个阶段入口记录阶段名
（`li_stage_set`）。失败时若一条诊断都没打出来，`main` 会补一条带阶段名的
「内部错误」——静默失败是最难查的一类问题。

```
1  读取对象        er_read_object    逐份校验 ELF 头/节头/符号表/RELA
2  全局符号收集    st_collect        建全局名表（哈希）、查重复强定义
3  引用位置绑定    st_bind_refs      检查未定义局部符号、记录首个引用点
4  未定义检查      st_report_undef   一次报全所有未定义强引用
5  符号分类        st_resolve        未定义/节内定义/绝对；全局按名字对齐首定义
6  布局            ly_build
    6a  GOT 分配   ly_alloc_got      按 (符号, addend) 复用槽位，补零占位
    6b  节合并     ly_merge_sections 按 对象序 × 节序 追加，记录每节 out_off
    6c  节偏移绑定 ly_bind_sym_offsets 把输入节 out_off 记到符号
    6d  段布局     ly_place_segments 页对齐的段基址 + 由基址反推文件偏移
    6e  符号定址   st_finalize       基址 + 节内偏移(out_off) + 符号偏移
    6f  GOT 回填   ly_fill_got       槽内容 = S + A
    6g  入口查找   ly_find_entry     入口必须已定义且在 .text
7  重定位          rl_alloc_bitmap / rl_apply_all
8  写出映像        ew_write_image    头 → 程序头 → 段 → 符号表 → 节头表 → 自检
```

### 4.1 符号定址（最容易错的一步）

符号的 `st_value` 是**节内偏移**，最终地址必须是三项之和：

```
最终地址 = 输出节基址 + 本输入节在输出节内的偏移(out_off) + 符号节内偏移
```

漏掉中间一项的后果：不同对象里所有符号都指向输出节开头。实测表现是跨对象
`bl` 跳到调用者自己，运行期死循环。中间项由 `ly_merge_sections` 记录、
`ly_bind_sym_offsets` 绑定、`st_finalize` 使用；自检的「多对象合并」组按
`imm26` 精确判定这一项，改动回归会立刻变红。

## 5. 重定位

### 5.1 白名单（12 种，与汇编器契约一致）

| 值 | 名称 | 形态 | 写入 |
| --- | --- | --- | --- |
| 257 | `ABS64` | 8 字节绝对量 | `S + A` |
| 275 | `ADR_PREL_PG_HI21` | `adrp` | 页差 `((S+A)&~0xfff − P&~0xfff)>>12` → `immlo:hi` |
| 277 | `ADD_ABS_LO12_NC` | `add xN, xM, #imm12` | `(S+A)&0xfff` → `imm12` |
| 278/284/285/286 | `LDST8/16/32/64_ABS_LO12_NC` | `ldr/str` | `((S+A)&0xfff) >> scale` → `imm12` |
| 280 | `CONDBR19` | `b.cond` / `cbz` | `(S+A−P)>>2` → `imm19` |
| 282 | `JUMP26` | `b` | `(S+A−P)>>2` → `imm26` |
| 283 | `CALL26` | `bl` | 同 `JUMP26` |
| 311 | `LD64_GOTPAGE_LO21` | `adrp` | 页差，目标为 GOT 槽地址 |
| 312 | `LD64_GOT_LO12_NC` | `ldr xN,[xM,#imm]` | GOT 槽低 12 位（按 8 缩放） |

白名单之外的重定位一律**报错并指出** `文件(节+偏移)`，不做静默忽略——
静态链接里没有"以后再说"的重定位，忽略就等于产出错误程序。

### 5.2 逐条校验（防"打错指令"）

每条重定位在写入前校验目标指令的形态（只看关键位段）：`adrp` 的
`op[31:24]=0x90`、`add` 立即数的 `op[28:24]`、`ldr/str` 的
`op[27:26]=11`、分支的 `op[30:26]=00101`、条件分支的 `op[31:24]`。
形态不符即报错。这样即使输入对象的 RELA 表被写坏，也不会把无关指令改掉。

### 5.3 重叠检测

每条重定位在写入前先在自己的字节范围上做标记（`rl_mark`/`rl_alloc_bitmap`），
同一段字节被两条重定位覆盖即报错。这能挡住"两个重定位互相踩"的隐蔽错误。

### 5.4 分支与范围

- 分支位移必须 4 字节对齐（用 `|d|` 取余判定：位移可能为负，而"除以再乘回"
  的取余对负数是向零取整，直接判零会把 `-8` 这类合法位移误判为未对齐）；
- 超出 `imm19`/`imm26` 可表示范围即报错，**不做跳板**（首版明确不做）；
- `adrp` 的页差按 `(vaddr & ~0xfff)` 计算，因此 `P` 的低 12 位无关。

## 6. 位运算规避策略（重要，且是现实约束）

种子编译器（`bin/yh-linux-arm64` 的 arm64 后端）在大立即数上存在实测错值：

| 运算 | 实测结果 | 应为 |
| --- | --- | --- |
| `%` | `0x510000 % 0x10000` → `0` | `0x1000` |
| `&` | `5308416 & 65535` → `0`；`0x90000001 & 0x9f000000` → `0` | `4096` / `0x90000000` |
| `*` | `81 * 65536` → 有时 `5304320` | `5308416` |

因此链接器**不依赖这三类运算做取位/缩放**，改用：

- **取位**：`low_bits(v, a)` = `v − (v / a) * a`（除以 2 的幂再乘回，等价于
  取低 `log2(a)` 位）；`hi_bits(v, lo, hi)` = `low_bits(v >> lo, 1 << (hi-lo))`；
- **写位段**：`set_bits_u(word, lo, hi, val)` = 清位段 + 置入（都在 u64 域）；
- **缩放倍乘**：`mul_add(k, a)` 用累加（每次左移一位）代替 `k * a`；
- **对齐**：`align_up(v, a)`、`divisible_by(v, a)` 都走上面的取位原语。

自检的基础算子组对每个用到的量级都做固定回归；一旦原语改回乘法/位运算实现，
自检立刻变红。**这是刻意的**：这些代价换来的是"链接器算出来的地址是对的"。

### 6.1 位段读写在两个域里分开

- **地址/偏移域**（int）：`low_bits`、`mul_add`、`pow2_i`、`hi_bits_int`、
  `flags_has`、`divisible_by`；
- **指令字域**（u64）：`hi_bits`、`set_bits_u`、`low_bits_u`、`shl_u`、
  `mul_add_u`、`mul256_u`、`pow2`。

分开的原因：同一函数里混用 u64 与 int 会触发编译器
「内部错误：SSA 函数校验失败」；而 `0xd28000e0` 这类指令字放不进有符号 int。
链接器的地址上限是 2 GiB（自检里显式判定），所以 int 域够用。

## 7. 输入契约与拒绝路径（"严格但可读自家产物"）

### 7.1 接受

- `ELF64`（`ELFCLASS64`）、小端、`ET_REL`、`EM_AARCH64`；
- 节类型：`PROGBITS` / `NOBITS` / `STRTAB` / `SYMTAB` / `RELA`；
- 三类节名映射：`.text` → `OSEC_TEXT`，`.rodata` → `OSEC_RODATA`，
  `.data` → `OSEC_DATA`，`.bss` → `OSEC_BSS`；
- 全局符号定义/引用、局部符号、绝对符号（`SHN_ABS`）。

### 7.2 静默忽略（只限明确列出的元数据）

`.comment`、`.note*`、`.debug*`、`.ARM.attributes`、`.llvm_addrsig`、
`.eh_frame`、非分配性 `PROGBITS`/`NOTE`、以及输入对象的
`.strtab`/`.shstrtab`。忽略是有意的：这些节不参与映像装载。

### 7.3 报错（拒绝路径）

| 情况 | 诊断要点 |
| --- | --- |
| 截断/魔数不符/类别不符/机器不符/非 `ET_REL` | 明确指出哪一条不满足 |
| 节头表、符号表、RELA 表越界或项大小不符 | 指出表名与期望项大小 |
| `SHT_REL`（无 addend 的重定位） | AArch64 只接受 `RELA` |
| 未定义的**局部**符号 | ELF 约定：未定义只能是全局或映射符号 |
| 未定义强引用 | 一次报全，并在括号里给出**首个引用点** |
| 重复强定义 | 指出两处来源对象 |
| 符号定义在不参与合并的节里 | 指出对象 |
| 未知的可分配节 | 不猜，直接报错 |
| 重定位类型不在白名单 | 指出 `文件(节+偏移)` |
| 重定位目标未解析、目标节非合并节、写入越界、位置重叠 | 分别报错 |
| 分支位移未对齐 / 超范围 | 分别报错 |
| `TLS`/弱符号/`COMMON`/`STV_HIDDEN` | 明确"首版不支持"而非错算 |
| 找不到入口符号 / 入口不在可执行节 | 提示 `--entry` |

### 7.4 一处有意的宽容

0 号空节（`SHT_NULL`）的字段：只拒绝**有语义**的字段非零
（`sh_type`/`sh_flags`/`sh_size`/`sh_addralign`），**容忍 `sh_offset`**。

原因：`yh_asm` 与 `llvm-mc` 都会把"节头表之前的字节数"写进空节的
`sh_offset`（严格按规范应当全零），而该字段在空节上没有语义、链接器也不读它。
不放宽就**读不了自家汇编器的产物**；而 `sh_type` 非零说明这根本不是空节，
必须报错。

## 8. 映射符号（`$x`/`$d`）的处理

AArch64 的汇编器会在每个指令/数据区域开头放一个局部映射符号（`$x`/`$d`），
服务反汇编器。它**不是可解析符号**：与用户符号共享名字空间。

早期版本把 `$x` 当普通局部符号登记，结果全局符号 `helper` 的地址被算成了
`$x` 的值，跨对象 `bl` 直接跳到自己头上形成死循环。现在：

- 读到即识别（`er_is_mapping_sym`），**不拒绝**（否则读不了自家产物）；
- 不进全局符号表、不参与跨对象解析、不占输出符号表位置
  （`st_is_mapping`、`ew_skip_sym`）；
- 未定义的局部映射符号（0 号符号位置）允许存在。

## 9. GOT 支持

`.got` 排在 R 段头部（`.rodata` 之前），表项 8 字节，槽内容 = `S + A`。

- 槽位按 **(目标符号, addend)** 复用：`ly_alloc_got` 线性查重，同目标同
  addend 只占一槽；
- `.got` 只在真的存在 `LD64_GOTPAGE_LO21`/`LD64_GOT_LO12_NC` 时出现，
  因此节头表长度可变（见 §2.3）；
- `LD64_GOTPAGE_LO21` 的页差是**页粒度**的，所以 `adrp` 所在的 PC 低 12 位
  无关；`LD64_GOT_LO12_NC` 按 8 字节缩放槽地址的低 12 位。

## 10. 命令行契约

| 调用 | 退出码 | 行为 |
| --- | --- | --- |
| `yh_link`（无参数） | 0/非 0 | 跑自检，退出码即门（与 `yh_asm` 一致） |
| `yh_link --version` | 0 | 打印 `yh_link <版本>` |
| `yh_link link ... in.o ...` | 0 | 链接成功并写出产物 |
| 同上，输入/链接失败 | 1 | 输入读不进来、格式非法、符号/重定位错误 |
| 用法错误 | 2 | 未知参数/子命令、缺输入、缺 `-o`、`--max-page-size` 非法 |

- 诊断一律写 fd 2，格式 `yh_link: [<文件>[(<节>+0x<偏移>)]] [: ]错误: <消息>`；
- `--verbose` 额外打印各阶段过程输出（读取/符号/布局/重定位的中间量）并把
  布局报告打出来；**不改退出码**；
- 产物**一次性写出**：链接成功后才创建输出文件，中途失败不留半成品。

## 11. 自检与验收门

### 11.1 自检（`yh_link` 无参数，四组）

| 组 | 覆盖 |
| --- | --- |
| 基础算子 | `%`/`&`/`*` 的实测错值量级、取位/写位原语、`mul_add`、`pow2`、`divisible_by`、`flags_has`、指令字形态判据 |
| 读取层拒绝 | 截断、魔数、类别、机器、非 `ET_REL`、节头越界、符号表项大小、RELA 类型等坏字节逐份要求被拒 |
| 单对象端到端 | 构造一个含 `_start` + `bl` 的对象，链接后核对 ELF 头、3 个程序头、段同余、权限、首条指令原样、`CALL26` 位移 |
| 多对象合并 | 引用方 + 定义方两个对象，定义方符号节内偏移非 0，核对 `CALL26` 位移与输出符号表地址 |

自检是**构建门的第一道**：`make yh-link-probe` 默认只跑构建 + 自检 + CLI 契约，
不需要汇编器、也不需要在 Linux 上运行产物。

### 11.2 端到端验收（`link/tests/link_accept.py`）

语料在 `link/tests/asm/`，每个用例都要过四关：**汇编成功 → 链接成功 →
结构合法 → 真跑得到期望退出码**，另加**确定性**（两次链接逐字节相同）。

| 用例 | 覆盖 | 期望退出码 |
| --- | --- | --- |
| `01-exit42` | 单对象最小可执行、`svc` 退出 | 42 |
| `02-twoobj` | 跨对象 `CALL26` + 跨对象 `adrp/add` 取数据 | 49 |
| `03-abs64` | `.data` 里 `.xword` 回填绝对地址 + `blr` 过去可用 | 42 |
| `04-page` | 非零页差 `ADRP` + 跨 64 KiB 的长距离 `CALL26` | 48 |
| `05-adrp-only` | 只取址不访存（把页寻址与访存问题分开） | 43 |
| `06-load-rodata` | 跨段访存（从 `.rodata` 读一个字） | 44 |
| `07-symoffset` | 节内偏移非 0 的标签（跨对象错位的根因） | 42 |

结构断言包括：`ELF64`/`ET_EXEC`/`AArch64`、`e_entry=0x400000`、正好 3 个
`PT_LOAD`、段页对齐且 `p_filesz <= p_memsz`、RW 段不可执行、首段可执行、
应有节名齐全、`e_shstrndx` 指向真正的 `SHT_STRTAB`、`.symtab.sh_link` 指向
真正的 `.strtab`、`.symtab.sh_entsize=24`。

### 11.3 差分回归（`link/tests/link_diff_regress.py`）

同一组对象分别交给 `yh_link` 与 `aarch64-linux-gnu-ld -static -nostdlib`，
比较**与布局无关**的结论：

1. 两个产物都真跑，退出码相同且等于期望值；
2. 两者都是静态 `ET_EXEC`/`AArch64`，无 `PT_INTERP`/`PT_DYNAMIC`；
3. **重定位语义**：把符号按输出节名分组，组内各符号相对于组内首符号的差值
   必须相同——绝对地址随布局变化，但"同一节里两个符号相距多远"是链接器
   必须算对的不变量。

不比较（有意）：段个数、节顺序、文件字节（布局自由度不同，逐字节比较无意义）。

### 11.4 运行环境说明（验证记录必须写明）

本机宿主是 Windows + WSL（Ubuntu x86_64），**没有 AArch64 硬件**，
产物经 `qemu-user`/`binfmt_misc` **模拟执行**，不是原生。因此：

- 验收结论记为「qemu-aarch64 模拟下通过」；
- `make yh-link-probe FULL=1` 需要 `tmp/wsl.sh` 设好的环境
  （`PATH` 含交叉 gcc 包装、`SEED=bin/yh-linux-arm64`、`YH_LINK=/nonexistent`）；
- 真机/arm64 容器验证是后续任务（并入仓库既有的 arm64 CI 作业）。

## 12. 已知限制（首版）

1. 只做 Linux/AArch64、静态、非 PIE；Darwin/Mach-O 目标是 `-t darwin` 的
   显式报错路径（后续任务）。
2. 不支持跳板：分支超出 ±128 MiB 直接报错。
3. 不支持 TLS / 弱符号 / COMMON / 符号可见性 / 链接脚本 / 归档库。
4. 映像上限 2 GiB（地址计算在 int 域）。
5. 段间不共享页面：每段页对齐起始，最多各浪费不到一页文件字节。
6. 映射符号不参与输出符号表。
7. 未接入编译器（用户要求：等稳定后再接入）。

## 13. 集成到编译器的前置条件（为什么现在不接）

集成会改变编译器的工具发现与用户可见行为，必须等以下条件同时成立：

1. 链接器自身的门（本文件 §11）在 Linux/aarch64 上全绿，且至少跑通一个
   **真实程序**（不是语料）的完整链路；
2. `compiler/cmd/link_cache.yh` 的汇编器查找已从 `yh_link` 改为 `yh_asm`
   （否则真链接器占用 `yh_link` 名字会直接破坏现有构建）；
3. `YH_ASM`/`YH_LINK` 环境变量与「找不到就回落系统 cc」的语义定稿；
4. `--toolchain=self` 的 driver 行为、产物可执行性、失败诊断与退出码在
   `tests/selfhost/` 有对应门。

在此之前，`link/` 保持独立开发，`Makefile` 只提供 `yh-link-build` /
`yh-link-probe` 两个不接入主流程的目标。

# yh string 标准库设计

日期：2026-10-23。状态：**ST0–ST6 首期已实施并通过本平台专项门**。
用户选择实用完整基础库：只读字符串视图、可增长 String、查找/切分/替换与
UTF-8 基础操作。[实施分期](../02-plan/yh-string标准库实施方案-2026-10-23.md)
列出 ST0–ST6；实现未改变语言语法，旧三接口保持原签名与 NUL 截止语义。
实际公开面与使用示例见 [`libs/string/doc.yh`](../../libs/string/doc.yh) 与
[`libs/string/README.md`](../../libs/string/README.md)。

## 1. 实际基线

- `libs/string/string.yh` 保留 `length(*char) u64`、`equals(*char,*char) int`、
  `compare(*char,*char) int`，全部操作 NUL 结尾字节串；首期新增
  `base.yh`、`view.yh`、`owned.yh`、`transform.yh`、`utf8.yh`
  与 `doc.yh`，不再保留空 `String` 占位。
- `tests/modules/projects/libsbase/src/main.yh` 已验收三函数，并有 cli 测试调用
  `string.equals`。不把老接口改成接收新类型，也不改变 0/1、-1/0/1 的返回约定。
- `libs/memory` 提供显式 alloc/release/copy；copy 禁止重叠，没有 realloc。
  当前运行时按映射分配，短字符串也有分配成本，应优先复用容量。
- os.DirEntry 和当前工作区的 toml.Text 已使用 `*u8 + u64`；cli 明确记录
  不能从裸堆指针构造动态切片。不能规划出依赖未支持切片构造的 API。
- toml 当前有模块私有 UTF-8 校验，但包含“拒绝开头 BOM”的格式规则；通用 string
  不应继承这条规则。本轮不改动正在演进的 TOML 实现或规划状态。
- 项目源码扫描能发现 string；`libs/project.toml` 未显式列出 string，不表示模块
  不可导入。不为这次扩展额外引入模块发现机制。

## 2. 方案取舍

| 方案 | 优点 | 代价与结论 |
| --- | --- | --- |
| **View + String，按字节存储，显式 UTF-8** | 借用不复制；支持 NUL；可接文件、TOML 和 C 边界 | 需要说明所有权和失效规则；推荐 |
| 继续只扩充 `*char` 函数 | 最小增量，调用现有代码方便 | 无长度边界、无法表达 NUL，增长与释放散落在调用者；不满足已选范围 |
| String 始终保证合法 UTF-8 | 部分文本操作前置条件更强 | 任意字节输入都需校验，字节修改受限，仍需另一套字节容器；首期不选 |

首期不加入 Unicode 大小写/折叠、规范化、字素切分、区域排序、正则、格式化、
数字解析、字符串驻留、引用计数、隐式析构、短字符串优化或自定义分配器。
`String` 同时承担增长缓冲的职责，不再新增同功能 Builder。

## 3. 核心模型和单位

```yh
// View 借用一段连续字节，不拥有存储；count 不含额外的结尾 NUL。
// 调用者必须保持源存活且不改写；data 不是语言层面的 const 指针。
pub struct View {
    data *u8
    count u64
}

// String 独占模块私有状态；handle 只允许本模块操作，零句柄表示空串。
// 结构体赋值不会复制内容或增加所有者，转移和复制分别使用 move、clone。
pub struct String {
    handle *void
}
```

私有状态保存 `data *u8`、`count u64`、`capacity u64`；不出现在 pub 签名中。
通过薄句柄避免公开增长状态，不承诺语言已能阻止复制句柄、改写 handle 或写入
View.data。只读、单一所有者和不手工构造非零句柄均为调用契约。

- 所有长度、位置、容量和切片边界单位都是**字节**，使用 u64。`count` 不重复
  使用内建 len 的数组/切片含义；不让 `len(String)` 成为隐式新语言能力。
- View 可以表达任意字节，包括 NUL 和非法 UTF-8。不承诺它是完整 Unicode 文本。
  空视图可用 `{data: 0, count: 0}`；count 非零时 data 必须指向可读区间。
- 已分配 String 始终满足 `count <= capacity`，分配 capacity+1 字节，并维护
  `data[count] == 0`。额外 NUL 不属于内容；内容内仍允许 NUL。
- 零句柄 String 合法，创建和释放后都可以继续追加。首次实际需要容量时才分配。
- View 和 String 的结构有效性不等于任意裸指针可被验证；悬空指针、伪造长度和
  外部改写不在库可检测的错误集合内。
- “码点计数”实际计 Unicode 标量；不叫“用户可见字符数”。组合字符、emoji
  序列与字素边界属于后续文本层。

## 4. 错误与结果

`Status` 建议成员为 `status_ok`、`status_end`、`status_invalid_argument`、
`status_bounds`、`status_overflow`、`status_out_of_memory`、
`status_invalid_utf8`、`status_embedded_nul`。end 仅表示迭代正常结束。

| 结果类型 | 字段及约定 |
| --- | --- |
| `ViewResult` | status、value View；失败/end 时 value 为空 |
| `StringResult` | status、value String；失败时零句柄，无需清理半成品 |
| `IndexResult` | found bool、index u64；未找到时 found=false、index=0 |
| `CStrResult` | status、data *char；失败时 data=0，成功指针只读借用 |
| `Utf8Info` | status、rune_count u64、error_offset u64；成功时计数有效，非法时首个错误偏移有效 |
| `RuneResult` | status、rune u32、width u64、offset u64；成功时为标量及字节区间，非法时 offset 为错误起点 |

错误不打印、不退出，不使用全局 last_error，不依赖本次分配来生成诊断。
新谓词返回 bool；旧 equals 继续返回 int。查找失败由 found 表示，避免把 u64
位置和 -1 哨兵混用。传给 out 的指针须非空；失败不修改 out，诊断结果另按表约定。

## 5. 只读构造、查询与切分

以下 API 接受有效 View；循环、指针加法和比较不得越过其 count。
构造入口检查可检测的空指针/长度组合，不能证明任意地址是否可读。

| 拟议 API | 契约 |
| --- | --- |
| `view_bytes(data *u8, count u64) ViewResult` | 不分配；(0,0) 合法，(0,非零) 参数错误；不检查 UTF-8 |
| `view_cstr(text *char) ViewResult` | 扫到首个 NUL 并借用；空指针是参数错误，空字符串合法 |
| `view_equal(left View, right View) bool` | 按长度和字节判断相等 |
| `view_compare(left View, right View) int` | 无符号字节词典序，固定 -1/0/1 |
| `starts_with(text View, prefix View) bool` / `ends_with(text View, suffix View) bool` | 空前/后缀均匹配 |
| `find(text View, needle View) IndexResult` / `rfind(text View, needle View) IndexResult` | 空 needle 分别匹配 0、text.count；其余匹配整个连续字节序列 |
| `contains(text View, needle View) bool` | 与 find 的 found 一致 |
| `slice(text View, start u64, end u64) ViewResult` | 半开区间 [start,end)，要求 start<=end<=count；不复制，不修复 UTF-8 边界 |
| `trim_ascii(text View) View` | 仅裁掉首尾 0x09–0x0D 与 0x20；返回借用视图 |
| `split(text View, separator View, out *SplitIter) Status` | 初始化无分配迭代器；空 separator 参数错误，失败不修改 out |
| `split_next(iter *SplitIter) ViewResult` | 返回下一借用片段；结束后持续返回 status_end |

SplitIter 保存源、分隔符、字节游标与结束标志，两段输入都借用，迭代器本身无需
release。复制迭代器只复制游标，可独立继续；源和分隔符必须在整个迭代期间存活
且保持内容不变。分隔符按从左到右、互不重叠匹配，保留全部空片段：

| text / separator | 结果 |
| --- | --- |
| `"a,,b,"` / `","` | `"a"`, `""`, `"b"`, `""` |
| `""` / `","` | 一个空片段，然后 end |
| `"aaaa"` / `"aa"` | 三个空片段 |
| 任意文本 / 空串 | 参数错误 |

不返回隐式分配的 `[]String`；需要长期保存时复制片段。空 separator 的逐码点
切分可通过 UTF-8 遍历明确完成，不让字节切分兼任两种语义。

## 6. 拥有者、增长与 C 边界

| 拟议 API | 契约 |
| --- | --- |
| `make() String` | 返回零句柄空串，不分配 |
| `from_view(text View) StringResult` | 独立复制全部字节，输入可立即释放或改写；空输入可返回零句柄 |
| `clone(value *String) StringResult` | 独立深复制；失败不改变原值 |
| `move(value *String) String` | 转移句柄并清零源；不分配，不能用来复制所有权 |
| `release(value *String) void` | 释放并清零，同一变量重复释放安全；允许空指针 |
| `as_view(value *String) View` | O(1) 只读借用，零句柄返回空视图 |
| `byte_length(value *String) u64` / `capacity(value *String) u64` | O(1)；capacity 不含额外结尾 NUL |
| `reserve(value *String, minimum u64) Status` | 保证容量至少 minimum，内容/长度不变；已有容量足够时不分配 |
| `clear(value *String) void` | 清空内容并保留容量，不分配 |
| `truncate(value *String, count u64) Status` | 只缩短至 count；超过原长度报 bounds，不自动扩长 |
| `assign(value *String, text View) Status` | 复制替换内容，复用容量；接受自身有效内容的子视图 |
| `append(value *String, text View) Status` | 追加字节；支持整体自追加与自身子视图追加 |
| `append_byte(value *String, byte u8) Status` | 追加任意单字节，包括 NUL；不保证 UTF-8 |
| `append_rune(value *String, rune u32) Status` | 只编码合法 Unicode 标量；非法标量不改变目标 |
| `c_str(value *String) CStrResult` | 扫描内容，含 NUL 返回 embedded_nul；否则借用已有结尾 NUL；空串返回静态空串 |

除 release 的空指针例外，`*String` 参数要求指向合法变量。StringResult.value
由接收方作为唯一所有者使用，不同时释放结果槽和复制出去的句柄。跨作用域转移用
move，需要两个独立可变值用 clone。销毁旧目标后再接收 move，避免覆盖旧所有者。

`c_str` 不分配、不截断，不把任意 View 冒充已终止指针；得到的 *char 只允许交给
读取型 C 接口。需要转换 View 时先 from_view，再 c_str；需要写入的 C 缓冲不在
这个入口处理。字节计数应使用 View.count，不能为包含 NUL 的内容调用 strlen。

### 6.1 失效和失败原子性

- **所有成功的可变操作和 release 都使该 String 先前派生的 View/C 指针失效**；
  即使地址未变也须重新获取。reserve 未增长、空追加等成功情况同样按此简单规则。
  只读查询不使其失效；失败的可变操作保留内容、长度、容量与既有视图。
- 扩容必须先分配、复制旧内容及必要源数据、补 NUL，全部成功后才交换状态并释放
  旧块；新增状态分配失败也必须回收已申请的块，不能留下半成品。
- 自追加先识别源是否为旧内容内的完整子区间并保存偏移；扩容后重定位源，不能
  在释放旧块后读取旧 View。assign 的重叠复制使用定向字节循环或经验证的
  memmove，不能把重叠区交给 memory.copy。
- 字符串单一所有者，不能并发读写；不可变视图可共享的前提是源不会被改写/释放。

### 6.2 长度和增长

建议内部最大内容长度为 `0x7ffffffffffffffe`，为有符号地址差与额外 NUL 留空间；
ST0 核实当前指针索引和分配路径后固定该实现限制，不宣称这么大的内存可实际分配。
所有长度求和、乘法、capacity+1 与倍增都必须先作减法/除法边界检查，超限返回
overflow，合法大小但分配失败返回 out_of_memory，不静默截断或回绕。

容量按几何增长，minimum 特别大时直接取足够值；不公开增长倍率或初始小容量，
测试只断言 capacity>=请求值、内容保持和分配次数上界。连续单字节 append 的
复制工作摊还线性；reserve 已足够时不能每次重新映射。

## 7. 组合、替换与 ASCII 转换

| 拟议 API | 契约 |
| --- | --- |
| `concat(left View, right View) StringResult` | 返回独立拥有的连接结果 |
| `join(parts []View, separator View) StringResult` | 先算总字节数再分配；零片段返回空串，空分隔符允许 |
| `replace(text View, old View, replacement View, limit u64) StringResult` | 左到右、非重叠替换，最多 limit 次；0 次返回独立原文副本；old 为空报参数错误 |
| `replace_all(text View, old View, replacement View) StringResult` | 同一实现的不限次数入口，不递归匹配新插入内容 |
| `lower_ascii(text View) StringResult` / `upper_ascii(text View) StringResult` | 只改变 ASCII A–Z/a–z；其他字节原样复制 |

`replace_all("aaaa", "aa", "b")` 得 `"bb"`；replacement 允许为空。
无匹配或大小写无需改变时仍返回独立 String，不返回借用伪装的拥有者。
join 的 View 切片由普通数组/既有切片提供，不依赖从堆指针构造切片。

首版查找可用边界明确的直接匹配，最坏 O(n*m)，n 为文本、m 为模式长度；
split/replace 的相应扫描同样披露该上界。实现处注明真实上界，长期重复前缀样本
留测量证据；有明确规模需求后再替换内部算法，不把 SIMD/KMP 作为公共接口前置。

## 8. UTF-8 基础

按 [RFC 3629 第 3–4 节](https://www.rfc-editor.org/info/rfc3629/) 实现 1–4 字节
严格解码：拒绝截断、错误续字节、过长编码、代理项和超过 U+10FFFF 的值；
U+0000 和 U+FEFF 是合法输入。通用库不跳过/拒绝 BOM，也不把非法字节静默替换为
U+FFFD。字素边界另属 [Unicode UAX #29](https://www.unicode.org/reports/tr29/tr29-49.html)，
首期不承诺。

| 拟议 API | 契约 |
| --- | --- |
| `utf8_validate(text View) Utf8Info` | 严格校验并计标量数；失败给首个非法编码序列起点，rune_count=0 |
| `utf8_next(text View, cursor *u64) RuneResult` | 从 cursor 解一个标量；成功推进 width 字节；在结尾返回 end；越界/非法时不推进 |
| `append_rune(value *String, rune u32) Status` | 编码到局部至多 4 字节缓冲后走 append；非法标量返回 invalid_utf8 |

utf8_next 不替调用者验证整个前缀；cursor 必须来自 0 或之前成功的推进结果。
指向续字节时返回 invalid_utf8，cursor>count 返回 bounds；成功 RuneResult.offset
是本次起点，end 时 offset=count、width=0。失败/end 的 rune、width 为 0；越界
offset 为传入值。合法 U+0000 与结束通过 status 区分。

示例语义：`"hé中😀"` 是 10 字节、4 个标量；`"e\u0301"` 是 2 个标量。
byte slice/truncate/append_byte 可能破坏编码；调用者按需重新 validate。
lower_ascii/upper_ascii 不转换中文、重音字母或其他非 ASCII 字节，也不读 locale。

## 9. 文件、消费者与兼容

建议按职责分为 `libs/string/string.yh`（公开模型和旧接口）、`view.yh`
（构造/查询/切分）、`owned.yh`（存储/增长/生命周期/C 边界）、
`transform.yh`（连接/替换/ASCII）、`utf8.yh`（严格解码和编码），
另加 `doc.yh` 与 README。文件按实际规模拆分，尽量不超过 500–1000 行，
不为凑行数提前创建空文件。所有新增结构体和函数写中文契约注释。

- 旧三接口在本轮保留原实现或经证明等价的实现，不改变原空指针前置条件。
- 新接口通过普通 `import string` 使用，无新字面量、方法语法、泛型、运算符或
  编译器内建；不修改 docs/yh.g4。
- toml.Text 可经 view_bytes(text.data,text.count) 显式适配，不直接改其公开类型；
  TOML 对 BOM/控制字符的限制仍归 TOML。cli/编译器的私有函数迁移后续单列，
  不因名称相似就批量替换，不在首期引入 compiler↔libs 循环依赖。
- 新函数只在确有外部调用/验收时 pub，内部存储、解码和分配辅助函数保持私有；
  module cmd 入口无需变动。
- 安装与 Release 应实际携带所有新增 `.yh` 文件；从仓库外验证默认发现与
  YH_STDLIB 覆盖。测试源码留在 tests/，避免进入标准库分发。

# yh 编译期首版语法分析

日期：2026-10-05。状态：**首版语法/语义目标；已实现子集见下**。

根据用户修订，编译期控制采用 `$if/$for` 形式，且不提供顶层 `$if`；
`@[comptime]` 作为编译期函数属性保留。进一步建议所有控制和诊断 `$...`
均限于函数体，使声明登记与模块依赖规则沿用现状。本文件确定首版建议范围；
函数求值器的细节继续见
[过程设计](yh-编译期过程设计.md)，实施顺序见
[实施方案](../02-plan/yh-编译期过程实施方案.md)。
本轮调用接口分析推荐用 `$f(...)` 显式调用编译期函数，
替代此前普通调用自动判断方案；取舍与统一语法见
[显式调用分析](yh-编译期函数显式调用分析.md)。

当前语法已经接入 `$f(...)`、函数体 `$if/$for`、`@[comptime]`、同模块 `$IDENT(...)`
及跨模块 `$module_alias.IDENT(...)` 调用形，顶层控制正反例进入语料。编译期函数执行器支持整数表达式、直接 `$g(...)`
调用、整数比较条件、普通 `if/else`、`return` 和条件递归；调用实参要求常量，递归上限为
64 帧。普通函数中的独立诊断指令已接入，编译期函数内的三个诊断指令也按实际执行路径
触发。编译期函数条件与 `$assert` 布尔条件支持 `&&/||` 短路求值；typed IR 已支持局部值、
赋值、普通条件 `for`、函数内 `$if/$else` 按本次实参选支、按本次调用边界执行的 typed `$for`，
以及局部受支持数组/切片字面量、切片视图、普通 for-in 和整数或受支持结构体元素下标读写；本地具名结构体支持整数或受支持结构体元素切片字段、嵌套字段初始化、链式成员读写和递归复制。普通副本共享切片元素，逃逸返回复制可见元素，顶层静态数据物化延后输出切片 backing；浮点/指针切片、联合体字段、其他非整型聚合和其余 AST 子类仍是后续工作。
结构 `$if` 条件支持
`linux/darwin/arm64` 输出目标标记及 `&&/||` 常量折叠。

## 1. 首版建议

建议首版交付以下六项；它们分别负责选择代码、展开代码、计算值和产生诊断。

| 语法 | 首版范围 | 实现成本 | 建议 |
| --- | --- | --- | --- |
| `$if (...) {}` / `$else $if (...) {}` / `$else {}` | 仅函数体内语句选择 | 中，涉及未选中分支与块作用域 | 必选 |
| `$for i in (start..end) {}` | 普通函数按常量区间静态展开；`@[comptime]` 函数按本次调用区间解释执行；左闭右开 | 中，涉及绑定、重复作用域与预算 | 必选 |
| `@[comptime] fn` 与 `$f(...)` | 同模块私有标量函数求值，支持普通 if/for 与函数体 `$if/$for` | 中高，需显式调用检查、无发码检查与解释器 | 必选，接在控制语法之后 |
| `$assert(cond, "说明");` | 普通函数内检查常量 bool；编译期函数内按实际调用检查 | 低，共用求值与诊断 | 必选，说明可省略 |
| `$compile_error("说明");` | 函数体内选中的编译期路径产生错误 | 低 | 必选 |
| `$compile_warn("说明");` | 同上，产生警告，成功与否仍取决于其他检查 | 低 | 建议一起加入 |

首版只提供 `linux/darwin/arm64` 三个目标布尔标记，不新增构建配置字段、
自定义 define 选项或未知标记默认 false 的规则。标记来自当前编译任务的
目标信息，不来自执行编译器机器的临时状态；arm64 不表示已经有 x64 后端。

`$for item in E.values {}` 是 CT4 的首个轻量反射扩展，按枚举声明顺序提供只读
`item.name` 与 `item.value`；空枚举零轮展开，同值成员仍逐个保留。`$for T.fields`
仍按实际用途决定；按字段名访问对象、泛型类型选择与任意源码生成留待后续。

## 2. `$if`：选择代码

```yh
// platform_code：只保留当前输出目标对应的返回语句。
fn platform_code() int {
    $if (linux && arm64) {
        return 1;
    } $else $if (darwin && arm64) {
        return 2;
    } $else {
        $compile_error("尚未支持这个输出目标");
    }
}
```

建议保留 yh 的 if 条件括号。`$else $if` 与 `$else` 均带 `$`，不增加 `$elif`。
分支必须使用块，整个控制语句不加尾分号。

**条件统一在函数体检查或准备时求值：**

- `$if` 的条件可含 bool 文字量、目标标记、现有常量表达式、
  已就绪标量 const、`sizeof` 查询、
  外层 `$for` 的展开常量，以及 CT3 之后可求值的编译期函数调用。
  条件必须是 bool；普通函数参数和 let 不因初值恰好为常量而获得许可。
- `linux/darwin/arm64` 在 `$if` 条件里有固定内建含义，不受局部同名变量遮蔽。
  它们不变成全局词法保留字；普通 yh 代码仍可使用这些标识符。
  其他名字按正常绑定解析，未声明/未知标记报错，不默认为 false。
- `@[comptime]` 函数内的 `$if` 同样要求在函数体准备时已知，首版不能依赖
  本次调用的形参或局部值。依赖形参的计算用普通 `if`，由解释器执行。

两支均做完整词法/语法检查，只有选中支登记名字和做名称/类型语义检查。
未选择支可引用当前目标不存在的类型或外部符号；不能包含坏语法。
选中支进入所在函数的语句树；不产生运行期条件跳转。

`$if` 只能出现在函数体及其嵌套块中；不用于包裹 module/import、
函数、类型或全局变量/常量声明。选中块保留正常块作用域，
块内 let/const 不泄漏到分支之后。

普通运行期 `if (false)` 的语义检查仍会检查其代码，因此不能代替 `$if`。
所有声明和 import 按现有规则登记，未使用检查按选中代码判断。
需要区分平台的声明或导入继续使用已有平台源文件；函数内 `$if`
不会隐藏另一个平台文件中的错误，也不会让不存在的依赖免于解析。

这次收敛省去声明选择预处理、声明块产生式和“顶层目标条件/函数常量条件”
两套许可集合。平台文件目前按宿主筛选，目标标记来自输出任务；
将来支持跨目标构建时，平台文件筛选仍需单独明确目标契约。

## 3. `$for`：展开代码

```yh
// main：把固定四次打印展开成四条运行期调用，编译器本身不执行 printf。
fn main() int {
    $for i in (0..4) {
        printf("%d\n", i);
    }
    return 0;
}
```

展开效果相当于四个独立块，分别绑定常量 i = 0、1、2、3。目标程序没有这个
区间遍历的运行期循环；块里的 printf、赋值等普通语句仍在运行期执行。
这项区间形式是 yh 的扩展建议，不把它声称为 V 已有的 `$for` 用法。

- 首版只支持一个只读 int 绑定，边界必须是可求值、可表示为 int 的整数。
- 区间整体使用括号：`(start..end)`，明确最后一个表达式与后续块的边界。
  这比引入另一套结构体字面量/块头部猜测规则更简单。
- 左闭右开；`start >= end` 展开零次，空区间的循环体仍必须语法正确。
- 普通函数每次静态展开有独立局部作用域和新的绑定身份；CT 函数每次解释迭代更新调用帧中的
  只读绑定。循环名仅在循环体内可见，
  可供嵌套 `$if/$for` 使用，不能被赋值、取地址或在循环结束后访问。
- 支持函数内嵌套；禁止顶层展开、函数名插值、类型/声明名称生成。
- 首版禁止以 `$for` 为目标或跨 `$for` 跳向外层循环的 break/continue。
  体内新建的普通 for 可正常 break/continue；return 仍返回所在 yh 函数。
  `$for` 不生成目标程序中的循环指令；普通函数在编译时静态展开，CT 函数由编译期解释器逐轮执行。
  当前解析器用结构控制起点的运行期循环深度校验跳转边界；break/continue 只能引用循环体内新建的普通循环。
- 普通函数中的 `$for` 边界必须是准备时已知的整数常量。
- `@[comptime]` 函数中的 `$for` 边界在准备期完成名字/类型检查并保存为 typed 表达式；
  调用时可读取形参、局部值和外层循环绑定，按左闭右开区间逐轮执行。普通条件 `for` 仍是
  另一种通用循环形式。

单个区间最多 1024 次；普通函数整个编译单元的静态展开合计最多 100000 个实例；
CT 函数循环另受共享 100000 步解释预算约束。结构控制展开深度最多 32；新增 AST 节点也设
100000 上限，以防少量大循环体耗尽内存。
当前 `$if/$for` 解析器共享并执行 32 层嵌套限制；typed AST 展开及其节点上限仍未
实现。所有检查先于不受限复制；计算数量使用足够宽的位型，禁止 `end-start` 溢出。
这些是首版固定内部限制，不先增加配置接口。

## 4. `@[comptime] fn`：计算值

```yh
// sum_to：编译时累计 [0,n)，要求 n 非负，返回整数总和。
@[comptime]
fn sum_to(n int) int {
    $assert(n >= 0, "n 必须非负");
    let result int = 0;
    let i int = 0;
    for i < n {
        result += i;
        i += 1;
    }
    return result;
}

const TOTAL int = $sum_to(8);
```

编译期间得到 TOTAL = 28。普通 `for` 是解释器中的计算循环；普通函数里的 `$for` 是准备
程序时的静态代码展开；`@[comptime]` 函数里的 `$for` 在调用时由解释器按本次边界执行。

首版使用过程设计已有的标量子集、类型转换、执行预算与纯操作边界。
同模块私有编译期函数推荐统一使用 `$f(...)` 调用，
包含编译期函数内部的嵌套/递归调用；普通 f(...) 仅用于普通函数。
显式调用是表达式，可以用于全局 const 等值位置，不恢复顶层控制结构。
函数无运行期符号、必须有非 void 返回；禁止 extern、运行期函数值和全局 let。
公开 `@[comptime] pub fn` 已可在跨模块构建中由 `.s.ct` 正文接口执行；首片和待补边界见
[编译期过程设计](yh-编译期过程设计.md)及[CT5B 方案](../02-plan/yh-编译期跨模块函数正文传递实施方案.md)。

## 5. 编译期诊断

```yh
// verify_layout：语义检查期间验证目标数据模型，不在运行期执行断言。
fn verify_layout() void {
    $assert(sizeof(int) == 4, "int 必须是 4 字节");
    $if (linux) {
        $compile_warn("正在生成 Linux 目标代码");
    }
}
```

- `$assert` 只收 bool 条件与可选字符串文字量消息，首版仅用于函数内。
- `$compile_error/$compile_warn` 只收一个字符串文字量，仅用于函数体内。
  不先加入字符串插值、环境读取或任意 *char 的编译期解引用。
- 普通函数内的指令在前端检查时执行：`$assert` 条件须为常量 bool，错误和警告
  消息须为字符串文字量。`@[comptime]` 函数中的诊断按实际调用路径运行，断言可读取
  当前调用帧中的局部值；typed IR 已支持标量局部状态、条件循环、`$if/$else` 选支、
  局部受支持数组/切片字面量和切片视图、普通 for-in、整数或受支持结构体元素下标读取与本地元素写入。其他非整型聚合及一般左值仍待后续实现。
- 被 `$if` 排除的指令不触发；编译期函数普通 if 未执行的支也不触发。
  普通运行期 if 里的指令仍会在编译时触发。
- `$for` 展开中的错误/警告包含原源码位置和从外层到内层的当前迭代值链；
  仅进入区间但尚未开始迭代的层不写入来源链。警告在实际语义检查发生时输出，
  首版不承诺缓存命中时重放警告。错误不能被发布成成功缓存。

## 6. 轻量反射可以加到什么程度

| 候选语法 | 可以提供的首批信息 | 额外工作 | 建议 |
| --- | --- | --- | --- |
| `$for item in E.values {}` | item.name、item.value | 枚举成员来源/声明顺序索引，元信息绑定 | CT4 首个扩展 |
| `$for field in T.fields {}` | field.name、field.index、field.offset、field.size | 复用 SField/目标布局，元信息绑定 | CT4 按用途加入 |
| `field.typ` 或 `$if (T is ...)` | 类型作为编译期值/类型分类 | 元类型、类型选择后的检查、泛型时点 | 后续 |
| `obj.$(field.name)` | 按元信息选择实际字段 | 新后缀语法、实例绑定、展开后的逐字段类型检查 | 后续 |

V 的 `$for` 解析与展开围绕 fields/values/methods 等元信息进行。
这里的轻量反射范围只借鉴该边界，首版不搬入全部动态选择能力。
来源：[V 的反射解析](https://github.com/vlang/v/blob/152ba0d24ccd2d1fd810e71888cba2383972c6a4/vlib/v/parser/parser.v#L4472)、
[V 的展开实现](https://github.com/vlang/v/blob/152ba0d24ccd2d1fd810e71888cba2383972c6a4/vlib/v/transform/comptime.v#L490)。

轻量扩展只处理已完成布局的具体命名类型；字段/枚举成员按声明顺序遍历。
枚举同值成员仍逐个保留，不按底层数值合并。元信息只读且不能作为普通结构体
逃逸；name 在需要进入运行期程序时物化为现有字符串字面量，不暴露编译器地址。
类型布局/成员变化必须进入使用方缓存键。

只用元信息就能生成枚举名称/值列表或布局日志；要为各种字段生成序列化、
自动比较等代码，仍需后续类型分派和动态字段选择，不能把二者混称为已支持。

## 7. 首版明确不加入的语法

- 表达式形式 `$if`：需要另定分支结果、类型合流和现有 `?:` 的关系。
- 顶层 `$if/$for` 与诊断指令：本版统一采用函数内语句规则，顶层声明沿用现状。
- 条件 import、声明名称插值：改变依赖图和名称生成契约，另行设计。
- `$if (T is Type)`、泛型、反射函数列表、动态成员选择：需要新的类型阶段机制。
- `$eval/$run` 或任意源码字符串求值：不属于选择/展开/纯值计算的最小范围。
- `$env/$embed_file`：会引入外部输入和缓存依赖，后续明确输入契约后再设计。
- `$sizeof/$len`：已有 sizeof/len 能承担相应查询，没有必要加同义语法。
- `@[comptime]` 跨模块函数正文：由 `.s.ct` 伴随文件传递，并支持 CT 正文调用另一模块公开
  CT 函数、已就绪整数常量闭包及私有别名在局部复合类型、结构体字面量、直接具名 cast 与
  `sizeof` 中的内联；模块限定公共类型在局部类型、结构体字面量、`.to_type` 与 `sizeof` 中已规范化，
  非字面式/外部指针常量仍在 CT5B 后续阶段；typed CT 局部整数槽的 `&`/`*` 读写已交付。
  定义路径、行、列映射已交付。

这与用户选择的 `$if/$for` 形式一致，但不表示 V 的所有编译期特性都进入首版。

## 8. 无歧义的参考产生式

以下仅为提案；正式实施时才加入 `docs/yh.g4`，目前活跃语法保持现状。

```antlr
ctIfStmt
    : '$' 'if' '(' expr ')' block
      ('$' 'else' (ctIfStmt | block))?
    ;
ctForStmt
    : '$' 'for' IDENT 'in' '(' expr RANGE expr ')' block
    ;
ctInvokeExpr
    : '$' IDENT '(' callArgs? ')'
    ;
```

ctIfStmt/ctForStmt 接入 stmt；ctInvokeExpr 接入 primaryExpr，
独立 $f(...); 使用已有 exprStmt。不修改 topLevelDecl，
新增 `$` token，不把三个诊断名字变成全局词法保留字。
`@[comptime]` 继续使用现有属性 IDENT，并增加语义白名单。

以 `$` 后的 `if/for/IDENT` 区分构造；控制只在语句位置，
IDENT 调用既可用于表达式，也可通过 exprStmt 独立出现。
if 条件与 for 区间的括号固定头部边界，else 明确绑定前一个有块的 `$if`。
诊断和用户函数共用调用形产生式，具体名字、参数、可用位置由语义检查约束。
诊断仅限函数内独立语句（可用括号包裹），不能作为值；三个内建名在 $ 调用位置保留，
普通同名函数仍能普通调用，CT 函数则拒绝这些名字。
不另保留 ctDirectiveStmt，以免与 exprStmt 重复匹配。

函数内收敛的上一轮验证见
[收敛记录](../01-finished/yh-编译期函数内语法收敛-2026-10-04.md)。

其中 10 个形态仅确认可解析，正式实施须由语义门拒绝，详见显式调用分析。
这是有限语料检查，不代替实施时新增正式语法/运行用例，

## 9. 实现顺序与主要接缝

1. **CT0**：冻结上面的语法、阶段、目标标记、诊断和整数边界；正式 g4、目标标记、常量就绪和定宽折叠边界已有回归。
2. **CT1**：新增 `$` token 与函数内 `$if`；在函数体检查时求值，只处理选中块。

当前 lexer 已识别 `$`，语句解析已接入函数体 `$if/$for`，声明索引沿用现有形态。
不能在 lexer 中做文本替换后直接复用已有 for 发码，否则会遗失作用域与
源映射，并把代码展开错误实现成运行期循环。

后续完整实现可保留经过语法检查的 token 范围作为控制节点输入，对选中块或每次
展开实例在新作用域建立 typed AST；实例身份独立，源范围指向原始文件，并
增加展开来源信息。无需先重写全部普通函数前端，但不能绕过现有 AST verifier。
单文件、项目、syntax-check/check/build 三条入口必须遵守同一结构规则。

目标标记、选中分支、展开语义版本及反射布局属于缓存输入；编译器源文件新增
实现必须使用旧种子已经支持的语法，通过两代固定点与全部门后再让 compiler
自身使用 `$if/$for`。计划任务与验证要求见实施方案。

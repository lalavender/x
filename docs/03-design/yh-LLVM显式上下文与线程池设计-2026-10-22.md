# yh LLVM 显式上下文与线程池设计（LA5）

日期：2026-10-22。性质：LA5 专项设计门，**不提前修改全仓函数签名**。
依据 [LA5 方案 §12](../02-plan/yh-LLVM架构分阶段实施方案-2026-10-22.md)。
当前 fork/COW worker 是正式过渡执行器；线程池必须在前端/AST/CT/诊断/缓存
全部显式隔离后引入。

## 1. 目标

把当前进程级 `gen.G()`、AST 模块级 arena、comptime 全局池、诊断/统计与
缓存提交改为显式上下文，再用固定线程池替换 fork；串行、2 worker、4 worker
必须产生相同的模块/接口/运行结果和稳定诊断顺序。

## 2. 上下文边界

- `FrontendTask`：源/词法/解析/语义表/目标/诊断游标；每个任务独占。
- `AstStore`：表达式/语句/边/绑定/声明/函数 arena 与所有权；每个任务独占。
- `CtContext`：CT 函数登记、布局请求、聚合池、执行预算；每个任务独占。
- `CacheContext`：函数 IR/check/文件对象提交句柄；只读输入与独占输出。
- `Diagnostics`：按稳定源顺序合并，不依赖线程完成顺序。
- `TargetContext`：宿主/输出目标身份只读共享。

## 3. 顺序

1. 审计 GenState、AST 模块变量、comptime 全局变量的真实写点；
2. 两份上下文串行交错执行，证明状态不串用；
3. 诊断/统计/缓存输出改为上下文私有；
4. 宿主线程桥（Linux clone / Darwin 审核 libSystem）与 `libs/sys` 原语；
5. 固定线程池、取消/失败协议；lld 继续一次性进程，不搬进共享线程。

## 4. 验收

- 两个函数/模块使用同名绑定、不同 CT 预算与目标事实，互不串用；
- 串行、2/4 worker 的模块/接口与运行结果一致；
- 任务失败不发布混合代产物；
- 诊断按稳定源顺序合并；
- 同项目独立构建会话互不覆盖；
- 完成前继续 fork/COW，不宣称线程安全。

## 5. 风险

- `gen.G()` 的调用面很广，不能只传 TaskCtx 指针就宣布隔离；
- AST/CT arena 的模块级生命周期与 parser 回滚紧密耦合；
- 宿主线程桥与 lld 的全局状态必须分开；
- 线程池失败/取消/结果合并比并行本身更难，必须独立门。

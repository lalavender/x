# extern 自动 C ABI

目标：在 Linux/AArch64 上，用户给出准确的 `@[extern]` 签名后，编译器直接生成 C ABI 调用与定义。Darwin/AArch64 使用单独的栈布局规则，保证本机回归。

## 类型与语法

函数类型包含调用约定，`ABI_YH` 与 `ABI_C` 参与签名去重和赋值检查。声明的 `extern` 决定函数入口的 ABI；其签名以及 extern struct/union 字段内的函数类型自动采用 C ABI。独立 C 函数指针使用 `@[extern] fn(int) int`，可用于变量、别名、参数、返回类型和字段。普通上下文中的 `fn(...)` 保持 yh ABI，二者不能隐式转换，函数类型之间的显式转换也不能改写调用约定。C 函数类型本身检查边界类型，局部变量和别名不能绕过限制。

`typeRef` 增加精确的 `@ [ extern ] fnType` 分支；该前缀与其他类型首 token 不同，无歧义。类型属性只允许单个 extern，不扩展顶层属性的适用声明。接口必须显式输出 C 函数类型，避免回调经普通 yh 函数、字段或别名导出时丢失 ABI。

## 分类与发射

共享分类器接收值描述（大小、对齐、聚合标志、浮点元素大小/HFA 个数）及目标，输出参数位置（GPR/FPR/栈、寄存器起点/片数、栈偏移、间接标志）。返回值使用相同分类，普通大聚合返回地址固定在 x8。

固定参数支持现有 C 标量、C 函数指针以及非空 extern struct/union。HFA 递归识别嵌套结构体、联合体和固定数组字段，先于大聚合分类；最多四个同种 f32/f64 元素。普通小聚合不拆分到寄存器和栈；普通大聚合传递调用方副本地址。Linux 栈参数至少八字节槽；Darwin 使用自然大小与对齐。调用栈最终按十六字节对齐。

调用端先按现有求值顺序暂存全部值，再按布局写栈与寄存器。入口先保存全部寄存器参数，再复制聚合，保证复制不会覆盖未保存参数。聚合在 yh 函数体内继续以地址表示，边界完成装箱/拆箱，不改变普通 yh 函数 ABI。

SSA 函数与调用携带 ABI，整数路径也消费共享分类器；暂不具备浮点/聚合内存表示的 SSA 函数明确回退到直接发射路径。IR 序列化版本为 6、前端 IR 缓存键版本为 11；接口显式携带类型 ABI，缓存不能复用旧格式。接口继续使用现有 v1/v2 外壳，在函数类型位置输出 `@[extern] fn(...)`。2026-10-14 修复一位 SSA bool 与源级字节值不一致的问题，规则见 [LLVM 语义契约](yh-LLVM语义与ABI契约.md)。

## 边界

切片、顶层按值数组、普通 yh 聚合、不透明值以及 C 变参继续拒绝。指针所有权、C 原型准确性和编译器尚无的 C 类型不由 extern 推断。

## 验收

独立 C 编译器双向验证小聚合（含 1/3/8/12/16 字节）、大聚合、嵌套 HFA、联合体、寄存器不足、浮点栈参数、窄整数栈参数、回调与函数指针返回、跨模块类型保持。执行 make、make test、make selfhost-native，并以静态 Linux/AArch64 ELF 验证。保留原有未提交改动，不滚动种子。

ABI 规则参照 [Arm AAPCS64](https://github.com/ARM-software/abi-aa/blob/main/aapcs64/aapcs64.rst) 与 [Apple arm64 调用约定](https://developer.apple.com/documentation/xcode/writing-arm64-code-for-apple-platforms)。源语言当前没有 128 位整数、binary128、向量、位域或自定义对齐，本实现不承诺这些 C 类型。

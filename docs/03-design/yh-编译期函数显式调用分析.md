# yh 编译期函数显式调用分析

修改时间：2026-11-06

状态：**同模块显式 CT 调用及跨模块正文首片已实现；完整执行器仍待实施**。

本轮按 `$函数名(实参)` 理解用户所说的“$函数签名调用”，例如
`$align_up(17, 16)`；调用处不重复参数类型和返回类型。
声明仍使用 `@[comptime] fn align_up(size int, unit int) int`。
首版控制仍限于函数体；显式调用是表达式，允许进入已有全局 const 等值位置。

当前支持直接名字调用、常量实参、整数返回、嵌套 `$g(...)` 与递归；全局 const、普通函数运行期
初始化、参数/局部槽、普通 if/条件 for、typed `$if/$for` 和按执行路径触发的诊断均有单文件或
同模块多文件回归。跨模块 `@[comptime] pub fn` 可通过 `$module_alias.function(...)` 调用，
本地递归/多层 helper 正文进入 `.s.ct` 闭包，依赖正文变化会使消费者缓存失效；CT 正文还可
调用另一模块的公开 CT 函数，导出时重写为提供方隐藏符号，导入 typed IR 切片会重定位到统一
arena。`comptimecross` 验证两层闭包、私有整数常量闭包、复合局部类型/结构体字面量/直接 cast 与
`sizeof` 中的私有别名内联，以及最底层正文/常量变化失效。CT 正文中模块限定公共类型可用于局部
类型、结构体字面量、直接 cast 与 `sizeof`，导出时按函数源文件的导入绑定改写为规范类型名。
当前跨模块公开函数签名仍限整数形参/返回；闭包常量已支持整数、直接浮点字面量和直接字符串字面量
`*char`（后二者只用于正文类型检查，不扩展浮点或外部指针求值）。定义路径/行/列映射已交付；typed CT
局部整数槽已支持帧内 `&`/`*` 读写，其他指针常量表达式与编译期外部指针常量求值仍待补齐。
有效闭包、签名篡改、错误版本、正文截断和语法损坏均有模块测试。
typed 区间 `$for` 可读取当前调用参数、局部值和外层迭代绑定；typed 普通
for-in 可遍历函数帧内受支持数组/切片字面量，下标表达式可读取或写入其整数或受支持结构体元素，切片表达式保留本帧元素存储别名；本地具名结构体支持整数或受支持结构体元素切片字段、嵌套字段初始化、链式读写和递归复制。全局数组长度现可使用 typed CT 调用、整数表达式及 pending `sizeof`，并按值/布局依赖推进求值。浮点/指针切片、联合体字段、其他非整型字段、跨模块正文闭包和全部 typed AST 子类仍未实现；本文中这些能力仍属目标范围。

## 1. 结论与接口取舍

可以采用，推荐 **编译期函数统一显式使用 $f(...) 调用**，
包括在另一个编译期函数内的调用和递归调用。

| 方案 | 好处 | 代价 | 建议 |
| --- | --- | --- | --- |
| 全部使用 $f(...) | 调用处明确阶段，规则统一，编译期调用不会伪装成普通调用 | 每次需要写 $ | 推荐 |
| f(...) 与 $f(...) 都支持 | 调用方便，兼容此前提案 | 同一行为有两种写法，普通调用也可能隐式执行编译期代码 | 首版不采用 |
| 普通函数内用 $f，编译期函数内可用 f | 减少函数体内标记 | 调用规则随上下文变化，还需两套缺标记诊断 | 首版不采用 |

这项建议替代上一轮“普通 f(...) 按属性自动判断”的调用接口提案，
控制/属性/值类型与求值预算的范围保持不变。函数身份与调用意图分工如下：

- `@[comptime]` 声明函数专用于受限编译期执行，不生成运行期函数符号。
- `$f(...)` 请求执行这个函数并得到值；$ 不让任意普通函数自动可求值。
- 普通 `f(...)` 只调用普通函数；如果绑定到编译期函数，提示改用 $f。
- 普通和编译期函数使用现有名字空间/遮蔽规则，不为 $ 建第二套用户函数表。
  局部变量遮蔽了 f 时，$f 绑定到该变量并报“不是可直接调用的编译期函数”，
  不能绕过遮蔽偷偷找到外层函数。

## 2. 使用示例

```yh
// align_up：计算非负 size 按正 unit 对齐后的字节数。
@[comptime]
fn align_up(size int, unit int) int {
    $assert(size >= 0 && unit > 0, "对齐参数无效");
    return ((size + unit - 1) / unit) * unit;
}

const BLOCK_SIZE int = $align_up(17, 16);

// main：验证全局编译期值与普通表达式中的编译期调用。
fn main() int {
    $assert(BLOCK_SIZE == 32);
    $if ($align_up(5, 4) == 8) {
        return 0;
    } $else {
        return 1;
    }
}
```

编译期间 BLOCK_SIZE 得到 32，选中 main 的第一个返回块；
目标代码不包含 align_up 的函数体或调用。

目标接口允许编译期函数内部把本次调用的局部值传给其他编译期函数：

```yh
// twice_aligned：在同一次编译期执行中把参数计算结果交给另一编译期函数。
@[comptime]
fn twice_aligned(n int) int {
    return $align_up(n * 2, 8);
}
```

要实现该形态，准备 `twice_aligned` 时应只检查调用和参数类型，执行时从调用帧取
`n` 再执行内部 `$align_up`；递归/互递归还需共享步数与帧预算。当前执行器尚不
支持此例。

## 3. 表达式位置与边界

| 用法 | 建议判定 |
| --- | --- |
| const N int = $f(4); | 支持，全局和局部 const 均为值位置 |
| let n int = 1 + $f(4); | 支持，结果作为运行期初始化中的常量 |
| printf("%d", $f(4)); | 支持，printf 在运行期，$f 的值在编译期取得 |
| $if ($is_valid(4)) { ... } | 支持，要求结果为 bool |
| $for i in (0..$count(4)) { ... } | 支持，要求结果适合 int 区间边界 |
| $f($g(4)); | 支持嵌套；可忽略结果，但调用仍须完成必要求值 |
| 普通函数形参/let 作为 $f 实参 | 拒绝，初值恰好为常量也不改变现有常量规则 |
| 编译期函数的形参/局部槽作为 $f 实参 | 执行时允许，由解释器帧提供值 |
| $普通函数(...)、$函数指针(...) | 拒绝；首版只允许按名字绑定的直接 CT 调用 |
| $m.f(...) | CT5B 首片支持导入模块的公开编译期函数；普通模块调用仍按运行期规则 |
| $f、$(表达式)(...) | 拒绝，不提供编译期函数值或任意被调表达式 |
| 全局数组/字段/签名长度直接写 $f(...) | 仍不开放；当前 CT5A 仅允许先行整数 const 初始化器调用已捕获的 typed CT 函数（递归受预算约束），再以该 const 名称请求有限布局 |

同模块多文件支持定义文件作用域；签名、显式参数类型、返回值类型不变。
$f 的优先级按基本表达式处理，结果可参与算术/比较/现有类型转换。
没有 typed 调用方帧的最外层 `$f(...)` 可返回受支持的数组、结构体，以及整数或受支持结构体元素切片，并将值物化为静态数据；typed 编译期函数之间可传递受支持的
数组/结构体值及上述切片。数组/结构体按值深复制，切片形参共享底层元素；结构体切片字段的普通副本共享其元素，逃逸返回时将可见元素复制到调用方帧，避免返回局部切片产生悬垂引用。静态序列化延后输出嵌套切片 backing，确保父结构与结构体数组字段偏移连续。数组/切片仍限于编译期调用帧内
的整型字面量初始化、for-in 读取及已支持的下标操作。

编译期函数中的 `$if/$else` 已按 typed 条件在每次调用时依赖实参/局部值选支；两支均做
名字与类型检查。typed `$for i in (lo..hi)` 在准备期检查并保存边界表达式，调用时按形参、局部值和
外层循环绑定执行；普通函数中的 `$for` 仍是常量静态展开。

## 4. 与诊断调用统一解析

上一轮参考规则是：

```antlr
ctDirectiveStmt : '$' IDENT '(' callArgs? ')' ';';
```

若再给 primaryExpr 加同形的 $f(...)，独立调用语句就可同时匹配
ctDirectiveStmt 和 exprStmt；这是真实的重复解析路径。

推荐删除独立 ctDirectiveStmt，统一为：

```antlr
ctInvokeExpr
    : '$' IDENT '(' callArgs? ')'
    ;
primaryExpr
    : ctInvokeExpr
    | literal
    | IDENT
    // 其余现有分支保持原样
    ;
```

stmt 只新增 ctIfStmt/ctForStmt；$f(...); 使用已有 exprStmt。
不把 assert/compile_error/compile_warn 变成全局词法保留字。

统一语法后的语义分类：

1. $ 后名字是 assert/compile_error/compile_warn：内建诊断，
   仅限函数内独立表达式语句，可用括号包裹，不产生可消费的值。
2. 其他名字：按正常作用域解析，必须绑定到带 comptime 属性的函数。
3. 内建名在 $ 调用位置不可由用户函数覆盖；普通 fn assert 可继续普通调用，
   编译期函数则拒绝使用这三个名字，以免声明后无法显式调用。

`const N int = $assert(true);` 等形态可以通过参考语法解析，
但必须在语义检查阶段拒绝。同理，诊断不能嵌入实参、条件、运算或后缀转换；
先校验位置再执行，不能先触发断言又报告其结果不可用。
未选 $if 分支仍只检查语法，普通运行期 if 和 CT 函数的诊断时点沿用原设计。

当前普通函数体已按此规则执行诊断：`$assert` 的条件必须是编译期 bool 常量，
编译错误/警告必须提供字符串文字量；诊断不能出现在值上下文。编译期函数体内的 typed 与兼容
执行路径均按实际调用路径求值。

这是位置检查从独立语句产生式转到统一调用语义的取舍，
不能把这种“语法接受”计为该用法已得到支持。

## 5. 当前实现接缝与后续工作

首个竖切片已经接入 `$` 词法、属性/签名登记、直接名字绑定、常量实参检查和整数
结果回填。当前工作边界如下：

- lexer 与 `parse_primary` 已识别 `$f(...)`，并拒绝普通方式调用编译期函数。
- 名字绑定复用现有符号表；实参检查调用现有常量/类型规则，暂限整数常量。
- `comptime` 保存 token/source 快照和 parser 准备出的 typed IR；兼容 token 执行器仍为未迁移
  的语句/表达式形式保留。typed IR 支持受支持数组/切片局部字面量、普通 for-in、切片视图和下标读写，也支持本地嵌套结构体及整数或受支持结构体元素切片字段初始化、链式成员读写和递归复制。
- 已验收全局 const、普通函数运行期初始化、嵌套调用实参与同模块多文件；CT5A 也已接入
  数组长度中的 typed CT 调用、递归、前向依赖、`sizeof` 布局依赖与环诊断。CT5B 首片支持
  `$module_alias.function(...)`、可达本地 helper 与已就绪整数常量闭包及缓存失效；模块私有类型、
  非整数全局常量闭包和损坏 sidecar 拒绝现已覆盖。来源路径/行/列映射也已交付；其他指针常量表达式与
  全局/字符串指针求值、跨帧指针传递及其他指针常量仍待 CT5B 后续阶段。编译期函数值、聚合 const 和浮点/指针/联合体
  等类型仍待设计或实现。
- 编译期函数体在普通前端解析时抑制发码；项目汇编验收确认其无目标符号。未覆盖的 typed
  AST 表达式/语句仍由兼容 token 执行器处理，后续应逐类迁移并锁定单文件与模块路径。

额外语法成本较小，主要新增显式调用与内建诊断的位置/名字检查。
标量求值器仍是 CT3 的主体工作；首版无需 VM/JIT 或普通函数纯度推断。

# yh 编码规范（2026-10-26）

状态：**生效**。适用于本仓库全部 `.yh` 源码（`compiler/`、`libs/`、`tests/`、
`examples/`）与用 yh 写的新项目。

依据（冲突时以靠前者为准）：

1. [`docs/yh.g4`](../yh.g4) —— 语法权威；
2. [yh 0.0.1 语义边界](00-语义边界-0.0.1.md)、[ADR-0013 模块私有类型](../adr/0013-yh模块私有类型.md)；
3. `AGENTS.md` 的「代码规范」「编码要求」；
4. `compiler/`、`libs/` 的既有写法。

本文标 **[强制]** 的条目不满足即缺陷；标 **[建议]** 的是默认做法，偏离时在
改动说明里写一句为什么。文中「现状」数据是对 2026-10-26 工作区的实测统计
（`wc -l`/`awk` 逐文件），描述现状，不构成本身要求以外的新规则。

## 0. 总纲

一个 yh 文件的理想形态：

```
module 头 → 文件级中文注释（这个文件为什么存在）→ 常量 → 类型 →
私有辅助函数 → pub 函数 → 语言内测试
```

读的人先看注释知道边界，再看签名知道能力，不必读函数体。规范里所有细则都
服务于这两步。

## 1. 排版

**[强制] 缩进 4 空格，禁止 tab。** 现状：`compiler/`、`libs/` 共 0 处 tab。

**[建议] 代码部分 ≤ 100 列；只有字符串可以更长。** 现状：中位数 35、p90 83；
超过 100 列的基本都是拆不开的中文诊断文案与 `backend/llvm_runtime.yh` 里内嵌的
LLVM IR 文本，最长 259 就出自那里。表达式、条件、参数表超长就抽局部变量或换行。

### 1.1 语句终结

**[强制] 不写尾分号。** yh 由换行终结语句（词法归一化 `compiler/lex/layout.yh`
在括号外补隐式 `;`），显式分号只在同一行放多条语句时才需要。现状：53,692 行
里只有 610 行以 `;` 结尾。

```yh
let a int = 1              // 推荐：换行终结
let b int = 1; let c int = 2   // 仅同一行多条时必须用 ; 分隔
```

**[强制] 以块收尾的语句整体不带尾分号**：`if` / `for` / `switch` / 裸块，以及
`fn` / `struct` / `union` / `enum` 声明（`}` 之后不写 `;`）。

### 1.2 续行

**[强制] 括号外的续行必须把运算符留在上一行末尾。** 这不是风格问题：
`compiler/lex/layout.yh` 只在括号/方括号外补隐式 `;`，所以上一行能终结时，
行首运算符会被当成**下一条语句**的开头——编译照样通过，值却错了（实测
2026-10-26：下面第二个例子的 `a` 是 `1`，不是 `3`，且无任何诊断）。

```yh
// 对：运算符在行尾，表达式跨行继续
let a int = x +
    2

// 危险：括号外行首运算符被拆成一条新语句（x 之后补了隐式 `;`）
let a int = x
    + 2

// 对：多行条件放进括号，括号内不终结，两种写法都合法
let ok int = (kind == gen.TK_RPAREN
    || kind == gen.TK_RBRACE).to_type(int)
```

括号/方括号内部换行是安全的（内部不终结语句），但为了一致，仍把运算符留在
行尾；括号内行首运算符只作权宜。对齐按 +4 空格。

### 1.3 花括号与空行

- **[强制]** `else` 与上一个 `}` 同行：`} else {`。多行条件导致 `}` 单独成行时，
  `else` 另起一行，缩进与 `if` 对齐。现状：`} else` 539 处。
- **[强制]** 单行守卫允许且推荐：`if (p == 0) { return -1 }`。块内超过一条语句
  就展开成多行块。
- **[强制]** 函数/类型声明之间 1 个空行；函数体内按逻辑段分组，段间 1 个空行；
  不出现连续 2 个以上空行。

## 2. 命名

| 对象 | 形式 | 例 |
| --- | --- | --- |
| 函数、变量、参数、字段 | `snake_case` | `buf_write`、`field_count`、`src` |
| struct / union / enum / type 别名 | `PascalCase` | `IRModule`、`ViewResult`、`Buf` |
| 常量（`const`） | `UPPER_SNAKE` | `TG_PTR_SIZE`、`JSON_MAX_INPUT` |
| 文件 | `snake_case.yh`，名字说明内容，不加数字前缀 | `reader.yh`、`ssa_module_model.yh` |

**[强制] 不要为新代码引入模块前缀。** `compiler/` 里的 `tg_`、`ir_`、`lex_`、
`sem_`、`mb_`、`pj_`、`li_`、`tc_`、`p_`（以及 `IR_*`、`TG_*`、`TOK_*` 常量前缀）
是 C stage0 时代为省链接冲突加的，属于历史；`libs/` 已改为无前缀。跨模块引用写
限定名 `模块.名字`：

```yh
let size int = gen.TG_INT_SIZE
```

### 2.1 函数名

**[强制] 动宾结构，动作在前**：`buf_write`、`parse_decl`、`ir_module_init`、
`view_result_ok`。查询/换算类可以名词短语开头（`view_bytes`、`target_arch_token`），
但不要倒装成 `bytes_view`。

**[强制] 动词只从这张表里挑**（括号内是本仓库实测出现次数，2026-10-26）：
`parse`(150)、`lower`(106)、`write`(71)、`add`(71)、`emit`(47)、`read`(44)、
`find`(39)、`get`(38)、`push`(34)、`append`(33)、`check`(32)、`set`(30)、
`verify`(24)、`init`(24)、`copy`(23)、`build`(23)、`scan`(22)、`close`(20)、
`open`(18)、`link`(18)、`reset`(17)、`release`(17)、`grow`(17)、`new`(15)、
`lookup`(15)、`load`(15)、`bind`(14)、`alloc`(14)、`fail`(13)。
不造 `do_*`、`handle_*`、`process_*` 这类动词。

**[强制] 谓词名只用 `is_*` 或 `*_ok` 两种形态，返回值类型跟随所在模块**：
`compiler/` 内部用 `int`（0/1；实测 `is_*` 18 处 int、2 处 bool，`*_ok` 27 处全是
int，如 `ir_type_ok`、`radix_ok`），`libs/` 与新写的库代码用 `bool`
（`view_equal`、`starts_with`）。不要新造第三种前缀。会产出诊断、有多处失败原因
的用 `check_*` / `verify_*`；返回 `int` 且 0 成功 / -1 失败的是**返回码**，注释必须
写 `0 = 成功`。

**[强制] 错误配对名**：`xxx_result_ok` / `xxx_result_error`（libs 风格）、
`xxx_result(value, status)`；编译器诊断用 `gen.fail` / `gen.err_*` / `gen.sem_err`。
同一模块内不要混用两套。

### 2.2 变量与参数

**[强制] 每个概念固定一个词，不造同义变体**（括号内是实测频次）：

| 概念 | 用这个词 | 不用 |
| --- | --- | --- |
| 元素个数 | `count`（79） | `num`、`cnt`、`total` |
| 字节长度 | `length` / `_len` 后缀（51） | `strlen` 以外的自造词 |
| 容量上限 | `cap`（40）、`capacity` | `limit`、`max`（除非真是上界） |
| 偏移 | `off` / `offset` | `pos`、`idx`（位置不是偏移） |
| 身份下标 | `id`（33） | `index`（那是位置） |
| 种类 | `kind`（22） | `type`（与类型系统混淆） |
| 状态 | `status`、`state` | `stat` |
| 输出参数 | `out`（201，参数名第一） | `result`（那用于返回值）、`ret` |
| 源 / 目标 | `src` / `dst` | `from` / `to`（除非天然配对） |

**[强制] 输出参数统一叫 `out`**，类型是 `*T`；结果值用局部 `result`（191 处）。

**[强制] 名字写全；只有下表允许缩写，且仅限 `compiler/` 内部**：
`i` / `j` / `k`（循环下标，649/125/80）、`n`（规模，168）、`b` / `t` / `r` / `v` /
`p` / `l`（短生命周期局部）、`gs` / `tk`（`GenState` / `TaskCtx` 的既定接收者）、
`buf`、`fd`、`ctx`、`src` / `dst`、`len`、`argc` / `argv`。
`libs/` 与对外 API 一律全词：`buffer` 不写 `buf`，`index` 不写 `i`。

**[强制] 字段单位写进名字**：`_count` 元素数、`_len` 字节数、`_cap` 容量、`_off`
偏移、`_size` 字节大小、`_id` 身份。`_n` 后缀（`tok_n`、`sym_n`，78 处）是旧同义词，
**不要新增**，新字段用 `_count`。

**[强制] 布尔局部用状态名**：`flag`、`found`、`done`、`at_end`；`is_*` 只用于函数名。

## 3. 类型与转换

**[强制] 所有声明显式写类型。** `let` / `const` / 参数 / 返回都必须有类型（语法
强制）；`let a int` 合法，`let a = 1` 非法。

**[强制] 整数默认 `int`（32 位）。** 下标、循环变量、枚举式的状态量用 `int`
（现状 810 处下标里 728 处是 `int`）；字节长度/容量、指针算术、哈希、与 libc
交接的尺寸用 `u64`（`malloc(size u64)`、`read`/`write` 返回 `i64`、`strlen` 返回
`u64`）——库的公开 API 按这个口径写（`view_bytes(data *u8, count u64)`）。

**[强制] 求和与累加器不要停在 `int`。** `int` 溢出静默变负（`docs/finish.md`
2026-10-26 条目真踩到过），累加器用 `i64` / `u64`。

**[强制]** 同一个结构体/同一组参数里，语义相同的量用同一类型（`count int` 配
`capacity u64` 会让每个调用点都长出 `.to_type`）。

### 3.1 转换规则（实测，2026-10-26）

只有**整数加宽**可以隐式，其余全部写 `.to_type(T)`：

| 情形 | 隐式？ | 例 |
| --- | --- | --- |
| 整数加宽（目标位宽更大） | 可以 | `u8 → int`、`int → u64`、`u32 → i64` |
| 整数窄化 | 不行 | `i64 → int`、`int → u8`（「不允许的隐式窄化」） |
| 同宽但符号不同 | 不行 | `int → u32`、`u64 → i64`（「同宽整数之间需要 .to_type」） |
| 整数 ↔ `bool` | 不行 | `int → bool`（「整数不能隐式转为 bool」） |
| 整数 ↔ 浮点、`f32` ↔ `f64` | 不行 | 浮点之间也不隐式 |

**[强制] 加宽到无符号前必须自己保证非负。** 隐式加宽不检查符号：`let a int = -1`
后再 `let b u64 = a` 得到 `18446744073709551615`。有符号转无符号（或反之）在
信任边界和长度/容量计算上要先判范围。

```yh
// 对：先判范围再转换（-1 表示参数非法；诊断口径见 §8）
if (delta < 0) {
    return -1
}
let count u64 = delta.to_type(u64)
```

### 3.2 文本、字节与容器

- **[强制]** `*char` = NUL 结尾 C 字符串；`[]u8` / `*u8` + 长度 = 已知长度字节；
  `View` = 借用只读视图。新 API 优先 `View`，只在 libc / C ABI 边界用 `*char`
  （`libs/string/string.yh` 就是这个口径：老接口保留，新代码走 `view.yh`）。
- **[强制]** 结构体、数组按值传递/返回（数组调用语义是值复制）。需要原地修改
  就传 `*T`，并在注释写明「本函数修改 *b 的 count」这类副作用。
- **[强制]** 结构体数组不能直接切片，先 `to_type([]T)`。
- **[强制]** 指针成员访问用 `.`，自动解引用，没有 `->`；`.to_type(T)` 作用于当前
  表达式本身、不解引用。`-x.to_type(int)` 是 `-(x.to_type(int))`，转换负数要写
  `(-x).to_type(int)`。
- **[强制]** `sizeof(T)` 只接受类型；`len(x)` 返回元素个数（`int`）。数组长度必须
  是 ≥1 的编译期常量，`[0]T` 报错；切片边界与空切片解引用是未定义行为，语言
  不检查（[语义边界 §6](00-语义边界-0.0.1.md)）。

## 4. 声明、可见性与模块

**[强制] 文件头部**：`module NAME` 是第一条非注释内容，空一行后列 `import`。
顺序按依赖层次（被依赖的基础模块在前，`gen` 在最前，现状 78 个文件都这么排），
不要求字母序，也不要为了排序去改动既有 `import` 行。

**[强制] 模块内顺序**：常量 → 类型 → 私有辅助函数 → `pub` 函数 → 测试。不是
语法要求，但决定了别人能不能从上往下读。

### 4.1 可见性（导出面收缩）

- **[强制]** 只导出别的模块**真的在用**的声明。只在本模块使用的 `fn` / `const`
  不写 `pub`；入口模块只保留 `main`。`pub` 同时决定 `.s.i` 接口与 `.globl`。
- **[强制]** 模块私有类型不写 `pub`；私有类型不得出现在本模块的 `pub fn` 签名、
  `pub struct` 字段、`pub type` 别名里（连指针形式也报错，ADR-0013）。
- **[强制]** `pub let` 非法。可变状态跨模块共享必须经 `pub fn` 封装。
- **[强制]** struct / union 字段一律公开，字段级 `pub` 报错。
- **[强制]** 字段顺序即内存布局顺序。布局敏感的结构体（跨模块、序列化、与 C
  共享）必须在块注释里写明「字段顺序是 ABI，不许重排」。

### 4.2 变量

- **[强制]** `const` 优先于 `let`：能在编译期求值就用 `const`（还能进 `case`
  与数组长度）。
- **[强制]** 就近声明，作用域尽量小。编译器不诊断未使用变量，也不禁止遮蔽
  （`let a int` 内层再 `let a int` 能通过检查）——**不依靠语言拦截，靠你自己**：
  不写未使用变量，不在内层遮蔽外层同名变量。
- **[强制]** 不要用零值当哨兵。`let n int` 是零值初始化，合法，但「0 表示未设置」
  必须显式写出来或改用 `bool` 标记。
- **[强制]** 类型声明只能出现在顶层，不允许嵌套。

## 5. 控制流

- **[强制]** `if` 条件必须带括号；`for` / `switch` 不带括号。
- **[强制]** 循环只有 `for`，三种形态：`for { }`（无限循环，配 `break`）、
  `for cond { }`、`for i in 0..n { }` / `for i, v in arr { }`。`while` / `do` 是
  保留字，写了直接报错，不存在「兼容写法」。
- **[强制]** 区间是左闭右开，空区间执行零次；不要写 `b - a` 形式的循环长度。
- **[强制]** `for-in` 绑定是**每次迭代的值拷贝**，改绑定不改容器
  （[语义边界 §8](00-语义边界-0.0.1.md)）。要改元素写 `arr[i] = x`，不要指望
  `for v in arr { v = x }`。
- **[强制]** `switch` 没有 fallthrough，每个 `case` 自带块，`default` 至多一个、
  位置任意。`default` 缺失不报错，需要穷尽时自己写并给出可解释的兜底。
- **[强制]** 提前返回优先于深嵌套：函数体理想 ≤3 层缩进，超过就抽私有函数。
  早退守卫用单行块（§1.3）。
- **[强制]** `break` / `continue` 只影响最内层循环，多目标循环就不要用它，改写条件。
- **[强制] 不用 `goto`。** 语言保留该语句，但 `compiler/` 与 `libs/` 里 0 处使用
  （只有 `tests/` 的语法语料在验证它）；需要跨层清理就抽 `xxx_release` 函数
  （§8）。标签必须后随被标记的语句，悬空标签非法。

## 6. 注释

**[强制] 只用 `//`，中文，标识符保持英文。** 块注释 `/* */` 语法支持，但
`compiler/` 与 `libs/` 里 0 处使用（只在 `tests/` 的少量语料里出现），新代码不用。

**[强制] 函数注释**：紧贴函数上方，第一行 `函数名：一句话做什么`，其后写清
四件事——参数与返回值语义、失败条件与返回码、副作用（分配/修改哪些参数）、
边界（空指针/越界/悬空由谁保证）。复杂函数 3–6 行，简单函数至少 1 行。

```yh
// buf_write 把 text 的 NUL 之前内容追加到 b 末尾；放不下时整段不写。
// 返回 0 表示写入成功，-1 表示参数非法或容量不足（此时 b 不变）。
// 不分配、不检查 b.data 的地址有效性——长度由 b.capacity 保证。
pub fn buf_write(b *Buf, text *char) int {
```

**[强制] 结构体注释**：用途 + 所有权/生命周期 + 字段含义与单位。字段少时逐字段
行内注释，字段多时在块注释里按声明顺序解释（`compiler/ir/ssa_module_00_model.yh`
是范例）。

**[强制] 私有 `fn` 同样写注释**：同模块的下一个人会读它，这比写测试更省事。

**[强制] 写「为什么」不写「是什么」。** `index += 1` 不注释；「容量取 2×n+1 是
因为最坏情况每两个 token 补一个终结符」必须注释。

**[强制]** 禁止 ASCII 装饰框（文件头 banner 除外，见 §7）；禁止把代码抄进注释。

**[建议]** 标记格式：`// TODO(2026-11-01): 具体下一步`、`// 注意: 这两行顺序不能
换`。不用 `// FIXME` 这类无后续信息的标记。

## 7. 文件组织

- **[强制] 一个文件一个主题，500–1000 行。** 超了就按职责拆（数据 / 算法 /
  输出各一份），不按行数硬切；小于 200 行的碎文件合并到同主题文件。
- **[强制] 文件头说明块**（`module` 与 `import` 之后）：

```yh
// ============================================================================
// view.yh —— 只读视图的构造、查询、查找与无分配切分
//
// 所有函数只读，不分配、不修改输入，也不检查地址可读性；调用者必须保证
// View 在调用期间有效。切片与切分返回的片段都借用源。
// ============================================================================
```

  说清三件事：本文件做什么、**明确不做什么**、与相邻文件的分工。
- **[强制] 文件名就是内容名，不加数字排序前缀**：`buffer.yh`、`reader.yh`、
  `parser.yh`、`ssa_module_model.yh`，不写 `view.yh`、`base.yh`。
  名字要能望文知内容（模块名可作前缀，如编译器内的 `模块_主题.yh`）。
- **[强制] 顺序靠名字本身解决，不靠数字。** 模块内按**文件名字节序**处理，
  声明必须先于使用（跨文件提前引用报「未知类型（类型必须先定义）」），所以：
  - 被依赖的声明（类型、常量）放进本模块字典序最早的文件，用语义名取得顺序
    （`base.yh`、`core.yh`、`defs.yh`、`types.yh`）；
  - 只被后面文件用到的常量放回自己主题的文件，不要为了排序把它拽到前面；
  - 拿不到合适的前置名字，就合并进使用它的文件——**不要退回数字前缀**。
- **[强制] 测试文件后缀为 `.test.yh`**（VTEST，2026-11-05）：`.test.yh`
  是测试文件的唯一标识，扫描排序保证它们排在模块内非测试文件之后，
  测试体引用生产声明不依赖文件名字典序（`zz_`/`99_` 排序前缀废止）。
  整库一个测试文件叫 `tests.test.yh`；按主题拆分为 `<主题>.test.yh`
  （如 cli 的 `actions.test.yh`、`basics.test.yh`）。
- **[强制] 共享声明放字节序最前的语义名文件（惯例 `base.yh`）**：模块内
  共享类型/常量先于消费者编译，`libs/` 已全部取消数字前缀（2026-11-06）；
  重命名必须同时核对文件名字节序与依赖顺序。
- **[强制] 平台差异用编译期文件选择**（`xx.linux.yh` / `xx.darwin.yh`），
  不在函数体里写 if 平台分支。
- **[强制] 不把「数据模型 + 算法 + 输出格式」塞进同一个文件。**

## 8. 错误处理与资源

两条**既有**约定，按模块性质选一条，不要混：

| 场景 | 形状 | 例 |
| --- | --- | --- |
| 编译器内部 | 返回 `int`：0 成功 / -1 失败，失败即诊断 | `gen.fail` / `gen.err_tok` / `gen.sem_err` |
| 标准库 / 库代码 | 返回 `XxxResult`，`xxx_result_ok` / `xxx_result_error` 构造 | `libs/string/view.yh`（存量命名） |

- **[强制] 不吞错。** 失败要么就地诊断（中文、指明文件名:行号或参数名），要么
  原样上抛。禁止「失败了但返回 0」。
- **[强制] 诊断消息是中文**，且可操作：「pub 接口引用了非 pub 类型（请将该类型
  声明为 pub）」是标准；「invalid argument」不是。
- **[强制] `malloc` 后立刻判空**并给出可操作诊断（现状 293 个调用点里约 57 个
  在随后 4 行内没有判空，不要新增）。
- **[强制] 缓冲区必须带容量参数并先校验。** 固定栈缓冲（`gen.append_str` 一族
  没有容量参数）调用方要自己保证目标 ≥ 源；**新增 API 一律带 `capacity`**。
- **[强制] 资源配对**：`open`/`close`、`malloc`/`free` 在同一函数内成对出现；
  提前返回的每条路径都要释放——把清理收进一个 `xxx_release` 私有函数，而不是
  在 5 个 `return` 前各写一遍。
- **[强制] 指针的可空性由注释声明，并由函数入口检查。** `*T` 不做空检查、
  `0` 不是合法对象；接收可空参数时第一件事是 `if (p == 0)`，这是信任边界。
- **[强制]** 越界下标、空切片解引用、返回局部数组的切片（悬垂视图）都是未定义
  行为。函数注释写明「谁负责保证」。语言不做静态生命周期证明。

## 9. 字符串与格式化

- **[强制] 人类可读文本的拼接用 `libs/fmt` 的插值** `${expr:spec}`：必须
  `import fmt`（标准库提供，只在项目模式下可用；单文件模式会报「字符串插值需要
  import fmt」）。限制：单行；内部不允许裸双引号、花括号、顶层三元。现状：唯一
  使用者是 `tests/modules/projects/fmtinterp/`；`compiler/` 的诊断拼接沿用既有
  `gen.fail` 形态，不要为了用插值给编译器引入 `fmt` 依赖。
- **[强制] 插值不用于拼协议、存储格式或 SQL/命令行。** 机器可解析的数据用显式
  缓冲 + 长度校验 + 显式转义。
- **[强制] 转义只用已知集合**：`\n \r \t \0 \a \b \f \v \' \" \\ \$` 与 `\xNN`。
  未知转义直接报编译错误，不要靠「反正能跑」。
- **[强制]** 字符串字面量是 `*char`，语言不保证其只读语义（[语义边界 §4](00-语义边界-0.0.1.md)）。
  不要把「字面量不可写」当作约束去设计 API。

## 10. 测试

- **[强制] 改行为必须带用例**：在 `tests/yh-run/`（运行语义）或 `tests/modules/`
  （模块/项目验收）新增 `.yh` 用例，`just test` 通过。这是 `AGENTS.md` 的硬要求。
- **[强制] 改语法**额外三步：`tests/yh/` 正例（按类目目录）+ `rejected/` 负例、
  `docs/yh.g4` 无歧义论证、刷新 `docs/` 下相关文档。
- **[强制] 语言内测试形态**：`test "行为描述" { ... }`，断言统一
  `$assert(cond, "中文期望")`；一例 5–20 条断言；用例名写行为，不写编号
  （`test "buf_write 拒绝超过容量的写入"`）。
- **[强制]** 测试体不能声明局部函数；helper 是模块私有 `fn`，数量要控制。
- **[强制]** 平台专属用例用头部指令 `// platform: linux` / `// platform: darwin-arm64`，
  不在测试体里分支。
- **[强制]** 测试不联网、不依赖仓库外路径；文件用例在 `/tmp` 下按用例名区分路径
  并自建自清（逐例是独立进程，并行时路径不能撞）。
- **[强制]** 负例断言具体错误，不只看「退出码非 0」。
- **[建议]** 改标准库时顺带跑 `just libs-test`；改标准库的 `test` 块性能敏感代码
  再跑 `just libs-test-o2`。

## 11. 编译期

- **[强制]** `$if (cond) { } $else { }`（语句）与 `$if (cond) a $else b`（表达式）
  的两个分支**都要能编译**：都做语法与类型检查，只有选中分支求值/发射。
- **[强制]** `$for name in (a..b) { }` / `$for name in MOD.ITEM { }` 用于整数区间
  展开与成员枚举，不要为了「省一次 if」而滥用。
- **[强制]** `$assert` / `$compile_error` / `$compile_warn` 只能作函数内的独立语句，
  不能当值。
- **[强制]** 编译期函数（`@[comptime]`）正文限定在受支持的 typed IR 子集内
  （含 `goto` 在内的特性不支持），复杂控制流先改写。
- **[强制]** 只为编译期服务的数据不要落进全局变量；运行期不需要就别发送。

# yh 语言内测试设计（提案）

日期：2026-10-23。状态：**YT0–YT3a 已随 0.0.9-rc.1 交付；YT3b（compiler 内嵌
测试）随 rc.2 交付；剩余 YT2d（并行/日志/缓存键）与 YT1.1（项目外单文件）**。
`docs/yh.g4` 与编译器已接受顶层 `test "名称" { ... }` / `test 声明名 { ... }`；
`yh test --list` 发现测试并绑定文档目标；`yh test` 把测试体降低为模块内
`pub` 无参 `void` 函数、生成入口模块、链接测试二进制并**逐例 fork/exec 执行**；
`$assert` 降为运行期 `__yh_test_assert(cond, line, col, msg)`。
支持 `--filter`（作用于执行）、`--timeout`、`libs/testing` 的 `fail/skip`、
失败位置与消息报告；`--no-run` 只构建不执行，`--emit-llvm` 可审阅降低结果。
标准库 `string` 已带内建测试（`libs/string/99_tests.yh`），由
`make test-lib-tests` 与 `make test` / `make selfhost-native` 执行；
`compiler/` 的 `gen`/`lex`/`parse` 内嵌测试随 **0.0.9-rc.2** 交付：rc.1 由
0.0.8 一代种子编译，该种子不认识 test 语法，因此 rc.1 的 `compiler/` 暂不含
test 块；rc.2 才能用 rc.1 的种子加入并由 `make test-compiler-tests` 执行。
现有 `$assert` 仍只支持编译期断言。实施顺序见
[分阶段方案](../02-plan/yh-test分阶段实施方案-2026-10-23.md)；块体降低、断言
执行与进程调度的展开见[执行模型分析](yh-test语法块执行模型-2026-10-23.md)。

## 1. 目标、依据与方案选择

目标是在 `.yh` 源码中直接描述单元测试，用 `yh test` 完成发现、编译、执行和
结果汇总；同模块私有函数、类型与状态可直接测试，不扩大 `pub` 导出面。
本提案假设用户需要 Zig 式的源码内测试，也需要项目级入口；暂不涉及测试框架插件。

当前 `tests/yh/`、`tests/yh-run/`、`tests/modules/` 与 `tests/selfhost/` 分别承担
语法、编译/运行语义、模块项目和自举验收；`libs/cli/test/` 另有外部 runner。
YT0 已把 test 声明写入 `docs/yh.g4` 与编译器词法/语法层；现有 `$assert` 仍只
执行编译期诊断。方案拟复用这一断言入口，为 test 体增加运行时检查，不另增
`assert` 名称。

Zig 的测试声明可与业务代码放在一起，普通构建省略它们；测试工具负责运行和
报告。[Zig 0.15.2 官方参考](https://ziglang.org/documentation/0.15.2/#Zig-Test)
还描述了过滤、跳过与 testing API。这里只借鉴核心使用方式；yh 不因此引入
Zig 的错误联合、`try`、泛型或反射。
根据用户补充，首版同时包含字符串行为测试与标识符文档测试（doctest）。

| 候选 | 优点 | 代价与结论 |
| --- | --- | --- |
| **顶层 `test "名称" { ... }` / `test 声明名 { ... }`** | 直接表达行为测试或声明文档测试；无注册表负担 | 增加一个声明种类；采用 |
| `@[test] fn 名称()` | 复用属性和函数解析 | 仍需规定签名、生成入口和收集测试；普通函数与测试身份混合；不推荐 |
| 特殊文件名或独立 main | 语法变化少 | 文件名承担语义、私有声明测试和手写入口较麻烦；保留现有集成测试用途 |

## 2. 用户写法

```yh
module arithmetic

// add 返回两个整数的和；默认保持模块私有。
fn add(a int, b int) int {
    return a + b
}

test "正数相加" {
    $assert(add(2, 3) == 5)
}

test "负数与零" {
    $assert(add(-2, 0) == -2)
}

// 文档测试直接关联 add 声明，作为其可执行用法示例。
test add {
    $assert(add(41, 1) == 42, "加法结果应为 42")
}
```

`test "正数相加"` 用字符串描述行为；`test add` 通过名字绑定关联被测声明，
作为该声明的可执行文档示例。两者都由 `yh test` 运行，断言与失败处理相同。
yh 统一写 `$assert(...)`，不必为基本断言 import testing，也不照搬 Zig 示例
中的 `try std.testing.expect(...)`。`try` 与错误联合仍不在本提案范围内。

测试既可紧邻被测函数，也可放在同模块另一份普通 `.yh` 文件中。不同文件仍按
现有模块规则共享声明，import 则保持文件作用域。文件名不决定是否为测试；
不引入 `_test.yh` 筛选机制，也不增加新的源文件后缀。

跨模块集成测试只能使用被测模块已有的 `pub` API，不突破私有边界。
外部测试目录仍须属于清单的 source 或使用独立 fixture 项目，不递归扫描项目外目录。

## 3. 语法与语义边界

以下语法增量已在 YT0 写入 `docs/yh.g4`，并由编译器词法/语法层实现：

```antlr
topLevelDecl
    : 'pub' exportedDeclBody
    | plainDeclBody
    | attributeGroup attributedDecl
    | testDecl
    ;

testDecl
    : 'test' testName block
    ;

testName
    : STRING
    | IDENT
    ;
```

- `test` 为保留字；已同步加入成员名放行集合，允许 `obj.test`、字段名 `test`
  等既有成员位置。YT0 实施前已检索仓库内 `.yh` 源码，未见以 `test` 作普通
  标识符；这是源码兼容性变化，仓库外源码需改用其他名字。
- 只允许顶层；禁止 `pub test`、属性前缀、函数或类型内部嵌套 test。
- 名称为非空字符串字面量或单个标识符；首版不接受匿名块、限定名
  （如 `test math.add`）或计算名称。空字符串由编译器语法检查拒绝（参考
  `yh.g4` 的 `STRING` 规则本身无法表达非空约束）。
- 测试体按无参、返回 `void` 的函数体检查；允许 `return`，禁止 `return 值`。
  原有局部声明与控制流规则保持一致，不能借此声明局部函数或局部类型。
- 测试声明没有用户可引用的函数名，不能被业务代码调用，也不进入 `.s.i`。
- 同文件内同种类且同名称的测试重复时报错；字符串 `test "add"` 与标识符
  `test add` 属于不同种类，可以共存。跨文件可同名，完整身份包含模块、
  相对路径、种类（test/decltest）和名称。
- 块后不加显式分号，换行归一化方式与现有函数声明一致。

文档测试的标识符须绑定到本模块的顶层声明，可以是函数、类型、常量或全局
变量；支持同模块跨文件声明、前向声明和私有声明。不绑定 import 模块名、
prelude 名字或任意显示名称；不能解析时，在测试构建语义检查中报错。
它只建立文档关联，不自动调用被关联的函数；测试体仍须显式编写用法和断言。
关联信息保存在测试元数据中，不扩大被测声明可见性，也不进入生产 `.s.i`。
未来文档生成器可将这些示例附到对应声明，首版不因此新增文档生成命令。

无歧义依据：新增产生式的首 token 为 `test`，与现有顶层分支互斥；名称的
STRING 与 IDENT token 互斥，随后必须是块；不引入表达式/声明二义性，也不
改变换行优先级。`test add { ... }` 中 add 只按声明名解析，不按调用表达式解析。
这是静态论证；YT0 已用 ANTLR 生成与 `tests/yh/` 正反语料验收。
生产 `build`/`run`/`check`/`--syntax-check` 目前只检查 test 声明与测试体的
语法，跳过测试体语义、名称绑定与代码发射；完整语义检查属于 `yh test`（YT1/T2）。

## 4. 命令与发现范围

```bash
yh test                         # 发现、构建并逐例执行测试
yh test arithmetic              # 只选择本项目模块的测试
yh test path/to/value.yh        # 用完整模块上下文检查该文件的测试
yh test --filter "正数"          # 按完整测试身份的子串过滤（--list 与执行）
yh test --filter add             # 同样可以筛选关联 add 的文档测试
yh test --list                   # 只列出测试身份、位置与文档目标
yh test --no-run                 # 只构建测试对象与入口，不链接/不执行
yh test --emit-llvm               # 额外写出每个模块的 LLVM 文本（审阅测试降低）
yh test --timeout 15             # 每个用例的超时秒数，缺省 15（1..3600）
```

- 不带选择器时覆盖当前项目全部模块，包括生产 main 不可达的本项目模块；
  不自动运行依赖项目或标准库的测试。依赖仍按现有解析规则编译。
- 模块选择器解析为本项目模块；要测另一个项目，进入该项目再执行。
- 文件在项目内时，使用完整所属模块作为编译上下文，但只检查/列出所选文件中的测试。
  项目外单文件视作一个临时模块，只编译该文件并允许导入工具链标准库；
  **YT1 尚未实现该形态，选择项目外文件会明确报错**。
- 顺序固定为模块名、项目相对文件路径、源码位置；过滤不改变剩余项的顺序。
- `--filter` 同时用于 `--list` 与执行：只运行身份含该子串的用例；它不隐藏
  所选模块其它测试体的编译/检查错误，也不改变构建范围。过滤后零用例报错。
- `--list` 只承诺发现和声明/绑定合法性；块体语义由构建/执行验收。
- `--no-run` 完成语义检查、降低、入口模块生成与对象发射，不链接、不执行。
- `yh test` 每个含测试的模块生成入口模块 `yh_test_<mod>`，链接测试二进制后
  逐例 fork/exec；argv[1] 首字节编码用例号（`'a' + 序号`）。
- 结果协议：fd 3 写 4 或 72 字节记录。测试体正常返回后入口写 `YHTP`；
  断言失败由运行时写 `YHTF + line(int32) + col(int32) + 60 字节消息` 并
  `exit(1)`；`testing.skip` 写 `YHTS` 并 `exit(0)`。父进程只在「退出码 0
  且有 YHTP」判 PASS；`YHTS` 判 SKIP；提前 `exit(0)`、崩溃、超时、记录缺失
  或格式不符一律 FAIL，且不阻断后续用例。汇总为
  `结果: N passed; M skipped; K failed`。
- `--timeout` 缺省 15 秒，父进程用 `WNOHANG` 轮询 + 单调时钟，超时 `kill`
  后仍回收子进程。
- 实际执行或构建时零用例视为错误，避免目录或过滤条件写错却得到绿灯；
  `--list` 允许空列表。已发现用例全部显式跳过时成功，但汇总必须显示零通过。
- 首版只运行宿主兼容目标；非宿主目标必须带 `--no-run`，不隐式启动容器或模拟器。

## 5. 普通构建、导入与平台规则

`build`、`run`、普通单文件编译和 `check` 识别 test 并检查其语法，但不检查
测试名称/文档目标的绑定和测试体类型，不生成其 IR、测试名称数据或 runner。
`--syntax-check` 同样检查完整测试语法；语义验收须使用 `yh test` 或其 `--no-run`。

仅在 test 体中使用的头部 import 是测试依赖：YT1 已在项目扫描期按 token
区间分类，生产构建跳过该导入的绑定、依赖边与未使用诊断；测试构建才启用它。
普通声明和 test 均使用的 import 是共有依赖；任何地方都没使用的 import 继续
沿用未使用诊断。分类按文件进行。
实现须基于声明区间区分引用，保留现有名称遮蔽规则，不能把字符串和注释算引用。
测试依赖参与既有环检测，不另开允许循环导入的通道。

这条规则同时适用于 `testing` 和其他测试辅助模块，不硬编码只有标准库可以
作为测试依赖。顶层普通 helper 仍是普通声明，按现有规则检查和发射；首版不
承诺自动识别并删除所有“仅被测试调用”的普通函数。

平台继续使用已有文件筛选，例如 `checks.linux.yh`、`checks.darwin.arm64.yh`；
按输出 TargetInfo 选择文件。不把语料 runner 的 `// platform:` 注释变成新语言
语义。运行期前置条件不足可显式 skip，但 skip 不能隐藏不存在的平台 API 的类型错误。

## 6. 统一 `$assert` 与最小测试辅助 API

基本断言只保留 `$assert(condition)` / `$assert(condition, "消息")`；不增加
独立的 `assert`，也不把 `testing.expect` 作为首版必需接口。条件仍必须是 bool，
消息仍为可选字符串字面量，调用只作独立语句，保持现有参数形态。

原先建议区分 `$assert` 与运行时 assert，是为了保持 `$` 表示编译期的既有
约定；这并非实现测试的必要条件。统一写法需明确扩展边界，不能假装现有
编译期实现已经能验证普通函数的运行结果。首版推荐下表的最小扩展：

| 词法上下文 | 执行时机与失败行为 |
| --- | --- |
| `test "名称"` 或 `test 声明名` 的体内 | 降为 `__yh_test_assert(cond, line, col, msg)` 运行期调用：false 时向 fd 3 写 `YHTF + line + col` 记录并 `exit(1)`，父进程继续下一例 |
| `@[comptime]` 函数内 | 保持现有规则，随编译期解释执行路径触发；false 为编译错误 |
| 其他普通函数内 | 保持现有规则，要求条件为编译期常量；false 为编译错误 |

该选择只扩展新 test 上下文，不改变已通过源码及现有“普通函数内动态条件
非法”的反例。执行时机由词法上下文决定，不能因优化器能否折叠条件而改变：
test 内 `$assert(false)` 仍是运行失败，`--no-run` 不触发它；运行时 if 的
未选分支不执行断言，条件只求值一次。test 内显式 `$函数(...)` 仍在编译期
求值，其中的编译期断言失败会使测试程序构建失败。

限制也须明确：从 test 调用普通 helper，不会把 helper 内原有 `$assert`
自动改成运行时断言；调用来源不是执行时机的传播规则。首版可在 test 内
断言 helper 的返回值，或由 helper 用条件分支调用 `testing.fail`。
把普通函数中的 `$assert` 一并推广为运行时内建会改变既有语义，另行评审。
本提案对 `$` 新增这一 test 上下文例外，实施时须同步编译期设计文档。

`libs/testing/` 首版仅保留按需导入的结果辅助函数：

| 接口 | 行为 |
| --- | --- |
| `fail(message *char) void` | 报告原因并结束当前用例 |
| `skip(reason *char) void` | 报告理由并结束当前用例，计入 SKIP |

这些函数只在测试执行环境内使用。不增加比较断言族、泛型比较、隐式错误
传播或可恢复异常；底层依赖限于 prelude 与测试运行时，不能 import
os/io/string，避免测试这些库时形成 `os → testing → os` 一类依赖环。

`$assert` 由编译器直接处理，已有源 token 可用于记录断言所在文件/行/列与
条件文本，无须先新增普通函数的调用位置反射能力。首版断言失败应报告完整
测试身份、断言位置、条件文本与自定义消息，并保留该用例 stdout/stderr。
`$assert` 与 `testing.fail/skip` 均已具备运行时失败/跳过报告：`YHTF`
记录带行、列与消息（最长 60 字节），`YHTS` 记录表示跳过；完整栈回溯和
自动展开比较两侧数值仍不在本期范围内。

输出示意（非当前实测）：

```text
PASS arithmetic::arithmetic.yh::test::正数相加
PASS arithmetic::arithmetic.yh::decltest::add
FAIL arithmetic::arithmetic.yh::test::负数与零
  断言位置: arithmetic.yh:14:5
  $assert(add(-2, 0) == -2)
结果: 2 passed; 0 skipped; 1 failed
```

## 7. 编译与执行结构

```mermaid
flowchart LR
    A[项目索引 / 单文件] --> B[按目标发现 test]
    B --> C[选中模块的测试体检查与现有 LLVM 流水线]
    C --> D[每个被测模块一个测试程序]
    D --> E[yh test 逐例启动子进程]
    E --> F[结果记录 + 退出状态 + 日志]
    F --> G[汇总与退出码]
```

test 是声明，索引或解析时不执行。`yh test` 先完成所有选中模块测试程序的
构建，成功后才开始逐例运行；构建失败停止命令，运行失败则继续后续用例。
普通走到块尾或执行 `return` 都返回到生成包装，只有该包装能够报告 PASS。
空块可以通过，不额外要求每例至少含一条断言。

YT1 只在测试模式下把测试体按临时无参 void 函数做语义检查，检查完回滚符号/
作用域，不进入受检快照或接口；真正降低为持久私有函数、生成入口与执行属于 YT2。
依赖模块使用生产对象，不收集依赖的测试。
不建立跨模块 pub 测试注册表，不为调用测试体增加 `.globl` 或 `.s.i` 导出。
被测模块原本有 main 时，由编译器提供测试启动入口并在测试变体内重命名
原程序入口、重绑定其内部引用；不得调用原 main，也不得产生两个链接入口。
这里“不得调用”指生成入口不自动调用；用例仍可显式调用原 main。
完整重绑定须覆盖递归与取地址，不能只重写一个输出符号名。

运行方式选择：首版默认串行，但 **每例启动新进程映像**，同模块多例共用
一次编译的测试程序，由私有 case id 选择执行；不是每例重新编译。
与单进程连续调用相比，多一次启动成本，换来断言失败/信号崩溃后继续运行、
进程内全局状态重新初始化，且无须先实现异常恢复。
文件、环境之外的系统资源等外部副作用仍须用例自行管理，不宣称完全隔离。

父进程通过专用结果通道接收 PASS/FAIL/SKIP 结束记录，并结合退出状态判定：
只有测试体正常返回后，生成的分派包装才写 PASS；提前 `exit(0)`、无结果退出、
信号、超时和结果/退出状态不一致都算失败。不能只凭退出码 0 判通过，也不能
仅凭某个保留退出码判跳过。结果通道与 stdout/stderr 分离，避免打印伪造成功。
testing 与生成入口共用最小运行时报告协议；初始化/报告属于编译器内部运行时
契约，不向业务模块增加公开测试函数。协议细节在 T2 固定并补故障用例。

使用显式 argv 执行，不经过 shell。计时复用单调时钟，超时终止并回收该用例
进程；启动的后代进程也须有明确清理策略，不能让继承日志描述符导致父进程挂起。
首版通过独立临时日志文件捕获输出，避免双管道写满造成死锁。

命令退出码：0 表示已选用例全部通过或显式跳过；1 表示编译/链接错误、
测试失败、崩溃、超时、启动失败或零用例；2 表示命令用法错误。

## 8. 缓存、自举与现有门禁

生产与测试对象使用独立缓存空间；测试键至少区分编译器身份、目标、优化等级、
所属项目/模块、源内容、活动导入和运行时协议版本，不能拿生产缓存冒充测试产物。
内部 case id/符号按稳定顺序生成，不含时间戳或机器绝对路径，以满足固定点。
全部生成物在项目 `tmp/yh-test/` 下（YT1/YT2a 已使用 `tmp/yh-test/check`），
单文件使用源文件所在目录的 tmp；
并发命令各用独立运行目录，不能覆盖生产产物或共享 LLVM 闭包缓存。

老种子不认识 test 语法，所以不能在实现开始时把 test 块直接塞进 compiler：
先用旧种子构建“能解析和执行 test、源码本身尚无 test 块”的新编译器，完成
门禁和候选自举，再依照滚种规则更新种子；之后才能给 compiler 模块添内嵌测试。
给 `compiler/` 加 test 块以滚种子为前提：入库种子必须支持 test 语法，
否则 `make`（种子冷编编译器源码）会失败。
发布说明须明确最低种子能力，外部 `.yh` fixture 可先由候选编译器验收。

新增 `yh test` 只承接语言内单元测试。编译失败反例仍在 `tests/yh-run/fail/`；
项目清单/导入/链接和命令行为仍由 `tests/modules/` 验收；自举两代固定点保持。
后续 make 门只增加对应标准库/编译器单元测试入口，不批量重写全部外部 runner。
本机验收只跑本平台；完整多平台继续交给 Gitea Actions。

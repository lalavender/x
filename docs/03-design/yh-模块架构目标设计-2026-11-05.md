# yh 模块架构目标设计（2026-11-05）

## 0. 文档定位

本文是 `compiler/` 模块组织的**目标架构**，后续模块级重构按本文执行。
与 `AGENTS.md` 冲突时以 AGENTS.md 为准，并回改本文。

约束前提（不可违反）：

- 滚动自举：任何结构变更必须过 `just` + `just test` + `just selfhost-native`
  三门，全绿后 `just seed` 滚种子；每阶段一次冷编 + 固定点，不做混合阶段。
- 模块导出面最小化（`pub` 只导出被跨模块使用的声明，ADR-0013 私有类型规则）。
- 平台特化文件统一按 `<name>.<os>[.<arch>].yh` 命名（`clock.darwin.yh`、
  `project_dir.linux.arm64.yh` 即此约定），扫描按文件名后缀筛选。
- 模块源码目录**支持子目录**（`pj_scan_entry` 对子目录递归），子目录内文件
  仍属同一模块——`build/cache/` 子目录方案由此可行。

## 1. 现状问题（2026-11-05 盘点）

| 问题 | 证据 |
|------|------|
| `gen` 是杂烩底座 | 13/17 模块依赖它；内含基础设施（buffer/clock/target/state）、语义模型（sem_*×6 + symbols 1233 行）、C ABI（abi_c）、静态数据四类无关物 |
| 缓存散落三处 | `build/module_cache.yh`、`build/function_ir_cache.yh`、`link/link_cache.yh`（1647 行），无公共键/失效/统计层 |
| `cmd` 两文件混合分派与实现 | `driver.yh`（分派，179 行）+ `api.yh`（全部命令实现，182 行），新增命令只能往 api.yh 堆 |
| `build` 超载 | 20 个文件 = 流水线 + 项目模型扫描（project*.yh 8 个）+ TOML 解析器（toml.yh 604 行）+ 缓存 |
| TOML 解析器重复 | `build/toml.yh` 与 `libs/toml` 并存 |
| `ast` 混入快照基础设施 | module_snapshot* 4 文件约 2.3k 行（CheckedModule 捕获/视图/切片/检查缓存），非 AST 关注点 |

## 2. 设计原则

1. **依赖单向、分层清晰**：上层可依赖下层，禁止反向与环。
2. **一个关注点一个家**：命令在 `cmd/`（一命令一文件）；缓存在 `build/cache/`；
   项目模型在 `proj/`；构建流水线在 `build/`；运行支撑在 `support/`。
3. **缓存三要素强制**：任何缓存必须同时给出——键组成、失效条件、存储路径
   （走 `proj_40_art` 产物路径层），并接 `gen.stats()`/`support.stats()` 统计。
4. **阶段化迁移**：每阶段独立可验收、可回滚（git + 固定点快照）。

## 3. 目标分层总览

```text
L4  入口     cmd（一命令一文件，导出面只有 main）
L3  驱动     build（纯流水线编排）  testkit  proj（项目模型/扫描/TOML/产物路径）
L2  前端     lex  parse  ast  check  comptime  lower
L1  中端     ir（不依赖任何 yh 模块）
L1  后端     backend（LLVM 描述）  link（工具链调用，缓存已移出）
L0  支撑     support（新：buffer/clock/target/state/统计）
L1.5 语义   sema（gen 更名瘦身：sem_*×6/symbols/model/front_stage/static_data）
```

目标依赖规则表（`→` 表示允许 import；`*` 为现有边的重命名映射）：

| 模块 | 允许依赖 |
|------|----------|
| support | 无 |
| ir | 无 |
| lex | support |
| ast | support, comptime |
| sema（原 gen） | support, proj |
| check | ast, sema, support, proj |
| comptime | sema, support, proj |
| parse | ast, comptime, lex, ir, sema, support, proj |
| lower | ast, ir, sema, support, proj |
| backend | ir, sema, support |
| proj | support（+ 评估后可加 libs/toml） |
| build | ast, backend, check, comptime, ir, lex, lower, parse, proj, sema, support |
| link | backend, proj, support（缓存迁出后不再依赖流水线） |
| testkit | build, parse, link, proj, sema, support |
| cmdline | support, libs/cli |
| cmd | 全部（入口唯一例外） |

说明：现有 `import gen` 的边按符号实际归属 1:1 改写为 `import support`
或 `import sema`；除表中列出的边外不得新增。

## 4. cmd/ 目标结构（一命令一文件）

```text
cmd/
  driver.yh         main：argv → 请求映射 + 子进程协议识别 + 分派（无业务）
  common.yh         命令共享前奏：state_init/proj.init/bind_cfg 次序、
                    API_* 形态常量、api_open_source、退出码契约注释
  cmd_build.yh      yh build / yh check（项目态，共享实现，两个入口）
  cmd_run.yh        yh run
  cmd_test.yh       yh test（含 --timeout 范围校验）
  cmd_list.yh       yh list [--resolve]
  cmd_version.yh    yh version / --contracts
  cmd_single.yh     单文件五形态：--syntax-check / --emit-asm / --emit-llvm /
                    -o <out> <file.yh> / check-with-src
  cmd_emit_module.yh  内部子进程协议 --emit-module（豁免 cli 的参数解析迁此）
  cmd_lld_link.yh     内部子进程协议 --lld-link（薄壳委托 link.mb_coff_link_child）
```

规则：

- `driver.yh` 只保留「解析 → 全局选项落状态 → 按命令分派」，每个分支不超过
  一行函数调用；no-fork 子进程协议（`--emit-module` 上界 23 项参数、
  `--lld-link`）的识别仍在 driver，豁免 cli 的理由不变（私有 ABI）。
- `api.yh` 拆散后**删除**；`api_*` 改为各 cmd_*.yh 的模块私有函数，
  cmd 模块导出面收缩为只有 `main`（当前无外部消费者，安全）。
- 退出码契约不变：0 成功、1 源/语义错误、2 用法错误、-1 内部或桥失败。
- 新增命令 = 新增一个 `cmd_<命令>.yh` + driver 一行分派 + cmdline 声明。

## 5. build/ 目标结构（流水线 + 统一缓存）

```text
build/
  build_ctx.yh          会话级构建上下文
  build_scheduler.yh    模块调度（fork / no-fork worker，PC3 冷构建判定）
  module_build.yh       单模块构建驱动
  module_worker.yh      worker 入口
  module_emit.yh        模块产物发射
  llvm_pipeline.yh      LLVM 流水线
  llvm_emit.yh          单文件 LLVM 发射
  stats_print.yh        统计输出
  unused_function.yh    未用函数裁剪
  cache/                ← 全部缓存唯一实现地（新增）
    cache_context.yh      公共层：缓存键（u64 salt / hex 编码）、manifest
                          读写、命中校验、mtime/哈希失效、命中统计上报
    module_cache.yh       模块 iface/产物缓存（自 build/ 根迁入）
    function_ir_cache.yh  函数级 IR 缓存 FIRC（自 build/ 根迁入）
    link_cache.yh         链接缓存（自 link/ 迁入；link 只留工具链调用）
    snapshot_cache.yh     受检快照检查缓存的宿主侧策略（对接
                          ast.checked_check_cache_*，占位，随 P2 或后置）
```

缓存规则（强制）：

1. **新增任何缓存必须放 `build/cache/`**，实现文件不得调用流水线文件
   （cache 是被流水线调用的底层；同模块内以调用方向约束）。
2. 每个缓存必须声明：键组成、失效条件、存储路径（经 `proj_40_art` 的
   产物路径与缓存键层，不自行拼路径）。
3. 命中/未命中必须进统计（stats），`YH_BUILD_CACHE` 语义不变
   （缓存位置迁移由该变量控制，不改变产物位置）。
4. `link_cache.yh` 是唯一跨模块搬家：link 模块职责收窄为
   「汇编/链接/lld/进程/时钟」调用层，与 AGENTS.md 对 link 的定义一致。

## 6. proj 吸收项目模型（build 收敛为纯流水线）

迁移清单：`project.yh`、`project_index.yh`、`project_resolve.yh`、
`project_link.yh`、`project_dir.<平台>.yh`×4、`toml.yh` → `proj/`。

- 前置校验：这批文件（`pj_*` 命名已预告归属）不得引用 build 其余符号；
  若有引用，先把被引符号下沉 proj 或改经 `proj.ctx()` 传递。
- `toml.yh` 与 `libs/toml` 二选一：先评估 `libs/toml` 对 project.toml
  解析需求的覆盖度（含 link-closure 生成节的容错读取），能覆盖则 compiler
  侧删除自研解析器；不能覆盖则保留并在本文记录差异清单。
- 迁移后 `build/` 只剩 §5 根目录九个流水线文件；
  `proj/` 职责 = 项目模型 + 源码扫描 + TOML + 产物路径/缓存键。

## 7. gen 拆分（P4，独立 ADR）

`gen/` 现有文件的目标归属：

| gen 现有文件 | 去向 | 理由 |
|--------------|------|------|
| buffer.yh | support | 纯缓冲区工具 |
| clock.darwin/linux.arm64/linux.x64/windows.x64.yh | support | 平台时钟 |
| state.yh | support | TaskCtx/GenState 会话状态，cmd/build 直接消费 |
| target.yh、target_info.yh | support | 目标三元组选择与描述 |
| abi_c.yh | support | C ABI 描述（后端/link 消费的目标知识） |
| model.yh | sema | 语义模型 |
| sem_call_literal/decl/expr/flow/value.yh | sema | 语义分析 |
| symbols.yh（1233 行） | sema | 符号表；拆分时顺带评估按 decl/expr 内聚再分 |
| front_stage.yh | sema | 前端阶段驱动 |
| static_data.yh | sema | 静态数据段准备 |

执行要点：

- 新模块目录 `compiler/support/`；`gen` 更名瘦身后的目录为 `compiler/sema/`
  （模块名同步改），全仓 `import gen` 按符号归属改写为 `import support`
  或 `import sema`。
- `gen.task()`/`gen.stats()` 等窄口随 state 落在 support：`support.task()`、
  `support.stats()`。
- 完成后 `gen` 目录删除；模块计数 17 → 18。
- 本阶段改动面最大（预计 60+ 文件的 import 行），必须单独 ADR +
  独立阶段执行，验收门不变（固定点 + 全语料 + seed）。

## 8. ast 快照基础设施（P5，候选）

`module_snapshot*.yh` 是 CheckedModule 的捕获/视图/切片导入/检查缓存键，
被 check、lower、build、cmd 消费。**不能**搬进 build（lower→build 会成环）。
两个选项：

- 选项 A（默认）：保留在 ast，接受命名噪音；
- 选项 B：新 `snapshot` 模块（依赖 ast/ir/support），ast 回归纯 AST。

默认选项 A，待 P4 完成后按实际内聚痛感决定是否立项。

## 9. 阶段计划与验收门

| 阶段 | 内容 | 风险 | 前置 |
|------|------|------|------|
| P1 | cmd 一命令一文件（§4） | 低：纯 cmd 内重组，无行为变化 | 无 |
| P2 | build/cache/ 落地 + link_cache 迁入（§5） | 中：iface/哈希变化，注意固定点 | 无 |
| P3 | 项目模型 → proj + TOML 合并评估（§6） | 中：需先跑 pj_* 符号引用校验 | P2 |
| P4 | gen 拆 support/sema（§7，独立 ADR） | 高：全仓 import 改写 | P1–P3 |
| P5 | snapshot 独立模块（§8，候选） | 中 | P4 |

每阶段统一验收：

1. `just` 冷编 + 新 yh 自编，两代 `.s`/`.s.i` 逐字节相同（固定点）；
2. `just test` + `just selfhost-native` 全绿；
3. `just seed` 滚种子；
4. 结构性变更在 `tests/modules/` 或 `tests/yh-run/` 补用例（导出面/模块
   私有类型的验收走既有 modules 项目门）；
5. `docs/finish.md` 记录，涉及决策的立 ADR 归档 `docs/adr/`，并同步
   AGENTS.md 的模块清单与本文。

## 10. 风险与对策

- **种子滚动成本**：五个阶段 = 五次冷编 + 固定点 + seed。不得合并阶段
  （合并后回滚粒度消失）。
- **link_cache 迁移**：`.s.i` 接口变化会影响缓存键，P2 落地当代缓存
  全部失效属预期，需在 finish 流水注明。
- **cmd 导出面收缩**：`api_*` 转私有后，若未来 testkit/外部工具需要复用
  单文件编译，应经 `build.llvm_emit_single_file` 而非 cmd。
- **TOML 合并**：`build/toml.yh` 需容忍 `tools/link-closure.py` 生成节的
  重复键与追加写；`libs/toml` 覆盖度评估结论必须落本文附录后再动手。
- **no-fork 平台（Windows）**：子进程协议参数上限 23 项的注释与校验逻辑
  随 `cmd_emit_module.yh` 迁移，不得改动语义。

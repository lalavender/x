# yh memory 标准库设计

日期：2026-10-23（第二版，参考 Zig `std.mem.Allocator` 与 `std.heap`）。
状态：**设计（未实施，等待确认）**。
目标：在 `libs/memory` 固化现有堆 API，并按 Zig 标准库的分配器分层补齐
`FixedBuffer`、增强 `Arena`、把 `FixedPool` 改为“Arena + 空闲链”，同时给出
可选的统一 `Allocator` 接口；不引入 GC、析构、线程安全或 Zig 的错误类型。

分期与验收见[实施方案](../02-plan/yh-memory标准库实施方案-2026-10-23.md)。

## 1. 范围与 Zig 参考

Zig 的内存管理由两层组成：

- `std.mem.Allocator`：统一分配器接口，vtable 固定为 `alloc`/`resize`/
  `remap`/`free`，错误只有 `error.OutOfMemory`；`free` 必须带长度与对齐，
  `resize` 尝试原地调整，`remap` 允许移动（返回 `null` 表示“调用方自行
  分配+复制+释放”），`realloc` 是三者之上的组合。
- `std.heap`：具体实现与包装，包括 `ArenaAllocator`、`FixedBufferAllocator`、
  `PageAllocator`、`MemoryPool`、`DebugAllocator`、`ThreadSafeAllocator`、
  `StackFallbackAllocator` 等。

本设计借鉴其**能力分层与语义**，按 yh 的语言事实调整：

首版设计承诺：

- 保留并固化现有 `alloc`/`release`/`copy` 的签名、返回值与失败语义；
- 新增 `reallocate`，补上“分配—复制—释放”组合；
- 新增 `FixedBuffer`：调用方提供缓冲区、零系统调用、支持最近分配的
  `resize`/`free` 与 `reset`（对应 Zig `FixedBufferAllocator`）；
- 增强 `Arena`：块几何增长、`reset` 模式、最近分配的 `resize`/`free`、
  `capacity` 查询（对应 Zig `ArenaAllocator`）；
- 定义 `FixedPool`：基于 Arena 与空闲链的固定大小池、`reserve` 预分配、
  `reset` 模式（对应 Zig `MemoryPool`）。

按需实施、设计只给契约：

- 统一 `Allocator` 接口（函数指针 vtable）列为 M5 可选层，见 §11；
- 调试分配器、线程安全包装、页分配适配器、StackFallback 列为 M6 后置候选，
  见 §2、§15。

明确不做：

- 垃圾回收、引用计数、自动析构、RAII；
- 线程安全分配器或内置锁；
- 泛型分配器接口（yh 没有泛型/接口；统一接口只能用函数指针 + context）；
- 替代 C ABI 的 `malloc`/`free` 符号（属 `libs/libc` L1.4，未实施）；
- 页映射封装（`libs/sys` 已有 `map_memory`/`unmap_memory`）；
- 修改 prelude、编译器 `gen/` 或现有 `string`/`toml` 的分配实现。

## 2. Zig 模块对照

| Zig | yh 设计 | 决策 |
| --- | --- | --- |
| `std.mem.Allocator`（vtable 四方法） | §11 `Allocator`（函数指针 + context） | M5 可选；首版直接 API 优先 |
| `ArenaAllocator` | §9 `Arena` | M3；几何增长、reset 模式、LIFO `resize`/`free` |
| `FixedBufferAllocator` | §8 `FixedBuffer` | M2；无系统调用，LIFO 语义 |
| `PageAllocator` | 不新增模块 | prelude `malloc` 每次直接 `mmap`，等价页分配；显式页映射用 `sys.map_memory` |
| `MemoryPool` | §10 `FixedPool` | M4；内部用 Arena + 空闲链，`block_size` 代替泛型 `Item` |
| `DebugAllocator` | §15 后置 | 无栈回溯；prelude `free` 立即 `munmap`，无法安全检测重复释放 |
| `ThreadSafeAllocator` | §14 不做 | yh 无 mutex/原子原语，等 J4 线程池 |
| `StackFallbackAllocator` | §15 后置 | 依赖 M5 `Allocator` + M2 `FixedBuffer` |
| `SmpAllocator`/`WasmAllocator`/`SbrkAllocator` | 不做 | 平台专属，无消费者 |
| `c_allocator`/`raw_c_allocator` | `libs/libc` L1.4 | 不与 prelude 混用 |
| `Allocator.failing` | M5 `failing_allocator()` | 测试用，分配恒失败 |

## 3. 现状基线

以下事实按当前工作区源码核对：

| 事实 | 依据 |
| --- | --- |
| `libs/memory` 只有 3 个函数，共 18 行，无 README/doc.yh/专项测试 | [`libs/memory/memory.yh`](../../libs/memory/memory.yh) |
| `alloc`/`release`/`copy` 分别转发 prelude 的 `malloc`/`free`/`memcpy` | 同上；[`compiler/builtin/prelude.yh`](../../compiler/builtin/prelude.yh) 56–72 行 |
| prelude 的 `malloc`/`free`/`memcpy` 是 `F_INTRINSIC` + 运行时内建，由后端发射 weak 定义 | `prelude.yh` 同上；[`llvm_runtime.yh`](../../compiler/backend/llvm_runtime.yh) 167–190 行 |
| Linux 每次 `malloc` 执行一次 `mmap`，前 16 字节记录映射长度，用户指针 16 字节对齐；`free` 读头部后一次 `munmap` | `llvm_runtime.yh` 167–190 行 |
| Darwin 布局相同，底层走 libSystem `mmap`/`munmap` | [`llvm_apple_runtime.yh`](../../compiler/backend/llvm_apple_runtime.yh) 23–40 行 |
| `malloc(0)` 返回非空指针；`size > 2^64-17` 返回空指针；`free(0)` 无操作 | 运行时实现同上 |
| 没有 `realloc`/`calloc`/对齐分配/容量或统计接口 | `libs/memory` 与 prelude 均无 |
| `string` 每次内容/状态分配都调用 `memory.alloc`，自行完成增长与重叠复制 | [`libs/string/owned.yh`](../../libs/string/owned.yh) 14–76 行 |
| `toml` 已实现私有块池：块用 `malloc`，整池 `free_all`，含失败注入与预算 | [`libs/toml/document.yh`](../../libs/toml/document.yh) 9–35、123–190 行 |
| `sys` 已提供跨平台 `map_memory`/`unmap_memory`，但 `memory` 不使用 | [`libs/sys/memory.linux.yh`](../../libs/sys/memory.linux.yh)、[`memory.darwin.yh`](../../libs/sys/memory.darwin.yh) |
| 编译器 `gen/buffer.yh` 等直接调用 prelude `malloc`/`free`，不经标准库 | `compiler/gen/buffer.yh` |

结论：现有 `memory` 是“prelude 三件套”的薄转发。与 Zig 相比，缺少的是
**可复用的缓冲区分配器**、**Arena 的回收/增长语义**、**基于空闲链的固定块池**
与**统一分配器接口**；`string`/`toml` 已各自造了局部方案。

## 4. 语言事实与约束

- 没有泛型、接口、方法、反射、闭包；不能定义“任意分配器”的抽象类型。
- 没有析构与 `defer`；所有权必须由调用方显式 `release`/`reset`。
- 结构体按值复制，复制句柄**不增加所有权**（`string.String` 同此规则）。
- 模块私有类型不得出现在 `pub` 签名、`pub` 字段或 `pub` 别名里
  （[ADR-0013](../adr/0013-yh模块私有类型.md)），因此公开结构体只能持有
  `*void` 句柄或标量配置。
- `sizeof`、`&`/`|`/`~`/移位、指针→`u64`、函数指针均可用；项目内已有
  函数指针字段先例（[`libs/cli/cli.yh`](../../libs/cli/cli.yh) 的
  `converter`/`validator`、[`libs/cli/extensions.yh`](../../libs/cli/extensions.yh)
  的调用点），因此 M5 的 vtable 不需要新语法。
- 无异常、无 `error` 类型；失败用 0（指针）或 0/1（`resize`/`free`）。
- 无栈回溯、无 mutex/原子原语；调试分配器与线程安全包装受限（§14、§15）。
- 标准库模块是普通 yh 项目；本设计不增加模块级可变状态（测试注入常量除外）。
- 语言没有标准线程 API；本设计的对象不宣称线程安全。

## 5. 方案取舍

| 方案 | 优点 | 代价与结论 |
| --- | --- | --- |
| A. 只保留现状三个 API | 零改动 | 每次小分配一次 `mmap`+`munmap`；消费者继续各自造池；无对齐/重分配契约；否决 |
| B. 以通用 `Allocator` vtable 为唯一入口（Zig 路线） | 接口统一、可组合、对齐/长度语义完整 | yh 无泛型容器，现有 `string`/`toml` 不接受分配器参数；间接调用与改造面大；首版成本高；作为 M5 可选，不做唯一入口 |
| C. `memory` 自带完整堆（size class、bin、合并） | 不依赖 prelude | 与运行时 `malloc` 重复，破坏“同一实现分配/释放”的配对原则，还要迁移编译器；否决 |
| **D. 直接 API + Zig 语义（FixedBuffer、Arena 增强、Pool 基于 Arena），M5 再加 vtable** | 依赖少、可逐片验收、对齐 Zig 的能力划分 | 组合能力（Arena child）要等 M5；采用 |
| E. 直接改走 `sys.map_memory` 取块 | 页对齐、错误码显式 | `memory` 新增 `sys` 依赖，与现有 `string`/`toml` 的 prelude 来源分叉；核心不做，页对齐由 `sys` 承担 |
| F. 等 libc L1.4 的 C ABI 分配器 | 与 C 互操作统一 | 未实施，且短期无法解决批量分配；后置评估（§13） |
| G. 完整移植 `DebugAllocator` | 检测能力强 | 无栈回溯；prelude 释放即 `munmap`，无法安全保留元数据；M6 只做简化版 |
| H. 移植 `ThreadSafeAllocator` | 并发可用 | 无 mutex/原子原语；等 J4；不做 |

采用 D。关键取舍：

- **核心直接 API 不依赖 vtable**：无泛型容器消费者时，`Allocator` 只会增加
  间接调用与调用点噪音；先把 `FixedBuffer`/`Arena`/`Pool` 的具体语义做对。
- **块来源统一为 prelude `malloc`/`free`**，不重复实现 mmap 判错、页对齐与
  `munmap` 长度；Arena/Pool 只负责把大块切成小片。
- **`resize`/`remap` 只在支持原地调整的分配器上实现**：prelude 堆没有可用的
  头部空间与 size class，`resize` 恒失败、`remap` 恒返回 0；`reallocate`
  仍是堆上的组合路径。
- **不读取运行时分配头**：prelude 头部只记录映射长度、不记录用户请求长度；
  因此所有 `resize`/`free`/`reallocate` 都要求调用方提供旧长度（与 Zig 的
  slice 语义一致）。
- **具体类型而非抽象接口**：Arena/FixedBuffer/FixedPool 各自是具体结构体；
  M5 的 `Allocator` 只是它们的适配器，不是核心依赖。

## 6. 分层与所有权

```text
调用方
  ├─ alloc / release / copy / reallocate     单个对象、heap
  │        └─ prelude malloc / free          yh 运行时，每次页映射
  ├─ FixedBuffer                             调用方缓冲区、零系统调用
  ├─ Arena                                   批量、同生命周期、块几何增长
  │        └─ 块：prelude malloc/free（M5 可换 child Allocator）
  ├─ FixedPool                               固定大小节点
  │        └─ 内部 Arena + 空闲链
  └─ Allocator（M5）                         可选统一接口，适配以上实现
sys.map_memory / unmap_memory                显式页映射，不经 memory
libs/libc 的 C ABI malloc/free               规划中，不与 prelude 混用
```

所有权规则：

1. 谁分配谁释放；`alloc` 的返回值只能交给 `release`/`reallocate`。
2. `FixedBuffer` 不拥有缓冲区；`free` 只回收最近分配，`reset` 重置游标。
3. `Arena` 拥有其块，不拥有块内对象；`arena_reset`/`arena_release` 后此前
   返回的所有地址立即失效，不调用析构。
4. `FixedPool` 拥有内部 Arena 与空闲链；`pool_free` 只把块放回空闲链，
   `pool_reset` 重置内部 Arena，`pool_release` 释放块。
5. 复制 `Arena`/`FixedPool`/`FixedBuffer` 句柄只复制字段，不新增所有者；
   对同一句柄重复 `release` 或两个副本各释放一次是未定义行为。
6. 分配与释放必须配对到**同一实现**：prelude 分配的块不能交给 `libc` 的
   `free`；`Allocator` 的 `free` 必须使用与该次 `alloc` 相同的分配器、
   长度与对齐。

## 7. 堆兼容层

### 7.1 现有 API（签名与语义不变）

| API | 契约 |
| --- | --- |
| `alloc(byte_count u64) *void` | 申请指定字节数；失败返回 0；`0` 返回非空地址；结果至少 16 字节对齐；不初始化内容 |
| `release(data *void) void` | 释放 `alloc`/`reallocate` 返回的地址；允许 0；重复释放、释放非本堆地址为未定义行为 |
| `copy(destination *void, source *void, byte_count u64) *void` | 复制指定字节数并返回目标；源与目标重叠时未定义（需要重叠复制用 `libc.memmove`）；不检查空指针 |

改动仅限文档与测试固化，函数体不变。

### 7.2 `reallocate`

```yh
pub fn reallocate(data *void, old_size u64, new_size u64) *void
```

| 情形 | 行为 |
| --- | --- |
| `data == 0` | 等价 `alloc(new_size)`；`old_size` 忽略；**优先于下一行** |
| `data != 0 && new_size == 0` | 释放 `data` 并返回 0 |
| `new_size < old_size` | 分配 `new_size`，只复制前 `new_size` 字节，释放旧块 |
| `new_size > old_size` | 分配 `new_size`，复制 `old_size` 字节，释放旧块 |
| 新分配失败 | 返回 0，**旧块与内容保持不变** |
| 其他 | 成功后旧指针失效；返回值至少 16 字节对齐 |

为什么需要 `old_size`：prelude 头部只记录 `mmap` 总长度，不记录用户请求长度；
标准库无法从 `data` 反推出复制多少字节。传错 `old_size` 是未定义行为。
实现顺序固定为“先分配 → 按较小者复制 → 成功后释放旧块”，失败不破坏旧块。

### 7.3 堆为什么不提供 `resize`/`remap`

Zig 的 `Allocator.resize` 依赖分配器能原地调整（size class、页映射或子分配器）。
prelude 堆每次分配是独立 `mmap`，头部只有一个总长度字段，无法在不移动的情况下
改变用户长度，也无法把两个映射合并。因此：

- 直接 API 只提供 `reallocate`（分配+复制+释放）；
- `resize`/`remap` 属于 `FixedBuffer`/`Arena` 与 M5 `Allocator` 适配器；
- M5 的 heap 适配器 `resize` 恒失败、`remap` 恒返回 0，`allocator_reallocate`
  自动落到“分配+复制+释放”。

### 7.4 为什么没有堆上的任意对齐分配

堆上的任意对齐分配需要在前置头部保存原始指针，并配一个只能用于对齐结果的
释放函数；一旦调用方误用普通 `release`，就会读到错误头部并 `munmap` 错地址。
首版不提供这种易误用的配对 API；大于 16 字节的对齐用
`fixed_buffer_alloc_aligned`/`arena_alloc_aligned`。M5 的 `Allocator` 适配器
要求 `free` 带对齐，届时可安全地补 heap 对齐分配（M6 候选）。

## 8. FixedBuffer（M2）

### 8.1 模型

```yh
// FixedBuffer 在调用方提供的连续缓冲区上线性分配，零系统调用。
// buffer 由调用方保管，FixedBuffer 不拥有也不释放它。
pub struct FixedBuffer {
    buffer *u8
    capacity u64
    used u64
}
```

- 零值无效（`buffer == 0` 或 `capacity == 0`），所有分配返回 0。
- 分配按绝对地址对齐；`used` 记录已用字节数。
- 不维护块头，也不调用 prelude；属于“有界 bump 分配器”。

### 8.2 API

| API | 契约 |
| --- | --- |
| `fixed_buffer_init(buffer *u8, capacity u64) FixedBuffer` | 绑定缓冲区；`buffer == 0` 或 `capacity == 0` 返回零值 |
| `fixed_buffer_alloc(fb *FixedBuffer, byte_count u64) *void` | 16 字节对齐；失败返回 0 |
| `fixed_buffer_alloc_aligned(fb *FixedBuffer, byte_count u64, alignment u64) *void` | 按绝对地址对齐；`alignment` 为 0 或非 2 的幂返回 0 |
| `fixed_buffer_resize(fb *FixedBuffer, data *void, old_size u64, new_size u64) int` | `new_size > 0`；最近分配可原地调整（缩小/扩大）；非最近分配只允许逻辑缩小，返回 1 但不回收空间；其余返回 0；`new_size == 0` 返回 0（释放用 `fixed_buffer_free`） |
| `fixed_buffer_free(fb *FixedBuffer, data *void, byte_count u64) int` | 仅最近分配回收；返回 1 表示回收，0 表示 no-op |
| `fixed_buffer_reset(fb *FixedBuffer) void` | `used = 0`；此前地址全部失效 |
| `fixed_buffer_owns(fb *FixedBuffer, data *void) int` | 地址落在 `[buffer, buffer+capacity)` 内返回 1；仅用于调试/断言 |
| `fixed_buffer_capacity(fb *FixedBuffer) u64` | 返回缓冲区容量 |
| `fixed_buffer_used(fb *FixedBuffer) u64` | 返回已用字节数 |

补充语义：

- `byte_count == 0`：返回当前对齐地址，不推进 `used`。
- 分配失败（空间不足或溢出）返回 0，`used` 不变。
- `free`/`resize` 不校验 `data` 是否属于本缓冲区；误用是未定义行为，
  `fixed_buffer_owns` 只是辅助断言。
- 非最近分配的“逻辑缩小”与 Zig `FixedBufferAllocator.resize` 一致：
  调用方可以认为新长度有效，但底层游标不回收，空间在 `reset` 前不会复用。
- 对齐 padding 在 `free` 时保留（与 Zig 相同）；后续分配会再次跳过它。

### 8.3 示例

```yh
import memory

fn main() int {
    let buffer [256]u8
    let fb memory.FixedBuffer = memory.fixed_buffer_init(&buffer[0], 256)
    let first *u8 = memory.fixed_buffer_alloc(&fb, 32).to_type(*u8)
    if (first == 0) { return 1 }
    let second *u8 = memory.fixed_buffer_alloc_aligned(&fb, 16, 64).to_type(*u8)
    if (second == 0 || second.to_type(u64) % 64 != 0) { return 2 }
    if (memory.fixed_buffer_free(&fb, second.to_type(*void), 16) != 1) { return 3 }
    memory.fixed_buffer_reset(&fb)
    return 0
}
```

## 9. Arena（M3）

### 9.1 模型

```yh
// Arena 是批量分配器：块按需映射，分配线性推进，reset/release 整批回收。
// 零值等价默认块大小且尚未映射；块大小只由 arena_init 设置。
pub struct Arena {
    head *void       // 最新块；模块私有布局，零表示无块
    block_size u64   // 0 表示默认；只由 arena_init 设置
}

// 默认块大小是实现常量（当前 64 KiB），不导出；arena_init(0) 使用它。
const ARENA_DEFAULT_BLOCK_SIZE u64 = 65536

// reset 模式：free_all 释放全部块；retain 保留最新块并释放其余块。
// 与 Zig 的 retain_capacity 不同，受限于 prelude 无 realloc，不做预扩。
pub enum ArenaResetMode {
    arena_reset_free_all
    arena_reset_retain
}
```

- 字段公开是语言规则；`head` 只允许本模块解释，直接改写字段属于违约。
- 块头是模块私有结构（示意）：

```yh
// arena_block 是映射块的前置头；payload 从 16 字节对齐偏移开始。
// size 是本块申请字节数，used 是 payload 已用字节数。
struct arena_block {
    next *arena_block
    size u64
    used u64
}
```

### 9.2 API

| API | 契约 |
| --- | --- |
| `arena_init(block_size u64) Arena` | 返回新的空 Arena：`0` 用默认块大小，非零向上取整到 16；不映射。只能用于尚未持有块的 Arena；对已有块的 Arena 重新 init 会丢失旧句柄（内存泄漏），必须先 `arena_release` |
| `arena_alloc(arena *Arena, byte_count u64) *void` | 16 字节对齐；失败返回 0 |
| `arena_alloc_aligned(arena *Arena, byte_count u64, alignment u64) *void` | 按绝对地址对齐；`alignment` 为 0 或非 2 的幂返回 0 |
| `arena_resize(arena *Arena, data *void, old_size u64, new_size u64) int` | `new_size > 0`；最近分配可原地调整；非最近分配只允许逻辑缩小（返回 1，不回收）；其余返回 0；`new_size == 0` 返回 0（释放用 `arena_free`） |
| `arena_free(arena *Arena, data *void, byte_count u64) int` | 仅最近分配回收；返回 1 表示回收，0 表示 no-op |
| `arena_reset(arena *Arena, mode ArenaResetMode) void` | `free_all` 释放全部块并归零；`retain` 保留最新块（`head`），释放其余块，`used = 0` |
| `arena_release(arena *Arena) void` | 释放全部块，`head` 归零；`block_size` 保留，便于复用 |
| `arena_capacity(arena *Arena) u64` | 所有块 payload 容量之和（不含块头）；用于调试/预算 |

补充语义：

- `byte_count == 0`：返回当前块内的非空对齐地址，不推进 `used`；若尚无块则先
  映射。
- 失败（块不足且新块映射失败）返回 0；已分配内容保持可读，状态不被破坏。
- `arena` 参数为空指针：未定义行为。
- 对齐余量、块大小、`used + 请求` 的加法都做溢出检查；检查失败返回 0。
- `arena_resize`/`arena_free` 的“最近分配”按 `data + old_size == payload + used`
  判断（与 Zig 一致）；非最近分配不回收，空间在 reset 前不会复用。
- 块头不进入用户可见区域；用户指针永远指向 payload 内。

### 9.3 分配与几何增长

1. 计算 `address = align_up(payload + used, alignment)`，`slot = address - payload`；
   若 `slot + byte_count` 不超过当前块容量，推进 `used` 并返回 `address`。
   对齐必须按**绝对地址**计算：块来自 prelude 堆，只保证 16 字节对齐，payload
   本身不保证大于 16 的对齐。
2. 否则映射新块：新块大小取以下三者的较大值，并向上取整到 16：
   - `block_size`；
   - 当前块 `size + size / 2`（几何增长，约 1.5 倍）；
   - 块头开销 + 对齐余量 + `byte_count`。
   新块挂到链头，成为当前块。
3. 新块映射失败返回 0；旧块链表与已分配数据不变。
4. `arena_reset(free_all)` 从链头释放全部块；`arena_reset(retain)` 保留链头
   （最新块），释放其余块并把它的 `used` 归零。
5. `arena_release` 释放全部块，`head = 0`。

与 Zig 的差异：Zig 的 `createNode` 会把最后一块 `resize` 到总容量以
“预热”；yh 的 prelude 不支持 `resize`，所以 `retain` 只保留最新块的现有
容量，不预扩。文档明确该差异，不用“retain_capacity”这个名字误导。

### 9.4 示例

```yh
import memory

fn main() int {
    let arena memory.Arena = memory.arena_init(4096)
    let first *u8 = memory.arena_alloc(&arena, 64).to_type(*u8)
    if (first == 0) { return 1 }
    first[0] = 7
    let block *u8 = memory.arena_alloc_aligned(&arena, 128, 64).to_type(*u8)
    if (block == 0 || block.to_type(u64) % 64 != 0) { return 2 }
    if (memory.arena_free(&arena, block.to_type(*void), 128) != 1) { return 3 }
    memory.arena_reset(&arena, memory.arena_reset_retain)
    memory.arena_release(&arena)
    return 0
}
```

## 10. FixedPool（M4）

### 10.1 模型

Zig 的 `MemoryPool` 由 `ArenaAllocator.State` + 空闲链组成，`create`/`destroy`
复用块。yh 没有泛型，用 `block_size` 代替 `Item`，结构直接持有内部 `Arena`：

```yh
// FixedPool 是固定块大小池：块从内部 Arena 分配，free 后进入空闲链复用。
// 零值（block_size == 0）表示未初始化；必须先 pool_init。
pub struct FixedPool {
    arena Arena
    free *void        // 空闲块链；块首 8 字节存 next
    block_size u64    // 对齐后的块大小；0 表示未初始化
    alignment u64     // 块对齐；至少 16，2 的幂
}
```

- 块大小由 `pool_init` 向上取整到 `max(16, alignment)`。
- 空闲块首 8 字节写入 `next`，因此最小块大小 16。
- 池不再自己管理 chunk；块来自内部 Arena，`pool_reset` 直接重置 Arena。

### 10.2 API

| API | 契约 |
| --- | --- |
| `pool_init(block_size u64) FixedPool` | `block_size == 0` 返回零值；否则对齐到 16，内部 Arena 用默认块大小；不预分配。只能用于空池；重复 init 会丢失旧 Arena，必须先 `pool_release` |
| `pool_init_aligned(block_size u64, alignment u64) FixedPool` | 同上；`alignment` 为 0 或非 2 的幂返回零值；对齐至少 16，块大小向上取整到该对齐 |
| `pool_reserve(pool *FixedPool, count u64) int` | 预分配 `count` 个块放入空闲链；成功 1，失败 0（已分配的块保留在链中，可继续使用） |
| `pool_alloc(pool *FixedPool) *void` | 从空闲链取块；空则从 Arena 分配；失败 0；零值池返回 0 |
| `pool_free(pool *FixedPool, block *void) void` | 归还单块；`block == 0` 无操作；零值池无操作；不解除映射；重复归还、跨池归还、非块首地址为未定义行为 |
| `pool_reset(pool *FixedPool, mode ArenaResetMode) void` | 清空空闲链并重置内部 Arena（模式见 §9）；此前返回的块全部失效 |
| `pool_release(pool *FixedPool) void` | 释放内部 Arena，`free = 0`；`block_size`/`alignment` 保留，可直接再次 `pool_alloc` |

补充语义：

- `pool_alloc` 分配到的块内容不初始化。
- 池不记录“哪些块已发放”；`pool_reset` 直接把所有块视为失效，因此 reset
  之前的块不能再使用，也不能再 `pool_free`。
- `pool_reserve` 的 `count == 0` 返回 1；失败时已预分配的块留在空闲链中，
  调用方可以先使用这些块，再重试 reserve。
- 与 Zig 的差异：没有泛型 `Item`、没有 `growable=false`（池始终可增长）、
  没有 `initCapacity` 的错误返回（用 `pool_reserve` 的 0/1）。

### 10.3 示例

```yh
import memory

fn main() int {
    let pool memory.FixedPool = memory.pool_init(48)
    if (memory.pool_reserve(&pool, 8) != 1) { return 1 }
    let node *u8 = memory.pool_alloc(&pool).to_type(*u8)
    if (node == 0) { return 2 }
    node[0] = 1
    memory.pool_free(&pool, node.to_type(*void))
    let again *u8 = memory.pool_alloc(&pool).to_type(*u8)
    // 空闲链后进先出；地址相等用 u64 比较，避免依赖指针关系运算。
    if (again == 0 || again.to_type(u64) != node.to_type(u64)) { return 3 }
    memory.pool_reset(&pool, memory.arena_reset_retain)
    memory.pool_release(&pool)
    return 0
}
```

`again == node` 只保证“同一实现、刚归还的块优先复用”，不是跨实现的稳定
顺序契约。

## 11. Allocator 统一接口（M5，可选）

Zig 的 `Allocator` 是四方法 vtable；yh 没有接口/泛型，但支持函数指针字段，
可以等价表达。**首版不作为核心入口**，只在 M5 实施，供未来容器或需要组合
分配器时使用。

### 11.1 类型

```yh
// AllocFn 分配 len 字节，按 alignment（字节，2 的幂；0 表示默认 16）对齐；
// 失败返回 0。context 是具体分配器的状态指针。
pub type AllocFn = fn(*void, u64, u64) *void

// ResizeFn 尝试原地调整：data 必须是最近一次成功 alloc/resize/remap 的结果，
// old_size/alignment 必须与分配时一致。成功返回 1，不移动；否则返回 0。
pub type ResizeFn = fn(*void, *void, u64, u64, u64) int

// RemapFn 允许移动：返回 0 表示“无法比分配+复制+释放更高效”，由调用方自行
// 复制；非 0 表示新地址（可能与旧地址相同），旧地址已失效。
pub type RemapFn = fn(*void, *void, u64, u64, u64) *void

// FreeFn 释放 data；len/alignment 必须与分配时一致。允许 data == 0。
pub type FreeFn = fn(*void, *void, u64, u64) void

// Allocator 是值类型；复制不增加所有权，context 的生命周期由实现方保证。
pub struct Allocator {
    context *void
    alloc_fn AllocFn
    resize_fn ResizeFn
    remap_fn RemapFn
    free_fn FreeFn
}
```

### 11.2 包装函数

| API | 契约 |
| --- | --- |
| `allocator_valid(a *Allocator) int` | `alloc_fn`/`free_fn` 非 0 返回 1（用 `to_type(*void)` 判空） |
| `allocator_alloc(a *Allocator, byte_count u64) *void` | 默认 16 对齐；失败 0 |
| `allocator_alloc_aligned(a *Allocator, byte_count u64, alignment u64) *void` | 0 或非 2 的幂返回 0 |
| `allocator_resize(a *Allocator, data *void, old_size u64, new_size u64, alignment u64) int` | `new_size == 0` 时等价 free 并返回 1；否则转发 vtable |
| `allocator_remap(a *Allocator, data *void, old_size u64, new_size u64, alignment u64) *void` | `new_size == 0` 时 free 并返回 0；否则转发 vtable |
| `allocator_free(a *Allocator, data *void, byte_count u64, alignment u64) void` | 转发 vtable；`data == 0` no-op |
| `allocator_reallocate(a *Allocator, data *void, old_size u64, new_size u64, alignment u64) *void` | 依次尝试 `resize` → `remap` → `alloc + copy + free`；与 Zig `realloc` 一致 |

- `allocator_reallocate` 的失败保留旧块；新分配失败返回 0。
- 组合路径复制 `min(old_size, new_size)` 字节；成功后释放旧块。
- `remap` 返回 0 不是错误，只是“调用方复制更合适”。

### 11.3 适配器

| API | 实现 | 限制 |
| --- | --- | --- |
| `heap_allocator() Allocator` | alloc 用 `memory.alloc`；resize 恒 0；remap 恒 0；free 用 `memory.release` | alignment 只支持 <= 16；更大的对齐返回 0（M6 可补过分配） |
| `arena_allocator(arena *Arena) Allocator` | alloc 用 `arena_alloc_aligned`；resize/free 用 Arena 的最近分配语义；remap 成功时返回同地址 | 非最近分配的 resize 只允许逻辑缩小；free 非最近 no-op |
| `fixed_buffer_allocator(fb *FixedBuffer) Allocator` | 同上 | 同上；容量由调用方缓冲区决定 |
| `pool_allocator(pool *FixedPool) Allocator` | alloc 只接受 `len <= block_size`，返回一个块；free 归还；resize/remap 恒 0 | 固定块，不支持变长 |
| `failing_allocator() Allocator` | alloc 恒 0；resize/remap 0；free no-op | 测试用 |

`Allocator` 的适配器函数返回的是值；每次调用都构造一个新的 `Allocator`，
但 vtable 与 context 不变，不分配内存。

### 11.4 为什么 M5 而不是首版核心

- yh 没有泛型容器/接口，现有 `string`/`toml` 也不接受分配器参数；先把
  `FixedBuffer`/`Arena`/`Pool` 的具体 API 做对，收益更直接。
- vtable 会引入间接调用和每个调用点的 `context` 争论；没有消费者时属于
  过度设计。
- 触发条件（任一）出现时再做 M5：需要让多个容器共享同一分配器接口；需要
  `Arena` 用 `FixedBuffer` 作 child；需要 `StackFallback`。
- M5 的 `Allocator` 一旦落地，`Arena` 可以增加
  `arena_init_with(child Allocator, block_size)`：块从 child 分配，为
  `FixedBuffer` + `Arena` 组合铺路。首版不预留该字段。

## 12. 失败、溢出与误用

| 场景 | 行为 |
| --- | --- |
| 映射/空间不足 | 返回 0；保留已有块/游标与内容 |
| 加法/乘法溢出 | 返回 0；不执行分配 |
| 对齐参数非法（0、非 2 的幂） | 返回 0 |
| `alloc`/`arena_alloc`/`fixed_buffer_alloc` 的 0 长度 | 返回非空地址（与 prelude 一致），不推进 |
| `release(0)`/`arena_free(...,0)`/`fixed_buffer_free(...,0)`/`pool_free(p,0)` | 无操作 |
| 非最近分配 `free` | 返回 0/no-op；空间不回收 |
| 非最近分配 `resize` 扩大 | 返回 0；缩小返回 1（逻辑缩小，不回收） |
| 重复释放、释放非本分配器地址、释放后使用 | 未定义行为，不做运行时检测 |
| 复制句柄后双释放 | 未定义行为 |
| 空指针作为 Arena/FixedBuffer/FixedPool 句柄 | 未定义行为 |
| `free` 的 size/alignment 与分配不一致 | 未定义行为（FixedBuffer/Arena 可能不回收或错位） |

不做运行时检测的理由：语言没有编译期“已释放”状态，也没有类型信息；魔数校验
会给每次分配/释放加分支与头部字节，却不改变误用的不可恢复性。需要排查时优先
用 `fixed_buffer_owns`/`arena_capacity` 断言与测试失败注入。

测试失败注入沿用项目既有做法：模块内私有常量

```yh
// MEMORY_TEST_FAIL_AFTER：产品构建恒为 -1；测试把标准库副本改成 >=0，
// 允许该次数的映射后下一次返回失败。
const MEMORY_TEST_FAIL_AFTER int = -1
```

注入点在块映射函数内，Arena/Pool 共用；FixedBuffer 没有映射，用容量边界
测试即可。产品源码不导出 `test_*` 接口。

## 13. 与现有模块和 libc 的关系

- **`string`**：`String` 是单对象所有权，增长时需要复制并释放旧块，不适合
  Arena（Arena 没有任意单块释放）；保留现有 `string_alloc`/
  `string_copy_overlap`，不迁移。M5 后可评估让 `String` 接受 `Allocator`。
- **`toml`**：`pool_alloc`/`pool_free_all` 与 Arena 的“整池释放”同构。可在
  独立切片中把 `pool` 换为 `FixedPool` 或 `Arena`，但必须保留预算统计、
  失败注入与“失败无半成品”语义；本设计不强制迁移。
- **`cli`**：已有自己的分配池；同样按需迁移，不在首版范围。
- **编译器 `gen/`**：直接使用 prelude 堆，性能与对象生命周期由编译器自己
  管理；标准库 Arena 不是编译器内部分配器的替代品，不迁移。
- **`libs/sys`**：`map_memory`/`unmap_memory` 继续服务需要显式页映射的调用方
  （文件映射、页对齐缓冲区）；`memory` 不依赖 `sys`，两者边界是“堆分配”与
  “页映射”。
- **`libs/libc` L1.4**：规划中的 C ABI `malloc`/`free` 与本模块的 `alloc`/
  `release` 是不同入口。在 E4 决定最终分配器之前，禁止跨入口配对释放；本设计
  不提供桥接，也不注册 `malloc` 符号。

## 14. 线程与进程边界

- `FixedBuffer`/`Arena`/`FixedPool`/prelude 堆都不是线程安全的；并发线程必须
  各自持有实例，或由调用方在外部串行化。标准库当前没有锁/原子模块，本设计
  不引入。Zig 的 `ThreadSafeAllocator` 对应能力等 J4 线程池。
- `fork` 后子进程继承映射；父子各自释放自己的副本（同一映射在各自地址空间）
  没有共享状态问题，但不要通过共享内存交叉释放。`vfork`/信号处理器中不保证
  可重入。
- 本设计不改变编译器线程池（J4）的分配方式；若后续接入，按线程/任务分区。

## 15. 不做什么（非缺口）

- GC/引用计数/自动析构：语言语义是显式所有权，标准库不引入隐式回收。
- 线程安全分配器：无锁实现需要原子与平台内存序，另立项。
- 泛型/接口分配器作为核心：没有语言设施；M5 只用函数指针适配，不作为唯一入口。
- 堆上的任意对齐分配：首版不提供；M6 可在 `Allocator` 适配器内补。
- `calloc`/`alloc_zeroed`：需要清零时由调用方用 `copy`/libc `memset` 显式完成。
- 统计（`total_requested_bytes`/上限）：M6 按需；Arena 已给 `capacity`。
- DebugAllocator：无栈回溯；prelude `free` 立即 `munmap`，无法安全保留元数据
  做重复释放检测；M6 只考虑魔数/泄漏的简化版，不承诺 Zig 级诊断。
- PageAllocator 模块：prelude 堆每次就是页映射；需要页对齐/文件映射用 `sys`。
- StackFallbackAllocator：依赖 M5 `Allocator` + `FixedBuffer`，M6 按需。
- Smp/Wasm/Sbrk 分配器：平台专属，无消费者。
- 替换 C ABI `malloc`/`free`：归 `libs/libc` E4。

## 16. 验收与完成定义

测试矩阵：

| 组 | 断言 |
| --- | --- |
| `heap` | `alloc(0)` 非 0；`alloc/copy/release` 读写；`release(0)`；`reallocate` 的 `data=0`/增长/缩小/`new_size=0`；超长请求失败后旧块内容保持 |
| `fixedbuffer` | 16/64/256 对齐；空间不足返回 0；跨容量失败；最近分配 resize/free；非最近 free no-op、缩小 resize=1；`reset` 复用；`owns` 边界；0 长度 |
| `arena` | 同块/跨块；几何增长（第二块大于第一块）；64/256 对齐；非法对齐与溢出返回 0；`arena_resize`/`arena_free` 最近分配；`reset(retain)` 保留最新块、`free_all` 释放全部；`capacity`；映射失败保留旧内容 |
| `pool` | `pool_reserve`；跨 Arena 块；`pool_free` 后同块复用；`reset` 后全部可再分配；`release` 后可再次 `pool_alloc`；`block_size=0`/非法 alignment 拒绝；`pool_alloc` 失败 0 |
| `allocator`（M5） | `heap`/`arena`/`fixed_buffer` 适配器；`reallocate` 的 resize→remap→copy 路径；`failing`；heap alignment>16 返回 0；`allocator_valid` |

门禁与证据：

- 每个切片先加断言（预期失败原因明确）→ 最小实现 → 定向用例通过；
- 本平台 `make test` 与 `make selfhost-native` 通过；
- O0 与 O2 各跑一次（新增 `make test-memory` 与 `test-memory-o2`）；
- Linux/AArch64 与 Darwin/ARM64 至少各一份运行证据；Linux/x64 按现有模拟/
  容器条件补充；
- 记录块映射次数与峰值（`strace`/`dtruss` 计数只作观察，不设固定门）；
- 修改任何行为后按 AGENTS 生成 `.yh` 用例；全绿后才允许 `make seed`。

阶段完成定义：

- **M1**：`reallocate` 契约与测试通过，现有三函数行为未变；
- **M2**：FixedBuffer 的分配/对齐/LIFO resize/free/reset/owns 全部通过；
- **M3**：Arena 的几何增长/对齐/最近分配回收/reset 模式/capacity 通过；
- **M4**：FixedPool 的 reserve/复用/reset/release 通过；
- **M5**：`Allocator` 适配器与组合 reallocate 通过（仅在触发条件成立后）；
- **M6**：按需求评估后置项，未做则明确记录“不做”。

## 17. 未决问题

1. **默认块大小与几何增长**：64 KiB、1.5 倍是保守起点；是否随工作负载调整，
   等基准数据，不改变 API。
2. **M5 `Allocator` 是否值得落地**：取决于是否出现需要统一分配器的容器/
   `FixedBuffer`+Arena 组合；没有消费者就保持设计不实现。
3. **堆对齐分配**：M5 适配器目前只支持 <=16；是否在 M6 补过分配实现，
   取决于是否有真实的大对齐消费者。
4. **DebugAllocator 的边界**：是否需要简化版（魔数/泄漏/野指针）以及是否接受
   其开销；重复释放检测受 prelude 立即 `munmap` 限制。
5. **FixedPool 与 toml 池的迁移**：把 `toml` 的私有池改为 `FixedPool`/`Arena`
   是独立切片，需保留预算统计与失败注入。
6. **libc 分配器配对**：E4 选择 prelude 替换或桥接之前，C ABI 与 yh 堆不能
   交叉释放。
7. **线程安全**：`ThreadSafeAllocator` 等 J4 线程池与原子原语，暂不做。

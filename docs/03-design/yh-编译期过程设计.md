# yh 编译期过程设计

日期：2026-10-06。状态：**设计目标；多个受限切片已实现，完整过程仍未完成**。

用户已明确采用 `$if/$for` 控制形式，删除顶层 `$if`，
并保留 `@[comptime]` 表示编译期函数。控制与诊断建议均限于函数体内。
首版建议的六项语法、作用域、阶段与歧义分析见
[首版语法分析](yh-编译期首版语法分析.md)。本文件保留函数求值器的详细设计：
编译器执行受限的 yh 函数，将结果作为常量交给后续编译阶段。
实施顺序见[实施方案](../02-plan/yh-编译期过程实施方案.md)。
本轮推荐使用 `$f(...)` 显式调用编译期函数，替代此前普通调用按属性判断；
可行性、接口取舍和诊断共用入口见[显式调用分析](yh-编译期函数显式调用分析.md)。

### 当前实现边界（2026-10-07）

当前编译器已解析 `@[comptime]`、`$f(...)`、函数体 `$if/$for` 和普通函数内独立
诊断指令。实现代码主要位于 `compiler/comptime/`；`compiler/parse/parse_comptime.yh`
负责在既有解析流程里选择分支和逐轮建立循环变量。函数准备阶段在全局初始化前复用
普通 parser，并将已绑定、已类型检查的表达式、语句与局部绑定复制到 comptime 私有
typed IR。typed 执行器已覆盖整数/布尔表达式、整数 `switch` 多值 case/default、`len(数组或切片)`、`$g(...)`、标量局部值、受支持数组/切片字面量
局部初始化、普通数组/切片 for-in 与受支持元素下标读写、直接局部赋值、普通 if/else、条件 for、整数区间 for-in、
编译期函数体 `$if/$else/$for` 按调用帧执行、调用表达式语句、break/continue/return 和
按实际路径触发的 typed 诊断；切片元素支持整数或受支持结构体，定长数组最多嵌套 32 层，元素可为整数或受支持结构体；for-in 绑定只读；下标元素可读写，切片表达式生成共享底层存储的视图；本地具名结构体支持整数或受支持结构体元素切片字段、嵌套结构体字段、结构体数组元素、多维定长数组字段初始化、链式成员读写和递归复制；普通结构体副本共享切片底层元素，嵌套返回复制切片可见元素，顶层聚合静态物化延后输出切片 backing 以保持父聚合布局连续；暂未迁移的
AST 形式仍使用 token 执行器。后者支持整数形参/文字量、一元正负、括号、`+ - * / %`、整数比较、直接
`$g(...)` 调用、普通 if/else、return 以及按实际调用路径执行的诊断语句。`if` 与
`$assert` 的 bool 条件支持整数比较、bool 文字量和括号组合；`&&/||` 短路，`&&` 优先级更高。调用实参
要求为常量，结果可用于全局 const、`$if` 条件和普通函数中的运行期初始化。普通函数中的
独立 `$assert/$compile_error/$compile_warn` 仍按前端语句路径执行；typed CT 函数中的同类指令
读取定义函数的源码快照，断言条件通过 typed 表达式边读取局部值，错误/警告消息要求字符串文字量。
兼容 token 路径仍保留给未迁移函数。未选 `$if` 分支不触发指令，
诊断不能作为表达式值。typed CT 执行器还支持当前调用帧内整数局部槽的 `&` 取址和 `*` 读取/写回；解释器指针只保存局部槽引用，禁止空指针解引用，并拒绝指针形参/返回、聚合逃逸、算术及全局/字符串指针求值。递归共享 64 层调用帧上限；typed IR 调用树另共享 100000 步预算。
短路跳过的右侧只解析并检查形参与调用签名，不执行除法或编译期调用。联合体、
浮点/指针切片元素及字段、非整型数组元素、一般左值和通用跨模块 typed CT 仍未完成；未支持 AST
子类的回退路径仍在使用 token 执行器。CT5A 布局常量/数组长度的值与类型布局混合依赖环
会在停滞时输出闭合节点路径。

跨模块 CT 闭包另可携带被正文引用的直接浮点字面量全局常量，供导入侧重新解析并检查函数体类型；
这不开放浮点编译期求值，其他浮点运算仍不属于当前 typed CT 执行器能力。
`.s.ct` 还为每个隐藏 CT 函数保存定义源码路径和函数体起始行，并为正文改写保存生成范围到原文范围的
列映射；导入正文的语义错误及实际执行的编译期诊断会映射回定义源码的路径、行、列。旧 sidecar
没有列映射注释时仍可按路径和行号导入。

普通函数体内 `$if` 要求编译时常量；`@[comptime]` 函数体内 `$if/$else` 保存为 typed
分支，并按本次调用的参数/局部值选择；两支均做名字与类型检查，未选支诊断不触发。
普通函数 `$if` 条件中的 `linux/darwin/arm64` 根据输出方言解析，
并且在该位置不受同名局部变量遮蔽；`&&/||` 按布尔常量折叠。未选分支只进行语法
检查。普通函数中的 `$for` 只接受常量整数半开区间 `[lo..hi)`，每个区间最多 1024 轮、
单编译单元最多静态展开 100000 轮。模块 worker 在检查与构建共用的解析中捕获 typed AST；
普通 `$for` 中不含嵌套 `$` 指令及局部 const/类型声明的函数体只捕获一份模板，SSA 按静态区间
逐轮降低并绑定各自的迭代常量，预算按逻辑实例化后的表达式、语句和绑定节点数限制 100000。
其他 `$for` 仍捕获逐轮展开 AST，普通 `$if` 选择分支。parser 对所有区间仍逐轮做语义检查和旧
后端发码；单文件路径尚未接入函数 AST，继续使用保守 token 规模预算，因此消除重复解析和
统一单文件、check/build/SSA 消费仍待完成。
`@[comptime]` 函数中的 typed `$if/$for` 保存表达式，
调用时按帧内值选支或执行区间；typed `$for` 每区间最多 1024 轮，并受共享 100000 步预算约束。
本切片在同模块多文件项目中有验收用例；这不等于支持跨模块求值。

## 2. 编译期函数接口

函数身份沿用现有属性列表；控制与诊断采用首版语法分析中的 `$...` 形式。

```yh
// align_up：将非负字节数向上取整为 unit 的整数倍。
// unit 必须大于零；调用时参数必须可编译期求值，返回对齐后的字节数。
@[comptime]
fn align_up(size int, unit int) int {
    return ((size + unit - 1) / unit) * unit;
}

const BLOCK_SIZE int = $align_up(17, 16);

// main：验证编译期结果可用作局部数组长度，成功退出零。
fn main() int {
    let buffer [BLOCK_SIZE]u8;
    return len(buffer) - 32;
}
```

预期：编译期间得到 `BLOCK_SIZE = 32`；目标程序不包含 `align_up` 的函数体或
调用指令。普通函数体内的独立诊断语句已实现。CT 执行器支持整数比较条件、普通
if/else、条件循环、typed `$if/$for`、return 及其表达式中的嵌套 `$g(...)` 调用；递归共享 64 层调用帧上限。函数体内
`$assert/$compile_error/$compile_warn` 由当前调用帧按实际执行路径触发；断言条件目前
接受整数比较、bool 文字量及其括号化的 `&&/||` 组合，错误和警告消息要求字符串文字量。

三种接口的取舍：

| 接口 | 优点 | 成本 | 选择 |
| --- | --- | --- | --- |
| `@[comptime] fn` 与 `$f(...)` | 属性规定身份，调用标记明确求值意图 | 专用于编译期，要求显式调用与可用实参 | 首版推荐 |
| `comptime(expr)` 调用点标记 | 同一个普通函数可同时供两阶段使用 | 要检查任意被调函数的副作用和可执行子集，还需新表达式规则 | 后续有需求再设计 |
| `$if/$for` 与诊断指令 | 函数体内条件选择、区间展开和编译期诊断 | 涉及块作用域、展开绑定与新 token | 用户已选择，进入首版；完整反射另分期 |

`@[comptime]` 只允许有函数体的顶层函数。首版拒绝与 `extern`、`inline`、
`noreturn` 组合；拒绝修饰入口 `main`、类型、变量、函数类型或外部原型。
首版初期拒绝 `pub` 编译期函数；CT5B 当前允许受限整数子集的公开正文经 `.s.ct` 跨模块传递，
更广的类型与常量闭包仍待后续阶段补齐。

## 3. 属性语法与歧义检查

`docs/yh.g4` 的当前规则包含 `comptime` 属性名；手写解析器也已登记该属性。
语法形状为：

```antlr
attributeGroup
    : '@' '[' attributeName (',' attributeName)* ']'
    ;
attributeName
    : IDENT | 'extern' | 'inline'
    ;
attributedDecl
    : 'pub'? attributedFnDecl
    | 'pub' (structDecl | unionDecl | enumDecl)
    ;
```

`comptime` 仍按普通 `IDENT` 进入属性语法，避免将它设为全局保留字。
`$if/$for` 位于 stmt，`$f(...)` 位于 primaryExpr；诊断内建复用 `$IDENT(...)`，再由
语义阶段保留三个内建名，限制为函数内独立语句并检查参数形态。属性适用范围和
函数签名约束由语义检查负责。

- 函数仍由 `fnSignature block` 解析，不引入与普通函数定义重叠的新分支。
- 属性仍在可选 `pub` 之前；单组、禁止重复和尾逗号的规则保持一致。
- `f(...)` 保持普通后缀调用；`$f(...)` 保存显式求值标记，
  绑定后验证 comptime 属性，不能简单删除 $ 再走普通发码。
- 参数、返回值和 const 均保留显式类型；分号与块终结规则保持一致。
- 普通标识符 `comptime` 不变成保留字；合法成员名和变量名不受影响。

## 4. 求值契约

### 4.1 两种处理状态

检查函数体时，形参只有类型和局部绑定，没有本次调用的值。这一阶段验证所有
分支的名称、类型、允许的操作与返回路径，生成只读 typed AST。

执行调用时，先取得实参常量，再建立调用帧。解释器只执行选中的分支和循环，
把返回值转换到声明返回类型。检查过程不能提前执行依赖参数的表达式。
const 等常量请求也应先取得完整受检表达式再求值，不能边消费 token 边执行
其中每个调用；否则 `false && f(0)` 仍可能错误执行未选中的调用。

- 普通函数中用 $f 调用编译期函数：所有实参必须可编译期求值。
  `let x int = 8;` 不使 x 成为常量，$f(x) 必须报错。
- 编译期函数体中也用 $f 调用其他编译期函数：检查时允许参数/局部槽作为实参；
  解释执行时这些槽已有本次调用的值。
- 普通函数不会因为传入常量而自动成为编译期函数；求值失败不能退回运行期。
- $普通函数(...) 和缺少 $ 的编译期函数调用都拒绝。
  $ 内建诊断仅用于函数内独立语句，具体位置/名字约束见显式调用分析。
- 编译期函数不能取地址、存入函数指针、作为函数值传递或导出运行期符号。
- 返回的常量可以用于普通运行期表达式，也可用于 const、标量全局初值、
  局部数组长度和 case 值。全局布局有两条受限路径：旧 token 探测只接纳算术 return、
  穷尽 `if/else`/`return` 和控制流前显式类型的顶层只读整数 `let`，并要求无环调用图；
  typed 布局请求允许先行整数 const 通过已捕获的 typed CT 调用求值，因此该函数可使用
  已支持的局部赋值、分支局部声明、循环和预算内递归。布局 typed CT 候选间可按依赖
  调度有限的前向整数 const，并给出常量依赖环链。数组长度还支持保存并延迟求值的整数
  表达式、显式 `$f(...)` 组合及等待布局完成的 `sizeof(T)`；普通全局 const 的一般前向
  求值、跨模块函数正文和非数组类型表达式仍属后续工作。

### 4.2 首版函数可执行子集（CT3）

| 类别 | 支持 |
| --- | --- |
| 值与签名 | 标量整数/bool/char 返回；嵌套及顶层 `$f(...)` 可返回受支持整数叶定长数组、结构体、整数切片或受支持结构体元素切片；固定形参可用标量、受支持定长数组/结构体或上述切片 |
| 表达式 | 文字量、参数、局部槽、就绪的标量 const、整数算术/位运算/比较、转换、短路、三元、`len(数组或切片)`、受支持数组/切片表达式（共享视图）和下标读取（基址可为函数返回的聚合表达式）、受支持嵌套结构体及结构体数组字面量与成员读取 |
| 声明和赋值 | 显式类型 let/const，局部与参数副本赋值；受支持数组/切片元素及结构体成员赋值；受支持定长数组/结构体初始化、切片字段视图、递归复制和多级下标读写（写入目标须来自当前帧可变局部值） |
| 控制流 | 块、`if (...)`、整数 `switch`、条件或无限 `for`、整型区间/数组/切片 for-in；数组和切片可遍历受支持结构体或嵌套数组元素，并按值复制；`break/continue/return` |
| 调用 | 已检查编译期函数的显式 $f 直接调用；递归与互递归受统一预算约束 |
| 查询 | 已完成布局且无依赖环的 `sizeof(Type)`；当前调用帧内数组/切片的 `len(value)` |

局部 const 的值可随调用参数变化，但局部变量的类型不能依赖本次调用参数；
局部数组仍须使用显式固定长度，切片使用局部字面量初始化，不引入依赖类型或按参数专门化 AST。

首版拒绝浮点、全局/字符串指针求值、联合体、浮点/指针切片字段及其他不受支持的聚合元素、变参、函数指针、`goto` 和反射；typed CT 函数仅允许对当前帧整数局部值执行 `&`/`*` 读取与写入，禁止空指针解引用及指针参数、返回、聚合逃逸和指针算术。顶层聚合结果可用于普通运行期局部初始化、全局可变初始化和嵌套 CT 调用，并通过静态数据存储物化；聚合 `const` 仍由既有语义拒绝。定长数组元素递归支持整数、受支持结构体或定长数组；切片元素支持整数或受支持结构体。数组/切片下标读写均可用，视图共享底层元素；`for-in` 绑定对结构体/数组元素按值复制。结构体字段中的切片按普通副本规则复制视图并共享元素；作为嵌套函数返回时，结构体元素及其受支持字段递归复制到调用方帧。静态数据序列化延后输出嵌套切片 backing，保持父结构和结构体数组的字段偏移。也拒绝调用普通函数、prelude、extern、系统调用，
以及读取/写入全局 let。解释器自身的内存分配不向被执行的源码开放。
数组和结构体形参在被调帧内按值深复制；受支持切片形参复制视图描述并共享底层元素存储。形参的聚合元素范围与局部值支持范围相同。
嵌套 typed 函数返回数组/结构体时，在被调帧释放前深复制到调用方帧；返回切片时复制可见元素及其中受支持结构体的嵌套值到调用方帧，因此不保留对被调帧局部数组或原视图底层存储的别名。没有 typed 调用方帧的 `$f(...)` 调用会把受支持聚合值编码为静态数据并返回其地址；用于编译期外层调用时则保留 CT 聚合存储到本编译单元清理。
`$assert/$compile_error/$compile_warn` 在函数准备时检查参数形态，执行时按
实际调用路径触发。`$if/$for` 在准备时选择/展开，只能使用当时已知的信息，
不能依赖本次调用形参；依赖形参的分支与循环使用普通 if/for。

`&&`、`||`、`?:` 与分支按需执行。未执行分支里的类型错误、越界调用集合等
静态错误仍要诊断；未执行表达式的除零等执行错误不应触发。
这里的按需执行针对编译期函数和常量请求。普通运行期代码中出现的编译期
调用仍必须完成编译期求值，不能依赖后端死代码删除来绕过坏调用。

### 4.3 整数边界

原有 `fold_binop(op, a, b)` 只接收 i64 位型，不能直接覆盖无符号比较/除法及
定宽转换。CT0 已在 `gen/sem_expr.yh` 增加按目标类型折叠的边界检查；受限
`@[comptime]` return 求值器也复用它处理 `+ - * / %`。普通常量表达式折叠覆盖
比较、位运算和移位；这不等同于完整 typed CT IR 或完整函数解释。

本提案采用保守边界：

- 参数、返回值和赋值使用现有类型兼容与字面量适配规则。
- 显式整数转换复用现有截断、符号扩展与零扩展契约；bool 结果规范化。
- 算术在结果类型可表示范围内执行；一元负号、加减乘溢出、除零、模零、最小负数除 -1
  在编译期报错。CT0 已覆盖当前常量折叠与受限函数 return 求值；首版不承诺
  溢出表达式可求值，也不修改普通运行期溢出行为。
- 有符号除法向零截断；余数按同一商计算；无符号比较和除法使用无符号值。
- 移位量必须满足 `0 <= count < 位宽`；左移超出结果可表示范围报错；有符号负值
  左移按保守规则拒绝；有符号负值右移采用算术右移，无符号值采用逻辑右移。
- `sizeof` 使用 yh 目标数据模型，不能使用宿主 Python/C 的类型大小。

结果中保存目标类型和原始位型；`Res.is_lit = 0`，不能把函数结果伪装成可
任意窄化的源字面量。常量消费者继续做自己的约束，如数组长度须在
`1..2147483647`，不能把 bool 当数组长度。

### 4.4 终止和诊断

每个最外层求值任务最多 100000 步、64 层调用帧。每次表达式/语句执行扣一步；
空循环的每次条件或回边也扣步。嵌套调用共享剩余预算，不能重新获得额度。
首版固定这些限制，不增加命令行配置或持久化求值结果缓存。

错误包含当前源码位置、最外层请求位置和调用链：例如“编译期参数不是常量”、
“编译期过程不允许调用 extern 函数”、“编译期求值超过步数上限”。
检查失败、除零或耗尽预算均返回普通编译错误，不崩溃、不启动子进程执行源码。

## 6. 前端准备与解释执行

处理顺序：

```text
源/词法快照
  → 既有声明索引与模块依赖登记
  → 类型与函数签名登记（记录编译期函数源码范围）
  → 按需准备编译期 typed AST（只检查，不求参数值）
  → 按既有顺序求值全局常量与标量初值
  → 检查普通函数；选择函数内 $if、展开 $for、在常量/调用点执行编译期过程
  → 把求值结果交给常量节点/Res
  → 既有 SSA 或旧后端
```

CT5A 仍不开放需要一般反射或跨模块正文的全局类型表达式；数组长度属于已实现的受限扩展。pass1 对含 `$`、未就绪整数 const 或 `sizeof` 的数组长度保存 token 范围并创建 pending 数组类型；CT 函数 typed IR 捕获后，单文件与同模块 worker 反复执行依赖已 READY 的布局 const 和长度表达式，并在每轮推进数组/结构体布局。局部赋值、循环、分支局部绑定和到达基例的递归由既有 typed 执行器求值；递归受 64 层调用和 100000 步预算约束。普通全局 const 的声明顺序保持不变，非候选前向引用仍报“编译期常量尚未就绪”。

**2026-10-13 补充（布局期普通 const 与数组类型编号）**：

- 数组长度引用**声明在前**的普通整数 const（`const N int = 3; let g [N]int;`）时，
  该常量登记为布局期值请求，由布局循环先求出值再定长；此前这类位置（全局、
  结构体字段、形参、返回）一律误报“编译期常量尚未就绪”，只有函数内局部数组
  可用。前向引用（常量声明在使用之后）不登记，仍按声明顺序拒绝。
- 延迟判定按“当前 pass 能不能折叠”分级：引用未就绪 const 时任何 pass 都延迟；
  含 `$`/`sizeof` 时只在 pass1 延迟（CT 正文 pass2 才捕获，后续 pass 直接折叠，
  避免重新取回长度仍为 -2 的 pending 项）。
- 数组类型项按**长度来源**去重（同一 const 符号 / 同一长度 token 区间 / 同一
  已知长度），布局完成后把同 (元素, 长度, 大小) 的重复项归一到最小编号并改写
  持久引用（类型表元素、字段、签名返回与形参、符号类型）；`sem_can_assign` 的
  结构化数组兼容判定保留为第二道防线。

pending 类型用负布局大小标记，完成请求前不会进入全局数据发射或普通函数编译。typed CT 函数准备时把 pending `sizeof(T)` 保存为目标类型编号，不伪造大小；函数调用会等目标布局 READY 后执行。可确认的常量依赖环显示名称闭链；值与布局互相阻塞时沿常量、数组/结构体布局及 typed CT 调用闭包中的布局引用构图，并输出闭合节点路径，例如 `ITEM_COUNT -> PendingLayoutPacket -> 数组长度(ITEM_COUNT) -> ITEM_COUNT`。数组表达式直接 `$` 调用中的布局依赖也纳入路径；无法证明为环时仍报告原有未完成依赖类别。该调度只服务数组长度和布局 CT const，不代表通用编译期值/类型请求图。

实现放在现有 parse 模块内，避免新增 `parse ↔ comptime` 模块循环：

- `ct_model.yh`：函数索引、检查状态、常量就绪状态、值、帧和预算上下文。
- `ct_prepare.yh`：借现有解析器建立受限 typed AST，做类型与操作许可检查。
- `ct_eval.yh`：执行表达式、语句、调用，返回正常/return/break/continue 状态（typed IR 执行器 `ct_ir.yh` 即此职责；早期 token 版本已删除）。
- 整数辅助只在需要时单独拆文件；按文件大小拆完整职责，不先建 VM/字节码。

检查状态与 `c_fold` 分开：参数表达式允许有类型但没有常量值。
`c_em_suppress` 只负责不输出 text，不能独自承担检查模式。直接调用在检查时
绑定到函数身份，执行时才读取实参值。局部 const 初始化同样保留表达式。

现有模块 AST 捕获要求合法的 file/decl 身份。单文件编译和单文件 check 当前
走旧遍历，CT3 需为编译期函数提供等价源码上下文，不能只接项目 build 路径。
准备函数时保存/恢复活动文件、游标、作用域、当前函数、调用实参基线与捕获
状态；执行解释器时不重入正在捕获函数的 parser，而是在不可变 AST 上建帧。

求值器复用 `binding_row` 标识局部槽，不能按可复用的 `sym_id` 存变量。
提前检查时对全局 const 保留声明引用，求值时要求其状态为 READY；
不能冻结尚未完成初始化的 `const_bits = 0`。所有函数体先被检查一次，
递归调用执行同一只读函数体，每次拥有独立局部帧。

CT5A 当前既有早期 token 探测、先行整数 const 的有限 typed 布局请求、数组长度表达式、
pending `sizeof` 固定点调度及值/布局混合环闭链诊断；仍需按需加入其他一般 typed CT
求值请求。这与允许的函数递归不同：
正常递归在已经检查的函数体上执行，受调用预算限制。普通全局 const 的既定顺序可见性
保持不变；仅布局 typed CT 候选（含数组长度引用的、声明在前的普通整数 const）允许
建立受限的前向 const 依赖。

## 7. 模块、缓存与接口

同模块的多个文件使用定义文件的 import 绑定和已有模块级函数签名索引。
CT5B 已开放 `@[comptime] pub fn` 的首个跨模块整型竖切片：`.s.i v3` 保留公开
签名，`.s.ct` 保存由公开 CT 函数可达的本地函数正文；导入模块可用
`$module_alias.function(...)` 显式求值。隐藏正文符号只进入 CT 函数表，不进入
调用方普通名字空间，也不生成目标运行期函数。

- 公共名字遵守现有可见性；私有依赖供解释器使用，不能加入调用方普通符号表。
- `.s.ct` 以隐藏名字保存已检查的 YH 函数正文；导入时经正常前端重新检查并捕获 typed IR。
  可达函数引用的已就绪整数常量随闭包导出为隐藏 `const`；导入方在函数正文捕获前折叠它们。
  私有 `type` 别名在完整局部类型（包括数组和指针）、结构体字面量、直接具名 `.to_type(Alias)`
  与 `sizeof(Alias)`、`sizeof(*Alias)`、`sizeof(**Alias)` 位置改写为底层类型引用。模块限定公共类型
  在局部类型、结构体字面量、`.to_type` 和 `sizeof` 中按定义文件导入快照解析，再输出接口规范类型名；
  `comptimecross` 以两个文件中的不同别名验证该绑定不会串用。可达正文引用的直接浮点字面量全局常量
  保留原始字面值传递，导入侧重新解析后用于正文类型检查，不用于浮点评估；直接字符串字面量初始化的
  私有 `*char` 常量也会随闭包传递，但不开放该外部地址的求值或解引用，sidecar 加载不会向消费者 `.data` 泄漏；typed CT 局部整数指针按本帧槽位单独处理。
  隐藏函数的定义路径与函数体起始行随 `.s.ct` 传递；旧 sidecar 没有映射时保留 sidecar 位置。
  当前语法规定结构体和联合体必须 `pub`。
- 导入方校验 `.s.ct` 头版本、目标和模块后缀，并逐一比对公开函数与隐藏正文的函数类型；
  正文缺失、签名不匹配或格式损坏时明确失败，不回退执行空函数体。
- 模块发布 `.s.ct` 后发布 `.s.i`；调度器以 `.s.i` 为就绪信号并同时确认 `.s.ct` 存在。
  依赖正文及缓存元数据保持同一轮身份。
- 求值器版本、编译器身份、目标数据模型和 `.s.ct` 内容进入消费者缓存键；
  修改公共函数的私有帮助函数也必须使消费者失效，不能只比公共签名。
- 无对应正文或版本不兼容时明确报错，不能静默按空体执行。
- `.s.ct` 闭包支持跨模块嵌套显式 `$` 调用：导出时将 `$alias.name(...)` 重写为依赖方稳定
  隐藏函数名；导入 typed IR 时把每个函数切片追加到统一 arena，并重定位表达式、语句、边和
  局部绑定引用。`comptimecross` 验证两层跨模块调用、无运行期发码及最底层正文变化失效。
- `.s.ct v1` 携带已就绪整数常量、直接浮点字面量及直接字符串字面量 `*char` 常量闭包和隐藏 CT
  函数的定义路径/体起始行映射；可选 `yh-ctcol v1` 注释逐段记录重写正文的生成列和原文列。
  浮点表达式、其他指针常量表达式及跨模块/全局指针求值仍待补齐；typed CT 局部整数变量的
  `&`/`*` 读取和写入已实现，指针不得跨帧传参或返回。
  有效 sidecar、篡改签名、错误版本、正文截断和语法损坏均有项目回归。

首版不做单次调用的持久化 memoization；函数 AST 在 worker 内复用即可。
解释器不读时间、环境变量、文件或网络。同样输入、目标和版本得到同样结果，
能进入现有两代 `.s/.s.i/.s.ct` 固定点门；CT5B 伴随文件逐字节固定。

## 8. 条件编译与反射的范围修订

`$if (...) { ... } $else { ... }` 限于函数体内，进入 CT1；函数内常量区间
`$for i in (lo..hi)` 进入 CT2。具体语法、未选择分支和常量阶段见首版语法分析。
yh 当前按宿主筛选 `.darwin.yh/.linux.yh`，条件编译必须明确区分构建编译器
所需的宿主 API 与输出程序的目标平台，不能从正在运行的机器推断目标。

顶层声明与模块依赖沿用现状，首版不引入顶层控制或诊断指令。
函数内两支均完整语法检查，选中支才检查名称/类型；选择在所需常量就绪后
完成，不加入参数相关的类型专门化。平台声明继续使用现有平台源文件，
不把 V 的某条处理路径直接当作 yh 所有场景的规范。

CT4 首片采用 `$for item in E.values {}` 遍历具名枚举成员，按声明顺序暴露只读
`item.name` 与 `item.value`，不合并重复判别值；字段 `T.fields` 再按用途决定。
类型值、泛型分派和动态成员选择留到 CT6；展开后的绑定、源映射、展开数量上限
与阶段不能因为初版只读元信息而省略。
不引入文本宏、任意源码字符串求值或可变编译器 AST API。

## 9. 交付与验收

首版目标为 CT0–CT3：函数内 `$if` 选择、常量区间 `$for`、三个诊断指令、
同模块私有标量/受支持聚合过程、局部数组长度/case/标量全局初值与执行预算。当前已交付
结构控制、目标标记、整数常量检查、typed 编译期函数调用与局部执行切片、诊断、
短路、函数体 typed `$if/$for` 和顶层聚合结果物化。CT1/CT2 typed AST 收尾和 CT3 完整 typed 执行器
仍在实施；局部数组/切片 for-in、下标读写、切片视图、递归嵌套结构体/数组值、受支持聚合形参/嵌套返回和结构体元素切片已完成首片，其他聚合/一般左值、
展开节点总量预算及剩余消费者位置尚未完成。
CT4 轻量反射、CT5A/CT5B 布局/跨模块正文、CT6 高阶能力均单独交付。

每个行为切片先添加 `.yh` 回归，再构建验证。验收不仅看输出正确，还要求：
编译期函数无目标符号/调用、check 真正执行必要求值且无后端产物、坏调用为
普通诊断、不同调用帧不串值、冷编/热编一致，以及完整自举门通过。

编译器自身新增文件须使用种子已支持的语法；首轮不在 compiler 源码中使用
新属性。`make test` 与 `make selfhost-native` 全绿后才可滚种子；
后续版本再让编译器源码消费新能力。

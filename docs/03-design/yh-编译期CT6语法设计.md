## 1. 范围与不做什么

- 两项都只在**编译期求值**；运行期语义与指令发射不受影响。
- 不引入泛型、无 first-class「类型值」、不做运行时反射（动态字段收敛为编译期
  反射元信息消费，见 §3）。
- 首版**仅单文件**：`.s.ct` 跨模块闭包的序列化延到正文格式确认后（§4）。

## 2. 表达式选择（表达式形态的分支求值）

### 2.1 动机与现状

函数内 `$if` 是**语句**形态（`comptimeIfStmt`，g4 265 行）；表达式里只有运行期
`?:`（`conditionalExpr`，g4 385-386 行）。「按编译期条件选一个**值**」目前只能
写到 `let` 里再引用，无法直接出现在实参/初始化位置。

### 2.2 决议的语法（候选 A）

| 候选 | 形态 | 决议 |
| --- | --- | --- |
| A（采用） | `$if (cond) e1 $else e2`，**`$else` 必须写** | 与语句形态同构，`$` 前缀已存在；表达式没有「原值」，不提供缺省形态 |
| B | 复用 `?:`：`cond ? $c1 : $c2` | **不采用**：同一运算符两种语义，合流与「未选分支是否执行」难以区分 |
| C | `$select { case cond1: e1; ... }` | **不采用**：更通用但语法面更大，留作后续 |

**g4**（`conditionalExpr` 之前增层，`expr` 链的最上层）：

```antlr
comptimeIfExpr
    : '$' 'if' '(' expr ')' expr '$' 'else' expr
    ;

expr
    : comptimeIfExpr
    | conditionalExpr
    ;
```

无歧义论证：语句形态 `$if (…) '{' … '}'` 的 `(expr)` 之后要求 `{`；表达式形态
要求 `expr`（不可从 `{` 开始），单 token lookahead 即可区分。

### 2.3 类型合流与求值语义

- 两分支都做名字与类型检查（未选分支不执行——与语句形态一致）。
- 合流规则**复用 `?:` 的既有合流检查**（实现上抽公共函数）：两支类型相等；
  或一支是整数/浮点字面量、另一支是目标类型（走 `sem_can_assign` 的 is_lit
  路径）。**按类型相等合流**；「结构相同但类型名不同的聚合值合流」不在首版
  （后续随类型分派再议）。
- typed IR：新增表达式节点（kind 可复用现有条件节点 + 结果框），选中分支的
  CtValue 复制为表达式结果；步数预算、`ct_ir_tick` 与 `$assert` 等诊断语句
  不改。

## 3. 类型分派与动态字段

### 3.1 动机与现状

首版语法分析（探针结论）：「只用元信息就能生成枚举名称/值列表或布局日志；
要为各种字段生成序列化、自动比较等代码，仍需类型分派和动态字段选择」。现状
编译期只能手写按类型 `if`，没有「类型谓词」或「按字段名取字段」。

### 3.2 类型分派（编译期按类型选择，候选 A 已决议）

| 候选 | 形态 | 决议 |
| --- | --- | --- |
| A（采用） | 类型谓词 `$is_type(<expr 的静态类型>, typeRef)` 与 `$is_int(x)`/`$is_float(x)` 快捷谓词 | 不引入类型值/重载表，与 `$if` 体系同构，正文捕获与闭包序列化代价最小 |
| B | `switch` 的类型 case：`switch ($type(x)) { case int: ... }` | **不采用**：语法更扁，但 `switch` 的 case 常量语义要禁类型 case 混排（歧义面大） |
| C | `@[comptime] fn` 按实参类型特化/重载 | **明确不做**：需要名字重载与特化选择机制，属独立大设计 |

首片：`$is_type(x, int)`、`$is_type(x, Point)` 等；`x` 只经受检的静态类型引用，
用例放在 `@[comptime]` 函数体与 `const` 初始化。

### 3.3 动态字段（编译期反射元信息消费；与 CT4 合并，先只读）

- yh **没有运行时反射诉求**（ADR 风格决议：不引入运行时元数据表）；「动态
  字段」定义为**编译期**按字段名/字段序访问：
  - 元信息消费形态 = **CT4 的扩展**：`$for f in T.fields`（字段名/类型元信息）
    + `$field(x, "name")`（按编译期常量名取值）。
  - **先只读**：`$field` 写值按 const 语义拒绝（与编译期模型写入只读同一策略）。
  - 字段名在编译期求值（intern 字符串即可），不得把编译器指针物化进目标程序
    （沿用 CT4 的既有约束）。
- 实现面：`T.fields` 复用 `SField`/布局就绪检查；`$field` 走成员访问同一路径，
  名字由 `$for` 绑定给出。**与 CT4 合并设计/实施**，不再单列。

## 4. 依赖、序列化与并发契约

- **表达式选择**：不改依赖图；`.s.ct` 闭包正文出现新节点形态时，重写器需处理
  条件表达式的 token 范围（与既有 `$if` 语句相同处理）；**首版仅单文件**，
  跨模块闭包延到正文格式确认后。
- **类型分派/动态字段**：影响 typed 正文捕获与跨模块闭包（`.s.ct` 需要携带
  谓词/字段访问形态）；建议先单文件验收，再评估 `.s.ct` 序列化。

## 6. 决策点决议记录

- **D1（已决议）**：`$if` 表达式形态**必须写 `$else`**，不提供缺省形态
  （表达式没有「原值」；语句形态 `$if` 保持现状）。
- **D2（已决议）**：表达式合流**按类型相等**；「结构相同但类型名不同」的
  聚合值合流不在首版（后续随类型分派再议）。
- **D3/D4（随条件导入撤销，2026-10-09）**：条件导入（`@[if(...)] import` 等
  候选）**不做**——无使用方，文件级平台后缀（`.darwin.yh`/`.linux.yh`）已能
  按宿主选文件；如未来需要，走平台后缀路线扩展，不再引入 import 级条件语法。
- **D5（已决议）**：类型分派用 `$is_type` 谓词 + `$is_int`/`$is_float` 快捷
  谓词（候选 A）。
- **D6（已决议）**：动态字段与 CT4 合并实施，**先只读**（`$field` 写值按
  const 语义拒绝）。

# yh 并行项目布局与依赖查找优化方向

- 日期：2026-11-05
- 状态：设计方向（未实施，未改任何代码）
- 关联：MOD-U2（toml.yh）、B1-1（proj_00_model.yh）、ADR-0006/0007

## 1. 目标语义

用户期望的项目布局是**并行兄弟目录**，依赖靠 `[dependencies]` 显式声明查找：

```
workspace/
├── a-project/   ← project.toml: b = { path = "../b-project" }
├── b-project/
└── c-project/
```

## 2. 现状确认（已经成立的部分）

以下语义当前实现已完整支持，无需新增能力：

| 语义 | 实现位置 |
|---|---|
| 依赖声明 `key = { path = "..." }`，相对路径解析 | `build/project_index.yh` `pj_load_project`（`proj.canon(root, path)`） |
| 依赖递归装载成任意深度 DAG | `pj_load_project` 递归调用自身 |
| 依赖环检测 | `proj.ctx().state[]`（0/1/2；state==1 时报"依赖环"） |
| 重复装载去重 | `proj.find_project_root` |
| 跨项目限定导入 `KEY.MOD` | `build/project_resolve.yh` `pj_bind_imports` 第 0 层（键→依赖项目直达） |
| 导入三层解析：本项目 → 标准库 → 直接依赖 | `pj_bind_imports` 第 1/2/3 层 |
| 物理嵌套边界：含 project.toml 的子目录不被扫描吸收 | `project_index.yh` `pj_scan_entry`（探测 `/project.toml` 后直接返回） |
| 跨项目模块级并行构建 | 全局模块 topo 序 + fork 调度（`build_scheduler.yh`），兄弟项目模块天然并发 |

活例子：`compiler/project.toml` 的 `libs = { path = "../libs" }`；
`tests/modules/projects/`（basic、alias、keyimp、modstate、ambiguity 等全是并行布局）。

因此优化方向是**消除摩擦**，不是补能力。

## 3. 优化方向（按性价比排序）

### 方向 1：依赖键 ↔ project.name 一致性校验（最小改动）

- 问题：依赖键是任意裸键，可与目标项目 `project.name` 脱节（键 `geo`、项目名
  `geom`），`KEY.MOD` 导入用的是键，写错不报错、报错难懂。
- 方案：`pj_load_project` 装载完依赖后，校验键必须等于
  `projs[dep].name`（字节比较走名字池，复用 `pj_same_np`），不一致经
  `proj.diag` 报错并指出两侧名字。
- 兼容性：现有语料存在键≠名（`alias`、`keyimp`、`comptimecross` 等），
  属破坏性变更——需先统一改语料，或改为「缺省键 = 项目名，显式别名键允许
  但要求项目名出现在诊断里」的温和方案。实施前必须盘点语料。

### 方向 2：解除 64 条依赖快照上限

- 问题：`pj_load_project` 装载 `[dependencies]` 前把条目快照进栈上定长数组
  `snap_key_off/snap_key_len/snap_path_off/snap_line [64]int`，超出 64 条
  **静默截断**。
- 方案：按 `toml_secs[dsec].val_n` 堆分配快照数组（malloc/free，与
  proj_10_table 的扩容风格一致）；或改为两遍式：先只记 `val_n`，递归装载
  依赖前逐条重读——不可行，因递归会重置全局 `toml_secs`，故必须堆快照。
- 改动点：`project_index.yh` 快照块（约 328–341 行）与循环里的取值下标。

### 方向 3：path 可省略，按名寻址兄弟目录

- 问题：清单必须写两遍名字（键 + path），并行布局下 path 几乎总是
  `../<键>`，纯噪音。
- 方案：`b = {}`（或 path 缺省）时按固定顺序解析兄弟目录：
  1. `../<键>`（相对声明者项目根）
  2. `<键>`（项目根内，供子目录式聚合）
  命中含 `project.toml` 的目录即装载；全部未命中报错并列出已尝试路径。
- 改动点：
  - `build/toml.yh` `tml_inline_table`：当前空表直接报
    "依赖必须提供 path"，需允许 path 缺省（`path_off = -1` 合法化）；
  - `build/project_index.yh` 依赖装载循环：path 缺省时走搜索规则。
- 注意：`TomlVal.kind==2` 的 path 语义变化要同步 `proj_40_art.yh` 等读取方。

### 方向 4：非传递依赖的智能诊断（语义保持不变）

- 问题：导入搜不到时只报"已搜索 本项目 → 标准库 → 直接依赖"；并行布局最
  常见坑是模块在「依赖的依赖」里，用户不知道该给谁加声明。
- 方案：第 3 层全部未命中后，追加一次间接查找（遍历直接依赖的 deps），
  命中则报：`模块不存在: X（存在于依赖 b 的依赖 c，请在 [dependencies]
  声明 c = { path = ... }）`。
- 语义决策：**导入保持非传递**（显式声明是对的，避免隐式耦合与歧义放大），
  本方向只改诊断质量。改动点：`project_resolve.yh` `pj_bind_imports`
  末尾报错路径。

### 方向 5：workspace 根清单（后置，大改）

- 触发条件：并行项目数量显著增长、兄弟相对路径维护成本显性化后再做。
- 设计要点：
  - 根目录 `workspace.toml`：`members = ["a-project", ...]`（字符串数组，
    TOML 解析器零扩展）；
  - 名字→路径映射靠读每个成员的 `project.name` 推导，不引入新 manifest
    结构；
  - 成员间依赖写 `b = {}`，经 workspace 注册表解析（在方向 3 的搜索规则
    之上加第 0 优先级）；
  - 可顺带承载共享目标配置（os/arch）的单一真源。
- 与方向 3 的关系：方向 3 是其子集，先做 3 不堵 5 的路。

## 4. 实施与验证约束（按仓库开发策略）

- 不涉及 yh 语言语法（`docs/yh.g4` 无需改动）；改动集中在 `build/` 模块。
- 每个方向在 `tests/modules/projects/` 新增并行布局用例：
  - 方向 1：键≠名报错用例（或温和方案下的合法别名用例）；
  - 方向 2：>64 条依赖的生成式用例（脚本造目录）；
  - 方向 3：path 缺省命中 `../<键>`、未命中报错两例；
  - 方向 4：间接依赖命中提示一例。
- 验证门：`just`（冷编）→ `just test` → `just selfhost-native`。
- 文档刷新：本文件随实施更新状态；`docs/03-design/` 相关清单 schema 文档
  与 `docs/finish.md` 记录条目。

## 5. 建议批次

1. 批次一：方向 2（纯防御性，无语义争议）+ 方向 4（只改诊断）。
2. 批次二：方向 3（解析器小扩展 + 搜索规则）。
3. 批次三：方向 1（先盘点语料决定破坏性程度）。
4. 方向 5 视项目规模另行立项到 `docs/todo.md`。

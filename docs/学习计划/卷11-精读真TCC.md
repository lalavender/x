# 卷11 · 参观原厂车间：精读真 TCC

> **本卷目标**：逐行读 TCC 源码的"十大主函数"，和你自己 mcc 的实现一一对答案。
> 读完这一卷，`src/` 目录 10 万行在你眼里不再是天书，而是"我见过的东西的豪华版"。
> **预计**：7 篇，约 1 周半。

方法（每篇都一样）：
1. 先花 5 分钟回忆**你自己**在这块写了什么；
2. 打开 TCC 对应函数**从第一行往下读**，遇到和你一样的写法就标记"✓同款"；
3. 遇到不一样的就停下来问："它为什么多出来的那部分要存在？"——
   答案永远藏在某一种 C 语法/某一种架构/某一种文件里。找到那一个，就赚了。

考古工具：`../graphify-out/graph.html`（函数调用地图）、
`../TCC编译器实现详解.md`（每站讲解）。

## 11.1 地图与罗盘

- **教什么**：graphify 图谱怎么看（god nodes = 枢纽函数；社区 = 模块簇）；
  20 个枢纽函数清单，按"你写过/没写过"分两栏——没写过的那几栏就是你 11 卷要补的课。
- **通关暗号**：说出 `tcc_error`（133 条边）为什么是全仓最大枢纽（提示：longjmp）。

## 11.2 37 行的全部秘密：tcc_compile

- **精读**：`src/core/libtcc.c:624`。逐行对照卷 3 你 mcc 的 main 编译循环。
  注意三个细节：`setjmp` 错误恢复（你的 mcc 用 exit，真编译器不行——为什么？）、
  `define_start` 宏栈回滚、`tccelf_begin/end_file`（编译单元边界）。
- **通关暗号**：给 tcc_compile 的每条语句标注它属于"前端/后端/链接器"哪一段。

## 11.3 next() 与宏录音带

- **精读**：`src/core/tccpp.c:3529`（39 行）→ `:3282` `macro_subst_tok` 的
  函数式宏分支。对比你卷 4 的实现——找三处你没想到的边界情况
  （空白保留、`TOK_PLCHLDR`、参数里的嵌套宏 `nested_list`）。
- **通关暗号**：解释 TCC 的"递归抑制"具体靠哪两个占位符 token 完成。

## 11.4 心脏解剖：gen_op / gv / unary / gfunc_call

- **精读**：`src/core/tccgen.c:2154`（gen_op 类型提升总线，找你的"折叠后直出"同款）、
  `:1253`（gv，重点读位域分支 1258-1291 和浮点常量落 .rodata 的 1293）、
  `:4594`（unary，挑 `(` 分支——它和你写的最大区别是**复合字面量**和 `sizeof 抑制代码`）、
  后端 `src/core/i386-gen.c:420`（gfunc_call，对照你的 7.2）。
- **通关暗号**：口头给外行讲"值栈上怎么完成一次函数调用"，10 分钟版。

## 11.5 链接器与目标文件：tccelf 五连

- **精读**：`set_elf_sym`（:490 符号合并）、`build_got_entries`（:1018）、
  `layout_sections`（:1563）、`relocate_section`（:825）、
  `tcc_write_elf_file`（:1977）+ `tcc_load_object_file`（:2283）。
  重点对比：**TCC 把"编译输出"和"链接输入"用同一个 Section 结构统一了**
  （你 9.1 是分开做的）——想清楚这省了什么。
- **通关暗号**：画出 `mcc -run` 和 `tcc -run` 的异同（至少 3 处差异，比如 bcheck、PE 分支、Win64 函数表）。

## 11.6 同一接口，五种人生：后端家族

- **精读**：`src/core/tcc.h:1466-1500`（契约）→
  对比 `i386-gen.c`、`x86_64-gen.c`（REX 前缀/双 gfunc_call）、`arm-gen.c`
  （`stuff_const` 的"立即数拆成 8 位循环移位"，你会觉得眼熟——卷 2 手写指令的变体）、
  `arm64-gen.c`（定长 4 字节编码 + `movz/movk` 凑 64 位常数）、
  `c67-gen.c`（表驱动怪）+ 任意一个 `-link.c`。
- **通关暗号**：说出一句 tccgen 里的话"为什么 gen_opi 只处理 int，浮点单独 gen_opf"
  在五个后端里的答案是否一样。

## 11.7 边角但重要：PE / 汇编器 / 运行时

- **精读（导读级）**：`src/formats/tccpe.c`（和 tccelf 对照看：同一堆节，两种装订法）、
  `src/core/tccasm.c`（内联 asm 的约束匹配：`asm_compute_constraints`——
  为什么 GNU asm 的 `%0/%1` 替换放在"词法器"层做最聪明）、
  `lib/bcheck.c`（边界检查器的"区域表"数据结构）、
  `src/core/tcctools.c` 的 `tcc_tool_ar`（编译器自己会打包 .a）。
- **通关暗号**：口头回答"TCC 为什么没有优化器还能这么有名？"
  （结合你一路走来的体会，3 个理由。）

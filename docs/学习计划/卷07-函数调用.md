# 卷07 · 打电话的规矩

> **本卷目标**：函数。包括调用约定（谁用什么寄存器、参数放哪）、
> 栈帧（prolog/epilog）、递归、结构体返回、`...` 变参、函数指针。
> 这一卷结束时，mcc 写的程序终于"像正经程序"了。
> **预计**：7 篇，约 1 周半。

函数 = 打电话。打电话前约好规矩：**你说几句（参数放哪）、
你说完我怎么回话（返回值放哪）、谁付话费（谁清栈）、
接电话时你手上的事放不放下（哪些寄存器要保存）**——
这套规矩叫**调用约定（calling convention）**。不同操作系统规矩不同，
TCC 为每种架构老老实实写了一份（这就是 `src/targets/` 存在的全部意义）。
我们学 x86-64 Linux 的 System V 规矩。

## 7.1 先抄规矩：System V 调用约定

- **教什么**：参数从左到右依次进 `rdi, rsi, rdx, rcx, r8, r9`，第 7 个起进栈
  （**从右往左**压，方便可变参数）；返回值在 `rax`；
  `rbx rbp r12-r15` 被调用者要原样还回来；`rsp` 永远指栈顶，
  调用瞬间 `call` 会把返回地址压栈。画一张"栈帧剖面图"并背下来。
- **你要写出**：手写 3 个汇编小函数（gcc -S 生成，读 30 分钟），
  然后**人肉**调用它们跑通。这是为了让你之后写 gfunc_call 时有肌肉记忆。
- **通关暗号**：说出 `int f(int a,int b,int c,int d,int e,int g,int h)` 里
  h 在哪；`g` 在哪个寄存器。
- **TCC 对照**：`src/core/x86_64-gen.c` 里 `arg_map/arg_regs` 那张表（搜 `REG_TEXT` 附近）。

## 7.2 gfunc_call：从值栈倒序卸货

- **教什么**：调用现场（卷 3 的便利贴栈）：`f(a,b,c)` 编译完参数后栈上躺着 3 张纸，
  **最上面是 c**。所以 `gfunc_call(3)` 从栈顶开始弹=从 c 弹到 a，
  第 k 个弹出来的放第 k 个位置——刚好符合"从右往左"的栈传参顺序，也符合寄存器倒装。
- **你要写出**：`gfunc_call(nb_args)`：弹栈 + `gv(RC_INT)` + `mov` 到目标寄存器/栈槽 + `call`。
- **通关暗号**：`./mcc "int add(int a,int b){return a+b;} add(2,3);"` → `CPU 说: 5`。
- **TCC 对照**：`src/core/i386-gen.c:420` `gfunc_call()` 的"倒序弹栈"循环；
  函数调用语法在 `unary()` 的 `(` 分支（tccgen.c:5157 起，注意它先压隐式 sret 指针）。

## 7.3 prolog/epilog：盖房与拆房

- **教什么**：进入函数：`push rbp; mov rbp,rsp; sub rsp,N`
  （N = 本地变量+溢出槽位，卷 3 的 save_reg 往这塞东西用的就是 `[rbp-x]`）；
  出去：恢复 callee-saved、`leave; ret`。
  **关键洞察**：卷 3 说"溢出=塞回它自己的家"——那个"家"就是 prolog 预留的栈帧槽！
  两卷在这里合龙。
- **你要写出**：`gfunc_prolog/epilog`；mcc 支持函数定义（参数登记进 local_stack，
  复用卷 5 的 sym_push）。
- **通关暗号**：`./mcc --run` 跑 gcd 递归（卷 6 毕业考改写），100% 正确。
- **TCC 对照**：`src/core/i386-gen.c:513` `gfunc_prolog`（注意它按 `func_vc` 算局部空间）和
  `gen_function()`（tccgen.c:7054）的编排骨架。

## 7.4 递归与栈：为什么不会死

- **教什么**：每次调用一张新栈帧，`call` 把"我念到第几行"压进栈。
  递归 = 一摞信纸；`return` 沿路退回。手动模拟 `fact(3)` 的栈变化（画图）。
- **你要写出**：递归阶乘跑通 + 故意 `while(1) f();` 观察栈耗尽
  （和真 TCC 一样，段错误——然后你理解为什么 TCC 不检查栈）。
- **通关暗号**：`fib(20)=6765` 且用 `--dump` 数出函数体里正好有 2 处 `call`。
- **TCC 对照**：`src/core/tccgen.c:7054` `gen_function()`；无栈检查就是全部"处理"。

## 7.5 结构体返回值：两种宇宙

- **教什么**：小结构（16 字节内）可以塞两个寄存器带回来（rax:rdx）；
  大结构怎么办？——**调用者偷偷多传一个隐藏参数：返回缓冲区地址**。
  TCC 的 `gfunc_sret()` 就是在问后端"这结构走哪条路"。
- **你要写出**：`>8 字节` 的 struct 返回走隐藏指针；测试 `struct S make(){...}`。
- **通关暗号**：`./mcc "struct S{long long a;};struct S m(){struct S s;s.a=9;return s;} m().a;"` → `CPU 说: 9`。
- **TCC 对照**：`src/core/tccgen.c:5183-5207`（sret 分支，`gfunc_sret`）；
  `src/core/x86_64-gen.c` 里的 `gfunc_sret`。

## 7.6 printf：变参之谜

- **教什么**：`printf("x=%d",x)`——函数怎么知道外面传了几个参数？
  x86-64 的答案很土：变参函数被调用前，`al` 里放"用了几个浮点寄存器"，
  **其余全靠格式字符串自己数**。mcc 简化：把 printf 当"宿主提供函数"（卷 10 再解决符号）。
- **你要写出**：函数原型解析支持 `...`；调用变参函数前 `mov al,0`。
- **通关暗号**：写一个自己实现的 `sum(n, ...)`（用 va_list 的等价物：栈偏移数），
  `./mcc "sum(3,10,20,30);"` → `CPU 说: 60`。
- **TCC 对照**：`src/core/tccgen.c` `FUNC_ELLIPSIS` 的判断、
  `src/core/libtcc.c` 里 `__builtin_va_*` 的登记、`lib/va_list.c` 运行时。

## 7.7 函数指针与毕业考

- **教什么**：`int (*f)(int)=add; f(2);`——函数指针 = "带类型标签的地址"。
  调用时把便利贴上的 CONST|SYM 换成间接 call。
- **你要写出**：函数指针调用 + 本卷毕业考。
- **通关暗号**：
  ```c
  int add(int a,int b){return a+b;} int mul(int a,int b){return a*b;}
  main(){ int (*f)(int,int)=add; int r=f(2,3); f=mul; return r+f(2,3); }
  ```
  → `CPU 说: 11`。

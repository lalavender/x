# 卷12 · 毕业项目

> **本卷目标**：把前 11 卷的零件打磨成一个**有测试集、有文档、跑得快**的
> 正式小编译器 `mcc`，并通过毕业考。毕业后，编译原理这四个字对你不再有神秘感。
> **预计**：6 篇，约 1-2 周。

## 12.1 写你自己的"C 子集"规格书

- **教什么**：正经编译器都有实现文档。给你的 mcc 写 `SPEC.md`：
  支持哪些语法（逐条对应卷 3-10）、不支持什么（浮点？位域？——诚实标注）、
  目标平台、错误信息策略。这份文档 = 你未来任何开源项目的门面。
- **通关暗号**：SPEC 里每一条"支持"都有卷 1-10 的某篇文档背书；
  每一条"不支持"你都知道**差哪几行代码**（写不出来才叫真不支持）。

## 12.2 移植 tests2：自动化测试台

- **教什么**：真 TCC 的测试集在 `tests/tests2/`（编号 .c + .expect 对照）。
  你的测试台：把 mcc 支持的子集用例列清单 → `run_tests.sh`：
  每个用例 `mcc -run X.c`，输出与 .expect diff。
  **这是卷 11 没教的工程课**：测试驱动编译器的开发。
- **通关暗号**：≥40 个用例，一键全绿（允许个别标注已知失败，但你要写清原因）。

## 12.3 给 mcc 提速

- **教什么**：TCC 编译 10 万行 C 只要零点几秒，靠的是：
  intern（4.1）、纸带直写（8.1）、不建树（3.x）、录音带宏（4.2）、include 缓存（4.4）、
  符号表 O(1) 进出（5.1）。逐条检查你的 mcc 做齐了几条，补上没做的。
  用 `time` 做基准：编译 1000 行测试文件，目标 < 真 TCC 同机耗时的 5 倍
  （你写 C 的水平肯定不如 Bellard，5 倍是诚实的及格线）。
- **通关暗号**：优化前后 `time` 对比截图存档。

## 12.4 ONE_SOURCE：一行 C 编译全世界

- **教什么**：把 mcc.c 重组成 `mcc.c + #include` 的 ONE_SOURCE 结构
  （对照 `src/core/tcc.c:23` 和 `src/core/libtcc.c:40-72`），
  然后用真 tcc 现场编译你自己的 mcc——让 TCC 编译你造的"小 TCC"：
  `tcc -o mcc_self mcc.c`，跑通毕业考。**这是你的毕业照。**
- **通关暗号**：`gcc -c mcc.c` 与 `tcc -c mcc.c` 产出的 mcc 行为一致。

## 12.5 选做挑战（任选其一，毕业加分）

- **自举**：mcc 编译 mcc 自己（子集裁剪得当的话——你会有"造出永动机"的错觉，
  历史上编译原理管这叫 bootstrapping，TCC 也真的能编译它自己，见 `tests/` 的
  tcctest 系列用 tcc 跑 tcc 源码）；
- **第二后端**：给你的 mcc 加 ARM64 后端——只改 `src/targets` 那一层
  （对照契约 11.6 读 `src/targets/arm64-gen.c`），体会"单遍架构下换后端有多轻"；
- **边界检查器**：抄 `lib/bcheck.c` 的思路，给 mcc 加 `-b`：
  每次指针算术插一个 `__bound_ptr_add` 调用（对照 tccgen.c 的 `VT_MUSTBOUND`）。

## 12.6 毕业考

综合测试卷（自己出，但必须包含以下场景，逐项验收）：
1. 100 行综合程序（struct 链表 + 函数指针排序 + 递归归并 + goto 错误处理 + 变参 printf）→ 一次通过；
2. tests2 移植测试台 ≥40 绿；
3. `mcc -run script.c` 当脚本用（shebang）；
4. 白板讲《`int f(int a){return a+1;}` 变机器码》30 分钟，中间每被问一个"为什么"
   你都能答到具体卷号（"问得好，这在卷 7.1/7.3……"）。

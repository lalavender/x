# 卷02 · 亲手执行机器码

> **本卷目标**：不再"当场算出答案"，而是教 mcc **写出一串机器码字节**，
> 然后让 CPU **真的执行你写的字节**。这是第一次"卧槽"时刻。
> **预计**：5 篇，约 1 周。

上一卷的机器人是"心算"。这一卷要造一个"笔算"机器人：
它不回答问题，它**把答案写成一封信（一串字节）**，交给 CPU 去执行。
这就是"编译"两个字的本义。

---

## 2.1 x86 的格子柜：寄存器与最小指令集

- **教什么**：CPU 手边有 16 个快速格子，叫 `rax, rbx, rcx, rdx, rsi, rdi, rsp, rbp, r8...r15`。
  x86 机器码看着吓人，其实规律很简单：`操作码 + 修饰字节(modrm)`。
  本卷只学 6 条指令，足够玩转一切：
  | 指令 | 字节 | 意思 |
  |---|---|---|
  | `mov rax, 立即数` | `48 C7 C7 <4字节>` | 把数放进 rax |
  | `add rax, rbx` | `48 01 D8` | rax = rax + rbx |
  | `sub rax, rbx` | `48 29 D8` | 减 |
  | `imul rax, rbx` | `48 0F AF C3` | 乘 |
  | `cqo; idiv rbx` | `48 99 48 F7 F9` | 除（rax/ rbx）|
  | `ret` | `C3` | 交卷，回家 |
- **你要写出**：没有编译器任务。练习：手抄 3 个 C 语句，人肉翻译成字节串，
  用 `printf` 写进文件（或直接看下一节工具）核对 `gcc -S`+`objdump` 的权威输出。
- **通关暗号**：口头/纸面：`mov rax,5` 的完整 7 个字节是什么？`add rax,rbx` 的 4 个字节呢？
- **TCC 对照**：`src/core/i386-gen.c:98-124`——真 TCC 发射指令就 3 个函数：
  `g()` 写一个字节、`gen_le32()` 写 4 字节小端、`gen_modrm()` 写修饰字节。
  它发射的就是你刚背的这几条。

## 2.2 让 CPU 执行你的第一串字节（内存执行初体验）

- **教什么**：Linux/macOS 上可以 `mmap` 申请一块内存，把机器码字节写进去，
  把页面改成"可执行"，然后像函数一样调用它。这段"黑魔法"代码只有 20 行，
  而且它其实就是 **TCC 的 `-run` 的完整原理**（第 10 卷我们会正式学）。
- **你要写出**：一个 `runner.c` 小工具：
  ```c
  int run_bytes(unsigned char *code, int len);  // 复制→mmap(PROT_READ|WRITE|EXEC)→调用→返回 int
  ```
- **动手**：`run_bytes((unsigned char[]){0x48,0xC7,0xC0,42,0,0,0, 0xC3}, 8)` → 返回 42。
- **通关暗号**：你的程序打印 `CPU 说: 42`。**你第一次让 CPU 执行了你亲手写的机器码。**
- **TCC 对照**：`src/core/tccrun.c:179` `tcc_relocate_ex()`——干的就是这事：
  复制节→`mprotect`/`set_pages_executable`（tccrun.c:280）→调 main。你写的 20 行是它的神。

## 2.3 表达式编译器：从"算"到"写"

- **教什么**：把卷 1 的递归下降改造成**代码生成器**：
  函数不再返回"算好的数"，而是**往一块缓冲区里发射机器码**，
  约定"算完后答案在 rax 里"。`parse_expr()` 变成 `gen_expr()`。
  乘除需要"暂时腾出手"时用 rbx/rdx——你已经摸到"寄存器分配"的门了。
- **你要写出**：`gen_expr()` 支持数字+四则+括号，把指令字节写进 `unsigned char code[4096]`；
  末尾自动发射 `ret`。
- **通关暗号**：`./mcc "1+2*3"` → 打印十六进制字节串 + `CPU 说: 7`。
  （对，CPU 说 7。不是你的程序算出来的——是**它**算的。）
- **TCC 对照**：`src/core/tccgen.c:2154` `gen_op()`——TCC 的"表达式归约"入口，
  也是接到后端 `gen_opi()`（i386-gen.c:750 发射 ALU 指令）。

## 2.4 寄存器不够用了：栈来救场

- **教什么**：`a*b + c*d` 只有一份 rax + 一份 rbx，不够用怎么办？
  把算了一半的中间结果**先存到栈上**（`push`），要用再取（`pop`）。
  rsp 这个寄存器就是"栈顶指针"。这是编译器"溢出(spill)"概念的萌芽。
- **你要写出**：给 2.3 加规则：嵌套超过两层寄存器时，用
  `push rbx / pop rbx` 套路（`53`/`5B`）。测试用例自己设计，至少 3 个四层嵌套式。
- **通关暗号**：`./mcc "(1+2)*(3+4)+5*(6-2)"` → `CPU 说: 29`。
- **TCC 对照**：`src/core/tccgen.c:962` `save_reg()`/`1062` `get_reg()`——
  TCC 的"腾手"比你会的多得多：它把整个值栈当仓库，需要哪个寄存器就"借"，
  借不到就把值栈里的旧货放回它原本在内存的家（溢出=写回栈帧）。卷 3 见全貌。

## 2.5 本卷收尾：给你的输出做个"反汇编自检"

- **教什么**：专业习惯：编译器生成的机器码，要能用别人的反汇编器验证自己。
  写一个 `dump.c`：把 code[] 写成 `.text` 裸二进制，用 `objdump -D -b binary -m i386:x86-64` 反汇编。
- **你要写出**：mcc 加 `--dump` 选项，打印人类可读的汇编文本。
- **通关暗号**：`./mcc --dump "10-3"` 的汇编里能看见 `mov`、`sub`、`ret`，
  且 `CPU 说: 7`。

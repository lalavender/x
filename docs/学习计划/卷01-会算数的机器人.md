# 卷01 · 会算数的机器人

> **本卷目标**：不碰任何"编译"字眼，先造一个**解释器**——一个会算 `1+2*3` 的机器人。
> 学完你会明白"解析"是怎么回事，而且手上有能跑的东西。
> **预计**：6 篇，约 1 周。

先记住一句话：**编译器就是翻译官。翻译一句话之前，得先听懂它。**
这一卷我们造的第一个机器人只负责"听懂并当场算出答案"，不负责"翻译成别的语言"。
翻译是后面几卷的事。别急。

---

## 1.1 计算机其实只认识数字

- **教什么**：内存是一排格子，每个格子放一个字节（0~255）。
  CPU 是一个只会做"把几个数字加起来/挪来挪去"的死脑筋。
  你写的 C 程序，最后会变成一串数字，比如 `48 31 C0` 就是"ax = ax + 0"。
  这串数字叫**机器码**。编译器的工作 = 把 `a+1` 这种人话换成数字串。
- **你要写出**：没有代码任务。这一篇只做两件事：
  1. 写 5 行 C：`int main(){return 2+3;}`，用 `gcc -S` 看它变成的"汇编"；
  2. 用 `objdump -d a.out`（或 `otool -tV`）找到 `main` 的那几行，
     圈出其中两个十六进制数，猜哪个数是 2、哪个是 3。
- **通关暗号**：口头回答——"`return 2+3` 的机器码里，加法指令的机器码字节是什么？
  返回值的数字放在哪个'格子'（寄存器）里？"（答案在文档正文里给。）
- **TCC 对照**：`src/core/libtcc.c` 里 `tcc_new()` 一行的注释——它一开始就是为"把人话变数字"存在的。

## 1.2 拆词游戏：词法器

- **教什么**：翻译第一步是把句子拆成单词。`int x = 1+2*3;` 拆成
  `int`、`x`、`=`、`1`、`+`、`2`、`*`、`3`、`;`。这些"单词"叫 **token**。
  拆词的程序叫**词法器**：一个字符一个字符读，凑成一个一个 token。
- **你要写出**：`mcc.c` 的第一版：
  - 一个全局 `char *p`（手指头，指着读到哪了）；
  - 函数 `int next(void)`：跳空格、识别数字（返回一个数字 token）、
    识别 `+ * ( )`（直接返回字符本身当 token）；
  - `main` 里循环调 `next()`，把拆出来的词一行一个打印。
- **动手**：故意输入 `1 +2*(3+4)`，检查拆得对不对；再试试 `1++2` 会不会崩（不会，先不管）。
- **通关暗号**：`./mcc "1+2*30"` 输出 5 行：`1`、`+`、`2`、`*`、`30`。
- **TCC 对照**：真 TCC 的词法器叫 `next_nomacro1()`，在 `src/core/tccpp.c:2561`。
  它的开头也是"跳空格"，和你写的一模一样——只是它的"手指头"是 `file->buf_ptr`。

## 1.3 先乘后加：递归下降

- **教什么**：拆出词还不够，`1+2*3` 得知道是 `1+(2*3)`。
  秘诀：**给每种运算规定一个"优先级"，用函数的嵌套来表达**。
  写三层函数：`expr()`（管加减）→ `term()`（管乘除）→ `primary()`（管数字和括号）。
  这个套娃套路叫**递归下降**，全世界解析器的 90% 都是它变的。
- **你要写出**：把 1.2 的词法器接上，实现 `primary → term → expr`，
  先不要输出任何东西，让函数**直接返回算出来的数**。
- **动手**：`((2+3)*4)-6` 应该得 14。故意少打一个右括号 `((2+3)*4`，看你的程序
  怎么优雅地报错（学 `expect()` 这个词，TCC 里到处都是）。
- **通关暗号**：`./mcc "((2+3)*4)-6"` → `14`。
- **TCC 对照**：真 TCC 的优先级阶梯在 `src/core/tccgen.c`：
  `expr_eq`(5655)→`expr_cond`(5480)→…→`expr_sum`(5299)→`expr_prod`(5286)→`unary`(4594)。
  比你多几层，但套路一模一样——它从 `unary()` 往上爬，你从 `primary()` 往上爬。

## 1.4 把算式画出来：第一次摸到"语法树"

- **教什么**：刚才的函数直接吐数字，是因为我们顺便算了。
  如果把"结构"先记下来再算，那堆结构就叫**语法树（AST）**——
  教科书编译器全靠它吃饭。我们先造一个，**下下卷就把它扔掉**（TCC 就没有！），
  这样你才知道 TCC 为什么敢扔。
- **你要写出**：
  ```c
  typedef struct Node { int op; struct Node *a, *b; int val; } Node;
  Node *parse_expr(void);   // 返回树而不是数字
  int eval(Node *n);        // 树 → 答案
  ```
- **通关暗号**：`./mcc "1+2*3"` 打印
  ```
  + 1 * 2 3      // 你的树长这样
  = 7
  ```
- **TCC 对照**：`src/core/tccgen.c` 文件里搜 `struct SValue`（`src/core/tcc.h:424`）——
  这就是 TCC 的"反树"：它不攒结构，攒的是"半成品值"。卷 3 见分晓。

## 1.5 给机器人装一个记性：变量

- **教什么**：`x = 5; x = x + 1;` 里，x 是什么？——一个贴了名字标签的格子。
  程序跑之前，名字和格子的对应关系记在一张表里，这张表叫**符号表**（本卷先用
  最简单的"数组当字典"糊弄过去，卷 5 再做正规货）。
- **你要写出**：
  - 词法器认标识符（字母开头）；
  - `parse` 支持 `IDENT = 表达式 ;` 和单独的 `IDENT ;`（后者=打印值）；
  - 一张 `struct { char name[32]; int val; } sym[100];` 表。
- **通关暗号**：`./mcc "x=5; x=x+1; x;"` → `6`。
- **TCC 对照**：真 TCC 的符号表叫 `Sym`，在 `src/core/tcc.h:465`，
  比你这张表复杂 100 倍——但本质就是你这个"名字→东西"的映射。

## 1.6 本卷收尾：把机器人改造成"流水线"

- **教什么**：复盘：你刚才写的东西已经有三个模块——
  **词法器 → 解析器 → 求值器**。所有编译器都是这三步的变体。
  把它们拆成三个清晰的函数阶段，给你的 mcc 起名字、留好扩展位。
- **你要写出**：重构代码；加 `--tree` 选项打印树，方便以后每加一个功能就看看"树对不对"。
- **通关暗号（本卷毕业考）**：
  `./mcc --tree "a=2; b=3; a*a+b*b;"` → 正确的树 + `= 13`。

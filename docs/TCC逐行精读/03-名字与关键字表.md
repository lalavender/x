# 03 · 名字与关键字表：一个名字只存一份，编号从哪来

> **本步输入**：一个名字的字符串（比如 `add`、`main`、`int`）
> **本步输出**：一个整数编号 `tok`，代表这个名字
>
> 对应源码：`src/core/tccpp.c:61-65`（关键字字符串表）、`src/core/tcc.h:1070-1078`
> （token 编号 enum）、`src/core/tccpp.c:413`（`tok_alloc_new`）、
> `src/core/tccpp.c:443-469`（哈希 + `tok_alloc`）、
> `src/core/tccpp.c:473`（`get_tok_str` 反向查名字）、
> `src/core/tccpp.c:3634`（`tccpp_new` 初始化）。

---

## 第 0 站：先搞懂"token 编号"是怎么定的

第 02 篇说"关键字编号写死在 `tcctok.h` 里"。到底怎么写死的？看 `tcc.h:1070`：

```c
/* src/core/tcc.h:1070-1078 */
enum tcc_token {
    TOK_LAST = TOK_IDENT - 1        /* = 255 */
#define DEF(id, str) ,id               /* ★ 把 DEF(x,"y") 变成 ", x" */
#include "tcctok.h"
#undef DEF
};
#define TOK_UIDENT TOK_DEFINE
```

再看 `tcctok.h` 开头（`src/core/tcctok.h`，注意它不在 core 目录里）：

```c
/* src/core/tcctok.h 开头 */
/* keywords */
DEF(TOK_INT, "int")
DEF(TOK_VOID, "void")
DEF(TOK_CHAR, "char")
DEF(TOK_IF, "if")
...
```

预处理器把 `#include "tcctok.h"` 展开后，`tcc.h:1070` 那个 enum 实际上变成：

```c
enum tcc_token {
    TOK_LAST = 255,
    , TOK_INT      /* 无语法的逗号？其实上一项 TOK_LAST 后面接 ,id 正好合法 */
    , TOK_VOID
    , TOK_CHAR
    , TOK_IF
    ...
};
```

> **小陷阱**：`DEF` 展开成 `, TOK_INT`，第一行 `TOK_LAST = TOK_IDENT - 1`
> 后面直接跟逗号也没关系——`enum { A = 1, , B }` 非法，
> 但这里是 `TOK_LAST = 255` 后面跟 `,TOK_INT`，也就是 `TOK_LAST = 255, TOK_INT`，
> 完全合法。**作者就是利用这个逗号技巧，让 `tcctok.h` 能同时被用两次。**
>
> （严格说这里 `enum { TOK_LAST = 255 ,TOK_INT ,TOK_VOID ... }` 是对的；
> `TOK_LAST` 本身不是 token，它只是给 C 枚举定一个起点。）

于是编号就是：

| 编号 | 谁 |
|---|---|
| `-1` | `TOK_EOF`（`tcc.h:979`） |
| `10` | `TOK_LINEFEED`（换行，正好等于 `'\n'`） |
| `0..255` | 单字符符号（ASCII 码，见第 02 篇）+ 少量多字符符号（`TOK_LE=0x...` 等，`tcc.h:975`） |
| `256` | `TOK_IDENT` 起步：**关键字**（`int`、`void`、`if`…按 `tcctok.h` 顺序） |
| 之后 | 更多关键字和内部 token，直到 `TOK_DEFINE` 为止（`TOK_UIDENT`） |
| `TOK_UIDENT` 之后 | 还不算"用户标识符"，是内部 token |
| `>= TOK_IDENT` 且**动态分配**的编号 | **用户标识符**（`add`、`main`、`x`…） |

**为什么关键字和用户标识符都用 `>= TOK_IDENT` 的编号？**
因为词法器遇到 `int` 时，只要它的编号 `< TOK_UIDENT`，就知道"这是关键字，不能当变量名"。
一个区间判断代替查表。

## 第 1 站：两套并行的表，同一个 `tcctok.h`（`tccpp.c:61`）

编号有了，那**名字字符串**在哪？在 `tccpp.c:61`：

```c
/* src/core/tccpp.c:61-65 */
static const char tcc_keywords[] =
#define DEF(id, str) str "\0"      /* ★ 把 DEF(x,"y") 变成 "y\0" */
#include "tcctok.h"
#undef DEF
;
```

同一个 `tcctok.h`，`DEF` 被定义了两次、展开了两次：

- 在 `tcc.h:1072`：`#define DEF(id, str) ,id` → 生成**编号枚举**；
- 在 `tccpp.c:62`：`#define DEF(id, str) str "\0"` → 生成**名字字符串**。

展开后 `tcc_keywords` 就是：

```c
static const char tcc_keywords[] =
    "int\0" "void\0" "char\0" "if\0" ... ;
```

也就是一串**用 `\0` 隔开的字符串**，像一串糖葫芦。
**关键点：两套表的顺序完全一样**，因为都来自同一个 `tcctok.h`。

## 第 2 站：初始化时配对（`tccpp.c:3634-3677`）

```c
/* src/core/tccpp.c:3634-3677（节选）*/
ST_FUNC void tccpp_new(TCCState *s)
{
    ...
    /* init isid table */
    for(i = CH_EOF; i<128; i++)
        set_idnum(i, is_space(i) ? IS_SPC : isid(i) ? IS_ID : isnum(i) ? IS_NUM : 0);
    for(i = 128; i<256; i++)
        set_idnum(i, IS_ID);

    /* init allocators */
    tal_new(&toksym_alloc, TOKSYM_TAL_LIMIT, TOKSYM_TAL_SIZE);
    ...
    memset(hash_ident, 0, TOK_HASH_SIZE * sizeof(TokenSym *));
    cstr_new(&cstr_buf);
    ...
    tok_ident = TOK_IDENT;                  /* ★ 下一个可用编号 = 256 */
    p = tcc_keywords;
    while (*p) {                            /* ★ 遍历关键字字符串表 */
        r = p;
        for(;;) {
            c = *r++;
            if (c == '\0')
                break;
        }
        tok_alloc(p, r - p - 1);            /* ★ 每个关键字登记进名字表 */
        p = r;
    }
}
```

逐行：

- `tok_ident = TOK_IDENT`（256）：**下一个要分配的编号**从这里开始。
- `p = tcc_keywords`：指向那串糖葫芦。
- 内层 `for` 从 `p` 扫到下一个 `\0`，算出这个关键字名字的长度。
- `tok_alloc(p, r-p-1)`：把这个关键字登记进名字表。

**因为 `tok_alloc` 是顺序调用的，第 1 个关键字得到的编号必然是 256、第 2 个是 257……
正好和 `tcc.h` 里的 enum 编号一一对上。** 这就是两套表配对的秘密。

## 第 3 站：造一个名字的座位 —— `tok_alloc_new`（`tccpp.c:413`）

```c
/* src/core/tccpp.c:412-441 */
static TokenSym *tok_alloc_new(TokenSym **pts, const char *str, int len)
{
    TokenSym *ts, **ptable;
    int i;

    if (tok_ident >= SYM_FIRST_ANOM)     /* 编号用光了？ */
        tcc_error("memory full (symbols)");

    /* 名字表数组要按需增长 */
    i = tok_ident - TOK_IDENT;
    if ((i % TOK_ALLOC_INCR) == 0) {     /* 每 512 个扩一次 */
        ptable = tcc_realloc(table_ident, (i + TOK_ALLOC_INCR) * sizeof(TokenSym *));
        table_ident = ptable;
    }

    ts = tal_realloc(toksym_alloc, 0, sizeof(TokenSym) + len);  /* ① 分配 */
    table_ident[i] = ts;                 /* ② 登记到数组第 i 格 */
    ts->tok = tok_ident++;               /* ③ ★ 领编号 */
    ts->sym_define = NULL;               /* ④ 四个抽屉都空着 */
    ts->sym_label = NULL;
    ts->sym_struct = NULL;
    ts->sym_identifier = NULL;
    ts->len = len;
    ts->hash_next = NULL;
    memcpy(ts->str, str, len);           /* ⑤ 把名字拷进去 */
    ts->str[len] = '\0';
    *pts = ts;                           /* ⑥ 接到哈希桶链尾 */
    return ts;
}
```

关键顺序：

1. **先按长度 `sizeof(TokenSym) + len` 分配**。`TokenSym` 的 `str[1]` 又是那个"柔性数组"花招，
   实际能装下整个名字。
2. **`table_ident[i] = ts`**：`table_ident` 是一张"编号 → TokenSym"的大表。
   第 `i` 格的编号就是 `TOK_IDENT + i`。于是**给出编号，就能 O(1) 反查名字**。
3. **`ts->tok = tok_ident++`**：领编号。
4. **四个抽屉**：`TokenSym` 定义在 `tcc.h:381`：
   ```c
   typedef struct TokenSym {
       struct TokenSym *hash_next;   /* 哈希桶里的下一个 */
       struct Sym *sym_define;       /* #define 抽屉 */
       struct Sym *sym_label;        /* 标签抽屉 */
       struct Sym *sym_struct;       /* struct/union 抽屉 */
       struct Sym *sym_identifier;   /* 变量/函数抽屉 */
       int tok;                      /* 编号 */
       int len;
       char str[1];                  /* 名字本体 */
   } TokenSym;
   ```
   **为什么要四个抽屉？** 因为 C 允许同一个名字同时是四种东西：
   ```c
   #define foo 1        /* 宏 foo */
   int foo;             /* 变量 foo */
   struct foo { int x; };   /* 类型 foo */
   foo:                 /* 标签 foo */
   ```
   一个 `TokenSym` 管名字本体，四个 `Sym*` 各管一个"世界"，互不打架。

## 第 4 站：哈希表怎么串 —— `tok_alloc`（`tccpp.c:443-469`）

```c
/* src/core/tccpp.c:443-444 */
#define TOK_HASH_INIT 1
#define TOK_HASH_FUNC(h, c) ((h) + ((h) << 5) + ((h) >> 27) + (c))

/* src/core/tccpp.c:447-469 */
ST_FUNC TokenSym *tok_alloc(const char *str, int len)
{
    TokenSym *ts, **pts;
    int i;
    unsigned int h;

    h = TOK_HASH_INIT;
    for(i=0;i<len;i++)
        h = TOK_HASH_FUNC(h, ((unsigned char *)str)[i]);   /* 算哈希 */
    h &= (TOK_HASH_SIZE - 1);                              /* 取模到 0..16383 */

    pts = &hash_ident[h];                                  /* 找到桶 */
    for(;;) {
        ts = *pts;
        if (!ts) break;                                    /* 空桶：没找到 */
        if (ts->len == len && !memcmp(ts->str, str, len))
            return ts;                                     /* 是同一个名字 */
        pts = &(ts->hash_next);                            /* 看下一个 */
    }
    return tok_alloc_new(pts, str, len);                   /* 新建并挂到链尾 */
}
```

这是最经典的"哈希表 + 链地址法"：

- `hash_ident[16384]`（`tccpp.c:43`）是桶数组。
- 同一个哈希值的名字，用 `hash_next` 串成一条链。
- 先比长度（`ts->len == len`），长度一样才逐字节 `memcmp`——**先便宜后昂贵的比较**。
- `pts` 是"指向链尾那个 `NULL` 的指针"，所以 `*pts = ts` 就是"挂到链尾"。

**好处**：不管源文件里 `add` 出现 1 次还是 1000 次，内存里**只有一个 `TokenSym`**。
后面所有地方判断两个 `add` 是不是同名，只要比较**编号**（一个整数）即可。

> `next_nomacro1` 的标识符快路径（第 02 篇）其实就是**把 `tok_alloc` 的哈希和查找内联展开**，
> 为的是少一次函数调用。逻辑一模一样。

## 第 5 站：反查名字 —— `get_tok_str`（`tccpp.c:473`）

有时候手里只有编号，要打印成名字（报错时）。这就是 `get_tok_str`：

```c
/* src/core/tccpp.c:473-583（节选）*/
ST_FUNC const char *get_tok_str(int v, CValue *cv)
{
    char *p;
    int i, len;

    cstr_reset(&cstr_buf);
    p = cstr_buf.data;

    switch(v) {
    case TOK_CINT: ... /* 数字：把值打印出来 */
        sprintf(p, "%llu", ...);
        break;
    case TOK_PPNUM:
    case TOK_PPSTR:
        return (char*)cv->str.data;      /* 原始文本直接返回 */
    ...
    case TOK_EOF:
        return strcpy(p, "<eof>");
    default:
        if (v < TOK_IDENT) {
            /* 1~255：多半是单字符符号，或查 tok_two_chars 表 */
            ...
        } else if (v < tok_ident) {
            return table_ident[v - TOK_IDENT]->str;    /* ★ 反查名字表 */
        } else if (v >= SYM_FIRST_ANOM) {
            sprintf(p, "L.%u", v - SYM_FIRST_ANOM);    /* 匿名符号 */
        } else {
            return NULL;
        }
    }
    return cstr_buf.data;
}
```

最漂亮的一行就是：

```c
return table_ident[v - TOK_IDENT]->str;
```

**给出编号 `v`，减 256 得到下标，直接取出 `TokenSym` 的名字。**
O(1)，不用查任何哈希表。这是"编号即下标"的胜利。

## 第 6 站：编号还会被用来当"名字的身份"

到这里你已经能看出 TCC 的一个核心约定：

> **在 TCC 的绝大部分代码里，一个"名字"就是一个小整数。**
> 比较名字 = 比较整数；存名字 = 存整数；查名字表 = 用整数当下标。

例子：

- `Sym.v`（`tcc.h:466`）存的就是这个整数编号；
- `TokenString` 里的 token 也是整数（第 09 篇）；
- `define_find(v)`（`tccpp.c:1324`）就是"用编号查 `sym_define` 抽屉"：
  ```c
  ST_INLN Sym *define_find(int v) {
      v -= TOK_IDENT;
      if ((unsigned)v >= (unsigned)(tok_ident - TOK_IDENT))
          return NULL;
      return table_ident[v]->sym_define;    /* 直接取抽屉 */
  }
  ```

**所以宏展开、符号查找快到离谱：全是数组下标访问，零字符串比较。**

## 【把 t.c 的名字登记一遍】

按顺序：

| 名字 | 谁登记的 | 拿到的编号 |
|---|---|---|
| `int` | `tccpp_new` 里 `tok_alloc` 第一个关键字 | 256（和 enum 里 `TOK_INT` 一致） |
| `void`、`char`、`if`… | 依次 | 257、258、259… |
| `add` | 读 `t.c` 时 `next_nomacro1` 快路径 | 某个 `>= TOK_IDENT` 的动态编号（比如 900） |
| `main`、`a`、`b`、`x`、`y` | 同上 | 各自唯一编号 |
| `K` | 同上（它要作为宏名存在，所以也必须有 TokenSym） | 另一个编号 |

从此刻起，`t.c` 里的 `add` 在内存里就是一个整数；`#define K 8` 会把
`table_ident[K编号]->sym_define` 指向一个 `Sym`。

## 【常见卡点】

- **`DEF` 被定义两次**：一次在 `tcc.h`（造编号），一次在 `tccpp.c`（造名字串），
  顺序一致所以能配对。
- **`TOK_IDENT = 256` 而不是 0 或 1**：因为 0..255 留给单字符符号（ASCII），
  256 起步才不与它们冲突。
- **`token_buf` / `tokcstr` / `cstr_buf` 三个缓冲区别混**：
  `token_buf` 给数字用，`tokcstr` 给"当前 token 的字符串"，`cstr_buf` 给 `get_tok_str` 用。

# 40 · 形参与实参配对：`gfunc_param_typed`

> **一句话**：函数调用时，每求出一个实参，就要把它和对应的形参比对类型并隐式转换。
> 老式函数（无原型）和 `...` 之后的实参走"默认提升"（`float`→`double`）。
>
> 对应源码：`src/core/tccgen.c:4511`（`gfunc_param_typed`）、
> `:4220`（`convert_parameter_type`）、`:5157`（`unary` 的调用分支，第 19 篇）。

---

## 第 0 站：形参链回顾

第 33 篇讲过，函数类型的 `ref->next` 是形参链，每个形参是一个带 `SYM_FIELD` 的 `Sym`。
调用时（`unary`，`tccgen.c:5234`）：

```c
/* src/core/tccgen.c:5234-5245（重贴）*/
            if (tok != ')') {
                for(;;) {
                    expr_eq();                 /* 求一个实参 → 压值栈 */
                    gfunc_param_typed(s, sa);  /* ★ 配对 + 转换 */
                    nb_args++;
                    if (sa) sa = sa->next;     /* 下一个形参 */
                    if (tok == ')') break;
                    skip(',');
                }
            }
```

`sa` 沿形参链走，走完还继续给实参就报"too many arguments"。

## 第 1 站：`gfunc_param_typed`（`tccgen.c:4511`）

```c
/* src/core/tccgen.c:4511-4534 */
static void gfunc_param_typed(Sym *func, Sym *arg)
{
    int func_type;
    CType type;

    func_type = func->f.func_type;      /* FUNC_NEW / FUNC_OLD / FUNC_ELLIPSIS */
    if (func_type == FUNC_OLD ||
        (func_type == FUNC_ELLIPSIS && arg == NULL)) {
        /* 无原型 或 ... 之后的实参：默认提升 */
        if ((vtop->type.t & VT_BTYPE) == VT_FLOAT) {
            gen_cast_s(VT_DOUBLE);      /* ★ float → double（C 默认实参提升） */
        } else if (vtop->type.t & VT_BITFIELD) {
            type.t = vtop->type.t & (VT_BTYPE | VT_UNSIGNED);
            type.ref = vtop->type.ref;
            gen_cast(&type);            /* 位域提升成整数 */
        }
    } else if (arg == NULL) {
        tcc_error("too many arguments to function");   /* 实参比形参多 */
    } else {
        type = arg->type;
        type.t &= ~VT_CONSTANT;         /* 去 const，避免误报警告 */
        gen_assign_cast(&type);         /* ★ 按形参类型检查+转换（第 23 篇） */
    }
}
```

三种情况：

| 函数类型 | `arg` | 处理 |
|---|---|---|
| `FUNC_OLD`（K&R 无原型） | 任意 | 默认提升：`float`→`double`，位域→整数 |
| `FUNC_ELLIPSIS`（变参） | 已用完（`arg==NULL`） | 默认提升 |
| `FUNC_NEW` | 有对应形参 | 按形参类型 `gen_assign_cast` |
| `FUNC_NEW` | 没形参了（`arg==NULL`） | 报"实参过多" |

**"默认实参提升"**是 C 的老规矩：没有原型时，`float` 一律提升成 `double`，
小整数提升成 `int`——这样被调用者不用猜。

## 第 2 站：形参类型本身的转换 —— `convert_parameter_type`（`:4220`）

第 33 篇讲过，但这里再强调一次，因为它决定"实参该转成什么"：

```c
/* src/core/tccgen.c:4218-4230 */
static inline void convert_parameter_type(CType *pt)
{
    pt->t &= ~(VT_CONSTANT | VT_VOLATILE);
    pt->t &= ~VT_ARRAY;                  /* int a[10] 参数 → int* */
    if ((pt->t & VT_BTYPE) == VT_FUNC)
        mk_pointer(pt);                  /* int f() 参数 → 函数指针 */
}
```

所以在 `post_type` 造形参链时（第 33 篇）就已经调用过它，
形参 `Sym.type` 里存的**已经是转换后的类型**（数组变指针、函数变函数指针）。
`gfunc_param_typed` 拿到的就是转换后的类型。

## 第 3 站：实参求值顺序

`expr_eq()` 从左到右依次求值，每个实参一算完就 `gfunc_param_typed`。
值栈上实参的顺序是：

```
f(a, b, c)
  → 压 a, 压 b, 压 c
  → 栈顶是 c（最后一个实参）
```

**注意这个顺序**：后端 `gfunc_call` 要从栈顶倒着卸（第 41 篇）。
但 `gfunc_param_typed` 用的是**形参链顺序**（`sa` 从头到尾），
和值栈顺序一致（从左到右），所以配对是对的。

## 第 4 站：一个易错点 —— 变参的默认提升

```c
void printf(const char *fmt, ...);
printf("%f", 3.14f);   /* 实参 3.14f 是 float，但 ... 要 double */
```

`arg == NULL`（`...` 之后没有形参），走默认提升分支，
`gen_cast_s(VT_DOUBLE)` 把 `float` 变成 `double`。

这就是为什么 `printf("%f", 3.14f)` 正确，而如果直接传 `float` 会出错——
**ABI 要求 `...` 的浮点实参是 `double`**。

## 【把 `add(x, y)` 配对走一遍】

假设 `int add(int a, int b);`：

| 步骤 | 动作 |
|---|---|
| 1 | `unary` 读 `add`，`(` 分支，`sa = 形参链头(a)` |
| 2 | `expr_eq()` 求 `x` → 值栈顶 |
| 3 | `gfunc_param_typed(add_sym, a)`：`FUNC_NEW`，`gen_assign_cast(int)` |
| 4 | `sa = a->next = b` |
| 5 | `expr_eq()` 求 `y` → 值栈顶 |
| 6 | `gfunc_param_typed(add_sym, b)` |
| 7 | `sa = b->next = NULL`，`tok == ')'` → 结束 |
| 8 | `nb_args == 2`，`gfunc_call(2)` |

## 【动手小实验】

1. `int f(int); f(1.5);` 看是否警告/截断为 1（按形参类型转换）。
2. `printf("%f\n", 1.5f);` 正常工作——因为已提升为 double。
3. `int f(int); f(1,2);` 看报错 "too many arguments"。
4. `int f(int,int); f(1);` 看报错 "too few arguments"（在 `unary` 的 `sa` 非空时）。

## 【常见卡点】

- **三种函数类型**：`FUNC_NEW`（有原型）/`FUNC_OLD`（K&R）/`FUNC_ELLIPSIS`（变参）。
- **`...` 之后的实参走默认提升**（`float`→`double`）。
- **形参类型在 `post_type` 时就已转换**（数组→指针）。
- **实参从左到右压栈**，栈顶是最后一个。

# 63 · 崩溃回溯：内存里跑的程序也能报源码行

> **一句话**：`tcc -run -g` 运行的程序崩溃时，TCC 能打印**源码文件和行号**。
> 它靠：装信号处理器 → 从 `ucontext` 取调用栈 → 用 stabs 调试信息反查源码位置。
>
> 对应源码：`src/core/tccrun.c:338`（`rt_printline` 反查源码位置）、
> `:480`（`rt_error` 打印调用栈）、`:505`（`sig_error` 信号处理器）、
> `:546`（`set_exception_handler`）、`:571`（`rt_get_caller_pc` 取上层 PC）、
> `:39`（`rt_num_callers` 回溯层数）。

---

## 第 0 站：为什么能报源码行

普通编译的程序崩溃，OS 只给一个地址（`segfault at 0x...`），
要看到源码行得有调试信息 + 回溯工具（`gdb`/`addr2line`）。

TCC 的 `-run` 程序**在内存里**，没有文件给 `addr2line` 用。
所以 TCC **自己实现回溯**：运行时在同一个进程里，能直接访问内存中的
符号表（`symtab_section`）和调试信息（`stab_section`）。

## 第 1 站：崩溃时发生了什么 —— `sig_error`（`tccrun.c:505`）

```c
/* src/core/tccrun.c:505-544（概念）*/
static void sig_error(int signum, siginfo_t *siginf, void *puc)
{
    ucontext_t *uc = puc;
    switch(signum) {
    case SIGFPE:   rt_error(uc, "floating point exception"); break;
    case SIGSEGV:  rt_error(uc, "segmentation fault"); break;
    case SIGBUS:   rt_error(uc, "bus error"); break;
    case SIGILL:   rt_error(uc, "illegal instruction"); break;
    case SIGABRT:  rt_error(uc, "abort() called"); break;
    ...
    }
    exit(255);
}
```

`set_exception_handler`（`:546`）用 `sigaction` 注册它。
**它是 TCC 进程自己的信号处理器**——因为 `-run` 的代码就在 TCC 进程里跑。

## 第 2 站：打印调用栈 —— `rt_error`（`tccrun.c:480`）

```c
/* src/core/tccrun.c:479-499 */
static void rt_error(ucontext_t *uc, const char *fmt, ...)
{
    va_list ap;
    addr_t pc;
    int i;

    fprintf(stderr, "Runtime error: ");
    va_start(ap, fmt);
    vfprintf(stderr, fmt, ap);       /* 比如 "segmentation fault" */
    va_end(ap);
    fprintf(stderr, "\n");

    /* ★ 逐层回溯 */
    for(i = 0; i < rt_num_callers; i++) {
        if (rt_get_caller_pc(&pc, uc, i) < 0)
            break;
        pc = rt_printline(pc, i ? "by" : "at");   /* 打印这个 PC 对应的源码行 */
        if (pc == (addr_t)rt_prog_main && pc)
            break;                                /* 回溯到 main 就停 */
    }
}
```

`rt_num_callers`（`:39`，默认 6）是回溯层数。
`rt_get_caller_pc`（`:571`）从 `ucontext` 或栈帧里取"第 i 层的返回地址"。

## 第 3 站：PC → 源码行 —— `rt_printline`（`tccrun.c:338`）

这是最有趣的部分。它**读 stabs 调试信息**（`-g` 时生成，存在 `stab_section`）
反查源码位置：

```c
/* src/core/tccrun.c:338-355（节选）*/
static addr_t rt_printline(addr_t wanted_pc, const char *msg)
{
    char func_name[128], last_func_name[128];
    addr_t func_addr, last_pc, pc;
    const char *incl_files[INCLUDE_STACK_SIZE];
    int incl_index, len, last_line_num, i;
    ...
    Stab_Sym *stab_sym = NULL, *stab_sym_end, *sym;
    int stab_len = 0;
    char *stab_str = NULL;

    if (stab_section) {
        stab_len = stab_section->data_offset;
        stab_sym = (Stab_Sym *)stab_section->data;        /* 内存里的调试信息 */
        stab_str = (char *) stabstr_section->data;        /* 字符串表 */
    }
```

然后遍历 stabs 条目：

```c
/* src/core/tccrun.c:366-427（节选）*/
    for (sym = stab_sym + 1; sym < stab_sym_end; ++sym) {
        switch(sym->n_type) {
        case N_FUN:                            /* 函数开始/结束 */
            if (sym->n_strx == 0) {
                pc = sym->n_value + func_addr; /* 函数结束 */
                if (wanted_pc >= last_pc && wanted_pc < pc) goto found;
                func_name[0] = '\0'; func_addr = 0;
            } else {
                /* 函数名 */
                str = stab_str + sym->n_strx;
                ...
                func_addr = sym->n_value;
            }
            break;
        case N_SLINE:                          /* 行号信息 */
            pc = sym->n_value + func_addr;
            if (wanted_pc >= last_pc && wanted_pc < pc) goto found;  /* ★ 命中 */
            last_pc = pc;
            last_line_num = sym->n_desc;       /* 行号 */
            strcpy(last_func_name, func_name);
            break;
        case N_BINCL:                          /* 头文件开始 */
            ...
        case N_EINCL:                          /* 头文件结束 */
            ...
        }
    }
```

**`N_SLINE` 条目给的是"某个 PC 起点对应哪一行"**。
线性扫描，找到 `wanted_pc` 落在哪一段。

```c
/* src/core/tccrun.c:457-476（节选）*/
 found:
    i = incl_index;
    if (i > 0)
        fprintf(stderr, "%s:%d: ", incl_files[--i], last_line_num);   /* 文件名:行号 */
    fprintf(stderr, "%s %p", msg, (void*)wanted_pc);
    if (last_func_name[0] != '\0')
        fprintf(stderr, " %s()", last_func_name);                     /* 函数名 */
    ...
```

输出形如：

```
file.c:12: at 0x7f... foo()
file.c:20: by 0x7f... bar()
file.c:30: by 0x7f... main()
```

## 第 4 站：没有 stabs 时的退化（`:429`）

```c
/* src/core/tccrun.c:429-456（节选）*/
no_stabs:
    /* 没有行号信息，就只用符号表找到"哪个函数" */
    for(sym = (ElfW(Sym) *)symtab_section->data + 1; sym < sym_end; sym++) {
        type = ELFW(ST_TYPE)(sym->st_info);
        if (type == STT_FUNC || type == STT_GNU_IFUNC) {
            if (wanted_pc >= sym->st_value && wanted_pc < sym->st_value + sym->st_size) {
                pstrcpy(last_func_name, ..., 符号名);
                func_addr = sym->st_value;
                goto found;
            }
        }
    }
    fprintf(stderr, "%s %p ???\n", msg, (void*)wanted_pc);   /* 只知道地址 */
```

**即使没 `-g`，也能报"在哪个函数里"**（靠符号表），只是没有行号。

## 第 5 站：取上层 PC —— `rt_get_caller_pc`（`:571`）

不同平台取调用栈的方法不同：

- x86-64：从栈帧链（`rbp` 链）或 `ucontext` 的保存寄存器取返回地址；
- 源码里有多份实现（`:571`/`:620`/`:662`/`:704`/`:726`/`:767`），
  用 `#ifdef` 按平台/架构选择。

**这是"深度依赖平台"的代码**，也是 TCC 里比较难移植的部分。

---

## 第 6 站：和 `gdb` 的对比

| | gdb | TCC `-run -g` |
|---|---|---|
| 程序 | 独立进程 | TCC 进程内 |
| 调试信息 | DWARF | stabs（TCC 自己的格式） |
| 回溯 | 完整（寄存器/栈/内联） | 有限（`rt_num_callers` 层） |
| 交互 | 断点/单步/修改变量 | 只能崩溃时打印 |

**TCC 的回溯不是为了替代 gdb，而是让 `-run` 崩溃时"至少知道在哪一行"。**

## 【把一次 `tcc -run -g` 崩溃走一遍】

```
1. tcc -run -g crash.c
2. 编译时生成 stabs（.stab/.stabstr），-g 也设 do_debug
3. tcc_run 里 set_exception_handler() 装信号处理器
4. 调 main，程序里解引用空指针 → SIGSEGV
5. sig_error 被调用 → rt_error
6. rt_get_caller_pc 取崩溃 PC
7. rt_printline：遍历 stab，找到 N_SLINE，打印 "crash.c:5: at ... main()"
8. exit(255)
```

## 【常见卡点】

- **TCC 自己装信号处理器**（因为代码在 TCC 进程里）。
- **`rt_printline` 读 stabs 反查源码行**。
- **没调试信息时退化为"函数名+地址"**。
- **`rt_num_callers` 限制回溯层数**。
- **取调用栈是平台相关代码**。

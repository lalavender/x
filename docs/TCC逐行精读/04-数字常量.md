# 04 · 数字常量：`0x1F`、`3.14`、`10ULL` 怎么变成数字

> **本步输入**：一个 `TOK_PPNUM` token，文本比如 `"0x1F"`
> **本步输出**：`tok = TOK_CINT`（或 `TOK_CDOUBLE`…），`tokc.i` / `tokc.d` 里是真正的值
>
> 对应源码：`src/core/tccpp.c:2260-2546`（`parse_number`）、
> `src/core/tccpp.c:2239/2250`（`bn_lshift` / `bn_zero`，大数移位用）。
>
> 词法阶段（第 02 篇）只把数字字符拼成字符串。**真正的数值计算在这里。**
> 谁调它？`next()`（`tccpp.c:3560`）看到 `TOK_PPNUM` 且开了 `PARSE_FLAG_TOK_NUM` 时。

---

## 第 0 站：函数长什么样

```c
/* src/core/tccpp.c:2258-2266 */
/* 解析以 '\0' 结尾的字符串 p，把结果放进当前 token */
static void parse_number(const char *p)
{
    int b, t, shift, frac_bits, s, exp_val, ch;
    char *q;
    unsigned int bn[BN_SIZE];   /* BN_SIZE = 2，两个 32 位拼成 64 位大数 */
    double d;

    /* number */
    q = token_buf;             /* token_buf 是全局临时缓冲 */
    ch = *p++;                 /* ch 读第一个字符 */
    t = ch;                    /* t 记住"上一个"字符（浮点判断要用） */
    ch = *p++;                 /* ch 读第二个字符，p 指向第三个 */
    *q++ = t;                  /* 把第一个字符写进缓冲 */
    b = 10;                    /* 默认十进制 */
```

这段的节奏很特别：**它总是超前读两个字符**（`t` 是前一个，`ch` 是当前），
因为判断 `0x`（十六进制）、`0b`（二进制）、`e+`（指数）都需要"看一位"。

`token_buf` 是全局缓冲（`tccpp.c:44`）：

```c
static char token_buf[STRING_MAX_SIZE + 1];   /* STRING_MAX_SIZE = 1024 */
```

## 第 1 站：判断进制（`tccpp.c:2274-2286`）

```c
/* src/core/tccpp.c:2274-2286 */
    if (t == '.') {
        goto float_frac_parse;      /* 以 '.' 开头：一定是浮点，跳到小数部分 */
    } else if (t == '0') {
        if (ch == 'x' || ch == 'X') {
            q--;                    /* 把已写进去的 '0' 撤掉 */
            ch = *p++;              /* 吃掉 'x' */
            b = 16;                 /* 十六进制 */
        } else if (tcc_ext && (ch == 'b' || ch == 'B')) {
            q--;                    /* TCC 扩展：0b1010 二进制 */
            ch = *p++;
            b = 2;
        }
        /* 注意：这里没写 "否则 b=8"。八进制在整数路径里判断（见第 5 站） */
    }
```

结论：

- `.5` → 直接当浮点；
- `0x1F` → 十六进制，`b=16`；
- `0b101` → 二进制（TCC 扩展），`b=2`；
- `017` → 这里看不出是八进制，留到后面（因为可能是 `0.17` 浮点）。

## 第 2 站：先把数字字符全收进来（`tccpp.c:2287-2306`）

```c
/* src/core/tccpp.c:2287-2306 */
    /* 把所有数字字符收进 token_buf。此时不判断八进制，因为可能是浮点 */
    while (1) {
        if (ch >= 'a' && ch <= 'f')      t = ch - 'a' + 10;
        else if (ch >= 'A' && ch <= 'F') t = ch - 'A' + 10;
        else if (isnum(ch))              t = ch - '0';
        else                             break;
        if (t >= b)                      break;   /* 超出进制范围就停 */
        if (q >= token_buf + STRING_MAX_SIZE)
            tcc_error("number too long");
        *q++ = ch;
        ch = *p++;
    }
```

注意：它**只收合法的当前进制数字**。`0x1G` 收到 `1` 就停（`G` ≥ 16）。
`q` 一直往前写，`p` 一直往前读。

## 第 3 站：分岔口 —— 整数还是浮点（`tccpp.c:2307-2309`）

```c
/* src/core/tccpp.c:2307-2309 */
    if (ch == '.' ||
        ((ch == 'e' || ch == 'E') && b == 10) ||
        ((ch == 'p' || ch == 'P') && (b == 16 || b == 2))) {
        /* ... 浮点 ... */
    } else {
        /* ... 整数 ... */
    }
```

三种情况判为浮点：

1. 后面跟 `.`（`3.14`、`1.`）；
2. 十进制数后面跟 `e`/`E`（`1e10`）；
3. 十六/二进制数后面跟 `p`/`P`（`0x1.8p3`，C99 十六进制浮点）。

**这个判断是 `parse_number` 的心脏**。剩下的两条大分支，我们先讲整数（因为更常用），
再讲浮点。

## 第 4 站（整数）：把位值累加起来（`tccpp.c:2456-2487`）

跳到 `else` 分支：

```c
/* src/core/tccpp.c:2456-2487 */
    } else {
        unsigned long long n, n1;
        int lcount, ucount, ov = 0;
        const char *p1;

        /* 整数 */
        *q = '\0';                 /* 收尾，token_buf 里是纯数字字符串 */
        q = token_buf;
        if (b == 10 && *q == '0') {
            b = 8;                 /* ★ 到这里才确定：前导 0 = 八进制 */
            q++;
        }
        n = 0;
        while(1) {
            t = *q++;
            if (t == '\0')
                break;
            else if (t >= 'a')      t = t - 'a' + 10;
            else if (t >= 'A')      t = t - 'A' + 10;
            else                    t = t - '0';
            if (t >= b)
                tcc_error("invalid digit");
            n1 = n;
            n = n * b + t;         /* ★ 经典"霍纳法则"：逐位累加 */
            /* 溢出检测 */
            if (n1 >= 0x1000000000000000ULL && n / b != n1)
                ov = 1;
        }
```

逐点：

- **`if (b == 10 && *q == '0') b = 8;`**：为什么八进制判断放这么晚？
  因为前面可能碰到 `0.5`（浮点），只能等到"确定是整数"再判。
  这是"信息不足就别急下结论"的写法。
- **`n = n * b + t`**：霍纳法则。比如 `0x1F`：
  - 从 1 开始：`n = 0*16+1 = 1`；
  - 处理 `F`(15)：`n = 1*16+15 = 31`。
  一次遍历，无需乘幂。
- **溢出检测**：`n1 >= 0x1000...`（即高位已经很大了），再乘 `b` 若回不去 `n1`，就溢出。
  用 `n / b != n1` 检测，比用库函数快。

## 第 5 站（整数）：后缀 `U` / `L` / `UL` / `LL`（`tccpp.c:2489-2510`）

```c
/* src/core/tccpp.c:2489-2510 */
        /* 根据后缀决定这个常量需要 unsigned 和/或 64 位 */
        lcount = ucount = 0;
        p1 = p;
        for(;;) {
            t = toup(ch);
            if (t == 'L') {
                if (lcount >= 2)
                    tcc_error("three 'l's in integer constant");
                if (lcount && *(p - 1) != ch)
                    tcc_error("incorrect integer suffix: %s", p1);
                lcount++;              /* L 或 LL */
                ch = *p++;
            } else if (t == 'U') {
                if (ucount >= 1)
                    tcc_error("two 'u's in integer constant");
                ucount++;              /* U */
                ch = *p++;
            } else {
                break;
            }
        }
```

- `lcount` 记有几个 `L`（1 个是 long，2 个是 long long）；
- `ucount` 记有几个 `U`（最多 1 个）；
- `10ULL` → `lcount=2, ucount=1`；
- `*(p - 1) != ch` 那个检查是防止 `L` 和 `l` 混写（`Ll`），C 标准不允许。

## 第 6 站（整数）：值本身决定类型（`tccpp.c:2512-2545`）

光看后缀不够。C 的规则是"**这个数放不进当前类型，就自动升级**"：

```c
/* src/core/tccpp.c:2512-2545 */
        if (ucount == 0 && b == 10) {
            if (lcount <= (LONG_SIZE == 4)) {
                if (n >= 0x80000000U)
                    lcount = (LONG_SIZE == 4) + 1;   /* 值太大：升级成 long long */
            }
            if (n >= 0x8000000000000000ULL)
                ov = 1, ucount = 1;                   /* 连 64 位都装不下 */
        } else {
            if (lcount <= (LONG_SIZE == 4)) {
                if (n >= 0x100000000ULL)
                    lcount = (LONG_SIZE == 4) + 1;
                else if (n >= 0x80000000U)
                    ucount = 1;                        /* 恰好装进 unsigned */
            }
            if (n >= 0x8000000000000000ULL)
                ucount = 1;
        }

        if (ov)
            tcc_warning("integer constant overflow");

        tok = TOK_CINT;
        if (lcount) {
            tok = TOK_CLONG;
            if (lcount == 2)
                tok = TOK_CLLONG;
        }
        if (ucount)
            ++tok;      /* TOK_CINT→TOK_CUINT, CLONG→CULONG, CLLONG→CULLONG */
        tokc.i = n;
    }
    if (ch)
        tcc_error("invalid number\n");
}
```

最后一招最妙：

```c
if (ucount)
    ++tok;   /* 编号 +1 就变成"无符号版本" */
```

因为在 `tcctok.h` 里，这几个 token 的编号是**成对相邻**的
（见第 03 篇 `get_tok_str` 里列的顺序）：

```
TOK_CINT, TOK_CUINT, TOK_CLONG, TOK_CULONG, TOK_CLLONG, TOK_CULLONG
```

所以 `TOK_CINT + 1 = TOK_CUINT`、`TOK_CLONG + 1 = TOK_CULONG`……
**一次自增代替一整个 switch。**

最后 `if (ch) tcc_error("invalid number")`：
如果收完数字还剩字符没消费（比如 `123abc`），就报错——防止把非法数字放过去。

## 第 7 站（浮点）：十进制走 `strtod`（`tccpp.c:2400-2455`）

```c
/* src/core/tccpp.c:2400-2455（节选）*/
        } else {
            /* decimal floats */
            if (ch == '.') { /* 收小数部分 */ }
            if (ch == 'e' || ch == 'E') { /* 收指数部分，含 +/- */ }
            *q = '\0';
            t = toup(ch);
            errno = 0;
            if (t == 'F') {
                ch = *p++;
                tok = TOK_CFLOAT;
                tokc.f = strtof(token_buf, NULL);   /* 交给 C 库 */
            } else if (t == 'L') {
                ch = *p++;
                tok = TOK_CLDOUBLE;
                tokc.ld = strtold(token_buf, NULL);
            } else {
                tok = TOK_CDOUBLE;
                tokc.d = strtod(token_buf, NULL);   /* 默认 double */
            }
        }
```

十进制浮点直接**借 C 标准库**（`strtof`/`strtod`/`strtold`）。
没有理由自己写——反正编译器本来就依赖 libc。

## 第 8 站（浮点）：十六进制浮点自己算（`tccpp.c:2310-2399`）

`0x1.8p3` 这种 C99 十六进制浮点，老 libc 的 `strtod` 不支持，
所以 TCC **自己用手写的大数移位**：

```c
/* src/core/tccpp.c:2310-2356（节选）*/
            *q = '\0';
            if (b == 16) shift = 4;
            else         shift = 1;              /* 二进制时每次移 1 位 */
            bn_zero(bn);                          /* 大数清零 */
            q = token_buf;
            while (1) {                           /* 整数部分 */
                t = *q++;
                if (t == '\0') break;
                ... 把字符转成 digit t ...
                bn_lshift(bn, shift, t);          /* bn = (bn << shift) | t */
            }
            frac_bits = 0;
            if (ch == '.') {                      /* 小数部分 */
                ch = *p++;
                while (1) {
                    ... 转 digit t ...
                    if (t >= b) tcc_error("invalid digit");
                    bn_lshift(bn, shift, t);
                    frac_bits += shift;           /* 记录小数占了多少位 */
                    ch = *p++;
                }
            }
            if (ch != 'p' && ch != 'P') expect("exponent");
            ... 解析 p 后面的十进制指数 exp_val ...
            d = (double)bn[1] * 4294967296.0 + (double)bn[0];   /* 拼两个 32 位 */
            d = ldexp(d, exp_val - frac_bits);                   /* 乘 2 的幂 */
```

`bn_lshift`（`tccpp.c:2239`）就是把 64 位大数左移 `shift` 位再或上 `or_val`：

```c
/* src/core/tccpp.c:2239-2248 */
static void bn_lshift(unsigned int *bn, int shift, int or_val)
{
    int i;
    unsigned int v;
    for(i=0;i<BN_SIZE;i++) {
        v = bn[i];
        bn[i] = (v << shift) | or_val;
        or_val = v >> (32 - shift);
    }
}
```

**要点**：这里用手写大数而不是 `strtod`，是为了支持所有 libc 都不支持的
十六进制浮点字面量。这就是"编译器不能假设 libc 有多强"的体现。

## 【把 t.c 里的 `2 * K` 走一遍】

`t.c` 里 `K` 先被展开成 `8`。当 `next()` 遇到这个 `TOK_PPNUM("8")`：

1. `parse_number("8")` 被调用；
2. `q=token_buf; t='8'; ch='\0'; *q++='8'; b=10`；
3. 收数字循环：`ch='\0'`，不是数字，立即结束；
4. 判断浮点：`ch` 不是 `.`/`e`/`p`，走整数；
5. `*q='\0'; q=token_buf; b==10 && *q=='8'`（不是 `'0'`），所以 b 仍为 10；
6. `n = 0*10 + 8 = 8`；
7. 后缀循环：`ch='\0'`，无后缀；
8. 类型判断：`ucount=0,b=10,lcount=0`，`n=8 < 0x80000000`，不用升级；
9. `tok = TOK_CINT; tokc.i = 8`。

回到 `2 * K` 的解析时，值栈上就是两个 `TOK_CINT`：`2` 和 `8`，
`gen_op('*')` 会调 `gen_opic` **在编译期直接算出 16**（第 3 部细讲）。
**机器码里连一条乘法指令都没有。**

## 【常见卡点】

- **八进制为什么在后面才判**：因为 `0.5` 是浮点，前导 0 不等于八进制。
- **`tok` 自增表示 unsigned**：因为 `tcctok.h` 里无符号版本紧跟有符号版本，
  这是第 03 篇"编号即一切"的直接利用。
- **十进制浮点用 libc，十六进制自己写**：因为老 libc 不支持后者。
- **`parse_number` 会读 `tcc_state` 的什么吗**：不，它是纯函数，只碰全局 `tok/tokc/token_buf`。

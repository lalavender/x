# 16 · 单遍编译总入口：`tccgen_compile` 与 `decl`

> **一句话**：整个 C 文件的编译，就是 `next()` 拿一个 token、`decl()` 处理一条外部声明，
> 循环到文件结束。**没有"先建树再生成"的中间步。**
>
> 对应源码：`src/core/tccgen.c:235`（`tccgen_compile`）、
> `src/core/tccgen.c:7381`（`decl`）、`src/core/tccgen.c:7144`（`decl0` 真正干活）、
> `src/core/tccgen.c:7054`（`gen_function` 函数定义）。

---

## 第 0 站：入口 —— `tccgen_compile`（`tccgen.c:235`）

第 01 篇贴过它的骨架，这里逐行看：

```c
/* src/core/tccgen.c:235-281 */
ST_FUNC int tccgen_compile(TCCState *s1)
{
    cur_text_section = NULL;
    funcname = "";
    anon_sym = SYM_FIRST_ANOM;      /* 匿名符号编号起点 */
    section_sym = 0;
    const_wanted = 0;
    nocode_wanted = 0x80000000;     /* 很大正数 = 现在不要生成代码 */

    /* 预先造好几个常用类型 */
    int_type.t = VT_INT;
    char_pointer_type.t = VT_BYTE;
    mk_pointer(&char_pointer_type); /* char_pointer_type = char* */
#if PTR_SIZE == 4
    size_type.t = VT_INT | VT_UNSIGNED;
    ptrdiff_type.t = VT_INT;
#elif LONG_SIZE == 4
    size_type.t = VT_LLONG | VT_UNSIGNED;
    ptrdiff_type.t = VT_LLONG;
#else
    size_type.t = VT_LONG | VT_LLONG | VT_UNSIGNED;   /* size_t */
    ptrdiff_type.t = VT_LONG | VT_LLONG;              /* ptrdiff_t */
#endif
    func_old_type.t = VT_FUNC;
    func_old_type.ref = sym_push(SYM_FIELD, &int_type, 0, 0);
    func_old_type.ref->f.func_call = FUNC_CDECL;
    func_old_type.ref->f.func_type = FUNC_OLD;        /* 老式函数类型（隐式声明用） */

    tcc_debug_start(s1);
    ...
    parse_flags = PARSE_FLAG_PREPROCESS | PARSE_FLAG_TOK_NUM | PARSE_FLAG_TOK_STR;
    next();                 /* ★ 拿第一个 token */
    decl(VT_CONST);         /* ★ 一直解析到文件结束 */
    gen_inline_functions(s1);   /* 编译被引用过的 inline 函数 */
    check_vstack();             /* 检查值栈没泄漏 */
    tcc_debug_end(s1);
    return 0;
}
```

**`decl(VT_CONST)` 不循环**——循环在 `decl0` 内部（下一站）。
注意 `nocode_wanted = 0x80000000`：这是一个"正在泛读、不生成代码"的开关，
解析类型/初始化时打开它，真生成函数体时才关掉。

## 第 1 站：`decl`/`decl0` 的骨架（`tccgen.c:7144`）

`decl(l)` 就是 `decl0(l, 0, NULL)`。`l` 是"默认存储类"：
顶层传 `VT_CONST`（全局），块内传 `VT_LOCAL`（局部）。

`decl0` 的主循环非常长（约 240 行），但结构清晰：

```c
/* src/core/tccgen.c:7144-7176（骨架）*/
static int decl0(int l, int is_for_loop_init, Sym *func_sym)
{
    ...
    while (1) {
        if (!parse_btype(&btype, &ad)) {     /* ① 读基本类型 */
            ... 不是类型：可能是 ';'、asm、或结束 ...
        }
        ...
        while (1) { /* iterate thru each declaration */
            type = btype;
            ...
            type_decl(&type, &ad, &v, TYPE_DIRECT);   /* ② 读声明符，得到名字 v */

            if ((type.t & VT_BTYPE) == VT_FUNC) {
                ... 老式函数原型处理 ...
            }
            ...
            if (tok == '{') {                 /* ③ 是函数定义 */
                ...
                sym = external_global_sym(v, &type, 0);
                ...
                if (static inline) {
                    /* 先记录成"宏"，用到才编（第 39 篇） */
                } else {
                    gen_function(sym);        /* ★ 生成函数代码 */
                }
                break;
            } else {
                ... 是变量声明或函数声明 ...
                decl_initializer_alloc(...);  /* 分配/初始化 */
                ...
                skip(';');
                break;
            }
        }
    }
    return 0;
}

static void decl(int l) { decl0(l, 0, NULL); }
```

三步：

1. **`parse_btype` 读基本类型**（`int`、`unsigned long`、`struct S`…，第 32 篇）。
2. **`type_decl` 读声明符**（`*`、`[]`、`()`、变量名，第 33 篇），得到名字编号 `v`。
3. **分岔**：
   - 后面是 `{` → **函数定义**，调 `gen_function`；
   - 否则 → **变量/函数声明**，调 `decl_initializer_alloc`（第 37 篇）。

**每读一条就立刻处理一条，没有攒起来。** 这就是"单遍"。

## 第 2 站：函数定义怎么"盖房" —— `gen_function`（`tccgen.c:7054`）

```c
/* src/core/tccgen.c:7054-7094 */
static void gen_function(Sym *sym)
{
    nocode_wanted = 0;               /* ★ 现在开始真要生成机器码了 */
    ind = cur_text_section->data_offset;   /* 记下函数代码起点 */
    put_extern_sym(sym, cur_text_section, ind, 0);  /* 登记符号（大小待定） */
    funcname = get_tok_str(sym->v, NULL);
    func_ind = ind;
    /* 初始化 VLA 状态 */
    vla_sp_loc = -1;
    vla_sp_root_loc = -1;
    tcc_debug_funcstart(tcc_state, sym);

    /* 压一个哑符号，方便局部符号存储 */
    sym_push2(&local_stack, SYM_FIELD, 0, 0);
    local_scope = 1;                 /* 参数作用域 */
    gfunc_prolog(&sym->type);        /* ★ 后端：盖栈帧、存参数（第 42 篇） */
    local_scope = 0;
    rsym = 0;
    block(NULL, NULL, 0);            /* ★ 解析并生成函数体（第 26 篇） */
    nocode_wanted = 0;
    gsym(rsym);                      /* 回填 return 的跳转 */
    gfunc_epilog();                  /* ★ 后端：拆栈帧、ret（第 42 篇） */
    cur_text_section->data_offset = ind;   /* 收尾 */
    label_pop(&global_label_stack, NULL, 0);
    local_scope = 0;
    sym_pop(&local_stack, NULL, 0);  /* ★ 清空函数局部符号 */
    elfsym(sym)->st_size = ind - func_ind; /* 回填函数大小 */
    tcc_debug_funcend(tcc_state, ind - func_ind);
    /* 安全起见清零 */
    cur_text_section = NULL;
    funcname = "";
    func_vt.t = VT_VOID;
    func_var = 0;
    ind = 0;
    nocode_wanted = 0x80000000;
    check_vstack();
}
```

顺序讲：

1. **`nocode_wanted = 0`**：从这里开始，值栈上的操作会真的发机器码。
2. **`put_extern_sym`**：在 `.symtab` 里登记函数符号，`st_value` 是代码起点，
   `st_size` 先写 0，函数编译完再回填。
3. **`gfunc_prolog`**：后端负责"盖房"——`push rbp; mov rbp,rsp; sub rsp, N`，
   并把寄存器里的参数存到栈上（第 42 篇）。
4. **`block(...)`**：函数体编译。**这就是 C 语句的调度室**（第 26 篇）。
5. **`gsym(rsym)`**：`return` 生成了跳转到函数末尾的指令，这里回填地址。
6. **`gfunc_epilog`**：后端"拆房"——`leave; ret`。
7. **`sym_pop(&local_stack, NULL, 0)`**：把函数的局部符号、参数卡全弹掉。
   注意 `local_scope = 0` 配合第 13 篇的抽屉回退。

**函数体从 `{` 到 `}` 生成完，立刻 `sym_pop`，内存马上回收。** 单遍编译省内存的关键。

## 第 3 站：大局观 —— 单遍到底省了什么

对比两种做法：

| | 教科书编译器 | TCC |
|---|---|---|
| 内存 | 整个文件 → 语法树（节点极多） | 只保留符号表 + 值栈 + 当前函数 |
| 速度 | 建树一遍、遍历一遍 | 一边读一边发码 |
| 优化 | 树上看很方便 | 只能做局部小优化（常量折叠等） |
| 编译大文件 | 树会把内存吃光 | 一个函数编完就扔 |

**代价**：TCC 做不了需要"看全局"的优化（比如循环优化、内联优化）。
**收益**：小、快、内存少，而且代码简单到你能读懂。

## 【把 t.c 的顶层走一遍】

```
#define K 8
int add(int a, int b) { return a + b; }
int main(void) { int x = 3; int y = 2*K; x = add(x, y); return x; }
```

1. `#define K 8` 在预处理阶段被吃掉（第 06 篇），**不进 `decl`**。
2. `next()` 给出 `TOK_INT` → `decl0` 循环开始：
   - `parse_btype` 读 `int`；
   - `type_decl` 读 `add(int a,int b)`，得到函数类型和名字 `add`；
   - 看到 `{` → `gen_function(add)`：
     - `gfunc_prolog` 盖房、存 `a`/`b`；
     - `block()` 生成 `return a+b` 的代码；
     - `gfunc_epilog` 拆房；
3. 回到 `decl0` 循环，`parse_btype` 读 `int`，`type_decl` 读 `main(void)`，
   看到 `{` → `gen_function(main)`；
4. 文件末尾 `next()` 给出 `TOK_EOF`，`decl0` 退出，`decl` 返回；
5. `gen_inline_functions`（没有 inline 函数，空转）；`check_vstack` 通过。

**全程只走了一遍 token 流。**

## 【常见卡点】

- **`decl` 不循环，循环在 `decl0`**。
- **`nocode_wanted` 是"暂不生成代码"的开关**，解析类型时打开，生成函数体时关。
- **函数编完立刻 `sym_pop` 清局部符号**，这是省内存的关键。
- **`st_size` 先填 0，最后回填**，因为此时不知道函数多大。

# 49 · 调用辅助与寄存器约定：TCC 为什么不保存"被调用者保存"寄存器

> **一句话**：x86-64 有一半寄存器是"被调用者保存"（`rbx`/`r12`~`r15`），
> 函数用了它们就得在 prolog 保存、epilog 恢复。TCC **干脆不用它们**——
> `reg_classes[]` 里只把 caller-saved 的 `rax/rcx/rdx/r8~r11` 标成 `RC_INT`。
>
> 对应源码：`src/targets/x86_64-gen.c:111`（`reg_classes`）、`:770`（`using_regs`）、
> `:803`（`gfunc_arg_size`）、`:758`（`gen_offs_sp`，PE）、`:1429`（`push_arg_reg`）。

---

## 第 0 站：System V 的寄存器分类

| 寄存器 | 谁负责保存 | TCC 用作临时？ |
|---|---|---|
| `rax`, `rcx`, `rdx` | 调用者（caller-saved） | 是 |
| `rsi`, `rdi` | 调用者 | 否（留给传参） |
| `r8`~`r11` | 调用者 | 是 |
| `rbx`, `r12`~`r15` | **被调用者**（callee-saved） | **否** |
| `rbp`, `rsp` | 特殊 | 帧指针/栈指针 |
| `xmm0`~`xmm15` | 全部 caller-saved | 只用 0~7 |

**如果 TCC 用了 `rbx`/`r12`，就必须在每个函数 prolog 保存、epilog 恢复**，
否则调用 `printf` 之类会破坏调用者的值。

## 第 1 站：看 `reg_classes` 就明白（`x86_64-gen.c:111`）

```c
/* src/targets/x86_64-gen.c:111-140（节选）*/
ST_DATA const int reg_classes[NB_REGS] = {
    /* eax */ RC_INT | RC_RAX,     /* ✓ 临时 */
    /* ecx */ RC_INT | RC_RCX,     /* ✓ 临时 */
    /* edx */ RC_INT | RC_RDX,     /* ✓ 临时 */
    0, 0, 0, 0,                    /* rsp, rbp, rsi, rdi：不是临时 */
    RC_R8,  RC_R9,  RC_R10, RC_R11,/* ★ 注意：只有 RC_R8 等，没有 RC_INT */
    0, 0, 0, 0,                    /* r12-r15：完全不用 */
    /* xmm0 */ RC_FLOAT | RC_XMM0, ...
    /* xmm6/xmm7 */ RC_XMM6, RC_XMM7,  /* 不标 RC_FLOAT（Windows 上 callee-saved） */
    /* st0 */ RC_ST0
};
```

两个关键：

1. **`r8`~`r11` 只有 `RC_R8` 等，没有 `RC_INT`**！所以第 21 篇 `get_reg(RC_INT)`
   **不会**选它们——它们只用于特定场合（`arg_prepare_reg` 中转、`gcall_or_jmp` 间接调用）。
   真正随便用的临时寄存器只有 `rax`/`rcx`/`rdx`。
2. **`r12`~`r15` 全是 `0`**——TCC 根本不用。
3. **`xmm6`/`xmm7` 不标 `RC_FLOAT`**，因为 Windows 上它们是 callee-saved，
   这样跨平台代码就统一了。

> **代价**：可用临时寄存器少（3 个整数），溢出（第 21 篇）会更频繁。
> **收益**：prolog/epilog 不需要 `push rbx`/`pop rbx` 之类，代码简单、正确性容易保证。
> 这正是 TCC "够用就好"的取舍。

## 第 2 站：参数大小与"用不用寄存器"（`:770/803`）

```c
/* src/targets/x86_64-gen.c:770-773（PE 区块，逻辑通用）*/
static int using_regs(int size)
{
    return !(size > 8 || (size & (size - 1)));   /* ≤8 且是 2 的幂 */
}
```

```c
/* src/targets/x86_64-gen.c:803-808 */
static int gfunc_arg_size(CType *type) {
    int align;
    if (type->t & (VT_ARRAY|VT_BITFIELD))
        return 8;                     /* 数组/位域按 8 字节 */
    return type_size(type, &align);
}
```

`using_regs` 判断"这个大小能不能整进一个寄存器"（1/2/4/8）。
`gfunc_arg_size` 处理数组/位域的特殊情况。

## 第 3 站：把寄存器参数"钉"到栈上 —— `push_arg_reg`（`:1429`）

```c
/* src/targets/x86_64-gen.c:1427-1432 */
#define FUNC_PROLOG_SIZE 11

static void push_arg_reg(int i) {
    loc -= 8;                                     /* 栈帧往下 8 字节 */
    gen_modrm64(0x89, arg_regs[i], VT_LOCAL, NULL, loc);   /* mov arg_regs[i], [rbp+loc] */
}
```

`push_arg_reg` 在 prolog 里把某个参数寄存器写到栈帧（第 42 篇）。
**它移动 `loc`，所以形参也算进了栈帧大小。** 这就是为什么第 42 篇的回填
要把 `loc` 算进 `sub rsp,N`。

## 第 4 站：`gen_offs_sp`（仅 PE，`:758`）

```c
/* src/targets/x86_64-gen.c:758-768 */
static void gen_offs_sp(int b, int r, int d)     /* 相对 rsp 的内存操作 */
{
    orex(1,0,r & 0x100 ? 0 : r, b);
    if (d == (char)d) {
        o(0x2444 | (REG_VALUE(r) << 3));         /* modrm, disp8 */
        g(d);
    } else {
        o(0x2484 | (REG_VALUE(r) << 3));         /* modrm, disp32 */
        gen_le32(d);
    }
}
```

Windows x64 要求"参数暂存区"（shadow space），这个函数用于访问 `rsp` 相对地址。
SysV 版不用它。

## 第 5 站：`stdcall` 与 `func_ret_sub`（PE）

```c
/* src/targets/x86_64-gen.c:1587-1629（节选）*/
    o(0xc9);             /* leave */
    if (func_ret_sub == 0) {
        o(0xc3);         /* ret */
    } else {
        o(0xc2);         /* ret n：被调用者清栈 */
        g(func_ret_sub);
        g(func_ret_sub >> 8);
    }
```

Windows 的 `__stdcall` 约定要求被调用者清栈，`func_ret_sub` 就是参数总大小。
SysV 一律 `ret`（调用者清栈）。

## 第 6 站：总结——寄存器分配策略的取舍

| 策略 | 好处 | 坏处 |
|---|---|---|
| 只用 caller-saved（TCC） | prolog/epilog 简单，不用保存恢复 | 可用寄存器少，溢出多 |
| 用上 callee-saved（GCC） | 寄存器多，性能好 | 要保存/恢复，代码复杂 |

TCC 选了前者——**因为它的目标读者是"想要快速编译"的人，而不是"想要最快代码"的人。**

1. 写一个表达式需要很多临时值的函数，反汇编看有没有 `push rbx`/`push r12`
   （应该**没有**，TCC 不用 callee-saved）。
2. 在 `get_reg` 里打印选中的寄存器号，看是不是只在 0/1/2/10/11 里选。
3. 对比 `gcc -O0` 的同类函数，看 GCC 会不会用 `rbx`。

## 【通关暗号】

```bash
printf 'int f(int a,int b,int c,int d,int e,int f,int g,int h){return a+b+c+d+e+f+g+h;}\n' > /tmp/r.c
./tcc -c /tmp/r.c -o /tmp/r.o && objdump -d /tmp/r.o 2>/dev/null | grep -cE 'push +%rbx|push +%r12|push +%r13'
# 期望：0（TCC 不保存被调用者保存寄存器）
```

## 【常见卡点】

- **TCC 不用 callee-saved 寄存器**，prolog/epilog 因此简单。
- **`r8`~`r11` 不在 `RC_INT` 里**，只有特殊场合用。
- **`push_arg_reg` 会把形参占的栈空间算进 `loc`**。
- **`stdcall` 用 `ret n`，SysV 用 `ret`**。

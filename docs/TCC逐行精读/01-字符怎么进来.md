# 01 · 字符怎么进来：从硬盘字节到"当前字符 ch"

> **本步输入**：磁盘上的文件 `t.c`
> **本步输出**：一个全局变量 `ch`，它的值永远是"编译器此刻正盯着的那个字符"
>
> 对应源码：`src/core/libtcc.c:535`（打开文件）、`src/core/tccpp.c:29-33`（全局书签）、
> `src/core/tccpp.c:587`（缓冲区读完了怎么办）、`src/core/tccpp.c:620`（读下一个字符）、
> `src/core/tccpp.c:681-711`（三个读字符的"魔法宏"）。

---

## 第 0 站：先认识两个全局变量（`tccpp.c:26-33`）

打开 `tccpp.c`，第 26 行附近有这么一段：

```c
/* src/core/tccpp.c:26-33 */
ST_DATA int tok_flags;              /* 当前 token 的附带小旗子（见第 02 篇）*/
ST_DATA int parse_flags;            /* 这次解析的模式开关（见第 02 篇）*/

ST_DATA struct BufferedFile *file;  /* ★ 当前正在读的文件 */
ST_DATA int ch, tok;                /* ★ ch = 当前字符；tok = 当前 token */
ST_DATA CValue tokc;                /* 当前 token 附带的值 */
ST_DATA const int *macro_ptr;       /* 若正在展开宏，指向那串 token */
ST_DATA CString tokcstr;            /* 当前解析中的字符串 */
```

`ST_DATA` 是个宏（`tcc.h` 里定义），在单文件编译模式下它就是空的，
意思是"这是一个全局变量"。**你只需要记住两个名字：`file` 和 `ch`。**

- `file` 是一张"书签"，告诉我们**现在在哪个文件、读到哪了**；
- `ch` 是**此刻正盯着的那一个字符**。

> **12 岁比喻**：`file` 是你手指夹着的那本书 + 夹在第几页的那根书签；
> `ch` 是你此刻正指着的那一个字。整部 TCC 的"读文件"就这两个东西。

## 第 1 站：书签长什么样 —— `BufferedFile`（`tcc.h:554`）

```c
/* src/core/tcc.h:554-569 */
typedef struct BufferedFile {
    uint8_t *buf_ptr;         /* ★ 读到缓冲区里的哪个位置了 */
    uint8_t *buf_end;         /* 缓冲区里有效数据到哪结束 */
    int fd;                   /* 操作系统给的文件编号（-1 表示"内存文件"） */
    struct BufferedFile *prev;/* ★ 上一个文件（#include 套娃用） */
    int line_num;             /* 当前行号（为了报错） */
    int line_ref;             /* tcc -E 用，先不管 */
    int ifndef_macro;         /* #ifndef 保护用，第 08 篇讲 */
    int ifndef_macro_saved;
    int *ifdef_stack_ptr;     /* 本文件开始时的 #if 栈位置 */
    int include_next_index;   /* #include_next 搜索位置 */
    char filename[1024];      /* 文件名 */
    char *true_filename;      /* 未被 #line 改过的真名 */
    unsigned char unget[4];
    unsigned char buffer[1];  /* ★ 缓冲区本体！注意这里是 [1] */
} BufferedFile;
```

三个要点：

1. **`buffer[1]` 是"障眼法"**。C 里这叫"柔性数组成员"的土办法：
   结构体末尾写 `[1]`，实际分配时 `malloc(sizeof(BufferedFile) + 需要的字节数)`，
   多出来的空间就接着 `buffer` 放。第 2 站你会看到这一行。

2. **`prev` 是 include 套娃的关键**。读 `a.c` 时遇到 `#include <stdio.h>`，
   就新造一个 `BufferedFile` 读 `stdio.h`，它的 `prev` 指向 `a.c` 的书签。
   读完了，顺着 `prev` 回去继续读 `a.c`。**不需要"栈"这个数据结构，链表就是栈。**

3. **`fd = -1` 表示这不是真文件，是内存里的假文件**（比如命令行 `-D` 展开的字符串）。
   `handle_eob` 看到 `fd < 0` 就知道"没有更多了"。

## 第 2 站：造一个书签 —— `tcc_open_bf`（`libtcc.c:535`）

谁来造书签？`tcc_open_bf`（bf = Buffered File）。它在 `libtcc.c` 里，不在 `tccpp.c`：

```c
/* src/core/libtcc.c:535-551 */
ST_FUNC void tcc_open_bf(TCCState *s1, const char *filename, int initlen) {
  BufferedFile *bf;
  int buflen = initlen ? initlen : IO_BUF_SIZE;   /* ① 要多大缓冲区 */

  bf = tcc_mallocz(sizeof(BufferedFile) + buflen); /* ② 一次分配"结构体+缓冲区" */
  bf->buf_ptr = bf->buffer;                        /* ③ 从头开始读 */
  bf->buf_end = bf->buffer + initlen;              /* ④ 有效数据到哪 */
  bf->buf_end[0] = CH_EOB;                         /* ⑤ 末尾插一个"墙"标记 */
  pstrcpy(bf->filename, sizeof(bf->filename), filename);
  bf->true_filename = bf->filename;
  bf->line_num = 1;                                /* ⑥ 行号从 1 开始 */
  bf->ifdef_stack_ptr = s1->ifdef_stack_ptr;
  bf->fd = -1;                                     /* ⑦ 默认"内存文件" */
  bf->prev = file;                                 /* ⑧ ★ 挂到旧书签前面 */
  file = bf;                                       /* ⑨ ★ 全局 file 换成新书签 */
  tok_flags = TOK_FLAG_BOL | TOK_FLAG_BOF;         /* ⑩ 这是行首、文件头 */
}
```

逐行翻译：

- **②** `sizeof(BufferedFile) + buflen`：因为我们结构体末尾是 `buffer[1]`，
  所以真正的缓冲区从 `buffer[0]` 开始，长度是我们额外要的 `buflen`。
  一次 `malloc` 把"书签 + 缓冲区"连在一起，**少一次内存分配，快**。
  `IO_BUF_SIZE` 是 `tcc.h:552` 定义的 `8192`——一次读 8KB。

- **⑤ `bf->buf_end[0] = CH_EOB`**：`CH_EOB` 是 `tcc.h:571` 定义的 `'\\'`。
  注意！这里放的是"**反斜杠**"当"缓冲区墙"的记号。
  为什么偏偏用 `\`？因为 C 里 `\` 换行是合法的续行符，读到 `\` 本来就要特殊处理，
  干脆复用它。**这是 TCC 省事的一个典型小花招**，也是后面 `handle_stray` 存在的原因。

- **⑦ `fd = -1`**：`tcc_open_bf` 只造书签，不打开真文件。
  真正打开文件在下一个函数里做，然后把 `fd` 覆盖掉。

- **⑧⑨ `prev = file; file = bf;`**：这就是"链表当栈"：
  新书签的 `prev` 指向旧书签，全局 `file` 指向新书签。**两行完成入栈。**

- **⑩** `TOK_FLAG_BOL/BOF` 见 `tcc.h:1202-1203`，是"行首""文件头"的小旗子。
  第 02 篇讲 `next_nomacro1` 处理 `#` 时会用到（`#` 只有在行首才是预处理指令）。

## 第 3 站：打开真文件 —— `tcc_open`（`libtcc.c:565`）

```c
/* src/core/libtcc.c:565-582 */
ST_FUNC int tcc_open(TCCState *s1, const char *filename) {
  int fd;
  if (strcmp(filename, "-") == 0)
    fd = 0, filename = "<stdin>";              /* "-" 表示读标准输入 */
  else
    fd = open(filename, O_RDONLY | O_BINARY);  /* 打开真文件 */
  if ((s1->verbose == 2 && fd >= 0) || s1->verbose == 3)
    printf("%s %*s%s\n", fd < 0 ? "nf" : "->",
           (int)(s1->include_stack_ptr - s1->include_stack), "", filename);
  if (fd < 0)
    return -1;                                  /* 打不开，返回 -1 */
  tcc_open_bf(s1, filename, 0);                 /* 先造书签 */
#ifdef _WIN32
  normalize_slashes(file->filename);
#endif
  file->fd = fd;                                /* ★ 再把 fd 填进去 */
  return fd;
}
```

关键顺序：**先 `tcc_open_bf` 造书签并挂上 `file`，再 `file->fd = fd`。**
所以从这一行往后，`file` 指向的就是这个刚打开的文件的缓冲区，
而 `fd` 是操作系统给的文件描述符。

**注意**：`tcc_open_bf(..., 0)` 传的 `initlen = 0`，
意味着此刻 `buf_end = buf_ptr = buffer`——**缓冲区是空的**。
文件内容还没读！什么时候读？答案在下一站。

## 第 4 站：缓冲区空了才读盘 —— `handle_eob`（`tccpp.c:587`）

所谓"读到文件末尾"在 TCC 里分成两种：
1. **缓冲区末尾（End Of Buffer, EOB）**：这次读的 8KB 用完了，该再读 8KB；
2. **文件末尾（End Of File, EOF）**：真的没有了。

`handle_eob` 处理的是第①种：

```c
/* src/core/tccpp.c:585-617 */
ST_FUNC int handle_eob(void)
{
    BufferedFile *bf = file;
    int len;

    /* 只有当缓冲区指针真的顶到头了，才去读盘 */
    if (bf->buf_ptr >= bf->buf_end) {
        if (bf->fd >= 0) {                    /* 真文件才读 */
            len = IO_BUF_SIZE;                /* 再读 8KB */
            len = read(bf->fd, bf->buffer, len);
            if (len < 0)
                len = 0;
        } else {
            len = 0;                          /* 内存文件：没得读 */
        }
        total_bytes += len;                   /* 统计用 */
        bf->buf_ptr = bf->buffer;             /* 回到缓冲区开头 */
        bf->buf_end = bf->buffer + len;       /* 新数据到这里结束 */
        *bf->buf_end = CH_EOB;                /* 又在新末尾插一堵"墙" */
    }
    if (bf->buf_ptr < bf->buf_end) {
        return bf->buf_ptr[0];                /* 返回当前字符 */
    } else {
        bf->buf_ptr = bf->buf_end;
        return CH_EOF;                        /* 真没了，返回 -1 */
    }
}
```

逐行翻译：

- 平时调它的时候，`buf_ptr < buf_end`，所以 `if` 不成立，直接跳到末尾返回 `buf_ptr[0]`。
  **它绝大多数时候只是"返回当前字符"**。
- 只有当 `buf_ptr >= buf_end`（顶到墙了），才 `read` 下一批。
  读回来一批后，`buf_end` 后移，并在新末尾再插一堵 `CH_EOB` 墙。
- 如果 `read` 返回 0（文件读完了），`buf_end = buf_ptr`，于是掉进最后 `else`，
  返回 `CH_EOF`（`tcc.h:572` 定义的 `-1`）。

> **为什么要有"墙"这个设计？**
> 因为要在"缓冲区末尾"和"文件末尾"之间做个区分。
> 普通字符可以用一个字节表示，但"末尾"这个状态需要一个哨兵。
> TCC 用 `\`（`CH_EOB`）当缓冲区末尾哨兵，用 `-1`（`CH_EOF`）当文件末尾哨兵。

## 第 5 站：读下一个字符 —— `inp`（`tccpp.c:620`）

```c
/* src/core/tccpp.c:619-626 */
ST_INLN void inp(void)
{
    ch = *(++(file->buf_ptr));    /* ① 指针前进一格，取出字符给 ch */
    if (ch == CH_EOB)             /* ② 撞墙了？ */
        ch = handle_eob();        /* ③ 交给 handle_eob 决定是"续读"还是 EOF */
}
```

三条线说完：

1. `++(file->buf_ptr)`：书签往前挪一个字。
2. `ch = *...`：把新位置的字取出来。
3. 如果取到的正好是那堵墙（`'\\'`，即 `CH_EOB`），
   就交给 `handle_eob`：要么它续读下一批、返回新的当前字符；
   要么返回 `CH_EOF = -1`。

**注意一个坑**：`CH_EOB` 的值就是 `'\\'`（反斜杠）。
所以 `inp()` 看到反斜杠时，**无法区分"这是文件里的反斜杠"还是"这是缓冲区墙"**。
这个歧义由 `handle_eob` 处理：如果 `buf_ptr` 真的顶到头了，就是墙；否则就是真反斜杠。
这就是为什么上面 `handle_eob` 里第一步要判断 `buf_ptr >= buf_end`。

## 第 6 站：三个"读字符宏"（`tccpp.c:681-711`）

TCC 里读字符不是都用 `inp`，因为不同场合要求不一样：

### `PEEKC_EOB(c, p)`：看下一个字符，只处理"墙"

```c
/* src/core/tccpp.c:680-690 */
#define PEEKC_EOB(c, p)\
{\
    p++;                    /* 指针+1 */\
    c = *p;                 /* 取字符 */\
    if (c == '\\') {        /* 撞到墙/反斜杠 */\
        file->buf_ptr = p;  /* 先把书签同步到 p */\
        c = handle_eob();   /* 让 handle_eob 处理 */\
        p = file->buf_ptr;  /* 它可能改了书签，取回来 */\
    }\
}
```

它**不处理"续行"**（`\<换行>`），只处理缓冲区边界。用在注释、字符串内部。

### `PEEKC(c, p)`：看下一个字符，处理"续行"

```c
/* src/core/tccpp.c:692-701 */
#define PEEKC(c, p)\
{\
    p++;\
    c = *p;\
    if (c == '\\') {\
        c = handle_stray1(p);   /* ★ 会吃掉 \<换行>，或报错 */\
        p = file->buf_ptr;\
    }\
}
```

`handle_stray1` 见 `tccpp.c:658`，它会判断这个 `\` 后面是不是紧跟换行
（那是合法的"续行符"，应当忽略），还是别的字符（那是非法的"游离反斜杠"）。

### `minp()`：读下一个字符，处理"续行"

```c
/* src/core/tccpp.c:703-711 */
ST_FUNC void minp(void)
{
    inp();                  /* 读一个 */
    if (ch == '\\')
        handle_stray();     /* 是反斜杠就尝试吃掉续行，否则报错 */
}
```

> **为什么要三个？** 因为"反斜杠"在 C 里身兼二职：
> 一是"缓冲区末尾的哨兵"，二是"续行符"。
> 有些地方（比如字符串里）不该把 `\<换行>` 当续行吃掉，
> 只该处理缓冲区边界——那就用 `PEEKC_EOB`。
> 这种"同一个字节两种含义"迫使 TCC 写了三个变体，是历史包袱，也是它的省事风格。

### 顺带看 `handle_stray_noerror`（`tccpp.c:629`）

```c
/* src/core/tccpp.c:628-648 */
static int handle_stray_noerror(void)
{
    while (ch == '\\') {
        inp();
        if (ch == '\n') {           /* \ 后是换行：合法续行 */
            file->line_num++;       /* 行号+1 */
            inp();                  /* 跳过换行，继续看 */
        } else if (ch == '\r') {    /* \ 后是回车：可能 \r\n */
            inp();
            if (ch != '\n') goto fail;
            file->line_num++;
            inp();
        } else {
        fail:
            return 1;               /* 不是续行，返回 1 表示"这是真的游离反斜杠" */
        }
    }
    return 0;                       /* 成功吃掉续行 */
}
```

它循环处理 `\`，把 `\<换行>` 这种合法续行全部吃掉，返回 0；
遇到不合法的就返回 1。调用者据此决定报不报错。

## 第 7 站：把这一站接回全局

现在你有了完整的"读字符"三件套：

- 想读下一个字符并处理续行 → `minp()` / `inp()`
- 想"偷看"下一个字符（不移动书签）→ `PEEKC` / `PEEKC_EOB`
- 撞到缓冲区末尾要续读 → `handle_eob()`

而"当前字符"永远躺在全局变量 **`ch`** 里。第 02 篇的 `next_nomacro1`
开头第一件事，就是把 `file->buf_ptr` 抄进一个局部指针 `p`，
然后用 `p` 高速扫描；只有在遇到 `\`（可能是墙也可能是续行）时，
才调用上面的工具。**为了快，它平时不碰 `ch`。**

## 【用 t.c 走一遍第一站】

假设 `t.c` 开头是：

```
#define K 8
```

编译器打开它、造好书签后：

| 时刻 | `file->buf_ptr` 指向 | `ch` | 说明 |
|---|---|---|---|
| 刚打开 | 缓冲区头（还没读盘） | 未定 | 等第一次 `inp` 触发读盘 |
| 第一次 `inp` | `'#'` | `'#'` | read 了 8KB，`ch='#'` |
| 再 `inp` | `'d'` | `'d'` | |
| … | … | … | 读到缓冲区第 8192 字节时撞墙 |
| 撞墙 | 墙 `\` | 触发 `handle_eob` | 续读下一批，或返回 `-1` |

到第 02 篇，我们就从这个 `ch='#'` 开始，看 TCC 怎么把它认成
"这是一个行首的预处理指令"，然后切进 `preprocess()`。

## 【常见卡点】

- **`CH_EOB` 和 `CH_EOF` 分不清**：前者是 `'\\'`（缓冲区墙），后者是 `-1`（文件真的没了）。
- **`buffer[1]` 到底多大**：声明是 1，实际用 `sizeof + buflen` 多分配，别被字面骗了。
- **为什么用反斜杠当墙**：因为反斜杠本来就要特殊处理，复用它最省事。

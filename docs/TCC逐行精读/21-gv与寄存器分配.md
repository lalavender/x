# 21 · `gv()` 与寄存器分配：寄存器是"临时工位"

> **一句话**：值栈上的便利贴说"我是个常量"或"我住在 `rbp-8`"。
> 要真的参与运算，得先把值装进 CPU 寄存器。`gv()` 就是那个"把便利贴上的值
> 搬进寄存器"的工头；寄存器不够用时，`save_reg` 把旧值"塞回它在栈帧里的家"。
>
> 对应源码：`src/core/tccgen.c:1253`（`gv`）、`:1062`（`get_reg`）、
> `:962/969`（`save_reg` / `save_reg_upstack`）、`:954`（`save_regs`）、
> `:1103`（`move_reg`）、`:1431`（`gv2`）。

---

## 第 0 站：核心思想（先记这句）

> **便利贴上的"住址"是事实，寄存器只是临时工位。**
> 需要算的时候才找 `get_reg` 借工位、`load` 取货；
> 工位不够，就把还坐在工位上的旧值 `save_reg` 到栈上（溢出）。

TCC **不提前规划寄存器**，是"用到一个借一个、不够就溢出"——这叫**最懒的寄存器分配**。
代价是可能多几次存取，收益是代码简单、寄存器不用做图着色。

---

## 第 1 站：借工位 —— `get_reg`（`tccgen.c:1062`）

```c
/* src/core/tccgen.c:1061-1099 */
ST_FUNC int get_reg(int rc)
{
    int r;
    SValue *p;

    /* 找一个空闲寄存器 */
    for(r=0;r<NB_REGS;r++) {
        if (reg_classes[r] & rc) {          /* r 属于要求的类别（整数/浮点）？ */
            if (nocode_wanted)
                return r;                   /* 不产码时随便给 */
            for(p=vstack;p<=vtop;p++) {
                if ((p->r & VT_VALMASK) == r ||
                    (p->r2 & VT_VALMASK) == r)
                    goto notfound;          /* ★ 有人在用，换下一个 */
            }
            return r;                       /* 没人用，就是它 */
        }
    notfound: ;
    }

    /* 没有空闲寄存器：把"最靠栈底"的一个溢出 */
    for(p=vstack;p<=vtop;p++) {
        r = p->r2 & VT_VALMASK;
        if (r < VT_CONST && (reg_classes[r] & rc))
            goto save_found;
        r = p->r & VT_VALMASK;
        if (r < VT_CONST && (reg_classes[r] & rc)) {
        save_found:
            save_reg(r);                    /* ★ 溢出它 */
            return r;
        }
    }
    return -1;  /* 不该到这里 */
}
```

三件事：

1. **`rc` 是"寄存器类别"**：`RC_INT` / `RC_FLOAT` 等。`reg_classes[]` 是后端提供的表，
   说明每个寄存器属于哪些类别。
2. **遍历值栈找"没人用"的寄存器**——没被任何便利贴占用的就是空闲的。
   *O(寄存器数 × 栈深度)*，寄存器就十来个、栈顶也就几十层，够快。
3. **都满了就溢出"最靠栈底"的**。注释特别说明：
   > VERY IMPORTANT to start from the bottom to ensure that we don't spill registers used in gen_opi()
   从底部找，保证当前运算正要用的寄存器不会刚借来就被抢。

## 第 2 站：溢出 —— `save_reg_upstack`（`tccgen.c:969`）

```c
/* src/core/tccgen.c:967-1034（节选） */
ST_FUNC void save_reg_upstack(int r, int n)
{
    int l, saved, size, align;
    SValue *p, *p1, sv;
    CType *type;

    if ((r &= VT_VALMASK) >= VT_CONST)
        return;                    /* 不是寄存器，无事可做 */
    if (nocode_wanted)
        return;

    saved = 0;
    l = 0;
    for(p = vstack, p1 = vtop - n; p <= p1; p++) {
        if ((p->r & VT_VALMASK) == r ||
            ((p->type.t & VT_BTYPE) == VT_LLONG && (p->r2 & VT_VALMASK) == r)) {
            /* 需要把它存回栈帧 */
            if (!saved) {
                r = p->r & VT_VALMASK;
                type = &p->type;
                ...
                size = type_size(type, &align);
                loc = (loc - size) & -align;    /* ★ 栈顶往下长，算出新偏移 */
                sv.type.t = type->t;
                sv.r = VT_LOCAL | VT_LVAL;
                sv.c.i = loc;
                store(r, &sv);                  /* ★ 后端：把寄存器写进 [rbp+loc] */
                ...
                l = loc;
                saved = 1;
            }
            /* 更新便利贴：它现在住在栈上了 */
            if (p->r & VT_LVAL) {
                p->r = (p->r & ~(VT_VALMASK | VT_BOUNDED)) | VT_LLOCAL;
            } else {
                p->r = lvalue_type(p->type.t) | VT_LOCAL;
            }
            p->r2 = VT_CONST;
            p->c.i = l;
        }
    }
}
```

- **`loc` 是"当前栈帧可用偏移"**（往下长，负方向）。溢出就是 `loc -= size`，
  然后用后端的 `store` 把寄存器写进 `[rbp+loc]`。
- **所有占用同一个寄存器的便利贴都要更新**（循环），因为它们其实指向同一份数据。
  更新成 `VT_LOCAL|VT_LVAL, c=loc`——"我现在住在栈帧这个位置"。
- `save_reg(r)` 就是 `save_reg_upstack(r, 0)`（只看整条栈）。
- `save_regs(n)`（`:954`）对栈上每一个便利贴都调 `save_reg`，**把寄存器全清空**——
  用在函数调用前（调用会破坏寄存器）。

## 第 3 站：工头 `gv()`（`tccgen.c:1253`）

```c
/* src/core/tccgen.c:1253-1256 */
ST_FUNC int gv(int rc)
{
    int r, bit_pos, bit_size, size, align, rc2;

    /* NOTE: get_reg can modify vstack[] */
    if (vtop->type.t & VT_BITFIELD) {
        /* 位域：先移位提取出来（第 49 篇细讲） */
        ...
        r = gv(rc);
    } else {
        if (is_float(vtop->type.t) &&
            (vtop->r & (VT_VALMASK | VT_LVAL)) == VT_CONST) {
            /* ★ 浮点常量：CPU 不能直接用立即数，先放进 .data 段 */
            size = type_size(&vtop->type, &align);
            offset = section_add(data_section, size, align);
            vpush_ref(&vtop->type, data_section, offset, size);
            vswap();
            init_putv(&vtop->type, data_section, offset);
            vtop->r |= VT_LVAL;
        }
        ...
        r = vtop->r & VT_VALMASK;
        rc2 = (rc & RC_FLOAT) ? RC_FLOAT : RC_INT;
        ...
        /* 需要重新装填的情形：常量 / 左值 / 寄存器类别不对 */
        if (r >= VT_CONST
         || (vtop->r & VT_LVAL)
         || !(reg_classes[r] & rc)
         || (long long 的第二个寄存器类别不对))
        {
            r = get_reg(rc);        /* ★ 借工位 */
            if (64 位类型需要两个寄存器) {
                /* 拆成两个寄存器装（第 20 篇的 lexpand 在这里的 64 位版） */
                ...
            } else if ((vtop->r & VT_LVAL) && !is_float(vtop->type.t)) {
                /* 左值且是整数：按字节大小 load */
                ...
                load(r, vtop);
            } else {
                load(r, vtop);      /* ★ 后端：发"取数"指令（第 46 篇） */
            }
        }
        vtop->r = r;                /* ★ 便利贴住址改写成"寄存器 r" */
    }
    return r;
}
```

三块：

1. **位域**：先由 `adjust_bf` + 移位提取，再递归 `gv`。
2. **浮点常量**：不能像整数那样直接用立即数，得先存进 `.data`，
   再当作"左值"取出来。**所以每个用到的浮点常量都会在 `.data` 里占几字节。**
3. **主分支**：判断"要不要重新装填"：
   - `r >= VT_CONST`：是常量，不在寄存器里 → 要；
   - `VT_LVAL`：是"位置"，得解引用取值 → 要；
   - `!(reg_classes[r] & rc)`：已在寄存器但类别不对（比如要浮点寄存器却是整数寄存器）→ 要。
   然后 `get_reg` 借、按需 `load`、最后把便利贴的 `r` 改成寄存器号。

**关键：`vtop->r = r` 之后，这张便利贴就说"我现在在寄存器 r 里"了。**
下次再 `gv` 同一张，发现已经在寄存器且类别对，就什么都不做——**幂等**。

## 第 4 站：搬运 / 双操作数 —— `move_reg` / `gv2`

```c
/* src/core/tccgen.c:1101-1115 */
static void move_reg(int r, int s, int t)
{
    SValue sv;
    if (r != s) {
        save_reg(r);            /* 目标寄存器里若有旧值，先存走 */
        sv.type.t = t;
        sv.type.ref = NULL;
        sv.r = s;
        sv.c.i = 0;
        load(r, &sv);           /* 把 s 装进 r */
    }
}
```

`move_reg` 用在需要"固定目标寄存器"的地方，比如三元运算把两分支结果
都放到同一个寄存器、函数返回值放到约定寄存器。

```c
/* src/core/tccgen.c:1430-1460（骨架）*/
ST_FUNC void gv2(int rc1, int rc2)
{
    /* 生成 vtop[-1] 和 vtop[0] 到 rc1/rc2 两类寄存器 */
    v = vtop[0].r & VT_VALMASK;
    if (v != VT_CMP && (v & ~1) != VT_JMP && rc1 <= rc2) {
        vswap(); gv(rc1); vswap(); gv(rc2);
        if ((vtop[-1].r & VT_VALMASK) >= VT_CONST) { vswap(); gv(rc1); vswap(); }
    } else {
        gv(rc2); vswap(); gv(rc1); vswap();
        if ((vtop[0].r & VT_VALMASK) >= VT_CONST) gv(rc2);
    }
}
```

`gv2` 是"给二元运算准备两个操作数"：**先装"更通用的类别"**，
但 `VT_CMP`/`VT_JMP` 必须优先（否则重载会出错）。
装完第一个后要再检查第二个有没有被挤出寄存器，挤出就重装。

## 第 5 站：后端的两个接口

`gv` 里调了 `load(r, vtop)`；`save_reg` 里调了 `store(r, &sv)`。
这两个是**后端提供**的（x86-64 在 `src/targets/x86_64-gen.c:343` / `:540`，第 46 篇）。
前端只管"要装/要存"，具体发什么指令由后端决定。

接口约定见 `tcc.h` 里那组后端函数指针：


## 【把 `a + b` 的取数过程走一遍】

假设 `a`、`b` 是局部 int：

1. `unary` 读 `a`：便利贴 `{type=int, r=VT_LOCAL|VT_LVAL, c=-8}`；
2. `unary` 读 `b`：便利贴 `{type=int, r=VT_LOCAL|VT_LVAL, c=-12}`；
3. `gen_op('+')` → `gen_opic` → 非全常量 → `gen_opi`（第 47 篇）：
   - `gv(RC_INT)` 对栈顶（`b`）：发现 `VT_LVAL` → `get_reg` 借 `rax`
     → `load(rax, b)` → 发 `mov eax, [rbp-12]` → 便利贴变成 `r=rax`；
   - `gv(RC_INT)` 对下面（`a`）：借 `rcx` → `load(rcx, a)` → `mov ecx,[rbp-8]`；
   - 后端发 `add ecx, eax`（或类似），结果留在某个寄存器；
4. 结果便利贴 `r=寄存器`, `type=int`。

**寄存器是"临时工位"：算完可能马上被别的便利贴借走或溢出。**

## 【常见卡点】

- **`gv` 幂等**：值已在正确类别的寄存器里就什么都不做。
- **溢出从栈底找寄存器**，避免抢当前运算要用的。
- **浮点常量要先进 `.data`**，因为 x86 不能直接用浮点立即数。
- **`save_regs(n)` 清空寄存器**，函数调用前必用。
- **`load`/`store` 是后端提供的**，前端不管指令细节。

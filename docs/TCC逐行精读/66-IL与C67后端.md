# 66 · IL 与 C67 后端：TCC 的"可移植中间层"（选读）

> **一句话**：`il-gen.c` 是一个**不针对真实 CPU 的后端**——它把 TCC 的
> `load`/`store`/`gen_opi` 等接口翻译成一套**自定义指令集**（"IL"），
> 由外部虚拟机执行。`c67-gen.c` 则是 TI C67x DSP 的后端。
>
> 对应源码：`src/targets/il-gen.c`（617 行）、`src/targets/il-opcodes.h`（251 行）、
> `src/targets/c67-gen.c`（2540 行）、`c67-link.c`。

---

## 第 0 站：IL 是什么

IL = **Intermediate Language**（中间语言）。`il-gen.c` 不生成 x86/ARM 指令，
而是生成"IL 字节码"。`il-opcodes.h` 定义这套指令集：

```c
/* src/targets/il-opcodes.h 里（概念）*/
DEF(IL_OP_...)      /* 每个 IL 指令一个编号 */
```

它是 TCC 里一个**实验性/教学性的后端**：证明了"前端 + 后端接口"的分层足够干净，
可以接一个完全不存在的机器。

---

## 第 1 站：IL 后端怎么实现接口

以 `load` 为例（概念）：

```c
/* src/targets/il-gen.c（概念）*/
void load(int r, SValue *sv)
{
    /* 不生成真实机器码，而是发 IL_LOAD / IL_ADDR 等操作码 */
    switch (...) {
        case ...: gen_il(IL_LOAD, ...); break;
    }
}
```

**寄存器编号、指令编码都是 TCC 自己定的**，只要"IL 解释器"认就行。

一个 IL 解释器（不在 TCC 仓库里，是配套的）读这些字节码并执行。
这样 TCC 就能在任意有 IL 解释器的平台上"运行"代码。

---

## 第 2 站：这说明了什么

IL 后端的存在验证了一件事：

> **TCC 的前端和后端之间，接口就是那批 `load`/`store`/`gen_opi`/`gfunc_call` 函数。
> 后端可以完全不面向真实硬件。**

这对理解 TCC 架构很有价值：**分层是真实的，不是口号**。

---

## 第 3 站：C67 后端

TI C67x 是德州仪器的浮点 DSP。`c67-gen.c` 是它的后端：

- 处理 DSP 特有的寄存器（`a0`~`a15`、`b0`~`b15`）；
- 处理定长/变长指令；
- `c67-link.c` 处理它的重定位。

**它主要用来证明 TCC 能移植到非主流的整数/浮点架构。** 日常用不到。

---

## 第 4 站：从这两个后端能学到什么

1. **接口抽象的重要性**：换后端不改前端，是因为接口设计得好；
2. **代价**：有些机器相关代码漏到了前端（比如 `VT_CMP`/`TREG_ST0` 的判断），
   所以不是 100% 干净的；
3. **寄存器分配是"最懒的"**（第 21 篇）：所以适配新架构时，
   主要工作就是写 `load`/`store`/`gen_opi` 等"指令选择"函数。

## 【动手小实验】

1. 打开 `il-opcodes.h`，看 IL 指令集长什么样（和 x86 差多少）。
2. 对比 `il-gen.c` 和 `x86_64-gen.c` 的 `gfunc_call`，看同一个接口的两种实现。
3. 搜 `TCC_TARGET_C67`，看 C67 后端在前端里有哪些特判。
4. 思考：如果让你写一个 RISC-V 后端，最少要实现哪些函数？

## 【常见卡点】

- **IL 是自定义指令集**，需要配套解释器。
- **它证明了前后端接口的分层**。
- **C67 是 DSP 后端**，日常用不到。
- **适配新架构主要写"指令选择"函数**。

# 67 · 内置汇编器与操作码表

> **一句话**：TCC 自带汇编器。它怎么知道 `mov %rax, %rbx` 该编成什么字节？
> 靠一张**操作码表**（`asm_instrs[]`）：每个助记符对应"操作码 + 操作数类型"。
>
> 对应源码：`src/targets/i386-asm.c:149`（`ASMInstr` 结构）、`:221`（`asm_instrs[]` 表）、
> `src/targets/x86_64-asm.h` / `i386-asm.h`（表的内容）、
> `src/core/tccasm.c:850`（汇编主循环，第 50 篇）、`:430`（指令解析）。

---

## 第 0 站：先回顾汇编器的两条路（第 50 篇）

- **`.s` 文件** → `tcc_assemble` → `tcc_assemble_internal`；
- **C 里的 `asm("...")`** → `tcc_assemble_inline`（假文件 `:asm:`）。

两者最终都调用 `asm_opcode(s1, opcode)` 来"汇编一条指令"。

---

## 第 1 站：操作码表的结构（`i386-asm.c:149`）

```c
/* src/targets/i386-asm.c:149-155 */
typedef struct ASMInstr {
    uint16_t sym;                    /* 助记符的 token 编号（TOK_ASM_mov 等） */
    uint16_t opcode;                 /* 操作码字节（可能含 0x0f 前缀）*/
    uint16_t instr_type;             /* 指令类型（前缀/算术/移位…） */
    uint8_t  nb_ops;                 /* 操作数个数 */
    uint8_t  op_type[MAX_OPERANDS];  /* 每个操作数的类型（OP_xxx 位掩码）*/
} ASMInstr;
```

一条记录 = "**这个助记符 + 这种操作数组合 → 这个操作码**"。

操作数类型（`i386-asm.c:60-120`）是一堆位掩码：

```c
/* src/targets/i386-asm.c:60-102（节选）*/
enum {
    OPT_REG8=0, OPT_REG16, OPT_REG32, OPT_REG64,
    OPT_MMX, OPT_SSE, OPT_CR, OPT_TR, OPT_DB, OPT_SEG, OPT_ST,
    OPT_IM8, OPT_IM8S, OPT_IM16, OPT_IM32, OPT_IM64,
    OPT_EAX, OPT_ST0, OPT_CL, OPT_DX,
    OPT_ADDR, OPT_INDIR,
    ...
    OPT_EA = 0x80      /* 可以和任何类型"或"起来，表示"有效地址" */
};
```

**为什么用位掩码？** 因为一个指令可能接受多种操作数（`mov` 能 mov 寄存器、
立即数、内存）。位掩码让"匹配"变成位与运算，快。

## 第 2 站：表怎么生成 —— 宏展开（`i386-asm.c:221`）

```c
/* src/targets/i386-asm.c:221-238（节选）*/
static const ASMInstr asm_instrs[] = {
#define ALT(x) x
/* 去掉第二字节的 0x0f 前缀 */
#define O(o) ((uint64_t) ((((o) & 0xff00) == 0x0f00) ? ((((o) >> 8) & ~0xff) | ((o) & 0xff)) : (o)))
/* 拼出 instr_type */
#define T(o,i,g) ((i) | ((g) << OPC_GROUP_SHIFT) | ((((o) & 0xff00) == 0x0f00) ? OPC_0F : 0))
#define DEF_ASM_OP0(name, opcode)                                    /* 无操作数 */
#define DEF_ASM_OP0L(name, opcode, group, instr_type) \
    { TOK_ASM_ ## name, O(opcode), T(opcode, instr_type, group), 0, { 0 } },
#define DEF_ASM_OP1(name, opcode, group, instr_type, op0) \
    { TOK_ASM_ ## name, O(opcode), T(opcode, instr_type, group), 1, { op0 }},
#define DEF_ASM_OP2(name, opcode, group, instr_type, op0, op1) \
    { TOK_ASM_ ## name, O(opcode), T(opcode, instr_type, group), 2, { op0, op1 }},
...
#ifdef TCC_TARGET_X86_64
# include "x86_64-asm.h"
#else
# include "i386-asm.h"
#endif
    /* last operation */
    { 0, },
};
```

**又是"宏 + `#include`"技巧**（和 `tcctok.h` 第 03 篇、`x86_64-gen.c` 第 44 篇一样）：

- `x86_64-asm.h` 里写 `DEF_ASM_OP2(mov, 0x89, ...)` 这样的声明；
- 这里用 `DEF_ASM_OP2` 展开成表项。

`TOK_ASM_mov` 这些 token 编号来自 `tcctok.h`（第 03 篇）。

**好处**：指令集描述（`.h` 文件）和表结构（`.c` 文件）分离，改指令集只改 `.h`。

## 第 3 站：汇编一条指令

`asm_opcode`（`i386-asm.c` 里）的大致流程：

1. **查表**：在 `asm_instrs[]` 里找 `sym` 匹配、且操作数类型匹配的记录；
2. **可能有多个候选**（比如 `mov` 的 8/16/32/64 位版本），选最合适的；
3. **编码**：根据记录的操作码和操作数，发前缀（REX/大小前缀）、操作码、ModRM、
   立即数；
4. **连接**：如果是跳转/引用，生成重定位。

`i386-asm.c` 里还有专门的 AT&T 语法解析（`%rax`、`$5`、`(%rbp)` 等）。

## 第 4 站：汇编指令与指令集描述文件

`x86_64-asm.h` 里长这样（概念）：

```c
/* src/targets/x86_64-asm.h（节选概念）*/
DEF_ASM_OP2(mov, 0x89, 0, OPC_MODRM, OPT_REG32, OPT_EA)
...
```

**这就是"x86 指令集的数据表格"**。想支持新指令，在这里加一行。

## 第 5 站：汇编器的指令（`tccasm.c:430`）

`.s` 文件里的伪指令由 `asm_parse_directive` 处理：

| 伪指令 | 作用 |
|---|---|
| `.text` / `.data` / `.bss` | 切换当前节（`use_section`） |
| `.globl name` | 符号设成全局 |
| `.byte` / `.word` / `.long` / `.quad` | 写数据 |
| `.align n` | 对齐 |
| `.section name` | 指定节 |
| `.set` / `=` | 符号赋值 |

它们大多直接调第 14 篇的 `Section` 函数。

## 第 6 站：整套设计的复用总结

TCC 用"宏 + include 生成表"这个模式，生成了至少四张表：

| 表 | 源文件 | 用途 |
|---|---|---|
| token 编号 + 关键字名 | `tcctok.h` | 词法器（第 03 篇） |
| 后端配置（寄存器等） | `*-gen.c` 的 `TARGET_DEFS_ONLY` 段 | 后端（第 44 篇） |
| 汇编操作码 | `*-asm.h` | 汇编器（本篇） |
| 重定位类型 | `*-link.c` 的 `TARGET_DEFS_ONLY` 段 | 链接（第 53 篇） |

**"数据用表描述，代码用宏生成"** 是 TCC 保持小体积的核心手法之一。

./tcc -c /tmp/a.c -o /tmp/a.o && objdump -d /tmp/a.o 2>/dev/null | grep -E 'mov.*0x5|ret'

## 【常见卡点】

- **操作码表用宏 + include 生成**，源数据在 `*-asm.h`。
- **操作数类型是位掩码**，匹配用位运算。
- **汇编器和 C 前端共用词法器**。
- **伪指令直接操作 `Section`**。
- **"宏生成表"是 TCC 的通用手法**（四张表）。

# 68 · 毕业项目：从零写一个 `mcc`，并读懂 TCC

> **一句话**：前面 67 篇把 TCC 拆了个遍。最后一篇给你一个**动手项目**：
> 自己写一个"小 TCC"（`mcc`），从 `1+2*3` 一路做到能链接库、能内存执行。
> 每写一块，回头对照 TCC 的对应源码——**你会发现自己写的和它长得几乎一样。**
>
> 对应源码：全仓库。本文是"施工图"。

---

## 第 0 站：为什么"写一个"比"读十遍"强

读代码是**理解别人的决定**；写代码是**自己做决定**。
只有自己卡在"值栈该存什么"时，才会真正理解第 12 篇为什么那样设计
`SValue`。所以毕业项目不是考试，是**把 67 篇的知识"过一遍手"**。

---

## 第 1 站：项目的技术目标

`mcc` 生成 **x86-64 机器码**（这样能在本机 `-run`，Linux 上还能落盘）。
支持的 C 子集（恰好是 TCC 的核心）：

```
整数、char、指针、数组、
struct/union/enum、
if/while/for/do/goto/switch、
函数/递归/函数指针/varargs(printf)、
全局/局部变量、
#define/#if/#include 基本款、
链接静态库
```

不要求：浮点（选做）、VLA、位域（选做）、内联汇编（只读不写）。

## 第 2 站：里程碑（每个都对应若干篇文档）

### M0 · 词法器（对应第 01–05 篇）

**目标**：读一个文件，输出 token 流。

- `BufferedFile` + 缓冲区（第 01 篇）；
- `next_nomacro` + `next`（第 02 篇）；
- 名字表（哈希）、关键字表（第 03 篇）；
- 数字/字符串解析（第 04、05 篇）。

**验收**：能打印 `int main(){return 42;}` 的所有 token。

### M1 · 预处理器（第 06–09 篇）

**目标**：支持 `#define`、宏展开、`#if`、`#include`。

- `Sym` 宏卡 + 录音带（第 06、09 篇）；
- `next()` 展开（第 07 篇）；
- `ifdef_stack` + `preprocess_skip`（第 08 篇）。

**验收**：`mcc -E` 能展开 `#define K 8`、`#if`。

### M2 · 单遍代码生成（第 10–25 篇）

**目标**：把 `int f(int a,int b){return a+b;}` 编成机器码。

- `CType`/`SValue`/值栈（第 11、12 篇）；
- `unary` + 递归下降 + `gen_op`（第 17–22 篇）；
- `gv`（懒寄存器分配）（第 21 篇）；
- `vstore` + 类型转换（第 23、24 篇）；
- 后端的 `g`/`o`/`load`/`store`/`gen_opi`（第 44–47 篇）。

**验收**：`mcc -c f.c -o f.o`，用 `objdump` 看到合理的 `push/mov/add/ret`。

### M3 · 语句与控制流（第 26–31 篇）

**目标**：`if`/`while`/`for`/`switch`/`goto` 全部工作。

- `block` 调度室（第 26 篇）；
- **跳转链 + 回填**（第 27 篇，最重要！）；
- 短路、`switch` 二分、标签（第 28–30 篇）。

**验收**：`mcc -run tests/loop.c` 输出正确。

### M4 · 类型系统与声明（第 32–39 篇）

**目标**：`struct`、数组、`typedef`、初始化、函数定义。

- `parse_btype`/`type_decl`（第 32、33 篇）；
- `struct_layout`（第 34 篇）；
- `decl_initializer`（第 36 篇）。

**验收**：`sizeof(struct {char a; int b;})` 正确。

### M5 · 函数与 ABI（第 40–43 篇）

**目标**：多参数、返回值、递归、`varargs`。

- `gfunc_call`/`gfunc_prolog`（第 41、42 篇）；
- 返回值寄存器（第 43 篇）。

**验收**：`printf` 能用（可以先借用系统 libc）。

### M6 · 链接与运行（第 51–56 篇）

**目标**：`mcc -run` 直接跑；`mcc f.c -o f` 产出可执行文件。

- `Section` + 符号表 + 重定位（第 51–53 篇）；
- ELF 输出或内存重定位（第 54、55 篇）；
- 短期目标：**内存执行**最简单（第 55 篇），先做它。

**验收**：`mcc -run tests/hello.c` 打印 `hello`。

## 第 3 站：推荐的开发顺序（不要跳）

```
M0 词法器  →  先能打印 token
M2 表达式  →  编 1+2*3，用运行时验证
M2 变量    →  编 x=3; return x;
M3 控制流  →  if/while
M2 函数    →  return a+b
M5 调用    →  多函数、printf
M4 类型    →  struct/数组/指针
M1 预处理  →  #define/#if
M6 输出    →  -run，再落盘
```

**先做"内存执行"（M6 的一半）**，因为它省掉了写 ELF 文件的麻烦：
你只需要"生成代码 → 申请可执行内存 → 跳过去"。

## 第 4 站：怎么对照 TCC 读源码

每写一块，问自己三个问题，然后去 TCC 找答案：

1. **"这东西存哪？"** → 查 `tcc.h` 的结构体（第 10–15 篇）。
2. **"这一步怎么实现的？"** → 查对应函数（本文档给的行号）。
3. **"为什么这么设计？"** → 看你自己的写法有什么痛点，对比 TCC 的取舍。

**典型对照清单**：

| 你写的 | 对照 TCC |
|---|---|
| `next_token()` | `next_nomacro1`（第 02 篇） |
| 值栈 `push/pop` | `vsetc`/`vpop`（第 12 篇） |
| 表达式递归 | `expr_*`（第 17 篇） |
| 常量折叠 | `gen_opic`（第 22 篇） |
| 跳转回填 | `gjmp`/`gsym`（第 27 篇） |
| 栈帧 | `gfunc_prolog`/`epilog`（第 42 篇） |
| 输出 | `elf_output_file`/`tcc_relocate_ex`（第 54、55 篇） |

## 第 5 站：自举（终极挑战）

TCC 最酷的能力之一是**编译自己**（自举）。你的 `mcc` 也可以尝试：

- **阶段一**：`mcc` 能编译"简化版 mcc"；
- **阶段二**：用 mcc 编译出的 mcc 再编译 mcc（自举）。

这要求你的 mcc 支持足够的 C 子集（指针、结构体、函数指针、递归…）。
**不为通过也没关系**——追踪"还差什么特性"的过程就是最好的复习。

## 第 6 站：毕业标准（自己给自己判分）

1. **能编译**：一个 100 行的综合程序（递归 + 结构体 + 函数指针 + `switch` + `goto`
   + 变参 `printf`），一次通过，运行正确；
2. **能通过测试集**：从 TCC 的 `tests/tests2/` 移植至少 40 个测试
   （`.c` + `.expect` 自动比对）；
3. **能讲清楚**：在白板前 30 分钟，给一个外行讲明白
   "`int f(int a){return a+1;}` 这一行是怎么变成机器码的"；
4. **（选做）能自举**，或实现 `-run`。

### 你现在应该能

- 指出 TCC 里任何一段代码"在哪、干什么、为什么"；
- 解释"没有语法树的编译器"怎么工作；
- 解释值栈、跳转链、录音带这三个 TCC 的核心机制；
- 解释从源码到可执行经过的每一站；
- 开始写自己的编译器。

### 最后一句

TCC 只有约 4 万行（核心），却是一个**完整、能自举、跑得飞快**的 C 编译器。
它的秘密不是"聪明"，而是**每个地方都做了简单而正确的取舍**：

- 不建树 → 值栈；
- 不做寄存器分配 → 懒溢出；
- 不做复杂链接 → 内置简单链接器；
- 不追求最大优化 → 常量折叠 + 代数化简。

**读懂它，你就摸到了"用小代价做对的事"的门道。**

## 【动手小实验（毕业作业）】

1. 建一个 `~/mcc/` 仓库，从 `mcc.c` 一个文件开始（TCC 也曾经是一个文件）。
2. 按 M0 → M2 → M3 → M5 → M4 → M1 → M6 的顺序推进。
3. 每完成一个里程碑，`git commit`，提交信息写"我学会了什么"。
4. 卡住时，回到本系列对应篇目，对照 TCC 源码。

## 【通关暗号】

```bash
# 最终，你应该能这样：
# ./mcc -run tests/all.c        # 一步编译运行
# ./mcc tests/all.c -o all && ./all
# 并且能对着 tests/ 里的每一个测试说："这对应 TCC 的哪个函数"
echo "毕业快乐 —— 现在你懂 TCC 了"
```

## 【常见卡点】

- **别一上来就写 ELF**：先用内存执行（第 55 篇）验证正确性。
- **跳转回填（第 27 篇）是第一个大坎**，慢下来啃。
- **寄存器分配先写最懒的**（第 21 篇），正确后再考虑优化。
- **遇到"为什么"，回头看 TCC 的注释**——作者写了很多解释。
- **卡住 30 分钟就来问 AI**，但先说清"我以为会怎样、实际怎样"。

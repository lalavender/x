# TCC 逐行精读 · 从这里开始

> 这套文档只有一个目标：
> **让你左边开着文档、右边开着 `src/` 里的真源码，一行一行地读懂 TCC。**
>
> 不要求你懂编译原理。文档里每个术语都会当场用"12 岁能懂的话"解释。
> 每一段源码都告诉你：**它在哪（文件:行号）、它是干嘛的、为什么非这么写不可。**

## 二、怎么读（重要）

1. 打开一个终端，`cd` 到本仓库根目录。
2. 打开另一个编辑器窗口，加载文档里点名的那**一个** `.c` 文件。
3. 文档说"看 `tccpp.c:2561`"，你就在编辑器里跳到 2561 行。
4. 文档贴的代码如果你觉得"好像少了几行"，那多半是文档故意删了无关行，旁边会有 `/* …省略… */` 标记。
5. 每篇结尾有【通关暗号】：一条命令 + 期望输出。**输出对上才算过关**（真 TCC 就是靠 `tests/*.expect` 这么玩的）。

源码目录约定（本仓库重新整理过）：

```
src/core/       编译器大脑：tcc.c tccpp.c tccgen.c tccelf.c tccrun.c libtcc.c tccasm.c tcc.h
src/targets/    各 CPU 的"翻译官"：x86_64-gen.c i386-gen.c arm-gen.c arm64-gen.c il-gen.c
src/formats/    输出格式：elf.h coff.h tccpe.c tcccoff.c
```

> 注意：很多人手里的 TCC 源码是平铺在一个目录里的。本仓库把文件分进了
> `core / targets / formats`，所以**网上教程的行号可能和这里差几行**，
> 但函数名和逻辑完全一样。以本仓库为准。

## 四、给完全没碰过编译器的人：30 秒世界观

编译器就是一条**翻译流水线**：

```
  人类写的 C 文本
        │  ① 词法/预处理：把字符切成一个个"词"（token）
        ▼
  一串 token        ── TCC 的 tccpp.c
        │  ② 语法/代码生成：边读 token，边吐出机器码
        ▼
  机器码字节        ── TCC 的 tccgen.c + targets/*-gen.c
        │  ③ 打包：把机器码装进 .text、名字装进符号表、欠条装进重定位表
        ▼
  目标文件(.o)      ── TCC 的 tccelf.c
        │  ④ 链接：把多个 .o + 库拼成一个可执行文件，回填欠条
        ▼
  可执行文件        ── TCC 的 tccelf.c（链接部分）
        │  ⑤ 运行
        ▼
  CPU 真的跑起来    ── TCC 的 tccrun.c（可以不落盘，直接在内存里跑）
```

`tcc.c` 只在第 ① 步之前和最后管命令行，真正的中枢是 `libtcc.c:585` 的 `tcc_compile()`。

看懂这条流水线，你就有了地图；接下来的每一篇，都是在其中某一站停下来，
把那一站的机器拆开，看每一个齿轮。

# 53 · 重定位：机器码里的"欠条"

> **一句话**：生成代码时不知道被引用符号的最终地址，就在指令里留个空，
> 并**记一条重定位条目**："这里要填 `符号 + 加数`，按类型 T 算"。
> 链接时（第 59 篇）或内存加载时（第 55 篇）统一回填。
>
> 对应源码：`src/core/tccgen.c:429`（`greloca`）、`src/core/tccelf.c:577`（`put_elf_reloca`）、
> `:825`（`relocate_section`）、`src/targets/x86_64-link.c:173`（`relocate` 实际回填）、
> `:27`（`code_reloc`）、`:62`（`gotplt_entry_type`）。

---

## 第 0 站：什么时候产生欠条

三个地方：

1. **调用外部函数**：`gcall_or_jmp`（第 41 篇）发 `call` 时生成 `R_X86_64_PLT32`；
2. **取全局变量地址**：`load`（第 46 篇）生成 `R_X86_64_GOTPCREL` / `R_X86_64_PC32`；
3. **全局初始化的指针**：`init_putv`（第 36 篇）生成 `R_DATA_PTR`（= `R_X86_64_64`）。

它们都通过前端的 `greloca`：

```c
/* src/core/tccgen.c:428-445 */
ST_FUNC void greloca(Section *s, Sym *sym, unsigned long offset, int type,
                     addr_t addend)
{
    int c = 0;

    if (nocode_wanted && s == cur_text_section)
        return;                         /* 不生成代码时不记 */
    if (sym) {
        if (0 == sym->c)
            put_extern_sym(sym, NULL, 0, 0);   /* 没发布就发布（未定义符号）*/
        c = sym->c;                     /* c = ELF 符号下标 */
    }
    put_elf_reloca(symtab_section, s, offset, type, c, addend);
}
```

**注意 `s == cur_text_section`**：只对当前代码节忽略 `nocode_wanted`，
数据节（如字符串）即使在 `sizeof` 里也要真的生成。

## 第 1 站：记一条重定位 —— `put_elf_reloca`（`tccelf.c:577`）

```c
/* src/core/tccelf.c:577-605 */
ST_FUNC void put_elf_reloca(Section *symtab, Section *s, unsigned long offset,
                            int type, int symbol, addr_t addend)
{
    char buf[256];
    Section *sr;
    ElfW_Rel *rel;

    sr = s->reloc;
    if (!sr) {
        /* 没有重定位节就建一个：.text → .rel.text */
        snprintf(buf, sizeof(buf), REL_SECTION_FMT, s->name);
        sr = new_section(tcc_state, buf, SHT_RELX, symtab->sh_flags);
        sr->sh_entsize = sizeof(ElfW_Rel);
        sr->link = symtab;              /* ★ 关联符号表 */
        sr->sh_info = s->sh_num;        /* ★ 这个重定位属于哪个节 */
        s->reloc = sr;                  /* ★ 反向指针 */
    }
    rel = section_ptr_add(sr, sizeof(ElfW_Rel));   /* 追加一条 */
    rel->r_offset = offset;             /* 在 s 里的偏移 */
    rel->r_info = ELFW(R_INFO)(symbol, type);      /* 符号下标 | 类型 */
#if SHT_RELX == SHT_RELA
    rel->r_addend = addend;             /* x86-64 用 RELA，带加数 */
#else
    if (addend) tcc_error("non-zero addend on REL architecture");
#endif
}
```

**每条重定位三项**：

- `r_offset`：要填的字节在**目标节**里的偏移；
- `r_info`：高 32 位是符号表下标，低 32 位是重定位类型；
- `r_addend`：加数（x86-64 是 RELA 格式）。

`Section` 的 `reloc`/`link`/`sh_info` 三个字段把"代码节↔重定位节↔符号表"串起来（第 14 篇）。

## 第 2 站：应用重定位 —— `relocate_section`（`tccelf.c:825`）

```c
/* src/core/tccelf.c:823-851 */
ST_FUNC void relocate_section(TCCState *s1, Section *s)
{
    Section *sr = s->reloc;
    ElfW_Rel *rel;
    ElfW_Sym *sym;
    int type, sym_index;
    unsigned char *ptr;
    addr_t tgt, addr;

    relocate_init(sr);
    for_each_elem(sr, 0, rel, ElfW_Rel) {        /* 遍历每条重定位 */
        ptr = s->data + rel->r_offset;           /* 要填的字节 */
        sym_index = ELFW(R_SYM)(rel->r_info);
        sym = &((ElfW(Sym) *)symtab_section->data)[sym_index];
        type = ELFW(R_TYPE)(rel->r_info);
        tgt = sym->st_value;                     /* 符号的最终值 */
#if SHT_RELX == SHT_RELA
        tgt += rel->r_addend;                    /* 加数 */
#endif
        addr = s->sh_addr + rel->r_offset;       /* 要填的位置的最终地址 */
        relocate(s1, rel, type, ptr, addr, tgt); /* ★ 后端执行 */
    }
    if (sr->sh_flags & SHF_ALLOC)
        sr->link = s1->dynsym;
}
```

**前端算 `tgt`（目标值）和 `addr`（位置），后端 `relocate` 按类型写字节。**

## 第 3 站：后端怎么填 —— `x86_64-link.c:173`

```c
/* src/targets/x86_64-link.c:173-196（节选）*/
void relocate(TCCState *s1, ElfW_Rel *rel, int type, unsigned char *ptr, addr_t addr, addr_t val)
{
    ...
    switch (type) {
        case R_X86_64_64:             /* 64 位绝对地址 */
            if (s1->output_type == TCC_OUTPUT_DLL) { ... 动态重定位 ... }
            add64le(ptr, val);        /* ★ 把 val 加到那 8 字节上 */
            break;
        case R_X86_64_32:
        case R_X86_64_32S:            /* 32 位绝对地址 */
            ...
            add32le(ptr, val);
            break;
```

其他类型（`:201` 起）：

| 类型 | 用途 | 计算 |
|---|---|---|
| `R_X86_64_64` | 数据里的 64 位指针 | `ptr += val` |
| `R_X86_64_32/32S` | 32 位绝对地址 | `ptr += val` |
| `R_X86_64_PC32` | PC 相对 32 位（如 RIP 数据访问） | `ptr += val - addr` |
| `R_X86_64_PLT32` | 调用外部函数 | `ptr += val - addr`（或经 PLT） |
| `R_X86_64_GOTPCREL` | 从 GOT 取地址 | 填 GOT 槽相对偏移 |
| `R_X86_64_GLOB_DAT`/`JUMP_SLOT` | 动态链接 | 产生动态重定位 |

**核心都是"把差值加到那几字节上"**（`add32le`/`add64le`）。因为指令里预留的是 0/占位，
加完就是正确值。注意 `add*le` 是**加上**而不是"写入"——这样支持 `sym + offset` 的加数。

## 第 4 站：重定位的辅助判断（`x86_64-link.c:27/62`）

```c
/* src/targets/x86_64-link.c:27-57（节选）*/
int code_reloc(int reloc_type)   /* 这个重定位是代码里的还是数据里的？ */
{
    switch (reloc_type) {
        case R_X86_64_32: case R_X86_64_32S: case R_X86_64_64:
        case R_X86_64_GOTPCREL: ... return 0;   /* 数据 */
        case R_X86_64_PC32: case R_X86_64_PLT32: ... return 1;   /* 代码 */
    }
    tcc_error("Unknown relocation type: %d", reloc_type);
}
```

```c
/* src/targets/x86_64-link.c:62-99（节选）*/
int gotplt_entry_type(int reloc_type)   /* 需不需要 GOT/PLT 槽 */
{
    switch (reloc_type) {
        case R_X86_64_GLOB_DAT: ... return NO_GOTPLT_ENTRY;
        case R_X86_64_PC32: ... return AUTO_GOTPLT_ENTRY;
        case R_X86_64_GOTPCREL: case R_X86_64_PLT32: ... return ALWAYS_GOTPLT_ENTRY;
    }
    ...
}
```

链接器用这两个判断决定"要不要为这个符号建 GOT/PLT 条目"（第 61 篇）。

## 第 5 站：`GOTPCREL` 为什么是"取地址"

第 46 篇 `load` 对非 static 全局变量生成的是：

```
mov GOTPCREL(sym), reg    ; 从 GOT 表里取 sym 的地址
mov [reg], reg            ; 再读值
```

这是 PIE（位置无关代码）的做法：**代码不硬编码变量地址，而是通过 GOT 表间接访问**。
链接/加载时 GOT 表被填上真实地址。`greloca(..., R_X86_64_GOTPCREL, ...)` 就是
"这里要填 GOT 槽的相对偏移"。

## 【把 `int main(){return f();}` 走一遍】

| 步骤 | 说明 |
|---|---|
| 1 | `unary` 调用 `f`，`gcall_or_jmp` 发 `call`（占位） |
| 2 | 同时 `greloca(cur_text_section, f_sym, ind+1, R_X86_64_PLT32, -4)` |
| 3 | `.rel.text` 里多一条：offset、`f` 的符号下标、类型 PLT32、加数 -4 |
| 4 | 链接时 `relocate_section` 遍历，算 `tgt = f.st_value` |
| 5 | 后端 `relocate`：`ptr += tgt - addr`（把 call 的相对位移填对） |

## 【动手小实验】

1. `int main(){return printf("x");}` 编译到 `.o`，`objdump -dr` 看 `R_X86_64_PLT32`。
2. `int g; int *p=&g;` 看 `.data` 上的 `R_X86_64_64`。
3. `extern int e; int f(){return e;}` 看 `R_X86_64_PC32` 或 `GOTPCREL`。
4. 用 `readelf -r` 列出所有重定位。

## 【常见卡点】

- **重定位三要素**：`r_offset`（位置）、`r_info`（符号+类型）、`r_addend`（加数）。
- **`.rel.text` ↔ `.text` ↔ `.symtab` 互相挂钩**。
- **回填是"加"到预留字节上**（`add32le`/`add64le`）。
- **`GOTPCREL` 是 PIE 访问全局变量的方式**。
- **`code_reloc`/`gotplt_entry_type` 供链接器判断**。

# 58 · 链接总流程：把积木拼成可执行文件

> **一句话**：TCC 的"链接"没有单独的 `ld` 阶段，它就在 `elf_output_file` 里：
> 加入运行时 → 解决公共符号 → 建 GOT/PLT → 排序符号 → 定地址 → 应用重定位 → 写文件。
>
> 对应源码：`src/core/tccelf.c:2233`（`tcc_output_file`）、`:2060`（`elf_output_file`）、
> `:1188`（`tcc_add_runtime`）、`:1272`（`resolve_common_syms`）、
> `:719`（`sort_syms`）、`:1821`（`final_sections_reloc`）。

---

## 第 0 站：链接的六步（再看 `elf_output_file`）

```c
/* src/core/tccelf.c:2060 起（要点）*/
static int elf_output_file(TCCState *s1, const char *filename)
{
    if (file_type != TCC_OUTPUT_OBJ) {
        tcc_add_runtime(s1);          /* ① 链接 libc/crt/libtcc1 */
        resolve_common_syms(s1);      /* ② common → .bss + 链接器符号 */

        if (!s1->static_link) {
            ... .interp / .dynsym / .dynamic ...
            build_got(s1);            /* ③ 建 GOT 表骨架 */
            bind_exe_dynsyms(s1);     /* ④ 解析动态符号（PLT/COPY） */
        }
        build_got_entries(s1);        /* ⑤ 为需要的符号建 GOT/PLT */
    }

    strsec = new_section(s1, ".shstrtab", ...);
    textrel = alloc_sec_names(s1, file_type, strsec);
    ... dyninf / phnum ...

    file_offset = layout_sections(...);   /* ⑥ 定地址 */

    if (file_type != TCC_OUTPUT_OBJ) {
        ... fill_dynamic / relocate_plt ...
        ret = final_sections_reloc(s1);   /* ⑦ 应用重定位 */
        tidy_section_headers(s1, sec_order);
        fill_got(s1);                     /* ⑧ 填 GOT */
    }

    ret = tcc_write_elf_file(...);        /* ⑨ 写文件 */
}
```

## 第 1 站：加入运行时 —— `tcc_add_runtime`（`:1188`）

```c
/* src/core/tccelf.c:1188-1208 */
ST_FUNC void tcc_add_runtime(TCCState *s1)
{
    tcc_add_bcheck(s1);              /* 边界检查运行时（-b） */
    tcc_add_pragma_libs(s1);         /* #pragma comment(lib,...) */
    if (!s1->nostdlib) {
        tcc_add_library_err(s1, "c");        /* ★ 链接 libc */
#ifdef TCC_LIBGCC
        if (!s1->static_link) tcc_add_dll(s1, TCC_LIBGCC, 0);
#endif
        tcc_add_support(s1, TCC_LIBTCC1);    /* ★ libtcc1（辅助函数，第 43 篇） */
        if (s1->output_type != TCC_OUTPUT_MEMORY)
            tcc_add_crt(s1, "crtn.o");       /* C 运行时收尾 */
    }
}
```

`TCC_LIBTCC1` 是 TCC 自带的运行时库，里面有 `__divdi3`（64 位除法）、
`alloca`、`va_arg` 辅助等（第 43 篇的 `__*tf3`、第 22 篇的 `__divdi3`）。

## 第 4 站：链接 vs 编译的边界

| 阶段 | 函数 | 输入 | 输出 |
|---|---|---|---|
| 编译 | `tccgen_compile` | C 源码 | 内存里的 `Section` + 符号 |
| 链接 | `elf_output_file` | `Section` + 符号 + 库 | ELF 文件 |

**TCC 把两者放在同一个 `TCCState` 里**，所以"编译"和"链接"之间没有落盘的 `.o`
（除非你显式 `-c`）。`tcc a.c` 一步到位。

---

## 第 5 站：和 GNU 链接器的对比

| | GNU ld | TCC |
|---|---|---|
| 独立程序 | 是（`ld`） | 否（内嵌在编译器里） |
| 输入 | `.o`/`.a`/`.so`/脚本 | 同上 |
| 符号解析 | 完整 | 基本够用 |
| 优化 | 有（section GC、ICF） | 几乎没有 |
| 速度 | 较慢 | 很快 |
| 链接脚本 | 完整支持 | 部分支持（`tcc_load_ldscript`） |

**TCC 的链接器小而快，够编译普通程序。**

## 【把链接一个程序走一遍】

```
tcc hello.c -o hello

1. tcc_add_file(hello.c)    → 编译进 .text/.data/.symtab
2. elf_output_file:
   tcc_add_runtime          → 加 libc.so / libtcc1.a / crtn.o
   resolve_common_syms      → int x; 归入 .bss
   build_got / build_got_entries → 为 printf 建 GOT/PLT
   layout_sections          → .text 定到 0x400000+，.data 跟在后面
   final_sections_reloc     → 回填所有重定位
   tcc_write_elf_file       → 写 hello
3. ./hello → OS 加载 → ld.so 解析 printf → main 运行
```

---

## 【动手小实验】

1. `tcc -v hello.c -o hello` 看 TCC 打印的链接信息（verbose）。
2. `tcc -nostdlib` 编译一个无 libc 的程序（会缺 `_start`）。
3. `tcc -static hello.c -o hello` 和动态版对比大小（`ls -l`）。
4. `readelf -d hello` 看 `NEEDED` 里依赖的动态库。

## 【通关暗号】

```bash
printf '#include <stdio.h>\nint main(void){printf("ok\\n"); return 0;}\n' > /tmp/h.c
./tcc /tmp/h.c -o /tmp/h && /tmp/h
# 期望：打印 ok（说明运行时、libc、重定位、布局全对）
```

## 【常见卡点】

- **TCC 没有独立链接器阶段**，编译和链接一体。
- **`tcc_add_runtime` 自动加 libc/libtcc1/crt**。
- **`sort_syms` 满足 ELF 局部符号在前的规范**。
- **`final_sections_reloc` 是"兑现所有欠条"**。

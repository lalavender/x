# 59 · 符号解析与公共符号：谁赢谁输

> **一句话**：多个 `.o` 可能有同名符号，谁的定义最终生效？
> 规则是"全局 > 弱 > 未定义""真实数据 > common/bss"。
> 另外 C 的"暂定定义"（`int x;` 写多处）靠 **common 符号** 在最后统一分配。
>
> 对应源码：`src/core/tccelf.c:1272`（`resolve_common_syms`）、
> `:1213`（`tcc_add_linker_symbols`）、`:779`（`relocate_syms`）、
> `:490`（`set_elf_sym` 的合并规则，第 52 篇）、`:1384`（`bind_exe_dynsyms`）。

---

## 第 0 站：解决公共符号 —— `resolve_common_syms`（`:1272`）

C 里可以写：

```c
int x;              /* a.c */
int x;              /* b.c */  // 两处都定义？C 允许（tentative definition）
```

编译器遇到这种"无初始化的全局变量"，不立刻放进 `.bss`，而是标记成 **common 符号**
（`st_shndx = SHN_COMMON`，`st_value` 存对齐）。链接时统一分配：

```c
/* src/core/tccelf.c:1272-1288 */
ST_FUNC void resolve_common_syms(TCCState *s1)
{
    ElfW(Sym) *sym;

    /* 把所有 common 符号分配进 .bss */
    for_each_elem(symtab_section, 1, sym, ElfW(Sym)) {
        if (sym->st_shndx == SHN_COMMON) {
            /* common 符号的 st_value 存的是"对齐" */
            sym->st_value = section_add(bss_section, sym->st_size, sym->st_value);
            sym->st_shndx = bss_section->sh_num;   /* 现在它属于 .bss 了 */
        }
    }

    /* 分配"链接器提供的符号"（_end、__start_xxx 等） */
    tcc_add_linker_symbols(s1);
}
```

**为什么用 common？** 因为每个 `.o` 都可能写 `int x;`，
如果各自在 `.bss` 分配空间，链接时会冲突（多个 `x`）。
common 符号让**链接器统一分配一次**——这就是 GCC 老版本的默认行为
（`-fcommon`；新 GCC 默认 `-fno-common`，TCC 默认 `nocommon=1`）。

## 第 1 站：链接器提供的符号 —— `tcc_add_linker_symbols`（`:1213`）

```c
/* src/core/tccelf.c:1213-1236（节选）*/
static void tcc_add_linker_symbols(TCCState *s1)
{
    set_elf_sym(symtab_section, text_section->data_offset, 0, ...,
                text_section->sh_num, "_etext");   /* .text 结束 */
    set_elf_sym(symtab_section, data_section->data_offset, 0, ...,
                data_section->sh_num, "_edata");   /* .data 结束 */
    set_elf_sym(symtab_section, bss_section->data_offset, 0, ...,
                bss_section->sh_num, "_end");      /* .bss 结束 */
    ...
    /* 每个可命名节的 __start_xxx / __stop_xxx */
}
```

这些是 C 运行时和链接脚本约定的符号，比如 `_end` 表示堆的开始。

## 第 2 站：合并规则全体现在 `set_elf_sym`（第 52 篇）

回顾第 52 篇 `set_elf_sym` 的规则：

```c
            if (shndx == SHN_UNDEF) {
                /* 已定义后又来未定义：忽略 */
            } else if (sym_bind == STB_GLOBAL && esym_bind == STB_WEAK) {
                goto do_patch;                /* 全局覆盖弱 */
            } else if (sym_bind == STB_WEAK && esym_bind == STB_GLOBAL) {
                /* 弱忽略（已有全局） */
            } else if (sym_bind == STB_WEAK && esym_bind == STB_WEAK) {
                /* 弱+弱：保留先找到的 */
            } else if ((esym->st_shndx == SHN_COMMON || esym->st_shndx == bss)
                       && (shndx 是真实数据节)) {
                goto do_patch;                /* 真实数据覆盖 common */
            } else if (shndx == SHN_COMMON || shndx == bss) {
                /* common 忽略（已有数据） */
            } else {
                tcc_error_noabort("'%s' defined twice", name);
            }
```

**优先级从高到低**：

```
真实数据定义  >  弱定义（先到先得）  >  common/bss  >  未定义
全局定义      >  弱定义
```

这套规则保证：多个 `.o` 里同名的 `int x;` 能合并，多个强定义会报错。

## 第 3 站：解析未定义符号 —— `relocate_syms`（`:779`）

```c
/* src/core/tccelf.c:779-821（重贴要点）*/
ST_FUNC void relocate_syms(TCCState *s1, Section *symtab, int do_resolve)
{
    for_each_elem(symtab, 1, sym, ElfW(Sym)) {
        if (sym->st_shndx == SHN_UNDEF) {
            name = ...;
            if (do_resolve) {
                /* -run 模式：问操作系统要地址 */
                void *addr = dlsym(RTLD_DEFAULT, name);
                if (addr) { sym->st_value = (addr_t)addr; goto found; }
            } else if (s1->dynsym && find_elf_sym(s1->dynsym, name))
                goto found;                     /* 动态库里找到了，交给动态重定位 */
            if (!strcmp(name, "_fp_hw")) goto found;    /* ABI 特例 */
            if (sym_bind == STB_WEAK) sym->st_value = 0;   /* 弱未定义：0 */
            else tcc_error_noabort("undefined symbol '%s'", name);
        } else if (sh_num < SHN_LORESERVE) {
            sym->st_value += s1->sections[sym->st_shndx]->sh_addr;   /* 加节基址 */
        }
    found: ;
    }
}
```

**未定义符号的三种归宿**：

1. `-run`：`dlsym` 从当前进程拿地址；
2. 可执行文件：动态符号表里有 → 生成动态重定位，运行时由 `ld.so` 解析；
3. 都没有 → 报 `undefined symbol`（弱符号则取 0）。

## 第 4 站：`bind_exe_dynsyms`（`:1384`）—— 可执行文件怎么接动态库

```c
/* src/core/tccelf.c:1384-1405（节选）*/
static void bind_exe_dynsyms(TCCState *s1)
{
    for_each_elem(symtab_section, 1, sym, ElfW(Sym)) {
        if (sym->st_shndx == SHN_UNDEF) {
            name = ...;
            sym_index = find_elf_sym(s1->dynsymtab_section, name);  /* 在动态符号里找 */
            if (sym_index) {
                esym = ...;
                type = ELFW(ST_TYPE)(esym->st_info);
                if (type == STT_FUNC || type == STT_GNU_IFUNC) {
                    /* 函数：走 PLT */
                } else if (type == STT_OBJECT) {
                    /* 数据：生成 COPY 重定位（把库里的数据拷到本程序 .bss） */
                }
            }
        }
    }
}
```

**函数用 PLT（延迟绑定），数据用 COPY 重定位**——这是 ELF 动态链接的标准做法。

## 【一个"公共符号"的完整故事】

```
a.c:  int x;      →  a.o 里 x 是 SHN_COMMON, size=4, align=4
b.c:  int x;      →  b.o 里 x 是 SHN_COMMON, size=4, align=4
main.c: x = 1;    →  引用 x

tcc a.o b.o main.c -o prog
  tcc_load_object_file(a.o)  → x 进符号表（common）
  tcc_load_object_file(b.o)  → x 已存在，set_elf_sym 合并（都 common，保留）
  elf_output_file:
    resolve_common_syms      → 在 .bss 分配 4 字节，x 变 .bss 符号
    final_sections_reloc     → main 里对 x 的引用填上地址
```

## 【动手小实验】

1. `echo 'int x;' > a.c; echo 'int x;' > b.c; echo 'int x; int main(){return x;}' > c.c`
   `tcc c.c a.c b.c -o p && ./p; echo $?`（应输出 0，不报重复定义）
2. 改成 `int x=1; int x=2;` 两处都有初值 → 报 `defined twice`。
3. 用 `__attribute__((weak)) int w;` 看弱符号行为。
4. `nm -C` 看 `_end`/`_etext`。

## 【通关暗号】

```bash
printf 'int x;\n' > /tmp/a.c; printf 'int x;\n' > /tmp/b.c
printf 'int x; int main(void){x=5; return x;}\n' > /tmp/c.c
./tcc /tmp/c.c /tmp/a.c /tmp/b.c -o /tmp/p && /tmp/p; echo $?
# 期望：5（两个 tentative 定义合并成功）
```

## 【常见卡点】

- **`int x;`（无初值全局）是 common 符号**，最后统一分配。
- **`set_elf_sym` 实现符号优先级**（全局>弱，数据>common）。
- **未定义符号三种归宿**：`dlsym` / 动态重定位 / 报错。
- **函数用 PLT，数据用 COPY 重定位**。

# 06 · 宏定义：`#define K 8` 被存成了什么

> **本步输入**：预处理器刚才读到的 `#define K 8` 这一行的 token 流
> **本步输出**：`define_stack` 上一个新 `Sym`，它的 `d` 指向一串整数（宏本体）；
> `K` 的 `TokenSym.sym_define` 指向这个 `Sym`
>
> 对应源码：`src/core/tccpp.c:1714`（`preprocess` 里分发 `#define`）、
> `src/core/tccpp.c:1472-1558`（`parse_define` 主角）、
> `src/core/tccpp.c:1302-1329`（`define_push` / `define_undef` / `define_find`）、
> `src/core/tccgen.c:501`（`sym_push2`，造 `Sym` 的底层工具）。

---

## 第 0 站：谁把活派给 `parse_define`

第 02 篇说，行首的 `#` 会调 `preprocess()`。在 `preprocess`（`tccpp.c:1714`）里：

```c
/* src/core/tccpp.c:1729-1737 */
    next_nomacro();          /* 读 # 后面那个词 */
 redo:
    switch(tok) {
    case TOK_DEFINE:         /* 这个 token 就是 "define" 关键字 */
        pp_debug_tok = tok;
        next_nomacro();      /* 读宏名（下一个 token） */
        pp_debug_symv = tok;
        parse_define();      /* ★ 交给 parse_define */
        break;
```

所以 `#define` 的 `define` 本身是个关键字 token（编号在 `tcctok.h` 里，
在 `TOK_IDENT` 之后、`TOK_UIDENT` 之前）。**宏名是 `parse_define` 进来时才读的。**

## 第 1 站：`parse_define` 全解（`tccpp.c:1472`）

### 1a. 开头：确认宏名（`:1472-1490`）

```c
/* src/core/tccpp.c:1471-1490 */
ST_FUNC void parse_define(void)
{
    Sym *s, *first, **ps;
    int v, t, varg, is_vaargs, spc;
    int saved_parse_flags = parse_flags;

    v = tok;                          /* v = 宏名的 token 编号 */
    if (v < TOK_IDENT || v == TOK_DEFINED)
        tcc_error("invalid macro name '%s'", get_tok_str(tok, &tokc));

    first = NULL;                     /* 形参链的头 */
    t = MACRO_OBJ;                    /* 默认是"对象宏"（无参） */

    /* 为了正确解析，临时切到"非汇编 + 保留空格"模式 */
    parse_flags = ((parse_flags & ~PARSE_FLAG_ASM_FILE) | PARSE_FLAG_SPACES);

    /* 只有紧挨着宏名的 '(' 才算函数宏，所以用 next_nomacro_spc 看空格 */
    next_nomacro_spc();
    if (tok == '(') {                 /* ★ 是函数宏 */
```

- `v = tok`：宏名已经读好了（`preprocess` 里 `next_nomacro` 读的）。
- `t = MACRO_OBJ`：`MACRO_OBJ` 和 `MACRO_FUNC` 定义在 `tcc.h:540-541`，
  分别表示"对象宏"（`#define K 8`）和"函数宏"（`#define ADD(a,b) ...`）。
- **关键**：`#define F (x)` 和 `#define F(x) ...` 不同。
  前者 `F` 展开成 `(x)`，后者是带参宏。区分方法：
  **看 `F` 后面是不是"紧挨着"的 `(`**。所以要 `next_nomacro_spc`（保留空格），
  看看 `(` 和 `F` 之间有没有空格。

### 1b. 函数宏的形参表（`:1491-1521`）

```c
/* src/core/tccpp.c:1491-1521 */

            varg = tok;                   /* 参数名 */

            } else if (tok == TOK_DOTS && gnu_ext) {  /* 参数名... GNU 扩展 */
                is_vaargs = 1;
                next_nomacro();
            }
```

逐点：

- **每个形参也是一个 `Sym`**，但它的 `v` 是 `参数名编号 | SYM_FIELD`。
  `SYM_FIELD`（`tcc.h:523`）是个高位标志位，用来标记"这是字段/参数，不是普通符号"。
- **`is_vaargs`** 存进 `Sym.type.t`（`sym_push2` 的第 3 个参数）。
  所以一个 `...` 参数会被记成 `type.t = 1`。
- **`first` 是形参链的头，`s->next` 串起来**。后面展开时按这条链配对实参。
- `set_idnum('.', 0)`：解析参数表时临时禁止 `.` 当标识符字符，
  这样 `#define F(a.b) ...` 里的 `.` 不会被吞进参数名。**用完立刻还原，很谨慎。**

### 1c. 宏本体（`:1523-1548`）

```c
/* src/core/tccpp.c:1523-1548 */
    tokstr_buf.len = 0;               /* 用全局缓冲 tokstr_buf 存本体 */
    spc = 2;                          /* spc：空格状态机（见下） */
    parse_flags |= PARSE_FLAG_ACCEPT_STRAYS | PARSE_FLAG_SPACES | PARSE_FLAG_LINEFEED;
    /* 注释：本体按文件模式解析标识符，但 '#' 要保留成 '#'，不能当行注释 */
    while (tok != TOK_LINEFEED && tok != TOK_EOF) {
        /* 去掉 ## 周围的空格、去掉 # 之后的空格 */
        if (TOK_TWOSHARPS == tok) {
            if (2 == spc)
                goto bad_twosharp;    /* ## 出现在开头：非法 */
            if (1 == spc)
                --tokstr_buf.len;     /* 去掉 ## 前面的那个空格 */
            spc = 3;
            tok = TOK_PPJOIN;         /* '##' 变成内部 token TOK_PPJOIN */
        } else if ('#' == tok) {
            spc = 4;                  /* '#' 之后不要空格 */
        } else if (check_space(tok, &spc)) {
            goto skip;                /* 空格：合并处理，别重复加 */
        }
        tok_str_add2(&tokstr_buf, tok, &tokc);   /* ★ 把 token 加进本体 */
    skip:
        next_nomacro_spc();
    }

    parse_flags = saved_parse_flags;  /* 恢复原来的模式 */
    if (spc == 1)
        --tokstr_buf.len;             /* 去掉末尾空格 */
    tok_str_add(&tokstr_buf, 0);      /* ★ 以 0 结尾 */
    if (3 == spc)
bad_twosharp:
        tcc_error("'##' cannot appear at either end of macro");
    define_push(v, t, tok_str_dup(&tokstr_buf), first);   /* ★ 登记 */
}
```

这是本步骤最需要慢慢看的地方：

1. **本体就是一串 token 的整数数组**（`TokenString`，第 09 篇细讲）。
   `tok_str_add2` 把每个 token（和它的值）追加进 `tokstr_buf.str`。
   `#define K 8` 的本体就是两个整数：`[TOK_PPNUM, <指向"8">, ..., 0]`。

2. **`spc` 是个"空格状态机"**：它记录"上一个 token 后面有没有空格"，
   取值含义大概是：
   - `spc = 0`：上一个不是空格；
   - `spc = 1`：刚加了一个空格；
   - `spc = 2`：句首；
   - `spc = 3`：刚处理完 `##`；
   - `spc = 4`：刚处理完 `#`。
   因为宏替换**空格是有意义的**（`#define X a+b` 和 `#define X a + b` 展开结果不同），
   但连续多个空格要合并成一个，还要特别处理 `#`/`##` 周围。
   **用状态机把"空格太多/太少/位置不对"全管住，是 `parse_define` 的精髓。**

3. **`tok_str_add(&tokstr_buf, 0)`**：末尾放一个 `0` 当**结束哨兵**。
   以后读宏本体时，读到 `0` 就知道结束了。

4. **`tok_str_dup`**：把 `tokstr_buf` 复制一份再交给 `define_push`。
   因为 `tokstr_buf` 是全局复用缓冲，不复制的话下一个 `#define` 会覆盖它。

## 第 2 站：登记进表 —— `define_push`（`tccpp.c:1302`）

```c
/* src/core/tccpp.c:1301-1314 */
ST_INLN void define_push(int v, int macro_type, int *str, Sym *first_arg)
{
    Sym *s, *o;

    o = define_find(v);                          /* 旧的定义（若重定义）*/
    s = sym_push2(&define_stack, v, macro_type, 0);   /* ① 往 define_stack 压一个 Sym */
    s->d = str;                                  /* ② 宏本体挂到 d */
    s->next = first_arg;                         /* ③ 形参链挂到 next */
    table_ident[v - TOK_IDENT]->sym_define = s;  /* ④ ★ 名字的抽屉指向它 */

    if (o && !macro_is_equal(o->d, s->d))
        tcc_warning("%s redefined", get_tok_str(v, NULL));
}
```

四行核心：

- **① `sym_push2(&define_stack, ...)`**：`define_stack`（`tcc.h:1281`）是宏符号栈。
  `sym_push2`（`tccgen.c:501`）做三件事：
  ```c
  s = sym_malloc();      /* 从内存池拿一个 Sym */
  memset(s, 0, sizeof *s);
  s->v = v;              /* 名字编号 */
  s->type.t = t;         /* MACRO_OBJ / MACRO_FUNC */
  s->c = c;
  s->prev = *ps;         /* 挂到栈顶 */
  *ps = s;               /* 栈顶变成它 */
  ```
- **② `s->d = str`**：`Sym.d`（`tcc.h:480`）是 union 里的一员，注释写着 "define token stream"。
  **宏本体就是这串整数。**
- **③ `s->next = first_arg`**：函数宏的形参链。
- **④ `sym_define` 抽屉**：第 03 篇说的 `TokenSym` 四个抽屉之一。
  这行之后，`define_find(K的编号)` 立刻能 O(1) 找到这个宏。

**重定义检查**：`macro_is_equal`（`tccpp.c:1281`）逐 token 比较两串本体，
不同才警告。所以 `#define K 8` 写两遍不报错，`#define K 9` 才警告。

## 第 3 站：查找与撤销（`tccpp.c:1317/1324`）

```c
/* src/core/tccpp.c:1316-1329 */
/* 撤销一个宏：把名字的 sym_define 抽屉清空 */
ST_FUNC void define_undef(Sym *s)
{
    int v = s->v;
    if (v >= TOK_IDENT && v < tok_ident)
        table_ident[v - TOK_IDENT]->sym_define = NULL;
}

/* 查宏：一行数组访问 */
ST_INLN Sym *define_find(int v)
{
    v -= TOK_IDENT;
    if ((unsigned)v >= (unsigned)(tok_ident - TOK_IDENT))
        return NULL;
    return table_ident[v]->sym_define;
}
```

这就是 `#undef K` 的实现：**把抽屉清空，`Sym` 本身不急着释放**。
好处是：如果同名 `Sym` 还在 `define_stack` 上，撤销只是"当前不可见"，
不会破坏别的引用。

`free_defines`（`tccpp.c:1333`）在文件编译结束时，把 `define_stack`
从这个文件开始时记下的位置一路弹回去——第 01 部的 `tcc_compile` 里调它。

## 第 4 站：为什么宏占用 `define_stack` 而不是别的栈

`tcc.h:1277-1281` 有三个符号栈：

```c
ST_DATA Sym *global_stack;   /* 全局变量/函数 */
ST_DATA Sym *local_stack;    /* 局部变量 */
ST_DATA Sym *define_stack;   /* 宏 */
```

**宏单独一个栈**，因为它和变量的作用域规则完全不同：
宏在文件里"从这里到文件末尾"有效，而变量有 `{}` 块作用域。
用同一个栈会互相干扰。分开最简单。

## 【把 `#define K 8` 走一遍】

1. `preprocess` 读到 `TOK_DEFINE` → `parse_define()`。
2. `v = K的编号`；`t = MACRO_OBJ`；`next_nomacro_spc()` 看到下一个是 `TOK_PPNUM`，不是 `(`，
   所以不是函数宏。
3. 本体循环：当前 token 是 `TOK_PPNUM`（文本 `"8"`），
   `check_space` 说前面有空格（`spc` 处理），加一个空格 token，再加 `TOK_PPNUM`。
4. 读到 `TOK_LINEFEED`，循环结束；补 `0` 哨兵。
5. `define_push(K的编号, MACRO_OBJ, 本体, NULL)`：
   - `define_stack` 顶部多一个 `Sym`；
   - `Sym.d` 指向 `[空格, TOK_PPNUM("8"), 0]`；
   - `table_ident[K编号]->sym_define = 这个 Sym`。

**从这一刻起，源文件里任何 `K` 被读到，`define_find` 一行就能找到它，
然后第 07 篇的宏展开上场。**

```bash

```

## 【常见卡点】

- **宏名和宏本体是谁读的**：名字由 `preprocess` 读出传进 `v`，本体由 `parse_define` 读。
- **`Sym` 的 `next` 和 `d` 别混**：函数宏 `next` 是形参链，`d` 是本体 token 串。
- **`tokstr_buf` 为什么要复制**：它是全局复用缓冲，不 `dup` 会被下一个宏覆盖。
- **`#undef` 为什么不真删**：只清抽屉，等文件结束时统一 `free_defines`。

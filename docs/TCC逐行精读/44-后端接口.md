# 44 · 后端接口：前端和后端怎么接头

> **一句话**：`tccgen.c`（前端）不直接写 x86 指令，而是调用一批"后端函数"：
> `load`/`store`/`gen_opi`/`gfunc_call`/`gfunc_prolog`… 这些函数由
> `src/targets/x86_64-gen.c`（或 i386/arm/arm64）实现。换后端就是换这个文件。
>
> 对应源码：`src/core/tcc.h`（后端函数声明、`TARGET_DEFS_ONLY` 机制）、
> `src/targets/x86_64-gen.c:23-105`（寄存器/类别定义）、`:111`（`reg_classes`）。

---

## 第 0 站：一个技巧——同一个文件用两次

打开 `x86_64-gen.c` 开头：

```c
/* src/targets/x86_64-gen.c:23-28（节选）*/
#ifdef TARGET_DEFS_ONLY
/* number of available registers */
#define NB_REGS         25
#define NB_ASM_REGS     16
#define CONFIG_TCC_ASM
...
```

```c
/* src/targets/x86_64-gen.c:105-111（节选）*/
#else /* ! TARGET_DEFS_ONLY */
#include "tcc.h"
#include <assert.h>

ST_DATA const int reg_classes[NB_REGS] = { ... };
```

**同一个 `.c` 文件被 `#include` 两次**：

1. 第一次定义 `TARGET_DEFS_ONLY`，只取**寄存器数量、类别、常量**（`NB_REGS`、
   `RC_INT`、`PTR_SIZE`、`LDOUBLE_SIZE`…）；
2. 第二次不定义，编译出**真正的函数体**（`load`/`store`/…）。

这样"配置常量"和"实现"写在同一个文件里，**换架构只需换这一个文件**。

> 这套 `#include` 在 `libtcc.c`（ONE_SOURCE 模式）里装配，
> 由 `tcc.h` 里的 `#ifdef TCC_TARGET_X86_64 ... #include "x86_64-gen.c"` 控制。

## 第 1 站：寄存器编号与类别（`x86_64-gen.c:26-101`）

```c
/* src/targets/x86_64-gen.c:25-54（节选）*/
#define NB_REGS         25
...
/* 一个寄存器可以属于多个类别，类别要从"通用"到"专用"排序 */
#define RC_INT     0x0001 /* 通用整数寄存器 */
#define RC_FLOAT   0x0002 /* 通用浮点寄存器 */
#define RC_RAX     0x0004
#define RC_RCX     0x0008
#define RC_RDX     0x0010
#define RC_ST0     0x0080 /* long double 专用 */
...
#define RC_IRET    RC_RAX /* 函数返回：整数 */
#define RC_LRET    RC_RDX /* 函数返回：第二个整数 */
#define RC_FRET    RC_XMM0 /* 函数返回：浮点 */
#define RC_QRET    RC_XMM1 /* 第二个浮点 */
```

寄存器**编号**（`enum`）：

```c
/* src/targets/x86_64-gen.c:57-82（节选）*/
enum {
    TREG_RAX = 0, TREG_RCX = 1, TREG_RDX = 2, TREG_RSP = 4,
    TREG_RSI = 6, TREG_RDI = 7,
    TREG_R8 = 8, TREG_R9 = 9, TREG_R10 = 10, TREG_R11 = 11,
    TREG_XMM0 = 16, ... TREG_XMM7 = 23,
    TREG_ST0 = 24,
    TREG_MEM = 0x20
};
```

**编号就是值栈 `SValue.r` 里存的那个数**（第 12 篇）。`TREG_MEM` 是个标志位，
`r | TREG_MEM` 表示"这个操作数在内存里"。

`reg_classes[]`（`:111`）告诉 `get_reg` 每个寄存器属于哪些类别：

```c
/* src/targets/x86_64-gen.c:111-140（节选）*/
ST_DATA const int reg_classes[NB_REGS] = {
    /* eax */ RC_INT | RC_RAX,
    /* ecx */ RC_INT | RC_RCX,
    ... 
    /* rax 之外的 r8-r11 只标了 RC_R8 等，没有 RC_INT */
    RC_R8, RC_R9, RC_R10, RC_R11,
    /* xmm0-xmm5 */ RC_FLOAT | RC_XMM0, ...
    /* xmm6/xmm7 故意不标 RC_FLOAT（Windows 上是 callee-saved） */
    RC_XMM6, RC_XMM7,
    /* st0 */ RC_ST0
};
```

注意 `RC_IRET = RC_RAX`：**"返回值用 rax"这条 ABI 规则，就是类别的一个别名。**

## 第 2 站：前端调用后端的接口清单

这些函数在 `tcc.h` 里声明，前端只管调用：

| 后端函数 | 前端在哪调 | 干什么 |
|---|---|---|
| `g(c)` / `o(c)` | 各处 | 发字节/指令 |
| `load(r, sv)` | `gv`、`save_reg`、`vstore` | 把值装进寄存器 |
| `store(r, v)` | `save_reg`、`vstore` | 把寄存器写回内存 |
| `gen_opi/opl/opf(op)` | `gen_opic`/`gen_opif` | 发 ALU/浮点指令 |
| `gen_cvt_ftoi/ftof/itof` | `gen_cast` | 类型转换指令 |
| `gtst(inv,t)` / `gjmp(t)` | `gvtst`/控制流 | 条件/无条件跳转 |
| `gfunc_call(nb)` | `unary` | 发函数调用 |
| `gfunc_prolog/epilog` | `gen_function` | 栈帧 |
| `gfunc_sret` / `gfunc_return` | 返回结构体 | ABI 返回约定 |
| `gen_vla_*` | VLA | 变长数组栈调整 |

**前端 = "我知道要做什么"，后端 = "我知道怎么用这台机器的指令做"。**
比如前端说 `load(r, sv)`，后端决定发 `mov`/`movsbl`/`movsd`…（第 46 篇）。

## 第 3 站：为什么这样分层能支持多架构

TCC 的后端文件：

```
src/targets/x86_64-gen.c   # x86-64
src/targets/i386-gen.c     # 32 位 x86
src/targets/arm-gen.c      # ARM
src/targets/arm64-gen.c    # ARM64
src/targets/c67-gen.c      # TI C67
src/targets/il-gen.c       # 一套"虚拟机"后端
```

它们**都实现同一批函数签名**（`load`/`store`/`gen_opi`/…）。
前端 `tccgen.c` 完全不知道自己在给什么 CPU 生成代码。

> **代价**：前端的 `SValue.r` 里存的是"后端寄存器编号"，所以前端也带一点机器相关代码
> （比如 `TREG_ST0` 的判断）。TCC 没有做到 100% 干净分层，但足够小。

## 【动手小实验】

1. 在 `reg_classes` 里数一数有多少个整数寄存器（带 `RC_INT`）——
   Windows 的 `REGN` 是 4，SysV 是 6。
2. 搜 `tcc_state->nosse`，看 `-mno-sse` 怎么让后端拒绝浮点寄存器。
3. 在 `libtcc.c`/`tcc.h` 里找 `#include "x86_64-gen.c"` 的位置，
   理解 `TARGET_DEFS_ONLY` 两次包含。

## 【通关暗号】

```bash
printf 'int main(void){return 0;}\n' > /tmp/z.c
./tcc -c /tmp/z.c -o /tmp/z.o && echo BUILD_OK
# 期望：BUILD_OK（说明后端被正确链接进编译器）
```

## 【常见卡点】

- **后端文件被 `#include` 两次**（配置 + 实现）。
- **`RC_IRET = RC_RAX`**：ABI 约定就是类别别名。
- **`SValue.r` 存的是后端寄存器编号**，所以前端带一点机器相关代码。
- **前端调接口，后端发指令**。

# 56 · 读目标文件与库：`.o` / `.a` / `.so`

> **一句话**：TCC 自己就是链接器，所以也要能读别人产出的 `.o`、静态库 `.a`、
> 动态库 `.so`，把它们的节合并进自己的 `Section` 体系。
>
> 对应源码：`src/core/libtcc.c:951`（`tcc_add_file_internal` 嗅探类型）、
> `src/core/tccelf.c:2283`（`tcc_load_object_file` 读 `.o`）、
> `:2636`（`tcc_load_archive` 读 `.a`）、`:2691`（`tcc_load_dll` 读 `.so`）、
> `:2262`（`tcc_object_type` 判断文件类型）。

---

## 第 0 站：先嗅探文件类型（`libtcc.c:951`）

`tcc_add_file` 怎么知道一个文件是 C 源码、`.o` 还是 `.a`？看开头几个字节：

```c
/* libtcc.c 里 tcc_add_file_internal（概念）*/
    /* 读文件头 */
    if (h[0] == 0x7f && h[1] == 'E' && h[2] == 'L' && h[3] == 'F') {
        /* ELF：.o 还是 .so？看 e_type */
        if (e_type == ET_REL)  → tcc_load_object_file   /* 可重定位目标 */
        else                   → tcc_load_dll           /* 动态库 */
    } else if (h 是 "!<arch>\n") {
        → tcc_load_archive                              /* 静态库 */
    } else {
        /* 纯文本：C 源码或 .s 汇编 */
    }
```

`tcc_object_type`（`tccelf.c:2262`）读 ELF 头判断类型。

```c
/* src/core/tccelf.c:2348-2420（节选）*/
    for(i = 1; i < ehdr.e_shnum; i++) {
        sh = &shdr[i];

```

**同名节（比如 `.text`）会合并**：`.o` 的 `.text` 拼到 TCC 的 `.text` 后面。
符号和重定位的下标都要重映射（用 `old_to_new_syms`/`sm_table`）。

> 注意：**TCC 只接受与自己机器类型相同的 `.o`**（`e_machine == EM_TCC_TARGET`）。
> 想链接 GCC 的 64 位 `.o`？可以（同为 `EM_X86_64`）。32 位混 64 位不行。

## 第 2 站：读静态库 `.a` —— `tcc_load_archive`（`:2636`）

`.a` 就是"一堆 `.o` 打包 + 一个符号索引"。TCC 的处理：

1. 检查开头是不是 `!<arch>\n`（ar 格式魔数）；
2. 读符号索引（`/` 或 `/SYM64/` 成员），知道**哪个符号在哪个成员里**；
3. 遍历成员，**只加载"被引用了的" `.o`**（`alacarte_link`）——这就是链接器
   "按需拉取"的行为；
4. 对每个需要的成员递归调 `tcc_load_object_file`。

**为什么只加载用到的？** 否则链接一个 `libc.a` 会把整个库拉进来。
`tcc_state->alacarte_link`（默认 1）控制这个行为。

TCC **不真正加载** `.so` 的代码（那是 `ld.so` 的活），只**读取它的导出符号表**，
让编译期的符号解析能找到 `printf` 等地址（对 `-run` 是运行时 `dlsym`；对可执行文件
是生成 `DT_NEEDED` 让系统加载器处理）。

## 第 4 站：链接的整体视角

```
tcc a.c b.o -lm

tcc_add_file(a.c)  → 编译成 .text/.data/... 进 TCCState
tcc_add_file(b.o)  → tcc_load_object_file：合并节、重定位、符号
tcc_add_file(-lm)  → tcc_load_archive/dll：读库符号
tcc_output_file    → 解符号、定地址、回填、写 ELF
```

**TCC 既是编译器，也是链接器。** 这两件事在 `tccelf.c` 里合在一起——
没有单独的 `ld` 阶段。

## 【动手小实验】

1. `echo 'int f(){return 1;}' > a.c; tcc -c a.c -o a.o`
2. `echo 'int f(); int main(){return f();}' > b.c; tcc b.c a.o -o b && ./b; echo $?`
3. 用 `ar rcs liba.a a.o` 打包，`tcc b.c -L. -la -o b2`。
4. 用 `tcc b.c -lm` 看是否链接数学库。

## 【通关暗号】

```bash
printf 'int f(void){return 6;}\n' > /tmp/a.c && ./tcc -c /tmp/a.c -o /tmp/a.o
printf 'int f(void); int main(void){return f();}\n' > /tmp/b.c && ./tcc /tmp/b.c /tmp/a.o -o /tmp/b && /tmp/b; echo $?
# 期望：6（多文件链接成功）
```

## 【常见卡点】

- **文件类型靠魔数嗅探**（ELF/ar/文本）。
- **`.o` 的节按名字合并进 TCC 的节**，符号/重定位下标要重映射。
- **静态库只加载被引用的成员**（`alacarte_link`）。
- **动态库只读符号表，不加载代码**。
- **TCC 编译 + 链接一体**。

# 07 · 宏展开：`K` 遇到 `#define` 的那一刻

> **本步输入**：一个标识符 token（比如 `K`）
> **本步输出**：它被替换成的一串 token（比如 `8`），而且这串 token **会被继续扫描**
> （可能又被替换，直到没有宏为止）
>
> 对应源码：`src/core/tccpp.c:3529`（`next()` 主入口）、
> `src/core/tccpp.c:1106-1127`（`begin_macro` / `end_macro`，"宏录音带"切换）、
> `src/core/tccpp.c:3282`（`macro_subst_tok` 单个宏展开）、
> `src/core/tccpp.c:3006`（`macro_arg_subst` 实参代入 + `#`/`##`）、
> `src/core/tccpp.c:3460`（`macro_subst` 反复扫描直到无宏）。

---

## 第 0 站：一切从 `next()` 开始（`tccpp.c:3529`）

编译器主循环调用的是 `next()`（不是 `next_nomacro`）。它长这样：

```c
/* src/core/tccpp.c:3528-3567 */
/* 返回下一个 token，并做宏替换 */
ST_FUNC void next(void)
{
 redo:                                       /* ★ 替换完还要回来重看 */
    if (parse_flags & PARSE_FLAG_SPACES)
        next_nomacro_spc();                  /* -E 模式：保留空格 */
    else
        next_nomacro();                      /* 普通模式：跳过空格 */

    if (macro_ptr) {                         /* ① 现在在读"宏录音带" */
        if (tok == TOK_NOSUBST || tok == TOK_PLCHLDR) {
            goto redo;                       /* 丢弃内部标记 */
        } else if (tok == 0) {
            end_macro();                     /* 录音带读完：回到上一层 */
            goto redo;
        }
    } else if (tok >= TOK_IDENT && (parse_flags & PARSE_FLAG_PREPROCESS)) {
        Sym *s;
        /* ② 从文件读到一个标识符：查查它是不是宏 */
        s = define_find(tok);
        if (s) {
            Sym *nested_list = NULL;
            tokstr_buf.len = 0;
            macro_subst_tok(&tokstr_buf, &nested_list, s);   /* ★ 展开 */
            tok_str_add(&tokstr_buf, 0);                     /* 加结束哨兵 */
            begin_macro(&tokstr_buf, 2);                     /* ★ 变成"当前录音带" */
            goto redo;                                       /* 回去读录音带 */
        }
    }
    /* ③ 把预处理 token 转成真正的 C token */
    if (tok == TOK_PPNUM) {
        if (parse_flags & PARSE_FLAG_TOK_NUM)
            parse_number((char *)tokc.str.data);   /* 第 04 篇 */
    } else if (tok == TOK_PPSTR) {
        if (parse_flags & PARSE_FLAG_TOK_STR)
            parse_string((char *)tokc.str.data, tokc.str.size - 1);  /* 第 05 篇 */
    }
}
```

**核心机制就一句话**：

> 读到标识符 `K` → 它是宏 → 把它的本体展开成一串 token，
> 把这串 token 变成"当前输入流"，然后 `goto redo` 继续读。
> 读到录音带末尾（`tok == 0`）就 `end_macro()` 回到原来的文件。

**这就是为什么宏可以嵌套、可以递归限制**：展开结果不是一次性算完的，
而是变成一个"临时输入源"，被 `next()` 逐 token 重新读、重新判断。

## 第 1 站：宏录音带 —— `begin_macro` / `end_macro`（`tccpp.c:1106`）

第 01 篇说过 `Macro_ptr` 指向一串整数（第 02 篇的 `next_nomacro_spc` 会读它）。
它是怎么被切来切去的？

```c
/* src/core/tccpp.c:1105-1127 */
ST_FUNC void begin_macro(TokenString *str, int alloc)
{
    str->alloc = alloc;          /* alloc: 1=自己要释放, 2=复用全局缓冲, 3=已结束 */
    str->prev = macro_stack;     /* 把当前录音带压栈 */
    str->prev_ptr = macro_ptr;
    str->save_line_num = file->line_num;
    macro_ptr = str->str;        /* ★ 切到新的录音带 */
    macro_stack = str;
}

ST_FUNC void end_macro(void)
{
    TokenString *str = macro_stack;
    macro_stack = str->prev;     /* 弹出 */
    macro_ptr = str->prev_ptr;   /* ★ 回到上一层的读位置 */
    file->line_num = str->save_line_num;
    if (str->alloc == 2) {
        str->alloc = 3;          /* 标记已结束（别重复释放） */
    } else {
        tok_str_free(str);
    }
}
```

- `macro_stack`（`tccpp.c:59`）是一条链，每个节点是一条"录音带"。
  **宏套宏时的层次就是这条链。**
- `begin_macro` = 入栈 + 把 `macro_ptr` 指向新录音带；
- `end_macro` = 出栈 + 把 `macro_ptr` 还原。
- **行号也要保存恢复**（`save_line_num`），否则宏展开把行号搞乱，报错会指错行。

> 你注意到没有：**宏展开和 `#include` 用的是同一种"换输入源"的思路**。
> include 换的是 `file`（书签链），宏换的是 `macro_ptr`（录音带链）。

`__LINE__`、`__FILE__`、`__DATE__`、`__TIME__`、`__COUNTER__` 这几个
**不是普通的 `#define`**，TCC 在展开时当场计算出结果，变成 `TOK_PPNUM` 或 `TOK_STR`
加进输出。

接着看普通宏的核心分支：

### 2a. 函数宏：收集实参（`:3334-3420`）

```c
            spc = 0;
            t = next_argstream(nested_list, &ws_str);
            if (t != '(') { ... 不是调用，还原 ... }
            args = NULL;
            sa = s->next;              /* sa 遍历形参链 */
            for(;;) {
                ...
                tok_str_new(&str);
                parlevel = spc = 0;
                /* 非 0 的 sa->type.t 表示这是 VA_ARGS */
                while ((parlevel > 0 ||
                        (tok != ')' &&
                         (tok != ',' || sa->type.t)))) {
                    if (tok == TOK_EOF || tok == 0) break;
                    if (tok == '(') parlevel++;       /* ★ 括号嵌套计数 */
                    else if (tok == ')') parlevel--;
                    if (tok == TOK_LINEFEED) tok = ' ';
                    if (!check_space(tok, &spc))
                        tok_str_add2(&str, tok, &tokc);   /* 收进这个实参 */
                    next_argstream(nested_list, NULL);
                }
                if (parlevel) expect(")");
                str.len -= spc;
                tok_str_add(&str, -1);     /* 实参结束标记 */
                tok_str_add(&str, 0);
                sa1 = sym_push2(&args, sa->v & ~SYM_FIELD, sa->type.t, 0);
                sa1->d = str.str;          /* ★ 实参本体挂在 Sym.d */
                sa = sa->next;
                if (tok == ')') break;
                if (tok != ',') expect(",");
            }
```

关键点：

- **`sa = s->next`**：第 06 篇里，函数宏的形参链就挂在 `Sym.next` 上。
  这里从链头开始，一个形参配一个实参。
- **`parlevel`**：括号嵌套深度。所以 `F((a,b), c)` 只按**最外层**逗号切分——
  内部 `(a,b)` 是一个实参。**没有这个计数器，`F((a,b),c)` 会被切错。**
- **每个实参也是一串 `TokenString`**，挂在实参 `Sym.d` 上。
- 结束时 `str.len -= spc` 去掉尾部空格，加 `-1` 和 `0` 两个结束标记。

### 2b. 实参代入 + `#`/`##` —— `macro_arg_subst`（`:3006`）

本体里的形参要换成实参。看三类 token 的处理：


- **`#param`（字符串化）**：把实参的 token 打印成文本，再包上引号，
  变成一个新的 `TOK_PPSTR`。这就是 `#define STR(x) #x` → `STR(hello)` → `"hello"`。
- **形参代入**：如果实参本身也是宏（比如 `F(G(1))`），会先把 `G(1)` 展开。
- **`TOK_PLCHLDR`（placeholder）**：实参为空时放一个占位符，
  防止 `F()` 展开成 `""` 时把后面的 token 错误粘在一起。

### 2c. `##` 拼接 —— `macro_twosharps` / `paste_tokens`（`:3124-3216`）

```c
/* src/core/tccpp.c:3124-3155（节选）*/
static int paste_tokens(int t1, CValue *v1, int t2, CValue *v2)
{
    CString cstr;
    cstr_new(&cstr);
    if (t1 != TOK_PLCHLDR)
        cstr_cat(&cstr, get_tok_str(t1, v1), -1);   /* 左边拼成文本 */
    n = cstr.size;
    if (t2 != TOK_PLCHLDR)
        cstr_cat(&cstr, get_tok_str(t2, v2), -1);   /* 右边拼成文本 */
    cstr_ccat(&cstr, '\0');

    tcc_open_bf(tcc_state, ":paste:", cstr.size);   /* ★ 造一个假文件 */
    memcpy(file->buffer, cstr.data, cstr.size);
    tok_flags = 0;
    for (;;) {
        next_nomacro1();                            /* ★ 重新词法扫描 */
        if (0 == *file->buf_ptr) break;
        if (is_space(tok)) continue;
        tcc_warning("pasting ... does not give a valid token");
        ret = 0;
        break;
    }
    tcc_close();
    ...
}
```

**`##` 的实现思路非常妙**：把左右两个 token 的**文本**拼起来，
塞进一个假的 `BufferedFile`（`tcc_open_bf`，文件名 `":paste:"`），
然后**重新跑一遍词法分析器**。

于是 `#define CAT(a,b) a##b` → `CAT(he, llo)` → 拼接文本 `"hello"` → 重新扫描 → 得到 `hello` 这个标识符 token。

> 为什么要重扫？因为 `a##b` 拼起来后**可能变成关键字或数字**，
> 只有词法分析器才知道它是什么。**"用词法器当字符串到 token 的转换器"**，
> 是 TCC 的巧劲。

`macro_twosharps`（`:3159`）在前面找到一个 `##`，然后把左右相邻 token
反复 `paste_tokens`，同时处理 `TOK_NOSUBST`（不替换标记）。

### 2d. 递归再扫描 —— `macro_subst`（`:3460`）

代入完、拼完，还要**把它当作新的输入再扫一遍**，因为实参或拼接结果里可能还有宏：

```c
/* src/core/tccpp.c:3460-3526（节选）*/
static void macro_subst(TokenString *tok_str, Sym **nested_list, const int *macro_str)
{
    Sym *s;
    int t, spc, nosubst;
    CValue cval;

    spc = nosubst = 0;
    while (1) {
        TOK_GET(&t, &macro_str, &cval);
        if (t <= 0) break;

        if (t >= TOK_IDENT && 0 == nosubst) {
            s = define_find(t);                 /* 是宏吗？ */
            if (s == NULL) goto no_subst;

            /* ★ 防止无限递归：如果一个宏此刻正在展开，就不要再展开它 */
            if (sym_find2(*nested_list, t)) {
                tok_str_add2(tok_str, TOK_NOSUBST, NULL);   /* 标记"别替换" */
                goto no_subst;
            }

            {
                TokenString str;
                str.str = (int*)macro_str;
                begin_macro(&str, 2);           /* 把它当成临时输入 */
                tok = t;
                macro_subst_tok(tok_str, nested_list, s);   /* ★ 递归 */
                if (str.alloc == 3) break;      /* 函数宏已经读完了实参 */
                macro_str = macro_ptr;
                end_macro();
            }
            ...
        } else {
            ... 原样加进输出 ...
        }
        if (t == TOK_DEFINED && pp_expr)
            nosubst = 2;
    }
}
```

**`nested_list` 是防死循环的关键**：它记录"当前正在展开哪些宏"。
如果一个宏已经在链上，就不再展开，而是标记 `TOK_NOSUBST`。

经典例子：

```c
#define A B
#define B A
int x = A;    /* 不能无限展开 */
```

`nested_list` 让 `A` 展开成 `B` 后，`B` 想再展开成 `A` 时发现 `A` 正在展开，就停下。
之后 `next()` 会丢弃 `TOK_NOSUBST`（`:3538`）。

## 第 3 站：把整条链串起来

一次宏展开的完整路径：

```
next() 读到标识符 K
  → define_find(K) 找到宏 Sym
  → macro_subst_tok(...)
      → 若是函数宏：next_argstream 收集实参
      → macro_arg_subst 代入实参 / 处理 # 和 ##
      → macro_twosharps 处理 ##
      → macro_subst 递归扫描（带 nested_list 防递归）
      → 结果写进 tokstr_buf
  → tok_str_add(0) 加哨兵
  → begin_macro(&tokstr_buf, 2) 把结果变成"当前录音带"
  → goto redo
next() 从录音带读 token
  → 读完（tok==0）→ end_macro() → 回到文件
```

---

## 【把 t.c 的 `2 * K` 展开一遍】

`t.c`：

```c
#define K 8
int y = 2 * K;
```

1. 词法读到 `K`（编号），`next()` 发现 `macro_ptr` 为空、`K >= TOK_IDENT`，
   `define_find(K)` 非空。
2. `macro_subst_tok`：`s->type.t == MACRO_OBJ`，不是函数宏；
   本体 `mstr = [空格, TOK_PPNUM("8"), 0]`。
3. `macro_twosharps` 找不到 `##`，返回 NULL，直接用 `mstr`。
4. `macro_subst` 扫描：空格原样加，`TOK_PPNUM("8")` 不是宏（`< TOK_IDENT`？不，
   `TOK_PPNUM` 是内部 token 编号，不在标识符区间），原样加，遇到 `0` 结束。
5. 结果写进 `tokstr_buf`，`begin_macro` 切过去。
6. `next()` 重读：拿到空格（跳过）、拿到 `TOK_PPNUM("8")`，
   因为开了 `PARSE_FLAG_TOK_NUM`，调 `parse_number("8")` → `tok = TOK_CINT, tokc.i = 8`。
7. 录音带读完，`end_macro` 回到文件，继续读 `;`。

于是语法分析器看到的等价源码是 `int y = 2 * 8;`，**`K` 从没进入过 C 语法层**。

## 【常见卡点】

- **展开结果是"新的输入流"，不是一次算完**：所以能嵌套、能递归限制。
- **`macro_ptr` 和 `file` 是两条独立的输入链**：宏用前者，include 用后者。
- **`nested_list` 防的是"同名宏递归"**，不是无限循环本身。
- **`#`/`##` 只在 `macro_arg_subst` 里处理**，普通 `#` token 不会走这里。

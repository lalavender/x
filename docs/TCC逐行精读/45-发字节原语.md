# 45 · 发字节原语：`g` / `o` / `gen_le32` / `orex` / `oad`

> **一句话**：所有机器码最终都是通过 `g(c)` 一个字节一个字节写进 `.text` 的。
> `o()` 发多字节指令，`gen_le32()` 发小端整数，`orex()` 加 REX 前缀，
> `oad()` 发"指令+4字节数据"。
>
> 对应源码：`src/targets/x86_64-gen.c:146`（`g`）、`:158`（`o`）、
> `:166/172/180`（`gen_le16/32/64`）、`:192`（`orex`）、`:228`（`oad`）、
> `:204`（`gsym_addr`）、`:326`（`gen_modrm`）。

---

## 第 0 站：最底层 —— `g`（`x86_64-gen.c:146`）

```c
/* src/targets/x86_64-gen.c:145-156 */
/* XXX: make it faster ? */
ST_FUNC void g(int c)
{
    int ind1;
    if (nocode_wanted)
        return;                          /* ★ 禁止生成代码时直接忽略 */
    ind1 = ind + 1;
    if (ind1 > cur_text_section->data_allocated)
        section_realloc(cur_text_section, ind1);   /* 段不够就长个 */
    cur_text_section->data[ind] = c;     /* 写一个字节 */
    ind = ind1;                          /* 位置前进 */
}
```

**所有机器码的最终出口就是这一行 `cur_text_section->data[ind] = c;`。**
`ind` 是当前 `.text` 偏移（全局变量）。

`nocode_wanted` 检查很重要：`sizeof` 里的表达式、`#if 0` 的代码、
`return` 之后不可达的代码都会调用生成函数，但**不该真的写字节**。

## 第 1 站：发多字节 —— `o`（`:158`）

```c
/* src/targets/x86_64-gen.c:158-164 */
ST_FUNC void o(unsigned int c)
{
    while (c) {
        g(c);           /* 发最低字节 */
        c = c >> 8;     /* 右移 */
    }
}
```

x86 指令是**小端**的：`o(0x89e5)` 会先发 `0xe5` 再发 `0x89`。
所以写代码时是**反着读**的：`o(0x48)` 是 Rex.W，`o(0x89)` 是 mov，
`o(0xe5)` 是 modrm。实践中用"指令字节从低到高"的写法。

> 注意 `o(0)` 什么都不发——因为 `while(c)` 直接结束。用来偷懒发"空"。

## 第 2 站：发小端整数 —— `gen_le16/32/64`（`:166-190`）

```c
/* src/targets/x86_64-gen.c:172-178 */
ST_FUNC void gen_le32(int c)
{
    g(c);           /* 低 8 位 */
    g(c >> 8);
    g(c >> 16);
    g(c >> 24);
}
```

```c
/* src/targets/x86_64-gen.c:180-190 */
ST_FUNC void gen_le64(int64_t c)
{
    g(c); g(c >> 8); g(c >> 16); g(c >> 24);
    g(c >> 32); g(c >> 40); g(c >> 48); g(c >> 56);
}
```

`gen_le32` 用于立即数、相对位移、地址；`gen_le64` 用于 64 位立即数。

**与 `read32le`/`write32le` 配套**（在 `tcc.h` 或别处）：
`gsym_addr` 回填时用它们读写那 4 字节。

---

## 第 3 站：REX 前缀 —— `orex`（`:192`）

x86-64 的 REX 前缀用于访问 `r8-r15` 和使用 64 位宽度：

```c
/* src/targets/x86_64-gen.c:192-201 */
static void orex(int ll, int r, int r2, int b)
{
    if ((r & VT_VALMASK) >= VT_CONST)
        r = 0;                          /* 非寄存器参数当 0 处理 */
    if ((r2 & VT_VALMASK) >= VT_CONST)
        r2 = 0;
    if (ll || REX_BASE(r) || REX_BASE(r2))
        o(0x40 | REX_BASE(r) | (REX_BASE(r2) << 2) | (ll << 3));
    o(b);                               /* 发真正的操作码 */
}
```

REX 字节格式：`0100 WRXB`
- `W`（bit3，`ll`）：是否 64 位操作数；
- `R`（bit2，`REX_BASE(r2)`）；
- `B`（bit0，`REX_BASE(r)`）。

`REX_BASE(reg)`（`:84`）就是 `(reg >> 3) & 1`——即"是不是 `r8`~`r15`/`xmm8+`"。

**什么时候需要 REX？** 用 64 位、或者用到 `r8+` 寄存器。否则省略（省 1 字节）。
`orex` 自动判断。

## 第 4 站：指令 + 4 字节数据 —— `oad`（`:228`）

```c
/* src/targets/x86_64-gen.c:227-240 */
/* instruction + 4 bytes data. Return the address of the data */
static int oad(int c, int s)
{
    int t;
    if (nocode_wanted)
        return s;
    o(c);              /* 发指令（1 字节） */
    t = ind;           /* ★ 记住 4 字节数据的地址 */
    gen_le32(s);       /* 发 4 字节（暂时填 s） */
    return t;          /* 返回数据字段地址 */
}

/* generate jmp to a label */
#define gjmp2(instr,lbl) oad(instr,lbl)
```

**它是跳转回填机制的基础**（第 27 篇）：`gjmp(t)` 就是 `oad(0xe9, t)`，
返回值是"位移字段的地址"，充当链表节点。

## 第 5 站：回填 —— `gsym_addr` / `gsym`（`:204`）

```c
/* src/targets/x86_64-gen.c:203-217 */
ST_FUNC void gsym_addr(int t, int a)
{
    while (t) {
        unsigned char *ptr = cur_text_section->data + t;
        uint32_t n = read32le(ptr);     /* 读出链表的"下一个节点" */
        write32le(ptr, a - t - 4);      /* ★ 回填相对位移 */
        t = n;
    }
}

void gsym(int t)
{
    gsym_addr(t, ind);                  /* 回填到当前位置 */
}
```

第 27 篇详细讲过。这里只强调：**它操作的是 `.text` 字节，不是数据结构**。
链表就串在指令的位移字段里。

## 第 6 站：生成内存操作数 —— `gen_modrm`（`:286`）

x86 指令的内存操作数用 ModRM 字节编码。`gen_modrm` 根据"基址寄存器 + 偏移"生成它：

```c
/* src/targets/x86_64-gen.c:286-329（节选）*/
static void gen_modrm_impl(int op_reg, int r, Sym *sym, int c, int is_got)
{
    op_reg = REG_VALUE(op_reg) << 3;
    if ((r & VT_VALMASK) == VT_CONST) {
        /* 常量地址 */
        if (!(r & VT_SYM)) {
            o(0x04 | op_reg); oad(0x25, c);      /* 绝对地址 [disp32] */
        } else {
            o(0x05 | op_reg);                     /* RIP 相对 */
            if (is_got) gen_gotpcrel(r, sym, c);
            else        gen_addrpc32(r, sym, c);
        }
    } else if ((r & VT_VALMASK) == VT_LOCAL) {
        /* 栈帧：用 rbp 当基址 */
        if (c == (char)c) {                      /* 偏移能用 1 字节 */
            o(0x45 | op_reg); g(c);
        } else {
            oad(0x85 | op_reg, c);               /* disp32 */
        }
    } else if ((r & VT_VALMASK) >= TREG_MEM) {
        /* 通过寄存器间接 + 偏移 */
        if (c) { g(0x80 | op_reg | REG_VALUE(r)); gen_le32(c); }
        else   { g(0x00 | op_reg | REG_VALUE(r)); }
    } else {
        g(0x00 | op_reg | REG_VALUE(r));         /* [reg] */
    }
}
```

四种情况：**全局常量地址**、**栈帧（`rbp` 相对）**、**寄存器间接+偏移**、**纯寄存器**。
`gen_modrm64`（`:333`）是加 REX 和 GOT 处理的版本。

## 【看一条 `mov eax, [rbp-4]` 的字节流】

对应源码可能是 `load` 里的 `gen_modrm(0x8b, VT_LOCAL, ...)`：

| 步骤 | 字节 | 含义 |
|---|---|---|
| `orex(0, ...)` | 无（32 位、低寄存器） | 不需 REX |
| `o(0x8b)` | `8B` | mov r32, r/m32 |
| `gen_modrm(0, VT_LOCAL, NULL, -4)` | `45 FC` | `[rbp-4]` |

合起来：`8B 45 FC` = `mov eax, [rbp-4]`。

## 【常见卡点】

- **`g` 是唯一真正写字节的地方**，`nocode_wanted` 时直接返回。
- **`o` 是小端**：`o(0x89e5)` 先发 `e5`。
- **`orex` 按需加 REX 前缀**（64 位或高寄存器）。
- **`oad` 返回位移字段地址**，是跳转链的节点。
- **`gsym_addr` 遍历链表回填相对位移**。

# 48 · 跳转与测试深入：`gtst` 与条件码算术

> **一句话**：`gtst(inv, t)` 把栈顶的 `VT_CMP`（标志位）变成一条条件跳转。
> 妙处在于它**用比较类型直接算出 jcc 操作码**，并用一个异或处理"反转测试"。
> `VT_JMP`（跳转链）则在链层面做合并。
>
> 对应源码：`src/targets/x86_64-gen.c:1688`（`gtst`）、`:1661`（`gtst_addr`）、
> `:1648`（`gjmp_addr`）、`:203`（`gsym_addr`）。前端入口：`gvtst`（`tccgen.c:1605`）。

---

## 第 0 站：`VT_CMP` 里存了什么

第 47 篇说，比较后栈顶变成：

```c
    vtop->r = VT_CMP;
    vtop->c.i = op;          /* 比较类型（TOK_EQ/TOK_LT/…），或浮点加 0x100 */
```

所以"这个比较是什么关系"存在 `c.i` 里。`gtst` 要把它翻译成一条 `jcc`。

## 第 1 站：`gtst`（`x86_64-gen.c:1688`）

```c
/* src/targets/x86_64-gen.c:1687-1734 */
ST_FUNC int gtst(int inv, int t)
{
    int v = vtop->r & VT_VALMASK;

    if (nocode_wanted) {
        ;                                    /* 不生成代码 */
    } else if (v == VT_CMP) {
        /* 快路径：标志位已设好，直接条件跳转 */
        if (vtop->c.i & 0x100) {             /* 浮点比较 */
            /* 处理 NaN：parity flag 置位表示无序 */
            vtop->c.i &= ~0x100;
            if (inv == (vtop->c.i == TOK_NE))
                o(0x067a);                   /* jp +6 */
            else {
                g(0x0f);
                t = gjmp2(0x8a, t);          /* jp t */
            }
        }
        g(0x0f);
        t = gjmp2((vtop->c.i - 16) ^ inv, t);   /* ★ 核心一行 */
    } else if (v == VT_JMP || v == VT_JMPI) {
        /* && / || 遗留的跳转链：合并到 t */
        if ((v & 1) == inv) {
            /* 方向相同：把 vtop 的链接到 t 后面 */
            uint32_t n1, n = vtop->c.i;
            if (n) {
                while ((n1 = read32le(cur_text_section->data + n)))
                    n = n1;
                write32le(cur_text_section->data + n, t);
                t = vtop->c.i;
            }
        } else {
            /* 方向相反：新发一条跳转，回填 vtop 的链 */
            t = gjmp(t);
            gsym(vtop->c.i);
        }
    }
    vtop--;                                  /* 弹出条件便利贴 */
    return t;
}
```

### 1a. 那行核心：`(vtop->c.i - 16) ^ inv`

为什么减 16 就得到 jcc 操作码？因为 token 编号和 x86 条件码是**精心对齐**的。

看 `tcc.h` 里比较 token 的编号（`TOK_ULT` 等），以及 x86 jcc 的条件码：

x86 条件跳转第二位（0x70~0x7f）的低 4 位就是条件码：

| 条件码 | 含义 | jcc |
|---|---|---|
| 0x0 | overflow | jo |
| 0x4 | equal/zero | je |
| 0x5 | not equal | jne |
| 0xC | less (signed) | jl |
| 0xF | greater (signed) | jg |
| ...

TCC 把比较 token 的编号安排成"**减去 16 就等于 x86 条件码**"。
于是 `(c.i - 16)` 直接是 jcc 的低 nibble。

**反转测试**：`^ inv` 把操作码翻最低位。因为 x86 jcc 的低位正好是"取反"：
`jl`(0xC)↔`jge`(0xD)、`je`(0x4)↔`jne`(0x5)……

> **一次减法 + 一次异或，替代一整个 switch 表。** 这是 TCC"用编号设计省代码"的又一绝招。

### 1b. 浮点比较的 NaN 处理（`:1696`）

浮点 `comisd` 后有四个标志位，其中 `PF`（parity）表示"无序"（NaN）。
TCC 用 `jp`（parity 跳转）单独处理：

```c
            if (inv == (vtop->c.i == TOK_NE))
                o(0x067a);        /* jp +6：跳过下一条 */
            else {
                g(0x0f);
                t = gjmp2(0x8a, t);   /* jp t：无序就跳到"假" */
            }
```

**`NaN` 参与比较时，除了 `!=` 都是假**——这段代码实现了这条 IEEE 规则。

### 1c. `VT_JMP` 链合并（`:1716`）

`&&`/`||` 留下的跳转链（第 28 篇）在这里被"接到"当前链上：

- **方向相同** `(v&1)==inv`：直接把 `vtop` 链（存在 `c.i`）的尾巴指向 `t`，
  合并成一条长链，O(链长) 但只改一个指针。
- **方向相反**：生成一条新跳转，把 `vtop` 链回填到它，再接 `t`。

**链的合并是"改指针"，不需要重新遍历所有节点。**

## 第 2 站：已知地址的跳转 —— `gjmp_addr` / `gtst_addr`

```c
/* src/targets/x86_64-gen.c:1648-1659 */
void gjmp_addr(int a)                 /* 跳到已知地址 a */
{
    int r;
    r = a - ind - 2;
    if (r == (char)r) {               /* 位移能用 1 字节？ */
        g(0xeb);                       /* jmp rel8（短跳转，2 字节） */
        g(r);
    } else {
        oad(0xe9, a - ind - 5);        /* jmp rel32（长跳转，5 字节） */
    }
}
```

**自动选短/长跳转**：循环回跳、小 if 分支常用短跳转，省 3 字节。

```c
/* src/targets/x86_64-gen.c:1661-1685 */
ST_FUNC void gtst_addr(int inv, int a)     /* 条件跳转到已知地址 */
{
    int v = vtop->r & VT_VALMASK;
    if (v == VT_CMP) {
        inv ^= (vtop--)->c.i;              /* 同样用异或算操作码 */
        a -= ind + 2;
        if (a == (char)a) {
            g(inv - 32);                    /* 短条件跳转 */
            g(a);
        } else {
            g(0x0f);
            oad(inv - 16, a - 4);           /* 长条件跳转 */
        }
    } else if ((v & ~1) == VT_JMP) {
        ... 链处理 ...
    }
}
```

`inv - 32`：短 jcc 是 `0x70 + 条件码`，而 `inv` 是 `0x80 + ...`，所以减 32 调整。

## 第 3 站：前端 `gvtst` 回顾（`tccgen.c:1605`）

```c
/* src/core/tccgen.c:1605-1620（重贴）*/
ST_FUNC int gvtst(int inv, int t)
{
    int v = vtop->r & VT_VALMASK;
    if (v != VT_CMP && v != VT_JMP && v != VT_JMPI) {
        vpushi(0);
        gen_op(TOK_NE);     /* 任意值 → 和 0 比较 → VT_CMP */
    }
    if (vtop 是常量) {
        if ((vtop->c.i != 0) != inv) t = gjmp(t);
        vtop--;
        return t;
    }
    return gtst(inv, t);    /* 交给后端 */
}
```

**前端负责"把值变成可测试的东西"，后端负责"发跳转指令"。**
`VT_CMP`/`VT_JMP` 是两者之间的接口。

## 【把 `if (a < b)` 走一遍】

| 步骤 | 说明 |
|---|---|
| 1 | `gexpr` 求 `a < b`：`gen_opi(TOK_LT)` 发 `cmp`，栈顶变 `VT_CMP, c.i=TOK_LT` |
| 2 | `if` 调 `gvtst(1, 0)`（条件假就跳到 else） |
| 3 | 前端发现已是 `VT_CMP`，直接 `gtst(1, 0)` |
| 4 | 后端：`(TOK_LT - 16) ^ 1` = 算出 `jge` 的操作码 |
| 5 | 发 `jge ???`，返回链头 |

**没有 0/1 中间值，没有额外比较。**

## 【动手小实验】

1. 写 `if (a<b) x=1;` 和 `if (a>b) x=1;`，反汇编对比 jcc（应该是 `jge` vs `jle`）。
2. 写 `if (a==0) x=1;`，看 `test`/`je`。
3. 写 `if (a<1.0) x=1;`，看 `comisd` + `ja`/`jp` 组合。

## 【常见卡点】

- **比较 token 编号 - 16 = x86 条件码**，`^ inv` 反转。
- **浮点比较用 `jp` 处理 NaN**。
- **`VT_JMP` 链合并只改指针**。
- **`gjmp_addr` 自动选短/长跳转**。
- **前端把值变 `VT_CMP`，后端发 jcc**。

# 02 · 先认六件工具：TCC 的零件盒

> 对应源码：`src/core/tcc.h`（1660 行，TCC 的数据模型全在这一个文件里）。
> 目标：t.c 里的每个名字（`K`、`add`、`x`）在 TCC 内存里**是哪个结构体**，你都能指出来。

开读前先记住一条铁律：**TCC 不造语法树**。它只有下面六样工具。

---

## 工具① TokenSym：每个词只住一次（tcc.h:381）

```c
typedef struct TokenSym {
    struct TokenSym *hash_next;
    struct Sym *sym_define;      /* 该名字当前可见的 #define */
    struct Sym *sym_label;       /* 该名字当前可见的标号 */
    struct Sym *sym_struct;      /* 该名字当前可见的 struct/union/enum tag */
    struct Sym *sym_identifier;  /* 该名字当前可见的标识符 */
    int tok;                     /* token 编号 */
    int len;
    char str[1];
} TokenSym;
```

C 允许 `int int_var;` 和 `#define int_var 5` 和 `goto int_var;` 和
`struct int_var {}` **同时存在**——一个名字，四个世界。
所以这个格子上挂了**四个抽屉**（`sym_define/label/struct/identifier`），
各放各的 `Sym`，永不打架。
t.c 里 `add`、`main`、`x`、`y`、`a`、`b` 各对应一个 TokenSym（哈希去重，
同一个名字在文件里出现 100 次也只有 1 个 TokenSym，编号见下一篇）。
关键字不是词：`int`/`return` 在 `tcctok.h` 的表里**天生自带固定编号**。

## 工具② CType：一个 int 装下所有类型（tcc.h:405 + :852）

```c
typedef struct CType {
    int t;            /* 一堆 bit 拼出来的类型 */
    struct Sym *ref;  /* 细节：结构体成员链 / 函数形参链 住在这 */
} CType;
```

`t` 里各位的含义（`tcc.h:853-880`）：

| bit 段 | 名字 | 含义 |
|---|---|---|
| 低 4 位 | `VT_BTYPE` | 基本类型：`VT_VOID=0, VT_BYTE=1, VT_SHORT=2, VT_INT=3, VT_LLONG=4, VT_PTR=5, VT_FUNC=6, VT_STRUCT=7, VT_FLOAT=8, VT_DOUBLE=9, VT_LDOUBLE=10, VT_BOOL=11` |
| `0x0010` | `VT_UNSIGNED` | unsigned |
| `0x0040` | `VT_ARRAY` | 数组（也是指针，见 :871 注释 "also has VT_PTR"）|
| `0x0080` | `VT_BITFIELD` | 位域（高 16 位编码起始/宽度）|
| `0x0100/0x0200/0x0400` | `VT_CONSTANT/VOLATILE/VLA` | const / volatile / 变长数组 |

**练习心算**：`int *` = `VT_PTR|VT_INT` = `0x5|0x3` = `0x7`（int 在 BTYPE 是 3、
指针在 BTYPE 是 5，注意 BTYPE 是"当前最外层是什么"，指针指向 int 靠 `ref`/位组合表达）。
`unsigned int` = `VT_INT|VT_UNSIGNED` = `0x13`。看不懂没关系——
03 篇的 `tok_alloc` 和 04 篇的 `gen_op` 会反复用到它，混个脸熟即可。

## 工具③ SValue：值栈上的一张"便利贴"（tcc.h:424）

```c
typedef struct SValue {
    CType type;           /* 类型 */
    unsigned short r;     /* 我现在住在哪：寄存器号? 还是 VT_CONST/VT_LOCAL/VT_CMP/VT_JMP */
    unsigned short r2;    /* 64 位值住两个寄存器时，第二个是哪个 */
    CValue c;             /* 常量值（r 含 VT_CONST 时）或栈帧偏移（r 含 VT_LOCAL 时）*/
    struct Sym *sym;      /* 如果这个值牵扯一个还没定地址的符号，欠条贴在这 */
} SValue;
```

`r` 的低 6 位是"住址"（`tcc.h:831-838`）：

| 值 | 名字 | 人话 |
|---|---|---|
| 0..0x2f | 寄存器号 | "我在 rax/rbx…身上" |
| 0x30 | `VT_CONST` | "我是个常量，值在 c 里" |
| 0x32 | `VT_LOCAL` | "我在栈帧的 c 偏移处（通常是 rbp 往前 c 字节）" |
| 0x33 | `VT_CMP` | "我的值在 **CPU 标志位**里（刚比较完，0/1 还没落地）" |
| 0x34/0x35 | `VT_JMP`/`VT_JMPI` | "我是一段跳转链，真假各一（&& 和 || 专用）" |

再加三个标志位（`tcc.h:839-846`）：`VT_LVAL`（这张便利贴代表"一个位置"，
读它要取货、写它要放货）、`VT_SYM`（贴了欠条 `sym`）、`VT_MUSTCAST`（char/short
塞在 32 位寄存器里，读之前要裁）。
**这一张便利贴就是 TCC 的全部"中间表示"**。04 篇全程在它身上做文章。

## 工具④ Sym：一人分饰五角（tcc.h:465）

```c
typedef struct Sym {
    int v;                 /* 我的名字的 token 编号（哪个 TokenSym） */
    unsigned short r;      /* 我住在哪（含义随身份变：偏移/寄存器/…） */
    struct SymAttr a;      /* aligned/packed/weak/visibility/dllexport */
    union {
        struct { int c;    /* 全局变量: ELF符号索引; 局部变量: 栈偏移; 标号: 跳转链 */
                 union { int sym_scope; int jnext; struct FuncAttr f; int auxtype; }; };
        long long enum_val;/* 枚举常量值 */
        int *d;            /* 宏：我的本体是一盘录音带（int token 数组）*/
    };
    CType type;            /* 我的类型（函数/变量/成员都有） */
    struct Sym *next;      /* 结构体成员链 / 函数形参链：下一个 */
    struct Sym *prev;      /* 作用域栈：上一个符号 */
    struct Sym *prev_tok;  /* 同名链：上一个"也叫这个名字"的符号 */
} Sym;
```

注意三根链：`prev` 是"作用域时间线"（进 `{` 记起点、出 `}` 沿它弹回），
`next` 是"结构体成员/函数参数"，`prev_tok` 是"同名前任"——
05 篇讲 `sym_pop` 时你会看到这三根链怎么配合，做到**进出作用域 O(1)、不查表**。

`t.c` 里：`K` 是 `define_stack` 上一个 `Sym`（`d` 指向录音带 `{TOK_PPNUM(8)}`）；
`add`/`main` 是 `global_stack` 上 `type.t=VT_FUNC` 的 Sym；
`a/b/x/y` 是 `local_stack` 上 `r=VT_LOCAL`、`c=栈偏移` 的 Sym。

## 工具⑤ Section：一切输出皆纸带（tcc.h:492）

```c
typedef struct Section {
    unsigned long data_offset;          /* 写到哪了 */
    unsigned char *data;                /* 会自己长大的字节数组 */
    unsigned long data_allocated;
    int sh_name, sh_num, sh_type, sh_flags, sh_entsize;  /* ELF 语义 */
    addr_t sh_addr;                     /* 最终地址（链接期才填） */
    struct Section *link;               /* 配套：symtab 的 link 是 strtab */
    struct Section *reloc;              /* 我欠的欠条放哪：.text 的 reloc 是 .rel.text */
    struct Section *hash;               /* 符号哈希表 */
    char name[1];
} Section;
```

编译器的全部输出都落在这些纸带上：机器码→`.text`、`y=2*8` 的 16→`.data`、
未初始化全局→`.bss`、名字→`.strtab`、`add/main` 登记→`.symtab`、
欠条→`.rel.text`。**TCC 的编译 = 往纸带上写字节**，就这么朴素。

## 工具⑥ BufferedFile / TokenString：文件与"录音带"（tcc.h:554/575）

```c
typedef struct BufferedFile {
    uint8_t *buf_ptr, *buf_end;   /* 读到哪 / 还有多少 */
    struct BufferedFile *prev;    /* 头文件套头文件：上一个还在这根链上 */
    int line_num;
    char filename[1024];
    ...
} BufferedFile;

typedef struct TokenString {
    int *str;            /* ★ token 序列就是一串整数！ */
    int len, allocated_len;
    int last_line_num;
    struct TokenString *prev;   /* 宏录音带栈：上一个 */
    ...
} TokenString;
```

**TokenString 是 TCC 预处理器的心脏概念**：宏不是"一段文本"，
而是**一串整数 token**（`int *`）。`#define K 8` 之后，`K` 的 `Sym.d`
指向的就是 `{整数K的编号?, 8对应的TOK_PPNUM…, 0结束符}` 这样一串整数。
03 篇讲 `next()` 时你就知道"展开宏 = 切到另一串整数上继续读"这么简单。

## 【给 t.c 点名】

| t.c 里的东西 | 是什么工具 |
|---|---|
| `#define K 8` | define_stack 上的 Sym，`d` 是录音带；`K` 的 TokenSym.sym_define 指着它 |
| `add` | global_stack 上的 Sym，`type.t=VT_FUNC`，`ref` 挂着参数 `a,b` 两个 Sym |
| `x`/`y` | local_stack 上的 Sym，`r=VT_LOCAL`，`c=-8/-16`（各自栈偏移） |
| `2 * K` 算出的 16 | 一张 SValue：`r=VT_CONST, type=int, c.i=16` |
| `main` 的机器码 | 正在往 .text Section 追加的字节 |

# 03 · 词法器与预处理器：`#define K 8` 是怎么生效的

> 对应源码：`src/core/tccpp.c`（3903 行）。
> 目标：追完 `K` 从"七个字符"变成"8"的全部旅程，并看懂 `next()` 这台调度器。

---

## 第 0 站：每个词先领一个编号——tok_alloc（tccpp.c:448）

```c
ST_FUNC TokenSym *tok_alloc(const char *str, int len)
{
    TokenSym *ts, **pts;
    int i; unsigned int h;

    h = TOK_HASH_INIT;
    for(i=0;i<len;i++)
        h = TOK_HASH_FUNC(h, ((unsigned char *)str)[i]);  /* 字符串哈希 */
    h &= (TOK_HASH_SIZE - 1);                             /* 落到 16384 个桶之一 */

    pts = &hash_ident[h];
    for(;;) {
        ts = *pts;
        if (!ts) break;                                   /* 桶空了 → 要新建 */
        if (ts->len == len && !memcmp(ts->str, str, len))
            return ts;                                    /* 见过 → 直接复用 */
        pts = &(ts->hash_next);                           /* 冲突 → 顺链表找 */
    }
    return tok_alloc_new(pts, str, len);                  /* 新建并登记 */
}
```

关键词就在开机时被 `tok_alloc` 登记过（来自 `tcctok.h` 的 X-macro 表），
所以 `int` 的编号天生固定；而 `add`/`x` 这种标识符是运行时现场发号。
**同一个词永远同一个编号**——这就是 02 篇说的"驻留"。

## 第 2 站：`K` 登场——next() 的调度（tccpp.c:3529）

这是全书最该背的一段 39 行代码：

```c
ST_FUNC void next(void)
{
 redo:
    if (parse_flags & PARSE_FLAG_SPACES) next_nomacro_spc();
    else next_nomacro();               /* ★ 从底层拿一个原始 token */

    if (macro_ptr) {
        if (tok == TOK_NOSUBST || tok == TOK_PLCHLDR) {
            goto redo;                 /* 占位符，丢掉（防递归的哨兵） */
        } else if (tok == 0) {
            end_macro();               /* 录音带放完了，弹回上一层 */
            goto redo;
        }
    } else if (tok >= TOK_IDENT && (parse_flags & PARSE_FLAG_PREPROCESS)) {
        Sym *s;
        s = define_find(tok);          /* ★ 这个词是宏吗？ */
        if (s) {
            Sym *nested_list = NULL;
            tokstr_buf.len = 0;
            macro_subst_tok(&tokstr_buf, &nested_list, s);  /* 展开成录音带 */
            tok_str_add(&tokstr_buf, 0);
            begin_macro(&tokstr_buf, 2);    /* ★ 切到新录音带播放 */
            goto redo;
        }
    }
    /* TOK_PPNUM/PPSTR 在需要时再转成真正的数字/字符串 */
    if (tok == TOK_PPNUM) parse_number(...);
    else if (tok == TOK_PPSTR) parse_string(...);
}
```

**`macro_ptr` 就是"当前正在播放的录音带"**。普通模式时它为空，从文件读；
遇到宏就 `begin_macro` 把 `macro_ptr` 指到新录音带，然后 `goto redo` 从头再取一次 token
（这次就从录音带取了）。录音带结束的标志是整数 `0` → `end_macro()` 弹回。

于是 `2 * K` 被词法器读到 `K` 时：`define_find(K)` 命中 → 展开 `K` 的录音带
`{8(PPNUM)}` → 下一次 `next()` 拿到的就是 `8`。**文本替换在 TCC 这里，
等于"换一叠 token 继续读"。**

三个信息量极大的细节：
1. **`nested_list` 防递归**：正在展开的宏被记进这张链，展开产物里再遇到自己就插入

## 第 5 站：include 与缓存（本课只用一句话）

`preprocess()` 里 `TOK_INCLUDE` 分支调 `tccpp.c:1786` 起的搜索循环：绝对路径 →
**当前文件所在目录**（引号 include 才走）→ 用户 `-I` 路径 → 系统路径。
重点是 tccpp.c:1819-1824 那句注释："search in file's dir if \"header.h\""——
这就是为什么源码移进 `src/core/` 后、同目录 `#include "tcc.h"` 仍然能工作。
头文件防重复靠 `search_cached_include`（tccpp.c:1560）查一张"文件名+哨兵宏"缓存表。

## 【t.c 走一遍：`#define K 8` → `2*K`】

1. `preprocess()` 见 `#define` → `parse_define` 把 `{8}` 录进录音带，挂到 `K` 的 Sym.d；
2. 主流程读到 `2 * K`，`next()` 在 `define_find(K)` 命中 → `begin_macro` 切到录音带；
3. 下一次 `next()` 吐出的就是 token `8`；
4. `K` 的录音带放完（读到 0）→ `end_macro()` 弹回文件，继续读 `;`。

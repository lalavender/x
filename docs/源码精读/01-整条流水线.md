# 01 · 整条流水线：从一条命令到一个可执行文件

> 对应源码：`src/core/tcc.c`（371 行，程序入口）、`src/core/libtcc.c`（`tcc_compile`）。
> 目标：读完后你能画出 TCC 的"车站图"，知道 `t.c` 现在正停在哪一站。

## 第 0 步：一切从 main 开始（tcc.c）

`tcc.c` 这个文件只有 371 行。为什么这么小？看它开头：

```c
/* src/core/tcc.c:21-25 */
#include "tcc.h"
#if ONE_SOURCE
# include "libtcc.c"
#endif
#include "tcctools.c"
```

**第一行就暴露了 TCC 的架构**：`tcc.c` 不是独立的编译器——
它把 `libtcc.c`（整个编译器+链接器）直接 `#include` 了进来！
这叫 **ONE_SOURCE（单文件）模式**：把几十个 `.c` 拼成一个巨大的编译单元，
一次性丢给 C 编译器。好处是：生成的 `tcc` 二进制更小、编译 tcc 本身更快。
`ONE_SOURCE` 默认就是开着的（`tcc.h:301` 附近）。
所以：**读懂 tcc_compile（在 libtcc.c 里）就读读懂了 TCC 的中枢**。

往下翻到 `main`（tcc.c:246）：

```c
int main(int argc, char **argv)
{
  ...
redo:
  argc = argc0, argv = argv0;
  s = tcc_new();                       /* 造一个编译会话（后面到处传的状态机）*/
  opt = tcc_parse_args(s, &argc, &argv, 1);   /* 解析命令行 */
  ...
  set_environment(s);                  /* 读 C_INCLUDE_PATH / LIBRARY_PATH 环境变量 */
  if (s->output_type == 0)
    s->output_type = TCC_OUTPUT_EXE;   /* 默认产出可执行文件 */
  tcc_set_output_type(s, s->output_type);

  /* compile or add each files or library */
  for (first_file = NULL, ret = 0;;) {
    struct filespec *f = s->files[s->nb_files - n];
    ...
    if (tcc_add_file(s, f->name) < 0)   /* ★ 把每个输入文件"喂"进编译器 */
      ret = 1;
    ...
  }

  ...
  if (s->output_type == TCC_OUTPUT_MEMORY) {
      ret = tcc_run(s, argc, argv);    /* -run 模式：内存里直接执行 */
  } else {

        ret = 1;
  }

```

三个关键点：

1. **命令行解析**（`tcc_parse_args`）只收集"有哪些文件、要输出什么"，
   真正编译发生在后面那个循环——每个文件调一次 `tcc_add_file`。
2. 对 `tcc t.c -o t`，循环里只有 `t.c` 一个文件，`tcc_add_file(t.c)` 一次搞定全部编译。
3. 最后二选一：`tcc_run`（内存执行）或 `tcc_output_file`（写文件）。
   你命令里的 19 就是在 `tcc_output_file` 之后、由 CPU 跑那个输出文件算出来的。

**tcc_add_file 之后去哪？** 它内部嗅探 `t.c` 的开头是文本（不是 ELF），
走 C 源码路径，最终调到下面这个 37 行的函数——全书最重要的一段代码。

## 第 1 站：tcc_compile（libtcc.c:624）—— 一个文件的完整编译

逐字看（已删减注释）：

```c
/* src/core/libtcc.c:624 */
static int tcc_compile(TCCState *s1)
{
    Sym *define_start;

    define_start = define_stack;      /* 记住宏栈的起点，本文件编完要回滚到这 */
    tccelf_begin_file(s1);            /* 准备 .text/.data/.bss 这些"纸带" */

    if (setjmp(s1->error_jmp_buf) == 0) {
        s1->nb_errors = 0;
        preprocess_start(s1, is_asm); /* 预处理器开机：内置宏、include 栈 */
        if (s1->output_type == TCC_OUTPUT_PREPROCESS) {
            tcc_preprocess(s1);       /* 走 -E 路线：只展开不编译 */
        } else if (is_asm) {
            tcc_assemble(s1, ...);    /* 走 .s 路线：内置汇编器 */
        } else {
            tccgen_compile(s1);       /* ★ 走 C 路线：词法→解析→生成代码 */
        }
    }

    preprocess_end(s1);
    free_inline_functions(s1);        /* 没被用过的 inline 函数扔掉 */
    free_defines(define_start);       /* 本文件里的 #define 回滚掉 */
    sym_pop(&global_stack, NULL, 0);  /* 清空全局符号栈 */
    sym_pop(&local_stack, NULL, 0);   /* 清空局部符号栈 */
    tccelf_end_file(s1);              /* 收尾 */
    return s1->nb_errors != 0 ? -1 : 0;
}
```

这段 37 行就是 TCC 的**总装车间**。三个值得停下来的设计：

**① `setjmp` 当"回到这里"按钮**（:634）。
`setjmp(…) == 0` 表示"第一次走到这，往下编译"。
后面任何地方语法出错，就调 `tcc_error()`（libtcc.c:538）——它不返回，
而是 `longjmp` 直接飞回这行，继续走收尾代码。
于是 TCC 的错误处理**没有逐层 return -1 的样板**，出错=按电梯回大厅。
`tcc_error` 在全仓库被调用 133 次（graphify 统计的第一枢纽），
它不是"错误多"，而是"每个函数出错都按同一部电梯"。

**② `tccgen_compile` 一站到底**。
注意没有 `parse.c → ir.c → codegen.c` 三段式——
一个 `tccgen_compile` 把"读 token + 解析 + 生成机器码"全包了。
这就是 04/05 篇要展开的心脏；现在只需知道：**心脏就住在这**。

**③ 作用域回滚**（:654-658）。
宏栈、符号栈都是**栈**：编译这个文件前记个起点，结束后弹回去。
`tcc a.c b.c` 两个文件互不污染，靠的就是这里，一行删除代码都没有。

## 第 2 站：心脏的入口——tccgen_compile（tccgen.c:235）

```c
/* src/core/tccgen.c:235（骨架） */
static void tccgen_compile(TCCState *s1)
{
    ...初始化 int_type/char_pointer_type 等"规范类型"、vtop/vstack 归零...
    next();                 /* ★ 从词法器拿第一个 token */
    while (tok != -1) {
        decl(VT_CONST);     /* ★ 解析一条"外部声明"（函数或全局变量） */
    }
    gen_inline_functions(s1); /* 编译被引用过的 inline 函数 */
}
```

就两个循环：`next()` 给词，`decl()` 翻译，给一个译一个——**没有"先把整个文件
存成语法树再翻译"的中间步骤**。这是 TCC 和教科书编译器最大的差别，
04 篇会用一行 `x = add(x, y);` 把这个过程拆开给你看。

## 第 3 站：出口——tcc_output_file（tccelf.c:2233）

所有 `.c` 编完，机器码躺在内存里的 `Section` 纸带上（06 篇细讲）。
`tcc_output_file` 按输出类型分发：ELF → `elf_output_file`（tccelf.c:2060），
Windows → `pe_output_file`（tccpe.c:1941）。
ELF 那条路的四步——**符号解析 → 定地址 → 回填重定位 → 写文件**——
是 06 篇的主角。

## 【把 t.c 走一遍】

| 步骤 | 函数 | t.c 发生了什么 |
|---|---|---|
| 命令行 | `main` | 认识参数 `t.c`、`-o`、`t` |
| 喂文件 | `tcc_add_file` | 读 t.c 前几个字节，判定是 C 源码 |
| 单遍编译 | `tcc_compile` | 开机预处理 → `tccgen_compile` 边读边生成机器码进 .text/.data → 回滚宏和符号 |
| 输出 | `tcc_output_file` | 解符号、定地址、回填、写 ELF |
| 运行 | OS+CPU | `./t` → main 返回 19 → 退出码 19 |

# 04 · 表达式与值栈：TCC 的心脏

> 对应源码：`src/core/tccgen.c`（7386 行）——TCC 最厚的文件，却**没有一句"语法树"**。
> 目标：用 `x = add(x, y);` 这一行，看清 token 如何在"便利贴栈"上一步步变成机器码。

---

## 第 0 站：优先级就是函数的套娃（tccgen.c:5286, 5678）

教科书会先建一棵树，TCC 直接让函数**互相调用**来表达优先级：

```c
ST_FUNC void expr_prod(void)          /* 层2：乘除 */
{
    int t;
    unary();                          /* 先吃一个最底层的项 */
    while (tok == '*' || tok == '/' || tok == '%') {
        t = tok; next(); unary();     /* 再来一个项 */
        gen_op(t);                    /* ★ 栈顶两值归约 */
    }
}

ST_FUNC void expr_sum(void)           /* 层1：加减 */
{
    int t;
    expr_prod();                      /* 先吃一个乘积 */
    while (tok == '+' || tok == '-') {
        t = tok; next(); expr_prod();
        gen_op(t);
    }
}
```

顶层入口 `gexpr()`（tccgen.c:5678）只管逗号：

```c
ST_FUNC void gexpr(void)
{
    while (1) { expr_eq(); if (tok != ',') break; vpop(); next(); }
}
```

看明白了吗：`a + b * c` → `expr_sum` 调 `expr_prod`（吃掉 `a`），
看 token 是 `+`，再调 `expr_prod`（吃掉 `b*c`，乘法在**更深的函数**里先归约）。
**函数嵌套深 = 优先级高**。递归下降四字，说的就是这件事。

## 第 1 站：贴便利贴——vsetc/vpushi（tccgen.c:630/702）

最底层的 `unary()`（tccgen.c:4594）读到数字或变量时，把结果贴到值栈：

```c
static void vsetc(CType *type, int r, CValue *vc)
{
    int v;
    if (vtop >= vstack + (VSTACK_SIZE - 1))
        tcc_error("memory full (vstack)");
    /* 栈顶若还攥着 CPU 标志/跳转链，先物化成寄存器（见 05 篇） */
    if (vtop >= vstack && !nocode_wanted) {
        v = vtop->r & VT_VALMASK;
        if (v == VT_CMP || (v & ~1) == VT_JMP)
            gv(RC_INT);
    }
    vtop++;                /* 栈顶升高一格 */
    vtop->type = *type;    /* 写上类型 */
    vtop->r = r;           /* 写上住址（比如 VT_CONST） */
    vtop->r2 = VT_CONST;
    vtop->c = *vc;         /* 写上值 */
    vtop->sym = NULL;
}

ST_FUNC void vpushi(int v)
{
    CValue cval; cval.i = v;
    vsetc(&int_type, VT_CONST, &cval);
}
```

`unary()` 里数字常量这一路（tccgen.c:4616-4621）：

```c
    case TOK_CINT:
    case TOK_CCHAR:
        t = VT_INT;
 push_tokc:
        type.t = t;
        vsetc(&type, VT_CONST, &tokc);   /* 贴一张"我是常量"的便利贴 */
        next();
        break;
```

**此时没有任何机器码被生成。** 一个常量 = 一张 `VT_CONST` 便利贴。

## 第 2 站：变量——Sym 里已经存好了家（tccgen.c:5079 起）

读标识符那段，会查到 Sym 并把它的"住址"抄到便利贴上：

```c
        /* 省略查找 global/local 符号栈... */
        r = s->r;
        ...
        vset(&s->type, r, s->c);   /* ★ 把 s 的住址和偏移抄进便利贴 */
        vtop->sym = s;
```

- 局部变量 `x`：`s->r = VT_LOCAL | VT_LVAL`、`s->c = 栈帧偏移 -8`。
  便利贴就成了"我住在 rbp-8，我是左值"。
- 全局变量：`s->r = VT_CONST | VT_SYM`，另贴 `sym` 欠条（06 篇兑）。

## 第 3 站：拿货 gv()（tccgen.c:1253）——寄存器只是"临时工位"

`2 * K` 要真算，就得把便利贴上的值装进寄存器。`gv()` 是那个"工头"：

```c
ST_FUNC int gv(int rc)
{
    int r, bit_pos, bit_size, size, align, rc2;

    if (vtop->type.t & VT_BITFIELD) { ... 移位提取位域... }

    r = vtop->r & VT_VALMASK;
    ...
    /* 需要重新装填的情形：
       - 是常量
       - 是左值（得先解引用取货）
       - 已在寄存器但类别不对 */
    if (r >= VT_CONST
     || (vtop->r & VT_LVAL)
     || !(reg_classes[r] & rc)
     ...)
    {
        r = get_reg(rc);          /* 借一个类别匹配的寄存器 */
        ...
        load(r, vtop);            /* ★ 发射真正的取数指令（后端函数） */
        ...
    }
    vtop->r = r;                  /* 便利贴住址改写成"寄存器 r" */
    return r;
}
```

精髓在注释和判断里：**便利贴的住址是事实，寄存器是临时工位**。
需要算了才 `get_reg` 借工位、`load` 取货；工位不够 `save_reg`（tccgen.c:962）
把工位上还坐着的旧值"塞回它在栈帧里的家"（= 溢出）。不需要提前规划，
要一个借一个——这就是"最懒的寄存器分配"。

## 第 4 站：归约 gen_op（tccgen.c:2154）——常量折叠 + 发指令

`gen_op('*')` 登场时，栈上两张便利贴：`2` 和 `16`（K 已展开）。看关键分支：

```c
ST_FUNC void gen_op(int op)
{
    int u, t1, t2, bt1, bt2, t;
    t1 = vtop[-1].type.t;   /* 下面那张 */
    t2 = vtop[0].type.t;    /* 上面那张 */
    bt1 = t1 & VT_BTYPE;
    bt2 = t2 & VT_BTYPE;

    if (bt1 == VT_STRUCT || bt2 == VT_STRUCT) tcc_error("operation on a struct");
    else if (bt1 == VT_PTR || bt2 == VT_PTR) {
        /* 指针算术：p+n → p + n*sizeof(*p)；p-p → 再除以元素大小 */
        ...
    } else if (is_float(bt1) || is_float(bt2)) {
        /* 取更宽者，float/double/long double 提升 */
        ...
    }
    ...   /* 整型一路最后归到 */
    gen_opic(op);   /* ★ 两个操作数都是常量 → 编译期直接算完（不产码！）*/
    // 或
    gen_opi(op);    /* ★ 不是常量 → 调后端发真实 ALU 指令 */
}
```

**这一句 `gen_opic` 就是 TCC 全部"优化"的主力**：`2*K` 两个都是常量，
直接折成一张 `VT_CONST, 16` 的便利贴，**机器码里连一条 imul 都没有**。
（`gen_opic` 在 tccgen.c:1864，除零检查、移位截断也在这里做。）

于是 `int y = 2 * K;` 编出来的代码 ≈ `mov DWORD [rbp-16], 16`——
你把 2 和 8 直接心算好了，CPU 一个 `mov` 就完事。这就是 TCC 快的一个原因：
**能当场算的，绝不留给 CPU。**

## 第 5 站：函数调用 add(x, y)——unary 的 `(` 分支（tccgen.c:5157）

读 `unary()` 到标识符 `add` 之后，token 是 `(`，进入调用生成：

```c
        } else if (tok == '(') {
            /* function call */
            ...
            s = vtop->type.ref;          /* 函数 Sym 的 ref 挂着形参链 a,b */
            next();
            sa = s->next;                /* 第一个形参 */
            nb_args = regsize = 0;
            ...
            if (tok != ')') {
                for(;;) {
                    expr_eq();            /* 求一个实参 → 压到值栈 */
                    gfunc_param_typed(s, sa);   /* ABI 分类：进寄存器还是进栈 */
                    nb_args++;
                    if (sa) sa = sa->next;
                    if (tok == ')') break;
                    skip(',');
                }
            }
            skip(')');
            gfunc_call(nb_args);         /* ★ 后端把值栈上的实参倒着装车、发 call */
```

实参**从左到右求值、依次压在值栈上**（`x` 先压、`y` 后压，栈顶是 `y`）。
这就是 02 篇说的："值栈"从编译器最深处一直用到函数调用。

## 第 6 站：x86-64 怎么装车——gfunc_call（x86_64-gen.c:810，节选）

```c
void gfunc_call(int nb_args)
{
    ...
    arg = nb_args;
    for(i = 0; i < nb_args; i++) {
        --arg;                          /* ★ 从栈顶(=最后一个实参)开始卸货 */
        bt = (vtop->type.t & VT_BTYPE);
        size = gfunc_arg_size(&vtop->type);
        if (!using_regs(size)) { ... }  /* 大结构体走栈，先记到暂存区 */
        else {
            if (is_sse_float(vtop->type.t)) { ... gv(RC_XMM0); ... }
            else {
                r = gv(RC_INT);          /* 拿货到整型寄存器 */
                if (arg >= REGN) { gen_offs_sp(0x89, r, arg*8); }  /* 第7个起压栈 */
                else { d = arg_prepare_reg(arg); ... mov r, 目标寄存器; }
            }
        }
        vtop--;                          /* 卸完一张撕一张 */
    }
    save_regs(0);
    ...
    gcall_or_jmp(0);                     /* 发 call（符号走重定位，06 篇） */
}
```

配合 `unary()` 里 `gfunc_param_typed` 的分类，整个过程是：
`add(x, y)` → 值栈压 x、y → `gfunc_call(2)` 从栈顶撕下 y（进 `rsi`）、
再撕下 x（进 `rdi`）→ `call add`。返回值约定在 `rax`，
`unary()` 末尾 `vsetc(&ret.type, REG_IRET, …)` 把"rax 里的结果"又贴回值栈。

## 第 7 站：`return x;` 收尾

`return` 的表达式算完后 `gen_assign_cast` 拷进返回值寄存器，
05 篇的 `gfunc_epilog` 负责 `leave; ret`。到这一步，`main` 的机器码已全部
躺在 `.text` 纸带里，`x=3, y=16, add=19` 一路心算+少得可怜的几条指令。

## 【t.c 里 `x = add(x, y);` 的完整推演】

| 动作 | 值栈（栈顶在右） | 机器码 |
|---|---|---|
| `x`(实参1) | [x@rbp-8] | 无 |
| `y`(实参2) | [x, y@rbp-16] | 无 |
| `gfunc_call(2)` | 弹空 | mov y→rsi; mov x→rdi; call add |
| 返回值 | [add 结果@rax] | 无 |
| `= x` | 弹空 | mov [rbp-8], rax |
| `return x` | — | mov eax,[rbp-8]; leave; ret |

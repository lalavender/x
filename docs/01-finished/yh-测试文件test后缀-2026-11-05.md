# yh-测试文件test后缀-2026-11-05

## 概述

测试文件命名约定改为：**`.test.yh` 后缀是测试文件的唯一标识**，
`zz_`/`99_` 排序前缀废止（用户决定）。配套的编译器排序规则保证测试文件
排在模块内非测试文件之后，文件名不再承担排序语义。

## 编译器变更（VTEST）

`compiler/build/project_index.yh`：

- 新增 `pj_name_is_test`：判断文件名是否以 `.test.yh` 结尾；
- `pj_dir_less` 排序规则：**`*.test.yh` 一律排在非测试文件之后**，
  其余仍按文件名字节序（跨宿主确定性不变）。

扫描器对 `.test.yh` 前的 `test` 段按普通文件名放行
（`pj_source_target_match` 未识别段即接受），平台变体照常工作：
`tests.test.linux.yh`、`tests.test.darwin.yh`。

## 文件改名（16 个，git mv 保历史）

- `libs/cli/`：`zz_tests_{actions,basics,commands,extensions,help}.yh`
  → `{actions,basics,commands,extensions,help}.test.yh`
- `libs/{fmt,io,json,net,os,string,sys,time,toml}/99_tests.yh`
  → `tests.test.yh`；`libs/num/zz_tests.yh` → `tests.test.yh`
- `compiler/ir/zz_tests_verify.yh` → `verify.test.yh`

生产文件中的内嵌测试块（`gen/buffer.yh`、`lex/layout.yh`、
`parse/iface.yh`、`parse/parse_type.yh`）不是测试文件，不改名。

## 引用同步

`tests/fmt/install.py`、`tests/{num,string,toml,modules}` 注释、
`libs/{cli,io,json,string}/README.md`、`libs/net/doc.yh`、justfile
缺测试提示（模式 `*tests*.yh` → `*.test.yh`）、设计文档

`docs/01-finished` 的带日期历史记录不改。

## 两代自举（滚动自举过渡）

旧种子按字典序扫描，`actions.test.yh` 会排到 `cli.yh` 之前而报
「未知类型」——排序规则在新编译器里，形成鸡生蛋死锁。按滚动自举流程过渡：

1. 临时改回 `zz_*.test.yh`/`99_tests.test.yh` 中间名（旧种子字典序可排对），
   旧种子编出 **yh-1**（内含新排序规则）；
2. 改回无前缀最终名，yh-1 自举编出 **yh-2**；
3. 固定点代理校验：yh-2 再编 yh-3，**两代产物逐字节相同**（`cmp` 通过）；
4. `just seed` 滚动 Windows 种子（哈希已写入 `bin/yh-windows-x64.sha256`）。

## ⚠️ 跨平台种子窗口

GitHub Release 分发的 linux/darwin 种子早于本变更，用它们构建本树的
`libs/cli` 会报「未知类型」。**下一次 Release 发布新种子前，其他平台的
CI/全新克隆构建会红**——需要协调发版（release.yml 四平台种子同时更新）
后才能在全新环境构建。本地 Windows 已滚种子，不受影响。

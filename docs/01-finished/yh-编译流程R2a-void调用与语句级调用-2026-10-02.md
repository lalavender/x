## 切片内容

本切片把「void 返回调用」与「语句级调用」接入 typed SSA 与 arm64 后端，
同时让 void 函数本身可由 SSA 降低：

1. **verifier 值编号稀疏化**：IR 设计本就允许无结果指令（void CALL、
   STORE 的 `result_id/result_type` 为 -1），但 `ir_verify` 末尾要求定义数
   与 `value_count` 精确相等。现放宽为「定义数不得超过 `value_count`」，
   值编号允许稀疏；逐指令的编号范围与唯一性检查保持不变。
2. **语句级调用**：新增 `ast_ir_expr_stmt_supported`/`ast_ir_lower_expr_stmt`。
   表达式语句只接受已检查的直接调用（`AST_STMT_EXPR` 单表达式边），
   void 返回发射无结果 CALL，标量返回照常定义结果值并丢弃使用。
   顺序路径与 if/else 分支块（`ast_ir_branch_assignments_*`）都接受
   调用语句，分支内与赋值混合时仍按源码顺序发射。
3. **void 函数降低**：`ast_ir_lower_function` 接受 void 返回签名
   （映射到固定类型表下标 0），支持末尾裸 `return;` 与隐式结束；
   分支合流形态对 void 返回仍显式回退。空函数体产生「单块零指令 +
   无值 RET」CFG。后端 `arm64_function_supported` 相应允许 void 返回与
   零指令函数，无值 RET 沿用既有 `mov x0, xzr` 尾声。
4. **跨模块 void 调用**：导入限定名走与既有直接调用相同的稳定符号
   规则（模块限定后缀 + Darwin 前缀），调用表与实参编码不变，
   序列化格式（v4）与缓存键版本无需升版。

## 性能

Apple M1 冻结 25 文件、13,338 行语料，各场景独立测量 20 轮，计入外部
汇编与链接（新种子 `d261e9b2…`，含本切片全部降低）。中位数/p95 为：
无改动 40.3/51.3ms、单函数修改 748.5/808.6ms、冷编 1963.9/2135.9ms；
汇编/链接调用依次为 0/0、1/1、4/1。函数修改场景捕获 80 个 AST 函数
上下文、0 个进入 SSA，冷编 378 个上下文、5 个进入 SSA——冻结语料中
被修改函数不含可降低语句，数字与上一轮在噪声范围内持平，本切片同样
不构成编译提速证明。无改动 50ms 中位数目标保持达标，单函数 200ms 与
冷编 1s 目标未达到；单函数修改的对象阶段（约 480ms 中位数，含一次
外部汇编）与最终链接阶段（约 151ms）仍是主要耗时。

## 边界

- void 函数的分支合流（两侧对局部赋值后隐式结束）尚未接入；
  循环、switch、goto、间接/浮点/聚合/变参调用仍在旧发射路径。
- 表达式语句仍只接受直接调用；其他有副作用的表达式形态不降低。
- 本切片不代表 R2a/R2b 完成：编译器自编项目进入 SSA 的函数占比
  仍然很低，函数级增量与线程池等 R2b 硬门继续实施。

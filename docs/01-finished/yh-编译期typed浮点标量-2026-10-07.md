# yh 编译期 typed 浮点标量

## 交付内容

- typed 编译期执行器支持 **f32/f64 标量**：字面量、局部值、`+ - * /` 与一元正负号、
  比较（`== != < <= > >=`）、显式转换（整数↔浮点、浮点↔浮点、f32 窄化）以及
  浮点形参与浮点返回。
- 浮点值以 IEEE754 **位模式**保存在 `CtValue.value`，类型仍由 `type_id` 决定；
  整数与浮点共用同一字段，复制、传参、返回与聚合以外的赋值天然正确。
- f32 内部按 f64 位模式保存，写入与物化时经一次往返窄化到单精度精度。
- 顶层常量物化：`ct_call` 把位模式写入 `Res.ival` 与 `Res.fval_bits`，非折叠
  模式发 `mov x0, bits` + `fmov d0, x0`；`sem_ident_val` 引用浮点常量时补
  `fval_bits` 与同样的浮点装载。
- 新增 `compiler/comptime/ct_ir_float.yh`（位模式↔f64、窄化、转换、浮点二元与比较），
  接入 `ct_ir.yh` 的常量、一元、二元、转换、赋值与局部声明路径；放行浮点形参/返回
  与顶层物化。
- 用例：`tests/yh-run/run/134-comptime-float-scalar.yh`（含 f32 窄化断言、三元、
  形参/返回与顶层常量消费）、`fail/137-comptime-float-array.yh`（浮点定长数组仍拒绝）、
  `fail/138-comptime-float-address.yh`（浮点取址仍拒绝）；`comptimelocal` 增加跨源文件
  浮点形参/返回、浮点比较与整数截断断言，`prog.yh` 消费浮点常量。

## 顺带修复的既有缺口

- `gen.sem_ident_val` 引用 const 时从不填 `fval_bits`、也不按浮点发 `fmov`：
  浮点常量（此前无法由编译期函数产生，属潜伏缺口）现在可被普通代码正确读取。
- 编译期执行器的**局部声明初始化**路径对标量统一走 `sem_fold_norm`，会把 f32
  位模式按 4 字节整数截断，导致 f32 局部值损坏；现按浮点只做宽度窄化。
- 单精度判定必须看类型表 `kind`，`type_id` 是类型表索引，不能与 `TY_F32` 常量比较
  （误判会让 f32 不做窄化）。
- 一元负号改走符号位翻转、浮点转整数统一有符号截断，避免生成 yh-link 冻结子集
  之外的 `fneg`/`fcvtzu`（自编导入审计构建曾因此失败）。

## 边界

- 仍拒绝：浮点数组/切片/结构体字段等聚合元素、浮点取址与指针、`%` 等非算术运算。
- 前端自身的浮点常量折叠（`const A f64 = 1.5 + 1.0;`）仍报「浮点常量折叠暂不支持」；
  普通函数里的编译期诊断也不能直接做浮点比较，需经编译期函数折算成整数。

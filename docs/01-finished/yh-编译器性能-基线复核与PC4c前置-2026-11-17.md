# 编译器性能测试：基线复核与 PC4c 前置断言（2026-11-17）

启动 `docs/todo.md` 的「编译器性能测试」节剩余项。本轮交付两件可本机验证的事：
重测当前基线（旧数字是 2026-10-26 的），以及补上 PC4c 要求的边界断言。

## 1. 复核事实

- **编译器耗时统计工具已删除**：`tools/compiler-performance.py` 在 `73ec7fd`
  （「删除休眠的 compiler-performance.py」）移除；`tests/perf/` 只剩产物基准
  （`perf-product.py` + `bench-*.yh`）。因此 PL1d2b / PC2d 里的「verify 占 lowering
  17%」「capture 13.4 ms/条」这类比例没有现成采集口径，只能临时打点或整机墙钟 A/B。
- **当前基线重测**（本机 darwin-arm64，0.0.16 编译器，`YH_CACHE=off just build`
  冷编 3 次）：

  | 场景 | 命令 | 结果 |
  | --- | --- | --- |
  | 冷编（29 模块） | `rm -rf compiler/.build && YH_CACHE=off just build` | 6,276 / 6,086 / 6,320 ms（中位 **6.28 s**） |
  | 热编（无改动） | `just dev` | **0.68 s** |
  | 单函数改动 | —— | **未复测**：`touch` 不改内容等于热编（0.7 s）；要测真实改动得改一处函数体 |

  对照 2026-10-26 基线（冷编 10.1 s / 热编 0.98 s，另一批二进制与宿主）：冷编明显变快，
  但两批语料与二进制不同，按归因口径**只比段落结构，不跨批比绝对值**。

## 2. 改动（PC4c 前置）

`compiler/ir/ssa_module_40_function_cache.yh`：

- `ir_fc_visit_type`：写 `order[count[0]]` 前断言 `0 <= count[0] < unit.type_count`
  （`order` 容量就是 `unit.type_count`；`state` 已保证每个类型最多追加一次，断言是
  为将来「按模块复用 scratch」兜底）。
- `ir_fc_mark_symbol`：`global_used[gi]` 前断言 `0 <= gi < unit.global_count`。

两处越界都返回 -1，不再静默写穿。

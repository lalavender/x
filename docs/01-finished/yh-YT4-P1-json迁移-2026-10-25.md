# YT4-P1：JSON 测试迁移（2026-10-25）

## 范围

把 `tests/modules/projects/json{model,strings,numbers,containers,errors,files}`
的 114 个 `ok()` 断言点迁入 `libs/json/99_tests.yh`，同版本删除 5 个纯断言
夹具与 `tests/json/run.py`，保留 `jsonmodel` 作为公开面/链接 smoke
（`build-check.py` 的 `j1-json-model`）。

## 断言对照表

旧夹具与函数 → 新 `test`；旧 `ok()` 调用点全部有对应断言。

| 旧夹具 / 函数 | 覆盖点 | 新 `test` |
| --- | --- | --- |
| `jsonmodel`: `check_kinds`(6 种根类型)、`check_empty`(5) | 根类型、空视图/空输入 | `模型：根类型与空输入` |
| `jsonmodel`: `check_multi`(4)、`check_borrow`(3)、`check_spans`(2) | 多文档、借用输入、位置 | `模型：多文档、借用与位置` |
| `jsonstrings`: `check_escapes`(6)、`check_surrogate`(4) | 短转义、`\uXXXX`、代理对 | `字符串：转义与 Unicode` |
| `jsonstrings`: `check_nul`(3)、`check_write_escapes`(2)、`check_invalid_utf8`(3) | NUL 键、写出转义、非法 UTF-8 | `字符串：NUL 键与写出转义` |
| `jsonnumbers`: `check_lexeme`(2)、`check_integer_bounds`(4)、`check_integer_reject`(4)、`is_integer`(1)、`check_float`(7) | 词素保真、i64 边界、f64 位模式/范围 | `数字：词素、i64 与 f64` |
| `jsonnumbers`: `check_write`(6) | 整数/浮点写出、NaN 拒绝与回滚 | `数字：写出形态与 NaN` |
| `jsoncontainers`: `check_nested`(8)、`check_bounds`(4) | 嵌套、插入顺序、越界/类型错误 | `容器：嵌套、顺序与边界` |
| `jsoncontainers`: `check_pretty`(2)、`check_sort`(4)、`check_builder_errors`(3)、`check_top_scalars`(2) | 缩进、排序、builder 误用、顶层标量 | `容器：缩进、排序与 builder 误用` |
| `jsonerrors`: `check_encoding`(3)、`check_strings`(6) | BOM/UTF-8、字符串层拒绝 | `错误：编码与字符串` |
| `jsonerrors`: `check_numbers`(7) | 数字 grammar 拒绝 | `错误：数字 grammar` |
| `jsonerrors`: `check_structure`(9)、`check_duplicate`(6)、`check_depth`(2)、`check_argument`(2) | 结构拒绝、重复键位置、嵌套上限、参数错误 | `错误：结构、重复键与上限` |
| `jsonfiles`: `check_roundtrip`(8)、`check_errors`(5) | 写文件→读回、I/O 错误分类 | `文件：往返与 I/O 错误` |

说明：

- 旧 `expect_error`/`expect_error_bytes` 对每个用例断言“无半成品文档 + 错误码”
  两条；新文件用 `jt_rejects`/`jt_rejects_bytes` 合并为一条
  `$assert(..., "<用例名>")`，覆盖内容不变（这也是 114 个旧调用点对应到 127 条
  新断言的原因之一：根类型循环展开为 2 条/类型）。
- 所有断言只调用 json 的 pub API（含测试专用 `import string`），与旧夹具的
  消费者视角一致（迁移决策 D7）。
- 文件用例按 `libs/io/99_tests.yh` 先例使用 `/tmp` 下按用例固定的路径
  （`/tmp/yh-json-test-files.json`），结束时 `unlink`。

# J6 收尾：Linux section 化、release 剥离与体积度量（2026-10-27）

本文件是 J6（产物体积）L2 / L4 与度量物的收口记录。L1（Darwin `-dead_strip`）
与 L3（依赖项目单独 O2）另有单独记录。

## L2：Linux `--gc-sections` + 每函数/每全局 section

### 为什么必须两件事一起做

ELF 的 `--gc-sections` 是 **section 粒度**回收。原先 yh 把所有函数发在同一个
`.text`、所有全局发在同一个 `.data`/`.rodata`，加了 GC 也只能整模块丢弃——
只要有任何一个符号被引用，整个模块的代码就都留着。因此先要让 IR 自己把每个
函数/每个全局放进独立 section（等价 `-ffunction-sections`/`-fdata-sections`）。

### 实现

`compiler/backend/llvm_module.yh`
- `llvm_elf_sections(unit)`：目标 key 为 1/2（`aarch64-unknown-linux-gnu` /
  `x86_64-unknown-linux-gnu`，见 `ir_module_target_expected`）时返回 1。
- `llvm_section_name(out, prefix, name)`：把符号名转成 section 后缀；mangling
  只用到 `[A-Za-z0-9_$]` 与全局的 `.LDn`，所以 `$`→`_S`、`.`→`_D` 后仍然唯一。

`compiler/backend/llvm_scalar.yh`（`llvm_function`）
- 函数签名后追加 `section ".text.<mangled>"`（仅 ELF）。

`compiler/backend/llvm_module.yh`（`llvm_globals`）
- 全局初始化后追加 `, section ".rodata.<n>"` / `".data.<n>"`（仅 ELF）。

`compiler/build/link_cache.yh`
- Linux 目标追加 `--gc-sections`（内嵌 lld）或 `-Wl,--gc-sections`（系统 cc）。

开关判定统一走目标 key，不依赖环境变量；产物内容变化会自然改变链接键。

### 验证（本机能做的部分）

- `--target aarch64-unknown-linux-gnu --emit-llvm`：ELF IR 中
  `fmt=61`、`io=32`、`main=1` 条 `section ".text.…"`；`fmt` 还有 8 条全局
  section。
- ELF 目标对象（本机可发对象、不可链接）节表：`.text.main`、`.text.memcpy`、
  `.text.memset` …（用 Python 解析 ELF 节头确认）。
- Darwin 目标 `.ll` 无新增 section（`section "` 只命中既有的
  `section "llvm.metadata"`），因此 Darwin 全部门禁不受影响。
- **未做**：Linux 端到端（`--gc-sections` 实际回收率）。本机 `container run`
  启动即报错（`server closed session with no notification`），按仓库分工交给
  Linux CI 的 `just test-llvm-linux-arm64` 复核；已在 `docs/todo.md` 留
  「L2 后续（Linux 端到端）」条目。

## L4：release 剥离与编译器自身度量

- `YH_LINK_STRIP=1`（缺省关）给 ld64.lld 加 `-x`（剥离局部符号表），并计入
  链接键。实测 fmt hello：`53,424 → 52,576 B（−1.6%）`；程序行为不变。
- 编译器自身（`SELFHOST_KEEP=1` 自举后比较候选代数）：

  | 代 | 由谁链接 | 文件大小 | 文本符号 |
  | --- | --- | --- | --- |
  | cc2 | 种子（无 `-dead_strip`） | 70,815,568 | 93,995 |
  | cc3 / cc4 | 新编译器（`-dead_strip`） | **65,112,448** | **79,168** |

  → **−5.7 MB（−8.1%）**。此前用 `just build` 对比「无变化」是方法错误：那一步
  由种子执行链接，不会带上本仓库新增的链接参数。
- 拆 fmt 模块（把浮点格式化移出 `append_value` 的可达集）**不做**：会破坏
  「fmt 不扩 API、不拆公开面」的边界，而且 L1+L3 后 fmt hello 仅比 printf hello
  大 6.3%，收益不再值得这笔复杂度。

## 度量物

- `tests/perf/fmt-size/printf-hello`：无依赖，`printf("hello\n")`。
- `tests/perf/fmt-size/fmt-hello`：`import fmt`，`fmt.print([of_cstr("hello\n")])`。
- `tools/size-report.py`：构建两者并输出文件大小与主要段（Darwin `size -m`、
  Linux `size -A`），支持 `--json`；`--budget-ratio` 为软门（默认 1.2），
  `--strict` 才把超预算变成失败。入口 `just size-report`（不进门禁）。
- 当前读数（macOS/arm64）：printf `50,256 B`、fmt `53,424 B`、比值 **1.063**。

## 验证与预算

- `just test` 全绿（含 `tests/modules/opt-level.py`、`darwin-dead-strip.py` 之外的
  各层；arch-check 自测 2/2）。
- `SELFHOST_KEEP=1 FAST_DIR=<repo>/tmp/yh-fast just selfhost-native` 退出码 0：
  cc3→cc4 固定点、全量语料、122/122 项目用例。
- `tools/arch-check.py`：`max_build_lines` 10878 → 10904（L2/L4 +26）。
- 经验：`$TMPDIR/yh-fast` 是并发会话共享的，跑主门请把 `FAST_DIR` 指到仓库内
  （本次曾因陈旧分期编译器报出不属于本树的 `函数未使用` 诊断而误判一次）。

# 顶层 const 结构体聚合常量（CT3 最小切片）

日期：2026-10-07。状态：已完成。

## 背景

`const P Point = Point{ x: 1 };` 此前直接报「const 不支持聚合类型」。这是 `fail/148`
（顶层聚合实参）的上游障碍：诊断让用户「用编译期常量中转」，但聚合常量本身不支持，
实测两条替代路也都走不通 —— `const` 报上面那句、全局 `let` 变量则报「变量不是编译期常量」。

## 改动（两处，共约 15 行）

1. `compiler/parse/parse_global_init.yh`：`TY_STRUCT` 分支的 `const` 拒绝**只在模块模式保留**
   （接口导出尚未覆盖聚合常量），单文件模式改为与全局变量走同一条 `parse_global_struct_init`
   数据发射路径；发射后把符号标记为已就绪（聚合常量没有标量值，但数据已就绪，否则读取时会
   被「编译期常量尚未就绪」拦下）。
2. `compiler/gen/sem_value.yh` 的 `sem_ident_val`：`SYM_CONST` 且**类型是聚合**
   （结构体/数组/切片/联合体）时降级为变量语义 —— 这类常量没有可用的标量 `cval`，必须与全局
   变量一样按**符号地址**访问。不加这一步会在运行期段错误（把 `cval = 0` 当地址用）。

## 用例

新增 `tests/yh-run/run/151-const-aggregate-global.yh`（`// exit: 0`）：

- `const ORIGIN Point = Point{ x: 3, y: 4 };`（标量字段）
- `const BOX Rect = Rect{ lo: Point{ x: 1, y: 2 }, hi: Point{ x: 5, y: 6 } };`（嵌套结构体字段）
- `let MUT Point = Point{ x: 1, y: 1 };`（对照，确认变量路径未被改动）
- `main` 读取全部字段求和后减 23 应得 0（同时覆盖通过局部变量间接读取）

## 效果与边界

| 写法 | 之前 | 现在 |
| --- | --- | --- |
| `const P Point = Point{ ... };`（单文件） | 拒绝 | **可用**（数据段只读读取） |
| 同上（模块模式） | 拒绝 | 仍拒绝（接口导出未覆盖聚合常量） |
| `const A [3]int = [1, 2, 3];`（数组/切片 const） | 拒绝 | 仍拒绝（本轮只放宽结构体） |

注意：`const` 聚合常量在语言层面仍可被写入而不报错（只读性未强制）—— 这是本轮接受的
简化，必要时后续加只读检查。

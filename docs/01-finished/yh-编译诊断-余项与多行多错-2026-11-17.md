# 编译诊断：右括号余项 + 多行跨度 + 索引阶段多错误上报（2026-11-17）

收掉 V 风格诊断留下的两项余工：`28` / `88` 两例 caret 落在调用右括号；以及 D5 剩余
（多行跨度逐行下划线、错误恢复后的多错误上报）。

## 1. 余项：caret 落在调用右括号 `)`

- **`28` C ABI 回调实参**（`check/api.yh` 的 C ABI 回调检查）：`err_tok` 此刻已越过
  实参列表、游标停在 `)`。改用 `support.fc().c_expr_first`（`parse_expr_iso` 记录的
  表达式起点）作锚点；取不到时退回 `err_tok`。现在 caret 落在实参上（`plain_callback`）。
- **`88` 编译期实参数量**（`parse/parse_expr.yh` 的 `parse_comptime_call`）：
  `$函数(...)` 的起始 token 已在函数开头存进 `call_token`，改用
  `token.err_at(call_token, …)`。现在 caret 落在 `$` 上。

## 2. 多行跨度（D5 剩余之一）

- **渲染**（`errors/render.yh` 的 `fmt_snippet`）：首行下划线仍夹到行尾；跨度未画完时，
  后续每一行补一行下划线（长度取剩余字节与该行显示列的小者），片段窗口自动扩到跨度
  末行。颜色只包下划线本身。
- **位置接口**（`token/api.yh`）：新增 `err_call_span(first, after, msg)`——与
  `err_range` 相同取 `first..after`（不含）的源码字节区间，但**不把宽度夹到首行行尾**。
- **调用点记录**：`support.FibCtx` 新增 `c_call_lparen *int`（每层调用的 `(` token，
  堆分配 64 项）与 `c_pending_lparen int`（parse 写、`sem_call_begin` 消费）；
  `parse_postfix` 在调用点记录 `(` 下标，`check/api.yh` 的实参个数检查用
  `err_call_span(c_call_lparen[深度], pos+1, …)`。
- **夹具**：`tests/yh-run/fail/217-call-arity-multiline.yh`（多行实参列表，验证逐行
  下划线）；单行调用仍只画一行（`add(1)` → `~~~` 覆盖 `(1)`）。

## 3. 多错误上报（D5 剩余之二，仅索引阶段）

- `build/project_index.yh` 的 `pj_scan_source`：单个文件索引失败后**继续扫描同目录其它
  条目**，最多 `PJ_SCAN_ERROR_LIMIT = 8` 条；达到上限时停止并写
  `yh: 已停止继续扫描：错误数达到上限（8 条）`，随后仍返回 -1。
- 覆盖范围：索引阶段（词法 + 模块头）。同一模块体内多处语义错误仍只报第一处——
  `check` 与 lowering 是返回 -1 链，未做错误恢复（见 `docs/todo.md`）。
- 夹具：`tests/diagnostics/cases/multi-file-errors/`（两个文件各含 `module ;`，
  `.expect` 用新增的 `heads: 2` 断言两条头行）。

# yh test 逐例日志与截断提示（YT2d-1）实施记录

日期：2026-10-23。范围：逐例 stdout/stderr 日志、失败时回显日志尾部、
断言消息超长截断提示。缓存键（YT2d-2）与并行执行（YT2d-3）仍未实施。

## 交付

- `compiler/cmd/test_cmd.yh`
  - 每例 fork 前把 `stdout`/`stderr` 重定向到
    `<项目>/tmp/yh-test/log/<模块>-<局部用例号>.log`；fd 3 仍是结果记录通道。
    子进程按「先把日志复制到 1/2，再把记录放到 3，最后关闭 >2 的原始 fd」
    的顺序处理，避免 open 恰好占用 fd 3 时把记录通道关掉。
  - 失败/崩溃/超时时输出「用例日志: <路径>」并回显末尾至多 2 KiB
    （`tc_tail_log`，滚动窗口只读一遍文件，不整份载入）。
  - 断言消息超过 59 字节时，运行时在记录偏移 71 写 `0x1e` 标记；
    父进程据此追加「…（消息已截断）」，并用 `tc_utf8_trim` 回退到完整
    UTF-8 边界，避免半个多字节字符。
- `compiler/backend/llvm_runtime.yh`
  - `__yh_test_assert` 消息拷贝上限改为 59 字节；拷满后读 `msg[59]`
    判断是否还有内容，有则写截断标记。
  - `@write` 声明只在模块既没有 `write` 也没有 `printf` 时补；printf 运行时
    支持本身已声明 `@write`，否则同一模块出现重复 `declare`。
- `libs/testing/testing.yh`：`fail`/`skip` 同步 59 字节上限与截断标记。

## 语料与门禁

- `tests/modules/projects/ytestskip/src/app/lib.yh` 新增「带输出的长消息失败」
  用例：先 `printf("case-stdout-marker")`，再用超过 59 字节的消息断言失败。
- `tests/modules/test-check.py` 增至 30 项：
  - `execute-skip-and-fail` 期望 `2 passed; 1 skipped; 3 failed`；
  - 新增 `per-case-log-and-truncation`（日志路径、用例 stdout 回显、
    `…（消息已截断）`）；
  - 新增 `per-case-log-files`（`tmp/yh-test/log/` 下每个用例一个日志）。

## 边界

- 日志目录按模块 + 局部用例号命名，同一次构建内稳定；不同命令并发执行时
  会互相覆盖（并发隔离随 YT2d-3 一起做）。
- 消息上限仍是 59 字节（记录 72 字节布局不变），超长只提示不扩容。
- 测试构建仍完全绕过模块/函数级缓存（YT2d-2 设计独立键后再恢复增量编译）。

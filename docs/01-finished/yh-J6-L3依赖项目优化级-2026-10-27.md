# J6-L3 依赖项目单独 O2（2026-10-27）

## 结论

依赖项目（标准库/第三方）的模块统一按 O2 发射代码，根项目（用户代码）仍用
命令行优化级（缺省 O0）；开关 `YH_DEP_OPT=0` 可回退。fmt 版 hello 项目从
89,632 B 降到 **71,008 B**，`__text` 从 35,732 降到 12,516；只用 fmt 少量叶
子的程序降到 53,696 B，与 printf 版 50,256 B 同档。

## 为什么这样分

L1 的 `-dead_strip` 已经把 269 个 IR 函数删到 91 个（66%），剩下的都是**真
可达**：`print → output_values → render_values → append_value`（含 f64 分支
与 spec 解析）→ `string.reserve` / `io.write_all_result` / `os.make_error` /
`sys.write` / `memory.alloc|release`。链接器按符号删，删不掉「函数里的一个
分支」，所以只能从**发射质量**下手：

- 依赖代码不是用户正在开发的东西，且已被 `just libs-test-o2` 覆盖过，
  适合 O2；
- 用户代码仍需 O0 的可预测性（自举固定点、语料口径、调试友好）。

## 实现

`compiler/build/project_state.yh`
- `pj_dep_opt_enabled()`：`YH_DEP_OPT` 首字符为 `0/n/N/f/F` 时关闭，缺省开。
- `pj_module_opt_level(m)`：模块所属项目是根项目 → 返回 `gs.c_opt_level`；
  否则返回 2。用同文件的 `pj_is_root_project` 判定根项目。

三个接入点（共用同一判定，避免漂移）：
1. **对象发射**：`llvm_pipeline.yh` 的 `llvm_emit_publish` 增加 `opt_level`，
   由 `llvm_emit_module_to_cached` / `llvm_emit_module_to` 透传；项目 worker
   `module_worker.yh` 传 `pj_module_opt_level(m)`，单文件路径传 `gs.c_opt_level`。
2. **模块 manifest 键**（`module_build.yh`）：`('0' + pj_module_opt_level(m))`，
   否则开↔关会命中旧对象。
3. **函数 IR 环境键**（`function_ir_cache.yh`）：同上。

缓存效果依赖对象内容：链接键本就对每个对象取哈希，因此对象内容变化会自然
换链接键，不需要额外的策略常量。

## 效果（macOS/arm64，O0 根项目）

| 程序 | 依赖 O0（`YH_DEP_OPT=0`） | 依赖 O2（缺省） |
| --- | --- | --- |
| fmt hello（多值打印） | 89,632 B / `__text` 35,732 | **71,008 B / `__text` 12,516** |
| fmt 语料（少量叶子 API） | 88,752 B | **53,696 B** |
| printf（无依赖） | 50,256 B | 50,256 B（不受影响） |

相对 L1 之后：−21%；相对最初（无 `-dead_strip`、全 O0 的 155,872 B）：−54%。

## 新门

`tests/modules/opt-level.py`（`just test` 的一环，平台无关）：

1. 导入 fmt 的程序：缺省体积 **小于** `YH_DEP_OPT=0`（依赖确实 O2）；
2. 两种配置 stdout 逐字节一致；
3. 先构建 `YH_DEP_OPT=0` 再构建缺省，体积仍为较小值（优化级进入缓存键）；
4. 无依赖项目在两种配置下体积相同（开关不碰根项目）。

## 顺带修复：外部缓存根下的闭包记录路径

`just` 会导出 `YH_LLVM_CACHE` 与 `SDKROOT`（指向仓库外的共享缓存），而
`tools/llvm-darwin-host.py` 原先用 `path.relative_to(ROOT)` 写 `host.json`：
缓存根在仓库外时直接抛 `ValueError`，导致 `just selfhost-native` 在闭包检测
阶段失败（`Darwin 自举需要本机固定 LLVM 闭包`）。

修复：新增 `recorded_path()`（仓库内写相对路径，仓库外写绝对路径）与
`resolve_recorded()`（读回时绝对原样、相对按仓库根展开），替换 7 处写入点与
`selfhost_runtime` 的读取点。这同时消解了 `docs/todo.md` H4 里「缓存路径不
可迁移」的一半问题。

## 预算与验证

- `tools/arch-check.py`：`max_build_lines` 10846 → 10878（+32），
  `max_g_call_sites` 165 → 166（`pj_module_opt_level` 读模块表）。
- `just`（种子冷编）→ `just test` 全层绿（含 `opt-level.py` 4 项、arch-check
  自测 2/2）→ `just selfhost-native` 退出码 0（cc3→cc4 固定点、全量语料、
  `darwin-dead-strip.py`、122/122 项目用例）。
- libs 作为根项目仍是 O0（`just libs-test` 行为未变），`just libs-test-o2` 仍
  全 O2。

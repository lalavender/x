## 1. 交付内容

### sys

新增 `libs/sys/60_process.linux.yh`：

| API | 内核映射 | 语义 |
| --- | --- | --- |
| `process_id() i64` | getpid 172/39 | 当前 PID |
| `fork_process() i64` | clone 220/56，flags=SIGCHLD、空子栈 | 父得正 PID，子得 0 |
| `execute(path, argv, envp) i64` | execve 221/59 | 精确路径替换映像，失败 -errno |
| `wait_process(pid, status *int, options) i64` | wait4 260/61 | 返回原始 32 位状态，不解码 |
| `exit_process(code) void` | exit_group 94/231 | 结束线程组，不做语言清理 |
| `send_signal(pid, signal) i64` | kill 129/62 | 发送信号 |

`create_pipe`（pipe2）已在 OS1 收尾交付；本次补齐 `SIGKILL/SIGTERM/SIGCHLD/
ECHILD/ENOEXEC/WNOHANG` 常量。clone 只使用 SIGCHLD、空子栈、无 CLONE_VM，
不提供任意 clone(flags, stack)。

### os

新增 `libs/os/30_process.linux.yh`：

- `spawn(path *char, argv **char, envp **char) PidResult`
- `wait(pid int) WaitResult`
- `exit_now(code int) void`
- `PidResult { pid, error }`
- `WaitState { wait_exited, wait_signaled, wait_error }`
- `WaitResult { state, exit_code, signal, error }`

spawn 握手：

1. pipe2(O_CLOEXEC) 创建错误管道，fork。
2. 子进程关闭读端，execve；失败时把 32 位 errno 写入管道，关闭写端，
   exit_group(127)。
3. 父进程关闭写端，读 4 字节帧；干净 EOF 表示 exec 成功，返回子 PID；
   收到帧则回收失败子进程并返回显式 Error。读帧处理 EINTR、短帧和提前 EOF。
4. 成功 exec 后写端由 CLOEXEC 关闭；spawn 只确认 exec 通过，不承诺子程序持续存活。

wait 遇 EINTR 内部重试；正常退出取 `(status >> 8) & 0xff`，信号退出取
`status & 0x7f`，停止状态不使用 WUNTRACED，按 error_other 返回。exit_now
立即 exit_group，不刷新未来缓冲流、不执行析构。

命名偏差：prelude 已有 `exit`，因此 os 使用 `exit_now`；旧 `os.process_id` 保留，
新 spawn 返回 PidResult，不重复导出 process_id。

## 2. 测试

| 用例 | 平台 | 覆盖 |
| --- | --- | --- |
| `tests/modules/projects/sysprocess` | Linux | getpid、两次 fork/exit(7/9)、wait4 原始状态、SIGTERM 信号退出、无子进程 ECHILD |
| `tests/modules/projects/osprocess` | Linux | 精确路径 spawn 成功（退出 42）、重复启动、信号退出、缺失路径、无执行权限文件、WNOHANG 无僵尸、envp 传递 |

`osprocess` 用 argv[0] 重新执行自身：子模式 `child` 调用 exit_now(42)，
`signal` 给自己发 SIGTERM。失败 spawn 必须回收子进程；父进程最后用
`wait4(-1, ..., WNOHANG)` 断言 ECHILD。

两用例接入 `build-check.py` 的 Linux 专属列表。

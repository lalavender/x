# 项目装载身份与链接对象去重（2026-11-17）

承接 2026-11-15 的 [libs 重复装载修复](yh-libs-重复装载修复-2026-11-15.md)：
那次只是构建脚本补丁（`YH_STDLIB=../libs` 让两种来源同拼写），本轮把
**编译器自身**的结构性缺陷补完，并把 Linux 目录枚举的 `DT_UNKNOWN` 兜底接上。

## 1. 根因回顾

项目身份 = 项目根路径的**字节**（`proj.find_project_root`）。同一目录的两种拼写
（标准库自动发现的绝对路径 vs 清单依赖的相对路径）会被登记成两个项目；两个项目
各自读到同一个 `project.name`，于是模块产物标签 `<项目名>-<模块名>` 与符号后缀
完全相同 → 同一个 `.o` 进链接两次（ld.lld 报 duplicate symbol，Darwin 的 ld64
只是容忍），或者两个项目各自索引一遍源码。

## 2. 改动

### 2.1 项目身份规范化（P0）

- `compiler/build/api.yh`：新增 `pj_root_key(off, len, &out_off, &out_len)`——
  `link.realpath`（相对按 cwd 解析、消 symlink、绝对化）→ `proj.canon`（统一 `'/'`、
  折叠 `"."`/`".."`、合并多余斜杠）→ 入池；`realpath` 失败（路径不存在）保留原拼写，
  让后续「找不到 project.toml」照旧报错。`realpath` 的声明留在 `link`
  （Windows 端由 `compiler/llvm/windows_shim.c` 的 `GetFullPathNameA` 提供）：
  `proj` 是纯逻辑模块，一旦引用 libc `realpath`，拷真实模块子集的夹具
  （`gen-split` / `ctfacts`）在 Windows 上会链接失败——0.0.16-rc.1 的 Windows 门
  实测红，rc.2 把这一步移到 `build`。
- 同一处：`load_project` 入口先做一次 `pj_root_key`，函数体内一律用规范路径；
  新增 `pj_load_root`（`pj_root_key` → `set_root_project` → `load_project`），
  并替换两处 `build`/`run` 的「设根 + 装载」。
- `compiler/testkit/api.yh`、`compiler/testkit/test_cmd.yh`：`yh test` 的根身份同样
  先规范化，保证与 `proj.is_root_project` 的比较一致（否则根项目被当成依赖项目，
  优化级与 `[link]` 组选错）。

### 2.2 模块产物键的项目身份校验（P0）

- `compiler/build/proj/api.yh`：`np_eq`（池内区间比较）、
  `mod_tag_conflict(m)`（扫描「同 tag、不同项目」的模块）。
- `compiler/build/api.yh`：`pj_check_mod_tags()` 放在 `pj_topo` 的第一行——任何 tag
  被用于缓存键/对象路径之前；命中即报
  `模块产物标签冲突: <tag>（两个同名项目 → 改 project.name 或去掉重复依赖：A / B）`，
  位置落在模块目录。这条诊断把「留给链接器」的结构错误变成装载期诊断。

### 2.3 链接参数对象去重（P1）

- `compiler/link/link_cache.yh`：新增 `mb_row_dup`（按装配后的行路径判重）与
  `mb_link_dup_note`（`YH_LINK_TRACE` 非空时提示「重复链接对象已去重: …」）；
  `mb_link_args` 的 LLVM 分支与旧发射分支都改为「已在列则跳过」。
  注意 `proj.env_fetch` 在变量缺失时也返回 0（值空串），所以提示门判的是 `len == 0`。

### 2.4 Linux 目录枚举 `DT_UNKNOWN` 兜底（P1）

- `compiler/build/project_dir.linux.x64.yh` / `…arm64.yh`：`d_type == 4` 仍直接判目录；
  `d_type == 0`（`DT_UNKNOWN`，部分 overlayfs/网络文件系统）改用
  `openat(dirfd, name, O_DIRECTORY|O_NOFOLLOW)` 探测，成功即目录、关闭 fd 后返回 1。
  取值按各自 ABI：x64 `0x30000`（`0x10000|0x20000`），arm64 `0xC000`
  （`0x4000|0x8000`），与 darwin `getattrlistbulk` 的「名字 + 类型」语义对齐。

### 2.5 顺带修掉：模块 ActionID 混入绝对路径

身份规范化后暴露出一个既有耦合：`module_emit` 把**模块目录**混进模块 ActionID，
而该目录是绝对路径 —— 于是 C4 的「同一项目换目录仍按 ActionID 全局命中」失效
（`tests/selfhost/cache/llvm-global-cache.py` 立刻红）。改为混入
`proj.mod_dir_rel(m, …)` 的**项目相对**目录：同名不同目录仍能区分，跨目录命中恢复。

### 2.6 文档与不变量

- `docs/03-design/yh-模块与项目管理设计.md`：§5 补「目录枚举只沿目录向下，`DT_UNKNOWN`
  用 `openat` 探测」；§7 补「项目身份 = `realpath` 规范绝对路径」与「同 tag 不同项目
  在装载期报冲突」。
- `docs/03-design/yh-缓存设计.md` §4.2：模块键混入**项目相对**模块目录（绝对路径不入键）。
- `docs/03-design/yh-编译流程-当前实现.md` §3：装载步骤改为 `pj_load_root`（身份规范化
  → 设根 → 装载），`load_project` 增加第 0 步 `pj_root_key`；装载器位置更正为
  `compiler/build/api.yh`。
- `proj.find_project_root` 注释写明「调用方必须传规范身份」，防止新调用点回退本 bug。

## 4. 收尾（0.0.16 种子到位后落地，2026-11-17）

0.0.16 正式版发出后，两条「依赖新种子」的后续项随即落地：

- **删除 `YH_STDLIB=../libs` 过渡补丁**：`justfile` 的 `build`/`dev` 与
  `tests/selfhost/bootstrap/native-selfhost.py` 的 `run()` 恢复原形态。验证：清空
  `compiler/.build` 后 `YH_CACHE=off just build` 冷编通过、`sys` 只出现一次
  （不再重复装载）；`just test` 与 `just selfhost-native` 全绿。
- **回退 `argv` 模块拆分**：`compiler/argvimpl/` 三个平台文件并回
  `compiler/cmd/yh/argv.<平台>.yh`（`module main`、实现去掉 `pub`、删除目录），
  `cmd/yh/argv.yh` 去掉 `import yh_argv_impl` 与限定名。依据：入口桩现在按
  `llvm_runtime_declared(unit, …)` 判重（`backend/api.yh:406`），与 `main` 同模块
  不再触发 `invalid redefinition of function`；Windows 侧由 CI 四端门覆盖。

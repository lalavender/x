# 换行终结语句完成记录

日期：2026-10-22，分支 `0.0.8-rc`。

## 行为

按用户决定让 `\n` 参与语句边界：简单语句、`module`/`import`、类型别名、字段与
枚举成员可以省略行尾分号。同一行相邻语句仍用 `;` 分隔；括号/方括号内允许自由
换行；括号外的续行运算符必须放在上一行末尾；裸 `return` 在行尾结束。右花括号与
EOF 前可省略最后一个分号。空语句、块后多余的显式分号继续拒绝。完整规则见
[设计](../03-design/yh-换行终结语句设计.md)，清理顺序见
[方案](../02-plan/yh-分号清理实施方案.md)。

## 实现

- `compiler/lex/layout.yh`（新增）：扫描后重建 token 表，在换行处、`}` 前与
  EOF 前补零长度 `TK_SEMI`；括号/方括号内、属性组之后、行首 `{` 之前不补；
  显式分号优先。`lex_all` 末尾接入，所有词法入口共用。
- `compiler/parse/parse_type.yh`：`p_implicit_semi` 用长度区分隐式/显式终结符；
  `p_take_block_end` 只消费隐式终结符；`p_expect('}')` 放行字面量尾部。
- `compiler/parse/parse_stmt.yh`、`parse_decl.yh`、`parse_comptime.yh`：块、
  顶层声明与编译期展开范围跨过隐式终结符。
- `docs/yh.g4`：新增 `tokens { IMPLICIT }` 与 `stmtEnd : ';' | IMPLICIT`；
  `tests/yh/check.py` 用与 `lex_layout` 相同的规则归一化 token 后再解析，
  ANTLR 与编译器两套实现判定一致。
- 严格续行迁移：编译器 201 处、语料与标准库 82 处行首运算符移到上一行末尾；
  迁移前后由种子产出的模块 `.s`/`.s.i` 逐字节相同（只有 manifest 的源码哈希变）。
- `tests/modules/projects/llvmchecked/fixture.yh` 的 token 数断言从 13 改为 14
  （文件尾补了 1 个隐式终结符）。

# 模块私有类型（2026-10-12）

## 背景

用户要求把**不带 `pub` 的 `struct`/`union`/`enum` 标识为模块私有类型**，
并按 `AGENTS.md`「修改语法规则」流程执行。规划见
[设计](../03-design/yh-模块私有类型设计.md)、
[实施方案](../02-plan/yh-模块私有类型实施方案.md)、
[ADR-0013](../adr/0013-yh模块私有类型.md)（修订 2026-10-02「类型必须带 pub」，
保留"字段一律公开""类型禁止嵌套"）。

## 语言规则（已落地）

| 声明 | 含义 |
| --- | --- |
| `pub struct/union/enum` | 进接口文件（`.s.i`），跨模块可 `模块.类型` 命名；字段一律公开随接口携带布局，enum 成员常量随枚举导出（`F_PUB`） |
| `struct/union/enum` | **模块私有类型**：只在本模块可见、不进接口；enum 成员只在模块内可见 |
| 私有类型出现在本模块 `pub` 签名 / `pub` 字段 / `pub` 别名体 | 报错「pub 接口引用了非 pub 类型（请将该类型声明为 pub）」——**指针形式同样不允许**（用户决定不做不透明句柄） |
| 其他模块命名私有类型 | 报错「模块没有导出该类型」 |

`pub` 只影响可见性，不改变布局与 ABI。

## 改动

1. **语法**（`docs/yh.g4`）：`attributedDecl` 的 struct/union/enum 分支改 `'pub'?`；
   `plainDeclBody` 增三类；更新 36-41 行与 plainDeclBody 注释。无歧义论证见设计 §4
   （三个分支首 token 集合互不相交：`pub` / `@` / 其余关键字）。
2. **前端**（`compiler/parse/parse_decl.yh`）：删除两处「必须带 pub」门禁
   （struct/union 与 enum），注释改为"pub 可选、缺省模块私有"。
   **其余机制原样复用**：`t_names.is_pub = c_decl_pub`、接口按 `is_pub` 过滤、
   enum 成员 `F_PUB` 按 `c_decl_pub` 条件化、pub 声明引用非 pub 类型的诊断、
   CT 跨模块私有类型诊断。
3. **语料**：
   - 转正并删除 `tests/yh/rejected/{30_bare_struct,31_bare_union,34_bare_enum}.yh`；
   - 新增语法正例 `tests/yh/03-decl/10_private_types.yh`（私有 struct/union/enum +
     模块内使用 + `sizeof`）、`11_private_extern_type.yh`（`@[extern]` 私有 C 布局类型）；
   - 新增运行正例 `tests/yh-run/run/175-private-types.yh`（退出码与输出比对）；
   - 新增模块语法正例 `tests/modules/accept/08-private-type.yh`；
   - 新增 fixture `tests/modules/projects/privtype/`（`lib` 私有类型 + pub 访问函数、
     `host` 正例、`host2` 跨模块命名、`host3` 私有 enum 成员、`badpub`/`badfield`/
     `badalias`/`badptr` 四条泄漏负例）与 7 条 build-check 用例。
4. **编译器自身类型私有化（P4）**：12 个类型去 `pub`（13 处，含 `CmdTimespec`
   的 .darwin/.linux 两份）：`ast.{AstExpr,AstFunctionContext,AstIRBuilder,
   AstIRInlineEntry,AstStmt}`、`cmd.{CmdTimespec,PJDirEntry,TomlArrayItem,TomlSec}`、
   `comptime.{CtDataSlice,CtGlobalAgg}`、`parse.IfaceCtColMap`。

## 过程中发现的两点

1. **函数名不能用 prelude 名**：负例最初把函数命名为 `open`，命中「顶层符号重定义」
   （prelude 已登记 `open`），与私有类型无关；改名后诊断正确。已在用例里注明。
2. **`tests/yh-run` 是单文件模式**：不发射接口，故"私有类型泄漏"这类**模块级**语义
   负例只有在项目模式才触发；因此它们落在 `tests/modules/projects/privtype/`。

## 遗留与后续

- **不透明导出类型**（`pub fn f() *Secret`）按用户决定**不做**；若将来要做，
  需要新的接口/布局语义（Go 风格设计 §5.3 的原设想），已在该文档标注。
- **macOS 种子 `bin/yh` 落后两代**：它含已删除的「必须带 pub」门禁，因此**无法编译
  当前源码**（`compiler/{ast,cmd,comptime,parse}` 已有模块私有类型）。恢复步骤：
  先取「语言规则一代」源码（P1 的两处改动：`docs/yh.g4` + `parse/parse_decl.yh`）用
  现有 `bin/yh` 构建一次并 `make seed`（写 `bin/yh`），再回到含 P4 的版本；已记入
  `docs/todo.md`。
- `docs/03-design/yh-编译器模块导出面收缩设计.md` §4 里"12/66 可私有"的估算已被本次
  实测确认（12 个全部落地）。

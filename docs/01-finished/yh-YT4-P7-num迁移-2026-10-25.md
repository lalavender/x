## 发现（同日修复）

`1.5e300` 等十进制字面量在**编译器**里被解析成 1 ULP 偏差的值：

```text
num.parse_f64("1.5e+300") → bits 9097811302482466869（与 Python 一致）
源码字面量 1.5e300        → bits 9097811302482466870（+1 ULP）
```

因此 `format_f64` 对「源码字面量」会输出 `1.5000000000000004e+300`（对该输入
而言仍是正确的最短往返）。num 测试先用 `parse_f64` 取精确值，避免依赖编译器
字面量舍入。

**2026-10-26 已修复**：编译器字面量解析改用宿主 `strtod`（正确舍入），并新增
`tests/yh-run/run/float-literal-rounding.yh` 回归；详见 `docs/finish.md`
同日条目与 todo E1.3（E1 迁移时替换为纯 yh 实现）。

# yh V 风格编译诊断 D3–D5：旁路收编、说明行与颜色（2026-11-17）

前序：D0–D2 见 [yh-V风格诊断-D0-D2-2026-11-15.md](yh-V风格诊断-D0-D2-2026-11-15.md)。

上一轮契约列出**余项**（caret 落点收敛），本轮一并处理。

## 1. 余项：caret 落点收敛

| 位置 | 之前 | 现在 |
| --- | --- | --- |
| `19-copaque-sizeof` | caret 在调用右括号 `)` | `check.sem_sizeof_at(first_tok, …)`：caret 覆盖 `sizeof` |
| `65-comptime-diag-value` | caret 在 `)` | `parse_comptime_diag_call` 把诊断名 token 记入 `fc().c_ct_diag_first`，误用诊断落在 `$compile_error` 上 |
| `58-comptime-argument-must-be-constant` | caret 在 `)` | `sem_ident_val(idx, r, ident_tok)`：编译期常量诊断落在名字 token |
| `12-wraps-too-many` | 纯 `yh: 聚合类型登记过多（上限 512）` | `check.ty_push_agg` 上限前置检查 → `path:line:col: 错误:` + 片段 |

`check.py` 新增可量化指标 `tail_paren`（`col == 行宽` 且末字符是 `)`）与硬门
`--max-tail-paren N`；`baseline.md` 汇总同步带该字段。

## 2. D3：旁路收编与 ICE

- `errors` 新增：`err_path_pos(path[,line[,col]], msg)`（路径级，无源码可画片段）、
  `ice(msg)` / `fmt_ice`（内部错误，带版本与 issue 指引）、`set_version`。
- 迁移到 `errors` 的旁路（原「自己拼 `path:line:col` 再 `write_all(2)`」）：
  `testkit/tc_diag`、`build/api.yh`（module 声明缺失、同目录双模块、模块导入环）、
  `build/module_emit.yh`（顶层声明与导入名冲突）、`build/project_resolve.yh`（导入诊断）、
  `build/toml.yh`（清单解析）、`build/proj/api.yh`（清单诊断）、
  `build/llvm_pipeline.yh`（LLVM 桥）、`backend/llvm_module.yh`（LLVM 首片）、
  `lower/module_snapshot_lower.yh`（lowering 失败）、`check/api.yh`
  （接口头不兼容 / 缺 suffix → ICE）。
- **剩余直写只有链接器原始输出**：`compiler/link/api.yh`(5)、`link/darwin_link.yh`(2)、
  `link/windows_link.yh`(3)——它们是 ld/lld/链接器的原文，不做源码映射（规范 §6）。
- `yh test`：测试体里的编译错误走同一前台检查路径，诊断带源码片段
  （夹具 `tests/diagnostics/cases/testkit-fail/`，`command: test`）。

## 3. D4：说明行与建议

- `errors.err_span_note` / `warn_span_note` / `token.err_at_note` / `err_tok_note`；
  渲染器 `fmt_diag_note` 把 `说明: ` 行放在片段之后（无片段时紧跟头行），空说明不输出。
- `table.vk_help(code)`：18 个高频值内核码的修复建议。
- `check/ty_display`：递归渲染类型（`*T`、`[N]T`、`[]T`、`fn`、具名聚合）。
- `sem_can_assign`：说明行拼「期望 `X`，得到 `Y`；<建议>」。
- `hint_suggest_ident` / `hint_suggest_type`：有界编辑距离（≤2、名字 ≥3 字节、最多 1 个
  候选）给「是否想用 `xxx`？」，接在未声明名字与未知类型上。

## 4. D5：颜色（仅 TTY）

- `DiagCtx.color` + `errors.set_color`；驱动入口按
  `YH_DIAG_COLOR=always|never` > `NO_COLOR` > `isatty(2)`（`libs.os.is_terminal`）判定。
- 着色只覆盖头行的 `错误`/`警告` 与 caret 下划线；`ESC` 用字节 27 直接写。
- 验收：`check.py --color-check`（管道无色 / `always` 有色 / `always`+`NO_COLOR` 有色 /
  仅 `NO_COLOR` 无色）。
- 未做：多错误恢复、多行跨度（需 parse/check 错误恢复，另立方案，已留在 todo）。

## 与契约的差异

1. **D5 只做颜色**：契约已明确多错误恢复与多行跨度另行立项，本次未做，仍留 todo。
2. **ICE 没有真实触发路径的端到端用例**：以 `fmt_ice` 逐字节单测钉住格式（契约要求
   即「不依赖真实触发 ICE 的路径」）。
3. **`12-wraps-too-many` 的落点是「超限那次登记处的游标」**（声明里数组类型处），
   不是某个更精确的符号名：该路径没有更细的构造 token，按「不猜位置」原则保留游标。

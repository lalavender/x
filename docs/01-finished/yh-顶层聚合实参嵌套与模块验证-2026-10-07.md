## 一、嵌套结构体字段（递归折叠）

上一轮 `p_ct_arg_struct_literal` 对聚合字段直接返回 1（不支持）。本轮把该分支改成**递归**：

```yh
let fk int = gs.t_types[field2.type_id].kind;
if (fk == gen.TY_UNION || fk == gen.TY_ARRAY || fk == gen.TY_SLICE) { return 1; }
p_adv();
if (p_expect(gen.TK_COLON, "期望 ':'") != 0) { return -1; }
if (fk == gen.TY_STRUCT) {
    // 嵌套结构体字段：递归折叠出子对象指针 —— 执行器对聚合字段存的也是对象指针。
    let sr gen.Res;
    let sub int = p_ct_arg_struct_literal(&sr, field2.type_id);
    if (sub < 0) { return -1; }
    if (sub != 0) { return 1; }
    vals[fi] = sr.ival;
} else {
    ... 标量路径不变 ...
}
```

没有新增任何 comptime 侧接口：`ct_arg_pool_struct` 建出来的对象指针本身就可以当作聚合字段的值，
这与执行器对聚合字段的表示一致。

用例 `tests/yh-run/run/154-comptime-top-nested-arg.yh`（`// exit: 0`）：

- `Box{ tag: 7, hi: Point{ x: 5, y: 6 }, lo: Point{ x: 1, y: 2 } }` → 顶层字段乱序 + 嵌套 → 23
- `$mix(100, Box{ lo: Point{ x: 1, y: 1 }, hi: Point{ x: 0, y: 0 }, tag: 1 })` → 标量与聚合混排 → 121

## 二、模块模式验证（补第 35 轮的未验证项）

第 35 轮只在单文件模式实测，模块模式标为「未验证」。本轮在既有 84 用例项目
`tests/modules/projects/comptimecross/math/src/base/extra.yh` 里加上自包含验收：

```yh
pub struct Pair { x int; y int; }

@[comptime]
fn weigh(p Pair) int { return p.x * 10 + p.y; }

// TOP：模块模式下的顶层编译期调用，实参是结构体字面量。
pub const TOP int = $weigh(Pair{ x: 3, y: 4 });

@[comptime]
pub fn top_ct() int { return TOP; }
```

`math/src/api.yh` 加 `probe_top()` 转发，`host/src/main/main.yh` 加
`const PT int = $math.probe_top();` 并在 `main` 的断言求和中加 `+ PT - 34`（3*10 + 4 = 34）。

**结果：模块模式可用**（跨模块转发、在导入方顶层求值都通过），项目门 84/84。

踩到的坑：`extra.yh` 里第一版写的是 `struct Pair`，报
「struct/union 必须带 pub（写作 pub struct / pub union，字段一律公开）」—— yh 里结构体一律要 `pub`。

# 全局聚合常量在编译期有值（2026-10-09）

## 背景与根因

`docs/todo.md` 的编译期过程汇总把这一条列为**该方向剩下的唯一实质工作**：

> 第 46 轮（单文件下标）与第 48 轮（跨模块闭包）从两个入口撞到同一根因：
> 全局聚合常量的 `cval` 是数据段标签，数据在**发射阶段**才写出，而 CT 执行在
> **语义分析阶段**。两处都只给了明确诊断（「编译期不支持下标访问全局聚合常量」、
> 「编译期不支持使用全局聚合常量」），但都只是「说清楚」不是「做到」。

解法就是前几轮定下的方向：**在语义阶段把全局聚合常量的元素值建模成
`CtAggregate`**（局部聚合常量已经这么做），编译期读下标/字段/迭代/传参于是
复用既有聚合路径。

## 交付内容

### 1. 新的编译期模型登记（`compiler/comptime/ct_global_agg.yh`）

- `CtGlobalAgg` 登记项 + 独立的只增拥有区 `ct_global_pool`（`CtFrame`），
  元素总量由 `ct_ir_aggregate_new` 的 100000 上限兜住；
- `ct_global_agg_modelable(tid, depth)`：只有整数/浮点标量、标量元素的定长数组、
  字段递归满足同一条件的结构体才建模（指针/字符串元素、切片、联合体不建模——
  前端对它们的全局初始化要么拒绝，要么只能给数据标签）；
- `ct_global_agg_new/set/set_obj`：建对象并按字段类型预置零值（命名式字面量漏写
  的字段得到正确零值类型），写入按目标类型归一（整数截断、浮点窄化）；
- `ct_global_agg_register/lookup/reset`：按符号登记模型；同一符号重复登记（多遍
  解析）覆盖旧对象；`ct_reset` 调 `ct_global_agg_reset` 清表（对象留在只增区）。

### 2. 前端在建模型的同时发数据（`compiler/parse/parse_global_init.yh`）

`const` 聚合常量走原有发射路径不变，额外把字面量元素值填进模型：
结构体分支、嵌套结构体字段（子对象递归）、数组分支（含 f64 位模式元素）；
顶层 CT 聚合结果（`const X = $f(...)`）直接把它已有的 `CtAggregate` 登记成模型。

### 3. 编译期求值接上模型（`compiler/comptime/ct_ir.yh`）

标识符求值时，就绪的全局 `SYM_CONST` 先查模型：命中则把模型对象指针当聚合值
返回，不再返回数据段标签。此后 `TABLE[0]`、`P.x`、`BX.hi.y`、`len(TABLE)`、
`for v in TABLE`、把常量按值传给编译期函数（复制进调用帧）全部走既有聚合路径。

### 4. 顶层调用的命名聚合实参（`compiler/parse/parse_expr.yh`）

`$f(TABLE)` / `$f(P)`：实参是单个标识符、形参是聚合类型、该符号是已建模的全局
常量时，直接把模型指针填进实参（`sem_res_reset` + `is_const`），与聚合字面量
实参走同一条 `ct_call` 协议；未建模的聚合常量给出可读诊断，局部变量仍走原路径。

### 5. 取址/写入的准确诊断（`compiler/comptime/ct_ir_place.yh`）

模型元素槽的可写性检查此前会报「下标写入必须来自可写局部变量」，对
`&TABLE[0]` 这种只读取址是误导；现在基址是全局模型时改为
「编译期不支持对全局聚合常量取元素地址或写入（模型存储只供读取）」。

### 6. 顺带修复：跨模块 CT 闭包里的 for-in 绑定（`compiler/comptime/ct_registry.yh`）

`.s.ct` 闭包发射对正文逐 token 做「局部声明类型改写」；for-in 元素/下标绑定
的名字后跟的是 `in`/`,` 而不是类型声明，被误判成局部声明后找不到初始化等号，
报「无法确定 CT 局部声明的类型范围」（此前跨模块 CT 正文从没出现过 for-in，
所以从未触发）。现在 `ct_iface_local_type_target` 对这两种后缀直接跳过，
循环绑定在改写后的正文里保持原样 —— 跨模块 CT 正文由此首次支持 for-in。

### 7. 模型元素的取址与只读别名（同日追加交付）

- `&TABLE[0]` / `&P.x`（含嵌套聚合）取址可用：`ct_ir_lvalue` 对模型基址的
  下标/字段分支放行（`ct_global_agg_owns`），`ct_ir_pointer_target` 的解析链
  加一段模型区扫描（`ct_global_agg_chain`，覆盖嵌套子对象），因此指针下标
  `p[i]`、指针算术 `p + 1`、指针形参转发（`$f(&TABLE[i])` 在正文内）都可
  只读使用；
- 写入统一按只读拒绝：赋值语句对 `place.direct` 命中模型槽区间
  （`ct_global_agg_hit`，与字符串只读池 `ct_pool_hit` 同一策略）或
  `place.aggregate` 属于模型（防御，前端已拒 const 聚合直接赋值）时报
  「编译期不能写入全局聚合常量（编译期模型只读）」；
- 原 fail/152「取址一律拒绝」形态升级为 run/164 并删除，写入拒绝由 fail/153 锁定。

### 8. 切片常量同样建模（同日追加交付）

`const SLICE []int = [10, 20, 30, 40];` 现在也建编译期模型：切片常量的元素个数
只有解析完字面量才知道，模型对象改在 `parse_global_array_init` 内部按 count 创建
（`ct_obj` 改为出参；定长数组仍按类型长度在外层创建）。编译期读下标、`len`、
`for-in`、切片视图表达式（`SLICE[1..3]` 生成共享视图）都可用；空切片（count 0）
与浮点元素一并覆盖。跨模块闭包同样重放切片常量的初始化式源文本
（`iface_ct_emit_const` 的 `agg_src` 加入 `TY_SLICE`），导入侧按 count 建模。

### 9. 顶层切片实参（同日追加交付）

- **切片字面量实参** `$f([1, 2, 3])`：新增 `p_ct_arg_slice_literal` 折进编译期
  临时构造区——backing 聚合按元素个数创建（与切片常量模型同一形状），
  `ct_ir_slice_param_valid` 校验后直接别名，**无需「地址 + 长度」的独立视图表示**
  （todo 里的难点描述是旧代码的帧校验前置，现校验只要求聚合形状合法）；元素支持
  标量/结构体/定长数组递归折叠，空切片字面量合法；
- **切片常量实参** `$f(SL)` 随切片常量建模自动可用；正文内转发保持视图别名语义，
  对模型 backing 的元素写入仍被只读拦截（fail/153 同路径）。
- 聚合字面量实参的形态至此全部覆盖（联合体不存在：`union` 不是 yh 关键字）。

### 10. pub 聚合常量跨模块导出（同日追加交付）

- 解析期放行模块模式下的**字面量初始化** pub 聚合常量（结构体/定长数组/切片）；
  `$` 调用初始化仍拒绝（没有可重放的源文本）。
- `.s.i` 对聚合常量按**初始化式源文本**重放（`const_expr_kind = 4`，与 `.s.ct`
  闭包共用同一份文本）；导入侧重新解析即**编译期建模**（round-1 的建模路径天然
  覆盖接口加载）。
- 运行期在**导入方物化本单元副本**：`em_data_symbol_header` 在 `c_iface_load`
  下写本地数据标签（`.LD<n>`）并把标签号记入 `cval`；`sem_ident_val` 对
  `F_EXTERN` 聚合常量按标签装载地址（与字符串指针常量同一路径）——不与提供方
  导出的同名全局符号在链接期重复定义。
- 提供方正文（.s.ct 闭包）、消费者自己正文（.s.i 加载模型）的编译期读都可用；
  comptimecross 的 `PUB_TBL` 覆盖（见用例表）。

### 11. return 聚合字面量 + CT 调用结果求值形态（同日追加交付）

- `parse_array_literal` 的「目标类型上下文」设置点此前漏了 **return**：
  `return [1, 2, 3]`（含嵌套 `[[1,2],[3,4]]`、切片字面量）在编译期与普通函数
  里都被拒。`parse_return` 现在求值返回表达式时把 `c_expect_tid` 设为函数
  返回类型（与 let 初始化/赋值/调用实参一致；非字面量不受影响，`sem_can_assign`
  校验不变）。
- 探针确认：编译期正文里对调用结果直接求值的下标、成员、切片视图、嵌套下标、
  for-in 早已可用（typed IR 路径）。
- 边界核实：顶层 const 折叠的 `$mk()[0]` 仍不支持（折叠路径无法索引裸聚合对象
  指针），惯用 `const T = $mk(); T[0]` 经模型可用；已记 todo。

## 边界（仍未支持，已记入 todo）

- **`$` 调用初始化的 pub 聚合常量**：没有可重放的源文本，跨模块导出仍拒绝；
- **指针/字符串元素、联合体**：不建模（前端初始化本身也受限）；
- **经指针写入模型**：按只读拒绝（fail/153），与字符串只读池同一策略。

跨模块部分在 `tests/modules/projects/comptimecross` 里验证：提供方私有聚合常量
经 `.s.ct` 闭包**重放初始化式源文本**（`const_expr_kind = 4`），导入侧重新解析
即在本编译单元建模，因此「CT 正文里引用聚合常量」这条也随本次交付打通
（`priv_tbl_ct()` 的跨模块编译期读）。

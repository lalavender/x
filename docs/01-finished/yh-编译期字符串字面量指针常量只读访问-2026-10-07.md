# 编译期字符串字面量指针常量只读访问

日期：2026-10-07。状态：已完成。方案：[yh-编译期字符串字面量指针常量只读访问实施方案](../02-plan/yh-编译期字符串字面量指针常量只读访问实施方案.md)。

## 背景

编译期函数能持有并传递字符串字面量指针常量，但解引用与下标读取被拒绝：
CT 指针解析只认存活调用帧内的标量槽，而字符串字面量指针的值是数据标签号。

## 改动

| 位置 | 改动 |
| --- | --- |
| `comptime/ct_00_model.yh` | 新增 `CtPoolSpan`（池区间 `addr`/`count`/`elem`）与全局池表；新增与 `ct_ir_exprs` 并行的 `ct_ir_expr_pool`/`ct_ir_expr_pool_cap` |
| `comptime/ct_ir.yh` | `ct_ir_grow` 新增第 5 类 arena；`ct_pool_register` 解码字符串 token（与后端 `.data` 相同的转义规则）并分配只读槽池；`ct_ir_register_string_pool` 在 `ct_ir_import` 里按「`is_const` + `*char`/`*u8`/`*i8` + 单个 `TOK_STRING` + 同批次 `token_count`」登记；`ct_ir_eval_expr` 的 `is_const` 分支优先返回池地址；`ct_pool_hit` 判定地址是否在池内；`ct_pool_reset` 随 `ct_reset` 释放 |
| `comptime/ct_ir_place.yh` | `ct_ir_pointer_target` 在存活帧链之后追加池区间查询（元素类型须一致）；`ct_ir_lvalue` 开头统一把 `place.direct` 置 0，避免未初始化字段影响写保护判定 |
| `comptime/ct_ir.yh` | 赋值语句在解析出位置后拒绝写入池（读与写共用 `ct_ir_lvalue`，保护必须落在赋值处） |

字符串字面量的字节按「每字节一个 `CtValue` 槽 + 末尾 0 槽」存放，指针直接指向池首槽，
于是既有的解引用、下标与指针算术路径全部复用，无需区分指针种类。

## 复用约束与边界

- 池区间只读：写入在赋值语句统一拒绝；`&p[0]` 沿用既有取址拒绝路径。
- 顶层/普通函数里的 CT 调用实参（`const N int = $f("abc");`）仍不支持字符串字面量指针
  常量：实参由前端直接求值成数据标签号，不经过 typed IR 捕获。函数体内构造再按形参传递
  是支持路径。
- 跨模块转发正文在导入方重新解析，导入方持有自己的 `c_src`/`c_toks`，池登记照常生效；
  `comptimecross` 的 `first_letter` 锁定该行为。
- 全局数组地址等其他指针常量、指针元素聚合仍未支持。
- 教训：给 `CtValue` 增加字段会踩未初始化风险（`let v CtValue;` 后逐字段赋值），
  本片改用「复用既有指针语义 + 并行地址表」，避免新增值字段。

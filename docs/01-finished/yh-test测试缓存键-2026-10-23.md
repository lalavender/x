# yh test 测试构建缓存键（YT2d-2）实施记录

日期：2026-10-23。范围：让测试构建可以增量复用**测试对象**，同时保持与生产
构建完全隔离。函数级 IR 缓存与 check 切片缓存仍未用于测试构建。

## 背景

rc.2 为了让「先 `yh build` 再 `yh test`」正确工作，测试构建一律绕过了三层缓存
（模块 manifest、函数级 IR、check 切片）——正确但没有增量，`yh test` 每次都
重编所有选中模块。本片恢复**模块级**缓存。

## 交付

- `compiler/gen/state.yh`：新增 `c_test_key u64`（本轮选中测试集合摘要）。
- `compiler/cmd/test_cmd.yh`
  - 发现完成后计算 `tc_test_key`：对每个用例混入 `模块/文件声明号/种类/是否选中`
    四个 32 位字段（FNV-1a），写入 `c_test_key`；
  - 该摘要只依赖**构建输入**（选中的测试集合），不依赖 `--filter`（过滤只影响
    执行，不改变构建范围）。
- `compiler/cmd/module_build.yh`
  - `mb_compile_start` 不再对测试模式强制绕过缓存；
  - manifest 键在既有字段之后混入：`'T' 'S'` + 协议标签 `yh-test-key-1` +
    `c_test_key` 的 8 字节。
  - 测试构建目录仍是 `<项目>/tmp/yh-test/check`（生产是
    `.build/targets/<triple>/llvm/O<n>`），两种构建的对象/接口天然不共享路径。
- `compiler/cmd/build_scheduler.yh`：测试构建也提交 manifest（写进
  `tmp/yh-test/check/manifest`）。

## 语料与门禁

- `tests/modules/test-check.py` 增至 34 项：
  - `test-build-cache-hit`：同一夹具第二次 `yh test` 输出 `[缓存]` 且结果不变；
  - `test-cache-selection-isolated`：把选择从「模块 app」改成「单文件
    more.yh」后必须重新 `[编译] app`（集合摘要变化 → 键失效）；
  - 既有 `test-after-production-build` 继续保证先生产构建再测试仍然正确。

## 验证

- 手工：`ytestparallel` 第二次运行 `[缓存] app` / `[缓存] yh_test_app`；
  `ytest` 先 `yh test app` 再 `yh test src/app/more.yh` 触发重新编译。
- `make test`（`FAST_DIR` 固定到仓库 `tmp/`）：语法 81/81、49/49；
  run 211/212、fail 136/136、pass 9/9；`test-check` 34/34；string 内建 5/5；
  `compiler-tests 3/3`；TOML 6/6；代码统计 6/6。
- `make selfhost-native`：30 个模块产物固定点一致、cc4 自解析 114 个源文件、
  `compiler-tests 3/3`、project cases 121/121。

## 边界与运维提示

- 函数级 IR 缓存与 check 切片缓存**仍不用于**测试构建：它们的键只建模
  `TK_FN` 声明，不覆盖 `test` 声明；若要启用需先扩展键与切片格式（另立项）。
- 测试构建目录不按 target 细分（同一项目的 Darwin/Linux 测试构建共用
  `tmp/yh-test/check`）。键里含 target，不会误命中，但交替跨目标构建会互相
  冲刷 manifest，失去部分增量收益。
- 本机 gate 偶发失败来自 macOS 对 `$TMPDIR`（`/var/folders/...`）的清理，
  不是编译器问题；把 `FAST_DIR` 指到仓库 `tmp/faststage` 后稳定复现全绿。

# 跨模块编译期单字节指针形参的错值修复

日期：2026-10-07。状态：已完成（按形参类型拒绝；支持路径待立项）。

## 背景

上一轮把「跨模块编译期调用的直接字符串字面量实参」按字面量形式拒绝。本轮按
`docs/todo.md` 的立项继续排查，实测发现**问题比字面量形式更宽**：换成模块内的
指针常量实参同样错值。

```yh
// math/api.yh
@[comptime] pub fn head_of(text *char) int {
    return text[0].to_type(int) * 1000 + text[1].to_type(int);
}
// host/main.yh
const MINE *char = "AB";
const HEAD int = $math.head_of(MINE);   // 期望 65066，实际 104105
```

实测证据（临时放开两处守卫后运行）：

| 调用形式 | 结果 | 说明 |
| --- | --- | --- |
| `$math.head_of("Z")` | `104` | 期望 90；104 = `'h'` |
| `$math.head_of("AB")` | `104105` | 期望 65066；104105 = `'h'`、`'i'` |
| `const MINE *char = "AB"; $math.head_of(MINE)` | `104105` | 同上 |

三种形式都读到同一段字节 `"hi"`（同项目里另一个编译期函数用到的字面量），
说明**不是**字面量实参特有的问题：跨模块调用的实参值来自提供方编译单元，
编译期侧按标签号在本地只读池映射里反查时命中本地无关字面量。同一项目里
`*int` 形参的跨模块写回（`write_back(&acc, 22)`）正常，因为整数指针不走字节池。

## 修复

拒绝范围从「字面量实参」扩到**按形参类型**：编译期调用是模块限定形式
（`$mod.fn(...)`）且对应形参是单字节指针（`char`/`u8`/`i8`，即会走只读池的类型）时
直接报诊断，与实参写法无关：

```
跨模块编译期调用不支持单字节指针形参（char/u8/i8）：实参的字符串来源无法跨编译单元解析，请改用模块导出的 pub const 指针常量
```

模块导出的 `pub const X *char = "..."` 常量仍是支持路径（接口原样重放声明，
导入方重新登记），`comptimecross` 的 `TEXT`/`exported_letter` 覆盖该路径。

## 遗留

真正支持该写法需要让实参的字节来源随调用跨编译单元传递（或在调用方求值后随调用
携带），已记入 `docs/todo.md` 的 CT5B，并附上本轮实测证据。在此之前保持拒绝，
避免静默错值。

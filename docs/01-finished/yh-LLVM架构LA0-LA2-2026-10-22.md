## 2. LA0：冻结入口行为

新增 `tests/modules/projects/llvmarchitecture/`：

- `src/main/main.yh` + `src/main/helper.yh` + `src/util/helper.yh`：
  单文件入口、同模块跨文件调用、跨模块调用与项目构建；
- `cases/entry.yh`：自包含单文件入口，`product(6, 7)` 返回 42；
- `cases/library.yh`：无 main 的库，含编译期函数与布局常量；
- `cases/invalid.yh`：未声明名字，保留路径/行/列诊断；
- `cases/forward.yh`、`cases/badmain.yh`：前向调用与错误 main；
- `cases/lowering.yh`：嵌套循环/continue/break、switch、goto、聚合副本、取址、
  函数指针与编译期展开来源；
- `cases/semantics.yh`：窄整数、bool 字节、移位、转换、聚合/切片别名；同一
  规则在编译期函数与运行期各执行一次，O0/O2 运行与 LLVM 文本对照。

新增 `tests/selfhost/llvm-architecture.py`：

- `--case entries|check|lowering|all`、`--opt-level 0|2`、
  `--baseline-compiler`、`--save-baseline`、`--self-test`；
- 工作目录含中文/空格，argv 调用并收集 stdout/stderr/文件清单；
- 失败发布回归：成功构建后注入源码错误，旧程序与 `*.manifest` 必须不变，
  无残留临时文件；恢复后重新构建运行；
- check 在无工具 PATH 下不生成 LLVM/对象/程序；项目 check 不留下 `.build` 文件；
- oracle 自检：入口返回 41 时 harness 必须失败，恢复后通过；
- 已接入 `Makefile` 的 `selfhost-native`。

基线保存在 `tmp/llvm-architecture/baseline/O0|O2/`（不入库）。

## 3. LA1a：统一快照到产物驱动

新增 `compiler/cmd/llvm_pipeline.yh`，提供：

```text
llvm_prepare_module(unit, mod_ir, output)
llvm_emit_module_to(unit, kind, out_path, text_path, stats)
llvm_emit_text_only(unit, text_path, stats)
```

- 单文件与项目 worker 共用 prepare、Darwin 部署元数据、桥调用、临时文件写入、
  对象 machine 校验与 rename 原子发布；
- 快照由调用方独占并释放；成功交出模块 IR/LLVMOutput，失败释放候选并保持
  出参为零；
- 统计只在成功发射后累计一次；桥失败统一按模块首个符号映射来源位置；
- `module_worker.yh` 只保留模块前端、快照校验与接口/缓存编排。

## 4. LA1b：单文件 check 与编译共用受检前端

- `compiler/cmd/llvm_emit.yh` 新增 `llvm_check_single_file(path, require_main, out)`；
  `run_file_check` 与 `llvm_emit_single_file` 都经该入口获得 CheckedModule；
- `gen.sem_check_main_common(require)` + `sem_check_main_optional()`：库文件
  check 允许 main 缺席，但已有的 main 仍必须满足与编译相同的签名规则；
- 删除失去消费者的 `compiler/cmd/compile.yh` 与 `sem_compile`；
- 库 check 不生成后端产物，正式构建缓存不被覆盖（`check-command.py` 通过）。

| 文件 | 函数数 | 职责 |

| `module_snapshot_lower_expr.yh` | 24 | 标量表达式、条件、三元、整数提升与转换 |
| `module_snapshot_lower_call.yh` | 6 | 实参、副本、类型化变参、直接/间接调用 |
| `module_snapshot_lower_flow.yh` | 24 | if/循环/switch/label-goto 与 phi 合流 |

## 6. LA2b：模块准备与逐函数构造

`lower_module` 现在依次调用私有 helper：

```text
checked_lower_prepare_tables(l, types)   // 类型/来源/静态数据/全局
checked_lower_declare_functions(l)       // 按原顺序登记运行期签名
checked_lower_build_functions(l, types)  // 按原顺序逐函数构造
checked_lower_release(l)                 // 只释放本次上下文
```

保留公开入口 `ast.lower_module`。新增 `llvmlower` fixture：

- `input/mutual.yh`：互递归 + 函数内字符串（4 个函数，verifier 通过）；
- `input/shadow.yh`：同函数嵌套作用域同名绑定（1 个函数）；
- `input/failmid.yh`：中间函数 lowering 失败，验证不交出半成品模块。

## 7. LA2b 函数依赖/贡献清单（LA3 输入）

`checked_lower_build_functions` 的注释已封存函数级输入事实；LA3 缓存单元至少包含：

| 类别 | 当前来源 | 是否进入函数键 |
| --- | --- | --- |
| 签名 | 模块符号 + 返回/参数模块类型下标、ABI、variadic、linkage、no_return | 是 |
| 类型布局 | `private_type_map`、`function_type_map`、目标 key、快照布局事实 | 是 |
| 符号/常量 | `global_map`/`static_map`/`string_map`、`checked_lower_name` 稳定命名 | 是（按实际读取） |
| 调用/副本策略 | 快照签名 ABI、`checked_lower_is_aggregate`、call 缓冲 | 是（按实际读取） |
| 编译期事实 | 已展开的 AST/CheckedModule；本阶段不再求值 | 是（展开结果/依赖） |
| 匿名全局/重定位 | `static_data` 行、按 label 去重字符串、模块 global reloc | 是（函数贡献闭包） |
| 来源 | `source_map`、函数 locs、token 偏移 | 否（命中后按当前源码重建） |
| 其他函数体 | 不进入单函数 lowering | 否（模块键才覆盖） |

本步只建立边界与记录，不读写缓存；函数级 check 复用、IR 序列化与重绑定仍是 LA3。

## 8. 已知缺陷

LA0 复现：含 `goto`/`label` 的函数中，函数指针绑定按内存驻留处理时生成
`alloca void`，LLVM 拒绝。已在 `docs/todo.md` 单列 D1；LA0 fixture 将 goto 与
函数指针放在独立函数，未降低断言，也未在本轮顺带修复。

## 9. 后续

LA3 函数 IR 复用、LA4 文件对象、LA5 线程池仍按方案分别接 J1/J2/J4。
第一包的函数接缝只提供 prepare/declare/build/release 边界，不包含函数缓存、
跳过函数 check 或对象级增量。

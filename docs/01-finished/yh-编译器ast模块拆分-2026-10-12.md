# 编译器 AST 模块拆分（2026-10-12）

## 背景

用户决定：**接下来开发主要集中在 Linux 平台，其他平台后接入**；并优化编译流程，
把 **AST 过程单独提出来放在 `ast` 目录**。

拆分前 `compiler/parse/` 同时存放语法分析器（`parse_*.yh`、`iface*.yh`）与 AST 阶段
（`ast_*.yh` 共 11 个文件）。yh 的编译单元是**模块**，因此 AST 与语法分析共用一个
编译单元：`yh-parse.s` 3.31 MB 为最大单元，AST 部分约 1.13 MB，两者无法并行，
任何 AST 改动都要重编整个 parse 单元。

设计与取舍见[设计文档](../03-design/yh-编译器ast模块拆分设计.md)。

## 改动内容

1. **新增模块 `compiler/ast/`**：`ast_decl`、`ast_expr`、`ast_stmt`、`ast_function`、
   `ast_ir`、`ast_ir_build`、`ast_ir_call`、`ast_ir_control`、`ast_ir_inline`、
   `ast_ir_template`、`ast_ir_cache` 共 11 个文件由 `parse/` 迁入，模块声明
   `module parse;` → `module ast;`。
2. **调用点加限定**：parse/cmd 中 80 处 `ast_*` 调用改 `ast.ast_*`，50 处
   `AST_EXPR_*`/`AST_STMT_*` 常量改 `ast.AST_*`；cmd 中原有的 `parse.ast_*`
   同步改 `ast.ast_*`（`compile.yh`、`module_worker.yh`）。
3. **解环**：`is_assign_op` 自 `parse/parse_type.yh` 迁入 `gen/buffer.yh`
   （与既有 `err_tok` 同一先例），`parse_stmt.yh` 与 `ast/ast_stmt.yh` 改调
   `gen.is_assign_op`。
4. **跨模块状态访问函数**：`let` 不导出，AST arena 的 7 个跨模块状态与语句节点
   `first_child` 字段改为 12 个 `pub fn` 访问函数（`ast_expr_count_now`、
   `ast_stmt_current_now`、`ast_stmt_node_op_set` 等），parse/cmd 侧约 33 处调用点
   同步改写；`pub struct` 字段已一律公开，结构体声明未改。
5. **新增模块 import**：`parse_decl`、`parse_expr`、`parse_stmt`、`parse_comptime`、
   `parse_global_init`、`iface_ct`、`cmd/compile`、`cmd/module_worker` 补
   `import ast;`。
6. **新增 `.yh` 用例**：`tests/modules/projects/modstate/`
   （`lib` 私有 `let` arena + `pub` 访问函数，`host` 正向运行，`host2` 反向拒绝），
   并在 `tests/modules/build-check.py` 增两条用例
   `u3-private-let-accessor`（run，退出码 7）与 `u3-private-let-access`
   （fail，诊断「模块没有导出该名字」），锁定「模块私有可变状态只经 pub 访问函数
   共享」这一约定。

## 验证（Linux，WSL2 Ubuntu x86_64 + qemu-user/binfmt）

环境（仓库内既有重建记录的前置条件，见
[WSL 种子链记录](yh-WSL重建Linux-aarch64自举种子-2026-10-09.md)）：

```bash
export PATH="$PWD/tmp/boot/crossbin:$PATH"   # gcc → aarch64-linux-gnu-gcc
export SEED=bin/yh-linux-arm64              # x86_64 宿主没有 x64 种子
export YH_LINK=/nonexistent                 # 仓库根 yh_link 是 Mach-O，强制回落交叉 gcc
```

| 步骤 | 结果 |
| --- | --- |
| `make` | 冷编产出 `yh`（8 个模块：ir/lex/backend/comptime/gen/ast/parse/main） |
| `make test` | ANTLR 层正例 76/76、反例 45/45；编译器语法模式正例 76/76、反例 45/45；运行语料 **292/292**（run 152、fail 132、pass 8） |
| `make selfhost-native` | 自举快照门自检 OK；模块固定点 cc3→cc4 **24 个产物逐字节一致**；cc4 自解析 71 个源文件 OK；固定点探针 OK；CLI 冒烟 OK；语法语料反例 45/45；运行语料 292/292；并发项目扫描 8/8；前端快照复用通过；自有运行时通过；`yh check` 通过；modules **17/17**；项目验收 **86/86**（含本轮新增 2 例） |

失败信息均无新增；`make selfhost-native` 中 `scratch-isolation` 若不带
`YH_LINK=/nonexistent` 会命中既有 WSL 环境问题（汇编步找到仓库根的 Mach-O
`yh_link`，报 `/…/yh_link: 1: Syntax error`），与本次改动无关，见
`docs/todo.md` 的「编译器汇编步查找名切换」。

## 滚种子

`make test` 与 `make selfhost-native` 全绿后滚动 Linux 种子（x86_64 宿主必须显式
`SEED_DEST`，否则 Makefile 会写到不存在的 `bin/yh-linux-x64`）：

```bash
SEED=bin/yh-linux-arm64 SEED_DEST=bin/yh-linux-arm64 make seed
```

- 旧种子 SHA-256：`137c5fdb1ab3b6559cc16b50e54127c72ee2b4a161744665655362ff6de76f2c`
- 新种子 SHA-256：`3eeae70428769831f1f65f21776328083f36eec143bd9e240e318a95d059aebe`
  （`bin/yh-linux-arm64` 与其 `.sha256` 已同步更新）
- 滚种子后用新种子复跑 `make selfhost-native`：模块固定点 cc3→cc4 仍为 24 个产物
  逐字节一致，其余门全绿（种子可用）。

说明：`make seed` 后「新种子复编产物」与种子**二进制**不同字节，这是既定的验收
口径——固定点比较的是模块 `.s`/`.s.i`/`.s.ct`
（[编译器源码模块化设计](../03-design/yh-编译器源码模块化设计.md) §6
「链接后二进制需要可运行，不默认要求逐字节相同」）；本流程按该口径验收。

## 观察与遗留

- `tests/yh-run/check.py` 的汇总行在 Linux 上仍打印「（Darwin Mach-O）」，
  是测试脚本的平台标签硬编码，属既有小瑕疵，本次未改。
- `ast` 模块的导出面目前偏宽（全部 `pub struct` 与部分仅模块内使用的 `pub fn`），
  与 `docs/todo.md`「接口 pub 收缩」一并处理。

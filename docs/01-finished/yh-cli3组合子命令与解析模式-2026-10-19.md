## 目标

补齐组合能力：子命令槽与子 parser 所有权、别名与规范命令路径、
父子默认值合成、`inherit` 深复制、展示组与互斥组、组级冲突策略，
以及 `parse_known` / `parse_intermixed` / `parse_with` 与初始命名空间。

## 已实现的行为

- **子命令**：`add_subparsers` 每 parser 最多一个槽；`add_parser` 返回归父所有、
  可继续 `add_argument` 的子句柄；别名只影响匹配，`Result.command_path` 保存规范名；
  `Subparsers.dest` 非空时把选中命令名写入 namespace；`required=true` 未选命令报
  usage_error；未知子命令即使 known 模式也报错。
- **分层解析**：选中子命令后剩余 token 全部交给子层；根选项只在子命令前有效；
  整次解析共享一个结果命名空间，显式 action 即时写入。
- **默认值合成**：解析结束后按「父 → 子」顺序应用默认值；子层默认覆盖父层默认，
  但不覆盖显式值与 `initial`；父层显式值不会被子层默认值改写。
- **inherit**：深复制参数、默认值、`set_default` 覆盖、展示组与互斥组，
  组/互斥 ID 重新映射；不复制 prog、输出策略或子命令树；禁止自继承。
- **展示组**：`add_group` + `Argument.group`；组级 `argument_default` 参与默认值层级；
  组级 `conflict=resolve` 优先于 parser 级策略。
- **互斥组**：`add_mutex` + `Argument.mutex`；默认最多一个成员显式出现，
  `required=true` 时恰好一个；默认值与 initial 不满足也不造成冲突；
  成功识别 help/version 后跳过互斥检查。
- **冲突策略**：`Conflict.resolve` 下重复名称从旧声明移除；名称全部移除的旧声明停用
  （不再参与匹配/展示/必需项/互斥），旧 ID 不复用；位置参数重名一律拒绝。
- **parse_known**：未知选项与未分配位置 token 按输入顺序进入 `Result.unparsed`；
  未知短组合整 token 保留、不部分提交；已识别但缺值/坏值仍是错误；
  缺少必需项、坏值与互斥冲突不会被 known 放宽。
- **intermixed**：先收集位置 token 再整体匹配；拒绝子命令、remainder、
  同一 dest 同时由选项与位置提供、同时含选项与位置成员的互斥组（config_error）。
- **initial**：`ParseConfig.initial` 深复制进结果；默认值不覆盖已有键，
  显式 action 覆盖它；调用者的命名空间不被修改。

## 已知边界

- 位置参数与子命令槽的相对顺序固定为「位置参数在前、槽在后」；当前实现不提供
  「槽后父级位置参数」的声明（设计禁止该组合），freeze 未额外诊断。
- 混合模式的位置 action 在选项之后统一提交；因此同一 dest 同时由选项与位置提供时，
  实现选择明确拒绝（config_error），而不是给出与原始 token 次序不一致的结果。
- 进入子 parser 前的 `initial` 已知键形状/choices 检查留给 CLI4 的 validator 一起实现。

# S3 spike：语义字段外置（真两遍化）的可行切片

状态：调研完成，**待收益决策**（2026-11-08）。上游：
[前端两遍化重新分析](yh-前端两遍化-重新分析-2026-11-08.md) §4 的 S3。

## 1. 目标（S3 的判据）

让 `parse` **只填语法字段**，语义字段（类型/常量性/常量值/符号绑定）由 `check` 在
遍历 AST 时写入。`AstExpr`/`AstStmt`/`AstBinding` 的**结构不变**，因此 `lower` 的
257 处读点、`CheckedModule` 快照格式、`.s.ct` 编码都不变——这是 S3 与 S4 的关键区别：
S3 只改「谁写这些字段」，不改「字段长什么样」。

完成后 `parse` 不再 import `check`，随即解锁 S2b（布局调度整体下沉 `check`）。

## 2. 现状实测（2026-11-08，S2a 之后）

`parse`：7,580 行 / 13 文件。

- 对 `check.sem_*` 的调用：**142 行**（按行计，一个调用行可能含多个调用；
  `sem_can_assign` 19、`sem_push_value` 11、`sem_binop` 8、`sem_res_copy` 6、
  `sem_call` 3、`sem_unary` 3 等）。已加 `arch-check` 预算
  `max_parse_check_calls: 142`（只减不增），作为 S3 的进度度量。
- `Res` 字段读取：**370 处**，其中**控制流决策 167 处**，按构造归类：

| 构造 | 决策点 | 能否延后到 `check` | 说明 |
| --- | ---: | --- | --- |
| 常量值（`ival`，折叠/长度/判别值） | 22 | 部分 | `$if`、`[N]T` 必须 parse 期已知；纯值折叠可延后 |
| 常量性（`is_const`） | 20 | 部分 | 同上：驱动 `$if`/`$for` 与「必须是常量」诊断 |
| 隐式转换（`sem_can_assign`） | 18 | **是** | 纯校验，不改变语法树走向（三元除外） |
| 类型编号（`type_id`） | 17 | 否 | 字面量定型、运算符结果类型、指针/数组元素类型都要立即用 |
| 编译期诊断（`ct_diag*`） | 8 | 是 | 已设计为「语句位置消费」，天然可延后 |
| 符号（`sym`） | 6 | 否 | 名字解析决定后续 `.`/调用形态 |
| 字面量性（`is_lit`/`lit_big`） | 4 | 否 | 参与窄化判定与类型选择 |
| `sizeof` 布局依赖 | 1 | 否 | 需要登记布局请求 |
| 浮点位型 | 1 | 是 | 纯值 |

结论：**「全量纯语法 parse」仍不可行**（`type_id`/`sym`/`is_lit` 是语法决策的输入），
但存在三个可独立落地的切片。

## 3. 三个切片（按风险从低到高）

### S3a 隐式转换校验后移（最安全，推荐先做）

- **搬什么**：`parse` 里 18 处 `check.sem_can_assign(...)` 中**不做结果类型选择**的
  16 处：`let` 初始化、赋值、`return`、调用实参、数组/结构体字面量元素、全局初始化、
  `@[comptime]` 范围检查。
- **怎么搬**：`check` 增加一趟 `check.walk_convert(view)`，在 `verify_module` 之前跑；
  目标类型从 AST 取（`AstBinding.sym_type_id`、函数声明 `type_id`、字段 `type_id`），
  实参类型/字面量标志从 `AstExpr` 取（parse 仍然填这些字段，S3 只改「校验在哪做」）。
- **风险**：诊断**时机与顺序**变化（原来在扫描到该构造时立即报，改为全部解析完再报），
  多错文件的错误顺序/条数可能变。`tests/yh-run/fail/*` 断言的是消息+位置，不看顺序，
  但要跑全量确认；三元表达式两处（`parse_expr.yh:209/215`）**必须留** parse（它用结果
  类型决定节点类型）。
- **规模**：parse −≈60 行、check +≈120 行；行为等价可逐例对比。

### S3b 编译期诊断延迟消费（中等）

- **搬什么**：`ct_diag*` 8 处决策。现在 parse 在「语句位置」消费 `$assert`/`$compile_*`
  的结果；该判断依赖「当前表达式是否整条语句」，是语法信息，但**诊断的发出**可以
  改为记录到语句节点、由 check 在语句边界统一发。
- **规模**：parse −≈40 行、check +≈80 行。
- **收益**：错误可以带「语句的完整 token 区间」，为「多诊断/错误恢复」铺路。

### S3c 纯值折叠后移（收益最小，最后做）

- **搬什么**：把「非长度、非 `$if` 条件」的常量折叠（`sem_binop`/`sem_unary` 的 11 处）
  改成记录运算符节点、由 check 折叠；`is_const`/`const_bits`/`fval_bits` 由 check 写。
- **难点**：折叠结果会被后续语法决策读取（如 `a + b` 作为 `[N]T` 的 N）——这类必须
  parse 期可算。因此只能搬「不在长度/条件位置」的折叠，判定本身要先在 parse 做
  上下文标记（`c_ct_target_ctx` 已有类似机制）。
- **规模**：parse −≈150 行、check +≈250 行；风险最高（折叠语义与诊断）。

### 不做的事

- 不引入独立 checked IR（S4）：`lower` 257 处读点 + 快照格式 + `.s.ct` 编码都要改，
  收益只在「诊断/增量/IDE」有硬需求时才成立。
- 不让 `parse` 完全不认识类型：`type_id`/`sym`/`is_lit` 必须保留（见 §2 表）。

## 5. 验收方式（每切片）

1. `just` + `just test`（370/372）+ `just selfhost-native`（固定点 + 语料 + project cases）
2. `comptimecross` 的 `.s.i`/`.s.ct` **逐字节一致**（S3 不改发射内容）
3. **诊断差分**：对 `tests/yh-run/fail/*` 全量比较「消息 + 文件:行:列」集合；

4. `arch-check` 8/8；每切片收紧一条预算（如 `max_parse_check_calls`，只减不增）

## 5.1 关键技术点：S3a 如何保持诊断逐字一致（已核实）

S3a 的唯一实质风险是「诊断从 parse 期移到 check 期后，位置/文案变了」。核实结论：
**可以用 AST 里已有的信息完全复现**，不需要给结构体加字段。

1. **位置**：parse 的 `sem_can_assign` 走 `sem_err` → `token.err_tok`，用的是**当时
   的 token 游标**。而 `ast_expr_finish` 恰好把 `after = token.ctx().pos` 写进节点，
   且在 `sem_can_assign` 调用前后游标不再移动 —— 所以
   `token.ctx().tokens[expr.after]` 就是原诊断位置，**可从 AST 精确还原**。
2. **文案**：`sem_can_assign` 已经是「值内核返回错误码 + `check.value_kernel` 用
   `token.err_tok(vk_msg(code))` 格式化」，所以 check 侧只要复用同一个映射即可得到
   逐字相同的中文消息。
3. **文件上下文**：多文件模块下，check 期当前 token 表可能已是别的文件。因此不能直接
   用 `token.err_tok`，需要一个「按 file_id 报告」的薄口：
   `check.diag_at(file_id, line, col, code)` → `support.err_lc` 前先按
   `proj.file(file_id)` 切换 `src_ctx().path`（或直接拼 `path:line:col`），报告后恢复。
   这是 S3a 需要新增的**唯一**基础设施（≈25 行）。
4. **顺序**：parse 遇到第一个转换错误就 `return -1`（后续不再解析）；改成后置趟后，
   同一文件可能报出多个转换错误。`tests/yh-run/fail/*` 只断言「消息 + 文件:行:列」
   的出现，不看顺序与条数，但**必须跑全量确认**；若某例依赖「只报第一个」，S3a 可以
   在 check 趟里「首个错误即停」以保持行为（代价是放弃多诊断，可后续再放开）。

结论：S3a 可以先做**「首个错误即停」的等价搬迁**（行为完全不变、诊断逐字一致），
之后若要「一次报多个」再单独开一个行为变更切片。

## 6. 需要决策

1. **收益**：S3a–S3c 的收益是「诊断可延后 → 为错误恢复/多诊断/增量检查铺路」。
   当前没有这些需求的话，S3 可以只做 S3a（纯校验后移，风险最低）。
2. **是否接受诊断顺序变化**：S3a 会让「先解析完再报转换错误」，与今天「边解析边报」
   不同。若不可接受，S3 就只剩 S3b（诊断延迟消费，顺序不变）。

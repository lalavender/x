# yh 编译器性能基线（PF1b 正式口径）

日期：2026-10-26。状态：**已完成**，对应 [性能测试方案](../02-plan/yh-编译器性能测试方案-2026-10-23.md)
的 PF0/PF1 正式化（PF1b）与「产物质量」首期。

## 1. 结论

以**第四批 `20261026-204539`** 为准（与最终语料、最终工具状态一致；Darwin/arm64，8 核，
start load1 6.49）：四场景各 20 轮、3 轮不计分预热，整批 `validity=ok`（无失败/超时/缺统计），
另有三个负向路径留证（§3.3）。四批同口径复核见 §5：

| 场景 | 中位 ms | p95 ms | MAD ms | load1 中位/峰值 | IR 命中/未命中 | check 命中 |
| --- | --- | --- | --- | --- | --- | --- |
| 冷编（清 .build） | 10070.1 | 10428.3 | 42.7 | 4.37/5.29 | 0 / 1470 | 0 |
| 全量重编（改接口常量，含写缓存） | 16781.5 | 17463.4 | 396.6 | 4.63/5.67 | 0 / 1352 | 0 |
| 热编（无改动） | 977.3 | 1014.2 | 3.9 | 4.81/4.97 | 0 / 0 | 0 |
| 单函数改动（私有函数体） | 3577.4 | 3682.7 | 35.4 | 3.84/4.71 | 204 / 1 | 38 |

四批中位数的最大差异为 +2.2%（§5），即本机噪声下限约 2%：±2% 以内的变化不能当回退。

父进程阶段耗时（中位）：冷编 project 186.9 / schedule 8178.7 / object 519.7 /
link 1143.2 / total 10046.6 ms；热编 schedule 仅 28.4 ms 而 object 508.3 + link 262.6 ms
（≈80% 时间在发射与链接，调度几乎不做事）；单函数改动 schedule 1701.6 + link 1165.0 ms，
印证「模块级 `.o` + 每轮整模块 LLVM 发射」是 ≤3 s 的瓶颈（PC7 函数级目标文件仍待做）。

生成产物质量（6 个用例 × O0/O2，每档 5 轮，checksum 由 Python 参照独立计算，且每个用例
在缺省输入下自校验一次，12/12 相符）：

| 用例 | 输入 | O0 中位 ms | O2 中位 ms | O0 .text B | O2 .text B | 只读 B(O2) | 文件 B |
| --- | --- | --- | --- | --- | --- | --- | --- |
| bench-loop-sum | 50000000 | 506.5 | 187.0 | 3232 | 1700 | 0 | 50256 |
| bench-array-scan | 20000 轮 | 238.2 | 57.0 | 4180 | 1912 | 0 | 50304 |
| bench-sort-insertion | 1800 轮 | 464.6 | 52.4 | 5304 | 2220 | 16 | 50336 |
| bench-hash-fnv | 36000000 B | 455.7 | 51.2 | 4076 | 1724 | 0 | 50256 |
| bench-struct-slice | 16000 轮 | 149.7 | 55.1 | 4840 | 2168 | 0 | 50336 |
| bench-call | 39 | 343.5 | 192.3 | 3104 | 1752 | 0 | 50288 |

O2 相对 O0 的运行时间快 1.8×–8.9×，代码段小 1.77×–2.39×；文件大小几乎不变（~50 KB
是 Mach-O 头、页对齐与链接元数据开销），所以「用整个文件大小代表代码质量」不可取，
报告一律以 `.text` / 只读数据分段呈现。编译器自身 70,814,624 字节（静态链接 LLVM）
单列，不计入产物代码质量。

## 2. 口径与可追溯身份

- **语料**：冻结 `compiler/`，120 文件、2,266,178 字节，
  SHA-256 `23399306220850c552d71306d5462d03a31fed038c536548a3e92e0ca2d366a6`
  （`tools/perf-baseline.py` 的 `digest_tree`：只算 `.yh` 与 `project.toml`，先按相对
  路径排序再拼 `路径\0内容`；排除 `tmp`/`.build`）。每次测量复制到
  `tmp/perf/baseline-work/a/compiler`，不读工作区改动。
- **编译器**：仓库根 `./yh`，70,814,624 字节，
  SHA-256 `1f59f0c92b95c5aec0cda343d5fc11cbfe225b2211d6bfa0979fb21d41030542`
  （与 `raw.json` 的 `compiler_a.sha256` 相同，可 `shasum -a 256 yh` 复核）。
- **机器**：`macOS-27.0-arm64-arm-64bit-Mach-O`，target `Darwin/arm64`，8 核。
- **轮数**：每场景 20 轮 + 3 轮不计分预热；单轮超时 1800 s；load1 逐轮记录
  （四批峰值 5.36 / 6.60 / 7.47 / 5.67，均在 8.0 告警线内）。
- **顺序**：本轮单编译器、无 A/B 交错。四个场景按组依次跑完 20 轮
  （cold → full-rebuild → hot → one-function），场景内轮次连续；没有随机化或交错，
  因此只看场景内部的 median/MAD，不跨场景比较。
- **原始数据**（tmp/ 不入库，关键结论已在此复述）：
  - 正式批次：`tmp/perf/20261026-204539/`（raw.json + report.md + product.json/md + bin/，
    report.md 内有逐轮 load1 与墙钟序列）
  - 复核批次：`tmp/perf/20261026-193043/`、`20261026-195432/`、`20261026-202140/`
  - 负向路径：`tmp/perf/20261026-204512/`（假编译器：退出 0 但无统计行）、
    `20261026-204530/`（编译器路径不存在）、`20261026-204530-2/`（`--timeout 1`）

## 3. 本轮的工具体检（并修掉三处真实缺陷）

### 3.1 `tools/perf-baseline.py`

- 新增 `--warmup`（默认 3，按完整场景流程预热但不计入样本）、`--timeout`
  （超时记作失败样本而不是崩掉整批）、`mad_ms` / `load1_max` / `errors`、
  `corpus_version` 与 `target`，以及整批 `validity`。
- **缺统计不再静默归零**：`run_build()` 先检查 `time_*_ns`、`ir_*`、`check_*` 三类统计行
  是否存在，缺失即给该样本写 `error="缺统计：…"`（`stats_missing` 同时记录），
  `usable()` 据此判定该轮不可用，`summarize()` 把它算进 `failed`，`validity()`
  据此把整批标 `invalid` 并在原因里列出具体缺哪类字段。此前 `rows` 为空时阶段耗时
  直接写 0，违反方案 §6「缺失字段写不支持，不能默认为零」。
- **run-id 唯一化**：run-id 只到秒，同秒内两次运行会互相覆盖报告；现在遇到同名目录
  自动加 `-2`、`-3` 后缀（本轮 `204530` / `204530-2` 即由此而来）。
- **修复 A/B 污染**：旧实现 A/B 共用一份语料，交错改动的 probe 常量让另一侧的
  `hot` / `one-function` 变成全量重编（实测 hot 报 18.9 s，真值 1.05 s）。现在两侧各用
  独立副本（`baseline-work/a`、`baseline-work/b`）并校验两份语料哈希一致。
- report.md 追加「逐轮样本（load1 / 墙钟 ms）」序列，便于事后核噪声。

### 3.2 `tools/perf-product.py`（新增）

编译 6 个基准用例的 O0/O2 产物，运行时传入规模参数，checksum 由本工具的 Python 参照
实现独立算出（不是"跑一次记下来"），并采集 `.text`、只读数据
（`__cstring`/`__const*`，不含 unwind/eh_frame）与文件大小；`--append-to <report.md>`
可把产物表并入同批次的编译体验报告。

### 3.3 负向路径留证（最终工具，可复查）

| run-id | 构造 | 结果 |
| --- | --- | --- |
| `20261026-204512` | 假编译器（`exit 0` 且不打印统计行） | 四场景各 1 轮全记 `缺统计：time_*_ns/ir_*/check_*`，`validity=invalid`，表格全部 `—` |
| `20261026-204530` | `--compiler /tmp/nope/yh` | `validity=invalid`（编译器不存在），退出码 1 |
| `20261026-204530-2` | `--timeout 1` | 四场景全 `timeout>1s`，`validity=invalid`，表格全部 `—`，退出码 1 |

### 3.4 `tests/perf/bench-*.yh`（新增 6 个）

整数循环、数组扫描、插入排序、FNV-1a 哈希、结构体+切片传参、递归调用。每个用例：
argv 运行期输入、内部不变量自检（排序有序性与元素和、切片与下标一致、哈希 32 位截断等）、
**缺省输入下比对冻结的期望 checksum**（不一致 `return 5`，换其他输入时跳过该断言）。
开发中确认两条语言事实并写进 README：**`int` 是 32 位**（种子与累加器必须显式
`i64`/`u64`，否则溢出成负数），结构体数组不能直接切片（先 `arr.to_type([]T)`）。

## 5. 四批复核（可重现性）

`perf-baseline.py --iterations 20 --warmup 3` 连跑四次（同语料、同二进制、同轮数；
第三批给基准补上「缺省输入自校验 checksum」，第四批起工具加「缺统计即无效」与
run-id 唯一化——前两批的统计行本就齐全，数值不受影响）：

| 场景 | 第一批 | 第二批 | 第三批 | 第四批 | 相对第一批 | MAD（一/二/三/四） |
| --- | --- | --- | --- | --- | --- | --- |
| 冷编 | 10042.7 | 10040.4 | 10089.6 | 10070.1 | −0.0%~+0.5% | 73.8 / 22.6 / 74.4 / 42.7 |
| 全量重编 | 16780.4 | 16849.4 | 16928.3 | 16781.5 | +0.0%~+0.9% | 344.8 / 377.6 / 342.7 / 396.6 |
| 热编 | 988.8 | 995.8 | 998.6 | 977.3 | −1.2%~+1.0% | 8.8 / 15.0 / 10.6 / 3.9 |
| 单函数改动 | 3545.7 | 3622.7 | 3589.3 | 3577.4 | +0.9%~+2.2% | 20.5 / 50.5 / 41.3 / 35.4 |

四批均 `validity=ok`（无失败/超时/缺统计）。各批 start load1 从 1.7 到 6.49 不等，
峰值最高 7.47（仍在 8.0 告警线内），与墙钟小幅上升同向——这些差异更像环境噪声而不是
代码差异。**批间噪声上限约 2.2%**，是后续设阈值时必须考虑的下限：±2% 内的差异不能当
回退。本报告不据此立门（PF4）。

## 6. 可复跑命令

```bash
just                                     # 产出与源码同步的 ./yh
python3 tools/perf-baseline.py --iterations 20 --warmup 3
# 记下输出里的 run-id，再把产物基准并入同一目录
python3 tools/perf-product.py --runs 5 --warmup 2 \
    --outdir tmp/perf/<run-id> --append-to tmp/perf/<run-id>/report.md

# 负向路径（应给出 invalid，不得出结论）
python3 tools/perf-baseline.py --compiler /tmp/nope/yh --iterations 1 --warmup 0
python3 tools/perf-baseline.py --iterations 1 --warmup 0 --timeout 1
printf '#!/bin/sh\nexit 0\n' > tmp/fake-yh && chmod +x tmp/fake-yh
python3 tools/perf-baseline.py --compiler tmp/fake-yh --iterations 1 --warmup 0

# 语料/编译器身份复核
shasum -a 256 yh
```

重跑同一条命令会生成新的 `tmp/perf/<时间戳>/`，字段与口径相同；`--ab <旧yh>`
可对两代编译器做交错对照（两侧独立语料副本，成对交错、正反顺序交替）。

## 7. 已知局限

- **只测 Darwin/arm64 原生**：Linux/AArch64 与 x86_64 未测，跨平台结论留给 CI。
- **内存未采**：本轮口径不含 RSS。方案要求区分「最大单个子进程 RSS」与并行构建总内存，
  后者需 cgroup 或进程树采样，属 PF2；本报告不给出任何内存结论。
- **场景成组而非交错**：无 A/B 时四场景顺序成组执行，跨场景的负载漂移会以「场景间
  不可比」的方式存在，故结论只看场景内部的 median/MAD。
- **`.fir` 写入量**：冷编 0 条；其余场景该轮未采集，统一记 `-1`（不做结论）。
- **p95 只作描述**：20 轮的 p95 不构成尾延迟承诺，尾部问题需 ≥100 轮另测。
- **产物基准的口径**：只统计 `__text` 与 `__cstring`/`__const*`，不含 `__unwind_info`、
  `__eh_frame` 与 Mach-O 头；文件大小仅供对照，不代表代码质量。

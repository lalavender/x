## 2. 三代构建链

```
stage0  宿主 C 实现的 yh（Mach-O，种子与差分参照）
  │  交叉编译拼接源码 compiler/ → AArch64 Linux ELF
  ▼
stage1  自举编译器第一代
  │  编译自身
  ▼
stage2  自举编译器第二代
  │  编译自身
  ▼
stage3  自举编译器第三代
```

进程记录只出现 yh 新编译器（`--emit-asm`）与标准 GNU 汇编器/链接器
（`as`/`ld`，经 gcc 驱动）；未调用 stage0、libtcc、ANTLR 或任何 C 翻译器
参与自编。

相同，二者均已满足。

## 4. 确定性检查

- 同一 stage 对同一输入重复发射，汇编逐字节一致（无时间戳/随机数）；
- 发射内容经扫描不含宿主绝对路径（`/Users/`、`/opt/homebrew`、`/work/`）
  或日期字符串；
- 无无序表遍历导致的顺序抖动。

## 8. 复现

```bash
# 前置：docker CLI 在 PATH（本机 /opt/homebrew/bin）、容器 yh-build 运行中、
#       仓库挂载于 /work、tmp/sysroot 存在。
make g3
```

`make g3` 会依次执行 `make bootstrap`（G1 + G2 + G2+ 固定点）与
`tests/selfhost/g3-acceptance.py`（分代全量复验、固定点、确定性、
诊断质量、归档）。任一前置缺失即失败，不 SKIP。

无容器时的本机等价回归：`make selfhost-native`（Mach-O 差分，含汇编固定点）。

## 9. 边界与后续

- **未替换默认 `yh`**：G3 达成不自动宣称现有 CLI/Mach-O/`-c/-run`/库接口
  已迁移；如要替换默认编译器须另立验收。
- **工具链未完全自给**：仍依赖系统汇编器/链接器与 C 运行时，符合方案
  既定范围（“工具链完全自给”另立目标）。
- **单目标**：仅 AArch64 Linux ELF；Darwin arm64 与其他架构不在首轮验收内。

# 模块模式枚举成员引用的边界定位与锁定

日期：2026-10-07。状态：已完成（边界定位 + 项目级锁定，无编译器改动）。

## 背景

上一轮把「枚举判别值延迟求值」交付到单文件路径，并记录模块模式边界为
「模块模式下在编译期函数正文里引用延迟枚举成员不可用，`Level.mid` 会落到字段访问」。
本轮把范围测准 —— 结论比原来记的更窄，**顶层引用在模块模式下是可用的**。

## 实测边界（`comptimecross` 项目）

| 位置 | 结果 |
| --- | --- |
| 模块内**顶层常量**：`pub const MID int = Level.mid;`（`Level` 判别值来自编译期调用） | **可用**，值正确（`low=4` → `mid=5`） |
| 模块内编译期函数读该常量：`return MID;` | **可用** |
| 跨模块转发该值（api 模块 `$base.mid_ct()`） | **可用** |
| 模块内编译期函数**正文里直接**引用枚举成员：`return Level.mid;` | **不可用**：报「『.』的左侧不是结构体或结构体指针」 |

也就是说：延迟判别值的回填在模块模式下**确实生效**（顶层常量读到了正确值），
失败的是「编译期函数正文里直接引用枚举成员」这一条解析路径 —— 准备期（typed 正文
捕获）的表达式解析没有走到 `parse_expr.yh` 里新增的枚举成员限定引用分支，
而是落到了运行期的字段访问诊断。

## 本轮改动（仅测试与文档）

- `tests/modules/projects/comptimecross/math/src/base/extra.yh` 新增：延迟判别值枚举
  `Level`（`low = $base_value() + 1; mid;`）、顶层常量 `MID = Level.mid`、
  编译期函数 `mid_ct` 读 `MID`。
- `math/src/api.yh` 新增 `@[comptime] pub fn level_mid()` 经 `$base.mid_ct()` 转发。
- `host/src/main/main.yh` 新增 `const MID int = $math.level_mid();` 与 `+ MID - 5` 断言。
- 已确认这些断言在 `project cases` 里通过（84/84）。

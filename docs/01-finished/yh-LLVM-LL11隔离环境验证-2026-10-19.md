# yh-LLVM-LL11 隔离环境验证（2026-10-19）

## 结论

LL11 的“无系统 LLVM 隔离环境验证”已完成：最终 x64 编译器（`bin/yh-linux-x64`）
在 **bubblewrap + `PATH=/nonexistent`** 的沙箱里完成单文件编译/链接/运行、
项目构建与冷编自举；产物 `readelf -d` 无 LLVM/lld 动态依赖；`strace execve`
只见编译器自身，无外部 LLVM 旁车；冷编自举 `fallback_functions=0`。

## 验证命令

```bash
make llvm-isolation
# 等价直接调用：
python3 tests/selfhost/llvm-isolation.py
```

脚本 `tests/selfhost/llvm-isolation.py` 的步骤：

1. 沙箱：`/usr/bin/bwrap --ro-bind / / --tmpfs /tmp --bind <repo> <repo>
   --setenv PATH /nonexistent`，隔离系统 PATH 上的 LLVM/交叉工具。
2. 单文件：`bin/yh-linux-x64 tests/yh-run/run/01-hello.yh -o ...` 编译、链接、
   运行，输出 `hello, yh!`。
3. 依赖面：`readelf -d` 断言最终编译器与用户程序 NEEDED 不含 `libLLVM*`/
   `liblld*`（编译器仅系统库 `libm/libstdc++/libz/libzstd/libxml2/libgcc_s/libc`）。
4. 旁车审计：`strace -f -e trace=execve` 断言 execve 只出现编译器自身。
5. 项目构建：`runtimeplain` 项目在隔离环境构建通过。
6. 冷编自举：种子在隔离环境对 `compiler/` 冷编一代
   （`--backend llvm --target x86_64-unknown-linux-gnu --emit-llvm`）；
   `fallback_functions=0`；冷编产物再次编译/运行 `.yh` 通过。

## 实测证据（WSL2 Linux/x86_64）

- `readelf NEEDED 无 LLVM/lld：yh-linux-x64 -> ['libm.so.6', 'libstdc++.so.6',
  'libz.so.1', 'libzstd.so.1', 'libxml2.so.16', 'libgcc_s.so.1', 'libc.so.6',
  'ld-linux-x86-64.so.2']`
- `readelf NEEDED 无 LLVM/lld：hello -> ['libc.so.6']`
- `execve 审计通过：仅 ['/mnt/c/Users/16904/Desktop/x/bin/yh-linux-x64']`
- 冷编产物 `yh-cold` NEEDED 同样无 LLVM/lld；内嵌 lld 身份 `21.1.8`。
- `LL11 隔离环境验证：全部通过`。

## 边界

- 隔离验证使用 bubblewrap 的用户命名空间 + 只读根，不依赖 root chroot；
  固定 SDK 的桥/LLVM 断言仍由 LL0E/LL10 的更底层门覆盖。
- 本机为 WSL/x86_64；ARM64 的 LLVM 运行时（F1）不在本验证范围。
- LL11 的默认切换已落地，但 20 轮性能对照/回退归因与 R2b 硬门（RS2/RS3/R2c）
  仍未关闭，未宣布 LL11 全量完成。

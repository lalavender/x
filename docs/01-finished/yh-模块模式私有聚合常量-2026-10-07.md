# 模块模式的私有聚合常量

日期：2026-10-07。状态：已完成。补上第 34–37 轮只做单文件留下的**一致性缺口**。

## 缺口

第 34–37 轮让**单文件**支持全局 `const` 聚合常量，模块模式却**一律拒绝**：

```yh
// 模块项目里
const PRIV_TBL [3]int = [1, 2, 3];   // → 错误: const 不支持聚合类型
```

拒绝的理由是「接口导出尚未覆盖聚合常量」—— 但那个理由只对 **pub** 常量成立：接口 `.s.i` 的常量
导出把标量 `cval` 打印成字面量，聚合的 `cval` 是数据段标签，导出没有意义；而**私有**常量根本不走
接口。

## 三层实测（每层都比上一层更靠后）

| 尝试 | 结果 |
| --- | --- |
| 私有聚合常量 + CT 正文里引用 | `const 不支持聚合类型`（守卫太宽） |
| 放宽守卫后同上 | `跨模块 CT 正文引用了不支持的模块常量类型`（`.s.ct` 闭包不携带聚合常量） |
| 私有聚合常量 + **运行期**读 | **通过**（本项目标） |

## 改动

`compiler/parse/parse_global_init.yh` 的两处守卫（结构体、数组/切片），由「模块模式一律拒绝」
改为「模块模式**且 pub** 才拒绝」，诊断同时改得更准确：

```yh
if (kind == gen.SYM_CONST && gs.c_module_mode != 0
    && (gs.c_syms[idx].flags & gen.F_PUB) != 0) {
    return gen.sem_err("pub const 聚合常量暂不支持跨模块导出");
}
```

## 效果

| 写法（模块项目里） | 之前 | 现在 |
| --- | --- | --- |
| `const TBL [3]int = [1, 2, 3];`（私有）+ 运行期读 | **拒绝** | **可用** |
| 私有 `const P Point = Point{...}` | **拒绝** | **可用** |
| `pub const TBL [3]int = ...` | 拒绝 | 拒绝（诊断更准：专注「跨模块导出」） |
| CT 正文里引用（私有或 pub）聚合常量 | 拒绝 | 拒绝（`.s.ct` 需携带元素值，另立 todo） |

## 用例

`Comptimecross`：`math/src/api.yh` 加私有 `const PRIV_TBL [3]int = [1, 2, 3];` 与
`pub fn priv_tbl_sum() int { return PRIV_TBL[0] + PRIV_TBL[1] + PRIV_TBL[2]; }`；
host 的 `main` 返回值加 `math.priv_tbl_sum() - 6`（运行期调用、跨模块，值错即非零）。

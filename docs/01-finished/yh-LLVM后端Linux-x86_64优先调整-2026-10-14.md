# yh LLVM 后端顺序调整：Linux/x86_64 优先

日期：2026-10-14。状态：**方案顺序调整完成，代码未实施**。

## 用户决定

用户要求“将 linux x86 优先实现，这样本地就可以验证”。沿用此前六格架构讨论，
这里的 x86 指 x86_64，不扩大到 32 位 x86。首期环境为当前 Windows 宿主上的
WSL Ubuntu x86_64，目标 triple 为 `x86_64-unknown-linux-gnu`。

## 同步内容

- [替换设计](../03-design/yh-LLVM后端替换设计.md)、
  [实施方案](../02-plan/yh-LLVM后端替换实施方案.md)、

  [ADR-0014 草案](../adr/0014-yh采用LLVM作为正式代码生成后端.md) 和 todo 已同步。
- Linux/x86_64 从 F1 前移为 LL0–LL11 首期；原 F1 改为 Linux/AArch64。
  LLVM-14/15 的 x64 宿主/运行时/链接/种子部分升为首期 P0。
- 首期包含 System V C ABI、x64 syscall/目录/时钟/内存/进程、原生链接与原生自举，
  不能只调平台列表而保留 ARM64 专用运行时。
- LL3 起生成的 x64 测试程序直接原生运行；此时启动编译器 A 仍可能通过 qemu。
- LL10 以 ARM64 种子启动 A，A 经 LLVM 产原生 B，B/C/D 原生连续自编，
  检查 ELF64/EM_X86_64=62，原生代不靠 qemu-aarch64 运行。
- 原生链接使用绝对路径的 x64 工具，不继承 `tmp/boot/crossbin/gcc` 的 ARM64 包装器。
- 首个 x64 种子按全部门禁后入库为 `bin/yh-linux-x64` 和独立 `.sha256`；
  现有 `bin/yh-linux-arm64` 仅作启动/差分桥且保持其二进制和哈希。
- LL12 退役旧机器后端等待 F1 ARM64 LLVM 回归；不阻挡本机 x64 原生候选或种子建设。

新路线：Linux/x86_64 → Linux/AArch64 → macOS/ARM64 → Windows/x86_64 →
macOS/x86_64、Windows/ARM64。32 位 x86 不在本次范围。

## 验证

本轮在 WSL 执行最小 LLVM IR 的本机验证：

1. `/usr/bin/clang-21 --target=x86_64-unknown-linux-gnu -x ir -c -O0` 生成对象。
2. `/usr/bin/gcc -no-pie` 原生链接；探针环境 PATH 仅 `/usr/bin:/bin`，未经过 ARM64 包装器。
3. 检查 ELF64、小端、machine=62，直接执行探针，退出码 0。

这是标量 IR 工具链探针，不是 yh 前端、运行时或自举验证。
临时对象、程序和报告在 `tmp/llvm-x64-order-review/`，没有写入 bin/。

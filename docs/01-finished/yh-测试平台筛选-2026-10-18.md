# 测试平台筛选（2026-10-18）

## 背景

`tests/yh-run/run/llvm-linux-x64-host.yh` 是 LL8b 的宿主桥探针，直接调用
`linux_syscall6`，只能在 Linux 上编译运行。它此前没有平台标注，`check.py` 也不
按平台跳过，于是 macOS 上跑全量运行语料永远是 342/343 且退出码 1——真正的问题
（平台不适用）被当成失败项，`make test` 在 macOS 上无法全绿。

## 机制：`// platform:` 头部指令

`tests/yh-run/check.py` 新增一条与 `// expect:` / `// exit:` 同级的头部指令：

```yh
// platform: linux            // 只在 Linux（任何架构）跑
// platform: linux-x64        // 只在 Linux/x64 跑
// platform: darwin-arm64 linux-x64   // 两个平台都跑，其余跳过
```

规则：

- **没有该指令 = 共有用例**，所有平台都跑（现有 342 个语料里绝大多数属于此类）；
- 带指令的只在**运行平台**匹配时执行，其余记 `SKIP`，不计失败、不影响退出码；
- tag 形式为 `<os>` 或 `<os>-<arch>`，`<os>` 匹配该 OS 的所有架构；
- `--cross` 模式的运行平台按 `linux-aarch64` 计（产物是 aarch64 ELF，在容器内运行），
  而不是编译宿主 Darwin。

实现落在 `check.py` 的三处：`host_platform_tag()` 给出本次运行平台、
`parse_platform_requirement()` 读指令、`platform_matches()` 做匹配；任务表增加
第六项 `skip_reason`，不匹配的用例在 `run_task` 里直接返回 `SKIP`，不创建产物目录。

## 用例标注

`run/llvm-linux-x64-host.yh` 标为 `// platform: linux`：正文对 arm64/x64 都有
syscall 号分支，因此按 OS 级声明，Linux 两个架构都跑、Darwin 跳过。文件名保留
历史上的 x64 标记（数字/名字前缀与大量文档引用绑定，不改名）。

其余语料复查结果：

- `tests/yh/`（词法/语法）无平台相关语料，纯语法，无需筛选；
- `tests/modules/check.py` 只做 `--syntax-check`，平台无关；
- `tests/modules/build-check.py` 已经用 `sys.platform` 自适应（native/cross 断言
  不同，交叉目标用 `-target` 检查而不运行），无需按平台删用例；
- `tests/selfhost/llvm-*.py` 是 Linux 专属门，由 `make test-llvm` 的
  Linux/x86_64 硬断言隔离，不进本机 `make test`。

## 验收

| 项 | 结果 |
| --- | --- |
| `make test`（Darwin/arm64） | 退出 0；三层全过，运行语料 342/343 + 跳过 1 |
| 跳过行 | `SKIP  run/llvm-linux-x64-host.yh —— 仅适用于 linux，当前 darwin-arm64` |
| 汇总行 | `总计：通过 342/343（darwin-arm64 原生，并发 8）` |
| Linux/x64 | 该用例照常执行（tag 匹配 `linux-x64`）；本机无法复跑，按匹配规则推导 |

顺带修正：汇总行的模式标签原先硬编码 `Darwin Mach-O`，在 Linux 上会误报；
现在输出实际运行平台（`darwin-arm64 原生` / `交叉 ELF（linux-arm64）`）。

## 后续

- 新增平台专属语料只需补一行 `// platform:`，不要改文件名前缀。
- `tests/modules/build-check.py` 的平台差异是「同一用例两种断言」，不是
  「平台专属用例」，保持现状；若将来出现只在某平台成立的项目 fixture，
  再按同一指令约定扩展。

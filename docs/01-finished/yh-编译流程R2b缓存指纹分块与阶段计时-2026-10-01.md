# 编译流程 R2b：缓存指纹分块与阶段计时

日期：2026-10-01。状态：完成一项热缓存优化和开发计时工具；R2b、R0–R6 仍在实施。

## 实现

`mb_hash_file` 原本对文件每个字节调用 FNV 更新。现在按小端 8 字节块混合，使用
malloc 对齐缓冲上的原生 64 位读取，尾部不足一块时仍逐字节处理；已支持主机均为小端，
因此与固定小端编码生成相同指纹。`mb_hash_init` 提升缓存指纹版本，使旧 module/object/link
manifest 自动失效。`tokenreplay` 增加末尾余数为 7 的 `.yh` 源文件，回归走过分块尾部路径。

`yh build --stats` 现在报告项目装载、模块调度、对象缓存/汇编、最终链接决策和构建内
总耗时。Darwin 通过经审核的 `clock_gettime(CLOCK_MONOTONIC)` OS API 计时；Linux arm64
直接调用 `clock_gettime` syscall，不导入 Linux libc 时钟函数。计时字段只在 `--stats`
输出中出现。

## M1 性能

冻结语料为 25 个 `.yh` 文件、13,338 行、464,518 字节；20 次独立进程采样，真实包含
汇编与链接。外部端到端时间和进程内阶段中位数/p95 如下：

| 场景 | 端到端 ms | 项目扫描/词法 ms | 模块调度 ms | 对象缓存/汇编 ms | 链接决策 ms | 构建内总 ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 无改动 | 32.8/37.3 | 13.0/15.0 | 4.1/7.0 | 7.0/9.6 | 2.9/3.6 | 27.2/32.8 |
| 单函数体变化 | 663.2/753.4 | 14.6/19.9 | 59.3/74.1 | 443.4/504.0 | 132.9/151.6 | 656.9/748.9 |
| 冷编 | 1,734.1/1,900.6 | 14.5/17.8 | 102.5/107.4 | 1,467.9/1,639.9 | 137.4/146.0 | 1,728.5/1,896.4 |

无改动构建仍对全部 25 个源文件做词法扫描和项目索引，声明解析为 0；对象与链接缓存
分别命中四个模块和程序，不调用汇编器或链接器。进程内总耗时中位数 27.2ms，外部端到端
32.8ms，p95 为 37.3ms，无改动 50ms 目标已达到。单函数体变化只重建 main、命中其他
三个模块，但模块内仍检查和捕获 80 个 AST 函数上下文；一次外部汇编器调用占对象阶段，
最终链接阶段还有一次链接器调用。冷编四个 worker 并行处理模块，但外部汇编/对象阶段
仍占中位数约 1.53s。

函数修改 200ms 与冷编 1s 目标未达到。下阶段重点是跳过无改动构建的全量词法/索引，建立
完整函数级 check/IR 增量，并替换系统汇编器与链接器。该测量反映当前迁移过渡工具链，
不表示完整 R2b/R3/R4 或最终性能目标已经验收。

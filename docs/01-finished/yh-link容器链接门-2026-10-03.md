## 做了什么

给 `link/` 加了一道**容器链接门**：宿主上汇编，容器里用 GNU 交叉 `ld` 链接并
真的运行，判定是差分的（本工具对象与 `llvm-mc` 参照对象跑出来的退出码与标准
输出必须一致）。

这道门当场抓出一个此前的所有门都看不见的正确性缺陷。

## 抓出的缺陷：汇编期回填了位置相关值

原实现把「目标符号已定义且与重定位同节」当作可以在汇编期直接回填的条件，
于是 `adrp sym`、`add xN, xN, sym@PAGEOFF`、`ldr xN, [xN, sym@PAGEOFF]`、
`.xword sym` 这四类在同节时都省掉了重定位。

**这些值全部依赖节的最终地址**：`(S & 0xFFF)` 只有在节按 4KiB 对齐放置时才
等于节内偏移。GNU `ld` 把 `.text` 放在 `0x400078` 这类地址上，于是：

- `add x0, x0, _weigh9@PAGEOFF` 汇编期算出 imm12 = 0，链接后应该是 0x78；
- `.xword sym` 在 `.data` 里写入了符号的节内偏移，而不是最终地址。

语料里 3 个对象因此在容器里段错误或执行到非法指令。

**为什么老门看不见**：`tests/check_corpus.py` 只比对「指向未定义符号」的重
定位，同节局部目标在两边都靠 Python 迷你链接器回填，回填逻辑跟汇编器犯的是
同一个错，于是自洽地通过了。

## 修法

1. `src/asm/60_assemble.yh`：能在汇编期定的只剩「**局部符号 + 同节 + 分支**」
   ——位移只跟节内两个偏移有关，与最终布局无关。其余一律出重定位。
   随之删除因本次改动而失效的 `fx_pg_hi21` / `fx_lo12` / `fx_lo12_ldst` /
   `fx_put64`；`ctx_get_sym` 也因前置改动失去调用方，一并删除。
2. `src/asm/40_parse.yh`：**没有 `.globl` 的标签一律是局部符号**（原来非点号
   名字默认全局，与 GNU as 不符）。引用时先用 `SYM_UNDEF` 占位，定义时定成
   局部；未定义的引用最终仍按全局输出（ELF 不允许未定义的局部符号）。
   判定改看绑定而不是节号——全局符号即使已定义也要留重定位，链接器可能把它
   重定向到别的目标文件里的同名符号。
3. `tests/check_corpus.py`：重定位改成**全量比对**（原来只比未定义符号的），
   目标按「节名 + 符号值 + addend」归一化；迷你链接器改用 4KiB 对齐的
   合成节基址，页寻址与低 12 位才真正算得对。

| --- | --- | --- |

| 编码器向量 | `python3 tests/check_enc.py` | 107 条，不一致 0 |

| **容器链接门** | `python3 tests/elf_link_check.py` | 44 个：可重定位链接 44，静态链接 44，**行为与参照一致 44，不一致 0** |

容器门里有 2 个语料在运行时段错误，但 `llvm-mc` 参照对象崩得一模一样，
原因是本仓库的 `_mmap` 运行时桩不全，不是汇编器问题；差分判定天然容忍。

## 顺带修掉的相邻缺陷

容器门跑之前，为了写出可运行的 `_start` 桩，暴露了系统指令解析从未被覆盖：

- `p_system` 用 `p_is_mn` 查已被消费的助记符，`nop`/`brk`/`svc`/`dsb`/`dmb`/
  `isb` 全部报「未知的指令」或吞掉下一条语句；改用 `p_mn_is`。
- 屏障域只在**同一行**才当屏障域，否则 `isb` 会把下一条语句的助记符吃掉。
- `isb` 原先借用 DSB 的编码基址，少 bit6（`0xd5033f9f` vs 正确 `0xd5033fdf`）；
  `e_barrier` 增加 `kind = 2`（ISB）。
- 新增定向语料 `tests/asm/06-sysops.s`，上述形态全部纳入逐字节比对。

## 环境事实（供后续复用）

- colima 引擎是 linux/arm64。`docker run --platform linux/amd64` 可用（binfmt
  模拟），但 **`docker build --platform linux/amd64` 会静默产出 arm64 镜像**。
- 要挂进容器的目录必须在工作区内：colima 不共享宿主 `/tmp`。
- 镜像 `yh-link-elf:latest` = `link/tests/docker/Dockerfile`（binutils 双架构 +
  qemu-user-static）。

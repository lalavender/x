# 跨模块编译期调用直接字面量实参的静默错值修复

日期：2026-10-07。状态：已完成（保守拒绝；支持路径待立项）。

## 缺陷

跨模块编译期调用的**直接字符串字面量实参**不会报错，但会取到无关字面量的值：

```yh
// math/api.yh
@[comptime] pub fn head_of(text *char) int { return (*text).to_type(int); }
// host/main.yh
const HEAD int = $math.head_of("Z");   // 期望 90，实际 104（'h'）
```

实测 `head=104 letter=104 exported=104`：`"Z"` 被解析成了同一调用链里另一个
字面量（`"hi"`）的首字节。根因是跨模块调用的实参在**提供方编译单元**里求值，
拿到的是那边的数据标签号；编译期侧按标签号在**本地**只读池映射里反查，
就命中了本地无关的字面量。上一轮为「直接写字面量实参」加的标签反查
（`ct_pool_adopt_label`）没有区分标签号的来源编译单元。

静默错值比拒绝更危险，所以先按保守路径处理。

## 修复

`compiler/parse/parse_expr.yh` 的编译期调用实参解析：调用是模块限定形式
（`$mod.fn(...)`）且当前实参是字符串字面量、对应形参又是单字节指针
（`char`/`u8`/`i8` 元素，即会走只读池的类型）时，直接报诊断：

```
跨模块编译期调用不支持直接字符串字面量实参，请改用模块导出的 pub const 指针常量
```

只按形参类型拒绝，其它形参类型不受影响；同模块的字面量实参（run/145）与
跨模块导出常量实参（`comptimecross` 的 `TEXT`/`exported_letter`）继续工作。

## 更正（同日）

次日实测发现同一根因还影响**非字面量**写法（`const MINE *char = "AB"; $math.head_of(MINE)`
同样读到无关字面量），因此拒绝范围已从「字面量实参」扩到「单字节指针形参」，
诊断串改为「跨模块编译期调用不支持单字节指针形参（char/u8/i8）：实参的字符串来源无法
跨编译单元解析，请改用模块导出的 pub const 指针常量」，检查拆成
`ct5b-crossmodule-literal-arg-rejected` 与 `ct5b-crossmodule-pointer-arg-rejected`。
见[后续完成记录](yh-跨模块单字节指针形参错值修复-2026-10-07.md)。

## 遗留

支持跨模块直接字面量实参需要把实参字面量的**字节来源**跨编译单元传递
（或让实参在调用方求值后随调用携带），已记入 `docs/todo.md` 的 CT5B。
在此之前保持拒绝，避免静默错值。

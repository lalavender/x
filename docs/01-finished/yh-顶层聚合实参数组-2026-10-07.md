# 顶层聚合实参：数组与嵌套数组

日期：2026-10-07。状态：已完成。承接第 35/36 轮（结构体、嵌套结构体）。

## 一、泛化构造区接口（删掉即将出现的第二个同形函数）

数组与结构体在 `ct_ir_aggregate_new` 里的差别只有一个参数：**结构体传自身类型，数组传元素类型**。
所以没有新增 `ct_arg_pool_array`，而是把上一轮的 `ct_arg_pool_struct` 泛化改名：

```yh
// elem_type 对结构体是它自身类型，对数组是**元素**类型（与 ct_ir_aggregate_new 的约定一致）。
pub fn ct_arg_pool_agg(elem_type int, vals *i64, tys *int, n int) i64
```

## 二、新增数组字面量折叠 `p_ct_arg_array_literal`

`compiler/parse/parse_expr.yh` 新增约 45 行：解析 `[e0, e1, ...]`，按源码顺序填位：

- 标量元素：`c_fold += 1` 折成常量 + 逐元素 `sem_can_assign`
- 数组元素：**递归**（因此嵌套数组 `[[1,2],[3,4]]` 可用 —— 这顺便绕过了前端「嵌套数组字面量需要
  目标类型上下文」的既有判定，因为这里是折叠路径自己解析的）
- 结构体元素：递归进 `p_ct_arg_struct_literal`
- 切片/联合体元素：返回 1（不支持）
- 长度不符或元素超 64：返回 1

接线两处：结构体折叠里 `TY_ARRAY` 字段改走它、顶层实参调用点加 `else if (pk == gen.TY_ARRAY)`。

## 三、诊断措辞更新

原诊断说「只支持字段全是标量的结构体字面量：数组、切片、联合体与嵌套聚合字段仍需…」——
数组与嵌套聚合现在都支持了，措辞已改为：

> 编译期调用实参里的聚合值暂时只支持结构体与数组字面量（字段/元素可递归嵌套标量、结构体、数组）；
> 切片与联合体仍需在 `@[comptime]` 函数体内构造

`fail/148` 也从「数组实参」改成仍不支持的**切片实参**（`$take([1, 2, 3])` 配 `[]int` 形参），
`fail-contains` 同步。

## 用例

`tests/yh-run/run/155-comptime-top-array-arg.yh`（`// exit: 0`）：

- 顶层数组实参 `$sum3([10, 20, 30])` → 60
- 结构体里的数组字段（字段乱序）`Row{ tag: 4, cells: [1, 2, 3] }` → 10
- 嵌套数组 `$gsum([[1, 2], [3, 4]])` → 4

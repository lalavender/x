# LLVM LL0E 静态桥验收

本阶段交付 LLVM C ABI 薄桥及固定私有 SDK 构建/静态链接工具。yh 前端仍使用旧 ARM64
路径；本阶段独立宿主成功不能替代完整后端迁移和连续自编验收。

SDK 为固定 Ubuntu LLVM 21.1.8 开发包，地址/哈希/组件清单在 vendor/llvm/sdk.lock.json。
工具校验下载包，从包中只取 C API/配置头、所需归档和许可，不安装系统 LLVM、不调用
clang/llvm-config/opt/llc。归档完整路径用于静态链接，桥源码和归档身份另存 config.json。
坏哈希验收已明确失败。许可保存在私有 SDK share/LICENSE，最终发行时必须随包携带。

桥提供 yh_llvm_version 与 yh_llvm_emit，输入/诊断由调用方持有，每次调用私有 LLVM
context、module、target machine；目标登记 pthread_once。验证/优化/代码生成均在进程内，
只有 O0/O2、Linux x64/AArch64 目标、对象/汇编两种输出。模块 triple/layout 不匹配、
非法 IR/CFG、优化/输出配置、路径错误都明确拒绝。生成结果先在内存完成，再临时写入
并 rename，失败保留原文件、不遗留临时文件。

真实验收：O0/O2 x64/ARM64 对象 ELF64 machine=62/183，x64 最小程序通过原生 gcc
链接并退出 0，x64 汇编输出通过。8 类拒绝案例各重复调用；另覆盖空参数、有界诊断、
原产物保留、目标目录导致 rename 失败与临时清理。tests/selfhost/llvm-embedded-probe.yh
验证现有 yh 能检查 C ABI 调用签名；它尚未以原生 yh 前端运行。

测试宿主动态依赖只有 libc、libm、zlib、zstd 和加载器，无 LLVM/clang 动态库。
在无任何 LLVM 工具的 PATH 中完成生成/运行；再于 WSL root 下创建仅含宿主、输入和
上述 OS 库的 chroot，成功生成 O2 x64 对象。本阶段 ARM64 只验对象，不声称原生运行。

GNU BFD 在 DrvFS 上的归档成员与输出小 IO 已导致超过 120 秒的超时，直接链接实验
耗时 459.8 秒，strace 显示大量 read/lseek，进程等待 9P RPC。静态链接工具改用匿名
memfd 保存原归档字节和 ELF 输出，仍使用普通 GNU 链接器，最后原子发布到 tmp。
持久临时文件没有移出仓库 tmp，不新增系统 LLVM/lld 依赖。

最终验证命令：WSL root 执行 python3 tests/selfhost/llvm-embedded.py --chroot 退出 0；
WSL 旧 ARM64 环境执行 make、make test、make selfhost-native 全绿。日志和报告在
tmp/llvm-migration/，种子哈希仍为 073282e9f1f773f162ccf9674a86f357e3bd6c9b74ccb65fe613968566916ccd。

下一步为 LL1 语义探针与 LL2 受检模块/目标边界；LL3 接入桥前准备独立 ARM64 启动 SDK，
LL10/LL11 完成原生 yh 嵌入、连续自编和最终分发门。运行时禁止导入政策仍保留，接入时
必须审计 LLVM/宿主 C++ 依赖，不通过放宽现有 runtime-memory 门完成替换。

# R3 自有 memcpy/strlen 运行时切片

日期：2026-10-01。状态：已交付本机 arm64 切片；R3 整体未完成。

## 变更

- `memcpy` 与 `strlen` 不再作为外部 C 函数导入。编译器在 arm64 汇编中发射本地
  ABI 入口，保留直接调用与函数值调用。
- `memcpy` 按 32/16/8 字节块和字节尾部复制，返回原目标指针；`strlen` 先逐字节走到
  机器字边界，再按字扫描并逐字节确定终止符位置。
- 新增 `tests/modules/projects/runtimebytes/` 与
  `tests/selfhost/runtime-memory.py`，覆盖长度 0、8、9、16、17、直接/函数指针调用、
  返回地址、空串、UTF-8 字节长度、对齐及非对齐字符串。审计 Darwin 程序与自编编译器
  不导入 `memcpy/strlen`；Linux arm64 生成汇编经开发用 clang 组装，目标对象无未定义符号。
- 入口声明由 `compiler/gen/symbols.yh` 标识，目标汇编由
  `compiler/gen/emit_runtime_memory.yh` 发射，并接入 `emit_arm64.yh`。

## 性能与边界

Apple M1，冻结语料 25 个文件、13,338 行，20 次测量。无改动热构建中位数/p95 为
105.9/129.8 ms；单函数体修改为 774.5/878.5 ms；冷编为 1,952.6/2,173.9 ms。
对照目标 50/200/1,000 ms，三项均未达到。改单函数仍 check 当前模块的 80 个函数，
缓存仅避免其余模块重建及对象/链接工作；后续需推进函数级 check/IR 缓存并继续分析
项目扫描与语义阶段耗时。

当前导入清单仍有 `malloc/free` 与审核中的 OS API；系统汇编器/链接器也仍通过显式
argv 使用。Linux 目标仅完成汇编对象交叉组装，尚未在 Linux 原生运行。因此该切片
不能作为 R3 完成或无系统工具链完成的证据。

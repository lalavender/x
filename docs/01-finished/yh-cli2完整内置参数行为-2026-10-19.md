# yh CLI2：完整内置参数行为（2026-10-19）

计划见[实施方案](../02-plan/yh-cli标准库实施方案.md)的 CLI2，
接口语义见 [cli 设计](../03-design/yh-cli标准库设计.md) 第 8/9 节。

## 目标

把 CLI1 的「最小可用」补齐到设计第 8/9 节的完整内置行为：
完整数量模型、全部内置 action、值形状（标量/列表/批次列表）、
token 识别规则（等号、附着值、短组合、负数、唯一缩写）、
choices 与默认值合并，并对非法声明组合给出配置错误。

## 已实现的行为

- **数量模型**：`single`、`exactly(n)`、`optional`、`zero_or_more`、`one_or_more`、
  `remainder`、`no_values`、`infer`。`infer` 由 action 推导：消费值的 action 为
  `single`，零参数 action 为 `no_values`。
- **值形状**：`store` 标量 depth 0 / 多值 depth 1；`append` 标量 depth 1、
  多值批次 depth 2；`append_const`/`extend` depth 1；`count` 与布尔 action 为标量。
  `exactly(1)` 仍是单元素列表，与 `single` 的值形状明确不同（`get_text` 对前者返回 -2）。
- **action**：`store`、`store_const`、`store_true`、`store_false`、`append`、
  `append_const`、`extend`、`count`（溢出报 usage_error）、`boolean_optional`
  （自动生成 `--no-xxx`，最后出现者胜出，缺省 none）、`help`、`version`。
- **位置参数分配**：按「声明顺序贪心 + 保留后续最低需求」，按选项边界分段；
  已完成的可变位置参数不因后面的新段重新打开，多余 token 报 usage_error 并带下标。
  `remainder` 一旦轮到就吞掉其后全部 token（含 `--help`、`--`、选项样式），
  段分配遇到 remainder 会把未消费 token 归还主循环。
- **token 识别**：精确名称 → `=` 拆分（含显式空串）→ 唯一长名称缩写（`allow_abbrev`，
  多义报错）→ 短选项组合（`-vvv`、`-abc`、`-Ipath`、`-I=path`）；
  零参数 action 带附着值报错；`--` 结束选项识别；单独的 `-` 是位置值。
- **负数特判**：无数字型短选项时，符合负数词法的 token（`-12`、`-1_000`、
  `-0.5`、`-2e-3`）按位置值处理；注册 `-1` 这类名称后关闭特判。
- **choices**：按转换后的类型与值比较，逐项校验；候选不含序列与 none。
- **默认值**：`inherit`/`explicit`/`suppress`、parser 级 `argument_default`、
  `set_default` 覆盖、`get_default` 查询；位置 `zero_or_more` 无输入产生空列表；
  `single`/`one_or_more`/`exactly(n)` 位置参数不能靠默认值绕过数量要求。
- **配置校验**：零参数 action 不得改写数量；`extend` 只接受多值数量；
  `append` 不接受 remainder；`remainder` 之后不得再声明位置参数；
  同 dest 必须具有一致的叶子类型与列表层数（兼容的布尔 action 可共用）。

# yh LLVM LL5 切片：数组切片与切片共享（2026-10-15）

**状态：**局部切片切片完成并验收。LL5 剩下的**全局/字符串/CT 数据**尚未完成，
原因与后续方案见 §4；LLVM 默认未切换、种子未滚。

## 1. 范围

- `let s []int = a[i..j];`（数组切片）、`s[i..j]`（切片再切片）、动态边界；
- `let u []int = [7, 8, 9];`（切片字面量，后备数组在函数入口预分配、循环内复用）；
- `s[k]` 读写共享底层数组（写切片即写原数组）、切片副本 `let t = s;`（16 字节复制）；
- `len(s)` 运行期长度；
- 头部布局 `{len u64, ptr *void}`（与旧后端及模块切片布局一致）。

## 2. 实现

**IR/后端**：复用数组切片的 `ALLOCA`/`GEP`/`MEMCPY`，无需新指令；头部字段用
`GEP + LOAD/STORE` 访问（ptr 字段以不透明指针类型存取，元素访问再 GEP 出
canonical 元素指针）。

**Lowering（`compiler/ast/checked_module_lower.yh`）**

- `checked_lower_slice_ptr`：切片变量的数据指针取头部 +8；切片表达式按
  `基址 + start×stride` 计算（数组/切片/指针三种基址）；
- `checked_lower_slice_len`：变量取头部 +0；切片表达式按 `end - start`；
  `len` 的语义类型是 `i32`，用 `checked_lower_adjust` 截回；
- `checked_lower_slice_header`：把变量副本/切片表达式/字面量写进头部；
- 切片字面量后备数组在函数入口按**表达式编号**预分配（`l.slice_storage`），
  循环内复用同一块存储；
- `lvalue_ptr` 的 INDEX 分支识别切片基址，改用头部数据指针；
- 聚合存储与序言放行 `TY_SLICE`；数组元素写入重构为
  `checked_lower_array_elements`（数组与切片字面量共用）；
- 修复分派顺序：切片字面量必须先于数组字面量分支处理。

## 4. LL5 剩余：全局/字符串/CT 数据（未完成，给出实测根因）

本片尝试继续做全局对象时确认了硬阻塞：**受检快照不含全局初始化表达式**。

- `parse_global_init` 的数据发射路径在解析全局初始化式时显式关闭 AST 捕获
  （`parse_decl.yh`/`parse_global_init.yh` 一带 `c_ast_capture = 0`），
  `AstDecl` 也没有初始化表达式字段；
- 快照只复制了 `bss_symbols`（零初始化全局清单）与字符串标签→名称池字节，
  没有已初始化全局的数据字节；
- 因此 LLVM lowering 既拿不到初始化表达式、也拿不到物化后的字节。

完成它需要独立切片：
1. 解析层为全局 `let` 捕获初始化表达式（`AstDecl` 增加 `init_expr`，在全局
   解析阶段开启捕获并挂边），快照与 verifier 同步；
2. 常量初始化求值器（标量/数组/结构体字面量递归物化字节，零初始化走 BSS）；
3. IR 增加全局取址指令（如 `IR_OP_GLOB_ADDR`，imm=模块符号下标）与模块
   verifier 校验；LLVM 发射把已定义全局统一按 `[N x i8]` 字节数组输出；
4. 字符串字面量表达式 → 匿名内部字节全局 + 取址；跨模块 `pub` 全局与
   private linkage 验收；CT backing 数据（含重定位）单独收敛。

这些改动跨解析、快照、IR、后端四层，按仓库规则需要 `.yh` 用例与
`make test`/`make selfhost-native` 同轮验收；本轮不再硬塞，作为 LL5 收尾的
下一步切片列入 todo。

# yh test 标准库内建测试与门禁（YT3a）实施记录

日期：2026-10-23。范围：给标准库加内建 test 块、接入 make 门禁，并修复暴露的
两个编译器缺陷。`compiler/` 内嵌测试（YT3b）以滚种子为前提，未实施。

## 交付

- `libs/string/99_tests.yh`（新文件）：5 条内建测试
  - 视图相等与比较（`view_equal` / `view_compare`）
  - 前后缀与查找（`starts_with` / `ends_with` / `contains` / `find`）
  - 无分配切分与修剪（`trim_ascii` / `split` / `split_next`）
  - 拥有者增长与 `c_str`（`from_view` / `append` / `append_byte` /
    `byte_length` / `c_str` / `release`）
  - UTF-8 校验（`utf8_validate` 的合法与非法输入）
- `Makefile`
  - 新目标 `test-lib-tests`：`cd libs && $(YH_RUN) test string --timeout 60`；
  - `make test` 与 `make selfhost-native` 均已接入。

## 修复的真实缺陷

1. **非目标项目的 test 声明被当作真实函数**
   - 现象：在标准库项目里跑 `yh test string` 时，作为依赖/标准库副本的
     `string` 模块也会登记测试函数，但它的测试体不参与本轮检查，导致
     `内部错误：函数声明 AST 缺少函数体根`。
   - 修复：新增 `p_test_decl_active()`（parse）与 `ast_decl_test_active()`
     （ast），只有当前文件所属项目等于 `c_test_project` 时才登记测试函数与
     绑定符号；其余项目按生产构建处理（只做语法）。
2. **源码根内构建产物被当源码扫描**
   - 现象：`libs` 项目 `source = "."`，`tmp/yh-test/gen/.../entry.yh` 落在
     源码根内；第二次运行会把它当项目源码扫描并再登记一次，报
     `顶层符号重定义（首次声明于 …）`。
   - 修复：新增 `pj_scan_skip_dir()`，源码扫描跳过 `tmp/` 与 `.build/`；
     `yh test` 连续两次运行现在结果一致。

- `make selfhost-native`：模块固定点一致、cc4 自解析 114 个源文件、
  project cases 121/121、标准库内建测试 5/5。

## 边界

- `compiler/` 源码仍不含 test 块：入库种子不认识 test 语法，必须先
  `make seed` 再给编译器模块加内嵌测试（YT3b）。
- 标准库只覆盖 `string`；其他模块的内建测试按需追加，并把模块名加进
  `test-lib-tests`。
- 未滚种子。

# yh LLVM 架构 LA3 完成报告（函数级 IR/check 复用，交付 1–3）

日期：2026-10-22。依据
[分阶段实施方案 §10](../02-plan/yh-LLVM架构分阶段实施方案-2026-10-22.md)与
[RS2 实施修订](../02-plan/yh-RS2-LLVM函数级IR缓存设计.md)。基线：LA0–LA2
完成后的 `llvm` 工作区。本报告覆盖 LA3 交付 1–3；函数级 check 复用已按安全子集启用。

## 1. 结论

项目构建现在按函数复用已序列化的语言 IR：

- 冷编 4 个运行期函数：0 hit / 4 miss / 4 lowered；
- 只改注释/空行：4 hit / 0 miss / 0 lowered（模块对象键变化，worker 仍运行）；
- 改一个函数体：3 hit / 1 miss / 1 lowered；
- 插入第 5 个函数：4 hit / 1 miss / 1 lowered；
- 损坏一条记录：只重建该记录（重建结果可能与原记录逐字节相同），其余仍命中；
- 改接口/CT/布局事实：环境键保守失效，全部 miss；
- 命中构建的对象与 LLVM 文本和冷编逐字节一致；O0/O2 均通过。

整模块前端检查仍保留；本阶段不跳过函数 check，也不承诺单函数 200ms。

## 2. 缓存单元

新增 `compiler/ir/ssa_module_40_function_cache.yh`：

- 从 `IRModule` 抽取单函数及其贡献闭包，构造只含该函数的迷你 `IRModule`；
- 类型闭包按依赖后序保存；符号闭包包含函数自身、`GLOB_ADDR`/`FN_ADDR`
  目标与直接调用名；其他函数降为外部声明；
- 全局闭包包含函数产生的字符串/静态数据及重定位目标；
- 迷你模块只保留一个空正文来源，不复制整份源码；命中时函数/符号 locs 按当前
  函数声明位置重建，避免注释/空行/前置声明移动旧字节偏移；
- 迷你模块先过 `ir_module_verify`，再复用 `ir_module_serialize`；
- 外层 32 字节头保存 magic、格式版本、环境键与 payload 长度；
- 递归/前向类型闭包返回 1（跳过缓存），由正常 lowering 重建。

新增 `compiler/ir/ssa_module_50_function_rebind.yh`：

- 反序列化迷你模块并核对完整目标/环境/函数身份；
- 类型按结构复用或补建，符号按名字复用或补建，全局按符号与内容复用/补建；
- 把函数体的模块符号/类型下标、`type_map` 与 locs 重绑到当前模块；
- 返回 0 成功、1 损坏/不兼容按 miss、-1 内部错误。

## 3. 键与生产接入

新增 `compiler/ast/module_snapshot_lower_cache.yh`：

- 函数键 = schema + 模块环境键 + 目标/指针位宽/布局/ABI + 源路径 +
  类型/字段/签名布局哈希 + 非函数声明 token 流 + 本函数 token 流；
- 词法器不保留注释/空白，注释/空行/缩进不改变函数键；
- 非函数声明（全局/常量/类型）进入键，运行期函数体不进入其他函数的键。

新增 `compiler/cmd/function_ir_cache.yh`：

- 目录 `<build>/firc/<tag>/`，`index` 每行一个 16 位十六进制键；
- 环境键由目标/优化/编译器指纹/桥版本 + 本模块 `.s.i`/`.s.ct` + 依赖接口
  内容算出，不含本模块函数体源码；
- 装载失败按空缓存；记录与索引在模块完整成功后原子提交；
- 缓存写失败只报告，不把只读/满盘环境变成编译失败。

`ast.lower_module_cached` 在 LA2b 的函数接缝查/写缓存；`module_worker` 与
`llvm_pipeline` 接入项目构建。单文件入口暂不接缓存。

## 4. 统计

`--stats` 现在区分：

- `ir_functions`：参与缓存判定的函数数（命中 + 未命中）；
- `ir_cache_hits` / `ir_cache_misses`：函数 IR 命中/未命中；
- `ir_lowered`：实际调用 `checked_lower_function` 的函数数；
- `checked_functions` / `backend_emitted_functions` 继续表示模块总函数与
  实际发射数。

## 6. 未完成与限制

- **LA3.3 函数级 check 复用已按安全子集实现**：设计见
  [函数受检事实缓存设计](../03-design/yh-函数受检事实缓存设计-2026-10-22.md)；
  C2 受检 AST 切片离线往返完成，C3 按方案 A 启用 session ready、依赖 CT 哈希门、
  源码级 const 值进入函数键与切片内存上限。`ct5b-transitive-body-invalidates-
  importer` 与 check 缓存矩阵通过；CT/模板/超大函数仍保守执行完整检查。
- 递归/前向类型闭包暂不缓存；这类函数每次重新 lowering。
- 旧版本 `.fir` 记录不主动删除；索引只列当前构建参与的函数。
- 命中时导入的符号/函数 locs 统一使用当前函数声明位置；冷编对字符串等符号
  可能保留更细的来源，诊断精度略有差异。
- check/IR 缓存装载有单记录 1 MiB、单集合 16 MiB 上限；超限函数按 miss
  完整检查，内存峰值尚未做专门基准。
- 单文件 `-o`/`--emit-asm` 路径未接函数缓存。
- 单函数 200ms 是性能任务目标，本次未做 20 轮性能测量，命中本身不证明达标。

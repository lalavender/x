# yh LLVM LL5 第一切片：局部标量内存（2026-10-15）

**状态：**第一切片完成并验收；聚合、全局数据、切片与指针算术仍按后续切片推进，
LLVM 默认未切换、种子未滚。

## 1. 范围

把 yh 的「局部标量取址 → 参数/局部指针 → 解引用读写」接进 LLVM 后端：

- `let p *int = &x;`（取局部/参数地址）
- `fn inc(p *int, d int) int { *p += d; return *p; }`（参数指针 + 复合赋值）
- `*p = v`、`*p += v`、`let v = *p`（解引用左值与右值）
- 循环内通过指针写入、指针局部经 if 合流（phi）、`void` 指针参数函数

聚合、全局对象、切片、`&arr[0]`/`&s.f`、指针算术继续带来源拒绝，不静默回退。

## 2. IR 与 lowering

**类型编码（`compiler/ir/ssa.yh`）**：`IR_TY_PTR` 扩展为 canonical 指针族
`12..24`，下标 = `IR_TY_PTR + 元素 kind`，`elem` 必须等于 `kind - IR_TY_PTR`；
`IR_TY_PTR`（12）仍保留旧 SSA 路径的「通用指针 + 任意元素」语义，两者兼容。
模块层指针统一 `IR_TY_PTR`，元素经 `type_map` 精确对照（`ssa_module_20_verify`）。

**新指令 `IR_OP_ADDR`**（`imm` = 函数内稳定绑定 ID）：在入口块为每个被取址的
绑定发一条，结果是按绑定类型编码的 canonical 指针；LLVM 后端把它降为 `alloca`。
函数 verifier 校验 `imm >= 0`、无 a/b/aux、结果是非 void 的 canonical 指针。

**lowering（`compiler/ast/checked_module_lower.yh`）**：

- 预扫描当前函数的表达式范围，标记 `&primary(变量)` 的绑定；
- 入口块按绑定顺序发 `ADDR`；被取址的**参数**同时把 PARAM 值 STORE 进槽；
- 被取址绑定的读取走 LOAD、赋值走 STORE；复合赋值先 LOAD 再按既有提升/截回
  规则计算；局部不再进入 SSA 值表；
- 循环携带与 if 合流跳过内存绑定（读取一律经 LOAD，不建 phi）；
- `&` 只接受 `&变量`；`*p` 检查指针元素类型与表达式类型一致；
- 所有拒绝仍带快照来源位置（`<文件>:行:列`），不发布部分产物。

`checked_lower_function` 现在在失败时写明确原因（SSA 校验 / 模块增建 / 模块校验），
不再一律报「构造或校验失败」。

## 3. LLVM 发射（`backend/`）

- `llvm_type` 把指针族发射为 opaque `ptr`；`llvm_type_supported` 放行指针，
  浮点/聚合继续拒绝；
- `IR_OP_ADDR` → `%vN = alloca <元素类型>, align <自然对齐>`；
- `IR_OP_LOAD`/`IR_OP_STORE` → `load`/`store`，未知来源对齐统一 `align 1`；
- 指针 `PARAM`/`COPY` 用零偏移 `getelementptr i8` 固体，指针 `CONST` 用
  `inttoptr`（不透明指针不能参与 `add` 整数 0 的旧发射法）；
- CALL 参数/返回按 opaque `ptr` 发射，指针函数签名在模块层验证。

## 5. 边界与后续

- 尚未支持：聚合与嵌套取址、全局/字符串/CT 数据、切片共享、指针算术与
  `&arr[0]`/`&s.f`、指针与整数转换（`ir_const_type` 仍只覆盖整数/bool）。
- 每个检查过语义的模块在 checked-lowering 下固定 25 个 canonical 类型
  （13 标量 + 12 指针变体），模块序列化身份随之变化，缓存自动失效重建；
  专用内存 lowering 文件（`ast_ir_memory.yh`/`llvm_memory.yh`）等聚合切片再拆。
- 未做对齐证明，load/store 一律 `align 1`；LL8a 的 `memcpy`/`memset` 尚未被
  聚合复制路径消费。
- LLVM 默认仍未切换，`--backend llvm` 需显式给出，种子未滚。

# yh os/sys OS1 收尾：短写、EINTR 与 CLI 重验

日期：2026-10-21。状态：**OS1 完成**（Linux/arm64 原生；Linux/x64 原生门由 CI 承担）。

依据：[os/sys 联合设计](../03-design/yh-os与sys标准库设计.md)、
[联合实施方案](../02-plan/yh-os与sys标准库实施方案.md) OS1 第 5 项。

## 1. 短写与 EINTR 驱动

新增 `tests/modules/projects/syseintr`（Linux 专属）：

- `c/intr.c` 安装**不带 SA_RESTART** 的 SIGALRM 处理器，并提供
  `test_socketpair`：创建 Unix 流式 socketpair 并把写端设为非阻塞。
- EINTR：在空管道上阻塞 `sys.read_fd`，1 秒后 SIGALRM 中断；断言返回
  `-EINTR`、处理器已运行，并确认中断后管道仍可写入/读取。
- 短写：向非阻塞 Unix 流式 socket 循环写入 65536 字节，直到发送缓冲不足；
  分别验证 `sys.write_fd` 与 `os.write_some` 返回 `0 < count < 65536`，
  而不是把整块当成功或提前放弃进度。
- 用例在开始/结束关闭全部 pipe/socket fd；失败返回不同诊断码。
- C 辅助只存在于测试 fixture，不进入标准库或编译器产品路径，不向公开 API
  添加测试开关。

为此提前交付 `sys.create_pipe(output *int, flags int)`（pipe2）及
`O_NONBLOCK`/`EAGAIN` 常量；fork/exec/wait 仍属 OS4。

## 2. CLI 重验与编译器修复

`libs/cli/test/run.py --compiler ./yh` 首轮 1/9：LLVM lowering 在
`libs/cli/extensions.yh` 的 `converter.to_type(*void)` 处报“首片不支持”。
根因是 fn 值到普通指针的显式 cast 未被当作指针转换：

- `compiler/ast/module_snapshot_lower.yh`：`checked_lower_adjust` 把
  `IR_TY_FN_PTR` 计入 from/to pointer。
- `compiler/ir/ssa.yh`：SSA CAST verifier 同样接受 `IR_TY_FN_PTR` 与普通指针互转。
- `compiler/backend/llvm_scalar.yh`：LLVM 中 fn 值本来就以 opaque ptr 存储，
  `llvm_cast` 对 fn↔ptr 按 ptr↔ptr 发射 `getelementptr i8, ptr ..., i64 0`，
  不生成类型错误的 `inttoptr i64 <ptr>`。

新增运行语料 `tests/yh-run/run/llvm-fnptr-null-cast.yh`：函数指针字段经
`*void` 做空判断，再赋值并间接调用。CLI 重验随后 **9/9** 通过。

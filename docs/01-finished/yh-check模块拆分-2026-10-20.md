# AST 一致性校验拆分为 check 模块（arena 阶段）

日期：2026-10-20。基线：`origin/llvm`（`6eace6f`）。

## 交付内容

- 新增 `compiler/check/verify.yh`，把表达式、语句、声明、函数上下文四项 AST
  一致性检查迁出 `ast`。四个检查器改为模块私有；`verify_module` 按表达式、语句、
  声明、函数顺序执行，并以 0 表示成功、1–4 表示失败阶段。
- `compiler/ast/ast_view.yh` 新增 `AstView` 与 `ast_view(out)`。视图只借用捕获
  arena、计数、解析/根链及函数封存状态，不分配、不复制、不转移所有权；仅在
  捕获完成且 AST 未修改/reset 时只读使用。
- `AstExpr`、`AstStmt`、`AstFunctionContext` 与 `AST_EXPR_ARG_LIST` 改为公开；删除
  原四个 `ast_*_verify` 导出。`cmd/module_worker` 两处与 `cmd/llvm_emit` 一处
  统一调用新入口，保留原有具体诊断和阶段外层诊断。
- 新增 `tests/modules/projects/astcheck/`，覆盖最小合法 AST、损坏的表达式子引用、
  语句链、声明函数体、函数上下文范围、绑定与编译期 `$for` 关联、捕获关闭和只读
  行为。项目验收脚本复制实际编译器模块至 `tmp/` 后执行；同步修复 `llvmlower`
  测试夹具对旧 AST 校验导出的依赖。
- 阶段一的依赖为 `check → ast/gen`、`cmd → check`；`parse` 不依赖 `check`。当时
  `CheckedModule` 快照校验仍留在 `ast`；后续快照迁移见下方第二阶段记录。

## 第二阶段：CheckedModule 快照校验（2026-10-20）

- 将原 `ast.checked_module_verify` 及其 `checked_storage_present`、全部
  `checked_verify_*` 私有实现迁至 `compiler/check/checked_module.yh`，统一入口为
  `check.verify_checked_module`。原 AST 文件已删除，不保留转发函数。
- 新增 `ast.CheckedModuleView` 借用快照的表、计数和目标身份，不分配、不复制、不
  转移所有权。AST 捕获保留复制/释放安全 guard，但不再执行内容一致性校验；所有
  `checked_module_capture` 后的 lowering/校验调用点在消费前显式调用 check。
- 更新 LLVM 模块 worker、单文件 LLVM 路径及 `llvmchecked` / `llvmlower` 测试。
  测试验证快照损坏被拒、恢复后通过、释放状态与另一个快照的独立性。`ast` 和
  `parse` 都不依赖 `check`；SSA 验证继续归 `ir`。
- Apple Container `debian:stable-slim`（Linux/arm64）中，`make`、`make test`、
  `make selfhost-native` 全部退出 0。固定点 129 项产物一致，自解析 107 个源文件，
  模块语料 18/18、项目验收 106/106；`yh check` 不生成后端产物。`make test` 的语法、
  运行与代码统计数量与第一阶段相同，详见上方验证记录。
- 容器未准备 LLVM host 桥/SDK，自举使用过渡种子内路径并在日志提示；种子哈希
  保持 `8ea2a9acc20438b385ccddd522b50b8dd4749423c8db2695c758296ada343b8c`，未滚种子。

# 跨模块编译期调用的单字节指针常量实参

日期：2026-10-07。状态：已完成。第 39 轮根因链的前置切片，本轮查清后**一次交付**。

## 上一轮的误判（先说清楚）

第 39 轮我判定「前置切片 = 扩展 CT 闭包收集」，依据是两条尝试都失败：

- `$math.head_of(math.TEXT)` → 「模块没有导出该名字」
- `pub const TEXT_PTR *char = base.TEXT;` → 「pub 指针常量（字符串）暂不支持跨模块导出」

**这两条失败都不是真正的阻塞。** 真正的原因是我把用例写错了：

`iface.yh:334-348`（`SYM_CONST` + `F_ADDR` 分支）**本来就支持**字符串字面量指针常量的导出，
条件只有一个 —— 常量的初始化必须是**直接字符串字面量**（`const_expr_kind == 2`），
接口把它「原样重放（含引号与转义）」，注释写明「导入方按与函数体内字面量相同的规则重新登记
只读字节池」。

所以：`base.TEXT` 转发失败是因为初始化式**不是字面量**（是引用），而不是「不支持导出」；
换成 `pub const TEXT_PTR *char = "AB";` 就一切正常。**闭包收集完全不需要扩**。

## 改动（一处放宽 + 诊断）

`compiler/parse/parse_expr.yh` 的单字节指针形参实参检查，原逻辑只接受**直接写在实参位置的
字符串字面量**（就地登记只读池），其余跨模块写法一律拒绝。放宽为：实参是
`SYM_CONST + F_ADDR + is_const` 的指针常量时也接受 —— 这类常量的标签号是**本地**的
（接口重放后在导入侧重新登记过字节池），与直接字面量走同一条路径。

```yh
} else if (qualified != 0) {
    // 非字面量实参：导入模块里以**字符串字面量**初始化的 pub const 指针常量由接口
    // 原样重放（`iface.yh` 的 F_ADDR 分支），导入侧的字面量已重新登记只读字节池，
    // 因此它的标签号是**本地**的，与直接字面量走同一条登记路径，可以直接使用。
    let asym int = args[arg_n].sym;
    ...
    if (local_addr == 0) {
        return gen.sem_err("编译期调用的单字节指针形参（char/u8/i8）只接受直接字符串字面量实参，或导入模块里以字符串字面量初始化的 pub const 指针常量");
    }
}
```

# 编译期顶层聚合实参诊断与聚合能力探针

日期：2026-10-07。状态：已完成（诊断加固；同时确认聚合能力无缺口）。

## 探针结论：聚合值能力已完整

用探针覆盖编译期聚合值/左值的剩余形态，**全部支持**：

| 场景 | 结果 |
| --- | --- |
| 结构体整体复制后改嵌套字段，原件保持隔离（值语义） | 98（含原件 0） |
| 定长数组复制后改元素，原件保持隔离 | 8（7 + 1） |
| 结构体**数组字段**的切片视图别名写回 | 5 |
| `for-in` 遍历结构体数组字段与切片字段 | 21（6 + 15） |

即前几轮记的「CT3 剩余：其他聚合值与一般左值」在常见形态上已无缺口。

## 探针发现的缺口：顶层聚合实参

顶层（或普通函数里）的编译期调用**不能**直接写聚合字面量实参：

```yh
@[comptime] fn take(p Point) int { return p.x; }
const R int = $take(Point{ x: 1 });   // 结构体字面量不是编译期常量
const S int = $sum([1, 2, 3]);        // 数组/切片字面量不是编译期常量
```

原因是顶层实参必须在 pass1 折叠成常量，聚合字面量做不到（聚合值要在编译期函数体内
构造才走 typed IR 执行器）。

## 本轮改动

原诊断「结构体字面量不是编译期常量」「数组/切片字面量不是编译期常量」像是在报内部
不变量，用户看不出该怎么改。`compiler/parse/parse_expr.yh` 的编译期调用实参解析新增
前置判定：实参位置是聚合字面量（`[` 开头，或 `标识符{`）且对应形参是聚合类型
（结构体/联合体/数组/切片）、且当前不在编译期函数正文里时，直接给出可读诊断：

```
编译期调用实参里的聚合值需要在编译期函数体内构造（顶层实参必须是编译期常量）
```

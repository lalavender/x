# 编译期调用实参里的直接字符串字面量

日期：2026-10-07。状态：已完成。

## 问题

直接写在编译期调用实参里的字符串字面量无法使用：

```yh
@[comptime] fn first_of(p *char) int { return (*p).to_type(int); }
const A int = $first_of("A");   // 错误: 编译期指针形参必须来自当前存活调用帧的标量局部取址
```

顶层或普通函数里的编译期调用实参由**前端直接求值**（`sem_string` → 数据标签号），
不经过 typed IR 捕获，也没有符号可查，因此 `ct_pool_adopt_label` 的符号反查路径
（上一轮加的 `F_ADDR` 常量反查）对它无效。

## 修复

让前端在求值字符串字面量时**登记标签 → 原样字节**映射，编译期侧按标签号反查：

1. `gen/state.yh`：新增独立全局表 `c_data_str_lbl/off/len`（上限 128 项）与
   `data_str_add` / `data_str_lookup`；`state_init` 复位计数。
   **不放 `GenState`**：`GenState` 已大到让后端单条 `add` 的字段偏移越界
   （`add x0, x0, #6528` 超过 12 位立即数范围，汇编直接失败），再加 3 个数组会立刻踩坑。
2. `gen/sem_value.yh` 的 `sem_string`：分配数据标签后调用 `data_str_add`
   （intern 原样字节，含引号与转义），表满时静默降级为旧行为。
3. `comptime/ct_ir.yh` 的 `ct_pool_adopt_label`：符号反查失败后按标签号调用
   `data_str_lookup`，命中则登记只读池并把实参值换成池地址。

映射表按会话/worker 累积，与 `c_data_n` 的计数范围一致，标签号在表内唯一；
跨模块实参仍走符号路径（提供方标签号不在本 worker 表内）。

## 边界

- 映射上限 128 项：单文件字面量超过上限后新字面量不再登记，退化为旧的拒绝路径。
- 跨模块实参里的**直接字面量**（`$other.f("abc")`）不在本 worker 表内，仍拒绝；
  用导出常量（`pub const X *char = "..."`）是支持路径。
- 非字符串指针常量（全局数组地址等）仍拒绝。

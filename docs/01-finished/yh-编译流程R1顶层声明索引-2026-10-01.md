# 编译流程重规划 R1 第二切片：顶层声明范围索引

日期：2026-10-01。建立顶层声明的紧凑 token 范围索引，降低旧式递归下降
编译器在 pass1、全局初始化 pass 与函数 pass 中重复遍历无关 token 的成本。

worker 在项目文件完成词法分析和 module/import 头解析后，扫描文件剩余 token，
记录每个顶层声明的起止位置、声明关键字和起始源位置。索引阶段不执行名称或
类型解析，也不建立表达式/语句树。模块 pass1 按索引解析声明签名，并直接跳到
函数体末尾；全局 pass 只解析 let/const；函数 pass 只解析 fn。单文件旧路径
保持原有 parser 行为。

新增的项目索引回归沿用三文件/两模块 `.yh` fixture，覆盖 token 重放、私有
跨文件类型、前向函数调用和跨模块导入。现有项目矩阵还覆盖 `pub struct`
后紧跟 `pub fn`：索引扫描最初漏把 `pub` 当作顶层起点，造成后一个函数失去
公开标志；修正后项目矩阵 32/32 通过。计数结果中，两个 worker 为 fixture
重复索引全部 4 个声明，`syntax=8`；项目索引 9 次、词法 10 次，三类模块遍历
各 3 个文件。

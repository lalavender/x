# 编译期成员名字段修复与表达式/语句覆盖审计

日期：2026-10-07。状态：已完成。

## 缺陷

结构体字段名使用被语言用作关键字的文本时，编译期成员访问报内部错误：

```yh
pub struct Holder { in int; }
@[comptime] fn f() int { let h Holder = Holder{ in: 5 }; return h.in; }
// 错误: 内部错误：编译期成员名 token 无效
```

前端允许这类字段名（字段匹配本来就按源文本进行），只有编译期路径额外校验
`member.kind == TOK_IDENT`，而 `in` 的词法类别是 `TK_IN`，于是把合法的字段名判为无效，
且暴露的是内部错误而不是用户可读诊断。

## 修复

`compiler/comptime/ct_ir_place.yh` 的成员名解析删掉 token 类别校验，只保留范围校验：
字段名与字段表按源文本逐字节比较，token 类别不影响匹配结果。

## 覆盖审计

顺带用探针把编译期表达式与语句种类过了一遍，结论是**当前全部支持**：

| 类别 | 覆盖情况 |
| --- | --- |
| 表达式 | 算术 `+ - * / %`、位运算 `& \| ^ << >>`、比较 `== != < <= > >=`、逻辑 `&& \|\| !`、一元 `- ~`、三元 `?:`、成员访问、下标、取址 `&` 与解引用写回 `*p += n`、`sizeof`、`.to_type` 转换、`len`、切片视图 `a[i..j]`、浮点算术、字符与字符串字面量 |
| 语句 | `if/else if/else`、区间 `for-in`、条件 `for` + `break`、`continue/break` 混合、`switch case/default`、`for-in` 双绑定（下标在前）、嵌套块、`$if/$for`、`$assert/$compile_error/$compile_warn` |

明确仍在拒绝路径上的是语言本身不允许或已立项的项：`goto`/标签语句、函数正文内的类型
声明（诊断已具体化）、`case` 值位置的 `$`（语法不接受）、枚举判别值用编译期调用。

### 附：撤销一个误判立项

上一轮把「`sizeof` 对定长数组返回 长度 × 4」记为缺陷，实测 `sizeof(int) == 4`
（`int` 就是 4 字节，与 `i32` 同宽），因此 `[3]int` = 12、`struct { [3]int; int }` = 16
都是正确值，该条目已撤销。

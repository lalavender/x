# yh LLVM LL5 全局与字符串数据切片（2026-10-16）

状态：普通全局与字符串数据切片完成，独立审查修复、完整门和 17 个 LLVM
专项门全部通过；结果见下方验收表。
承接 [实施方案](../02-plan/yh-LLVM-LL5全局数据切片实施方案.md)，无语法变更。

## 1. 范围与数据交接

- 模块级整数/bool/char/enum 的常量初始化与零初始化；定长数组、嵌套结构体
  字面量与零初始化 union，指针字段/元素允许 NULL。
- 全局读写/取址、字段/下标、聚合副本、全局数组的切片共享、数组长度；
  标量 const 引用在函数体内按已确定的声明类型取值。
- 字符串表达式和字符串常量引用：完整转义、嵌入 NUL、终止 NUL、UTF-8 字节，
  按原标签去重并保留对象身份。
- 提供方 pub/private linkage 与现行模块后缀规则；LLVM 项目模式尚未接入，
  本片不把提供方符号验证视为跨模块消费通过。

`AstDecl.init_expr` 保存全局初始化根，解析三条路径（标量、数组、结构体）同步
构造 AST；声明和受检快照 verifier 检查归属及范围。快照独占源码、表达式与
字符串目录，lowering 在原 arena 销毁后仍可构建独立模块。

新增 `compiler/ast/checked_module_global.yh` 负责对象布局、字节物化、全局符号
映射及字符串。整数读取前端折叠位型，按目标大小写小端字节；数组按元素位置、
结构体按受检字段偏移递归，预清零缓冲保留布局间隙和尾部填充。无初始化根时
只接受 BSS 清单，不把缺失 CT 数据当成零。

## 2. IR 与 LLVM

`IR_OP_GLOB_ADDR` 的 imm 为模块符号下标，函数 verifier 检查指令形态，模块
verifier 检查它指向已定义全局且结果映射为指针。读取与写入复用 LOAD/STORE，
聚合位置和副本复用 GEP/MEMCPY；全局数组可直接作为已实现切片的基址。

已定义全局统一发 `[N x i8]`，全零用 `zeroinitializer`，其余输出完整字节串，
保留大小、对齐和链接属性。canonical 指针扩到 36，覆盖读取/写入 `*int` 对象
所需的 `**int` 地址；更深字段/下标存储地址明确拒绝，避免类型表越界。

## 3. 独立审查与红绿回归

审查确认四类 Important 问题，均形成正式回归后修复：

1. 字符串被发成只读 `constant`，经 *char 写入触发 SIGSEGV。
2. 源聚合 const 同样允许裸指针别名写，发只读对象也会触发 SIGSEGV。
   两者现均为可写 `global`；前端对 const 直接左值的限制保持现行语义。
   手建 IR 的真正只读对象仍可由后端发 `constant`。
3. 任意指针 `const_bits` 可能是整数，也可能是旧字符串标签；数字 1 恰好
   命中字符串标签时曾被错编为字符串地址，反向转换曾把地址错编为整数 1。
   现要求字符串来源可追溯，指针/整数转换在本片明确拒绝。
4. 函数体 CAST 的 `is_const` 不代表已折叠：运行期前端仍可能保留转换前位型。
   快捷路径缩到常量叶、整数字面量一元式、枚举和数组长度；括号先解包，
   CAST 逐节点处理。i8/u8 窄化再拓宽、浮点转换拒绝均有独立断言。

另外，测试锁住 bool 常量的低八位（2 不能归一为 1）、完整 u64 位型、显式
i64 宽文字量、NULL/聚合指针等值比较，以及窄负字面量的上下文类型适配。

完整项目门另抓到接口重放边界：`.s.ct` 的隐藏常量解析使用临时文件/声明编号，
没有本模块的 AstDecl；开启全局 AST 捕获会报“找不到全局 AST 声明节点”，
首次项目验收为 98/100。现仅在接口/CT 闭包的全局初始化调用期间暂停捕获，
求值与 CT 模型保留，返回后恢复原开关，随后 CT 函数正文仍按现行流程捕获。
`comptimecross` 新增 `capture_boundary.yh`：另一源文件的私有常量经私有 CT
过程进入公开正文闭包，在消费者中真正执行。修复后该项目独立构建与运行退出 0。

## 4. 测试与验收

新增 `tests/yh-run/run/llvm-global.yh`，共享源由 `llvm-global.py` 去掉旧入口后
交给真实前端；O0/O2 精确检查对象字节，再经 opt verify、clang 对象生成、
宿主 `/usr/bin/gcc` 链接并运行 C 驱动。C 独立检查对象地址、可写别名、填充、
完整字符串和导出数据，避免只依赖 yh 内部比较得到假阳性。

`llvmlower/input/global.yh` 由负例转正，配套快照/项目门同步；新增 11 个合法
前端输入的拒绝 fixture，分别检查 LLVM 文本和二进制两条入口均不发布部分产物。
独立 `llvm-global-backend.py` 用手建 IR 验证只读/可写、链接、对齐、16 字节
非零数据后半段和拒绝后输出保持原值。

## 5. 剩余边界

CT backing、导入聚合常量副本、静态非零指针重定位、全局切片仍未验收；
浮点归 LL6、聚合调用/ABI 归 LL7，项目 LLVM 驱动与缓存归后续阶段。
因此本片关闭了普通全局/字符串数据切片，不能宣称 LL5 全覆盖或默认后端切换。
本轮不滚种子，不改默认后端。

另发现旧 ARM64 后端对 `!(address() == &cell)` 的既有常量标记问题；已在
`docs/todo.md` 单独登记，本片不扩展修复。验收用 bool 局部承接同一 EQ/NE，
保留 LLVM 指针比较覆盖并使旧后端语义锁通过。

# yh LLVM LL4 首片：嵌套循环、break/continue 与无限循环（2026-10-15）

**状态：**LL4 前两行（嵌套循环与 break/continue、无限循环 `for {}`）完成并验收；
`switch`/`goto`/`for-in` 仍按后续切片推进，LLVM 默认未切换、种子未滚。

## 1. 范围

- 嵌套 `for` 循环：内层 `break`/`continue` 只作用于最内层，外层循环继续携带；
- 无限循环 `for { ... }`：header 无条件进入，唯一出口是 `break`；
- 循环体层级状态（携带绑定、header phi、break 快照、continue/break 计数）
  从单份 `CheckedFlow` 字段改为按嵌套深度共存的 `CheckedLoop` 栈（上限 16 层）；
- 顺带修复两个已在旧单层实现中存在的缺陷（见 §3）。

## 2. 实现

**`compiler/ast/checked_module_ctx.yh`**

- 新增 `CheckedLoop`：每层独占 `carry`（携带绑定 ID，去重源码顺序）、
  `carry_phis`、`break_blocks/break_vals/break_capacity`、`continue_done/break_done`、
  `break_target/continue_target` 与 `stmt_id`；
- `CheckedFlow` 改为 `builder + loops *CheckedLoop + loop_depth`，栈由
  `lower_module` 分配、函数结束释放；上限 `CHECKED_LOOP_MAX = 16`。

**`compiler/ast/checked_module_lower.yh`**

- `checked_lower_carry_record` 把赋值记进**所有**活跃循环层：内层写入的绑定
  同时参与外层循环的跨迭代值；
- `checked_lower_loop` 拆为包装（压栈/弹栈/失败清理）与 `checked_lower_loop_body`
  （两趟协议）；`for {}` 走无条件下钻路径；
- `break`/`continue` 只消费栈顶；`checked_lower_continue` 在发现趟（`carry_phis == 0`）
  只计站点数，避免空指针崩；
- **循环体内声明的绑定不进入携带 phi**：`binding.stmt_id > loop.stmt_id` 时跳过
  （否则 preheader 处该绑定无值，phi 输入为 -1；这是单层实现也存在的潜在缺陷）；
- **无限循环的 exit phi 只以 break 站点为前驱**：header 不连退出块，若仍把
  header 当 phi 输入，verifier 以前驱数不符拒绝（单层实现同样存在的缺陷）；
- `checked_lower_break_snapshot` 改用本层 `break_capacity`，修掉
  `l.function_break_sites` 从未赋值导致的「break + 携带绑定必失败」。

## 3. 门禁与验收

**新增**

- `tests/selfhost/llvm-control.py`：O0 文本至少 4 个 `phi`、3 个条件回边；
  `opt -passes=verify`；O0 文本与 `default<O2>` 管线对象分别 clang 汇编、
  gcc 链接并原生运行（五组嵌套/无限/携带断言退出 0）；`goto` 带
  `bad_goto` 来源诊断拒绝且不发布产物；
- `tests/yh-run/run/llvm-control-flow.yh`：同源旧后端语义锁（170→171，
  总计 309→310）；
- `tests/modules/projects/llvmlower/input/control.yh` + `llvm-lower.py`
  control 用例：嵌套 + 无限循环必须降低成功且 `phis > 0`。

## 4. 边界与后续

- 剩余 LL4 切片：`switch`、`goto`/label、`for-in`；`goto` 现在明确带来源拒绝。
- 循环嵌套上限 16；超出时报「首片不支持此语句或表达式」，不无限增长栈。
- 聚合/全局数据等 LL5 剩余项不变；LLVM 默认未切换、种子未滚。

# yh 编译期 typed 指针算术与指针下标

## 交付内容

- 指针算术：`p + i`、`i + p`、`p - i` 在编译期可用，按 `CtValue` 槽步进。
  编译期聚合元素本身就是 `CtValue` 槽，因此按槽前进等价于语言上「指向下一个元素」
  （f32 元素同样只占一槽）。步数绝对值超过 100000 直接报错。
- 指针下标：`p[i]` 支持读取与写入。`ct_ir_index_place` 增加指针基址分支返回
  `place.direct`，读路径（`ct_ir_index_read`）与写路径（`ct_ir_lvalue` → STORE 的
  direct 分支）因此同时支持。
- 安全边界不变：偏移结果只是地址值，解引用与下标写入统一交给 `ct_ir_pointer_target`
  按存活帧（局部槽区间 + 帧拥有聚合元素块）逐类型匹配解析，越界或指向帧外一律拒绝。
- typed 执行器的指针算术分支排在整数分支之前（否则 `i + p` 会被整数分支截获），
  且只匹配 `+`/`-`，指针比较仍走 `==`/`!=` 分支。
- 用例：`run/138-comptime-pointer-arith.yh`、`fail/140-comptime-pointer-arith-out-of-range.yh`、
  `fail/141-comptime-pointer-plus-pointer.yh`；`comptimelocal` 增加跨源文件指针下标累加
  与指针算术断言。

## 顺带修复的既有缺陷

- 前端 `sem_binop` 的「整数 + 指针」分支只发码、不设 `lhs.type_id`，
  导致 `let q *T = 1 + p;` 报「不能把非指针值赋给指针」。
- `*dst = *src;`（两侧都是指针解引用、结构体类型）会让编译器段错误；
  `ct_ir_index_read` 改为逐字段复制规避，后端根因已记入 `docs/todo.md`
  「编译器已知缺陷」段。

## 边界

- 仍拒绝：指针之间的算术（前端报「指针/数组不参与该运算」）、指针乘除、指针比较大小、
  指针返回逃逸、浮点指针常量。
- 「算出越界地址但不解引用」是允许的常数值行为，访问时才校验。

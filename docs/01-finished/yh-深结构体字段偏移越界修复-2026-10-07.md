# 深结构体字段偏移越界修复

日期：2026-10-07。状态：已完成。

## 缺陷

结构体字段偏移超过 4095 时，通过结构体指针访问聚合字段会生成非法指令，汇编直接失败：

```yh
pub struct Inner { v int; }
pub struct Big { pad [1024]int; arr [4]int; inner Inner; }

fn touch(p *Big, v int) int {
    p.arr[1] = v;      // arr 偏移 4096
    p.inner.v = v + 1; // inner 偏移 4112
    return p.arr[1] + p.inner.v;
}
// 错误: add x0, x0, #4112 / error: expected compatible register, symbol or integer in range [0, 4095]
```

`compiler/gen/sem_expr.yh` 的成员访问在拿到字段地址后无条件发一条
`add x0, x0, #off`。AArch64 的 `add` 立即数只有 12 位无符号（0–4095），
偏移更大的字段必然汇编失败。标量字段走的是 `ldr/str [xN, #imm]`（无符号 12 位
按元素宽度缩放，范围更大），所以只有聚合字段（数组/结构体/切片）的地址计算会踩到。

## 修复

偏移超过 4095 时借 `x12` 装载偏移再 `add x0, x0, x12`，与
`em_lea_local*` 系列既有的深帧约定一致（注释里明确：调用方不得依赖 x12 跨 lea 存活）。

## 验证

- 新增 `tests/yh-run/run/148-deep-struct-field-offset.yh`：覆盖偏移 4096 起的数组字段、
  4112 的结构体字段、8192 起的数组字段与 8208 的标量字段，结果 5678。
- 修复前该用例汇编失败（`add x0, x0, #4112`），修复后通过。
- 复现过程中确认：**编译器自身的 `GenState` 已经大到字段偏移越过 4095**，
  在 `GenState` 里追加 512 个 `int`（2048 字节）后，用修复前的种子构建编译器
  会报 634 处 `add x0, x0, #47xx` 汇编错误；滚种子后用新种子重做同一实验构建成功。
  即该修复同时解除了「编译器状态结构无法继续扩展」的阻塞。
- `make test` 252/252（run 126/126、fail 118/118、pass 8/8）。
- `make selfhost-native` 全绿：自解析 70 文件、语料 252/252、`modules 17/17`、
  `project cases 84/84`。
- 滚种子后冷编复核（`make` + 两道主门）全绿；新种子 SHA-256：`498543a7e5b9483e0ca6877accf54854926fdc6b91b72a3856fc07e42c164cf1`。

## 边界

- 只修了 `add` 立即数越界这一条路径；`ldr/str [xN, #imm]` 的缩放立即数范围更大
  （按元素宽度最多到 32760 字节），实测 131072 字节偏移的标量字段访问正常。
- `x12` 的临时寄存器约定沿用既有做法：调用方不得依赖它跨 lea 存活。

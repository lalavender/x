# LLVM LL8b：Linux x86_64 完整运行时与宿主桥

日期：2026-10-17  
范围：Linux/x86_64 SysV；LLVM 仍是显式实验后端，默认生产后端未切换。

## 交付

- `compiler/backend/llvm_runtime.yh` 为 LLVM 模块提供按需弱定义：`linux_syscall6`、
  `malloc`、`free`、`printf`；并继续提供 `memcpy`、`memset`、`strlen`，需要聚合复制时
  提供 `memmove`。`llvm.used` 保留运行时入口；声明生成跳过由运行时提供的符号，用户已有
  强定义仍优先。
- x64 `linux_syscall6` 采用 `rax/rdi/rsi/rdx/r10/r8/r9` Linux syscall ABI，并声明
  `rcx/r11/memory` clobber。`malloc` 用 `mmap` 分配带 16 字节头的映射，返回 16 字节对齐
  地址；零尺寸请求取得最小 payload，大小溢出和映射错误返回空指针；`free(NULL)` 无操作，
  其他分配按头部记录的映射长度调用 `munmap`。
- `printf` 支持当前 yh runtime 使用的 `%d/%i/%u/%lld/%llu/%s/%c/%%` 格式，按 UTF-8
  字节输出并返回写出的字节数；write 短写会继续，输出错误返回 -1。格式能力和 ARM64
  现有自有 printf 一致，不扩展宽度、精度、浮点格式或 locale。
- CheckedModule/SSA lowering 允许受限 C 裸变参入口与函数指针，按 C 默认提升处理
  bool/窄整数及 f32 参数；指针到指针、指针到整数和反向转换供 runtime/syscall ABI 使用。
  LLVM verifier 接受固定参数之后的变参，后端只在 SysV AMD64 放行裸 C 变参。
- 目录枚举和时钟按目标架构拆分为 `.linux.arm64.yh` / `.linux.x64.yh` 文件，分别采用
  自身 syscall 编号与目录标志。通用 `process.yh` 保持 C ABI `open/fork/execvp/exit/waitpid`，
  由 LL7 的 C ABI lowering 提供支持；LLVM x64 探针实际执行 `/bin/true` 并检查子进程退出码。
- 新增 `tests/yh-run/run/llvm-runtime-complete.yh` 与
  `tests/yh-run/run/llvm-linux-x64-host.yh`。前者覆盖分配大小边界、16 字节对齐、直接/间接
  分配与内存入口、UTF-8/整数格式、长输出、溢出拒绝和 stdout 错误；后者覆盖嵌套中文/空格
  路径、mkdir/open/getdents64/close、单调时钟和 `fork/execvp/exit/waitpid`。
- `tests/selfhost/llvm-runtime.py --suite complete` 保留 LL8a 内存 helper 边界门，随后对两份
  `.yh` 在 O0/O2 执行 LLVM verifier、O2 优化、对象符号/未定义导入/自递归审计和 x64 原生运行。
  新增的 `runtime-memory.py --llvm-x64` 检查 LLVM 对象没有 `malloc/free/memcpy/memmove/
  memset/strlen/printf/linux_syscall6` 或相关整数 libcall 未定义导入。默认
  `runtime-memory.py` 原 runtimebytes、自编候选导入和 ARM64 汇编断言保持原样。

## 边界

- 本自有运行时仅供 Linux/x86_64 SysV LLVM 目标。非该目标使用这些入口时在 LLVM 预检
  阶段拒绝；Linux/aarch64 旧后端启动与运行时分支保留，LLVM AAPCS64/HFA 与运行时归 F1。
- 运行时测试对象只允许它们实际依赖的宿主符号（运行时探针为 `close`；宿主桥另允许
  `execvp/exit/fork/open/waitpid`）；LLVM runtime 与相关 libcall 不留未定义符号。
- LLVM 命令行/模块 worker 的生产驱动、完整生产缓存键与事务发布仍归 LL9；LL8b 不切换
  默认后端。后续次序见[实施方案](../02-plan/yh-LLVM后端替换实施方案.md)。

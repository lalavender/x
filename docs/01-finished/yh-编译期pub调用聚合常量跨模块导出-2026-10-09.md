`pub const TBL [3]int = $mk();` 形态的聚合常量跨模块导出。

## 背景与难点

字面量初始化的 pub 聚合常量（`const_expr_kind = 4`）此前已可导出：`.s.i` 按
初始化式源文本重放，导入侧重新解析即建模并物化本地副本。`$` 调用初始化的
形态被解析期守卫拒绝，原因是「没有可直接重放的文本」。实际实现时有三个难点：

1. **闭包可达性**：`.s.ct` 闭包只从「pub `@[comptime] fn`」按调用边收集可达
   正文；`pub const TBL = $mk();` 里的 `mk` 不在任何函数 IR 的调用边上，默认
   不会进闭包，导入方执行时找不到正文。
2. **加载顺序**：模块 worker 先加载 `.s.i`（`iface_load`）再加载 `.s.ct`
   （`iface_ct_load`）。`.s.i` 若直接执行初始化式，调用目标（闭包隐藏符号）
   尚未登记。
3. **名字可见性**：`.s.i` 重放的调用文本里是**裸名** `$mk`，而导入方只登记
   闭包隐藏名 `$__yhct_mk__<prefix>`（与闭包正文重写同一约定）。

## 实现

| 环节 | 改动 |
| --- | --- |
| 导出放行 | `parse_global_init.yh` 删除两处「pub + `$` 拒绝」守卫；新增 `parse_global_comptime_aggregate_ex` 统一处理 pub/私有与提供方/导入方两条路径 |
| 源文本记录 | `record_aggregate_const_src` 增加形态参数：4 = 字面量、**5 = `$` 调用**；提供方 pub 形态在求值后记录（`const_expr_kind = 5`） |
| 闭包可达种子 | `comptime/ct_registry.yh` 新增 `ct_pub_agg_fn_add/count/at`（上限 64，按符号去重，`ct_reset` 清空）；提供方解析 `pub const … = $fn(…)` 时登记**同模块** `$fn` 目标（模块限定形态明确拒绝）；`iface_ct_emit` 把该表作为附加可达种子，`mk` 正文随闭包传递 |
| `.s.i` 导出重写 | `iface.yh` 的聚合常量导出行放宽到 kind 4/5；新增 `iface_emit_pub_agg_src`：kind 4 原样重放、kind 5 扫描文本把 `$fn` 重写为闭包隐藏名（其余字节原样） |
| 闭包常量重放 | `iface_ct.yh` 的 `iface_ct_emit_const` 同步支持 kind 5（复用同一重写实现）——正文里引用该常量的情形 |
| 导入侧延迟执行 | 接口加载阶段（`c_iface_load`）**不再立即执行** `$` 聚合初始化：`pub_agg_deferred_add` 记录符号、初始化式 token 起点与 `.s.i` 路径（`GenState.c_pub_agg_dep`，`model.PubAggDeferred`），随后 `skip_init()` 消费初始化式 token；`.s.ct` 隐藏常量形态同样延迟 |
| 执行时机 | `module_worker.yh` 在 `.s.ct` 闭包加载完成后调用 `parse.pub_agg_deferred_run()`：逐项重新读源、词法化（临时关闭 AST 捕获）、按记录起点解析并走 `parse_global_comptime_aggregate`（建模 + 本地物化 + `const_ready`） |
| 就绪标记 | 提供方 `$` 聚合常量求值后设 `const_ready = 1`（与字面量路径一致，闭包发射要求） |

## 边界

- `pub 聚合常量的 $ 初始化暂只支持同模块函数调用`：`$mod.f(...)` 形态的导出
  重写首版不覆盖（解析期给明确诊断）。
- 延迟执行项上限隐含于动态表（按需扩容）；接口文件路径在登记时 intern 到
  名字池，执行时重新读取。

# 编译期延迟数组类型的结构性兼容修复

日期：2026-10-07。状态：已完成。

## 问题

`type Pair = [$f()]int;`（长度来自编译期调用）与同文件里同长度的定长数组
（函数返回类型、局部变量、形参）冲突：`fn g() [2]int { let v [2]int = ...; return v; }`
报「聚合类型不匹配（长度或元素类型不同）」，而两者元素类型与长度完全一致。

最小复现：

```yh
@[comptime] fn two() int { return 2; }
type Pair = [$two()]int;
fn make_pair() [2]int { let v [2]int = [7, 8]; return v; }
fn main() int { let q [2]int = make_pair(); return q[1] - 8; }
```

## 根因

数组长度含编译期调用时，`parse_type_ref` 在 pass1 走
`ct_layout_array_expr`，用 `ty_push_agg` 建立一个**延迟布局的独立数组类型项** A
（`len` 暂为未就绪）。pass1 里函数体内 `let v [2]int` 求值时 A 尚未完成，
`gen.ty_array(int, 2)` 找不到等价项，于是建立规范类型项 B；别名布局在 pass1 之后
完成，A 的 `len` 变成 2，随后 pass2 重新解析函数返回类型 `[2]int` 时命中 A。
于是 `return v;` 的两侧是 A 与 B——`kind`/`size`/`align`/`elem`/`len`/`sub` 全部相同，
但 type_id 不同，`sem_can_assign` 的聚合分支只认 `dst == src`，直接拒绝。

定位方式：在 `sem_can_assign` 的聚合分支临时分段比较（长度、元素、种类、大小、对齐、
字段表），全部相同后确认是重复类型项而非字段差异。

## 修复

数组是**结构化类型**：`sem_can_assign` 的聚合分支对 `TY_ARRAY` 增加按内容的兼容判定
（元素类型与长度都相同即放行），结构体/联合体仍按名义类型严格比较。

```yh
// compiler/gen/symbols.yh sem_can_assign
if (dk == TY_ARRAY && sk == TY_ARRAY
    && g_state.t_types[dst].elem == g_state.t_types[src].elem
    && g_state.t_types[dst].len == g_state.t_types[src].len) {
    return 0;
}
```

选择按内容放行而不是合并类型项：合并需要让 pass1 建立的字面量类型项预知后续延迟布局
的结果，改动面大且会引入时序耦合；数组的结构化兼容与语言语义一致，diff 最小。

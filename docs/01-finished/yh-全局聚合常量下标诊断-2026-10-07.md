# 全局聚合常量的编译期下标：内部错误改为明确诊断

日期：2026-10-07。状态：已完成。诊断质量修复，行为边界未变。

## 发现

第 46 轮探针（编译期正文里读全局 const 数组）：

```yh
pub const TABLE [3]int = [7, 8, 9];

@[comptime]
fn head() int { return TABLE[0]; }          // 探针 p46b
// 以及
@[comptime]
fn head2() int { let p *int = &TABLE[0]; return *p; }   // 探针 p46
```

两种写法都报：

```
错误: 内部错误：编译期数组/切片存储无效
```

**「内部错误」不该出现在用户能写出的代码上** —— 这是本轮要修的。

## 根因

`compiler/comptime/ct_ir_place.yh:64` 把下标的基础值当作 `CtAggregate` 对象指针来校验：

```yh
let aggregate *CtAggregate = base.value.to_type(u64).to_type(*CtAggregate);
if (aggregate == 0 || aggregate.count < 0 || ... ) {
    return gen.sem_err("内部错误：编译期数组/切片存储无效");
}
```

局部 `const` 聚合（前几轮交付的）在编译期确实被建模成 `CtAggregate`；但**全局** `const` 聚合的
`cval` 是**数据段标签**（`.data`/`.bss` 里的存储），编译期尚未为它建模 —— 于是 `aggregate == 0`，
落进这条内部一致性检查。

## 改动

在内部检查之前先判 `aggregate == 0`（即「基础值根本不是编译期聚合对象」），给出明确诊断；
其余情况仍保留内部错误语义（那才是真的不该发生）：

```yh
if (aggregate == 0) {
    return gen.sem_err("编译期不支持下标访问全局聚合常量（其存储尚未在编译期建模）");
}
return gen.sem_err("内部错误：编译期数组/切片存储无效");
```

## 效果

| 写法 | 之前 | 现在 |
| --- | --- | --- |
| 编译期正文 `TABLE[0]`（TABLE 全局 const 数组） | **内部错误**（误导，像是编译器 bug） | 明确诊断：不支持，且说明原因 |
| 编译期正文 `&TABLE[0]` | 同上 | 同上 |
| 局部 const 聚合的下标 | 可用 | 可用（未受影响） |

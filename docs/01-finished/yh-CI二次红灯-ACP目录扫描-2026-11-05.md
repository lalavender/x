# CI 二次红灯：Windows ACP 目录扫描（条件跳过，非修复）

- 日期：2026-11-05
- 触发：CI run [41952142547](https://github.com/lalavender/x/actions/runs/41952142547)
  （commit `b6fafa7`，VENC-2 修复）windows-x64 job。

## 结果

VENC-2 生效：第 9 步「全量回归」`success`（此前两次 run 均因
`test-check.py` 的中文 `--filter` 失败），linux-x64 / linux-arm64 /
darwin-arm64 三个 job 全绿。第 10 步「自举主门」首次跑到（此前 5 次 run
全部 `step9=failure/skipped → step10=skipped`），暴露既有遗留：

```
FAIL r3-directory-filenames-are-byte-safe
FAIL r3-directory-enumeration-grows-past-one-batch
yh: 无法打开文件: ./space ' ?.yh
project cases: 通过 128/130
```

## 根因（与 VENC-2 无关）

- `tests/modules/build-check.py:1331` 创建 `space ' 雪.yh`，让 `yh check` 扫描；
- `compiler/build/project_dir.windows.x64.yh` 用 `FindFirstFileA`，按**进程 ACP**
  返回文件名字节。GitHub `windows-2022` 英文 runner 的 ACP=1252 无法表示
  「雪」，替换成 `?`（不可逆）；
- `gen.read_source` 用 CRT `open()`（同样按 ACP），拿 `?` 路径打不开真实文件；
- 第二例同批文件，还没走到「重复顶层声明」断言就退出；
- 对照：本机 ACP=936（GBK 可表示「雪」）下，修复后的 `yh.exe` 与修复前的
  `yh2.exe` 都是 `rc=0`；Linux/macOS 用 `readdir`（字节安全），三平台 job 全绿；
- 这正是 [VENC-2 完成文档](yh-VENC2-Windows-CRT入口argv修复-2026-11-05.md)
  登记的「CRT 文件路径仍按 ACP」P2 遗留的另一种表现。

## 处理：按 ACP 精确跳过（用户决策）

`tests/modules/build-check.py` 新增 `windows_acp_lossy()`（用
`kernel32.GetACP()` 判定该 ACP 能否编码「雪」），`windows_skip_reason()` 仅在
**不能编码**时对上述两个断言返回 SKIP 原因：

- ACP=1252（英文 runner）→ SKIP，注明 W2-9 / VENC-2 遗留；
- ACP=936（本机 GBK）、ACP=65001（UTF-8 manifest）、ACP=932 等能表示该字符
  的码页 → **照常实测**，不掩盖能力；
- 拿不到 ACP 或未知码页 → 不跳过，保留原断言。

沿用脚本已有的 `WINDOWS_SKIP`/`windows_skip_reason` 机制（与现有 14 个
Windows 边界 SKIP 一致）。**这是隔离 CI 环境差异，不是修复缺陷**；根治已
升级为 [docs/todo.md](../todo.md) 的 P1 项。

## 验证

- 单元：模拟 ACP=1252 返回跳过原因；936 / 65001 / 932 返回 None；本机真实
  ACP 返回 None；
- 手工：`space ' 雪.yh` + `.ignored.yh` 的 `yh check` 在修复前后编译器上均
  `rc=0`；
- 本地全量 `build-check.py` 未能跑完：既有 Windows 环境差异
  （`comptime-local` 用例执行 `.build/comptimelocal` 报 WinError 2，CI 上该
  用例为 OK），与本次改动无关；完整流程由 CI 四端回归验证。

## 根治路线（P1，未做）

把编译器 Windows 路径层统一到 UTF-8：`FindFirstFileA` → `FindFirstFileW`、
`open` → `_wopen`、新增 UTF-8↔UTF-16 转换辅助、`kernel32.def`/`manifest.json`
增补 `FindFirstFileW`/`MultiByteToWideChar` 导出；或嵌入 SDK 里现成的
`lib/yh-utf8.manifest`（activeCodePage=UTF-8）让整个 CRT 进程说 UTF-8。
两者都需重跑固定点与四端回归，故未夹带进本次 CI 修复。

# 模块模式编译期正文直接引用枚举成员（打通）

日期：2026-10-07。状态：已完成。承接第 26 轮根因定位、第 27 轮回退、第 28 轮重做。

## 问题

模块模式下，`@[comptime]` 函数正文里直接写 `EnumName.member` 会被拒绝。第 26 轮插桩确认
根因：同一段编译期正文被**解析两次**，第二次解析时枚举成员符号在名字表里查不到，而
`EnumName` 已被求值成一个常量符号，于是 `EnumName.member` 被当成**成员访问表达式**送进
编译期执行器，最终在 `ct_ir_member_place` 报「编译期成员访问只支持本地结构体或联合体值」。

## 本轮改动（三处，最小）

1. `gen/state.yh`：枚举成员表按枚举类型无关的**名字**反查，并把比较逻辑泛化为可接受任意
   源码缓冲 —— 新增 `em_find_src(src *u8, start, n)`（`em_find` 现在就是它配 `g_state.c_src`
   的薄封装）。原因是编译期目标另有一份源码缓冲 `frame.target.src`，与前端 `c_src` 不一定是
   同一个。
2. `comptime/ct_ir_place.yh` 的 `ct_ir_member_read`：在进入结构体字段路径之前先判基底类型 ——
   `TY_ENUM` 时用该表达式已有的成员名 token 位置
   （`expr.after - frame.target.body_token_first - 1`，与结构体字段同一取法）经 `em_find_src`
   查表，命中且就绪即把成员常量值作为结果返回；未登记/未就绪分别给出准确诊断。
3. 成员表本身（登记、延迟回填同步、`sem_member` 兜底）来自第 28 轮，本轮未改。

改动只有 1 个新函数 + 1 个分支，没有新增表、没有动前端解析路径，也不影响结构体字段访问
（只有基底类型**本来就是** `TY_ENUM` 这条此前必然报错的路径才走新分支）。

## 用例

`tests/modules/projects/comptimecross`（既有的跨模块编译期验收项目）新增：

- `math/src/base/extra.yh`：`pub enum Simple { one = 1; two; }`、`@[comptime] pub fn simple_ct()`
  （返回 `Simple.two`，普通成员）、`@[comptime] pub fn low_ct()`（返回 `Level.low`，
  判别值来自编译期调用、走延迟回填路径）。
- `math/src/api.yh`：`probe_simple` / `probe_low` 跨模块转发。
- `host/src/main/main.yh`：`const PS = $math.probe_simple();`、`const PL = $math.probe_low();`
  并入 `main()` 的偏差和（期望 `PS = 2`、`PL = 4`）。

**有效性验证**：把期望值故意改成 `PS - 99`（即期望 `PS = 99`）后 `build-check.py` 报
`FAIL ct5b-cross-module-body ... run=159`、`project cases: 通过 83/84`；还原后恢复 84/84 ——
说明该断言确实在检验这两条路径。

## 效果

模块模式下引用枚举成员现在三种写法都工作（此前只有第一种）：

| 写法 | 第 28 轮前 | 现在 |
| --- | --- | --- |
| 同模块顶层 `pub const X int = 枚举名.成员;` | 可 | 可 |
| 编译期函数读该常量、跨模块转发 | 可 | 可 |
| `@[comptime]` 正文里**直接** `枚举名.成员` | 拒绝 | **可**（普通成员与延迟判别值成员均可） |

单文件模式不受影响（三种位置一直可用）。

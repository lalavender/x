# yh 编译期 typed 布局请求

日期：2026-10-06

## 交付内容

- pass1 遇到结构体字段或文件级数组中的 `[COUNT]T`，且 `COUNT` 是已声明但未就绪的整数 `const` 时，登记 pending 数组布局，不再把未就绪长度当作 0。
- CT 函数 typed IR 捕获完成后，按文件和声明顺序准备符合条件的未就绪整数常量：初始化器必须包含至少一个同模块 `@[comptime]` 调用，且调用图无环。现有 typed 执行器可在这些函数中处理已支持的局部可变值、分支局部声明和循环。
- 布局求解器先完成数组，再按元素与字段依赖完成内层及外层结构体。单文件和项目模块构建均在正常全局初始化和函数编译前运行该阶段。
- pending 类型不能进入普通函数编译或全局数据发射；在 typed 函数准备期间查询 pending 类型的 `sizeof` 会报错。前向 const、递归调用树及其他未支持布局依赖不会被提前求值。
- 新增 `tests/yh-run/run/117-comptime-typed-layout-request.yh`，验证循环计算的 typed 结果决定结构体字段、嵌套结构体及全局/局部数组布局，程序输出 `typed-layout-request=40`。`comptimelocal` 增加多文件项目覆盖。
- 将先前的 fail/108、fail/114、fail/116 升级为 run/108、run/114、run/116，分别验证分支局部值、所选返回路径与局部赋值；新增 fail/118–120 锁定前向 const、pending `sizeof` 和实际执行路径无返回。
- 主要实现位于 `compiler/comptime/ct_layout.yh`、`ct_00_model.yh`、`ct_registry.yh`、`compiler/parse/parse_ct_layout.yh`、`parse_type.yh`、`parse_decl.yh` 及编译阶段调度文件。

## 边界

本片初次交付时只支持单个已声明整数 const 名称作为数组长度，并要求初始化器调用图无环；递归限制随后由[递归布局求值阶段](yh-编译期typed递归布局求值-2026-10-06.md)扩展。普通字面量 const 不因此改变 pass1 顺序可见性；不支持任意长度表达式、前向常量、循环布局依赖、pending 类型的 `sizeof`、直接在类型中写 `$f(...)`，也不传递跨模块编译期函数正文。通用 UNSEEN/VISITING/READY 值与布局依赖图、循环链路诊断仍属于 CT5A 后续阶段。

# yh_asm 汇编器稳定化（ASM-0–ASM-8，2026-10-12）

范围：`asm/`（yh_asm 汇编器）与它的门禁、契约与文档。**本轮不接入编译器**。
方案：[yh-asm 汇编器稳定化实施方案](../02-plan/yh-asm汇编器稳定化实施方案.md)。
验证环境：Windows 宿主 + WSL（Ubuntu x86_64 + qemu-user/binfmt，
`SEED=bin/yh-linux-arm64`，交叉 gcc 包装在 `tmp/boot/crossbin/`）。

## 结论

1. **编译器自己的汇编文本现在可以原文进 yh_asm**：8 个模块、8.98 MB、
   1974 条 `adrp` 的模块在内，全部汇编成功，且与 clang 对象的**逐节内容与
   逐重定位完全一致**（0 不一致、0 跳过）。修前这些模块一条都汇编不了。
2. **编译器不再自动用汇编器**（断电）：`make yh-link` 别名与根目录入库副本
   已删除，编译器回落系统 cc；主门 `make test` / `make selfhost-native`
   在断电后复验全绿。
3. **端到端能力用影子验收证明**：显式 `YH_LINK=<asm 产物>` 冷编编译器两代，
   16 次汇编调用、16 个模块产物固定点 0 不一致。
4. **门禁在只有 clang 的宿主也能跑全套**：oracle 回退到 clang 集成汇编器，
   链接运行门用交叉 ld + qemu，不需要 docker、不需要 llvm-mc。
5. **性能如实记录、未优化**：同批语料 clang 5.52 s vs yh_asm 41.18 s
   （≈7.5×）；WSL 上 yh_asm 走 qemu 模拟，实测模拟因子 2.2–3.0×，
   折算原生 arm64 约 2.5–3.5×。是否接受这个代价留给接入决策。

## 做了什么

### ASM-0 断电与基线冻结

- `Makefile`：删 `yh-link` 目标与 `YH_LINK` 变量、更新头部说明与 `.PHONY`。
- `.gitignore`：收住 `/yh_asm`、`/yh_link`。
- `asm/README.md`：把「与编译器的对接」改写为「当前不接入」，并给出显式
  `YH_LINK` 用法与影子验收入口。
- `docs/todo.md`：「编译器汇编步查找名切换」条目改写为「接入编译器（本轮
  不做）」+ ASM-1…ASM-8 工作包清单。

### ASM-1 ELF/GNU 方言接受（本轮阻塞项）

- 修前实测：编译器模块 `.s` 的第一条 `adrp x0, sym` 即报
  「adrp 需要 sym@PAGE」，补 `@PAGE` 后 `add x0, x0, :lo12:sym` 报
  「加减的第三个操作数只能是…sym@PAGEOFF」。
- 改动：`asm/src/asm/52_parse_ins.yh` 的 `p_adr` 接受裸符号（ELF 目标；
  Darwin 目标仍拒绝并给出说明），`asm/src/asm/51_parse_alu.yh` 的
  `p_addsub_tail` 接受 `EX_LO12`。访存路径本就接受 `:lo12:`。
- 用例：`70_selftest.yh` 新增 `asm_gnu_selftest()`（10 个机器字 + 8 条重定位
  类型），语料 `asm/tests/asm-gnu/10-gnu-dialect.s`（`ldr/ldrsw/ldrb/ldrh/
  ldrsb/ldrsh/str/strb/strh` + 局部标签 + `.xword`）。
- 结果：8/8 模块原文汇编成功，`check_corpus.py` 与 clang 差分 0 不一致。

### ASM-2 语料重建与盘点（TC0 落地）

- 新增 `tools/yh-toolchain-inventory.py`：单文件 `yh --emit-asm` +
  模块 `yh build` 收集 `.build/asm/*.s`，输出直方图与契约差异表。
- 实测：单文件语料 161 个、模块语料 8 个，跳过 0；69 个助记符、2 个伪指令
  （`.globl`、`.p2align`）；**契约外出现 1 种：`uxtw`（95 次）**——编译器
  运行时代码会发射 `uxtw x27, w27`，v1 契约漏列，已补进契约 v2。

### ASM-3 oracle 可移植

- `check_corpus.py`：`LLVM_MC` 环境变量 → Homebrew 默认 → clang 集成汇编器；
  新增 `oracle_kind()`/`oracle_asm()`，并**校验候选是真 clang**
  （WSL 上 `tmp/boot/crossbin/clang` 其实是 aarch64-linux-gnu-gcc 的包装，
  直接拿来当 oracle 会失败）；支持多语料目录与 `--bin`；oracle 拒绝而我们
  接受时判为**不一致**而不是静默跳过；一个都没比对成功时门判失败。
- `check_enc.py`：clang 模式下改为「把用例按顺序汇成一个 `.s`，读 `.text`
  顺序比对」，比文本比对更严（不再需要别名退化）。
- `check.py --full`：串起拒绝路径、编码、两类语料、结构、Darwin 快照与
  链接运行门，并按宿主选择链接门。

### ASM-4 原生链接运行差分门

- 新增 `asm/tests/elf_link_native.py`、`asm/tests/elf/start-linux.s`
  （Linux 方言的 `_start` → `main` → exit 93）与 `asm/tests/elf/yhr-linux.s`
  （运行时外部符号桩：`read/write/open/close/_Exit/abs/strtoul`，
  按 Linux 系统调用与 C 语义原样转接；`strtoul` 是够用的十进制解析）。
- 差分语义：两边各自汇编、各自链接、各自运行；「两边都拒绝汇编」
  「两边同样链不上」计跳过并记名字；「一边成功一边失败」或行为不同判失败。
- 实测（169 个程序语料）：**159 行为一致、0 不一致、10 跳过**（补桩前
  152/0/17）。跳过明细：8 个编译器模块（缺入口/跨模块运行时符号）、
  2 个与寄存器同名的符号语料（本工具与 clang 都拒绝）。

### ASM-5 拒绝层与诊断质量

- 内建自检新增 `neg_selftest()`（25 条，每条负例配**正向对照**，防「全部
  拒绝」式假通过）；为不让预期内的诊断淹没门输出，`Ctx` 增加 `quiet`
  开关（只计数不打印），诊断格式改由子进程门验。
- 新增 `asm/tests/asm-neg/`（10 条语料）与 `asm/tests/check_neg.py`：
  断言退出码 1、首行是 `<path>:<line>:<col>: 错误: …`、含类别关键字。
- 顺带修掉的既有缺陷（都是先探测、后写用例、再改实现）：
  1. `.balign 3` 只有退出码、没有诊断（现在报「.balign 的对齐必须是 2 的幂」）；
  2. `b sym@PAGEOFF` / `b.eq sym@PAGE` / `cbz x0, sym@PAGE` 被**静默编成
     `b #0`**（自跳转），现在是明确拒绝；
  3. `b .Lmissing` 把未定义局部符号降级成未定义**全局**符号（clang 报
     "Undefined temporary symbol"），现在解析结束统一检查并拒绝；
  4. 未闭合块注释报成「无法识别的语句开头」，且列号算出负数
     （实测 `:5:-12:`）；现在词法层记录「块注释未闭合」与正确位置，
     `整数溢出`/`非法字符` 同样带上位置与信息。

### ASM-6 CLI、交叉目标与稳健性

- 退出码契约：0 成功 / 1 输入错误 / 2 用法错误（此前输入错误退 255）。
- **交叉目标写对象修复**：写文件的 open 旗标原先按**目标**取（`-t darwin`
  用 0x601），Linux 宿主上 0x601 没有 `O_CREAT`，目标文件不存在时直接
  「写对象文件失败」；现在按**宿主**取（`host_darwin()` 探
  `/System/Library/CoreServices/SystemVersion.plist`，与编译器同一套判据）。
- 边界实测：`b #0x2000000`（±32 MB）与 clang 一致接受，`b #0x40000000`
  两边都拒绝；`cbz x0, #0x100000`（1 MB > ±256 KB）拒绝；LF/CRLF 输入
  产出对象逐字节相同；同一输入两次汇编逐字节相同。

### ASM-7 影子验收

- 新增 `asm/tests/shadow-build.py`：把 `YH_LINK` 指向一个记录调用与耗时的
  转发脚本，冷编 `compiler` 两代（各自独立拷贝，不共享 `.build`），比对
  模块 `.s`/`.s.i` 的 sha256。
- 实测：第一代 57.3 s、第二代 52.0 s、**汇编调用 16 次**、汇编总耗时 93.3 s、
  **固定点不一致 0**。报告落在 `tmp/shadow/report.md`。

### ASM-8 Mach-O 不回退守门

- `check_obj.py` 新增 `--target darwin --snapshot <文件> [--write]`：
  逐语料记录 `-t darwin` 对象 sha256（拒绝的记诊断首行），快照入库为
  `asm/tests/darwin-snapshot.txt`（9 个文件）。快照只与输入有关、与宿主无关，
  所以 Linux 上跑同样有效。
- `03-mem-reloc.s` 的记录是「拒绝: Mach-O 目标不支持该重定位」（`beq` 跳
  外部符号，Mach-O 表达不了），与既有文档一致。

## 性能（如实记录，本轮不优化）

| 项 | clang | yh_asm | 倍数 |
| --- | --- | --- | --- |
| 编译器 8 模块（8.98 MB） | 5.52 s | 41.18 s | 7.5× |
| 最大模块 `yh-parse.s`（2.1 MB） | 1.32 s | 12.37 s | 9.3× |
| 影子构建两代（汇编部分） | — | 93.3 s / 109 s 总时长 | — |

WSL 上 yh_asm 是 aarch64 ELF 跑在 qemu-user 下：自建 CPU 基准（2000 万次
64 位乘加循环）实测原生 x86_64 0.034 s、qemu-aarch64 0.077 s（2.2×），
加倍负载时 3.0×。折算原生 arm64 约 **2.5–3.5×** clang。
本轮按方案「只做低风险优化、不达标就如实记录」处理：**不动热路径**，
接入决策前需要有原生 arm64 的实测数据。模块 `.text` 大小实测
35 KB–413 KB。

## 没做什么（明确的边界）

- **不接入编译器**：查找名 `yh_link` → `yh_asm`/`YH_ASM`、默认目标切换、
  安装布局、缓存键纳入工具版本，全部留到 S1–S7 通过后另立。
- **长条件分支放宽不做**：`b.cond`/`cbz`/`cbnz` ±256 KB 越界即报诊断。
  编译器最大模块 `.text` 已 413 KB，但没有出现越界的条件分支（两边都能
  汇编 8 个模块）。
- **`.size` 的符号表达式不做**：契约按实测收窄为「只接受纯数字」；
  编译器语料里没有 `.size`（盘点实测只有 `.globl` 与 `.p2align`）。
- **GOT 窄形态不做**：LP64 下只有 64 位访存有对应重定位。
- **寄存器同名符号不动**：`w12:` 这类标签本工具与 clang 都汇编不了
  （clang 接受标签定义但拒绝 `bl w12`）。根因在编译器发射用户符号未避让
  寄存器名，属编译器侧缺陷，记在 `docs/todo.md`。
- **macOS 原生 macho 两门未跑**：本轮环境只有 Linux，`macho_corpus_check.py`
  与 `macho_link_run.py` 未执行；Darwin 输出只由字节快照守住不回退。

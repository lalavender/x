# macOS 种子补代与平台命名（2026-10-18）

## 背景

`llvm` 分支自 2026-10-14 起全部开发与验收都在 Linux 上完成，macOS 入库种子
`bin/yh`（`b123acbe…`，2026-10-13 的中间代）停在 LL2 之前。用它对当前
`compiler/` 冷编，在 `gen/target_info.yh` 报「编译期常量尚未就绪」并中止；
`make` 与 `tools/seed-build.py` 同一失败。同时 macOS 上还缺两样东西：
固定 LLVM SDK 只发布 Linux 宿主，`Makefile` 也只在 Linux 宿主设置 `LLVM_HOST`。

## 补代链

| 代 | 编译器 | 源码提交 | 产物 | 结果 |
| --- | --- | --- | --- | --- |

| S2 | S1 | `8fe3c80`（倒数第二代） | `yhA` | 成功（需桥桩） |
| S3 | S2 | HEAD + 临时补丁 | `yhB2` | 成功（需桥桩 + 链接查询补丁） |

途中遇到两个跨代不兼容点，都只在临时工作树里绕过，没有进仓库：

- HEAD 提交 `dfa7195` 把 `clock.linux.yh` 改名为 `clock.linux.arm64.yh` 并新增
  `clock.linux.x64.yh`；旧编译器按 `.linux.` 段筛选会同时选中两个文件，报
  `CmdTimespec` 类型重定义。补代时临时改回旧名，新编译器就位后恢复。
- 同一提交在 `cmd/link_cache.yh` 新增 GCC 风格链接驱动查询
  （`-print-search-dirs`/`-print-sysroot`/`-dumpspecs` 等），Darwin 上的 clang
  直接报 `unknown argument: '-print-sysroot'` 并让整轮构建失败。

## 正式化：两处平台分支

1. **桥绑定按目标平台分文件**（`compiler/backend/`）：
   - `llvm_bind.linux.yh` —— 原来的 9 个 `@[extern]` 声明，符号由固定 SDK 归档提供；
   - `llvm_bind.darwin.yh` —— 返回失败的桩，让 yh 在 macOS 上能链接自身。
   - `llvm_bridge.yh` 只保留包装函数与契约注释，不再声明 extern。
   分文件而不是 `$if`：`$if` 只支持语句级，包顶层声明会报「此处需要一个顶层声明」。
   筛选由 `cmd/project_index.yh` 的 `pj_source_target_match` 按文件名后缀完成，
   与 `clock.darwin.yh` / `clock.linux.arm64.yh` 同一机制。
2. **链接查询加 Darwin 分支**（`compiler/cmd/link_cache.yh` 的
   `mb_link_query_identity`）：目标 OS 为 Darwin 时清空 `fixed_queries` 跳过整轮，
   签名只保留驱动器路径与环境变量。

两处都只影响 Darwin 目标：Linux 上仍然编入 extern 声明、仍然执行完整 GCC 查询，
行为零变化（本机无法复跑 Linux 门，结构性依据是平台文件筛选与目标 OS 判据）。

## 命名规则

入库种子统一按 `yh-<平台>-<架构>` 命名，宿主直接取对应文件：

| 宿主 | 种子 |
| --- | --- |
| Darwin/arm64 | `bin/yh-darwin-arm64` |
| Darwin/x64 | `bin/yh-darwin-x64` |
| Linux/arm64 | `bin/yh-linux-arm64` |
| Linux/x64 | `bin/yh-linux-x64` |

`bin/yh` 与 `bin/yh.sha256` 已删除，不再有「macOS/arm64 特例」。同步改动：

- `Makefile`：`HOST_TAG` + `BIN_SEED = $(REPO_BIN)/yh-$(HOST_TAG)-$(SEED_ARCH)`；
- `tools/selfhost_snapshot_gate.py` 的 `default_seed`：删掉 Darwin/arm64 特判；
- `tests/selfhost/native-selfhost.py` 的 `llvm_shim_for_seed`：非 Linux 种子直接
  返回 None（原先按名字含 `arm64` 会误判成 `linux-aarch64` 并尝试准备不存在的 SDK）；
- `.github/workflows/ci.yml`、`release.yml`：种子路径与 artifact 名；
  补代步骤里的 `clock.linux.yh` 同步为新文件名；
- `README`、`AGENTS.md`、`compiler/README.md`、`asm/README.md` 的种子路径说明。

## 边界

- macOS 上 `--backend llvm` 不可用：桩返回 -1，`llvm_bridge_emit` 会带诊断失败。
  要真正支持需发布 Darwin 版固定 SDK 与对应链接/签名路径（归 F2）。
- `make test-llvm` / `make selfhost-llvm` 仍只能在 Linux/x86_64 跑（Makefile 硬断言）。
- 本机（Darwin/arm64）无法验证 Linux 侧是否零回退；改动只落在 Darwin 分支，
  依据是平台文件筛选与 `c_target.os` 判据，Linux 门需在 Linux 宿主复跑确认。
- 临时补代工作树与中间产物在 `tmp/boot/`（约 315 MB），未入库。

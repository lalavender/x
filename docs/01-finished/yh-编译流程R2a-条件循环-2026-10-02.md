## 切片内容

本切片把条件循环 `for cond { ... }`（原 while 形态）接入 typed SSA 与
arm64 后端，函数体形态为「[顺序前缀] for cond { 顺序体 } [顺序尾语句]
返回」：

1. **四块 CFG**：入口块（前缀语句 + 无条件 BR）→ 循环头（phi + 条件 +
   COND_BR）→ 循环体（顺序语句 + 回边 BR）→ 退出块（尾语句 + RET）。
   块填充顺序与编号一致，不需要放宽 verifier 的连续区间检查。
2. **循环携带值**：体内被赋值的外部绑定（参数或循环前局部）在循环头
   建立双前驱 phi（入口输入创建时已定，回边输入在体降低后回填）；
   条件与体内后续读到的都是 phi 结果，循环后视角恢复为 header phi 值。
   携带绑定去重上限 16，超出回退旧发射器。体内 `let` 每次迭代重新
   执行定义指令，不参与携带。
3. **顺序语句复用**：原直线路径的语句检查与降低抽取为
   `ast_ir_straight_scan`/`ast_ir_straight_emit` 共享辅助，直线、循环
   前缀/体/尾三段共用；直线行为逐字保持（回归由既有语料覆盖）。
   `ast_ir_lower_cleanup` 改为按 phi 非空走分支释放路径。
4. **形态约束**：循环体只接受 let/标量赋值/调用语句；体内出现
   return/break/continue/goto/if/嵌套循环或 for-in 绑定时整体回退；
   `for {}` 无限循环与 for-in 迭代协议暂不接入。void 函数的循环
   （裸 return 或隐式结束）同样受支持。

## 边界

- break/continue 需要多前驱 phi 与任意块序（continue 站点各占一条
  header 入边），要求动态块构造器，尚未接入；循环体内嵌套 if/else
  同样等待动态块构造器。
- for-in 迭代协议、`for {}` 无限循环、switch、goto 仍走旧发射路径。
- 本切片不代表 R2a/R2b 完成：编译器自编项目进入 SSA 的函数占比仍然
  有限，函数级增量与线程池等 R2b 硬门继续实施。

# 跨模块编译期调用直接字面量实参支持

日期：2026-10-07。状态：已完成。

## 背景

前两轮把跨模块编译期调用的单字节指针形参一律拒绝，因为实参值来自提供方编译单元，
编译期侧按标签号在本地只读池映射里反查会命中无关字面量（`head_of("AB")` 得到
`104105` = `"hi"`）。本轮实现了支持路径。

## 排查结论（决定实现方式）

- 临时把本地字面量编号整体后移（在 host 顶部加一个 `const PAD *char = "PAD";`）后，
  `head_of("AB")` 的结果从 `104` 变成 `65`（正确的 `'A'`）。这说明实参值是**提供方
  编译单元分配的标签号**，被调用方 worker 用自己的编号解释，于是撞上接口重放进来的
  无关字面量。
- 因此**按标签号反查本地表**这条路根本不可靠：调用方无法知道标签号属于哪个编译单元。
- 但**直接写在实参位置的字符串字面量**不受影响：它的字节就在调用方源码里，
  可以在调用方就地登记只读池，完全绕开标签号。

## 实现

`compiler/parse/parse_expr.yh` 的编译期调用实参解析：解析实参**之前**记下当前 token
是否是字符串字面量（`arg_str_tok`），解析完成后，若对应形参是单字节指针
（`char`/`u8`/`i8`，即走只读池的类型）：

- 是字面量 → 用 `comptime.ct_pool_register_src`（新增的标量参数包装，内部转调
  `ct_pool_register`，避免跨模块传 `*u8`）就地登记只读池，并把实参值**覆盖**成池地址；
- 不是字面量且调用是模块限定形式（`$mod.f(...)`）→ 保持拒绝并给出改用导出常量的诊断；
- 不是字面量且调用是同模块形式 → 放行，继续走既有的 `ct_pool_adopt_label` 反查
  （同编译单元内标签号可信），run/144 的 `$first_of(TEXT)` 覆盖这条路径。

实现细节：覆盖发生在 `parse_expr_iso` **之后**，不改动实参循环的控制流。早先尝试在
循环里用 `continue` 跳过解析的写法会让编译器报出「模块没有导出该名字」这种与代码无关
的诊断（行号落在 `gen.TOK_COMMA` 上），换成本方案后编译正常。

## 边界

- 跨模块单字节指针形参只接受**直接字符串字面量**实参；模块内指针常量、全局数组地址等
  写法仍拒绝（诊断给出改用导出常量的提示）。
- 同模块调用不受此限制，既有标签号反查继续工作。

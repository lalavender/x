# 枚举判别值里的编译期调用（延迟求值）

日期：2026-10-07。状态：已完成（单文件路径）。

## 缺口

上一轮把「枚举判别值里的编译期调用」改进成了可读诊断，本轮实现支持：

```yh
@[comptime] fn two() int { return 2; }
pub enum E {
    a = $two() + 1;   // 此前: 编译期函数正文不在受支持的 typed IR 子集内
    b;                // 隐式成员依赖前值
    c = $two() * 10;
    d;
}
```

根因是**求值时机**：判别值在 pass1 折叠成常量，而编译期函数的 typed 正文要到 pass2
才捕获，pass1 没有可执行的正文。

## 设计与实现

沿用数组长度延迟求值的既有模式（登记 token 区间 + 调度阶段重解析）：

1. `compiler/parse/parse_ct_layout.yh` 新增延迟表（独立全局数组，避免撑大 `GenState`）：
   成员符号、显式值表达式的 token 区间（`first`/`after`，隐式成员记 `-1`）、声明顺序上的
   前一个成员符号；上限 64。
2. `compiler/parse/parse_decl.yh` 枚举成员解析：判别值 token 扫描到 `;`/`}` 前若出现 `$`，
   **不解析表达式**，只登记 token 区间；该成员及其后所有成员（含隐式）都标记为待回填
   （`const_ready = 0`、`cval = 0`）。`$` 之后的成员一律延迟，因为隐式值依赖前值。
3. 回填（`ct_enum_pending_run`）：按登记顺序，显式成员重解析表达式求值（此时正文已捕获，
   `c_ast_capture` 关闭避免重复捕获），隐式成员取前一成员的 `cval + 1`；写回 `cval` 并把
   `const_ready` 置 1。
4. 接入驱动：`cmd/compile.yh` 与 `cmd/module_worker.yh` 都在 `ct_layout_resolve()` 之后、
   pass2a 全局初始化之前调用回填，因此后续常量初始化能看到已就绪的成员值。

配套放宽：`parse_expr.yh` 的枚举成员限定引用分支不再要求 `const_ready != 0`，未就绪时
交给 `sem_ident_val` 给出「编译期常量尚未就绪」这类准确诊断，而不是回落成
「引用了未声明的名字」。

## 边界

- **模块模式**下在编译期函数正文里引用延迟枚举成员仍不可用：模块模式的标识符解析走
  另一条路径，`Level.mid` 会落到字段访问并报「『.』的左侧不是结构体或结构体指针」。
  模块 worker 已接入回填逻辑（对同模块顶层引用有效），但枚举成员限定引用在模块模式的
  解析支持另见 `docs/todo.md`。
- 上限 64 个延迟成员，超出报清晰诊断；`extern enum` 的判别值不允许延迟。

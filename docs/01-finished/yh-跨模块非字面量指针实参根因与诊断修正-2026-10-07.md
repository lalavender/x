# 跨模块非字面量指针实参：根因链定位与诊断修正

日期：2026-10-07。状态：本轮交付**诊断修正**；功能放宽经实测判定不可行，已回退。

## 目标（todo 原条目）

「跨模块编译期调用的非字面量单字节指针实参（模块内指针常量、全局数组地址等）：需要让实参的
字节来源随调用跨编译单元传递，当前为拒绝路径（诊断提示改用导出常量）。」

## 实测：三层阻塞，逐层验证

1. **单文件路径本来是好的**：`pub const TEXT *char = "hi";` + `$first(TEXT)`（`*char` 形参）→
   编译运行 `rc=0`。问题只在 `qualified != 0`（`$mod.f(...)`）这条分支。
2. **放宽「跨模块实参是本地重放的指针常量」——可行但验证不到**：`.s.ct` 用**源字面式**重放
   `*char` 常量（`iface_ct.yh:722-730` 的 `string_ptr` 分支），导入侧重新解析后**有本地标签号**，
   所以拒绝条件看起来过度保守。改成分支判断 `SYM_CONST + F_ADDR + is_const` 后本可放行，
   但要构造真实用例就必须让**调用方**能写出来源：
   - `math.TEXT` → 报「模块没有导出该名字」（`TEXT` 在 `base` 子模块，不在 `math` 的公开名字空间）；
   - 改用 `api.yh` 里 `pub const TEXT_PTR *char = base.TEXT;` 转发 →
     报 **「pub 指针常量（字符串）暂不支持跨模块导出」**（`iface.yh:339`）。
3. **结论**：提供方**根本导不出**字符串指针常量，而 `.s.ct` 重放只覆盖「可达 CT **正文**引用的
   常量」——实参位置的引用不触发重放。所以整条路要通，需要先扩展 CT 闭包的常量收集范围
   （把实参位置的引用也算作可达），属独立中等切片，不是一行放宽能解决的。
   **放宽已回退**（无凭据支持，宁保守）。

## 本轮实际交付：诊断修正

原诊断让用户「请改用直接字面量或**模块导出的 pub const 指针常量**」—— 而第 2 步实测证明
这第二种写法**本身就不被支持**，属误导。新诊断：

> 编译期调用的单字节指针形参（char/u8/i8）只接受直接字符串字面量实参：非字面量的跨模块指针实参
> 需要让字节来源随调用跨编译单元传递，尚未支持（`pub const *char` 常量本身也不能跨模块导出，
> 实测报「pub 指针常量（字符串）暂不支持跨模块导出」）

`tests/modules/build-check.py:337` 的期望字符串同步更新（它断言了旧文本）。

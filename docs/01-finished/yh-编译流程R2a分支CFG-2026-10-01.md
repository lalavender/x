# yh 编译流程 R2a 分支 CFG 接入报告

日期：2026-10-01。状态：完成一个窄 AST→SSA 迁移切片；R1/R2a/R2b 与后续平台工作仍在实施。

## 交付内容

`compiler/parse/ast_ir.yh` 已将受限的 AST lowering 从单块直接 return 扩展到简单双臂
`if/else`。函数必须无参数，两个分支都是显式块，且各自只含一个直接 `return`。入口块
按条件表达式生成 SSA 值并以 `IR_TERM_COND_BR` 指向 then/else；两个后继块各自返回值。
`+`、`-`、`*`、`==` 及整数、布尔、字符常量沿用既有表达式 lowering。生成结果先执行
低成本简化，再通过 verifier；无法匹配该窄形状的函数安全地跳过 IR lowering，继续由旧发射器处理。

项目 fixture 增加 true 与 false 两条执行路径，其中 true 条件由整数比较形成。build 统计要求
至少六个函数通过 lowering；`yh check` 仍要求 `ir_functions=0`，证明 check 命令在 IR 前停止。
程序入口实际调用两个分支函数，预期退出码为 50。

## 性能

Apple M1、冻结 25 个源文件、20 轮，时间包含汇编和链接。各项为中位数/p95：

| 场景 | 时间 | 汇编/链接调用 | 说明 |
| --- | ---: | ---: | --- |
| 无改动 | 190/225 ms | 0/0 | 4 个模块对象缓存命中 |
| 单函数体修改 | 985/1,079 ms | 1/1 | 重建 main 模块 |
| 冷编 | 2,353/2,550 ms | 4/1 | 重建 gen、lex、parse、main |

已确认的验收目标为 50/200/1,000 ms，目前三项均未达标。冻结语料本身没有可被当前窄 lowering
接受的函数，因此基准中 `ir_functions=0`；这次分支实现由 `irfront` fixture 的 IR 统计与运行结果验证。
新路径目前增加语义后 AST lowering 与 verifier 工作，但没有函数级缓存或增量后端来回收这部分成本。

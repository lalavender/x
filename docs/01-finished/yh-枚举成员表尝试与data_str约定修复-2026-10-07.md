# 枚举成员表尝试（回退）与 data_str 返回值约定修复

日期：2026-10-07。状态：已完成（尝试失败并回退；期间引入的一处回归已修复，门全绿）。

## 目标

按第 26 轮定下的可行方向 ②「让枚举类型项自带成员表」，绕开「模块 worker 二次解析时枚举
成员符号不可见」的根因，实现模块模式下编译期正文里直接引用枚举成员。

## 做法与结果

新增独立全局枚举成员登记表（`em_name_off/len`、`em_sym`、`em_val`、`em_ready`，上限 512），
在 `parse_decl.yh` 登记成员时**快照**名字池偏移与值（不依赖符号表），`sem_member` 的枚举
基底分支在 `sym_lookup` 失败后按名字字节反查该表。

逐步排除后的实测结论：

| 步骤 | 结果 |
| --- | --- |
| 表内按「类型 id + 名字」反查 | 查不到（模块 worker 二次解析时枚举类型 id 已重建） |
| 按「名字」反查 | 表非空但名字不匹配 —— 登记的符号下标在二次解析后已失效 |
| 改为登记时快照名字池偏移与值 | 找到成员，但 `em_ready == 0`（`em_add` 登记早于 `const_ready` 赋值） |
| 调整登记顺序到赋值之后 | 普通成员路径打通，但**已被破坏的 `data_str` 路径**先报错 |

## 期间引入的回归与修复

用文本切片删除 `em_*` 相关代码时**误删了同文件里的 `data_str_add`/`data_str_lookup`**
及其三个数组（`c_data_str_lbl/off/len`），随后按文档描述重写。重写时把
`data_str_lookup` 的返回值约定写反：写成了「命中返回 0、未命中返回 -1」，而消费侧
`ct_ir.yh` 的用法是

```yh
if (gen.data_str_lookup(value.value.to_type(int), &off, &slen) != 0) { ... }
```

即**命中必须返回非零**。写反后未命中分支照样进入，而那时 `off`/`slen` 还是 0，于是
`ct_pool_register(..., slen=0, ...)` 触发「编译期字符串字面量为空」——
`comptimecross` 项目里 `$math.head_of("AB")` 直接编译失败（门红：82/84，两条 `ct5b` 用例失败）。

修正为「命中返回 1、未命中返回 0」后门恢复全绿（84/84）。

## 最终处置

`em_*` 成员表整体回退（`state.yh`、`parse_decl.yh`、`parse_ct_layout.yh`、`sem_expr.yh`
全部还原到第 26 轮状态），模块模式该写法仍走第 26 轮的可操作诊断。保留的改动只有
`state.yh` 里重写的 `data_str_add`/`data_str_lookup`（语义与文档描述一致：登记时把字节
intern 进名字池，命中返回非零）。

## 教训（已写入 todo）

1. **删除代码前先确认切片边界覆盖的完整范围**：`state.yh` 里 `c_data_str_n` 声明与
   `state_init` 之间除了要删的块，还有 `c_data_str_*` 数组与两个函数。
2. **重写被误删的函数前，必须先读消费侧调用约定**（这里是 `ct_pool_adopt_label` 的
   `!= 0` 判命中），而不是按「lookup 命中返回 0」的惯例写。
3. 枚举成员表方向本身仍可行，但需要先解决「登记的符号下标在二次解析后失效」——
   快照名字与值已能命中成员，剩下的只是登记时序与延迟成员的就绪位联动。

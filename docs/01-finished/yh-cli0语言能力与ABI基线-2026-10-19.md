# yh CLI0：语言能力与 ABI 基线（2026-10-19）

计划见[实施方案](../02-plan/yh-cli标准库实施方案.md)的 CLI0，
接口语义见 [cli 设计](../03-design/yh-cli标准库设计.md)。

## 目标

在实现 `libs/cli` 之前，用普通 `.yh` 项目证明设计依赖的语言能力和 ABI 成立，
并把不成立的部分收敛成明确结论：能做的写进实现，不能在 CLI0 范围内做的
（需要新语法或新编译期能力）先登记，不把猜测带进 CLI1。

## 已验证的能力

| 能力 | 探针位置 | 结论 |
| --- | --- | --- |
| tagged union（enum 标签 + union 载荷） | `model.ValueKind`/`ValueData` | 可用，跨模块构造与读取正常 |
| 递归指针类型 | `model.Node` + `build_list` | 可用，`next *Node` 自引用、堆结点链表遍历正常 |
| 跨模块返回结构体 | `model.make_integer` 等 | 可用 |
| 跨模块返回 `[]T` 切片 | `model.handle_view`、`model.bag_view` | 可用，前提是切片 data 指向**堆内**存储 |
| 切片作为形参跨模块传递 | `model.sequence_sum` | 可用 |
| 函数类型回调 + `*void` user 指针 | `model.apply_callback` + `main.collect` | 可用，回调真实执行并回写上下文 |
| 公开薄句柄（`*void` 持有私有状态） | `model.Handle` + `handle_state` | 可用，私有类型不出现在 pub 签名 |
| 堆内数组成员数组切片 | `model.handle_view`、`model.bag_view` | 可用；`state.items[0..count]` 的 data 在堆上，返回后不悬垂 |
| 跨模块枚举项引用 | `main` 的 `model.integer` 等 | 只能用 `模块名.枚举项`，三段式见下 |

## 语言边界（结论）

1. **切片不能指向裸堆指针**：`let p *T = malloc(...); let s []T = p[0..n];` 被
   语义阶段拒绝（「切片表达式需要数组或切片」）。因为切片描述符只能从数组或
   切片构造，`library` 的动态列表不能用「裸指针 + 长度」实现。
   可行替代（探针已证明）：把列表存储建成**堆上结构体的成员数组**，
   切片写成 `state.items[0..count]`，data 指向堆内地址，返回描述符安全。
2. **union 载荷不能递归引用自身类型**：`union ValueData { items []Value; }`
   与 `items *Value` 都被拒绝（「未知类型（类型必须先定义）」）。设计据此把
   序列载荷改成不透明指针 `*void`，见设计第 5.1 节。
3. **跨模块枚举项引用只支持 `模块名.枚举项`**（如 `model.integer`）；
   `模块名.枚举类型名.成员` 三段式被拒绝。枚举项随 `pub enum` 导出，
   且同名枚举成员不能在同一模块内共存。
4. `libs/sys`、`libs/toml` 目前只有占位目录（无 `.yh`），CLI1 只能用
   `io`/`memory`/`string`/`os`/`math`/`time`。

## 编译器修改（说明修改原因）

CLI0 允许为前置缺陷修编译器，但必须是最小修复、独立于 cli 实现，并按
仓库规则补 `.yh` 用例。本次只有一处修复：

### 枚举成员名被同名形参遮蔽

- 现象：`pub enum Kind { none; text; integer; }` 下，
  `fn make_text(text *char) Value { v.kind = Kind.text; ... }` 报
  `错误: 引用了未声明的名字`。
- 根因：`compiler/parse/parse_expr.yh` 的 `EnumName.member` 快路径用
  `sym_lookup` 查成员名；函数体内同名形参在符号表中优先命中，而该符号不是
  枚举成员，快路径随即放弃，退回到把 `Kind` 当普通标识符求值的路径而失败。
- 修复：`compiler/gen/state.yh` 新增 `sym_find_enum_member(etid, src, start, n)`
  （在符号表里按名字找属于该枚举类型的成员符号）；
  `parse_expr.yh` 在 `sym_lookup` 命中的不是枚举成员时改用它反查。
  `.` 右侧的名字总是成员名，词法作用域优先只适用于基底名字，语义不变。
- 为什么必须修而不是绕开：cli 设计大量使用与枚举成员同名的形参
  （如 `value_text(text *char)`、`optional(...)`、`count(...)` 类构造函数），
  绕开只能给每个形参改名，会把语言缺陷固化成库的命名约束。

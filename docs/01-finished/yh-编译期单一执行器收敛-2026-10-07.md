# 编译期单一执行器收敛（删除早期 token 求值器）

日期：2026-10-07。状态：已完成。方案：[yh-编译期单一执行器收敛实施方案](../02-plan/yh-编译期单一执行器收敛实施方案.md)。

## 背景

编译期函数此前有两套执行器：typed IR 执行器（`ct_ir.yh`、`ct_ir_place.yh`）与早期
token 求值器（`ct_eval_expr.yh`、`ct_eval_bool.yh`，合计约 650 行）。后者只在目标函数
尚未捕获 typed IR（`ir_ready == 0`）时兜底，服务两条 pass1 早期快路径：

1. `parse/parse_global_init.yh` 的 `parse_global_ct_const_probe`：顶层 `const` 的
   `$f(...)` 初始化器立即折叠；
2. `comptime/ct_registry.yh` 的数组长度 token 探测链
   （`ct_array_length_probe_*`、`ct_find_name`，约 130 行）。

两条快路径都在 pass1（`parse_source` 期间）求值，而 typed IR 捕获发生在 pass2 的
`parse_source_ct_fns`，因此必然回退到 token 求值器。

## 改动

| 位置 | 改动 |
| --- | --- |
| `parse/parse_global_init.yh` | `parse_global_ct_const_probe` 准入条件由 `ct_array_length_probe_supported(sym) != 0` 改为 `comptime.ct_is_prepared(sym) != 0`；pass1 期间恒为 0，早期折叠让位给 typed 布局常量依赖调度 |
| `comptime/ct_registry.yh` | 删除数组长度 token 探测链与 `ct_find_name`；`ct_invoke_in_frame` 回退分支改为诊断「编译期函数正文不在受支持的 typed IR 子集内」 |
| `comptime/ct_eval_expr.yh`、`comptime/ct_eval_bool.yh` | 删除文件 |
| `comptime/ct_00_model.yh` | 删除 `CtReader`、`CtLocal`；`ct_eval_depth` 注释改为 typed IR 执行器 |
| `parse/parse_decl.yh` | comptime 返回值/形参诊断去掉「首版」措辞并补上联合体与浮点描述 |

`comptime/` 模块总行数由 5480 降到 4593（净减 887 行）。

## 复用约束

- typed IR 是编译期唯一执行器：未被 `ct_ir_import` 捕获或不在支持子集内的编译期函数
  不再有解释兜底，直接报「编译期函数正文不在受支持的 typed IR 子集内」。
- 顶层整数常量与数组长度中的编译期调用必须在 pass2a 之后由
  `ct_layout_register` / `ct_layout_advance` 调度求值；若将来需要在 pass1 提前折叠，
  只有目标函数 `ct_is_prepared` 已就绪时快路径才会生效。
- 删除执行器类代码前先确认所有调用路径都能被目标执行器接管；未提交的工作区文件
  需先备份。本次第一轮删除只改了回退分支、未收敛快路径，导致 9 个用例失败，
  并误删未提交的 `ct_eval_expr.yh`（557 行）与 `ct_eval_bool.yh`。

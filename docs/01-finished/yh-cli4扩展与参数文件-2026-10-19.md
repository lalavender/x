# yh CLI4：扩展与参数文件（2026-10-19）

计划见[实施方案](../02-plan/yh-cli标准库实施方案.md)的 CLI4，
接口语义见 [cli 设计](../03-design/yh-cli标准库设计.md) 第 12/13 节。

## 目标

把 CLI1–CLI3 的固定能力扩展到应用可编程：转换器、校验器、自定义 action
与命名注册表，以及 `@file` 参数文件展开（含逐行回调、嵌套相对路径与上限）。

## 已实现的行为

- **converter**：`Argument.converter` 或 `type_name` 绑定；输出必须与 `value_kind`
  一致，否则 usage_error；回调返回 -1 时把诊断消息写入结果。
- **validator**：转换与 choices 之后逐值调用；`freeze` 时同样校验显式默认值与
  零参数 action 的常量，失败为 config_error（validator 因此可能被调用多次）。
- **custom action**：`Argument.custom_action` 或 `action_name` 绑定；必须显式声明数量
  与输出形状；`ActionContext` 提供参数 ID、dest、实际名称、出现次数、本次值、旧值与
  分配上下文；输出形状不符为 usage_error。
- **注册表**：`register_type`/`register_action` 限定当前 parser；重复名称、空回调、
  infer 数量、无效形状都在注册或 freeze 时拒绝；`type_name` 与 `converter`、
  `action_name` 与 `custom_action`、显式 `output_shape` 与注册项不能同时提供。
- **分配入口**：`context_text(context, text)` 把回调产生的文本复制进结果池；
  回调可以借用输入 token（解析期间有效）。
- **参数文件**：`fromfile_prefix_chars` 开启后，`@file` 在解析前展开为 token；
  默认一行一个完整参数（去 LF/CRLF、保留行内空白、空行产生空串、可选去首行 BOM），
  可用 `line_converter` 逐行改写；嵌套包含按包含文件目录解析；
  活动包含栈检测循环；深度、累计字节、token 数三个上限都可从 `ParseConfig` 调整；
  打开/读取失败、超限都返回带文件与行号的 resource_error，且不使用部分展开结果；
  所有 fd 在成功与失败路径都关闭。
- **子 parser 约束**：子命令 parser 不得设置参数文件前缀或逐行回调，
  在根 `freeze`（递归冻结整棵树）时返回 config_error。

## 本版本限制

- 展开相关常量：单文件 token 上限 4096、单行长度上限 4096、
  累计字节默认 1 MiB（`ParseConfig.file_max_bytes` 可调小）。
  设计文档中的默认值（100000 token / 8 MiB）按本版本常量收敛，超出即报错。
- 参数文件诊断带文件与行号，列号不提供（`Diagnostic.column` 为 -1）。
- `line_converter` 返回的 `LineTokens` 必须由回调自己持有（例如全局或池化存储）；
  库在回调返回后立即复制 token，不会借用回调栈数组。
- 自定义 action 的 `output_shape` 支持 depth 0/1/2；叶子类型不能是 sequence。

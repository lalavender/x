# 模块模式枚举成员限定引用：失败路径定位（排除假说）

日期：2026-10-07。状态：已完成（定位，无编译器改动 —— 两条放宽假设都被实验否定，已回退）。

## 目标

第 24 轮定位到：模块模式下**顶层常量**引用枚举成员可用，只有「编译期函数正文里直接引用
枚举成员」不可用（报「『.』的左侧不是结构体或结构体指针」）。本轮尝试修掉它。
结论是**没修成，但排除了两个具体假说，并把失败点夹逼到一条解析路径上**。

## 实验一：在标识符入口加阶段化诊断

在 `parse_expr.yh` 的枚举成员分支前插入只在准备期（`c_ct_prepare_active != 0`）打印的
分档诊断（类型查找失败 / 基名不是枚举 / 成员查不到 / 成员不是枚举成员 / 类型不匹配 /
命中），跑模块探针（`comptimecross` 副本 + 在 `@[comptime]` 函数体里写 `return Level.mid;`）：

```
../math/src/base/extra.yh:43:12: 警告: DBG enum-qual: MATCH
../math/src/base/extra.yh:43:21: 错误: 『.』的左侧不是结构体或结构体指针
```

`43:12` 是 `Level`，`43:21` 是 `.mid`。也就是说：**标识符入口这一次是命中了的**
（所有条件都成立，包括 `F_ENUM_MEMBER` 与类型归属），但同一次编译里仍然报出了字段访问
错误。说明 `Level.mid` 在这条路径上还被**另一条**解析路径处理了一次，而那条路径不经过
`parse_expr` 的标识符入口分支。

## 实验二：放宽分支条件

假说是"第二次解析时 `ty_lookup_name(Level)` 返回 -1 或 `sym_lookup(Level) >= 0`，导致
分支不命中"。按此放宽两次：

1. 去掉 `sym_lookup(istart, ilen) < 0`（只按「基名是 `TY_ENUM` + 成员属于该枚举」判断）；
2. 再放宽带类型可见性：只要求「基名不是符号 + 成员是 `F_ENUM_MEMBER`」，类型名可见时
   才额外校验归属。

两次都**不改变结果**，仍报同一个错误。因此假说被否定：问题不在分支条件，而在
**那条路径根本没走到这个分支**。

## 处置

两条放宽都没有收益，却各自引入一点误判风险（局部变量与枚举成员同名时的遮蔽、未声明标识符
加末尾点号时的误解析），所以按"只动该动的"原则**全部回退**，`parse_expr.yh` 恢复到第 22 轮
交付的状态。本轮不产生编译器改动，种子不滚动。

## 现状与推荐写法

模块模式里编译期正文**直接**引用枚举成员仍不可用；同模块**顶层常量**引用可用
（`comptimecross` 已锁定：`pub const MID int = Level.mid;` → `low=4`、`mid=5`，
编译期函数读该常量、跨模块转发都正常）。因此模块模式下的**推荐写法是用顶层常量中转**：

```yh
pub const MID int = Level.mid;     // 顶层：模块模式下可用
@[comptime] pub fn mid_ct() int {  // 编译期正文读常量，而不是直接写 Level.mid
    return MID;
}
```

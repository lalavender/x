# yh 标准库默认发现与安装布局

日期：2026-10-21。状态：**完成**（仓库布局与安装布局均已验证）。

依据：OS6“标准库加载与示例可重复使用”，以及 `docs/todo.md` 中
“为 libs 增加工具链默认发现与安装打包布局”。

## 1. 编译器行为

`compiler/cmd/module_build.yh` 的 `load_stdlib` 现在按以下优先级绑定标准库：

1. `YH_STDLIB` 非空：显式路径优先；路径无效或项目损坏直接失败，不回退默认层。
2. `YH_STDLIB` 为空或未设置：按可执行文件目录依次尝试
   - `<exe_dir>/libs`（仓库根 `yh` → `<root>/libs`）
   - `<exe_dir>/../libs`（`<root>/bin/yh-*` → `<root>/libs`）
   - `<exe_dir>/../share/yh/libs`（安装 `prefix/bin/yh` → `prefix/share/yh/libs`）
3. 都不存在时保持无标准库层；候选存在但 `project.toml` 损坏/装载失败时返回
   错误，不静默换下一个候选。

候选目录必须包含 `project.toml`；路径经现有 `pj_canon` 规范化，不按当前
工作目录猜测标准库。显式项目依赖仍按 `project.toml` 解析，优先于默认层。

## 2. 安装布局

`make install` 新增：

- `$(PREFIX)/share/yh/libs/`：安装 `libs/` 下全部 `.yh` 与 `project.toml`，
  排除 `libs/cli/test` fixture；保留模块目录结构。
- `make uninstall` 删除该目录。
- 补上 `INSTALL ?= install`，此前 `$(INSTALL)` 为空会让 install 命令缺命令名；
  安装循环从 `libs/` 目录内执行，目标为 `share/yh/libs/<模块目录>`。

编译器从 `<prefix>/bin/yh` 启动时自动找到 `<prefix>/share/yh/libs`，不要求
用户再设置 `YH_STDLIB`。安装后仍可用 `YH_STDLIB` 覆盖，或由项目显式依赖绑定。

## 3. 测试

- `tests/modules/build-check.py` 新增 `os6-default-stdlib`（kind
  `default-stdlib-run`）：在用例目录复制最小安装布局
  `<root>/bin/yh` + `<root>/share/yh/libs`，显式注入空 `YH_STDLIB` 后构建并
  运行 `osmodel`；该用例已在 `make selfhost-native` 中通过。
- 仓库布局：`env -u YH_STDLIB ./yh run`（仓库根编译器 + 仓库 `libs/`）编译
  `os` 并输出 `os model ok`。
- 安装布局：`prefix/bin/yh` + `prefix/share/yh/libs`，清空 `.build` 后同样
  不设 `YH_STDLIB` 运行，os 重新编译并成功。
- 显式覆盖仍由既有 stdlib 用例（`u2-stdlib-fallback`、`u2-stdlib-shadowed`）
  和 `examples/os-demo-explicit` 覆盖。

## 4. 验证环境说明

0.0.7 同步后的主工作区最初缺少 `libs/os`/`libs/sys`；本实现从备份 stash
选择性恢复 OS0–OS6 文件并适配 0.0.7 的 `[project].os/arch` 必填字段。恢复后
在 /Users/lavender/Documents/x 主工作区重新构建并验证：

- `make`、`make test`、CLI 9/9 通过。
- `make selfhost-native SKIP_CORPUS=1`：固定点 27 项产物一致、自解析 100 个
  文件、项目用例 115/115（含 `os6-default-stdlib`）。
- Linux/arm64 容器 15 个 os/sys fixture 全部退出 0。
- 未修改无关的 project-link 文件；未修改种子。

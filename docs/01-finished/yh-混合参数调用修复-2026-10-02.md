## 根因与修复

`compiler/gen/sem_call_literal.yh` 原来按总实参数量减八计算栈参数，
忽略 AArch64 的整数/指针和浮点各有八个独立参数寄存器。十个交错
实参只有五个整数和五个浮点，应全部进寄存器，旧实现却先弹出末尾
两个，再在混合路径弹出十个，导致值栈失衡和错误结果。

现调用点先按类别计数，栈槽只计算整数寄存器溢出的部分。混合路径
一次性弹出全部实参并暂存，随后按整数和浮点各自序号装载寄存器。
整数溢出实参按顺序写入暂存栈槽，再统一回填调用点栈区；夹在其中
的浮点实参仍进入浮点寄存器。纯整数路径沿用直接弹入寄存器的方式。

类型化变参打包后，其元数据同步为切片类型，避免把切片地址沿用为
首个浮点元素的类型。超过八个固定浮点参数在调用点明确拒绝，与
现有函数入口限制一致，避免函数指针调用静默丢弃第九个浮点参数。

本次未修改语法或拓展 C 裸变参、浮点溢出栈参数、聚合 C ABI。

## 正式回归

- `tests/yh-run/run/52-mixed-many-args.yh`：十个 f32/f64/int 交错参数，
  十一个整数与三个浮点的非连续栈参数，直接/间接/嵌套调用，以及
  浮点类型化变参切片。不同参数使用不同权重，预期值手算为
  385、1015、1531 与 14，参数错序不能被普通加法掩盖。
- `tests/yh-run/fail/33-too-many-float-args.yh`：第九个浮点实参的间接
  调用必须编译失败，并产生“过多的浮点参数暂不支持”诊断。
- `tests/modules/projects/cinterop/src/mixed_args.yh` 与
  `c/mixed_args.c`：C/yh 双向验证十个交错标量和十四个混合参数。
  整数溢出用 i64，覆盖三个八字节栈槽。C → yh 控制组先运行，后续
  返回码区分两个 yh → C 调用错误；通过现有项目验收持续执行。

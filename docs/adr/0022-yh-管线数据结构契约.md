# ADR-0022：管线数据结构契约——阶段显式化，不引入 UIR

日期：2026-11-10。状态：**已批准，实施中**（B0 编排片先行）。
决策人：用户（D1/D2/D3 三项均按推荐拍板）。

关联：[ADR-0009](0009-yh采用check与IR及早期并行.md)（check/IR/并行）、
[ADR-0021](0021-yh-gen职责拆分.md)（模块归属）、
[ADR-0020](0020-yh对象粒度停在模块级.md)（对象粒度）。
方案：[管线数据结构重设计](../02-plan/yh-管线数据结构重设计-2026-11-10.md)
（字段级结构、现状映射与切片；全量完成后归档删除）。

## 背景

「编译流程不清晰」的三个数据结构根源（2026-11-10 实测）：

1. **阶段身份靠开关组合**：`SessionCtx` 9 个阶段行为开关 × `mb_pass2_file`
   魔数 mode（0–5），同一文件重复 parse 6+ 次，读 worker 主流程需脑内维护 flag 矩阵。
2. **阶段产物靠全局 arena**：parse/check/CT 各写全局表，唯一显式阶段产物是
   `CheckedModule`；`AstExpr` 25 字段中 15 个是语义注解，语法/语义同体。
3. **编排输入隐式分散**：worker 输入散在函数参数、`BuildCtx.dep`、
   `proj.cfg()` 改写与 `support.fs()`；调度态是三条平行数组；`LinkPlan`
   是过程私有 scratchpad 而非契约。

架构 §6.11 草案（Zig 对齐 AstGen/UIR/Sema）待评审，需一并拍板。

## 决定

### 1. 不引入 UIR 层（D1）

- yh AST **已是扁平 arena + id 引用**，Zig AstGen「指针树→扁平流」的转换前提
  不存在；再加 UIR 近乎同构复制，多一份 arena/verifier/缓存失效矩阵。
- PF2 实测前端仅占冷编 worker CPU 6%（lowering 66%），文件级 UIR 缓存收益
  无测量支撑；函数级增量已由 `.fchk`/`.fir` 覆盖。
- §6.11 的核心收益由「AST 纯化 + 注解侧表」全部获得：语法/语义分离、
  CT 在显式节点上展开、HIR 契约、eager full。
- **CT 展开位置修订为纯语法 AST**（原草案「放 UIR」）；「暂不接受惰性 Sema」
  维持不变。将来前端实测成瓶颈或需文件级并行时再立 ADR 引入 UIR——
  本决定的语法/语义分离是其必要前提，不返工。

### 2. 阶段显式化，存储不搬家

fork/COW 模型下单例存储合法；重做的是**阶段间契约**，不是线程化 203 个模块级
`let`。状态归属判据沿用架构 §4.5：fork 后允许各不同 → 任务私有。

### 3. 管线契约结构（字段级定义见方案 §4）

| 结构 | 契约 | 取代 |
| --- | --- | --- |
| `ModuleJob` | worker 唯一输入（模块/mode/依赖接口/符号后缀/产物目录/指纹） | 五参数 + `BuildCtx.dep` + `proj.cfg()` 改写 + `support.fs().sym_sfx` |
| `FrontendStage` 枚举 + 命名阶段入口 | 阶段身份 | SessionCtx 阶段开关 × 魔数 mode |
| `WorkerSlot` | 调度状态（命名枚举 + pid + ActionID） | states/pids/keys 三平行数组 |
| `AstExpr` 纯语法（10 字段）+ `ExprSem` 注解侧表（15 字段，check 拥有） | 语法/语义分离 | AstExpr 双重身份；S4-2e/f 终态 |
| `CheckedStorage` 持纯语法节点 + 侧表 | HIR 容器 | AST 快照含语义注解 |
| `LinkJob` / `LinkScratch` | 链接输入契约 / 阶段私态 | LinkPlan 大杂烩 |

行为配置收编（D3）：`check_only/test_mode` → `ModuleJob.mode`；
`legacy_system` → 构建会话配置；SessionCtx 最终只剩阶段游标并删除。

### 4. 兼容硬门

- 纯移动片产物逐字节一致（`--emit-asm` 与种子差分）；
- 内存拆分、落盘合并：`.fchk`/快照字节不变，缓存键 schema 不动；
- `--emit-module` 子进程协议 argv 不变；fork 与 Windows re-exec 两路径保持；
- 每片 `just build` + `just test`；提交前 `just selfhost-native`（CI）。

### 5. 推进顺序（D2）

B0（ModuleJob/WorkerSlot/命名阶段）先行，与 S4 前端片双线独立，
B2（CheckedStorage 定稿）汇合；B1/B3/B4 随后。切片表见方案 §6。

## 备选与被否决的方案

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| 引入 UIR（§6.11 原草案） | 否决 | 扁平 arena 前提不存在；前端 6% 收益无测量；多一层缓存失效矩阵 |
| 只合并 build 文件（build_pipeline 方案） | 正交，不替代 | 文件组织不解决阶段身份/产物隐式；该方案仍独立待决 |
| 线程化全部全局状态 | 否决 | fork/COW 下单例合法；diff 巨大且无并行收益（线程池 LA5 暂缓） |
| 等 S4 收口再动编排 | 否决（D2） | 流程不清晰持续数周；B0 纯搬移与影子门互不影响 |
| 行为配置留 SessionCtx | 否决（D3） | 阶段与配置混在一个结构正是问题本身 |

## 后果

- 架构 §6.10 目标链路不变；§6.11 标记已评审否决（保留作评审记录）。
- `BuildCtx` 只剩构建会话自属态；`proj` 只读模型不再被 worker 改写。
- S4-2 影子门判据不变；侧表即 S4-2e/f 的落点，前端切片不返工。
- `SessionCtx`/`FrontCtx` 字段只减不增；旧发射器字段（`c_fp_off/c_spill_*` 等）
  仍被 check 维护，B4 只盘点，删除另行立项。

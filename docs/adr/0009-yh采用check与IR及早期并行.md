# ADR-0009：yh 采用 check、IR 与早期并行路线

日期：2026-10-01。状态：D1–D15 与完整工程方案均已由用户确认，
实施中；R0 已完成，R1/R2a/R2b 已进入分片实施。本决定替代 ADR-0008 的路线建议。
2026-11-06：增量缓存中的“文件对象”部分由 [ADR-0020](0020-yh对象粒度停在模块级.md)
撤销；文件解析、函数 check/IR 与其余路线继续有效。

用户指定编译主线为词法、语法、语义、check、IR、多平台汇编、汇编
与链接，且增量编译速度第一、冷编第二，均计入汇编与链接。check
是独立逻辑阶段和命令，允许合并部分遍历；模块并行从早期架构考虑。
因此不继续采用上一轮“先整理 token 直发射，延后 IR/并行”的路线。

当前模块级并行先以最多四个独立进程 worker 落地，作为隔离现有可变全局的
过渡方案；worker 通过显式 argv 启动，接口按构建会话隔离并原子提交。它只验证
模块依赖调度契约，首个完整 SSA 版本仍须落实线程池和任务私有状态。

首版选择 SSA IR，即使前期成本较高；并行采用线程池与任务私有
上下文，过渡可用进程 worker。公开接口检查完成即可推进依赖者，
仅在本次构建内提前使用，持久产物另行提交。增量缓存采用文件解析、
函数 check/IR、文件对象，公开接口变更先保守扩大失效范围。

最终 yh 与普通程序无需外部工具、shell、libc/CRT，保留 OS API，
开发测试工具暂允许。后续自研汇编器、链接器，并配套最小运行时与
宿主接口。首批验收 macOS/Linux arm64，Linux 先完成自有工具链闭环，
随后扩展 x64 与 Windows。Linux 首版支持自有后端/运行时汇编子集与
静态 ELF；macOS 允许审核后的 libSystem OS API 与 dyld，按导入 API
验收。独立配置不提供隐式 system；旧行为仅在过渡兼容配置保留。

词法/语法跨目标复用，check/IR 先按目标数据模型与 ABI 隔离。默认
低成本 SSA 优化，昂贵优化留给显式发布模式。允许重组编译器内部
模块以隔离状态和职责，但公共模块只放必要能力，控制依赖与数量。

暂定固定约 1.3 万行、M1、无常驻守护进程、含汇编链接的最终目标：
无改动≤50ms、真实单函数修改≤200ms、冷编≤1s。它们是验收目标，
不是已实现保证；重构成本与自有工具链范围通过分期计划控制。
详见[架构设计 §4.1/§7](../03-design/yh-架构设计.md)与
[实施方案](../02-plan/yh-编译流程重规划实施方案.md)。

# ADR-0013：yh 模块私有类型（struct/union/enum 的 pub 可选）

日期：2026-10-12。状态：**已实施**（Linux/WSL 全绿并滚种子，见
[完成报告](../01-finished/yh-模块私有类型-2026-10-12.md)）。本文修订 2026-10-02
「pub struct/union/enum 一等化」中"必须写 pub"的部分；该决定的另外两条
（字段一律公开、类型声明禁止嵌套）继续有效。

## 背景

2026-10-02 的「一等化」把 `pub` 从类型级可见性开关改成无信息的强制前缀：
struct/union/enum 裸写即语法错误，所有类型一律进接口文件（`.s.i`）。
带来的后果：

- 模块无法隐藏内部数据结构，接口必然携带全部类型的完整字段布局；
- 模块导出面无法收缩：编译器自身 66 个类型全是 `pub struct`，接口 39,990 字节
  中相当部分是消费者不需要的类型；
- 与[Go 风格模块与包设计](../03-design/yh-Go风格模块与包设计.md) §5.1 的原始设计
  不一致——那里写明"`struct/type/union/enum`：其他包名字不可使用"。

用户要求把不带 `pub` 的 struct/union/enum 标识为**模块私有类型**，恢复类型级
可见性语义。

## 备选

| 路线 | 优点 | 代价 |
| --- | --- | --- |
| 维持强制 pub（现状） | 规则简单、接口自洽、无需新语料 | 模块无法隐藏内部类型；导出面与接口体量无法再收 |
| pub 可选 = 模块私有（**采用**） | 恢复类型级可见性；接口只带公开类型；与 fn/const/type 的既有口径一致 | 需改语法与两处门禁、3 条负例语料转正、文档刷新；多一类可见性需要新的用例矩阵 |
| 不透明导出类型（pub 但隐藏布局） | 能对外暴露不完整类型 | 需要新的接口/布局传递语义与 ABI 规则，工作量与风险远大于本次目标 |

## 决定

1. `struct` / `union` / `enum` 的 `pub` **可选**：`pub` 形式进接口、跨模块可命名；
   无 `pub` 形式为**模块私有类型**，只在本模块可见、不进接口。
2. 私有类型**不得出现在任何公开 API**：本模块的 `pub fn` 签名、`pub struct` 字段、
   `pub type` 别名体引用私有类型时，沿用既有诊断
   「pub 接口引用了非 pub 类型（请将该类型声明为 pub）」报错（连指针形式也不行）。
3. enum 成员常量随枚举可见性：私有 enum 的成员不带 `F_PUB`（现有实现已按
   `c_decl_pub` 条件化，无需改动）。
4. 字段仍然一律公开（模块内可见），字段级 `pub` 前缀仍然报错；类型声明仍然只能
   在顶层；`pub let` 仍然非法。
5. `pub` 只影响可见性，不影响布局与 ABI；私有类型与 pub 类型的 `sizeof`/对齐相同。

## 后果与取舍

- **放宽而非收紧**：裸类型以前是错误、现在合法，现有正确代码不受影响；需要改的
  只有依赖该错误的 3 条负例语料与相关文档。
- **实现面很小**：删 `parse/parse_decl.yh` 两处门禁即可；接口发射（`is_pub` 过滤）、
  enum 成员 `F_PUB`、pub 声明引用非 pub 类型的诊断、CT 跨模块私有类型诊断都已存在。
- **两段自举是硬约束**：门禁在编译器二进制里，必须先用旧种子编出"门禁已删"的编译器，
  再让编译器源码使用私有类型；因此编译器自身的类型私有化排在语言规则落地并滚种子之后。
- **收益有上限**：静态估算 66 个类型中只有 12 个可干净私有化（ast 5、main 4、
  comptime 2、parse 1；gen/ir 为 0），实测 3 个类型使接口 39,990 → 38,871 字节。
  本决定的主动机是**语言表达力与模块封装**，不是接口字节数。
- **不引入**不透明导出类型、类型嵌套、字段级可见性、`pub let`；这些仍未决或明确不做。

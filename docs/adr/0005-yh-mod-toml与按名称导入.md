# ADR-0005：mod.toml 项目与按名称导入的源码模块

日期：2026-09-29。状态：**已实施**（MOD-U0–U5 于 2026-09-29/30 交付并过门）。
替代 ADR-0004 的项目清单、源码归属、导入与 internal 决策。

> 0.0.3 补记：清单文件已于 2026-09-30 由 `mod.toml` 改名为 `project.toml`，
> 并删除 `entry` 字段——入口由源码中的 `module main;` 决定。文件名变化不改变
> 本 ADR 的实质决策。

设计见 [模块与项目管理](../03-design/yh-模块与项目管理设计.md)，
实施见 [执行方案](../02-plan/yh-模块与项目管理实施方案.md)。

## 背景与要求

用户要求使用项目清单管理项目（初名 `mod.toml`，现 `project.toml`），将
package 改为 module，去掉 internal 机制；import 直接使用模块名，先找本项目，
再找标准库，最后第三方。上一版的 Go 式完整路径导入与 yh.mod 已不再适用。

## 决策与取舍

| 决策 | 规则 | 代价与处理 |
| --- | --- | --- |
| 项目清单 | project.toml；管理源根与依赖（入口 = `module main;`，无 entry 字段） | 需要 TOML 解析与 schema 诊断；不是自定义逐行文本 |
| 源码组织 | module IDENT；同模块可包含多个 .yh 文件 | 构建器需要模块头索引；同名文件声明合并，同模块重声明报错 |
| 名称导入 | import os；本项目 → 标准库 → 直接依赖 | 本地可遮蔽标准库；解析结果可通过诊断命令检查 |
| 绑定后错误 | 已找到的模块编译失败或缺成员直接报错 | 不以失败回退，不按成员合并各层接口 |
| 解析上下文 | 当前项目是导入文件所属项目 | 主项目不能覆盖依赖或标准库内部的导入；缓存须包含项目身份 |
| 同层同名 | 多个第三方项目提供同名候选时报歧义 | 不按依赖排列任选；首版通过明确依赖与模块命名处理 |
| 可见性 | 模块私有 + pub；internal 无特殊权限 | 项目内跨模块协作也需要 pub；同模块拆文件无需公开辅助函数 |
| 真实身份 | 提供方项目 + module，而非导入短名称 | 类型、机器符号、接口和缓存都保留提供方身份 |

## 后果与边界

项目内文件移动不改变显式模块名。导入仍属于文件作用域。
库模块不要求 main，源码模块导入图禁止循环。同项目和依赖项目分别
建立上下文，传递依赖不进入调用者的直接可搜索集合。

本地 os 的存在会遮蔽标准库 os，是用户要求的确定行为；本设计不额外
增加绕过优先级的来源限定语法。需要两者同时使用时再设计专门机制。

先完成当前项目、标准库和本地第三方项目的完整运行。远程版本、锁文件、
工作区与选择性导入不沿用旧方案承诺，后续按实际需求单独确定。
本次只更改设计和任务文档，没有更改 grammar、编译器或项目构建入口。

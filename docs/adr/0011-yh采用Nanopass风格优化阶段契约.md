# ADR-0011：yh 采用 Nanopass 风格优化阶段契约

日期：2026-10-02。状态：**部分被 ADR-0014 取代（2026-10-26），只保留 NP3**。
编号 0010 已在 FFI 待办中预留；本草案使用 0011，不代替 ADR-0009。
本轮定位见文末《2026-10-26 定位决定》。

## 背景

用户希望为 yh 适配 Nanopass 类似的优化架构，并选择优化扩展与自举稳定优先。
现有 typed SSA、verifier、函数缓存与 arm64 后端提供了演进基础；
`ir_simplify` 混合多种处理，AST lowering 还负责缓存与后端替换，
新旧发射交织，限制了优化的独立验证和函数任务隔离。

既有 ADR-0009 已确定 SSA、增量速度优先与低成本默认优化，本决定只细化内部边界。

## 备选

| 路线 | 优点 | 代价 |
| --- | --- | --- |
| 在当前简化函数中继续增加规则 | 初期改动少 | 契约隐含、引用/分析失效易遗漏、后续难定位 |
| 阶段契约 + 小 pass + 复用 SSA（推荐） | 与现有代码衔接；可逐项自举；职责和语义前提清楚 | 需共用引用工具/分析索引和若干边界校验 |
| 完整移植 Nanopass DSL 或一次建立大量独立 IR | 可表达丰富语言派生与生成规则 | yh 缺少相应宏设施；增加宿主/工具依赖和迁移成本 |

## 建议决定

1. 采用受检/Core、typed SSA、机器 IR 三个内存表示族；用具体阶段契约
   表达多个逻辑语言。S → S 优化复用同一 schema，不每 pass 新建结构体。
2. pass 使用普通 yh 函数与静态顺序，函数状态私有；不依赖 Scheme/Racket。
3. 先拆现有简化且保持结果，再增加低成本优化。默认 O1、对照 O0 与
   发布 O2 为拟议模式，全部进入完整缓存失效链。
4. 第一批优化保守对待效果、陷阱、调用及浮点；寄存器分配与昂贵优化分期。
5. 稳定遍历/ID/预算；结构校验、模式语义差分、候选两代固定点均作为门。
6. 初期复用既有优化后 SSA 缓存；不持久缓存每个小 pass。

## 后果与取舍

规则更容易测试和复用，失败可以定位到具体表示与变换。
额外遍历/校验可能增加编译成本，所以复用 arena/分析表，并以冻结语料测量。
阶段元数据不能代替实际 verifier；固定点不能证明优化语义等价。

该架构不自动提高运行性能，现有每值独立栈槽的问题仍需机器 IR/分配解决。
完整受检输入与新后端覆盖需要逐切片迁移；优化子项目不能替代 R2b 的
真正线程池、增量对象或 R4/R5 的自有工具链验收。

## 验证

先交付 NP0–NP2，保持已有自举策略与语法；每个行为切片有 `.yh` 用例、
`make` 和针对性回归，每阶段 `make test` 与 `make selfhost-native` 全绿。
无有效语义证据、回退掩盖新路径或产物不确定时不滚种子。

详见[架构设计 §7](../03-design/yh-架构设计.md)与
[实施方案](../02-plan/yh-Nanopass风格优化架构实施方案.md)。

## 2026-10-26 定位决定

用户决定：**只保留 NP3（受检契约与 lowering 解耦），NP0/NP1/NP2/NP4/NP5 关闭**。

| 阶段 | 处置 | 依据 |
| --- | --- | --- |
| NP0 语义/对照/O0-O1 | 关闭，口径并入现有 `make test` + O0/O2 门与自举门 | 不另建一套 O1 模式与阶段计数设施 |
| NP1 拆 `ir_simplify` | 关闭 | `ir_simplify` 已从 `compiler/` 删除（A0e），对象代码不存在 |
| NP2 默认自研 SSA 优化 | 关闭 | 通用优化交固定 LLVM 管线（ADR-0014）；`ssa_inline` 亦已删除（A0b） |
| NP3 受检/Core 与解耦 | **保留**，仍是独立阶段 | ADR-0014 明文「NP3 的受检/解耦工作继续」 |
| NP4 自研机器 IR/分配 | 关闭 | ADR-0014：由 LLVM 取代，不再是前置 |
| NP5 发布优化 | 关闭 | 语言/CT 专属变换仍需独立验证，届时按普通任务立项 |

本决定不改变 NP3 的范围与验收（封存受检快照、按控制流规范化、预检与构造分离、
受支持函数只走一次），也不改变 ADR-0009 的增量与自举约束。

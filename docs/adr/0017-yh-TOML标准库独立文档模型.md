# ADR-0017：yh TOML 标准库采用独立文档模型

日期：2026-10-23。状态：**接受并实施 reader（T0–T5，2026-10-23）**；
编译器迁移（T6）与 writer（T7）仍待办。
用户已确认“完整 reader 优先、写入后置”；独立文档模型按本 ADR 落地，实际
实现见 `libs/toml/`。

## 背景

编译器现有 `cmd/toml.yh` 只解析清单子集，依赖全局游标、`toml_secs` 和 gen 名字池。
递归加载项目会重置解析状态。标准库需要多个文档同时存活、通用值树、类型化查询和
明确释放，不能把进程级一次解析状态当成应用 API。

现有 cli 已验证私有池和薄句柄可行，但其 NUL 结尾文本不能表示 TOML 解码结果中的
全部字符串/键；浮点转换规则也需要独立验证。

## 备选

1. 直接导出现有清单解析器：最少改动，但保留 gen 耦合、子集语义和全局生命周期。
2. 完整 reader + 独立 Document + 只读 Value：新增通用模型，能独立验收，推荐。
3. 从保真语法树开始，同时做 reader/writer/编辑器：能力更多，但注释和布局模型
   超出当前需求，交付与维护成本最高。

## 提议

- 标准库为普通 `libs/toml` 模块，目标规范固定 TOML 1.1.0，不修改 yh 语法。
- T0–T5 交付完整 reader；writer 后置，保真编辑、反射映射和 schema 框架不预建。
- Document 独占私有池；成功后输入可释放，Value/文本仅借用文档存储。
  失败回收全部临时资源；没有全局错误、结果缓冲、隐式析构或引用计数。
- 文本与键使用 `*u8 + 长度`；值和容器使用不透明句柄，避开递归类型与裸指针切片
  的现有限制。只导出真实消费接口，不对外暴露池和节点布局。
- TOML 解析/值树和 `project.toml` schema 分层；迁移在 T6 另做，显式依赖标准库，
  不迁入 gen 耦合，不以新解析器绕过原项目字段与路径校验。
- 解析实现使用 yh，文件适配复用 os；浮点精确转换先做风险探针和独立参考差分，
  不把宿主默认 locale 的 strtod 或 CLI 简化算法作为隐含实现。
- 固定 toml-test 版本、显式选 1.1，标准一致性、API/所有权、资源和自举各有独立门。

## 后果与权衡

私有存储与输入解耦需要复制键和值，内存高于零拷贝借用，但生命周期易于解释。
只读句柄避免暴露递归结构和容器扩容地址，代价是需要查询函数；yh 不能静态禁止
复制所有权或释放后使用，因此调用者仍须遵守显式契约。

以 i64 / binary64 和资源预算约束实现，超范围明确失败；不承诺无限精度/无限大小。
精确浮点和表定义状态是主要实现成本，分期不能取消这些正确性门。
时间先返回带独立类型的已验证文本，保留精度；日历结构转换按真实消费者另加。

首期不改编译器，暂时有两套解析路径；待通用库验收后迁移并删除失去消费者的旧版，
以此控制滚动自举风险。只要 T6 未完成，就不能宣称编译器已经使用标准库 TOML。

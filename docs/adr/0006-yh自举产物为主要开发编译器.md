# ADR-0006：yh 自举产物为主要开发编译器，stage0 冻结为种子与参照

日期：2026-09-29。状态：已接受（用户指示）。**2026-09-30 更新**：0.0.3 已删除 src/（stage0）与 bootstrap/，本决策的「种子与参照」角色终结，进入滚动自举（种子 = bin/yh，2026-09-30 起主编译器二进制由 yh-new 更名为 yh），见 docs/finish.md 同日条目。

## 背景

自举链（compiler/ 下的 yh 源码，经 stage0 → stage1 → stage2 → stage3）
已达 G3：三代固定点、全量语料通过（语法 66/66 + 29/29、运行 61/61），
且自举产物具备本机直接可用的完整工具形态——`yh file -o out`（双形态
CLI、宿主自动方言探测）在 Darwin 与 Linux 容器均跑下全部语料
（`make selfhost-native` / `make bootstrap` / `make g3` 全绿）。

与此同时，差分压测（tmp/dt-gen.py）记录了 stage0（src/ 下 C 实现）
的一批自身缺陷：u64 局部 store 断言、深帧多 switch/三元断言、数组
形参直接 for-in 误拒、聚合返回值直接作实参断言、深帧聚合局部零初始
化失效（详见 docs/todo.md「stage0 参照系缺陷六项」）。stage0 与自举
侧并行修改还带来协调成本（同一时期两处修复同一族 bug）。

## 决策

1. **后续所有功能开发与 bug 修复一律在 compiler/（yh 自举源码）实现**；
   新特性先在自举侧落地并跑通全量语料（语法 + 运行 + 固定点），再谈
   其他。
2. **stage0（src/ 下 C 代码）冻结** → **0.0.3 已删除**：`src/`、`bootstrap/`
   与 `make test` 的 stage0 语义全部随删除终结，构建改为入库种子 `bin/yh`
   对 `compiler/` 项目一步链 `yh build`（`make SEED=…` 可覆盖种子路径）。
   差分参照系不复存在，自举侧不再与 stage0 对照。
3. ~~**允许修改 stage0 的唯一例外**~~ —— 对象已不存在，本条终结。
4. 日常验证以**自举产物**为准：`make selfhost-native`（两代模块固定点 +
   自解析 + 全量语法/运行语料 + 模块语料 + 项目验收）为主门；
   `make test` 是三层回归（ANTLR 语法 + 编译器语法模式 + `tests/yh-run`），
   与 stage0 无关。容器门 `make g3` 已随 stage0 删除而移除。

## 影响

- stage0 参照系缺陷六项转入「已知不修」清单（docs/todo.md），差分压测
  （tmp/dt-gen.py）遇到这些场景需规避或按 ADR-0002/0001 语义以自举
  输出为准。
- 「是否替换默认 yh」的原悬置问题（G3 验收报告 §9）按本决策**渐进
  解决**：开发与验收事实上已切换到自举产物；默认 `yh` 二进制的切换
  （make 产物指向自举编译器）另立里程碑验收，不在本 ADR 范围。
- 工具链未完全自给的现状（依赖系统 as/gcc/clang 与 C 运行时）不变，
  符合自举方案既定边界。

## 后续（建议，另立任务）

- 为自举产物建立每平台种子二进制归档与哈希校验流程（`bin/yh` +
  `bin/yh.sha256` 已是本机形态的种子归档，跨平台归档仍待建立）；
- ~~自举侧补齐 stage0 独有能力（`-c`、`-run` 等）~~ —— 这些能力已随
  stage0 删除而**不再补齐**；产物形态改由宿主决定，Linux 开发/CI 需另行
  建立（见 `docs/todo.md`）。

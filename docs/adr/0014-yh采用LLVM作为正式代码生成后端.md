# ADR-0014：yh 采用 LLVM 作为正式代码生成后端

日期：2026-10-14。状态：**已采纳，分阶段实施中，生产后端尚未切换**。
用户授权按现有方案制定计划、开始实施、每阶段验收后提交，要求 yh 嵌入 LLVM、
不依赖系统 LLVM 并通过全部用例；该新要求取代原草案的外部 clang 路线。
Linux/x86_64 优先、原有语义/运行时/自举硬门保留。

## 背景与建议

yh 希望支持 Windows/Linux/macOS 以及 x86_64/ARM64。现有运行期 IR 覆盖有限，
前端与 ARM64 直接发射交织；继续自研需要承担机器 IR、寄存器分配、多 ISA 发射和
对象工具链的长期维护。建议保留 yh 的语义/check、编译期执行和语言 IR，将生产代码生成
逐步替换为 LLVM。完整语义、运行时、缓存和连续自编通过后，LLVM 成为默认且唯一生产后端。

## 取舍

- 首期以 LLVM 21.1.8 文本 IR + 静态 LLVM C API 桥完成进程内对象生成；
  LLVM 库嵌入 yh，编译时不查找系统 LLVM、不调用 clang/llc，也不依赖 libLLVM.so。
  构建用校验过的固定 SDK，不向系统安装 LLVM。Linux/x86_64 的最终链接使用静态嵌入的
  lld；其他宿主/目标在各自阶段接入前仍可使用显式平台链接驱动。普通 AOT 程序不携带
  LLVM/lld；C++ 构建器与 OS/运行时依赖分别披露。
- 过渡期保留旧后端用于旧种子冷编和独立产物差分；不做同模块自动回退，不混旧 yh ABI 对象。
- Linux/x86_64 先完成原生验证、默认切换和独立种子；旧 ARM64 种子经 qemu 仅作启动桥。
  随后接 Linux/AArch64、macOS/ARM64、Windows/x86_64，再补其余两格。
- 首期要实现 x64 OS/运行时桥和原生链接，不误用 ARM64 crossbin/gcc；
  x64 产物不覆盖 ARM64 种子。旧后端退役等待 Linux/AArch64 LLVM 回归，不阻挡 x64 首期。
- 运行时禁止 C 服务导入、语义正确性、增量速度目标及滚动自举/种子门继续保留。
  R2b 已确认的完整版本硬门不能因后端变化被静默降低。
- 通用优化/寄存器分配交给 LLVM，NP3 的受检/解耦工作继续；NP4 自研机器 IR/分配器
  不再作为此路线前置，NP2/NP5 仅保留必要的语言规范化。
- asm/、link/ 保留已有成果及历史；其是否继续作为独立产品由后续需求确定。
  不把自研多平台汇编/链接器建设继续列作 LLVM 默认切换的必要条件。

本决定替代 ADR-0009 中自研代码生成终态的相关条款；LLVM 生成对象不需要外部工具。
LL9L 后 Linux/x86_64 使用内嵌 lld 完成最终链接；尚未接入 lld 的宿主/目标仍显式依赖
平台链接驱动。不撤销其语义、SSA、增量/并发、运行时及验证要求。
已有“yh 独立工具链/独立配置”术语属于旧产品政策，采纳时同步调整定义和发行说明。

备选为继续自研，或永久维护两个完整后端；前者保留小工具链优势但多架构维护成本高，
后者保留选择但重复承担覆盖/ABI/回归成本。LLVM 的代价是额外工具链分发、编译成本、
版本约束和正确语义 lowering；不承诺替换本身提升冷编或增量速度。

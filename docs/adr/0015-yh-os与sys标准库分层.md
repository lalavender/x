# ADR-0015：yh os 与 sys 标准库分层

日期：2026-10-19。状态：**提议，待接口评审；尚未实施**。
用户已确认标准库可用性优先；该优先级不等于具体新 API 已定稿。

## 背景

os 已存在 libc 薄封装，sys 仍是 2026-10-03 的规划。直接按旧 SYS0–SYS6
顺序实施，会把应用可用性排在全部原语、编译器迁移和独立自举之后；旧文档
还没有包含目前 Linux/x64 LLVM 入口和 OS/架构组合文件筛选能力。

## 备选

1. 继续只扩 os/libc：短期少一层，长期保留错误丢失和平台常量外泄。
2. 先做完整 sys 和编译器迁移：统一底层，但应用交付受整个工具链排期约束。
3. sys 原语与 os 应用接口分层，每批打通一个场景：多一层小转换，先交付文件，
   再目录、环境、进程；与已确认优先级一致，推荐此方案。

## 提议

- sys 集中目标 ABI，Linux 保留 -errno、单次调用，不分配/重试，不依赖上层。
- os 新接口使用具体结果结构和稳定错误分类，native_code 保留平台错误号；
  不增加全局 errno、泛型、异常或隐式分配。旧接口保留原契约。
- os 的打开选项不使用宿主 O_* 数值；目录借用调用方缓冲；环境显式接收 envp；
  spawn 精确路径并回传 exec 失败。io/time/memory 保持各自算法与资源职责。
- Linux/x64 与 ARM64 分别适配 ABI，沿用现有 CI 和本地分工；Darwin 新接口
  后续逐项接入，旧接口继续使用。平台完成情况分别记录。
- 按 OS0–OS6 交付库能力，OS7 编译器迁移/独立审计与 OS8 Darwin 适配后续执行；
  不撤销 ADR-0014 的 LLVM/lld 路线或种子硬门。

## 后果

短期同时存在新错误结构与旧 -1 接口，但转换位置明确；新旧打开标志不能混用。
借用缓冲和 envp 避免隐式分配，也要求调用方遵守生命周期。精确路径 spawn
范围较小，但必须承担错误握手和子进程回收；不把 fork 成功包装成执行成功。
跨平台 API 的一致性需逐目标验收，不能仅凭公共模型声明支持。

## 验证与关联

各阶段以真实 `.yh` 项目、本平台 make test/selfhost-native 与 CI 对应目标结果
关闭。库可用性与静态 ELF、编译器自举分别验收；本轮只交付规划。

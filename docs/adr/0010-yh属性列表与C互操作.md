# ADR-0010：顶层属性列表与 C 互操作

- 状态：已采纳并实施；Linux AArch64 原生运行单独待验收
- 日期：2026-10-02

后续固定参数聚合/HFA 与函数类型 ABI 扩展由
[ADR-0012](0012-yh函数类型保存调用约定并自动转换C-ABI.md)规定；以下保留首版决策。

## 背景

yh 需要直接声明 C 接口，并为函数提供 inline 与 noreturn 控制流/优化信息。
旧方案同时包含多种属性书写、堆分配类型语义及 C ABI 推断，扩大了语法和
类型系统的改动范围。

## 决策

所有属性统一使用顶层单组列表 `@[extern, noreturn]`。列表可以包含多个
逗号分隔属性，但一个声明只能有一组；该列表位于可选 `pub` 之前。未知属性、
重复属性、空组、尾逗号和声明种类错配都拒绝。

当前只提供 `extern`、`inline`、`noreturn`。删除 `heap`；分配行为另行设计，
不改变现役值语义。属性不修饰全局/局部 let、const 或 type 别名。

`extern fn` 有体时按 C ABI 定义裸 C 符号，无体时引用 C 符号；无体声明必须
带 `extern`。`pub` 仍独立表示 yh 模块导出。C ABI 标记与 `F_EXTERN` 模块引用
标记分离，避免把用户 C 符号、prelude 与导入模块混为一类。

`extern` struct/union/enum 用于共享 C 数据表示；不透明 struct/union 仅允许
指针使用，enum 固定 i32。每类 C ABI 签名必须逐目标验收，聚合按值不直接穿过
边界。项目 `[c]` 混编另按统一实施方案的 U3 验收。

当前 `printf` 继续使用 yh runtime；本决策不开放用户裸 C 变参，也不隐式把
yh 类型化变参映射到 libc 变参。

## 后果

grammar 只新增 `@` 前缀分支，不改变现有声明首 token；手写解析器的多遍索引、
接口序列化与 CABI 符号路径必须显式识别属性元数据。`inline` 在有限 SSA pass
交付前只是提示，不能宣称已执行内联。更完整的决定与验收条件见
[统一实施方案](../02-plan/yh-属性系统与C互操作统一实施方案.md)。

# ADR-0020：对象粒度停在模块级，撤销文件级对象缓存

日期：2026-11-06。状态：**已决定；文件级对象不实施，函数级 `.o` 暂缓**。

## 背景

2026-11-06 的缓存方案在模块对象缓存之外，规划了“每个 `.yh` 一个 `.o`”的
文件级对象（C5/LA4），并在性能项里保留函数级 `.o`（PC7）。文件级对象要求
按文件发射 LLVM、跨文件私有符号 hidden linkage、N 个对象的链接与提交协议，
目标是让单文件改动只重发该文件。

实际收益被三层事实限制：

1. 现有模块对象缓存命中已跳过整个 worker；文件对象只在模块已失效时提供二级
   复用。
2. 前端是模块级的 parse/check/CT，文件对象不减少同模块其他文件的前端工作；
   函数 check 切片与函数 IR 缓存已经承担这部分增量。
3. 函数 IR 缓存只省 lowering，不省整模块 LLVM 发射；文件对象能省发射，但
   引入 hidden linkage、对象归属和 N 对象链接的复杂度。

## 决定

- 对象粒度停在**模块级**：每个模块一个 `.o`，继续由模块对象缓存 + 链接缓存
  复用；不做文件级对象。
- 撤销 C5（文件级对象）与 LA4 的后续实施；`cache.ACTION_FILE` /
  `OUTPUT_SUPPORT` 常量保留为 schema 预留，不接入消费者。
- 函数级 `.o`（PC7）暂缓，不进入当前路线；桥调用数量与链接对象开销高，
  只有未来测量证明整模块发射重新成为主瓶颈时才重新评估。
- 保留函数 check 切片与函数 IR 缓存：它们负责模块失效后的函数级增量；
  后端整模块发射与链接复用是接受的成本。
- 仍继续 C0–C4/C6 的键正确性、全局 content store、清理与锁；这些与对象
  粒度无关。
- 单函数改动 ≤3 s 不再作为当前承诺。

## 理由

- O0 单函数改动 3.6 s 中，模块级 LLVM 发射约 0.5 s、链接约 1.3 s，其余约
  1.8 s 是前端/lowering；文件对象只能碰前者的一小部分，函数缓存才是
  1.8 s 的主力。
- O2 单函数改动 7.55 s 中内嵌桥约 3.59 s（整模块 LLVM 优化重跑）；文件级
  对象能减少重优化范围，但需要整套 hidden linkage/对象归属，风险和工期
  远高于收益。
- 函数级 `.o` 更差：编译器自身约 1460 个函数，桥调用会从 13 次量级升到
  1460 次，固定开销可能抵消收益。
- 2026-10-25 的键不稳定事故（0 命中、1206 条 `.fir`/49 MB）和 check 切片
  兼容性内部错误说明：缓存复杂度本身就是风险；在函数缓存已能覆盖增量
  前端/lowering 时，不再增加对象层。

## 后果

- 单文件/单函数改动仍会重发整模块 `.o` 并重跑链接；这是明确接受的成本。
- 不需要引入 `IR_MODULE_LINK_HIDDEN`、文件级 ActionID、support 对象、
  N 对象链接清单与跨文件私有符号规则。
- `cache.ACTION_FILE` 与 `OUTPUT_SUPPORT` 保留为预留常量；如未来重启
  对象粒度方案，需新 ADR，不复用本文结论。
- 文档：C5/LA4 从 todo 与缓存方案删除；架构设计、缓存设计、缓存键审计
  与 Go 对比同步改为“模块级唯一对象粒度”。

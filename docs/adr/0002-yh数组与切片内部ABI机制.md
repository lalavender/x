# ADR-0002：yh 数组与切片的内部 ABI 机制

> [ADR-0001](0001-yh数组按值调用边界.md) 为准**。
- 状态：已接受

## 背景

ADR-0001 锁定语言可观察行为（yh 函数收到的 `[N]T` 是独立数组值），但内部
传递机制待实测选择。两个候选：

- **机制 a：包装结构体**。`[N]T` 参数/返回在 yh 层降糖为匿名
  `struct { T a[N]; }`，走 TCC arm64 后端现有 AAPCS64 聚合路径。
- **机制 b：调用点拷贝后传隐式指针**。参数类型实际为 `T *`，yh 层在每个
  调用点生成临时副本并传地址；返回值同样需要调用方分配的隐藏空间。

## 探针证据（tmp/abi/，AArch64 Linux 容器 ubuntu:24.04 + gcc 13.3）

`probe-a.c`（机制 a，tcc 与 gcc 双编译、运行输出逐字节一致）：

| 场景 | 结果 |
| --- | --- |
| `[1]int`/`[4]int` 参数、形参修改 | 调用方不变；16B 聚合进整数寄存器（C.10） |
| `[2]f64`/`[4]f32` 参数与返回 | 浮点正确；float×4 走 HFA/V 寄存器路径（C.2） |
| 8 整数 + 多数组参数（寄存器耗尽） | 溢出参数正确落栈（C.13），副本修改不影响调用方 |
| 返回局部数组（16B / 2400B） | 值正确；>16B 经 X8 隐藏指针，不依赖已结束栈帧 |
| 递归 + 嵌套拷贝 | 各层副本互不串写 |
| 切片结构体 `{u64 len; int *data}` | 参数/返回正确（16B，寄存器传递） |
| 4072B 单数组参数 | 可调用 |

`arm64_pcs_aux`（arm64-gen.c:655）现状：`VT_ARRAY` 与 `VT_FUNC` 一律按
size=align=8 分类（C 数组退化）——yh 数组**不能**直接用 `VT_ARRAY` 传参，
必须换类型标记为包装结构体（或切片结构体）后再进聚合路径。

断言边界（iso1–iso5）：`gfunc_call()` 的 `assert(stack < 0x1000)`
（arm64-gen.c:844）作用于「栈传参 + >16B 聚合调用点拷贝」之和向上取整到
16 字节后的值。实测：2400B×2（4800B）触发断言崩溃；单参数 4088B
（对齐后 4096）触发；4072B（对齐后 4080）通过。`sub sp/add sp, #n` 的
12 位立即数编码上限 4095 是根因。

`probe-b.c`（机制 b）：行为与机制 a 等价（副本独立），但拷贝、隐藏返回
空间、临时生命周期管理全部要 yh 层新增生成逻辑；且所有尺寸数组都退化为
指针传递，偏离 AAPCS64 的小数组寄存器传递。

## 决定

1. **采用机制 a（包装结构体）**：
   - 参数/返回：yh 的 `[N]T` 在函数签名与调用边界降糖为匿名
     `struct { T a[N]; }`，完全复用现有聚合路径（寄存器、HFA、栈、X8 返回）。
   - 切片 `[]T` 降糖为规范化匿名 `struct { u64 len; T *data; }`（16B，
     按方案 §2.3），同一元素类型全局唯一 Sym，与机制 a 使用同一套聚合传递。
   - arm64 后端的参数分类/传递代码**零改动**即可满足 ADR-0001 的正确性矩阵。
2. **4KB 断言在 M4-01 修复后端**，不设语言级尺寸上限：
   `gfunc_call()` 的 `sub sp`/`add sp`（arm64-gen.c:846、931）在
   `stack >= 0x1000` 时改为经临时寄存器的等长调整序列（`movz/movk` +
   `sub/add sp, sp, xN`），删除断言。修复以 iso5（双 2400B）与 >4096B 用例
   作为回归。在此之前，M3 阶段限制测试用例的聚合参数总量不超过边界。
3. 机制 b 记录为已评估并否决：正确性等价，但需要新增"任意尺寸数组值拷贝 +
   临时管理"代码，改动面更大，且失去小数组寄存器传递。
4. 数组按值仅发生在 yh 函数之间（ADR-0001 决定 3）：包装结构体只出现在
   yh 内部调用边界；外部 C 函数（prelude）一律经指针/切片访问数组数据。

## 后果

- M4-01 的实现聚焦于「yh 层把数组类型映射为包装结构体」+「后端栈调整修复」，
  不再需要比较两种机制。
- 每个调用边界的拷贝开销沿用现有结构体路径；>16B 数组由 `gfunc_call` 的
  调用点拷贝负责（已实测正确）。
- `VT_ARRAY` 仅用于局部/全局数组存储布局；进入调用/返回前必须完成类型
  替换，避免触发 8 字节退化分类。

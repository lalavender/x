# ADR-0007：按既有目录迁移 yh 自举编译器源码模块

日期：2026-09-30。状态：已实施（P0–P5 全部完成，见
[finish 历史归档](../01-finished/finish-历史归档-2026-09-27至2026-10-21.md)）；2026-09-30 晚间进一步删除 src/ 与 bootstrap/，构建种子 = bin/yh（滚动自举；同日主编译器二进制由 yh-new 更名为 yh）。

详细设计见[编译器源码模块化](../03-design/yh-编译器源码模块化设计.md)，
阶段与验证门见[实施方案](../02-plan/yh-编译器模块化详细方案.md)。
语言模块规则沿用 ADR-0005；C stage0 冻结沿用 ADR-0006。

## 背景

用户已经将原有文件归入 compiler/cmd、compiler/gen、compiler/lex、
compiler/parse 四个目录，另有 model、buffer、symbols、iface 在根部。
清单为空，源码没有模块声明，旧构建清单未更新。先前以
engine/project/build/main 为目标的方案未尊重这项现有目录规划。

当前 iface 格式不支持公开签名引用别的模块的具名类型。语义文件
sem.yh 调解析入口、symbols.yh 调解析器错误函数、parse_decl.yh 调
cmd/toml 的名字池辅助，直接按目录加 module 会形成反向依赖。

## 决策

1. 保留四个目录名作为四个 yh 模块：gen、lex、parse、cmd；
   `compiler/project.toml` 使用 source = "."（**无 `entry` 字段**——入口是
   `cmd/*.yh` 的 `module main;`）。模块归属由文件头 module 声明确定，
   不由目录自动决定。
2. model、buffer、symbols 归 gen；iface 归 parse。sem_compile 归
   cmd，err_tok 和通用名字池辅助归 gen，使 gen 无反向 import，
   lex/parse/cmd 只向下依赖。
3. 先修复用户已移动目录后的 Makefile/自举清单，再冻结种子；种子存于
   编译器项目扫描范围之外（仓库根 `bin/yh`）。~~C stage0 不扩语法~~ ——
   C stage0 已于 0.0.3 删除。
4. 先做最小四模块接口探针再改写全部文件。仅导出实际跨模块使用的类型、
   字段与符号；类型 Tok/Res 归 gen，避免当前 iface 格式的
   “公开签名含外模块具名类型”限制。（实际落地为 25 个文件。）
5. sem、project、parse_decl 在各自既定目录内按完整函数边界拆文件；
   emit_arm64 等已接近建议范围的文件不为凑目录或行数而拆。
6. 自举改为两代冷编固定点链：`bin/yh` → cc2 → cc3，比较两次产出的
   全部模块 `.s`/`.s.i`。每代冷编（缓存键不含编译器身份）。旧的单文件
   固定点（`make bootstrap`/`make g3`）已随 stage0 删除，不再是门。

## 备选与代价

13 个文件各自成模块会放大 import/pub 面并制造环；此前的 13 模块
分类草案未覆盖当前目录选择。四目录方案仍可能要求公开较多 gen
状态，必须由实际接口产物和调用者审查。若状态面过大，先在现有
四模块内收紧任务接口，不把“继续增加目录”当成解决办法。

正则去掉模块语法再拼接活跃源码作为唯一 stage0 种子，看似省一份
快照，却难以证明限定名、私有语义、字符串和注释等价；选择冻结
无模块 seed，接受维护种子升级流程的成本。

编译器以四模块构建并跑完旧 CLI、模块项目和运行用例；P4 文件
拆分前后行为一致；P5 新冷编固定点通过。

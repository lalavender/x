# ADR-0004：yh 采用 Go 风格的模块、包和导入

日期：2026-09-29。状态：已被 [ADR-0005](0005-yh-mod-toml与按名称导入.md)
替代，保留历史记录，尚未实施。

设计见 [模块与项目管理设计](../03-design/yh-模块与项目管理设计.md)，
计划见 [实施方案](../02-plan/yh-Go风格模块化实施方案.md)。
本次需求是用户代码模块化，原 ADR-0003 的内部重构路线不作为此任务前提。

## 背景

当前 yh 没有 package/import；pub 主要改变 ELF 绑定，不能导入类型和
常量接口。自举通过拼接文件组织源码，但那不提供文件级导入或包隔离。
用户明确要求类似 Go 的模块化方案。

## 决策与取舍

| 决策 | 建议 | 备选与取舍 |
| --- | --- | --- |
| 模块／包分层 | yh.mod 管依赖；目录是包；源码声明 package | 每文件独立模块简单，但难以共享私有实现；一个项目一个包又缺少隔离 |
| 导入作用域 | import 路径是包身份，别名只在当前文件可用 | 包级共享导入书写更少，但会让文件依赖不明确、移动文件改变绑定 |
| 导出 | 保留 pub，并支持字段可见性 | Go 大写导出与 yh 现有代码习惯不一致；两种机制并用会冲突 |
| 多文件编译 | 保存文件身份／导入表；统一登记同包声明 | 裸拼接无法可靠保存文件作用域和诊断；完整 AST 非本轮必要条件 |
| 包产物 | 一包一个对象 + 稳定导出接口，机器符号含完整包身份 | 只靠 .globl 无法传递类型／常量；每源文件对象还需处理包私有跨对象引用 |
| 模块依赖 | 本地 require/replace 先行；远程阶段采用 MVS 和内容摘要 | 通用版本约束求解复杂；任选最新使构建依赖网络状态 |
| 兼容 | 旧单文件入口保留，新目录构建显式进入包模式 | 立即要求所有旧文件加 package 会破坏现有测试和引导链 |

## 必要后果

pub 在包模式成为语言访问控制；同包跨文件不加 pub 仍可访问。
导出接口必须包含类型依赖闭包，同时不暴露私有名字；具名类型身份
包含包归属，别名不创造新身份。

库包不要求 main，入口包装由最终构建生成。跨包对象必须使用一致的
目标、生成器和 ABI；现有 stage0／自举聚合机制不能未经验证混用。
import 包图禁止循环，但模块版本需求图不作同样限制。

远程获取、工作区、自举项目发现和动态初始化分别验收。第一里程碑
完成当前模块多包、本地替换模块及真实链接运行；不能把 grammar 通过
或者源码拼接成功视作模块功能完成。

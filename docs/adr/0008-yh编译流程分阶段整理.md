# ADR-0008：分阶段整理 yh 编译流程

日期：2026-09-30。状态：已撤回，未实施。2026-10-01 用户选择包含
check、IR、早期并行与后续自有工具链的新路线，见
[ADR-0009](0009-yh采用check与IR及早期并行.md)。

## 背景

yh 已进入四目录模块构建与滚动自举。现有前端保存 token，按声明、
全局初始化、函数体三次遍历，边检查语义边生成 AArch64 汇编。
单文件与项目模块的编排重复；自举脚本的快照时机错误；缓存覆盖
源码到汇编，尚未覆盖汇编和链接。共享临时文件、目标传播与提前
发布接口也影响后续流程整理。

用户要求重新规划编译器流程，尚未指定必须引入优化器、AST 或 IR。
优先保持每个阶段都能由入库种子构建并通过有意义的固定点门。

## 建议决策

1. 先修正固定点验证，立即保存每代独立产物，增加会失败的反例。
2. 保留现有四目录和模块子进程，统一编译核心；明确阶段、状态
   生命周期及错误后停止下游的契约，不改变语法和 ABI。
3. 将目标、工具链与产物提交集中在 cmd，成功检查后发布产物，
   完成标记作为缓存提交边界。
4. 分别验证编译、汇编、链接缓存；先测量，再处理重复词法。
5. AST/IR 另由独立语义分析、LSP、优化或第二 ISA 的具体需求驱动。

## 备选路线

立即迁移 AST 可以保留源码结构，便于独立分析，但需要迁移当前
语义钩子，且不能独自消除 ISA/ABI 耦合。一次迁移 AST、类型化
表示和 IR 可支持优化、多后端，代价是改造面扩大、故障定位与
自举验证更困难。两者均保留为明确需求后的候选。

## 影响与代价

收益是改动可逐阶段验收，先建立可信证据，再整理现有能力。
代价是语义与发射仍交织，首轮不提供完整的独立语义分析能力；
串行模块子进程和全局表也继续存在。若用户主要目标是优化或多
后端，应重新选择路线，不能将本决策冒充长期终局架构。

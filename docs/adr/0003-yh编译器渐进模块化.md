# ADR-0003：yh 编译器采用渐进模块化

日期：2026-09-29。状态：已撤回本次执行范围，未实施。

用户纠正需求为 Go 风格语言模块化。本文件保留原内部重构取舍作为历史，
不作为当前方案或前置任务；当前决策见
[ADR-0004](0004-yh-Go风格模块与包.md)。

详细计划见 [yh 编译器模块化详细方案](../02-plan/yh-编译器模块化详细方案.md)。

## 背景

仓库包含 C 版 stage0 和 yh 自举版。C 版依赖 ONE_SOURCE 的隐式静态
可见性；自举版依赖有序源码拼接、共享可变全局及语义层中的 ARM64
寄存器／调用栈操作。已有自举验收不能单独证明每项语言语义正确，最新
todo 还记录了超 8 参数排列错误的未修复问题。

当前目标是改善模块边界、维护和验证能力，同时保留可用引导与自举链。
没有明确需求要求本轮增加优化器、语言模块语法或新的目标架构。

## 决策 1：保留直接生成流程，先拆职责

推荐渐进地建立 parser、semantic、codegen、ABI、backend、output、
host、pipeline 的边界。semantic 返回语言检查结果；生成层决定求值与
存储；ABI 决定调用位置；backend 产生指令。阶段编排不属于 semantic。

备选是只移动文件，或者完整改写 AST／IR。前者不足以解决共享状态与
平台泄漏；后者扩大自举验证范围且目前缺少必要需求。完整 AST／IR 留作
后续有优化、IDE 或多后端复用需求时的独立决策。

后果：保留多遍 token 流与流式生成；不能宣称 parser／后端可完全独立重跑。

## 决策 2：使用明确所有者的状态对象

将源输入、解析、类型／符号、函数、生成、ABI／帧、输出状态分别归属到
模块，并由会话管理生命周期。按组迁移，状态只有一份存储，以指针传递。

备选是继续使用共享全局，或把全部字段放入一个大上下文。共享全局难以
表达重置边界；万能上下文仍允许所有模块任意访问。选择小组所有权，
迁移成本较高，但能定位嵌套调用和函数状态污染。

后果：需要明确初始化、保存恢复和失败清理；不自动获得并发安全。

## 决策 3：构建集中于唯一清单，yh 暂保留拼接

建议建立 `compiler/sources.list` 与共同读取工具，Makefile／native
自举链共同消费。保持显式顺序和现有顶层声明拼接，附加位置映射由开发
工具处理，不添加 `import`、`#line` 或新的 yh 语法。

备选是保留两份清单、目录 glob 或实现语言模块。重复清单容易漂移，
自动排序可能破坏声明依赖，语言模块属于更大的语言设计项目。

后果：源码模块边界仍由检查工具和评审约束，不等于独立编译。

## 决策 4：C 版先建立适配边界，再评估独立编译

优先封装 yh 实际使用的 TCC 能力，取消跨实现文件 static 声明；
ONE_SOURCE 保持可用，独立 `.o` 按组验证后再考虑成为默认。
保留 `libtcc.h` 与现有 CLI，不在此决策下替换默认 yh。

备选是一次关闭 ONE_SOURCE 或全面重构 TCC。前者会把隐式依赖变成大量
extern，后者投入大且可能与自举版重复。有限适配使 stage0 能继续承担
引导；是否全面拆分取决于长期维护价值。

后果：两套实现不会立刻拥有相同目录或内部机器 ABI；以现有语言承诺与
运行行为对照，不以二进制相同作为条件。

## 实施前提与复核

先用不可交换实参和求值副作用测试修复／冻结 P0 基线。每次代码修改
增加 `.yh` 回归并构建。纯移动比较旧／新汇编；生成策略变更验证语义与
新固定点。graphify 当前未覆盖 yh，不能据其结果直接删除代码。

本 ADR 记录建议和取舍，方案交付不表示架构已经实施或用户已经批准
启动全部阶段。若范围改为仅 C 版或完整 AST／IR，应修订本决策和阶段计划。
